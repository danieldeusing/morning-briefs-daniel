OpenHands v1.25.0: der Router bekommt einen Schalter

Update seit gestern: Gestern stand OpenHands noch auf v1.24.0 vom 25.09. Heute, am 06.10., ist v1.25.0 erschienen.[1] Drei Punkte stehen oben in den Release Notes:

  • Sprach-Diktat: „add optional voice dictation to the chat input". Du sprichst den Auftrag, statt ihn zu tippen.[1]
  • Modell-Router: ein neuer Schalter „Run at conversation start". Du legst fest, ob der Router schon beim Start des Gesprächs ein Modell wählt.[1]
  • Personas: „give a profile its own persona or extra instructions". Jedes Agent-Profil bekommt eigene Anweisungen.[1]

Dazu kommen kleinere Dinge: LLM-Profile lassen sich pro Verbindung gesammelt verwalten, Canvas-Apps aktualisieren, der Gesprächs-Drawer hat Tabs. Breaking Changes nennen die Notes nicht.[1]

Modell-Router: Eine Weiche vor den Sprachmodellen. Sie schaut sich die Aufgabe an und schickt sie an ein passendes Modell — die schnelle, billige Variante für eine Umbenennung, die teure für einen Architektur-Umbau. Wie eine Werkstatt, in der der Meister entscheidet, ob der Lehrling oder der Spezialist an das Auto geht. Der neue Schalter regelt, ob diese Entscheidung schon fällt, bevor du die erste Frage gestellt hast.

Der Takt ist bemerkenswert. Von v1.17.0 (09.09.) bis v1.25.0 (06.10.) sind es neun Releases in vier Wochen.[1] Mit v1.19.0 (16.09.) kam GPT-6 Astra dazu und die Möglichkeit, MCP-Server pro Agent-Profil einzugrenzen.[1]

Meine Sicht: Die Profile sind das eigentliche Produkt geworden. Ein Profil bündelt jetzt Modell, MCP-Server, Persona und Router-Verhalten. Das ist genau das, was du in Claude Code über Subagents und Settings-Dateien zusammensteckst — nur in einer Oberfläche und modellneutral. Wer zwischen Anthropic, OpenAI und lokalen Modellen wechselt, bekommt hier die sauberste Trennung.

Ausprobieren Lege zwei Profile an: eins mit lokalem Modell (Ollama) und engem MCP-Zugriff für Routine-Refactorings, eins mit einem großen Cloud-Modell für Planung. Dann merkst du in einer Woche, wie viel der teuren Arbeit eigentlich billig geht.

GitHub beschreibt die zwei Modelle unterschiedlich. Sonnet 5.5 ist „designed for well-scoped everyday work like building features and fixing bugs". GPT-6.1 Sol ist „designed for agentic coding and terminal workflows".[1] Das ist Herstellersprache, aber ein nützlicher Hinweis, wofür GitHub sie selbst einsetzt.

Harness: Alles um das Modell herum — wie das Werkzeug Dateien liest, Befehle ausführt, Kontext zusammenfasst, Rückfragen stellt und Fehler korrigiert. Das Modell ist der Motor, der Harness ist das Auto. Zwei Autos mit demselben Motor fahren sich trotzdem sehr verschieden.

Meine Lesart: Ein Modell-Vorsprung hält im Moment etwa einen Tag. Danach haben es alle großen Werkzeuge. Für die Wahl deines Werkzeugs heißt das: Frag nicht „welches Modell hat es?", sondern „was macht es mit dem Kontext?". Genau dort setzen die Releases dieser Woche an — Cline mit /compact, OpenHands mit dem Router, Claude Code mit Mods. Der Wettbewerb hat sich vom Modell auf die Bedienung verlagert.

Copilot bedient jetzt Desktop-Programme

Am 01.10. hat GitHub „Computer use" für Copilot freigegeben: „now available in public preview in GitHub Copilot CLI and the GitHub Copilot app on macOS and Windows".[1] Im CLI schaltest du es mit /computer on ein, in der App unter Settings → Computer Use.[1]

Zur Kontrolle schreibt GitHub: „Copilot asks for approval before controlling an app". Freigaben für „always allow" kannst du später prüfen und zurücksetzen. Organisationen können die Funktion zentral abschalten.[1] Welches Modell dahinter arbeitet und für welche Tarife es gilt, steht nicht im Eintrag.

Computer Use: Das Modell sieht Bildschirmfotos und steuert Maus und Tastatur, wie ein Mensch. So kann ein Agent auch Programme bedienen, die keine API haben — den Simulator, ein Admin-Tool, einen Installer. Der Preis: Es ist langsam, und ein falscher Klick ist ein echter Klick.

Meine Sicht: Für Entwickler ist der Nutzen eng, aber real — etwa eine App im Simulator durchklicken, nachdem der Agent den Code geändert hat. Die Approval-Abfrage ist Pflicht, nicht Komfort. Gib „always allow" nur Programmen, in denen ein Fehlklick nichts kostet. Kein Browser mit eingeloggtem Bank-Konto, kein Mail-Client.

Claude Code: Sonnet 5.5 in der Sonnet-Stufe, dazu Mods

Laut Changelog hat v2.1.284 Claude Sonnet 5.5 zum Standardmodell der Sonnet-Stufe über die Anthropic-API gemacht. Das Standardmodell von Claude Code selbst bleibt Opus 5.5. v2.1.287 brachte „Claude Mods" mit einem eingebauten Mod namens „You should know". Seither folgten weitere Patches bis v2.1.291.[1] Der Changelog führt nur Versionsnummern, keine Daten. Welche Version in den letzten 24 Stunden kam, lässt sich daraus nicht sagen.

Mods: Erweiterungen, die das Verhalten von Claude Code selbst ändern — nicht nur ein zusätzliches Werkzeug wie ein MCP-Server, sondern ein Eingriff in Prompts oder Oberfläche. Wie ein Plugin für deinen Editor im Vergleich zu einem externen Programm, das du aus dem Editor aufrufst.

Anthropic nennt Sonnet 5.5 „30% faster" als den Vorgänger.[2] Für den Alltag heißt das: Wer nichts einstellt, arbeitet weiter mit Opus 5.5. Sonnet 5.5 bekommst du erst, wenn du die Sonnet-Stufe ausdrücklich wählst.

Meine Sicht: Die Mods machen Claude Code zu einer Plattform, wie es OpenHands mit Profilen und Cline mit Connectors versuchen. Prüfe nach dem Update kurz mit /model, ob du dort landest, wo du willst — besonders, wenn du bisher Opus fest eingestellt hattest.

Bench-Notiz: Pro ist nicht Verified

Für Claude Sonnet 5.5 und Opus 5.5 kursieren vor allem diese Zahlen: 81,3 % und 89,9 % auf SWE-Bench Pro.[1] Das sind Herstellerangaben aus Anthropics Release-Tabelle, hier nur über einen Aggregator abgerufen. Auf SWE-Bench Verified, dem Test, den du verfolgst, steht für Sonnet 5.5 noch „Coming soon".[1] Die offizielle Tabelle auf swebench.com lieferte beim Abruf keine Werte.[2]

SWE-Bench Verified vs. Pro: Beide geben dem Modell echte GitHub-Issues zum Lösen. Verified ist ein von Menschen geprüfter Satz bekannter Aufgaben. Pro ist ein neuerer, schwererer Satz. Das sind zwei verschiedene Prüfungen — wie ein Abitur und eine Uni-Klausur. Die Noten kannst du nicht direkt vergleichen.

Die Falle steht im selben Aggregator: Sonnet 5 kam auf 85,2 % Verified, Sonnet 5.5 auf 81,3 % Pro.[1] Wer die Zahlen nebeneinander legt, liest einen Rückschritt. Es ist keiner, sondern ein anderer Test. Sauber ist nur der Vergleich Pro gegen Pro: Sonnet 5 lag dort bei 63,2 %.[1] Auch das ist eine Herstellerzahl.

Dasselbe gilt für GPT-6 Astra (seit 03.09.): OpenAI meldet etwa 57,9 % auf Terminal-Bench 4.0, nach 37,3 % beim Vorgänger — nur über Sekundärquellen, ohne unabhängigen Eintrag.[3]

  • Aider-Leaderboard: Stand 20.11.2025, oben „gpt-5 (high)" mit 88,0 %. Fast elf Monate alt.[4]
  • LiveCodeBench: Die Seite zeigt nur „Loading leaderboard data…". Keine Zahl.[5]
  • LMArena Code Arena (WebDev): Um den 05.09. lag GPT-6 Astra mit 1797 vor Claude Fable 5.1 mit 1762 — laut einer Sekundärquelle, einen Monat alt.[6]

Meine Sicht: Gerade gibt es keinen unabhängigen, gemeinsamen Coding-Test für die Modelle vom September. Darum heute kein Balkendiagramm. Bis Verified-Einträge kommen, ist dein eigenes Repo der ehrlichste Benchmark.

Es ist Dienstag, der sechste Oktober. Die einzige echte Neuigkeit der letzten vierundzwanzig Stunden kommt aus dem Open-Source-Lager: OpenHands hat heute Version eins Punkt fünfundzwanzig veröffentlicht.

Drei Dinge sind neu. Du kannst deinen Auftrag jetzt in den Chat diktieren. Der Modell-Router, also die Weiche, die eine Aufgabe an ein passendes Modell schickt, bekommt einen Schalter, ob er schon beim Start des Gesprächs entscheidet. Und jedes Agent-Profil kann eine eigene Persona mit eigenen Anweisungen haben. Es ist das neunte Release in vier Wochen.

Damit wird das Profil zum eigentlichen Produkt: Modell, MCP-Server, Persona und Router in einem Paket, unabhängig vom Anbieter. Ein guter Test ist ein Profil mit lokalem Modell für Routine-Arbeit und eins mit Cloud-Modell für die Planung.

Das passt zum Muster der Woche. Claude Sonnet fünf Punkt fünf kam am achtundzwanzigsten September und war am selben Tag in GitHub Copilot. GPT sechs Punkt eins Sol folgte einen Tag später. Cline hat es am dreißigsten September zum Standard gemacht, und in Claude Code ist Sonnet fünf Punkt fünf jetzt der Standard der Sonnet-Stufe über die API. Claude Code selbst bleibt standardmäßig bei Opus fünf Punkt fünf. Ein Modell-Vorsprung hält gerade etwa einen Tag. Entscheidend ist, was das Werkzeug drumherum mit dem Kontext macht.

GitHub hat am ersten Oktober Computer Use für Copilot freigegeben, als Vorschau im CLI und in der App für macOS und Windows. Copilot kann damit Desktop-Programme bedienen, fragt aber vorher um Erlaubnis. Gib die dauerhafte Freigabe nur Programmen, in denen ein falscher Klick nichts kostet. Am zweiten Oktober hat Copilot außerdem vier Modelle gestrichen, darunter Claude Opus vier Punkt sieben und zwei ältere Gemini-Flash-Versionen.

In Claude Code kamen neben dem neuen Sonnet-Standard die sogenannten Mods, Erweiterungen, die das Verhalten des Werkzeugs selbst ändern. Der Changelog nennt allerdings keine Daten, nur Versionsnummern.

Zu den Benchmarks eine Warnung. Für Sonnet und Opus fünf Punkt fünf kursieren einundachtzig und knapp neunzig Prozent, aber auf SWE-Bench Pro, nicht auf SWE-Bench Verified. Das sind zwei verschiedene Tests, und die Zahlen stammen von Anthropic selbst. Ein Verified-Eintrag fehlt noch. Das Aider-Leaderboard ist fast elf Monate alt, LiveCodeBench lieferte keine Daten.

Cursor ist seit dem dreiundzwanzigsten September still, lokal gibt es keine neuen Coding-Modelle. Morgen schauen wir, ob Cursor nachzieht und ob die ersten unabhängigen Verified-Werte für die neuen Claude-Modelle auftauchen.
