Die Zahl hinter dieser Woche: Claude Code überholt Copilot deutlich

JetBrains hat für seine zehnte Developer Ecosystem Survey „more than 15,000 professional developers worldwide" befragt, zwischen Mai und Juli 2026. Die Ergebnisse zu Coding-Agenten stehen seit August im JetBrains-Research-Blog.[1] Die Nachricht ist also ein paar Wochen alt. Sie gehört trotzdem nach oben, weil sie die größte Verschiebung bei Entwickler-Werkzeugen in diesem Jahr ist — und weil sie erklärt, warum GitHub und Cursor gerade so schnell liefern.

Dazu zwei Werte: In den USA liegt Claude Code bei 47 %. Für 31 % aller Befragten ist es das meistgenutzte Werkzeug. JetBrains nennt das „an almost 80% conversion rate" — wer es nutzt, nimmt es meistens als Hauptwerkzeug.[1] Insgesamt nutzen 90 % der Befragten mindestens wöchentlich Coding-Agenten, 68 % täglich.[1]

Umgewichtete Umfrage: Wer an einer Umfrage teilnimmt, ist nie ein perfektes Abbild aller Entwickler — zum Beispiel antworten JetBrains-Kunden eher als andere. Darum rechnet JetBrains die Antworten nach Region, Erfahrung und anderen Merkmalen nach, damit das Ergebnis „better represent[s] the global developer population".[1] Wie ein Koch, der eine zu salzige Probe verdünnt, bevor er das ganze Essen beurteilt. Es hilft, aber es bleibt eine Probe.

Meine Sicht: Drei Dinge sind wichtiger als die Rangfolge. Erstens fällt Copilot, obwohl es in jedem GitHub-Konto steckt — Verteilung allein reicht nicht mehr. Zweitens ist Codex der zweite Gewinner: von 3 auf 16 % in einem halben Jahr. Das Rennen läuft zwischen zwei Agenten aus dem Terminal, nicht zwischen zwei Editoren. Drittens verliert ausgerechnet Cursor, der bekannteste AI-Editor. Ein Vorbehalt bleibt: JetBrains verkauft mit Junie selbst einen Konkurrenten, und die Zahlen sind Selbstauskünfte. Als Richtung sind sie trotzdem eindeutig.

Wie viel Code schreiben Agenten wirklich?

Eine zweite JetBrains-Auswertung aus derselben Umfrage fragt nach dem Anteil am eigenen Code. Im Schnitt aller Befragten gilt:[1]

  • etwa 47 % „fully written by agents",
  • etwa 38 % mit etwas AI-Hilfe geschrieben,
  • etwa 27 % komplett von Hand.

Das ergibt zusammen mehr als 100 %. Das ist kein Fehler: Die Befragten wählten Spannen wie „21–40 %", und JetBrains rechnet mit den Mittelwerten der Spannen. Die Methodik-Notiz sagt selbst, dass die Summe „could exceed 100%".[1] Lies die drei Zahlen also als grobe Gewichte, nicht als exakte Anteile.

Zwischen den Werkzeugen gibt es Unterschiede. Cursor-Nutzer lassen 58 % ihres Codes von Agenten schreiben; bei 28 % von ihnen sind es über 80 %. Von den Entwicklern mit Claude Code als Hauptwerkzeug lassen etwa 32 % über 80 % ihres Codes von Agenten schreiben.[1]

Zum Vergleich ein älterer Wert: Im Stack Overflow Developer Survey 2025 (49.000+ Antworten, veröffentlicht 29.07.2025) sagten 84 %, dass sie AI-Werkzeuge nutzen oder nutzen wollen, nach 76 % im Jahr 2024.[2] Das misst Nutzung, nicht Code-Anteil.

Was wir bewusst weglassen: Die Zahl „41 % des Codes ist AI-geschrieben" kursiert auf vielen Seiten mit Verweis auf JetBrains. Wir konnten sie keiner Primärquelle in dieser Form zuordnen. JetBrains selbst nennt für 2026 die Werte oben.

Meine Sicht: Die Cursor-Zahl ist die interessante. Cursor verliert Nutzer, aber die verbleibenden delegieren mehr als der Durchschnitt. Das spricht für ein Werkzeug, das von einer breiten Masse zu einem Kern von Power-Usern schrumpft.

Cursor: lokale Agenten vom Handy aus steuern

Update seit gestern: Gestern war Cursor noch still seit dem 23.09. Am 06.10. kam „Remote control for local agents".[1] Mit der Cursor-App für iOS siehst du, was ein Agent auf deinem Rechner gerade tut, und kannst ihm Nachrichten schicken.

  • Der Agent zieht nicht um: „It keeps running on your computer, and the app connects to it."[1]
  • Der Rechner muss „on and online" bleiben. Damit ein Laptop nicht einschläft: „plugged in with the lid open".[1]
  • Die Kopplung bestätigst du in der Desktop-App.[1]
  • Standardmäßig an für alle außer Enterprise. Dort schalten Admins es unter „Org settings > Security and identity > Remote control" frei.[1]

Meine Sicht: Das ist die Antwort auf das Muster „Agent arbeitet zwei Stunden, ich bin nicht am Schreibtisch". Der Vorteil gegenüber Cloud-Agenten: Code, Secrets und lokale Modelle bleiben auf deinem Rechner. Der Nachteil: Standardmäßig an heißt, dass ein verlorenes, entsperrtes Handy einen Weg zu deinem Agenten öffnet. Prüfe, welche Rechte der Agent auf dem Rechner hat, bevor du ihn aus der Ferne weiterlaufen lässt.

Ausprobieren Wenn du Cursor nutzt: einen langen Refactoring-Lauf starten, weggehen und per iOS-App nur die Rückfragen beantworten. So siehst du schnell, wie oft dein Agent wirklich auf dich wartet.

Copilot liefert im Tagestakt

Wer in einer Umfrage von 29 auf 21 % fällt, muss zeigen, dass er sich bewegt. Die Copilot-Einträge der letzten zehn Tage im GitHub-Changelog:[1]

DatumEintrag

02.10.Code Review: API-Zugriff und neue Standard-Stufe
06.10.IDE updaten, damit Agent-Aktivität wieder in den Nutzungs-Metriken erscheint

Neu für dich ist vor allem Code Review: „You can now request a review from Copilot using the supported REST and GraphQL APIs."[2] Die bisherige Stufe „Default" läuft jetzt als „Balanced"; die Änderung „took effect September 28, 2026". Allgemein verfügbar für Pro, Pro+, Max, Business und Enterprise.[2]

Effort-Stufe: Wie lange das Modell nachdenken darf, bevor es antwortet. Niedrig ist schnell und billig, hoch ist gründlicher und teurer. Wie die Wahl zwischen einem kurzen Blick eines Kollegen auf deinen Pull Request und einer echten Review mit Kaffee.

Der Eintrag vom 06.10. betrifft Teams, die Copilot-Nutzung messen: Ältere IDE-Plugins melden die Agent-Aktivität nicht mehr korrekt.[1] Wer Lizenzen anhand dieser Metriken verteilt, sollte erst die Plugins aktualisieren.

Meine Sicht: Die API ist der eigentliche Hebel. Damit wird Copilot Review ein Baustein in deiner CI, nicht nur ein Knopf in der Oberfläche. Für Teams, die schon auf GitHub sind, ist das bequemer als jedes Fremd-Werkzeug.

Ausprobieren Einen CI-Schritt bauen, der bei Label „ready" per API eine Copilot-Review anfordert. Dann vergleichst du in zwei Wochen, was sie findet, mit dem, was deine eigene Claude-Code- oder Codex-Review findet.

Claude Code v2.1.292: Effort pro Subagent, viele Sicherheits-Fixes

Update seit gestern: Gestern stand der Changelog bei v2.1.291. Jetzt steht oben v2.1.292.[1] Der Changelog nennt keine Daten.

  • Effort für Subagents: „Added an effort parameter to the Agent tool, so Claude runs a sub-agent at the effort level you ask for".[1]
  • Plugins: claude plugin install kennt jetzt --marketplace <source>.[1]
  • Sicherheit: Ein Fix für „PreToolUse hook approvals and auto mode bypassing the permission prompt for file reads from network (UNC) paths". Dazu Fixes für Dateizugriffe außerhalb der Freigabe über einen während des Lesens getauschten Link (macOS, Windows) und für rm -rf auf alternative Windows-Schreibweisen des Home-Ordners.[1]

Meine Sicht: Der effort-Parameter ist dieselbe Idee wie Copilots „Balanced" — Rechenzeit gezielt verteilen. Ein Recherche-Subagent braucht selten die höchste Stufe, ein Planungs-Subagent schon. Die Sicherheits-Fixes betreffen vor allem Windows und Netzlaufwerke, aber Hook-Umgehungen sind genau die Lücken, auf die du dich bei Auto-Mode verlässt. Also: updaten.

Die Herausforderer: Meta über den Preis, Google über das Ziel

Meta Muse Code ist seit dem 05.08.2026 als Beta draußen und läuft auf dem Modell Muse Spark 1.2.[1] Auf Terminal-Bench 2.1 kommt Muse Code laut Bericht auf 82,9 %, Claude Code mit Opus 5 auf 86,7 % — Herstellerangaben aus der Ankündigung, nicht unabhängig gemessen.[1] Meta spielt deshalb den Preis: Eine „contributor tier" kostet 0,20 $ pro Million Output-Tokens, „more than ten times cheaper". Bedingung ist, dass du der Weitergabe von Feedback-Daten zustimmst.[2]

Google Jules geht einen anderen Weg. Auf der Google I/O am 19.05.2026 stellte Google Jules V2 vor, intern „Project Jitro": Statt Schritt-für-Schritt-Prompts gibst du ein Ziel vor.[3] Jules läuft für Pro-Abos auf Gemini 3.1 Pro, im Gratis-Tarif auf Gemini 3 Flash.[3] In der JetBrains-Umfrage taucht Jules nicht eigens auf; Googles Antigravity steht dort bei 6 %.[4]

Ziel statt Schritte: Bisher sagst du dem Agenten „lies Datei X, ändere Funktion Y, starte die Tests". Bei einem zielgesteuerten Agenten sagst du nur „die Tests sollen grün sein und der Login soll OAuth nutzen", und er plant die Schritte selbst. Wie ein Taxifahrer, dem du die Adresse gibst statt jeder Abbiegung.

Meine Sicht: Ein Abstand von knapp vier Punkten auf einem Hersteller-Benchmark ist in der Praxis klein, ein Preisfaktor zehn ist groß. Der Haken sitzt in der Bedingung: Wer billig fährt, gibt Daten ab. Für ein Hobby-Repo vertretbar, für Kunden-Code nicht. Jules bleibt im Alltag die Nummer drei hinter den beiden Terminal-Agenten.

Bench-Notiz: die Tabelle bleibt leer

Die offizielle SWE-Bench-Verified-Tabelle auf swebench.com lädt ihre Werte per JavaScript; der Abruf lieferte auch heute keine Zahlen. Der Aggregator llm-stats.com nennt Claude Fable 5 mit 95,0 % und Claude Mythos Preview mit 93,9 % an der Spitze.[1] Diese Werte konnten wir nicht gegen die geprüfte Tabelle abgleichen. Behandle sie als Hersteller- oder Aggregator-Angaben, nicht als Messung.

Warum 95 % wenig heißt: SWE-Bench Verified ist ein fester, öffentlicher Satz von GitHub-Issues. Je länger ein Test öffentlich ist, desto eher landen die Aufgaben oder ihre Lösungen im Trainingsmaterial neuer Modelle. Dann misst der Test Auswendiglernen statt Können — wie eine Klausur, deren Fragen seit Jahren im Netz stehen. Bei Werten über 90 % ist der Abstand zwischen zwei Modellen kaum noch aussagekräftig.
  • Aider-Leaderboard: „Last updated" 20.11.2025, oben „gpt-5 (high)" mit 88,0 %. Fast elf Monate alt — als aktueller Vergleich unbrauchbar.[2]
  • LiveCodeBench: Nur Aggregator-Zusammenfassungen, keine Primärdaten. Wir nennen keine Zahl.

Meine Sicht: Die einzige belastbare Coding-Zahl dieser Woche ist eine Umfrage, kein Benchmark. Die Entwickler haben mit den Füßen abgestimmt, während die Leaderboards still stehen. Darum heute kein Balkendiagramm.

Was heute nicht drinsteht

Stacked Pull Requests GA und AI-Scan-Status im Code Scanning (beide GitHub, 06.10.) gehören in den Software-Brief. Enterprise-Einsatz von AI steht im Anwendungs-Brief.

Es ist Mittwoch, der siebte Oktober. Die wichtigste Zahl zu Coding-Agenten in diesem Jahr ist schon ein paar Wochen alt, aber sie erklärt die Nachrichten dieser Woche.

JetBrains hat zwischen Mai und Juli mehr als fünfzehntausend Profi-Entwickler befragt. Neununddreißig Prozent nutzen Claude Code bei der Arbeit, im Januar waren es achtzehn. GitHub Copilot fiel auf einundzwanzig Prozent, ein Jahr zuvor waren es neunundzwanzig. Cursor fiel von achtzehn auf zwölf Prozent. Der zweite Gewinner ist OpenAI Codex, von drei auf sechzehn Prozent. Das Rennen läuft also zwischen zwei Agenten aus dem Terminal. Ein Vorbehalt: Es sind Selbstauskünfte, und JetBrains verkauft selbst einen Konkurrenten.

Im Schnitt lassen die Befragten etwa siebenundvierzig Prozent ihres Codes komplett von Agenten schreiben. Die Zahl einundvierzig Prozent, die oft kursiert, lassen wir weg, weil sie keiner Primärquelle zuzuordnen ist.

Wer verliert, beschleunigt. Cursor hat gestern eine Fernbedienung gebracht: Mit der iOS-App siehst und steuerst du einen Agenten, der weiter auf deinem eigenen Rechner läuft. Die Funktion ist standardmäßig an. Prüfe also, welche Rechte dein Agent hat.

GitHub liefert im Tagestakt. Copilot Code Review lässt sich jetzt per API anstoßen, und die Standard-Stufe heißt Balanced. Das macht die Review zu einem Baustein in deiner CI.

Claude Code steht bei Version zwei Punkt eins Punkt zweihundertzweiundneunzig. Neu ist ein Effort-Parameter für Subagents, dazu mehrere Sicherheits-Fixes, unter anderem gegen eine Umgehung der Hook-Freigaben bei Netzlaufwerken. Updaten lohnt sich.

Bei den Herausforderern setzt Meta mit Muse Code auf den Preis, mehr als zehnmal billiger, wenn du Feedback-Daten teilst. Google setzt bei Jules auf Ziele statt einzelner Schritte.

Die Benchmarks stehen still. Die offizielle SWE-Bench-Tabelle lieferte keine Werte, und das Aider-Leaderboard ist fast elf Monate alt. Lokal gibt es nichts Neues. Bis zur GitHub Universe Ende Oktober dürfte Copilot noch einiges nachlegen.
