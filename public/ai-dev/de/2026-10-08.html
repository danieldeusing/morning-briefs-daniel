Claude Haiku 5.5: das billige Modell für die Fleißarbeit

Anthropic hat gestern, am 07.10., Claude Haiku 5.5 vorgestellt: „Our fastest, cheapest, and most capable small model yet."[1] Der Preis hängt von der Prompt-Länge ab. Bis 100K Tokens kostet es 0,10 $ pro Million Input-Tokens und 0,50 $ pro Million Output-Tokens. Darüber sind es 0,50 $ und 2,50 $.[2] Das Modell heißt in der API claude-haiku-5-5 und läuft auch bei AWS, Google Cloud und Microsoft Foundry.[2]

Für dich als Claude-Code-Nutzer ist die wichtigere Zeile im Changelog von v2.1.293: „Added Claude Haiku 5.5 (claude-haiku-5-5) as the default Haiku model on the Anthropic API, with 1M context."[3] Die Produktseite selbst nennt kein Kontextfenster — die 1M stehen nur im Changelog.

Preis pro Million Tokens: Ein Token ist ein Wortstück, grob drei Viertel eines Wortes. Du zahlst getrennt für das, was du hineingibst (Input), und für das, was das Modell schreibt (Output). Wie beim Copyshop: Einscannen kostet wenig, Drucken mehr. Bei 0,10 $ pro Million Input-Tokens kostet es etwa 1 Cent, einem Agenten eine Codebasis mit 100.000 Tokens zu zeigen.

Was fehlt: jede Benchmark-Zahl. Die Produktseite zeigt die Vergleiche nur als Bild. Im Text steht nur, Haiku 5.5 sei „a significant step up over Haiku 4.5 across coding, tool use, computer use, and agents".[2] Zum Vergleich nennt die Seite für Haiku 4.5 einen Wert von 73,3 % auf SWE-Bench Verified. Daneben stehen Kundenzitate: Box misst „11 points higher than Haiku 4.5 at about half the latency", HubSpot „92.8% averaged over three runs" auf einer eigenen Test-Suite.[2] Das sind Angaben von Kunden auf der Herstellerseite, keine unabhängige Messung. Einen unabhängigen Wert gibt es noch nicht.

Meine Sicht: Haiku ist nicht das Modell, mit dem du programmierst. Es ist das Modell für die Subagents, die Dateien durchsuchen, Logs zusammenfassen und Tests auswerten. Zusammen mit dem effort-Parameter für Subagents aus v2.1.292 (gestern im Brief) baust du dir damit eine Kostenstufe: Haiku sucht, Sonnet oder Opus entscheidet. Bevor du das breit nutzt, prüfe es auf deinem eigenen Repo — ohne veröffentlichte Zahlen ist dein eigener Test die einzige Messung, die zählt.

Ausprobieren Einen Explorations-Subagent in Claude Code explizit auf Haiku setzen und eine Woche lang vergleichen, wie oft der Hauptagent seine Funde nachprüfen muss. So siehst du, ob die Ersparnis echt ist.

OpenAI: GPT-6.1 Sol in Codex, GPT-5.5 geht am 14.10.

Auf dem DevDay am 29.09. kam GPT-6.1 Sol, laut Folie „Near-Astra level intelligence at a fifth of the price".[1] Es kostet 2 $/10 $ pro Million Tokens, GPT-6 Astra 10 $/50 $. Gecachte Input-Tokens kosten 0,10 $ statt 1,00 $.[1] In Codex steht es als gpt-6.1-sol bereit.[2]

Zu den Leistungsdaten haben wir nur Sekundärquellen, weil openai.com beim Abruf blockte. Ein Bericht nennt für Sol auf DeepSWE v1.1 rund 75 % (Berichte: 75,2 %), gleichauf mit Astra (rund 74,8 %), bei 80 % weniger Kosten pro Aufgabe.[3] Ein anderer Aggregator listet 71,9 %. Beides sind Herstellerangaben in zweiter Hand. Behandle sie als grobe Richtung.

  • Ultrafast-Modus: bis zu 300 Tokens pro Sekunde zum sechsfachen Preis.[1]
  • Codex Security: laut OpenAI-Folie 53 kritische Funde am ersten Tag behoben, 1 % Rollback-Rate.[1] Herstellerangabe.
  • Lange Aufgaben: Der Anteil von 8- bis 16-Stunden-Aufgaben ohne Eingriff stieg laut Folie von 10 % im Januar auf 35 % im Juli 2026.[1]
Frist „On October 14, 2026, GPT-5.5 will retire from ChatGPT, ChatGPT Work, and Codex on all plans."[2] Die API ist nicht betroffen. Wer in Codex-Konfigurationen oder Skripten GPT-5.5 fest eingetragen hat, stellt jetzt um. Schon seit 05.09. entfernt: das Kommando codex mcp-server; der Ersatz ist der Codex App Server.[2]

Meine Sicht: Sol ist OpenAIs direkte Antwort auf Sonnet — gleicher Preis, gleiche Rolle. Die Folie mit 35 % langen Aufgaben ohne Eingriff ist die interessanteste Zahl des DevDay, aber auch die am schwersten prüfbare. „Ohne Eingriff" sagt nichts darüber, ob das Ergebnis gut war.

Pwn2Own Irland: Codex fällt mit einem Bug

Am ersten Tag von Pwn2Own Irland, am 06.10., haben Forscher 32 Zero-Days ausgenutzt und dafür 388.500 $ bekommen.[1] Unter den Zielen war auch ein Coding-Agent: Die Forscher „took down the OpenAI Codex cloud-based AI coding agent" mit „a single argument-injection bug".[1] Der Bericht nennt weder das Team noch das Preisgeld für diesen Angriff. Die Hersteller haben jetzt 90 Tage für ein Update, bevor die Zero Day Initiative Details veröffentlicht.[1]

Argument Injection: Ein Programm baut einen Befehl zusammen und setzt einen Wert ein, den ein Angreifer kontrolliert — etwa einen Dateinamen. Beginnt dieser Wert mit einem Bindestrich, liest das aufgerufene Werkzeug ihn als Option statt als Namen. Aus „öffne die Datei -oProxyCommand=…" wird dann „führe diesen Befehl aus". Wie ein Formular, in dem jemand in das Feld „Name" den Satz „und überweise 1000 €" schreibt, und der Sachbearbeiter liest alles vor.

Der Schutz ist alt und einfach: Werte von außen gehören hinter ein --, damit git, ssh und Co. sie nicht als Optionen lesen. Ein Agent, der Shell-Befehle aus Repo-Inhalten, Issue-Texten oder Dateinamen zusammensetzt, ist genau so ein Programm.

Meine Sicht: Das ist die wichtigste Sicherheitsnachricht der Woche für dich, auch wenn Codex nicht dein Werkzeug ist. Ein Coding-Agent mit Shell-Zugriff ist ein Werkzeug, das fremde Eingaben in Befehle verwandelt — das klassische Muster für Injection. Claude Code, Cursor und Copilot haben dieselbe Angriffsfläche. Darum zählen die Sicherheits-Fixes in jedem Changelog, und darum gehört ein Agent in eine Sandbox, wenn er fremde Repos liest.

MCP: Claude Code spricht jetzt das neue Protokoll

Claude Code v2.1.292 (06.10.) „Changed local stdio MCP servers to negotiate protocol version 2026-07-28 by default."[1] Wenn ein älterer Server damit Probleme hat, gibt es einen Ausweg: die Umgebungsvariable MCP_PROTOCOL_NEGOTIATION=legacy.[1]

Die Spec-Version 2026-07-28 ist laut CData die größte Überarbeitung seit dem Start: ein zustandsloser Kern und ein Rahmen für Erweiterungen, zuerst MCP Apps und Tasks. Einige Änderungen sind nicht rückwärtskompatibel.[2]

Protokoll-Verhandlung (MCP): MCP ist die gemeinsame Sprache, mit der ein Agent externe Werkzeuge anspricht — Datenbank, Browser, Ticket-System. Beim Verbinden einigen sich beide Seiten zuerst auf eine Sprachversion. Wie zwei Leute, die am Telefon kurz klären, ob sie Deutsch oder Englisch sprechen. Jetzt schlägt Claude Code zuerst die neue Version vor.

Meine Sicht: Wenn ein selbst gebauter MCP-Server nach dem Update komisch reagiert, ist das der erste Verdacht. Setze die Variable nur als Übergang und hebe den Server auf die neue Version — „zustandslos" macht Server einfacher zu betreiben, nicht schwerer.

Open Weights: Mistral Large 4 kommt, mit Fragezeichen

Die Gewichte sollen „end of this month" folgen. Im Index von Artificial Analysis steht es bei 38, Large 3 bei 9.[1] Eine Mitteilung von Mistral selbst haben wir nicht gefunden. Aktive Parameter (Mixture of Experts): Das Modell besteht aus vielen Spezialisten, aber für jedes Wort arbeiten nur wenige davon. Ein Billion Parameter liegen im Speicher, 49 Milliarden rechnen. Wie ein großes Krankenhaus: alle Ärzte sind im Haus, aber dich behandeln nur zwei.
  • Qwen3.8-27B (Mitte August, Apache 2.0) — die Größe, die auf eine 24-GB-GPU passt. Ausprobieren wenn du lokal mit Ollama arbeitest: ein dichtes 27B-Modell ist einfacher zu betreiben als ein MoE-Riese.[2]

Morgen schauen wir, ob für Haiku fünf Komma fünf erste unabhängige Messungen auftauchen, und wie die Umstellung von GPT fünf Komma fünf in Codex läuft.
