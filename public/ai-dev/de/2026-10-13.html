Claude Code: Hooks, die bei einem Fehler wirklich stoppen

Die wichtigste Zeile der letzten Woche steht tief im Changelog von 2.1.295 (08.10.): „Added onFailure: "block" for command and HTTP hooks, so a hook that fails to start, times out, or exits unexpectedly blocks the action."[1]

Warum das zählt: Viele nutzen Hooks als Schutzzaun. Ein Hook prüft zum Beispiel, ob ein Befehl Secrets anfasst oder in den falschen Ordner schreibt. Wenn dieser Hook aber selbst abstürzt oder hängt, lief die Aktion bisher je nach Fall trotzdem weiter. Der Zaun hatte also ein Loch genau dann, wenn er kaputt war.

Fail-open und fail-closed: Stell dir eine elektrische Tür vor. Bei Stromausfall bleibt sie entweder offen (fail-open) oder zu (fail-closed). Für einen Notausgang willst du offen. Für einen Tresor willst du zu. Ein Sicherheits-Hook ist ein Tresor. Mit onFailure: "block" kannst du ihn jetzt so einstellen.

Dazu kam in derselben Version CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS, eine Obergrenze für Wartezeiten bei Wiederholungen.[1] Simon Willison schrieb passend dazu am 03.10.: „We're going to need default hard budget caps on pretty much everything".[2] Den Text dahinter haben wir nicht gelesen, nur die Überschrift. Die Richtung ist aber klar: Agenten laufen länger und unbeaufsichtigt, also brauchen sie harte Grenzen.

Meine Sicht: Das ist das nützlichste Feature der Woche, auch wenn es niemand bewirbt. Gestern ging es hier um Agenten, die vom Handy aus weiterlaufen. Genau dafür braucht man Hooks, die im Zweifel Nein sagen.

Ausprobieren Geh deine Sicherheits-Hooks durch und setz bei jedem onFailure: "block". Dann bau einen Hook mit Absicht kaputt (falscher Pfad) und prüf, ob die Aktion wirklich stoppt.

Claude Code 2.1.296: Subagenten, MCP und ein halbierter Cache-Preis

Die aktuelle Version ist 2.1.296 vom 09.10.[1] Danach haben wir bis heute nichts Neues gefunden. Anfang Oktober kamen zehn Releases in neun Tagen, von 2.1.287 am 01.10. bis 2.1.296.[2] Die Punkte, die für den Alltag zählen:

  • autoCompactWindow im Frontmatter von Subagenten: Jeder Subagent kann eine eigene Grenze bekommen, ab der er seinen Verlauf zusammenfasst.[1]
  • MCP-Tool-Beschreibungen: „Changed the default limit on MCP tool descriptions and server instructions from 2,048 to 4,096 characters."[1]
  • Sonnet 5.5 Cache-Lesen: „Updated Sonnet 5.5 cache-read pricing to $0.10 per million tokens (was $0.20)."[1]
  • Neu ist auch CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL, um das Modell für Workflow-Subagenten festzulegen.[1]
Auto-Compaction: Ein Agent hat ein begrenztes Gedächtnis pro Sitzung, das Kontextfenster. Wird es voll, fasst er den bisherigen Verlauf zusammen und macht mit der Zusammenfassung weiter. Wie ein Protokoll statt einer Tonaufnahme der ganzen Besprechung. Das spart Platz, aber Details gehen verloren. Mit autoCompactWindow legst du pro Subagent fest, wann das passiert.
Cache-Lesen: Agenten schicken bei jedem Schritt fast denselben langen Text mit, etwa Systemprompt und Dateien. Der Anbieter merkt sich diesen Anfang. Beim nächsten Mal liest er ihn aus dem Speicher, und das kostet nur einen Bruchteil. Bei langen Agent-Läufen ist das oft der größte Posten der Rechnung.

Meine Sicht: Der Cache-Preis ist für Vielnutzer mehr wert, als er klingt. In einer langen Sitzung wird derselbe Kontext hunderte Male gelesen. Eine Halbierung dort trifft direkt die Kosten pro Aufgabe. Die längeren MCP-Beschreibungen sind zweischneidig: Sie helfen dem Modell, ein Tool richtig zu nutzen, kosten aber bei jedem Aufruf Kontext. Wer zehn MCP-Server aktiv hat, zahlt das zehnmal.

Ausprobieren Gib einem Recherche-Subagenten, der viel liest, ein kleineres autoCompactWindow. So verbraucht er den Kontext nicht, bevor er fertig ist.

OpenAI: Decisions API, weniger Tarifstufen und die Frist am Mittwoch

Im API-Changelog von OpenAI stehen drei Punkte, die für Entwickler zählen:[1]

  • Decisions API (Beta, 06.10.): „launched in beta with gpt-6-luna for turning text and images into typed answers."
  • Usage Tiers (06.10.): „Usage tiers were reduced from five to three: Build, Launch, and Grow."
  • GPT-6.1 Sol (29.09.): 2 $ Input und 10 $ Output pro Million Tokens, für Prompts bis 272K Tokens, Multi-Agent-Support als Beta. Gestern hatten wir den Preis nur aus der Fachpresse, jetzt ist er an der Primärquelle bestätigt.
Typisierte Antworten: Normal antwortet ein Modell mit freiem Text, und dein Code muss den Text zerlegen. Eine typisierte Antwort hat ein festes Format, zum Beispiel „ja/nein plus Begründung" oder eine Zahl aus einer Liste. Wie ein Formular mit Ankreuzfeldern statt eines Briefs. Für Code, der mit der Antwort weiterarbeitet, ist das viel robuster.

Für GPT-6 Astra stehen Migrationshinweise im Changelog: Astra unterstützt den Reasoning-Aufwand none nicht, und Tool-Calling braucht die Responses API.[1] Wer alten Code auf Astra umstellt, muss also mehr anpassen als den Modellnamen.

Und die Frist: „On October 14, 2026, GPT-5.5 will retire from ChatGPT, ChatGPT Work, and Codex on all plans". Die API ist ausgenommen.[2] Das ist morgen.

Meine Sicht: Die Decisions API ist kein Coding-Tool im engeren Sinn. Für jeden, der Klassifizierung in Skripten oder CI baut, etwa „ist dieser Commit ein Breaking Change?", ist sie aber genau das richtige Werkzeug. Zusammen mit dem Luna-Preis wird so eine Prüfung pro Aufruf fast kostenlos.

Ausprobieren Heute noch: Such in Codex-Konfigurationen und Skripten nach gpt-5.5. Morgen ist das Modell dort weg.

Lokal: Bei Qwen3.8-27B entscheidet der Reasoning-Schalter

Simon Willison testete am 04.10. Qwen3.8-27B lokal mit Additionsaufgaben, die als Wörter geschrieben waren. Ohne Reasoning lag die Trefferquote bei etwa 24 %. Mit Reasoning waren es 167 von 169 richtigen Antworten, in einem einzigen Pilotlauf.[1]

Reasoning-Modus: Das Modell schreibt erst eine Art Notizzettel mit Zwischenschritten und gibt dann die Antwort. Wie Kopfrechnen gegen schriftliches Rechnen. Das dauert länger und kostet mehr Tokens, ist aber bei mehrstufigen Aufgaben viel genauer.

Meine Sicht: Ein Lauf ist keine Studie. Die Lehre für Ollama-Nutzer ist trotzdem klar: Wer ein lokales Modell schwach findet, sollte zuerst prüfen, ob Reasoning an ist. Auf dem eigenen Rechner kostet es nur Zeit, kein Geld.

Es ist Dienstag, der dreizehnte Oktober, und es ist wieder ruhig. Seit Freitag gibt es keine neue Version von Claude Code und kein neues Coding-Modell. Deshalb schauen wir heute ins Kleingedruckte der letzten Woche.

Die nützlichste Neuerung ist leise. Claude Code kann Hooks seit Version zwei Komma eins Komma zwei neun fünf so einstellen, dass ein abgestürzter oder hängender Hook die Aktion blockiert. Bisher konnte ein kaputter Sicherheits-Hook die Aktion durchwinken. Mein Tipp: Setz bei deinen Sicherheits-Hooks die Option zum Blockieren, und teste sie mit einem absichtlich kaputten Hook.

In Version zwei Komma eins Komma zwei neun sechs kamen weitere Details. Subagenten können eine eigene Grenze für das Zusammenfassen ihres Verlaufs bekommen. MCP-Tool-Beschreibungen dürfen doppelt so lang sein wie bisher. Und laut Changelog kostet das Lesen aus dem Cache bei Sonnet fünf Komma fünf nur noch zehn Cent statt zwanzig Cent pro Million Tokens. Bei langen Agent-Läufen spart das spürbar.

Bei den kleinen Modellen herrscht Preiskrieg. Claude Haiku fünf Komma fünf kostet zehn Cent Input und fünfzig Cent Output pro Million Tokens, genau so viel wie GPT sechs Luna von OpenAI. Laut Simon Willison zählt der neue Tokenizer aber etwa ein Viertel mehr Tokens. Offizielle Benchmarks für Haiku haben wir nicht gefunden.

OpenAI hat eine neue Decisions API als Beta gestartet. Sie macht aus Text und Bildern Antworten mit festem Format. Die Tarifstufen der API sind von fünf auf drei geschrumpft. Und morgen, am vierzehnten Oktober, verschwindet GPT fünf Komma fünf aus ChatGPT und Codex. Such heute noch in deinen Konfigurationen nach dem Modellnamen.

Bei den Benchmarks ist SWE-Bench Verified fast voll. Laut dem Aggregator BenchLM führt Claude Opus fünf mit sechsundneunzig Prozent. Die ersten drei liegen einen Punkt auseinander, das ist Rauschen. Die neuen Modelle stehen dort noch gar nicht. Für Opus fünf Komma fünf gibt es weiter nur die Zahlen von Anthropic selbst.

Für lokale Modelle eine kleine Lehre: Simon Willison testete Qwen drei Komma acht mit siebenundzwanzig Milliarden Parametern. Ohne Reasoning traf es etwa ein Viertel der Aufgaben, mit Reasoning fast alle. Wer ein lokales Modell schwach findet, sollte zuerst den Reasoning-Schalter prüfen.

Bei den Werkzeugen bauen Cursor, Copilot und Claude Code alle dasselbe Muster: ein Chef-Agent mit vielen Helfern. Morgen schauen wir, ob die GPT-fünf-Komma-fünf-Abschaltung reibungslos läuft und ob Anthropic nach vier Tagen Pause eine neue Version von Claude Code bringt.
