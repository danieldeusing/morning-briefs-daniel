Gemini 4 Argon: allgemein verfügbar, aber kein klarer Sieger

Seit dem 13.10. steht im Changelog der Gemini API: „Gemini 4 Argon (gemini-4-argon) generally available (GA)."[1] Angekündigt hatte Google das Modell schon am 30.09. Zuerst bekamen es laut Fachpresse aber keine zahlenden Kunden, sondern „trusted cyber defenders inside its Fairwind Program".[2] Jetzt kann jeder mit einem API-Key es aufrufen.

Preis: Simon Willison nennt 2 $ Input und 10 $ Output pro Million Tokens. Das ist so viel wie GPT-6.1 Sol und die Hälfte von Opus 5.5. Er schreibt aber auch: „on December 1st Argon is set to double in price."[3] Andere Quellen sprechen von einem Einführungspreis, nach dem 4 $ / 20 $ gelten, ohne festes Enddatum.[4] Auf Googles Changelog-Seite steht kein Preis. Rechne also besser mit 4 $ / 20 $, wenn du heute etwas Dauerhaftes baust.

GA (General Availability): Ein Modell durchläuft meist drei Stufen. Erst testen es wenige Eingeladene, dann gibt es eine „Preview", die sich noch ändern darf. Bei GA sagt der Anbieter: Das ist stabil, darauf darfst du Produkte bauen. Wie ein Restaurant nach der Probe-Eröffnung.

Leistung: Googles eigene Zahlen sind gemischt. Wir kennen sie nur aus einem Artikel von Android Headlines, nicht von Google selbst. Laut dem Artikel hat Google 10 der 19 Werte selbst berechnet.[2]

Die einzige unabhängige Zahl, die wir selbst abgerufen haben, ist der Intelligence Index von Artificial Analysis: Argon (High) steht bei 53, Opus 5.5 (max) bei 58, Sonnet 5.5 bei 56.[5] Der Testlauf von Artificial Analysis kostete für Argon laut Willison 2.407 $.[3] Laut Bloomberg finden Google-Mitarbeiter, dass Argon „struggles when put to work on real-world coding tasks and front-end website design". Google widerspricht.[2]

Herstellerangabe: Der Anbieter misst sein eigenes Modell, wählt die Tests aus und rechnet die Werte der Konkurrenz oft selbst nach. Das ist nicht gelogen, aber wie ein Restaurant, das seine eigenen Kritiken schreibt. Erst eine fremde Messung zeigt, ob die Zahl hält.

Meine Sicht: Argon ist kein Opus-Killer. Interessant ist das Muster in Googles eigener Tabelle. Bei kurzen Coding-Aufgaben (DeepSWE) führt Argon, bei langen Terminal-Aufgaben liegt es neun Punkte hinter Opus 5.5. Genau das passt zum Bloomberg-Bericht. Für einen Agenten, der eine Stunde allein im Terminal arbeitet, würde ich weiter Opus oder GPT-6 nehmen. Für viele kleine Code-Fragen zum halben Preis ist Argon einen Test wert, solange der Einführungspreis gilt.

Ausprobieren Willisons llm-gemini-Plugin kann Argon schon.[3] Gib Argon und deinem Standardmodell dieselbe echte Aufgabe aus deinem Repo und vergleiche Ergebnis und Kosten.

Anthropic ersetzt Git: Was passiert, wenn Agenten committen

Der spannendste Text des Tages ist ein Engineering-Beitrag von Anthropic vom 13.10.: „In May 2026, Anthropic averaged around 2,500 code changes merged per day; as of September, we merged over 30,000 per day."[1] Das ist das Zwölffache in vier Monaten. Git hielt das nicht mehr aus. Anthropic hat deshalb ein eigenes Versionskontrollsystem namens Scion gebaut und in fünf Monaten migriert.[1]

Die Größenordnung: „The history of our main branch alone is almost 100 GB, and a compressed working copy is over 25 GB."[2] Die CI checkt laut Anthropic etwa 25 Millionen Mal pro Tag Code aus. Mit normalem git fetch wären das laut Beitrag über 600 PB Datenverkehr pro Tag.[1][2] Willison vermutet, dass Agenten auf Fable- oder Mythos-Niveau hinter dem Sprung stehen. Das ist seine Vermutung, Anthropic sagt es so nicht.[2]

Agenten schreiben mehr Code→12× mehr Merges→CI checkt ständig aus→Git skaliert nicht mehr
Warum Git hier bricht: Git ist so gebaut, dass jeder eine komplette Kopie der ganzen Geschichte hat. Für ein Team von Menschen ist das super. Wenn aber Millionen CI-Läufe am Tag jeweils ein riesiges Repo holen, ist das wie eine Bibliothek, die jedem Besucher alle Bücher nach Hause schickt, nur damit er eine Seite liest.

Meine Sicht: Für deinen Alltag ändert Scion nichts, es ist ein internes Werkzeug. Der Beitrag ist aber ein Blick in die Zukunft. Wenn Agenten die meisten Commits machen, verschiebt sich der Engpass von „Code schreiben" zu „Code mergen, testen und reviewen". Das spürt man auch in kleinen Teams: mehr PRs, mehr CI-Minuten, mehr Merge-Konflikte. Wer heute Agenten parallel laufen lässt, sollte zuerst seine CI-Kosten und seine Review-Kapazität ansehen.

Claude Code 2.1.299: Compaction im Leerlauf und ein Sandbox-Loch weniger

Heute erschien 2.1.299.[1] Zwei Punkte zählen:

  • Idle-Compaction: „a 200K+ token conversation left idle for about 54 minutes is compacted before its one-hour prompt cache expires".[1] Die Schwelle lässt sich über CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS einstellen.
  • Sandbox-Fix: „Fixed a sandboxed shell command being able to write into a --plugin-dir folder, whose code Claude Code reloads and runs outside the sandbox".[1]

Dazu: Warnungen bei /usage, eine neue Variable CLAUDE_CODE_DISABLE_FILE_MENTIONS und ein längerer Stream-Timeout (300 statt 180 Sekunden) für eigene ANTHROPIC_BASE_URL.[1] Laut Tracker ist das der elfte Release im Oktober. Die Versionen 2.1.297 und 2.1.298 tauchen weder dort noch auf GitHub auf.[2]

Sandbox-Escape: Die Sandbox ist ein Käfig, in dem Befehle des Agenten laufen. Der Fehler: Ein Befehl im Käfig konnte Dateien in den Plugin-Ordner legen. Claude Code lädt diesen Ordner später neu und führt ihn außerhalb des Käfigs aus. Der Käfig hatte also eine Klappe, durch die man Code nach draußen schieben konnte.

Meine Sicht: Die Idle-Compaction ist clever. Ein voller Kontext, der nach einer Stunde aus dem Cache fällt, kostet beim nächsten Prompt den vollen Preis. Besser vorher zusammenfassen. Der Haken: Nach der Mittagspause arbeitest du mit einer Zusammenfassung statt mit dem vollen Verlauf. Der Sandbox-Fix ist der wichtigere Teil. Wer mit --plugin-dir arbeitet, sollte heute aktualisieren.

Ausprobieren Update auf 2.1.299. Wer lange Sitzungen nicht verlieren will, setzt CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS höher und prüft, ob das Verhalten passt.

Agent-Praxis: zwei Muster von Willison und Huntley

Willison hat am 13.10. web-edit 0.1a1 veröffentlicht. Die Optimierungen schrieb Opus 5.5, auf Basis eines Profiling-Berichts, den GPT-6 Astra erstellt hatte.[1] Zwei Modelle, zwei Rollen: eines misst, eines baut. Dazu passt der neue Sampling-Profiler in Python 3.15, das am 12.10. erschien.[1]

Geoffrey Huntley beschreibt einen Trick mit Pre-Commit-Hooks. Hält sich der Agent nicht an eine Regel, scheitert der Commit, und der Hook gibt ihm eine Anweisung mit: „Boom: fail the commit, inject a prompt telling the agent to use the diagnostics library."[2]

Meine Sicht: Huntleys Idee ist das Gegenstück zu den blockierenden Hooks aus Claude Code 2.1.295 von gestern. Regeln in einer CLAUDE.md sind Bitten. Ein Hook, der den Commit stoppt und den Grund nennt, ist eine Leitplanke. Das funktioniert mit jedem Agenten, weil Git-Hooks werkzeugneutral sind.

Ausprobieren Nimm die Regel, gegen die dein Agent am häufigsten verstößt. Bau einen Pre-Commit-Hook, der genau das prüft und eine klare Fehlermeldung ausgibt.

Cursor Origin: ein App-Marktplatz für den Agenten

Cursor hat am 13.10. einen App-Marktplatz für Origin gestartet: „Origin now integrates with over 20 apps for deployments, CI, code review, security, monitoring, and project management."[1] Dabei sind unter anderem Cloudflare, Linear, Sentry, Socket Security, Vercel und CodeRabbit. Jeder kann eigene Apps einreichen.[1]

Marktplatz für Agenten-Integrationen: Ein Agent kann nur das tun, wofür er Werkzeuge hat. Ein Marktplatz ist wie ein App-Store für diese Werkzeuge: Statt jede Anbindung selbst zu bauen, klickst du „Sentry" an, und der Agent kann Fehlerberichte lesen. Technisch ähnelt das MCP-Servern, nur kuratiert vom Tool-Hersteller.

Meine Sicht: Claude Code hat seit 2.1.292 (06.10.) Plugin-Installation aus Marketplaces, jetzt zieht Cursor nach.[2] Alle großen Harnesses landen beim selben Modell. Der Unterschied liegt künftig weniger im Agenten als in der Frage, wer die Integrationen prüft. „Offen für Einreichungen" heißt auch: Jede App bekommt Zugriff auf deinen Code. Socket Security auf der Liste ist da fast ironisch.
