Gemini 4 Argon kommt in Copilot an

Gestern ging es um die Gemini API, heute um die Verteilung. Laut GitHub ist Argon seit dem 13.10. „now generally available in GitHub Copilot".[1] Freigeschaltet wird es für „Copilot Pro+, Max, Business, and Enterprise". Der Haken steht im selben Text: „Rollout will be gradual."[1] Wer Argon heute im Modell-Menü nicht sieht, hat also nichts falsch gemacht.

In der Gemini API heißt das Modell gemini-4-argon. Google nennt es „our most capable model built for complex coding, agentic, math, and science tasks".[2]

Preis, weiter nur aus einer Quelle: Simon Willison nennt 2 $ Input und 10 $ Output pro Million Tokens zum Start. Und: „on December 1st Argon is set to double in price - so it will be the same price as Opus 5.5."[3] Auf Googles Changelog steht kein Preis. Andere Preis-Tracker nennen einen Einführungspreis, der später auf 4 $/20 $ steigt, ohne Datum. Der 01.12. stammt also nur von Willison. Bis Google das selbst bestätigt, gilt meine Empfehlung von gestern: Rechne mit dem doppelten Preis, wenn du etwas Dauerhaftes baust.

Modell in Copilot vs. in der API: In der API zahlst du pro Token, direkt bei Google. In Copilot zahlst du dein Copilot-Abo, und GitHub rechnet die Nutzung gegen dein Kontingent. Für dich heißt das: In Copilot kannst du Argon testen, ohne einen Google-Account oder Key einzurichten. Ob der Dezember-Preis auch dort etwas ändert, sagt GitHub nicht.

Leistung: Daran hat sich seit gestern nichts geändert. Googles eigene Zahlen, nur über Sekundärquellen gelesen: DeepSWE v1.1 77,9 % gegen 74,2 % für Opus 5.5, aber Terminal-Bench 4.0 57,4 % gegen 66,4 %.[4] Unabhängig ist nur der Intelligence Index von Artificial Analysis: Argon (high) 53, Opus 5.5 (max) 58.[5] Pro Aufgabe kostete der AA-Lauf für Argon 1,99 $, für Opus 5.5 5,98 $.[5]

Meine Sicht: Copilot ist der eigentlich wichtige Kanal für Argon. Dort sitzen die Entwickler, die nie einen Gemini-Key anlegen würden. Wer Copilot Pro+ hat, bekommt jetzt einen kostenlosen A/B-Test: dieselbe Aufgabe einmal mit Argon, einmal mit deinem Standardmodell. Für lange Agenten-Läufe im Terminal bleibe ich skeptisch, die Terminal-Bench-Lücke von neun Punkten ist Googles eigene Zahl.

Ausprobieren Wenn Argon in deinem Copilot-Menü auftaucht: eine echte Bug-Fix-Aufgabe aus deinem Repo, zwei Modelle, Ergebnis und Anzahl der Korrekturrunden vergleichen.

GitHub blockiert Anthropic-Keys beim Push

Seit dem 13.10. erkennt GitHubs Secret Scanning zwei neue Typen: anthropic_service_api_key und anthropic_user_api_key. Beide sind laut GitHub „blocked with push protection by default".[1] Das gilt für alle Repos mit aktivem Secret Scanning, „including free public repositories".[1]

Push Protection: GitHub schaut sich deinen Commit an, bevor er auf dem Server landet. Steht darin etwas, das wie ein API-Key aussieht, lehnt GitHub den Push ab. Das ist wie ein Türsteher, der dich nicht mit dem Hausschlüssel in der Hand auf ein öffentliches Foto lässt.

Meine Sicht: Das ist kein Nebenthema. Agenten schreiben heute viele Commits, und sie legen gern .env-Dateien, Testskripte oder Debug-Logs an. Ein Claude-Key in so einer Datei kostet im schlimmsten Fall echtes Geld. Der Block hilft, ersetzt aber kein .gitignore. Achtung bei Agent-Läufen: Wenn der Push abgelehnt wird, darf der Agent nicht versuchen, die Sperre zu umgehen. Das gehört als Regel in deine Hooks oder Anweisungen.

Ausprobieren Prüfe, ob Secret Scanning in deinen privaten Repos aktiv ist. Für öffentliche Repos ist es laut GitHub ohnehin dabei.

Claude Code 2.1.300: Advisor auf AWS, bessere Kosten-Telemetrie

Am 14.10. kamen zwei Versionen. Über 2.1.299 haben wir gestern geschrieben: Idle-Compaction für Gespräche ab 200K Tokens nach etwa 54 Minuten Leerlauf.[1] Danach folgte 2.1.300:[1]

  • /advisor auf Claude Platform on AWS: „no advisor runs until you pick one with /advisor, advisorModel or --advisor".
  • OpenTelemetry: neue Felder für Tokens, die beim Anlegen des Prompt-Caches anfallen.
  • Beenden: „Changed exit to force-kill background commands still running 1.5 seconds after being asked to stop".
Cache-Creation-Tokens: Wenn Claude einen langen Kontext zum ersten Mal sieht, legt es einen Cache an. Das kostet einmal etwas mehr, danach wird jeder weitere Aufruf billiger. Wer nur „Tokens gesamt" misst, sieht nicht, wo das Geld hingeht. Die neuen Felder machen diesen Posten sichtbar.

Meine Sicht: Für die meisten ist das ein unspektakulärer Release. Wer Claude Code im Team mit OTel überwacht, bekommt aber endlich die Zahl, die zur Idle-Compaction von 2.1.299 passt: Wie viel kostet es, den Cache neu aufzubauen? Das Force-Kill nach 1,5 Sekunden ist gut gegen hängende Dev-Server, kann aber einen Job abschneiden, der beim Beenden noch aufräumt.

Claude Code 2.1.293 (07.10.) hat Haiku 5.5 hinzugefügt, jetzt das Standard-Haiku-Modell, mit 1M Kontext (0,10 $/0,50 $ pro Mio. Tokens).[1]

Ausprobieren Wer OTel-Export nutzt: ein Dashboard-Panel für Cache-Creation-Tokens anlegen und eine Woche beobachten.

Copilot HydraFusion Max: das Modell wählt das Modell

GitHub hat am 14.10. HydraFusion erweitert. Die Idee: „HydraFusion orchestrates multiple models to produce a single response."[1] Du wählst kein Modell mehr pro Aufgabe. Die neue Variante Max ist laut GitHub „tuned for frontier capability on more demanding tasks" und nutzt mehr Reasoning, wo es zählt.[1] Beide laufen in VS Code, in der Copilot-App und in der Copilot CLI, für Pro, Pro+, Business und Enterprise. Voraussetzung: Preview-Features sind aktiviert. Beide „remain in research preview".[1]

Modell-Orchestrierung: Statt eines Modells arbeitet ein kleines Team. Ein Dirigent verteilt Teilaufgaben an verschiedene Modelle und setzt die Antworten zusammen. Gut für Qualität, schlecht für Vorhersagbarkeit: Du weißt nicht genau, wer was gemacht hat.

Meine Sicht: Hier zeigt sich ein Gegentrend zum Modell-Menü. Copilot nimmt dir die Wahl ab, Claude Code und Codex geben dir mehr Regler. Was HydraFusion Max kostet, steht im Beitrag nicht. Bei „research preview" und unklarer Abrechnung würde ich es nur für einzelne harte Aufgaben nutzen, nicht als Standard.

Harness-Runde: Cline und OpenHands bewegen sich

Cline 4.1.24 (13.10.) ändert den Standard: „With no model chosen, the Cline and OpenRouter providers now use Claude Sonnet 5.5."[1] Dazu kommen Haiku 5.5 und drei neue Provider. Parallel erschien Cline Desktop 0.0.46.[1]

OpenHands 1.27.0 und 1.27.1 (12.10.) bringen „OpenCode and Pi as built-in ACP agents on local backends".[2]

ACP (Agent Client Protocol): MCP verbindet einen Agenten mit Werkzeugen. ACP verbindet eine Oberfläche mit einem Agenten. OpenHands wird damit zur Hülle, in der auch fremde Agenten wie OpenCode laufen. Wie ein Fernseher, an den du verschiedene Receiver anschließt.

Codex CLI steht stabil bei 0.162.1 vom 09.10., ein TUI-Absturz-Fix. Die Alphas von 0.163.0 kamen am 13. und 14.10. bis alpha.11.[3] Cursor hatte am 13.10. den Origin Marketplace mit über 20 Apps, am 06.10. die Fernsteuerung lokaler Agenten aus der iOS-App.[4]

Meine Sicht: Clines Wechsel auf Sonnet 5.5 als Standard zeigt, wohin der Markt geht. Die Open-Source-Harnesses setzen nicht auf das billigste, sondern auf das solide Mittelklasse-Modell. OpenHands geht einen anderen Weg und wird zur Plattform für andere Agenten. Für dich als Nutzer heißt ACP: weniger Lock-in, weil du den Agenten tauschen kannst, ohne die Oberfläche zu wechseln.

Ausprobieren Wer OpenHands lokal nutzt: OpenCode als ACP-Agent einhängen und mit dem eingebauten Agenten auf derselben Aufgabe vergleichen.

API-Fristen: Google räumt auf, OpenAI wird schneller

Google hat am 08.10. Deprecations angekündigt: gemini-3.7-flash wird durch 3.8-flash ersetzt. deep-research-pro-preview-12-2025 „will be shut down on October 23, 2026".[1] Wer das Preview-Modell in einem Skript fest eingetragen hat, hat noch gut eine Woche.

Bei OpenAI gibt es seit dem 08.10. einen Ultrafast-Modus für GPT-6.1 Sol in der Responses API, er soll die Zeit zwischen den Ausgabe-Tokens senken. Am 06.10. kam eine Decisions API als Beta mit gpt-6-luna, laut OpenAI „10x faster than the Responses API".[2]

Meine Sicht: Geschwindigkeit wird bei OpenAI zum eigenen Produkt. Für Agenten, die viele kleine Tool-Calls machen, zählt die Latenz pro Schritt oft mehr als ein Punkt mehr im Benchmark.
