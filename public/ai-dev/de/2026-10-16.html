Copilot macht Security zur Agenten-Arbeit

GitHub hat am 15.10. zwei Security-Funktionen auf GA gesetzt. Beide verschieben dieselbe Arbeit vom Menschen zum Agenten.

Agentic Autofix für Code-Scanning-Alerts. Laut GitHub „remediates alerts by working across your codebase the way a developer would“.[1] Copilot liest die relevanten Dateien, schlägt einen Fix vor, lässt CodeQL erneut laufen und öffnet dann einen Draft-PR. Du kannst bis zu 25 Alerts auswählen, Copilot fixt sie in einem PR. Das gilt nur für Alerts auf dem Default-Branch. Verfügbar ist es für Kunden mit Code Security oder Advanced Security auf GitHub Enterprise Cloud. Abgerechnet wird über AI Credits aus dem Code-Security-Budget plus Actions-Minuten. Konkrete Preise nennt GitHub nicht.[1]

AI Scan für Pull Requests. Das Werkzeug sucht Schwachstellen in PR-Änderungen, vor allem in Sprachen und Frameworks, die CodeQL noch nicht abdeckt. Es läuft auf öffentlichen Repos von Organisationen und Personen. Für private Repos braucht es Code Security oder Advanced Security, eine Copilot-Lizenz aber nicht. Wichtig: Die Funde „do not fail the code scanning check and cannot block pull request merges“.[2] Auf PRs aus Forks und von Dependabot läuft der Scan nicht.

CodeQL als Prüfer: CodeQL ist GitHubs regelbasierter Code-Scanner. Er rät nicht, er sucht nach festen Mustern. Beim Autofix schreibt das Sprachmodell den Fix, und CodeQL prüft danach, ob der Alert wirklich weg ist. Das ist wie ein Lehrling, der repariert, und ein Meister, der danach mit dem Messgerät nachmisst.

Meine Sicht: Der Autofix hat das richtige Muster. Ein Modell schlägt vor, ein deterministisches Werkzeug prüft, ein Mensch merged. So sollten Agenten-Workflows grundsätzlich aussehen. Beim AI Scan bin ich vorsichtiger. Ein KI-Fund, der nichts blockiert, ist ein Hinweis, kein Gate. Das ist ehrlich von GitHub, heißt aber auch: Es ist eine zweite Meinung, kein Ersatz für Tests. Die offene Frage ist der Preis. „AI Credits“ ohne Zahl machen jede Budgetplanung zum Ratespiel.

Ausprobieren Auf einem öffentlichen Repo mit aktivem Code Scanning den AI Scan einschalten und eine Woche lang zählen, wie viele Funde echt sind.

Scion: Anthropic baut sich ein eigenes Git

Am 13.10. hat Anthropic beschrieben, warum es Git für sein Monorepo ersetzt hat. Die Zahlen sind der eigentliche Punkt. Im Mai lag Anthropic bei „around 2,500 code changes merged per day“. Im September waren es „over 30,000 per day“.[1] Die Historie des Main-Branch ist „almost 100 GB“ groß. Für CI laufen etwa 25 Millionen Checkouts pro Tag, Agenten-Sandboxen nicht mitgezählt.[1]

Git geht davon aus, dass jeder Client offline arbeitet und eine volle Kopie hat. Anthropics Clients sind aber vor allem Agenten und Jobs, die immer online sind. Scion ist deshalb serverzentriert. Ein Team von sieben Leuten hat es gebaut und die Migration in fünf Monaten abgeschlossen. Freigeben will Anthropic Scion nicht: Es weiche zu weit von Git ab und hänge an interner Werkzeugkette. Stattdessen teilt Anthropic das Design, damit andere die Ideen auf Git anwenden können.[1]

Monorepo und Merge-Rate: Ein Monorepo ist ein einziges Repository für den Code einer ganzen Firma. Jede Änderung, die in den Hauptzweig kommt, ist ein Merge. Zwölfmal mehr Merges in vier Monaten ist wie eine Landstraße, auf der plötzlich Autobahnverkehr fährt. Irgendwann ist nicht mehr das Auto das Problem, sondern die Straße.

Meine Sicht: Das ist für dich kein Werkzeug, aber ein Blick in die Zukunft. Wenn Agenten schreiben, verschiebt sich der Engpass weg vom Code hin zu Versionierung, CI und Review. Das spürst du schon im Kleinen: viele Worktrees, viele parallele Branches, lange CI-Queues. Die Zahlen sind Anthropics eigene Angaben und nicht unabhängig geprüft. Die Richtung halte ich trotzdem für glaubwürdig.

Claude Code 2.1.301: Grep lügt nicht mehr

Version 2.1.301 kam am 15.10. mit einer langen Liste von Fixes.[1] Die wichtigsten für den Alltag:

  • Grep und Glob: Bisher meldeten sie „keine Treffer“, wenn das Suchprogramm vorher abstürzte. Jetzt kommt ein Fehler, der sagt, dass die Suche gescheitert ist.
  • Retry-Watchdog: Neu ist CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS. Im unbeaufsichtigten Retry-Modus bricht Claude Code eine Anfrage ab, wenn das Nutzungslimit erst zu spät zurückgesetzt wird. Bisher wartete es.
  • Worktrees: Beim Beenden wurde ein Worktree aus einem WorktreeCreate-Hook ohne Nachfrage gelöscht, auch mit nicht gepushten Commits. Das ist behoben.
  • Modellwechsel: Wer auf ein Modell mit kleinerem Kontext wechselte, konnte ohne Nachfrage Credits für eine Zusammenfassung verbrauchen. Auch behoben.
  • OpenTelemetry: tool_decision-Events tragen jetzt classifier_verdict und permission_mode. Du siehst also, ob der Auto-Mode-Klassifikator oder eine Regel entschieden hat.
Falsches „nichts gefunden“: Ein Agent glaubt seinen Werkzeugen. Meldet die Suche „keine Treffer“, schließt er: Diese Funktion gibt es nicht. Dann schreibt er sie neu, und du hast doppelten Code. Ein ehrlicher Fehler ist viel besser als eine leere Antwort.

Meine Sicht: Der Grep-Fix ist der wichtigste Eintrag, auch wenn er klein aussieht. Stille Falsch-Negative sind der teuerste Fehlertyp bei Agenten, weil niemand sie bemerkt. Der Retry-Watchdog ist für alle interessant, die Claude Code per Cron oder in CI laufen lassen. Ein Lauf, der stundenlang auf ein Limit wartet, blockiert sonst alles dahinter.

Aus derselben Woche noch nachzutragen: Das Standard-Limit für MCP-Tool-Beschreibungen stieg von 2.048 auf 4.096 Zeichen, und Hooks kennen jetzt onFailure: "block".[1]

Ausprobieren Wer Claude Code unbeaufsichtigt laufen lässt: die neue Variable setzen und prüfen, ob dein Job bei einem Limit sauber abbricht statt zu hängen.

Haiku 5.5: billig und jetzt Standard-Haiku

Claude Haiku 5.5 erschien am 07.10. Anthropic nennt 0,10 $ Input und 0,50 $ Output pro Million Tokens für Prompts bis 100.000 Tokens, darüber 0,50 $/2,50 $.[1] Die Modell-ID ist claude-haiku-5-5. Auf Terminal-Bench 4.0 nennt Anthropic 39,2 %, auf FrontierCode 1.1 46,4 %. Beides sind Herstellerzahlen, einen SWE-Bench-Wert gibt Anthropic nicht an.[1]

Bestätigung zu gestern: Wir schrieben, Claude Code 2.1.293 habe Haiku 5.5 zum Standard-Haiku gemacht, mit 1M Kontext. Das stimmt: Die GitHub-Release-Notes von 2.1.293 (07.10.) nennen Haiku 5.5 das Standard-Haiku auf der Anthropic-API mit 1M Kontext.[2] Anthropics Launch-Seite nennt das Kontextfenster nicht.

Meine Sicht: Der Preis ist die Geschichte. Haiku 5.5 kostet beim Input ein Zwanzigstel von GPT-6.1 Sol oder Argon. Für Sub-Agenten, die Dateien lesen, Logs zusammenfassen oder Commits beschreiben, ist das ein klarer Kandidat. Für die eigentliche Planung bei langen Agenten-Läufen würde ich es nach 39,2 % auf Terminal-Bench nicht einsetzen.

Ausprobieren Einen Sub-Agenten, der heute auf Sonnet läuft, für eine Woche auf claude-haiku-5-5 umstellen und Kosten gegen Nacharbeit vergleichen.

Es ist Freitag, der sechzehnte Oktober. Gestern gehörte GitHub, und fast alles drehte sich darum, Agenten mehr Arbeit zu geben.

Copilot kann jetzt Code-Scanning-Alerts selbst beheben. Der Agent liest den Code, schlägt einen Fix vor, lässt CodeQL noch einmal prüfen und öffnet einen Draft-Pull-Request. Bis zu fünfundzwanzig Alerts gehen in einen Pull Request. Dazu ist der AI Scan für Pull Requests allgemein verfügbar. Er sucht Schwachstellen auch in Sprachen, die CodeQL nicht kennt, blockiert aber keine Merges. Was das in AI Credits kostet, sagt GitHub nicht.

Wichtig für alle Copilot-Nutzer: Am sechzehnten November fallen Claude Opus vier Komma acht, Claude Opus fünf und GPT fünf Komma sechs Terra weg. Der empfohlene Ersatz ist Opus fünf Komma fünf beziehungsweise GPT sechs Komma eins Sol.

Anthropic hat erklärt, warum es Git durch ein eigenes System namens Scion ersetzt hat. Im Mai lag die Firma bei rund zweieinhalb Tausend Merges am Tag, im September bei über dreißig Tausend. Git ist für Menschen gebaut, die offline arbeiten. Agenten sind immer online und erzeugen viel mehr Änderungen. Scion wird nicht veröffentlicht, aber das Design ist ein Blick darauf, wo der nächste Engpass liegt.

Claude Code ist bei Version zwei Komma eins Komma dreihunderteins. Der wichtigste Fix: Grep und Glob melden jetzt einen Fehler, wenn die Suche scheitert, statt fälschlich keine Treffer zu melden. Neu ist außerdem eine Einstellung, mit der unbeaufsichtigte Läufe an einem Nutzungslimit abbrechen, statt stundenlang zu warten.

Bei den Benchmarks bleibt es dünn. Google zugeschrieben werden für Gemini vier Argon siebenundsiebzig Komma neun Prozent auf DeepSWE, eine Primärquelle gibt es dafür nicht. Das unabhängige Board ist vom zweiundzwanzigsten September, und dort liegen die besten Modelle gleichauf bei vierundsiebzig Prozent.

Eine Bestätigung zu gestern: Laut den GitHub-Release-Notes von Claude Code zwei Punkt eins Punkt zwei neun drei ist Haiku fünf Komma fünf das Standard-Haiku und hat eine Million Tokens Kontext. Sicher ist der Preis: zehn Cent pro Million Input-Tokens. Damit ist es ein guter Kandidat für günstige Sub-Agenten.

Bei OpenAI ist GPT sechs Komma eins Sol inzwischen Standard in der Codex CLI und kostet zum Start genauso viel wie Argon. Cursor, Cline und OpenHands hatten ruhige Tage, lokal gab es keine neuen Coding-Modelle. Morgen schauen wir, ob das DeepSWE-Board die neuen Modelle endlich listet.
