Cline: drei Releases an einem Montag

Gestern stand Cline noch in unserer Still-Liste. Heute hat das Projekt drei Pakete auf einmal veröffentlicht, alle am 26.10.[1] Damit ist Cline das einzige Coding-Tool mit echter Bewegung seit Freitag.

Desktop 0.0.49 (als „Latest“ markiert) wird mehr zur IDE. Es gibt einen Changes-Knopf für die Änderungen des Agenten, und „an integrated terminal panel opens at the bottom of the window“.[1] Startet der Hub nicht, zeigt die App jetzt eine eigene Fehlerseite statt einfach zu hängen.

CLI 3.0.74 löst ein Problem, das jeder kennt, der mehrere Fenster offen hat: „Opening a task that's already running in another Cline app now attaches to that run.“[1] Bisher konnte so ein zweiter Lauf entstehen. Außerdem hängen hub status und doctor nicht mehr, und Kimi K3 bekommt für die Stufen Extra High und Max die Reasoning-Stufe max.[1]

SDK 0.2.0 ist für alle wichtig, die eigene Agenten auf Cline bauen. „Model requests retry at most 3 times after the first attempt (down from 5).“[1] Das SDK kann sich jetzt auch an eine laufende Sitzung wieder anhängen. Und der Gemini-Provider schickt die native Google-Suche nicht mehr mit.[1]

Retry-Obergrenze: Wenn ein Modell-Aufruf scheitert, versucht das Tool es automatisch noch einmal. Die Obergrenze sagt, wie oft. Das ist wie ein Anruf bei einer besetzten Hotline: Nach drei Versuchen legst du auf, statt fünfmal in der Warteschleife Geld zu verbrennen. Bei einem Agenten kostet jeder Versuch Token und Zeit.

Meine Sicht: Die Desktop-App ist der interessante Teil. Ein Terminal und eine Diff-Ansicht in derselben App zeigen, wohin Cline will: weg vom reinen VS-Code-Plugin, hin zu einer eigenen Oberfläche, wie Cursor und die Claude-App. Ob das gegen Cursor besteht, ist offen. Die Senkung von 5 auf 3 Retries ist klein, aber richtig. Fünf Wiederholungen verstecken einen kaputten Provider zu lange und kosten Geld. Wer im SDK eigene Logik auf viele Retries gebaut hat, sollte das nach dem Update prüfen.

Ausprobieren Desktop 0.0.49 einmal parallel zur CLI öffnen und denselben Task in beiden starten. Wenn das Anhängen an den laufenden Lauf klappt, ist Cline für Arbeit über mehrere Fenster endlich brauchbar.

Eine Rangliste für Harness plus Modell

Die meisten Benchmarks messen ein Modell allein. Der Coding Agent Index v2.0 von Artificial Analysis misst dagegen die Kombination aus Werkzeug und Modell.[1] Auf der Vergleichsseite stehen bei unserem Abruf drei Einträge:

  • Claude Code mit Opus 5.5 (max): 62
  • Codex mit GPT-6 Astra (max): 55
  • Opencode mit GLM-5.3: 49
Harness: Das Programm um das Modell herum. Es liest Dateien, ruft Werkzeuge auf, führt Befehle aus und entscheidet, was das Modell als Nächstes sieht. Das Modell ist der Motor, der Harness ist das Auto. Ein starker Motor in einem schlechten Auto gewinnt kein Rennen.

Drei Einschränkungen. Erstens zeigt die Seite kein Datum, und die Tabelle lädt per JavaScript nach. Wir haben nur diese drei Werte gesehen, nicht die ganze Liste. Cline, Cursor oder Aider fehlen also vielleicht nur in unserem Ausschnitt. Zweitens trennt der Index nicht, wie viel vom Abstand das Modell und wie viel der Harness bringt. Drittens nutzt der Codex-Eintrag GPT-6 Astra. Das Standardmodell der Codex CLI ist laut Sekundärberichten seit Version 0.161.0 aber GPT-6.1 Sol (Versionen später wurde die Standard-Kennzeichnung in der Modellauswahl wieder entfernt).[2] Das haben wir nicht in einer Primärquelle geprüft.

Meine Sicht: Trotzdem ist das die ehrlichere Frage. Du arbeitest nie mit einem nackten Modell, sondern immer mit einem Harness. Der Abstand von 7 Punkten zwischen Claude Code und Codex ist deutlich. Er sagt aber nicht, dass Codex mit einem anderen Modell nicht aufholen könnte. Für die eigene Wahl reicht er als Hinweis, nicht als Urteil.

Lokal: Ollama reicht Kontext an Coding-Tools weiter

Ollama 0.40.11 vom 24.10. ist weiter die aktuelle stabile Version.[1] Für Coding ist eine ältere Änderung wichtiger: Seit 0.40.9 vom 22.10. gibt ollama launch Kontextlänge und Fähigkeiten von Cloud-Modellen an Coding-Tools weiter.[1] Das Tool muss dann nicht raten, wie groß das Fenster ist.

In 0.40.10 vom 23.10. kam Nemotron 3.5 Bolt E4B von NVIDIA dazu: ein Bild-und-Text-Modell auf Basis von Gemma 4, mit 128K Kontext und Tool-Use. Es bringt einen DFlash-Entwurf für Speculative Decoding mit.[1]

Speculative Decoding: Ein kleines, schnelles Modell rät die nächsten Wörter vor. Das große Modell prüft den ganzen Entwurf in einem Schritt und übernimmt, was stimmt. Das ist wie ein Praktikant, der einen Brief vorschreibt, und die Chefin streicht nur die falschen Stellen. Die Antwort ist gleich gut, kommt aber schneller.

Meine Sicht: Mit Tool-Use und 128K Kontext ist Bolt E4B ein Kandidat für kleine lokale Agenten-Aufgaben. Coding-Messungen dazu haben wir nicht gefunden.

Kurz notiert

  • OpenHands 1.33.0 (23.10.) setzt eine Regel durch: Fremdpakete müssen sieben Tage alt sein, bevor sie ins Projekt kommen („enforce seven-day third-party release-age policy“). Dazu kommen ein Dialog zum Installieren von MCP-Servern und das Maskieren von Secrets.[1] Die Wartezeit ist eine einfache Bremse gegen Supply-Chain-Angriffe. Die kannst du auch im eigenen Projekt nachbauen.
  • OpenAI API: Seit 20.10. hält das Prompt-Caching in der Responses API bis zu 12 Stunden. Seit 16.10. haben die Sandboxen der Agents API das Artifact SDK und Skills.[2] Für Coding-Agenten mit langem Systemprompt und großem Repo-Kontext kann der längere Cache die Kosten senken.
  • Agent Skills liegen seit 22.10. bei der Agentic AI Foundation unter der Linux Foundation. Die AAIF hostet auch MCP.[3] Halte eigene Skills herstellerneutral.
Prompt-Caching: Der Anbieter merkt sich den gleichbleibenden Anfang deiner Anfrage, zum Beispiel Systemprompt und Repo-Übersicht. Bei der nächsten Anfrage zahlst du für diesen Teil weniger. Das ist wie eine Stammkundenkarte: Beim zweiten Besuch musst du dich nicht noch einmal vorstellen.
