Fast Mode für Opus 4.8 wird entfernt

Claude Code 2.1.316: Fast Mode für Opus 4.8 endet

Das Release vom 31.10. enthält eine Zeile, die du kennen solltest: „Deprecated fast mode for Opus 4.8 as of October 30, 2026; it will be removed on November 30, 2026.“[1] Neu ist außerdem die Umgebungsvariable CLAUDE_CODE_DISABLE_ULTRATHINK.[1]

Fast Mode: Ein Schalter, mit dem dasselbe Modell schneller antwortet. Das ist wie ein Express-Zuschlag bei der Post: gleicher Brief, schnellere Zustellung. Fällt der Schalter weg, läuft Opus 4.8 nur noch im normalen Tempo.

Meine Sicht: Das ist ein Aufräum-Signal. Opus 4.8 ist nicht mehr das Spitzenmodell, die Ranglisten dieser Woche führen Opus 5.5. Anthropic will offenbar keine Sonderwege für ältere Modelle mehr pflegen. Wenn du in einem Skript, einer CI-Pipeline oder deinen Settings Opus 4.8 mit Fast Mode fest eingestellt hast, plane den Wechsel jetzt. Am 30.11. bricht sonst etwas, vermutlich nachts in einem Lauf, den niemand beobachtet.

Ausprobieren grep -rn "4-8" ~/.claude .claude über deine Configs laufen lassen. Fünf Minuten jetzt sparen dir einen kaputten Lauf am 30.11.

Nachtrag: Schreibsperre jetzt offiziell

Gestern stützten wir uns für 2.1.314 nur auf einen Drittanbieter-Spiegel. Der offizielle Changelog bestätigt es jetzt mit dem genauen Namen: „Added permissions.blockWritesOutsideWorkingDirectories: Write, Edit and NotebookEdit refuse paths outside the working directories in every permission mode“.[1] Wichtig ist „in every permission mode“: Die Sperre gilt auch, wenn du den Agenten sonst frei laufen lässt.

Ein kleineres Detail aus 2.1.312 (27.10.): Das Nutzungslimit heißt in den Meldungen jetzt „5-hour limit“ statt „session limit“.[1] Das ist nur ein neuer Name, aber er ist ehrlicher. Das Limit hängt an einem Zeitfenster, nicht an deiner Sitzung.

Meine Sicht: Schalte die Schreibsperre ein, wenn du Claude Code mit weiten Rechten laufen lässt. Sie kostet dich nur dann etwas, wenn dein Workflow bewusst außerhalb des Projekts schreibt, etwa in /tmp. Dann nimm das Verzeichnis als weiteres Arbeitsverzeichnis auf.

Gemini 4 Carbon: vorn, aber nur um eine Nasenlänge

Stand Samstag hat sich am Zugang nichts geändert. Carbon geht laut Presseberichten nur an ausgewählte Firmen aus der Cyber-Abwehr, über Googles Fairwind-Programm. Einen öffentlichen Zeitplan gibt es nicht.[1] Die Google-Primärquelle lieferte heute keinen Text, die Fakten stammen aus Sekundärpresse.

Drei Ranglisten setzen Carbon auf Platz 1. Die Abstände sind aber klein:

  • Artificial Analysis Intelligence Index: Carbon 59, Opus 5.5 58, GPT-6 Astra 57, GPT-6.1 Sol 55, Sonnet 5.5 54.[2] Ein allgemeiner Index, kein Coding-Test, und ohne Datum auf der Seite.
  • LMArena Text: Carbon 1528 ±9, als „preliminary“ markiert. Dahinter Gemini 4 Argon 1520 und Opus 5.5 1509.[3] Die Seite ist auf den 27.10. datiert, also vor der Ankündigung. Den Coding-Tab konnten wir nicht auslesen.
  • Vals: Vals Index 70,36 % (Platz 2), Terminal-Bench 4.0 63,13 % (Platz 4).[4] Beim Coden ist Carbon also Spitzengruppe, nicht Spitze.

Google meldet dazu eigene Sicherheitswerte: 88,2 % auf SEC-bench Pro und 0 % erfolgreiche Prompt-Injection-Angriffe im Grey-Swan-Test. Opus 5.5 liegt dort bei 1 %, GPT-6 Astra bei 8,5 %.[1] Das sind Herstellerangaben. Eine unabhängige Messung haben wir nicht gefunden.

Prompt Injection: Ein Angreifer versteckt Befehle in Text, den der Agent liest, zum Beispiel in einer README oder einem Issue. Der Agent hält das für einen Auftrag und führt ihn aus. Das ist wie ein gefälschter Zettel „Bitte Tresor öffnen“, den jemand in die Hauspost schmuggelt.

Meine Sicht: Ein Punkt Abstand im AA-Index und 8 Elo-Punkte bei einer Fehlerspanne von ±9 sind keine Führung, sondern ein Gleichstand. Interessant für dich ist eher die Prompt-Injection-Zahl. Wenn sie unabhängig hält, ist das für Agenten, die fremde Repos lesen, wichtiger als ein Punkt mehr im Index. Bis dahin bleibt es eine Behauptung im eigenen Test.

GPT-6.1 Terra: Wochenbilanz

Terra kam am 26.10., zu 1 $ pro Million Input-Token und 5 $ pro Million Output-Token. Die API-ID ist gpt-6.1-terra, das Modell ist auch in Codex verfügbar.[1] OpenAI meldet auf Terminal-Bench 4.0 im höchsten Effort-Modus 50,3 %, gegen 21,5 % beim Vorgänger GPT-5.6 Terra.[1] OpenAI sagt selbst: Für die schwersten Coding-Aufgaben bleiben GPT-6.1 Sol oder GPT-6 Astra die Empfehlung.[1]

Unabhängig führt Vals Terra im allgemeinen Vals Index bei 60,17 %, Platz 10 von 28.[2] Diese Zahl haben wir nur aus einem Such-Snippet, nicht von der Seite selbst.

Zum Vergleich der Billig-Stufe: Claude Haiku 5.5 kostet laut Anthropic 0,10 $ und 0,50 $ pro Million Token, bei Prompts bis 100.000 Token.[3] Eine SWE-bench-Verified-Zahl nennt Anthropic für Haiku 5.5 nicht.

Modell-Kaskade: Du schickst jede Aufgabe zuerst an ein billiges Modell. Nur wenn es scheitert oder unsicher ist, geht sie an ein teures. Das ist wie eine Hotline: Die erste Stufe löst die einfachen Fälle, die Spezialisten bekommen nur den Rest.

Meine Sicht: Terra ist genau das, was OpenAI verspricht, ein günstiger Arbeiter. Für Routine wie Umbenennen, Tests ergänzen oder Logs zusammenfassen reicht das. Für Architekturfragen nicht. Die eigentliche Frage ist, ob Terra sich gegen Haiku 5.5 als erste Stufe einer Kaskade lohnt. Haiku ist laut Listenpreis zehnmal billiger. Ohne gemeinsame Messung auf demselben Test lässt sich das nicht entscheiden. Teste es auf deinem eigenen Repo.

Die Woche der Hintergrund-Agenten

Drei Plattformen haben in den letzten zwölf Tagen dieselbe Richtung eingeschlagen:

  • Cursor Agent SDK (20.10.): „Agents are defined as code projects, tested with evals, and deployed to Cursor or your own infrastructure.“ Auslöser sind GitHub, GitLab, Bitbucket, Slack, Webhooks oder Cron.[1]
  • GitHub Copilot (28.10., Universe): Copilot Fusion zum Routen zwischen Modellen, eine eigene Copilot-App, Copilot Automations für geteilte Team-Workflows. Copilot ist jetzt in GitHub Enterprise enthalten.[2] Details der Einträge haben wir nicht geöffnet.
  • Cline 4.1.26 (26.10.): ein Umschalter zwischen lokaler und Cloud-Ausführung. Standardmodell ist jetzt Claude Sonnet 5.5.[3]
Agents as Code: Statt einem Agenten im Chat zu sagen, was er tun soll, schreibst du seine Aufgabe als kleines Projekt mit Tests. Ein Ereignis startet ihn, zum Beispiel ein neues Issue oder ein Zeitplan. Das ist wie der Unterschied zwischen einem Anruf beim Handwerker und einem Wartungsvertrag.

Meine Sicht: Das ist der wichtigste Trend der Woche, auch wenn er keine Schlagzeile macht. Der Agent wandert aus deinem Editor in die Pipeline. Dafür brauchst du Evals, sonst merkst du nicht, wenn ein Modellwechsel deinen Agenten verschlechtert. Cursors SDK ist dabei der klarste Ansatz, weil es Evals direkt mitbringt.

Ausprobieren Cursor Agent SDK mit einem Cron-Auslöser für eine langweilige Aufgabe, etwa ein wöchentlicher Dependency-Bericht. Warum: Du lernst den Eval-Teil an einem Fall, bei dem ein Fehler nichts kostet.
