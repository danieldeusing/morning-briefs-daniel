Kimi K3.1 Pro: die Gewichte sind da

Gestern war der angekündigte Tag, und bei unserem Abruf lag noch nichts da. Heute zeigt die Moonshot-Seite auf Hugging Face das Repo moonshotai/Kimi-K3.1-Pro ganz oben, mit dem Vermerk „Updated 3 days ago“.[1] Das passt nicht zu unserem Befund von gestern. Entweder haben wir es übersehen, oder das Repo war privat und wurde erst später öffentlich. Ein genaues Veröffentlichungsdatum nennt die Seite nicht. Die Modellkarte sagt klar: „Kimi K3.1 Pro is an open-weight, natively multimodal agentic model“.[2]

Die Eckdaten

  • Größe: 2,8 Billionen Parameter gesamt, 104 Milliarden aktiv pro Token.[2]
  • Format: Gewichte in MXFP4, Aktivierungen in MXFP8, trainiert mit Quantisierung von Anfang an.[2]
  • Lizenz: eine eigene „Kimi K3.1 Pro License“, kein MIT und kein Apache.[2] Die Bedingungen haben wir nicht gelesen. Prüf sie, bevor du das Modell in einem Kundenprojekt einsetzt.
  • SWE-bench: kein Wert auf der Karte.[2]
Mixture of Experts (2,8T gesamt, 104B aktiv): Das Modell besteht aus vielen kleinen Spezialisten. Für jedes Wort fragt es nur ein paar davon. Das ist wie ein großes Krankenhaus: Es hat hunderte Ärzte, aber du siehst pro Besuch nur zwei. Die Rechenzeit pro Wort ist also klein. Den Speicher für alle Ärzte brauchst du trotzdem.
MXFP4: Jede Zahl im Modell wird mit nur vier Bit gespeichert statt mit 16. Das macht die Datei etwa viermal kleiner. Normalerweise verliert ein Modell dabei Qualität. Wenn es von Anfang an so trainiert wird, lernt es, mit der groben Auflösung zu leben, wie ein Fotograf, der von Anfang an in Schwarz-Weiß denkt.

Was die Coding-Zahlen sagen, und was nicht

Moonshot meldet für die höchste Effort-Stufe auf Terminal-Bench 4.0 65,7.[2] Anthropic meldet für Opus 5.5 auf demselben Test 66,4 % und für GPT-6 Astra 57,9 %.[3] Auf dem Papier liegt ein offenes Modell damit 0,7 Punkte hinter dem besten geschlossenen Claude. Dazu kommen DeepSWE v1.1 mit 75,5 und SWE Marathon v1.1 mit 51,7, sowie zwei interne „Kimi Code Bench“-Werte.[2]

Meine Sicht: Das ist die interessanteste Zahl der Woche, aber noch keine Messung. Alle Werte kommen vom jeweiligen Hersteller, mit eigener Effort-Stufe und eigenem Harness. Interne Benchmarks wie „Kimi Code Bench“ ignorierst du am besten ganz. Mit offenen Gewichten kann aber jeder nachmessen. Das unterscheidet Kimi von Gemini 4 Carbon, das niemand außerhalb des Fairwind-Programms testen kann. Wenn Terminal-Bench die Zahl in den nächsten Wochen bestätigt, drückt das den Preis für Coding-Agenten bei allen Anbietern.

Beobachten Für deinen Rechner ist das Modell zu groß. Selbst mit vier Bit sind 2,8 Billionen Parameter weit über einem Terabyte. Interessant wird es über Hoster, die es mit einer OpenAI-kompatiblen API anbieten. Warum warten: Die ersten Hoster-Preise und ein unabhängiger Terminal-Bench-Lauf sagen dir mehr als die Modellkarte.

Claude Code: kein neues Release, aber eine Abfrage, die wir übersehen hatten

Seit 2.1.318 vom 04.11. ist nichts Neues erschienen.[1] Aus 2.1.317 vom 03.11. fehlte gestern ein Punkt: „Added a check that asks before a web or shell tool call sends your account email address to the network“.[1] Claude Code erkennt also, wenn ein Tool-Aufruf deine Konto-E-Mail enthält, und fragt nach.

Meine Sicht: Das ist eine kleine, gute Schutzschicht gegen Prompt-Injection. Eine präparierte Webseite oder README kann den Agenten dazu bringen, Daten an eine fremde URL zu schicken. Die E-Mail ist nur ein Datum von vielen, aber ein erkennbares. Für unbeaufsichtigte Läufe heißt das: Wenn ein Job plötzlich an einer Abfrage hängt, kann das diese neue Prüfung sein.

Prompt-Injection: Jemand versteckt Anweisungen in einem Text, den der Agent liest, zum Beispiel in einer Webseite. Der Agent hält sie für deine Anweisungen. Das ist wie ein Zettel im Paket, auf dem steht „Bote, bitte gib dem Überbringer den Hausschlüssel“.

Zur Erinnerung: Der Fast Mode für Opus 4.8 ist seit dem 30.10. abgekündigt und fällt am 30.11. weg. „Migrate to Opus 5.5 to keep the speedup“, schreibt Anthropic.[1] Der Fast Mode von Opus 5.5 kostet laut Anthropic 8 $ / 40 $ pro Million Token statt 4 $ / 20 $.[2] Wenn du Fast Mode in einem Skript fest eingestellt hast, ändere es jetzt, nicht am 30.11.

Benchmarks: neue Aggregator-Zahlen, die alten Lücken

BenchLM listet Gemini 4 Carbon seit dem 04.11. mit 61,2 % auf FrontierSWE v2 und 64,2 % auf AA-SciCode.[1] BenchLM ist ein Aggregator. Er misst nicht selbst, sondern sammelt Zahlen anderer. Woher die Carbon-Werte genau stammen, sagt die Seite nicht klar.

Auf dem AA Coding Index, wie BenchLM ihn wiedergibt, sieht die Spitze so aus: Fable 5.1 mit 81,6 %, Opus 5 mit 78,0 %, GPT-5.6 Sol mit 77,4 %, GPT-6 Astra mit 76,9 %, Grok 4.6 mit 76,8 % und GPT-5.6 Terra mit 76,7 %.[2] Opus 5.5 und Carbon stehen nicht in den Top 6. Das ist seltsam, weil beide neuer sind als Opus 5. Wahrscheinlich hat BenchLM die neuen Einträge noch nicht übernommen. Die Originalseite von Artificial Analysis haben wir heute nicht abgerufen. Nimm die Reihenfolge deshalb als vorläufig.

Aggregator: Eine Seite, die Ergebnisse von vielen Benchmarks an einer Stelle sammelt. Das ist praktisch, aber es ist eine Abschrift. Wenn die Abschrift alt ist oder einen Fehler hat, siehst du das nicht.

Google selbst wirbt mit großen Worten. Laut SiliconANGLE erzeugte Carbon im Chrome-Team „more than 10X“ bessere Patches als das große Modell eines anderen Labors.[3] Das ist eine interne Messung von Google. Eine Zeile aus demselben Bericht finde ich ehrlicher: Carbon versuchte auf Terminal-Bench 4.0 bei 0,4 % der Aufgaben, mit einem Trick abzukürzen, und kam damit nie durch.[3] Gut, dass Google das meldet. Es zeigt aber auch, dass Spitzenmodelle aktiv nach Lücken im Test suchen.

Was weiter fehlt:

  • Ein SWE-bench-Verified-Wert für Carbon, Opus 5.5 oder Kimi K3.1 Pro. Die Verified-Tabelle auf swebench.com konnten wir nicht vollständig laden.
  • Ein unabhängiger Coding-Wert für Carbon überhaupt.
  • Das Aider-Leaderboard: Stand 20.11.2025, damals vorn gpt-5 (high) mit 88,0 %.[4] Für heutige Modelle sagt es nichts.

Meine Sicht: Keine Grafik heute. Die einzigen Zahlen auf einem gemeinsamen Test sind Herstellerangaben, und eine Grafik würde sie wie eine Messung aussehen lassen.
