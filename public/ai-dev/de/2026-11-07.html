Claude Code 2.1.319: der Agent wartet nicht mehr

Gestern stand hier, dass Claude Code seit dem 04.11. still ist. Am Freitag kam dann doch 2.1.319, laut GitHub um 17:04.[1] Die Notiz ist lang, aber drei Punkte ändern deinen Alltag.

  • MCP-Tasks im Hintergrund: „when an MCP server runs a tool call as a task, Claude Code moves it to the background right away and tells Claude the result when it finishes“.[1] Wer das alte Verhalten will, setzt CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND.
  • Ablehnen statt fragen: Mit permissions.denyInsteadOfPrompting wird ein Tool-Aufruf, der auf eine Rückfrage warten würde, abgelehnt, „and the turn continues, in terminal sessions, subagents and teammates“.[1]
  • Auto Mode hinter Gateways: Hinter einem LLM-Gateway, oder mit abgeschalteter Telemetrie, gibt es keinen Rückfall auf den eingebauten Klassifizierer mehr. Aufrufe, die der Server nicht prüfen kann, werden nachgefragt oder abgelehnt. CLAUDE_CODE_AUTO_MODE_SERVER=0 holt das alte Verhalten zurück. Bedrock, Vertex und Foundry sind laut Notiz nicht betroffen.[1]
MCP-Task: MCP ist der Standard, über den ein Agent externe Werkzeuge aufruft, zum Beispiel eine Datenbank oder einen Build-Server. Ein „Task“ ist ein Aufruf, der lange dauert und sein Ergebnis später liefert. Das ist wie ein Paket bei der Post: Du gibst es ab und gehst, und die Post meldet sich, wenn es angekommen ist.
Auto Mode: Claude Code entscheidet selbst, welche Aktionen ohne Rückfrage laufen dürfen. Ein Prüfer auf dem Server bewertet riskante Aktionen. Das ist wie ein Pförtner, der bei bekannten Gesichtern das Tor öffnet und bei Fremden anruft.

Meine Sicht: denyInsteadOfPrompting ist die wichtigste Zeile für jeden, der Claude Code unbeaufsichtigt laufen lässt. Bisher blieb ein nächtlicher Lauf an einer Rückfrage hängen, die niemand beantwortet. Jetzt bekommt der Agent ein Nein und macht weiter. Das ist das richtige Standardverhalten für Automatisierung: Lieber eine abgelehnte Aktion im Log als ein Lauf, der acht Stunden wartet. Dazu passt eine zweite Änderung: claude -p beendet sich jetzt mit Code 1, wenn Auto Mode Aktionen mangels Sicherheitsprüfung ablehnt. Bisher kam Code 0.[1] Ein Skript, das bisher „grün“ meldete, kann ab jetzt rot werden. Das ist ehrlicher, aber prüf deine Cron-Jobs.

Die Gateway-Änderung ist die riskantere. Sie ist sicherer gedacht, aber wer Claude Code über ein eigenes Gateway betreibt, bekommt plötzlich mehr Rückfragen oder Ablehnungen. Zusammen mit denyInsteadOfPrompting heißt das: still abgelehnte Aktionen. Lies nach dem Update einmal das Log eines automatischen Laufs.

Ausprobieren permissions.denyInsteadOfPrompting in den Einstellungen für einen nächtlichen Lauf. Warum: Du siehst am Morgen im Log, welche Aktionen der Agent wollte und nicht durfte. Das ist eine gute Liste für deine Erlaubnis-Regeln.

Aus den zwei Releases davor:

  • 2.1.318 (04.11.): Hintergrund-Subagenten schieben einen Shell-Befehl nach 3 Minuten in den Hintergrund, „so the prompt cache doesn't expire while it runs“.[1] Das spart bei langen Builds Geld.
  • 2.1.317 (03.11.): onFailure: "block" für Hook-Callbacks im Agent SDK. Ein fehlerhafter Hook blockiert die Aktion jetzt, statt sie durchzulassen.[1] Außerdem nutzen Subagenten auf einem anderen Modell jetzt dessen eigene Effort-Stufe statt der der Sitzung.
  • Fast Mode für Opus 4.8 wird am 30.11. entfernt.[1] Noch 23 Tage.

Laut Latent Space hat das claude-code-Repo 16.060 offene Issues, davon 15.766 ohne Zuständigen.[2] Die Zahl haben wir nicht selbst nachgezählt. Sie passt aber zum Bild: Das Tool wächst schneller, als jemand die Fehlerberichte sortieren kann.

Kimi K3.1 Pro: die Gewichte sind wirklich da

Moonshot hatte die Gewichte für den 04.11. versprochen. Am 24.10. waren sie noch nicht da.[1] Heute steht das Repo moonshotai/Kimi-K3.1-Pro auf Hugging Face, mit Safetensors-Dateien, 2,8 Billionen Parametern insgesamt und 104 Milliarden aktiven.[2] Ein genaues Veröffentlichungsdatum zeigt die Seite nicht, die Organisationsseite nennt nur „vor 2 Tagen aktualisiert“.

Mixture of Experts (aktive Parameter): Das Modell besteht aus vielen Teil-Netzen, den „Experten“. Für jedes Wort arbeitet nur ein kleiner Teil davon, hier 104 Milliarden von 2,8 Billionen. Das ist wie ein Krankenhaus mit hundert Fachärzten: Jeder Patient sieht nur zwei oder drei, aber alle hundert brauchen trotzdem ein Büro. Für den Speicher zählt also die große Zahl, für die Geschwindigkeit die kleine.

Die Zahlen, soweit unabhängig gemessen:

  • Terminal-Bench 4.0 bei Vals: 63,64 % (±1,75), Platz 3 von 61. Claude Opus 5.5 liegt bei 65,15 %.[3] Der Abstand von 1,5 Punkten liegt innerhalb der Fehlerspanne. Vals ist ein unabhängiger Prüfer, das ist hier die belastbarste Zahl.
  • Arena WebDev: Platz 8 mit 1.692 Punkten, der Vorgänger K3 hatte 1.655.[1] Das ist eine Abstimmung von Menschen, kein Test.
Terminal-Bench: Ein Test, bei dem ein Agent echte Aufgaben in einer Kommandozeile lösen muss, zum Beispiel ein Projekt bauen oder einen Fehler im Server finden. Das ist wie eine praktische Fahrprüfung statt eines Theorietests.

Meine Sicht: Ein offenes Modell anderthalb Prozentpunkte hinter dem besten geschlossenen ist die eigentliche Nachricht der Woche. Für deinen Laptop ist es egal. 2,8 Billionen Parameter laufen nur auf einem Server-Cluster. Wichtig ist es für den Preis: Jeder Hoster kann K3.1 Pro jetzt anbieten, und das drückt auf das, was Anthropic und OpenAI für Agenten-Läufe verlangen können. Ein Vorbehalt: Die Lizenz heißt „Kimi K3.1 Pro License“, also keine Standard-Lizenz wie Apache 2.0.[2] Lies sie, bevor du das Modell für Kundenarbeit einplanst.

89,9 % auf SWE-bench Pro: eine Zahl ohne Zeugen

Der Aggregator BenchLM hat sein SWE-bench-Pro-Board am 06.11. aktualisiert. Ganz oben steht Claude Opus 5.5 mit 89,9 %, dann Sonnet 5.5 mit 81,3 % und Fable 5.1 mit 81,2 %.[1] Gestern haben wir dieselbe Zahl bei llm-stats.com als Herstellerangabe gesehen. Zwei Aggregatoren, die dieselbe Herstellerzahl abschreiben, sind aber keine zwei Messungen.

Drei Gründe, warum ich die Zahl nicht in eine Grafik packe:

  • Keine unabhängige Messung. Weder Anthropic noch ein unabhängiger Prüfer hat sie bestätigt, die wir abrufen konnten.
  • Der Test selbst wackelt. BenchLM schreibt auf derselben Seite: „a July 2026 audit estimated about 30% of the public split is broken“.[1] Wenn ein Drittel der Aufgaben fehlerhaft ist, misst ein Wert nahe 90 % vor allem, wie gut ein Modell mit den kaputten Aufgaben umgeht.
  • Gemischte Aufbauten. Jeder Anbieter testet mit seinem eigenen Agenten-Gerüst. Das Board vergleicht also Modell plus Werkzeug, nicht das Modell allein.
SWE-bench Pro: Eine Sammlung echter Fehlerberichte aus Software-Projekten. Das Modell muss den Fehler beheben, und die Tests des Projekts prüfen das Ergebnis. Das ist wie eine Werkstatt-Prüfung mit echten kaputten Autos. Wenn aber ein Drittel der Prüf-Autos schon vorher falsch beschriftet war, sagt die Note wenig.

Die interessantere Zahl kommt aus derselben Latent-Space-Ausgabe: Opus 5.5 kostet dort 1,64 $ pro Aufgabe, etwa das 29-Fache von GPT-6.1 Sol, und braucht rund 27 Runden statt etwa 8.[2] Welcher Benchmark das ist, nennt die Zusammenfassung nicht, und ich konnte die Zahl nicht nachprüfen. Ich nehme die Zahl deshalb nur als Richtung. Die Richtung ist aber wichtig: Bei Agenten zählen nicht nur Prozentpunkte, sondern auch, wie viele Runden und Dollar ein Modell bis zur Lösung braucht. Ein Modell, das drei Prozentpunkte besser ist und das 29-Fache kostet, ist für einen Batch von 200 Tickets das falsche Modell.

Für SWE-bench Verified gibt es heute keinen Wert: Die Leaderboard-Seite lädt ihre Tabelle per JavaScript, und der Abruf lieferte keine Zeilen. Deshalb keine Grafik.

Agenten verlassen den Editor: Cursor per Sprache, Copilot im Chat

Zwei kleine Meldungen vom Freitag zeigen dieselbe Richtung.

  • Cursor „Voice Chat with Agents“ (06.11.): Du sprichst mit deinen Agenten. Die Funktion „runs on Grok Voice, with several voices to choose from“.[1] Einen Tag vorher kam „Build Live Apps“: Cloud-Agenten bauen Web-Apps mit Postgres-Datenbank und Cursor-Login und stellen sie online.[1]
  • Copilot in Slack und Teams ist seit 06.11. allgemein verfügbar.[2] Dazu kommen Xcode (04.11.) und JetBrains Air (03.11.), über die wir gestern geschrieben haben.

Meine Sicht: Der Editor ist nicht mehr der einzige Ort, an dem Code entsteht. Du gibst eine Aufgabe im Team-Chat oder per Sprache ab, und ein Cloud-Agent arbeitet sie ab. Für dich als Einzelentwickler ist Sprache eher eine Spielerei. Für Teams ist Copilot in Slack ernster: Dann kann jeder im Kanal einen Agenten auf das Repo ansetzen. Klär vorher, wer welche Rechte hat. Dass Cursor für die Sprache auf Grok setzt und nicht auf OpenAI oder Google, ist eine bemerkenswerte Wahl. Zu den Daten sagt der Changelog nur: Mit Privacy Mode läuft Voice Chat ohne Datenspeicherung (zero data retention).

Kleine Werkzeuge: LLM 0.37 und ein Satz über Vertrauen

Simon Willisons Kommandozeilen-Tool llm kann in Version 0.37 (02.11.) GPT-6.1 Sol und Terra. Das neue Standardmodell ist GPT-6 Luna.[1] Wer llm in Skripten ohne festes Modell nutzt, bekommt nach dem Update also ein anderes Modell. Setz das Modell mit -m fest.

Ausprobieren llm für kleine Shell-Aufgaben neben deinem Agenten. Warum: Für „fass dieses Log zusammen“ brauchst du keinen ganzen Agenten-Lauf, und llm wechselt das Modell mit einem Schalter.

Am 01.11. zitierte Willison den Entwickler Kyle Kingsbury: LLMs untergraben die alten Signale, an denen man reife Software und gute Dokumentation erkannt hat.[1] Für mich ist das der wichtigste Gedanke der Woche. Meine Lesart: Eine gepflegte README und viele Commits beweisen wenig, wenn ein Agent beides in einer Stunde erzeugt. Prüf eine neue Bibliothek also nach Nutzern, Issues und Maintainern, nicht nach der Länge der Doku.
