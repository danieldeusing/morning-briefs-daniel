Claude Code 2.1.325: Sicherheits-Fix beim Entpacken

Das einzige neue Coding-Release seit gestern früh: Claude Code 2.1.325. GitHub zeigt den 13.11. um 20:40 Uhr, aber ohne Jahr und ohne Zeitzone. Der Release-Tracker releasebot sah es zuerst am 14.11.2026. Die Release-Notes sagen: „Fixed a security issue in how zstd-compressed responses are decoded“.[1]

zstd-Kompression: zstd (Zstandard) ist ein Packformat wie ZIP, nur schneller. Server packen Antworten damit klein, damit weniger Daten über die Leitung gehen. Dein Client muss sie wieder auspacken. Genau beim Auspacken entstehen klassische Lücken: Ein präpariertes Paket kann den Entpacker zum Absturz bringen, sehr viel Speicher fressen („Zip-Bombe“) oder schlimmeres auslösen.

Was die Notes nicht sagen: wie schwer das Problem war, wer es ausnutzen konnte und ob es eine CVE-Nummer gibt. Wir haben keine CVE und kein Advisory gefunden. Darum nennen wir es auch nicht so. Klar ist nur der Ort: Es geht um Antworten, die Claude Code empfängt. Das betrifft also jede Sitzung, nicht ein exotisches Feature.

Meine Sicht: Ein Agent, der Code ausführt und Dateien schreibt, ist ein lohnendes Ziel. Jede Lücke im Pfad, über den Daten in ihn hineinkommen, ist ernster als bei einem normalen CLI-Tool. Dass Anthropic den Fix in einer eigenen Release-Zeile nennt, statt ihn in „bug fixes“ zu verstecken, finde ich gut. Ein Advisory mit Schweregrad wäre besser. Bis es eins gibt, behandle ich das als „sofort updaten“ und nicht als „irgendwann“.

Ausprobieren Führe claude update aus und prüfe mit claude --version, dass mindestens 2.1.325 läuft. Warum: Das kostet eine Minute, und Sicherheits-Fixes sind der eine Fall, in dem „später“ die falsche Antwort ist. Gilt besonders, wenn du Claude Code hinter einem eigenen Gateway oder Proxy betreibst.

Wochenbilanz: Was diese Woche für dein Setup heißt

Vier Releases von Claude Code in einer Woche, ein neues Spitzenmodell und eine neue Gemini-Familie. Hier das, was davon bleibt, in der Reihenfolge, in der es dein tägliches Arbeiten ändert.

  • Fable 5.2 als neuer Standard (09.11.) — Claude Code 2.1.321 macht claude-fable-5-2 zum Standard-Fable-Modell: 1M Kontext, 8 $ / 40 $ pro Million Tokens, Cache-Reads 0,20 $.[1] Im allgemeinen Index von Artificial Analysis führt es mit 65 Punkten.[2]
  • Code Mode (12.11.) — Claude schreibt im Opt-in-Modus JavaScript, um seine Tools aufzurufen.[1] Zwei Tage später gibt es noch keine Zahlen zu Tempo oder Kosten. Meine Einschätzung von gestern bleibt: die interessanteste Harness-Idee der Woche, aber erst in einem Wegwerf-Repo testen.
  • Auto Mode hinter Gateways (06.11.) — wenn Telemetrie oder Feature-Flags aus sind, etwa hinter einem LLM-Gateway, fragt Claude Code jetzt nach oder lehnt ab, wenn der Server einen Aufruf nicht prüfen kann. Es gibt keinen Rückfall auf den eingebauten Klassifizierer mehr.[1] Wer Claude Code über einen eigenen Proxy betreibt, sieht dadurch mehr Rückfragen. Das ist Absicht, kein Fehler.
  • Fast Mode auf Vertex (10.11.) — in den Regionen global, us und eu, mit Rückfall auf normale Geschwindigkeit.[1]
  • Managed Agents selbst gehostet (12.11.) — private Beta.[3] Für dich heute nichts zum Ausprobieren, aber ein Argument für Kunden mit strengen Datenregeln.

Meine Sicht: Die Woche gehört Anthropic, aber nicht wegen Fable 5.2. Ein stärkeres Modell merkst du in einzelnen Sitzungen. Code Mode und die strengere Auto-Mode-Regel ändern dagegen, wie der Agent arbeitet und was er ohne dich darf. Das sind die Änderungen, die du kennen solltest, bevor sie dich überraschen.

Gemini 4: Hydrogen hat jetzt einen vollen Preis

Gestern fehlte uns der Output-Preis von Gemini 4 Hydrogen. Simon Willison nennt ihn im Eintrag zu llm-gemini 0.37 vom 12.11.: 1,50 $ Input, 0,075 $ für gecachten Input und 7,50 $ Output pro Million Tokens. Er nennt Hydrogen „the lowest cost member of the Gemini 4 family“.[1] Hydrogen ist das neue Modell im kostenlosen Tarif und treibt laut Willison die AI-Funktionen der Google-Suche.[1]

Für Carbon und Argon gilt bis 30.11. 2 $ / 10 $, ab 01.12. 4 $ / 20 $.[1] Willisons Pelikan-Test (ein SVG zeichnen lassen) zeigt den Abstand im Alltag: Hydrogen auf hoher Stufe kostete 3,99 Cent in 19 Sekunden, Carbon 20,31 Cent in 4 Minuten 11 Sekunden.[1] Das ist eine einzelne Aufgabe, kein Benchmark, aber ein ehrliches Gefühl für die Größenordnung.

„Billigstes Gemini 4“ heißt nicht billig. Laut Willison kostet Hydrogen etwa 15-mal so viel wie die Modelle für 0,10 $ / 0,50 $, also Claude Haiku 5.5 und GPT-6 Luna.[1]

Meine Sicht: Hydrogen sitzt in einer unbequemen Mitte. Für Routine-Schritte eines Agenten gibt es deutlich billigere Modelle, für schwere Entscheidungen stärkere. Interessant wird es nur, wenn es beim Coden klar besser ist als Haiku 5.5 oder Luna. Dafür haben wir keine Zahl. Carbon bleibt bis Monatsende das spannendere Testobjekt, weil der Preis danach doppelt so hoch ist.

Ausprobieren Gib Carbon und Hydrogen dieselbe kleine Aufgabe aus deinem Backlog und vergleiche Ergebnis, Zeit und Kosten. Warum: Bis 30.11. kostet der Carbon-Teil des Tests die Hälfte, und Willisons Zahlen zeigen, dass der Abstand groß sein kann.

Open-Weights: viele Namen, wenig gesicherte Daten

Im Open-Weights-Thread schwirren diese Woche mehrere Coding-Modelle herum. Das Problem: Für die meisten haben wir nur Suchtreffer, kein bestätigtes Datum und keine unabhängige Messung.

  • Poolside Laguna S 2.1 — 118 Milliarden Parameter, offene Gewichte auf Hugging Face, Lizenz OpenMDW-1.1, für agentisches Coden. Es soll auf eine einzelne DGX Spark passen.[1] Das Datum zeigt die Quelle nicht.
  • JetBrains Mellum 2 — ein MoE-Coding-Modell, jetzt Open Source.[2] Datum ebenfalls unklar.
  • Ripple-65B Preview (04.11.) — Apache 2.0, Gewichte auf Hugging Face. Die 80,5 % auf TerminalBench 2.1 stammen vom Anbieter selbst.[3]
MoE (Mixture of Experts): Ein großes Modell aus vielen kleinen Teil-Modellen („Experten“). Für jedes Wort rechnen nur wenige davon. So hat das Modell viel Wissen, braucht pro Antwort aber nur einen Bruchteil der Rechenzeit. Für dich lokal heißt das: Es braucht viel Speicher, läuft aber schneller, als die Gesamtgröße vermuten lässt.

Meine Sicht: 118 Milliarden Parameter auf einem einzelnen Gerät ist für lokales Coden die interessanteste Zahl hier. Für einen normalen Laptop mit Ollama ist das trotzdem zu groß. Für Qwen, DeepSeek und Ollama haben wir diese Woche kein neues Coding-Release gefunden. Wer lokal arbeitet, verpasst also nichts, wenn er abwartet, bis Ollama-Builds und erste unabhängige Tests da sind.
