Claude Code 2.1.326: Schluss mit stillen Fehlern

Am Montagabend kam Version 2.1.326. Die Release-Notes auf GitHub sind so lang, dass die Seite sie abschneidet.[1] Neue Funktionen gibt es kaum. Dafür gibt es Dutzende Fixes. Liest man sie am Stück, sieht man ein Muster: Viele Fehler passierten bisher still. Jetzt meldet Claude Code sie. Die wichtigsten für dich:

  • Unvollständige Tool-Regeln: Beim Start warnt Claude Code jetzt, wenn ein Wert in --allowedTools, --disallowedTools oder --tools nicht wie eine vollständige Regel aussieht.
  • Kaputte Settings-Datei: Wurde eine Settings-Datei mitten in der Sitzung mit einem Fehler gespeichert, hat Claude Code sie still übersprungen. Jetzt kommt eine Warnung mit dem Dateinamen.
  • Regeln, die nur gespeichert aussahen: Regeln aus /permissions und Ordner aus /add-dir wirkten gespeichert, auch wenn die Datei nicht schreibbar war. Jetzt warnt das Terminal.
  • Falsche Zusammenfassung: Befehle wie find -delete, cat a > b oder sort -o löschen oder überschreiben Dateien. Im Transkript erschienen sie trotzdem als „Suche" oder „Lesen". Behoben.
  • claude purge: Bei umgeleiteter Standardausgabe waren die Rückfragen unsichtbar. Ein einziges ungesehenes Enter konnte die Daten eines Projekts löschen. Die Fragen erscheinen jetzt immer im Terminal.
  • Ordner-Vertrauen: Pfeil hoch und Enter beantworteten die Vertrauens-Frage für einen Unterordner mit Ja. Behoben.
  • Gateway nach Absturz: Hintergrund-Sitzungen verloren nach einem Absturz das LLM-Gateway aus deiner Shell. Jetzt stoppen sie, bevor sie eine Modell-Anfrage senden.
Fail-closed gegen fail-open: Eine Tür mit kaputtem Schloss kann zu bleiben (fail-closed) oder aufgehen (fail-open). Bei Sicherheit willst du immer die erste Variante. Viele Fixes dieser Woche verschieben Claude Code von „das Schloss ist kaputt, aber niemand merkt es" zu „das Schloss ist kaputt, und eine Lampe leuchtet".

Meine Sicht: Das ist ein langweiliges Release, und das ist gut so. Letzte Woche ging es um Lücken im Rechte-System. Diese Woche geht es um die Frage dahinter: Woher weißt du, dass deine Regeln überhaupt gelten? Die Warnung bei unvollständigen --allowedTools-Regeln ist für Skripte und CI am wertvollsten. Ein Tippfehler in einer Regel war bisher einfach keine Regel, und niemand hat es bemerkt. Der Transkript-Fix ist subtiler, aber auch wichtig. Wer das Protokoll eines Agenten liest, verlässt sich darauf, dass „Lesen" auch Lesen heißt.

Ausprobieren Aktualisiere auf 2.1.326 und starte claude einmal in jedem Projekt mit eigenen Settings. Mit Ctrl+O siehst du versteckte Startmeldungen. Warum: Die neuen Warnungen zeigen dir Regeln und Settings, die schon lange nicht gewirkt haben.

Code Mode jetzt auch mit Agent Teams

Code Mode kam am 12.11. mit 2.1.323 als experimentelles Opt-in. Dabei schreibt Claude JavaScript, um seine Tools aufzurufen.[1] Mit 2.1.326 lässt er sich auch einschalten, wenn Agent Teams aktiv sind. Wer Code Mode schon an hatte, startet Sitzungen mit Teams jetzt direkt darin.[1] Zwei weitere Fixes betreffen Skills mit Inline-!-Befehlen in Code Mode. Sie luden unter Auto Mode nicht oder ließen Hintergrund-Sub-Agenten scheitern.

Agent Teams: Statt eines Agenten arbeitet eine kleine Mannschaft. Ein Agent verteilt die Arbeit, andere erledigen Teile davon parallel. Code Mode heißt hier: Jedes Team-Mitglied schreibt ein kleines Programm für seine Werkzeug-Aufrufe, statt jeden Aufruf einzeln zu bestellen.

Meine Sicht: Vier Tage nach dem Start schon die erste Kombination mit Teams und zwei Skill-Fixes. Das zeigt, dass Anthropic Code Mode ernst meint. Es zeigt aber auch, wie viele Ecken die Funktion noch hat. Ich würde weiter in einem Test-Repo bleiben.

Arena-Score: Menschen sehen zwei anonyme Antworten auf dieselbe Aufgabe und wählen die bessere. Daraus rechnet die Arena eine Punktzahl, wie beim Schach. Das „±19" ist die Unsicherheit: Der echte Wert liegt wahrscheinlich irgendwo zwischen 1807 und 1845. Überlappen sich zwei solche Bereiche, ist der Rang nicht sicher.

Der Abstand zwischen Fable 5.2 und Opus 5.5 ist 10 Punkte. Die Unsicherheit bei Fable 5.2 (±19) ist fast doppelt so groß wie dieser Abstand. Fable 5.2 hat auch erst etwa ein Drittel der Stimmen von Opus 5.5. Statistisch ist das ein Gleichstand. Der echte Sprung ist ein anderer: Fable 5.2 liegt 83 Punkte über seinem Vorgänger Fable 5.1.

Im allgemeinen Intelligence Index von Artificial Analysis ist der Abstand größer: Fable 5.2 (Max) 65, Gemini 4 Carbon (High) 60, Opus 5.5 (Max) 59.[2] Die Seite nennt kein Datum. Anbieter-Zahl dazu: 49,1 % auf FrontierCode 2.0 bei Effort Xhigh, laut Ankündigung.[3]

Meine Sicht: Drei Vorbehalte. Erstens misst die Arena Geschmack bei Web-Apps, nicht das Fixen von Bugs in einem großen Repo. Zweitens laufen beide Claude-Modelle auf hohen Effort-Stufen. In Claude Code ist der Standard Medium.[3] Drittens: SWE-bench Verified und LiveCodeBench konnten wir wieder nicht abrufen, beide laden ihre Daten per JavaScript. Trotzdem passt das Bild zu Anthropics eigenem Satz: „Claude Opus 5.5, our strongest daily driver"[3] Fable 5.2 kostet 8 $ / 40 $ pro Million Tokens.[3] Für den Alltag ist Opus 5.5 also die vernünftige Wahl. Fable 5.2 bleibt für die harten Fälle.

Korrektur: Codex hat im November geliefert

Gestern stand hier, OpenAI habe im November keinen Codex-Eintrag. Das stimmte nur für den API-Changelog. Auf GitHub ist Codex 0.169.0 vom 13.11. das aktuelle stabile Release. Es bringt unter anderem mehrere Side-Chat-Tabs im optionalen Terminal-Workspace.[1] Laut releasebot kam am selben Tag 0.168.0 mit einer Auswahl von Modell-Anbietern („Browse model providers under Sessions → Model providers") und Chats nebeneinander.[2] Seit dem 13.11. erscheinen außerdem mehrere Alphas pro Tag von 0.171.0, heute schon alpha.11. Ihre Notizen sind leer.[1]

Meine Sicht: Die Auswahl von Modell-Anbietern ist der interessante Teil. Ein Harness, der nicht an das Modell seines Herstellers gebunden ist, wird damit vergleichbar mit OpenHands oder Cline. Wie offen das wirklich ist, also welche Anbieter und ob auch lokale Endpunkte gehen, sagt die Notiz nicht. Das prüfen wir, sobald 0.171 stabil ist.

Ausprobieren Wenn du ein OpenAI-Abo hast: Probiere die Side-Chat-Tabs in 0.169 für eine Nebenfrage, während der Hauptagent arbeitet. Warum: Eine Nebenfrage in einem eigenen Tab stört den Kontext des Hauptagenten nicht.

Qwen4-Max: stark in der Arena, aber nicht für dich zu Hause

Alibaba hat am 11.11. eine Vorschau von Qwen4-Max veröffentlicht. Laut zwei Sekundärquellen gibt es sie nur im Token Plan, ohne Bezahlung pro Nutzung, und sie endet am 25.11. Offizielle Benchmarks und offene Gewichte wurden nicht angekündigt.[1] In der Code Arena steht Qwen4-Max (xHigh) vorläufig auf Platz 6 mit 1750, knapp vor Fable 5.1.[2]

Offene Gewichte: Die „Gewichte" sind die gelernten Zahlen im Modell, also das Modell selbst. Sind sie offen, kannst du die Datei herunterladen und mit Ollama auf deinem Rechner laufen lassen. Ohne offene Gewichte ist das Modell nur ein Dienst in Alibabas Cloud, wie Claude oder GPT.

Meine Sicht: Für einen lokalen Workflow ist das heute keine Nachricht. Interessant ist die Richtung: Ein chinesisches Labor liegt in einem unabhängigen Coding-Ranking in Sichtweite von Anthropic, Google und OpenAI. Ob es von Qwen4 später offene Varianten gibt, wissen wir nicht.
