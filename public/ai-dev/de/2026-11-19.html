Claude Code 2.1.328: der Auto-Modus wird Standard

Die neue Version erschien am 18. oder 19.11. Der Release-Tracker havoptic nennt den 18., die GitHub-Release-Seite „19 Nov". Der Kern steht in der Release-Notiz: „Added auto mode for Claude Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude apps gateway; interactive sessions with no permission mode start in it".[1]

Das heißt zweierlei. Erstens gibt es den Auto-Modus jetzt auch für Firmen, die Claude nicht direkt bei Anthropic beziehen, sondern über ihre Cloud. Zweitens ändert sich das Verhalten beim Start: Wer keinen Rechte-Modus setzt, landet im Auto-Modus und nicht mehr im Modus mit Rückfrage bei jeder Aktion. Ob das nur für die genannten Cloud-Setups gilt oder für alle, sagt der Satz nicht eindeutig.

Auto-Modus: Normalerweise fragt Claude Code vor vielen Aktionen nach, zum Beispiel bevor es einen Shell-Befehl ausführt. Im Auto-Modus fragt es nicht jedes Mal. Eine automatische Prüfung entscheidet, was ohne Rückfrage laufen darf. Stell dir einen Praktikanten vor, der Routine-Aufgaben ohne Unterschrift erledigen darf, aber für Größeres trotzdem zu dir kommt.

Die zweite Neuerung passt dazu: "onFailure": "block" gibt es jetzt auch für mcp_tool-Hooks, so wie schon für Command- und HTTP-Hooks. Die Notiz sagt: „a hook whose call fails blocks the action".[1] Ein Sicherheits-Hook, der selbst abstürzt, lässt die Aktion also nicht mehr still durch.

Fail-closed statt fail-open: Ein Türsteher, der krank ist, kann zwei Folgen haben. Entweder ist die Tür offen, dann kommt jeder rein. Oder die Tür bleibt zu, bis er zurück ist. „onFailure: block" wählt die geschlossene Tür.

Meine Sicht: Diese Woche zeigt bei Claude Code ein klares Muster. Am 13.11. kam ein Fix für eine Lücke, durch die manche verketteten Bash-Befehle ohne Rückfrage liefen.[1] Jetzt wird der Auto-Modus breiter zum Standard, und gleichzeitig kommt ein Hook-Schalter, der im Fehlerfall blockiert. Anthropic gibt dem Agenten mehr Freiheit und baut die Absicherung im selben Zug. Für dich als Einzel-Entwickler mit direktem Anthropic-Zugang ändert sich vermutlich wenig. Für Teams auf Bedrock oder Foundry ändert sich viel: Wer bisher bewusst mit Rückfragen gearbeitet hat, sollte den Rechte-Modus jetzt explizit setzen, statt sich auf den Standard zu verlassen.

Ausprobieren Falls du Sicherheits-Hooks über MCP-Tools nutzt: Setze "onFailure": "block" und lass den Hook einmal absichtlich scheitern. Warum: Erst dann weißt du, ob deine Absicherung bei einem Fehler wirklich hält.

Claude Code 2.1.327, jetzt vollständig gelesen

Update seit gestern Gestern brach die Zusammenfassung der Stdin-Option ab. Jetzt ist klar, welcher Befehl gemeint ist: „Added claude mcp add-json <name> - to read the server's JSON from stdin, so tokens can stay off the command line".[1]

Im selben Release steckt ein Fix, der leicht übersehen wird. claude mcp add und claude mcp remove mit Projekt-Scope haben andere Top-Level-Keys aus der .mcp.json gelöscht.[1] Wer dort eigene Einträge pflegt, sollte die Datei einmal gegen Git prüfen.

Für die Woche komplett: 2.1.321 (09.11.) machte Fable 5.2 zum Standard-Modell, 2.1.323 (12.11.) brachte den experimentellen Code Mode, in dem Claude JavaScript schreibt, um seine Tools aufzurufen. 2.1.326 (16.11.) erlaubt Code Mode zusammen mit Agent Teams.[1][2] Acht Versionen in zehn Tagen.

Ausprobieren Leite MCP-Konfigurationen mit Tokens per Pipe ein, zum Beispiel aus 1Password: op read … | claude mcp add-json name -. Warum: Das Token erscheint dann nie in der Shell-Historie.

OpenHands: zwei Releases in drei Tagen

Das Open-Source-Harness OpenHands hat diese Woche zweimal geliefert.[1]

  • v1.42.0 (18.11.): „pick the exact connected git provider for repositories". Wichtig, wenn du GitHub und GitLab parallel verbunden hast.
  • v1.41.0 (16.11.): „choose the reasoning effort from what the agent reports" über ACP.
Reasoning Effort: Wie lange ein Modell nachdenkt, bevor es antwortet. Mehr Effort heißt bessere Antworten bei schweren Aufgaben, aber mehr Tokens und mehr Kosten. OpenHands zeigt jetzt die Stufen an, die der angeschlossene Agent selbst meldet, statt eine feste Liste vorzugeben.

Meine Sicht: Kleine Releases, aber sie zeigen, wohin OpenHands geht. Es wird zur neutralen Oberfläche, an die man verschiedene Agenten hängt. Das passt zu einem Markt, in dem sich das beste Modell jede Woche ändert.

GPT-6.2, Tag zwei: billigere Tokens, nicht immer billigere Aufgaben

Update seit gestern Die Preise sind bekannt: Astra 6.2 kostet 8 $ / 40 $ pro Million Tokens, Sol 6.2 bleibt bei 2 $ / 10 $.[1] Neu ist der Blick auf die echten Kosten pro Aufgabe. Simon Willison lässt jedes Modell auf mehreren Effort-Stufen dasselbe Testbild zeichnen, seinen bekannten Pelikan. Seine Kosten pro Bild:[1]

ModellHighXhighMax
GPT-6.2 Astra11,55 ¢17,70 ¢88,71 ¢
GPT-6 Astra18,37 ¢33,85 ¢63,21 ¢
GPT-6.2 Sol2,41 ¢6,74 ¢13,69 ¢
GPT-6.1 Sol3,66 ¢5,39 ¢13,48 ¢

Auf High und Xhigh ist Astra 6.2 deutlich billiger als der Vorgänger. Auf Max kostet es aber mehr, obwohl der Token-Preis um 20 % gefallen ist. Das Modell verbraucht dort also viel mehr Tokens. Das ist ein einzelner Test mit einer einzigen Aufgabe, keine Statistik.

Zur Qualität: Willisons eigener, nicht standardisierter Test bittet die Modelle, Yonkers in einen großen Mech zu verwandeln. Sein Urteil: „Neither of them did a good enough job", „at least in comparison to Claude Fable 5.2 and Gemini 4 Carbon".[1] Latent Space fasst die Stimmung so zusammen: Astra 6.2 sei „better and 20%-600% cheaper, but has mixed reviews", und Sol 6.2 werde „likely main workhorse".[2]

Benchmark-Stand Für GPT-6.2, Fable 5.2 und Gemini 4 Carbon gibt es weiter keine unabhängige Zahl. Im SWE-bench-Experiments-Repo ist die letzte Verified-Einreichung vom 01.09.2026.[3] Das Aider-Board nennt kein Datum. Anthropics Werte für Fable 5.2 (FrontierCode 2.0: 49,1 %, FrontierSWE v2: 69,9 %) sind anbieter-gemeldet.[4] Darum heute kein Bar-Chart.

Meine Sicht: Die Tabelle ist die wichtigste Lektion des Tages, wichtiger als die Rangliste. Für Agenten zählt nicht der Preis pro Token, sondern der Preis pro erledigter Aufgabe. Und der hängt stark davon ab, wie viel das Modell nachdenkt. Wer Astra 6.2 auf Max stellt, weil „es ja billiger geworden ist", zahlt im Zweifel mehr. Für den Alltag spricht wenig gegen Sol 6.2 auf High. Für die schweren Fälle würde ich noch bei dem Modell bleiben, das sich im eigenen Repo bewährt hat.

Ausprobieren Miss bei deinem nächsten Agenten-Lauf die Kosten pro Aufgabe auf zwei Effort-Stufen. Warum: Erst diese Zahl sagt dir, welche Stufe sich für dein Repo lohnt.

Gemini 4 Carbon: offen für zahlende Entwickler

Google hat Gemini 4 Carbon am 10.11. für Entwickler geöffnet: „Starting today, developers can build with Gemini 4 Carbon." Der Zugang läuft über die bezahlte API-Stufe in Google AI Studio und Android Studio, dazu in Antigravity.[1] Auf der Seite stehen weder Preise noch Benchmark-Zahlen. Einen Preis aus Sekundärquellen nennen wir deshalb nicht.

Nach einer Sekundärquelle hat Antigravity eine Vorschau für /swarm mit mehreren Agenten und einen Orchestrator mit Gemini 4 Carbon bekommen. Das haben wir nicht in der Primärquelle geprüft. Google führt Nutzer außerdem von Gemini CLI zu Antigravity CLI.[2]

Meine Sicht: Carbon fällt in Willisons Test positiv auf und lag in Anthropics eigener Tabelle auf AutomationBench sogar vor Fable 5.2. Ohne offiziellen Preis lässt sich aber nicht sagen, ob es die günstige Alternative ist. Wer noch Gemini CLI nutzt, sollte den Umstieg auf Antigravity CLI einplanen.

Es ist Donnerstag, der neunzehnte November. Nach dem großen OpenAI-Tag am Dienstag ist es heute ruhig. Die wichtigste Neuigkeit kommt von Claude Code.

Claude Code zwei Punkt eins Punkt drei zwei acht bringt den Auto-Modus auf Amazon Bedrock, Google Cloud, Microsoft Foundry und das Claude-Apps-Gateway, für Opus vier Punkt sechs und Sonnet vier Punkt sechs. Interaktive Sitzungen ohne gesetzten Rechte-Modus starten jetzt darin. Im Auto-Modus fragt Claude Code nicht vor jeder Aktion nach, eine automatische Prüfung entscheidet. Wer bewusst mit Rückfragen arbeitet, sollte den Modus jetzt ausdrücklich setzen.

Dazu kommt ein Sicherheits-Schalter. Hooks über MCP-Tools können jetzt die Aktion blockieren, wenn sie selbst scheitern. Ein kaputter Wächter lässt also nichts mehr still durch. Schon die Version davor erlaubt, MCP-Konfigurationen mit Tokens über die Standardeingabe einzulesen, damit sie nicht in der Shell-Historie landen.

Zu GPT sechs Punkt zwei gibt es erste Eindrücke. Latent Space spricht von gemischten Kritiken. In Simon Willisons eigenem Test schlägt keines der neuen OpenAI-Modelle Claude Fable fünf Punkt zwei oder Gemini vier Carbon. Spannender ist seine Kosten-Tabelle. Auf der höchsten Effort-Stufe kostet Astra sechs Punkt zwei rund neunundachtzig Cent pro Testbild, der Vorgänger rund dreiundsechzig Cent. Der Token-Preis ist gefallen, die Aufgabe ist trotzdem teurer, weil das Modell mehr nachdenkt.

Unabhängige Benchmark-Zahlen gibt es für keines der neuen Top-Modelle. Die SWE-bench-Einreichungen stehen seit Anfang September still. Mein Rat bleibt: im eigenen Repo messen, und zwar die Kosten pro Aufgabe, nicht pro Token.

Google hat Gemini vier Carbon für zahlende API-Entwickler geöffnet, nennt auf der Seite aber keinen Preis. Das Open-Source-Harness OpenHands hat zwei kleine Releases gebracht. Cursor ist seit dem sechsten November still, Continue sogar seit Juni.

Morgen schauen wir, ob die erste unabhängige Messung für GPT sechs Punkt zwei auftaucht und wie Teams auf den neuen Auto-Modus reagieren.
