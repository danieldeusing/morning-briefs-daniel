Die ersten Vergleichszahlen: Fable vorn, Sol am günstigsten

Fable 5.2 (09.11.), GPT-6.2 Astra und Sol (17.11.), Gemini 4 Carbon und Neon: Bisher kannten wir zu all diesen Modellen nur die Tabellen der Anbieter. VKTR berichtet am 18.11. über zwei Vergleiche von Dritten.[1] Der erste ist Cognitions FrontierCode 2.0.

FrontierCode 2.0: Ein Test, der KI-Code so bewertet, wie es die Maintainer eines Projekts vor dem Merge tun würden. Fehlt eine Pflicht-Anforderung, gibt es null Punkte. Wie eine Fahrprüfung: Ein überfahrenes Stoppschild macht die sonst gute Fahrt wertlos.

Stand laut VKTR: 18.11., jeweils der beste Reasoning-Modus, Kosten zu Listenpreisen der API.[1] Drei Dinge fallen auf:

  • Sol 6.2 ist fast so gut wie Astra 6.2. 0,4 Punkte Abstand, aber nur gut ein Fünftel der Kosten.
  • Astra 6.2 ist kaum besser als GPT-6 Astra. 44,2 gegen 44,0 %. Der Fortschritt steckt im Preis, nicht in der Leistung.
  • Fable 5.2 führt klar, kostet pro Lauf aber fast das Vierzehnfache von Sol 6.2.

Der zweite Vergleich kommt von Artificial Analysis. Ihr Coding Agent Index sieht Claude Code mit Fable 5.2 oder Opus 5.5 bei 58 Punkten, Codex mit Astra 6.2 bei 53 und mit Sol 6.2 bei 50.[1] Mit Astra in Codex auf Max-Effort sieht AA keine Verbesserung gegenüber GPT-6 Astra.[1] Im allgemeinen Intelligence Index liegt Astra bei 62, drei Punkte hinter Fable 5.2, Sol bei 57.[1]

Harness-Benchmark: Der Coding Agent Index misst nicht das Modell allein, sondern das Paket aus Werkzeug und Modell, also Claude Code oder Codex. Wie ein Autorennen: Es gewinnt nicht der Motor, sondern das ganze Auto mit Fahrer.
Vorbehalt Wir haben die Leaderboards von Cognition und Artificial Analysis nicht selbst abgerufen, beide laden ihre Zahlen per JavaScript. Alle Werte stammen aus dem VKTR-Bericht. VKTR schreibt selbst: „Cognition sells a coding agent, so it is not a neutral party".[1] Die Aufgaben stammen aus öffentlichen Open-Source-Projekten. Die sind gut dokumentiert und den Modellen vertrauter als dein privates Repo. OpenAIs eigene Terminal-Bench-Werte zu GPT-6.2 konnten wir nicht im Text prüfen, darum nennen wir sie nicht. Aus diesen Gründen heute kein Bar-Chart.

Meine Sicht: Der Abstand zwischen den Top-Modellen ist klein, der Abstand bei den Kosten ist riesig. Das ist die eigentliche Nachricht der Woche. Wer einen Agenten den ganzen Tag laufen lässt, zahlt mit Fable rund vierzehnmal so viel wie mit Sol 6.2 und bekommt dafür 6,4 Punkte mehr. Für schwere Aufgaben kann sich das lohnen, für Routine nicht. Dazu kommt der Harness-Effekt: Im AA-Index liegt Claude Code fünf Punkte vor Codex mit Astra. Ein Teil davon ist das Werkzeug, nicht das Modell. Darum gilt weiter: Ein Wechsel des Modells allein sagt wenig. Miss das Paket, das du wirklich benutzt.

Ausprobieren Nimm drei echte, abgeschlossene Aufgaben aus deinem Repo und lass sie mit deinem Standard-Modell und mit Sol 6.2 laufen. Zähle, wie oft du das Ergebnis ohne Nacharbeit mergen würdest, und notiere die Kosten. Warum: Das ist FrontierCode im Kleinen, aber mit deinem Code statt mit Open-Source-Projekten.

Claude Code 2.1.330: Charts im Terminal, Login für Firmen

Am 20.11. um 22:32 kam die nächste Version. Die sichtbarste Neuerung ist easel: „a built-in mod that draws charts when asked and under MCP metrics results".[1] Das gibt es für Pro und Max und, wo verfügbar, für Team und Enterprise, auf macOS und Linux. Die automatischen Charts lassen sich in /config abschalten.[1]

Mod: Eine Erweiterung, die die Oberfläche von Claude Code selbst verändert, nicht nur, was der Agent tut. easel ist ein mitgelieferter Mod: Fragst du nach einem Chart oder liefert ein MCP-Server Messwerte, zeichnet er die Grafik direkt in die Sitzung. Wie ein Taschenrechner, der plötzlich auch Kurven zeichnen kann.

Für Firmen wichtig: Nach claude auth login übernimmt Claude Code jetzt die Einstellungen einer Organisation aus Anthropics Enterprise-Admin-Konsole und nutzt deren Cloud-Provider oder Gateway.[1] Damit verwaltet die IT zentral, statt jeden Laptop einzeln einzurichten.

Zwei Fixes treffen Alltagsprobleme:[1]

  • Claude Code fror „for up to several minutes" ein, direkt nachdem es ein sehr langes Gespräch kompaktiert hatte.
  • Änderungen an den Nutzer-Einstellungen gingen verloren, wenn mehrere Claude-Code-Prozesse gleichzeitig speicherten.
Kompaktieren: Wird ein Gespräch zu lang für das Gedächtnis des Modells, fasst Claude Code den alten Teil zusammen und arbeitet mit der Zusammenfassung weiter. Wie ein Protokoll einer langen Sitzung: Nicht jedes Wort bleibt, aber die Beschlüsse.

Der zweite Fix passt zum Fix von 2.1.329, bei dem ~/.claude.json auf Standard zurückfiel. Wer mehrere Sitzungen parallel laufen lässt, hatte bisher ein echtes Risiko für die eigene Konfiguration.

Die Woche bei Claude Code Fünf Versionen in fünf Tagen:[1]

  • 2.1.326 (16.11.): Code Mode lässt sich jetzt auch mit Agent Teams einschalten.
  • 2.1.327 (17.11.): claude mcp add-json <name> - liest das JSON eines MCP-Servers von stdin, „so tokens can stay off the command line".
  • 2.1.328 (19.11.): Auto-Modus für Opus 4.6 und Sonnet 4.6 auf Bedrock, Google Cloud, Foundry und dem Claude-Apps-Gateway.
  • 2.1.329 (19.11.): Trust-Dialog zeigt, wo die Hooks eines Ordners deklariert sind. Eine Endlosschleife im Code Mode, die den Speicher füllte, stoppt jetzt an einem Limit.
  • 2.1.330 (20.11.): easel, Enterprise-Login, die Fixes oben.

Meine Sicht: easel ist nett, aber nicht der Grund für das Update. Der Grund sind die zwei Fixes. Wer lange Sitzungen fährt und dabei mehrere Terminals offen hat, sollte heute aktualisieren. Die Lehre aus 2.1.327 bleibt die nützlichste der Woche: Tokens gehören nicht in die Shell-History.

Ausprobieren Richte deinen nächsten MCP-Server mit claude mcp add-json name - ein und gib das JSON per Pipe aus deinem Passwort-Manager. Warum: Der Token landet nicht in ~/.zsh_history.

OpenHands 1.43: Automationen ab dem ersten Setup

Die Open-Source-Plattform für Coding-Agenten hat am 20.11. v1.43.0 veröffentlicht, zwei Tage nach v1.42.0.[1] Zwei Neuerungen:

  • „create automations enabled from the setup wizard": Wer OpenHands neu einrichtet, legt die ersten Automationen gleich mit an.
  • „show the agent's message edits (experimental)": Der Chat zeigt, wenn der Agent eigene Nachrichten nachträglich ändert.

v1.42.0 vom 18.11. hatte die Auswahl des genauen Git-Providers für Repositories gebracht.[1]

Meine Sicht: Die Edit-Ansicht ist die interessantere Funktion, auch wenn sie experimentell ist. Wenn ein Agent seine eigenen Aussagen umschreibt, will man das sehen. Bei geschlossenen Tools wie Cursor oder Codex fehlt so eine Transparenz meist. OpenHands bleibt damit die erste Wahl, wenn du einen Agenten selbst hosten und nachvollziehen willst.

Ausprobieren Falls du OpenHands lokal betreibst: Schalte die Edit-Ansicht für eine längere Aufgabe ein. Warum: Du siehst, wie oft der Agent seine Zwischenstände korrigiert, und lernst, wann du früher eingreifen solltest.

GPT-6.2 in der API: billiger, wenn du warten kannst

OpenAIs API-Changelog vom 17.11. positioniert die zwei Modelle so: „Astra targets demanding reasoning and coding tasks, and Sol targets everyday coding and agent workflows."[1] Die Preise pro Million Tokens: Astra 8 $ Eingabe und 40 $ Ausgabe, Sol 2 $ und 10 $.[2] Tool-Calling braucht die Responses API.[1]

Neu sind Hintergrund-Aufträge mit Zeitfenster. Laut Changelog sind die Token-Preise im Zwei-Stunden-Fenster 30 % und im Acht-Stunden-Fenster 40 % niedriger als im Standard. Neue Modelle unterstützen Flex Processing nicht mehr.[1]

Zeitfenster-Auftrag: Du schickst eine Anfrage und sagst: Das Ergebnis brauche ich erst in zwei oder acht Stunden. Dafür zahlst du weniger. Wie ein Paket mit Standard- statt Express-Versand.

Meine Sicht: Für nächtliche Agenten-Jobs ist das interessant: Code-Reviews, Doku-Läufe oder Test-Generierung, die bis morgen fertig sein müssen. Wer heute Flex nutzt, muss bei den neuen Modellen umbauen.

Ein Teil des Vorsprungs liegt also am Werkzeug. Wichtig ist der Vorbehalt: Wir kennen alle Zahlen nur aus zweiter Hand, und Cognition verkauft selbst einen Coding-Agenten.
