Gemini 4 Neon: Googles eigene Coding-Zahlen

Am Freitag kannten wir Neon nur aus Simon Willisons Beitrag. Jetzt konnten wir Googles Ankündigung vom 18.11. selbst lesen.[1] Der Satz, der zählt: Neon liegt „#1 overall on the Artificial Analysis Coding Agent Index (58.6)".[1] InfoWorld gibt dieselbe Zahl am 19.11. wieder, aber auch nur als Aussage von Google.[2]

Das Problem: Gestern stand im VKTR-Bericht, dass Claude Code mit Fable 5.2 oder Opus 5.5 in diesem Index auf 58 Punkte kommt.[3] 58,6 gegen 58 ist ein Abstand, der schon durch Rundung entstehen kann. Die Seite von Artificial Analysis zeigt ihre Werte nur per JavaScript. Unser Abruf lieferte die Überschrift „Coding Agent Index v2.1" und den Hinweis „15 of 40 models", aber keine Zahlen.[4] Wir können also keine der beiden Zahlen direkt bestätigen.

Quelle für alle Zeilen: Googles Blog vom 18.11., abgerufen 22.11.[1]

Terminal-Bench: Ein Test, bei dem das Modell echte Aufgaben in einer Kommandozeile lösen muss: Pakete bauen, Logs auswerten, Server einrichten. Wie eine praktische Prüfung in der Werkstatt statt eines Multiple-Choice-Tests.

Die interessanteste Zeile ist die unterste. Auf SWE-sweep, einem Test, den Google in den gelesenen Sätzen nicht erklärt, kommt Neon mit dem schlanken mini-SWE-Harness auf 12,8 %. Im eigenen Werkzeug Antigravity „more than triples to a state-of-the-art 39.0%".[1] Google schreibt selbst, das zeige, „what the Antigravity harness unlocks".[1]

Harness: Das Programm um das Modell herum: Es gibt dem Modell Werkzeuge, liest Dateien, führt Tests aus und entscheidet, wann ein Versuch fertig ist. mini-SWE ist ein absichtlich minimales Harness, Antigravity ist Googles volles Agenten-Werkzeug. Wie derselbe Koch einmal mit einem Campingkocher und einmal in einer Profiküche.
Vorbehalt Jede Zahl in diesem Abschnitt kommt von Google. Wir haben keinen Eintrag für Neon auf SWE-bench Verified, LiveCodeBench oder LMArena gefunden. Die AA-Werte sind nicht abrufbar, weil die Seite per JavaScript lädt. In den gelesenen Sätzen sagt Google nicht, mit welchem Harness die 58,6 gemessen wurden. Darum heute kein Bar-Chart.

Was Google zum Preis sagt, ist dagegen klar: 3 $ pro Million Eingabe-Tokens, 0,15 $ für gecachte Eingabe, 15 $ pro Million Ausgabe-Tokens und ein Kontext von einer Million Tokens.[1] Neon soll pro Aufgabe 32 % weniger kosten als Carbon.[1] Bis 30.11. stimmt das wohl nicht, weil Carbon noch zum Aktionspreis von 2 $ / 10 $ läuft.[5] Neon gibt es in der Gemini API über AI Studio und für zahlende AI-Pro- und Ultra-Kunden in Antigravity.[1]

Meine Sicht: Der Satz „#1 overall" ist Marketing für einen Gleichstand. Die echte Nachricht steckt in Googles eigener Fußnote: Dasselbe Modell schafft dreimal so viel, wenn das Werkzeug drumherum besser ist. Das bestätigt, was der AA-Index schon gestern gezeigt hat. Für dich heißt das: Neon in Antigravity zu testen sagt wenig darüber, wie Neon in deinem Claude Code oder deinem eigenen Harness läuft. Wer vergleichen will, muss das Werkzeug gleich lassen und nur das Modell tauschen. Mit 3 $ / 15 $ liegt Neon preislich zwischen Sol und Fable. Das macht es interessant für lange Agenten-Läufe, falls die Qualität unabhängig bestätigt wird.

Ausprobieren Wenn du ein Harness hast, das mehrere Anbieter kann: Lass eine echte Aufgabe einmal mit Neon und einmal mit deinem Standard-Modell laufen, im selben Werkzeug. Warum: Nur so trennst du den Modell-Effekt vom Harness-Effekt, den Google selbst so deutlich zeigt.

Sonntags-Experiment: Code Mode in Claude Code

Seit v2.1.323 vom 12.11. hat Claude Code den Code Mode: „an experimental opt-in in which Claude writes JavaScript to call its tools".[1] Seit v2.1.326 vom 16.11. lässt er sich auch mit Agent Teams einschalten.[1] Unter der Woche fehlt oft die Zeit, so etwas auszuprobieren. Heute passt es.

Code Mode: Normal ruft das Modell ein Tool auf, wartet auf das Ergebnis, liest es und ruft das nächste Tool auf. Jeder Schritt ist eine eigene Runde. Im Code Mode schreibt das Modell stattdessen ein kleines Programm, das mehrere Tools nacheinander aufruft und die Ergebnisse selbst verarbeitet. Wie der Unterschied zwischen fünf einzelnen Anrufen beim Handwerker und einem Zettel mit allen fünf Aufträgen.

Der mögliche Vorteil: weniger Runden und weniger Zwischenergebnisse im Kontext, wenn eine Aufgabe viele kleine Tool-Aufrufe braucht. Das Risiko zeigt die Notiz zu 2.1.329: Dort wurde eine Endlosschleife im Code Mode, die den Speicher füllte, an einem Limit gestoppt.[2] Das Feature ist also wirklich experimentell.

Meine Sicht: Code Mode lohnt sich am ehesten bei Aufgaben mit vielen gleichartigen Schritten, etwa „lies diese zwanzig Dateien und sammle alle TODOs". Für einzelne, vorsichtige Änderungen an Produktions-Code würde ich beim normalen Modus bleiben. Dort siehst du jeden Schritt einzeln.

Ausprobieren Schalte Code Mode in einem Wegwerf-Repo ein und gib dieselbe Sammel-Aufgabe einmal mit und einmal ohne. Vergleiche Dauer und Token-Verbrauch. Warum: Du weißt danach, ob sich das Opt-in für deinen Alltag lohnt, bevor es Standard wird.

Claude Code: Bist du mindestens auf 2.1.325?

Neueste Version ist weiter v2.1.330 vom 20.11., beim Abruf am Sonntag war nichts Neueres da.[1] Der wichtigste Grund für ein Update liegt aber eine Woche zurück. v2.1.325 vom 13.11. enthält zwei Sicherheits-Fixes:[1]

  • „Fixed a security issue in how zstd-compressed responses are decoded."
  • „Fixed some deny and ask rules not applying to certain Bash commands."
deny/ask-Regeln: In den Einstellungen legst du fest, welche Befehle Claude Code nie ausführen darf (deny) und bei welchen es vorher fragen muss (ask). Wie eine Kindersicherung am Herd. Der Fix heißt: Bei manchen Bash-Befehlen griff die Sicherung nicht.

Dazu passt v2.1.329 vom 19.11.: Der Trust-Dialog zeigt jetzt, wo die Hooks eines Ordners deklariert sind.[1] Wer ein fremdes Repo öffnet, sieht also, woher automatisch laufende Befehle kommen.

Meine Sicht: Wer sich auf deny-Regeln verlässt, um einen Agenten in Schach zu halten, und noch eine Version vor 2.1.325 hat, hat eine falsche Sicherheit. claude --version kostet eine Sekunde.

Es ist Sonntag, der zweiundzwanzigste November. Ein ruhiger Tag: Am Wochenende kam kein neues Release der großen Anbieter. Neu ist nur, dass wir jetzt Googles eigene Seite zu Gemini vier Neon lesen konnten.

Google schreibt, Neon liege auf Platz eins im Coding Agent Index von Artificial Analysis, mit achtundfünfzig Komma sechs Punkten. Gestern stand im VKTR-Bericht, dass Claude Code im selben Index auf achtundfünfzig kommt. Das ist praktisch ein Gleichstand. Und beide Zahlen konnten wir nicht direkt beim Index prüfen, weil die Seite ihre Werte nur per JavaScript lädt.

Spannender ist eine andere Angabe von Google. Auf dem Test SWE-sweep schafft Neon mit einem schlanken Werkzeug knapp dreizehn Prozent, in Googles eigenem Werkzeug Antigravity neununddreißig Prozent. Dasselbe Modell, dreimal so viel Erfolg. Das Werkzeug um das Modell herum zählt also mindestens so viel wie das Modell selbst. Neon kostet drei Dollar pro Million Eingabe-Tokens und fünfzehn Dollar pro Million Ausgabe-Tokens.

Für den Sonntag ein Experiment: Claude Code hat seit Mitte November einen experimentellen Code Mode. Dabei schreibt Claude ein kleines JavaScript-Programm, das mehrere Tools auf einmal aufruft. Teste ihn in einem Wegwerf-Repo mit einer Sammel-Aufgabe und vergleiche Dauer und Token-Verbrauch.

Wichtig für die Sicherheit: Version zwei Punkt eins Punkt drei zwei fünf vom dreizehnten November hat eine Lücke beim Dekodieren komprimierter Antworten geschlossen. Außerdem griffen manche Verbots- und Nachfrage-Regeln bei bestimmten Bash-Befehlen nicht. Wer älter ist, sollte aktualisieren.

Cursor ist seit dem sechsten November still, OpenHands und Codex haben seit Freitag nichts Neues. Am dreißigsten November endet der Aktionspreis für Gemini vier Carbon. In der nächsten Ausgabe schauen wir, ob Neon in einer unabhängigen Messung auftaucht.
