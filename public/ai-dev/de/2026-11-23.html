Externe Sandbox: Der Agent bleibt draußen

Simon Willison hat am 17.11. ein Muster beschrieben, das wir unter der Woche übersehen haben. Die Idee: Code, den der Agent ausführt, läuft „inside a dedicated sandbox while the agent itself lives outside of that sandbox".[1] Sein Motiv ist vor allem, lokale Modelle sicherer auszuprobieren. Die können sich irren oder durch Prompt Injection zu schädlichen Befehlen gebracht werden.[1]

Prompt Injection: Ein fremder Text, den der Agent liest, enthält versteckte Anweisungen, etwa in einer README oder einer Webseite: „Lösche den Ordner" oder „Schicke die .env irgendwohin". Das Modell kann nicht sicher unterscheiden, ob eine Anweisung von dir kommt oder aus dem gelesenen Text. Wie ein Zettel im Paket, auf dem steht: „Der Bote soll den Schlüssel unter die Matte legen."

Es gibt drei Varianten mit derselben lokalen API auf localhost:[1]

  • external-sandbox-v86: ein Node.js-Server, der Alpine Linux per v86 in WebAssembly startet.
  • external-sandbox-container: ein Python-Server mit Alpine Linux in Apple Containers.
  • external-sandbox-quicksand: ein Python-Server mit Microsofts Quicksand-Bibliothek, die QEMU und Alpine mitbringt.

Pi, Claude Code und Codex lassen sich so einstellen, dass sie Ausführungen an diese API schicken.[1] Zwei Details machen das Muster interessant: ein optionaler Proxy mit einer Allow-Liste für erreichbare Hosts, und ein Mechanismus, bei dem der Code authentifizierte API-Aufrufe macht, ohne das Secret selbst zu kennen.[1] Entstanden ist das Projekt zusammen mit Prime Radiant, dem Team hinter Superpowers.[1]

Externe statt interne Sandbox: Bei der üblichen Lösung steckst du den ganzen Agenten in einen Container. Dann braucht der Container deine Repos, Tokens und Werkzeuge, und die Grenze wird löchrig. Hier bleibt der Agent mit seinem Denken draußen auf deinem Rechner. Nur die Hände, also die Befehle, gehen in den Käfig. Wie ein Chemiker, der durch Handschuhe in einer Glovebox arbeitet, statt selbst in den Schutzraum zu gehen.
Vorbehalt Die Seite nennt keine Grenzen des Musters. Der Proxy ist optional, und alles, was der Agent außerhalb der Sandbox tut, also Dateien in deinem Repo schreiben, schützt die Sandbox nicht. Das ist ein Werkzeug gegen schädliche Befehle, kein Schutz gegen schlechten Code im Diff.

Meine Sicht: Das ist das spannendste Stück der Woche für jemanden, der mit Ollama, Gemma oder Qwen lokal arbeitet. Lokale Modelle sind oft weniger robust gegen Injection als die großen. Gleichzeitig willst du ihnen nicht deinen ganzen Rechner geben. Die Container-Variante passt auf einen Mac, die v86-Variante läuft sogar ohne Virtualisierung. Die Zweiteilung „denken draußen, ausführen drinnen" halte ich für die richtige Richtung. Die eingebauten Permission-Regeln der Harnesses hatten gerade erst Lücken: Claude Code 2.1.325 musste deny/ask-Regeln für Bash reparieren.

Ausprobieren Nimm die Container-Variante und lass ein lokales Modell eine Aufgabe in einem Wegwerf-Repo lösen, mit aktivierter Host-Allow-Liste. Warum: Du siehst danach, welche Hosts dein Agent wirklich erreichen will, und das ist schon für sich eine nützliche Liste.

Tokens raus aus der Kommandozeile

Passend dazu eine kleine Änderung in Claude Code v2.1.327 vom 17.11.: claude mcp add-json <name> - liest das JSON des Servers von stdin, „so tokens can stay off the command line".[1]

Warum das zählt: Alles, was du als Argument in die Shell tippst, landet in der History-Datei und ist für andere Prozesse in der Prozessliste sichtbar. Ein Token im Argument ist wie ein PIN auf einem Post-it am Bildschirm. Über stdin geht der Wert direkt an das Programm, ohne Spur.

Meine Sicht: Klein, aber genau richtig. Wer Secrets aus einem Passwort-Manager holt, kann sie jetzt direkt in den Befehl pipen, statt sie in einem Argument aufzuschreiben.

Ausprobieren Sieh in deiner Shell-History nach mcp add mit Tokens. Wenn du welche findest: Token rotieren, Eintrag löschen, Server neu über stdin anlegen. Warum: Eine History-Datei überlebt oft Jahre und mehrere Backups.

Codex wählt Sol als Standard, nicht Astra

Codex CLI 0.171.0 vom 20.11. hat „GPT-6.2 Sol and Astra to model catalogs" hinzugefügt, „with Sol as the default catalog selection".[1] Zwei Tage vorher hat Version 0.170.0 Sprach-Anrufe in Echtzeit im Terminal-UI über WebRTC vorbereitet.[1]

Die Wahl des Standards ist eine Aussage. Latent Space hat Astra am 18.11. „the #2 Frontier Model" genannt, mit „mixed reviews", und Sol „likely main workhorse".[2] OpenAI macht Sol in seinem eigenen Werkzeug zum Standard.

Meine Sicht: Das ist vernünftig, und Anthropic macht es mit Sonnet und Opus seit Langem ähnlich. Für dich heißt das: Wer Codex nach dem Update startet, testet Sol, nicht Astra. Wer Erfahrungsberichte zu „GPT-6.2 in Codex" liest, sollte darum fragen, welches der beiden gemeint ist. Unabhängige Coding-Zahlen zu beiden haben wir weiter nicht.

Claude Code: Was im Hintergrund läuft, steht jetzt in /tasks

Neueste Version ist weiter v2.1.330 vom 20.11.[1] Am Wochenende kam nichts dazu. Für den Alltag am nützlichsten aus der Woche ist v2.1.329 vom 19.11.: /tasks zeigt jetzt „this session's scheduled tasks, /loop wakeups, the goal and this conversation's forks".[1]

Dazu v2.1.330: Anmeldung an Organisationen aus Anthropics Enterprise Admin Console, danach übernimmt Claude Code deren Einstellungen und Cloud-Provider oder Gateway.[1] Neu ist auch easel, „a built-in mod that draws charts when asked and under MCP metrics results".[1] Und v2.1.328 vom 19.11. bringt den Auto-Modus für Opus 4.6 und Sonnet 4.6 auf Bedrock, Google Clouds Agent Platform, Microsoft Foundry und dem Claude-Apps-Gateway.[1]

Meine Sicht: Die Woche zeigt eine klare Richtung. Agenten laufen immer öfter unbeaufsichtigt, mit Loops, geplanten Tasks und Forks, und die Werkzeuge bauen jetzt das Armaturenbrett dafür. /tasks ist genau das: eine Stelle, an der du siehst, was gleich von selbst wieder aufwacht.

Ausprobieren Starte in einer Session einen /loop und öffne dann /tasks. Warum: Du lernst in einer Minute, wie du einen vergessenen Loop findest, bevor er dir Tokens kostet.

Cline: Kompaktierung lässt sich abbrechen

Das einzige neue Release seit Freitag. Cline v4.1.27 und Cline SDK v0.2.1 kamen am 21.11.[1] Im SDK gilt jetzt: „A running compaction can be stopped, and cancellations are counted in telemetry".[1] Die Extension enthält außerdem die Lizenz-Hinweise ihrer Drittanbieter-Pakete.[1]

Kompaktierung: Wenn das Gespräch mit dem Agenten zu lang für das Kontext-Fenster wird, fasst das Werkzeug den bisherigen Verlauf zusammen und macht mit der Zusammenfassung weiter. Das dauert und kostet Tokens. Wie ein Protokoll, das jemand schreibt, bevor das Whiteboard gewischt wird.

Meine Sicht: Ein kleines Release, aber ein echtes Problem. Eine Kompaktierung im falschen Moment kann Details verlieren, die du gerade brauchst. Wer sie abbrechen kann, behält die Kontrolle.

Es ist Montag, der dreiundzwanzigste November. Ruhig heute: Seit Freitag kam kein neues Release von Anthropic, OpenAI, Google oder Cursor. Nur Cline hat am Samstag ein kleines Update gebracht.

Das wichtigste Thema ist ein Sicherheits-Muster von Simon Willison. Bei der externen Sandbox läuft der Agent normal auf deinem Rechner, aber jeder Befehl, den er ausführt, läuft in einer abgeschotteten Linux-Umgebung. Es gibt drei Varianten, eine davon mit Apple Containers. Claude Code und Codex lassen sich daran anschließen. Dazu kommen eine Liste erlaubter Hosts und ein Weg, API-Aufrufe zu machen, ohne dass der Code das Secret kennt. Das ist besonders nützlich, wenn du lokale Modelle ausprobierst.

Passend dazu: Claude Code kann seit Version zwei Punkt eins Punkt drei zwei sieben MCP-Server über die Standard-Eingabe anlegen. So landen Tokens nicht mehr in der Shell-History.

Bei OpenAI ist GPT sechs Punkt zwei Sol jetzt das Standard-Modell in Codex, nicht Astra. Wer Berichte über GPT sechs Punkt zwei in Codex liest, sollte fragen, welches der beiden gemeint ist.

Claude Code zeigt mit dem Befehl tasks jetzt geplante Aufgaben, Loops und Forks an einer Stelle. Und bei Cline lässt sich eine laufende Kompaktierung jetzt abbrechen.

Cursor ist seit dem sechsten November still, Continue seit Juni. Eine Frist zum Schluss: Gemini vier Carbon kostet ab dem ersten Dezember das Doppelte, vier Dollar pro Million Eingabe-Tokens und zwanzig Dollar pro Million Ausgabe-Tokens.
