GLM 5.4: Schleifen statt mehr Parameter

Z.ai hat am 23.11. GLM 5.4 vorgestellt. Der Titel der Ankündigung lautet „Toward Generalized Coding with Our First Loop Transformer".[1] Simon Willison hat das Modell sofort ausprobiert. Seine zwei wichtigsten Sätze betreffen den Zugang: „GLM 5.4 is not (yet?) available as open weights" und „5.4 cannot currently be accessed through the regular API".[1] Er hat das Coding-Plan-Abo von Z.ai abgeschlossen, und mit dessen API-Key kam er an das neue Modell.[1]

Loop Transformer: Ein normales Sprachmodell schickt jedes Wort einmal durch einen Stapel von Schichten, von unten nach oben. Z.ai beschreibt es so: „a group of weight-shared layers runs for multiple iterations".[1] Ein Teil des Stapels läuft also mehrmals hintereinander, mit denselben Gewichten. Das Ergebnis laut Z.ai: „a deeper network without increasing the parameter count".[1] Wie ein Text, den du dreimal liest statt einmal: Du brauchst kein größeres Gehirn, aber mehr Zeit.

Was wir nicht wissen: Preise und Benchmark-Zahlen. Die Seite nennt keine davon.[1] Willisons eigener Test ist sein bekannter Pelikan auf dem Fahrrad, also ein Bauchgefühl-Test, kein Benchmark. Sein Urteil zur Version mit maximalem Aufwand: „It's not great to be honest - the pelican is recognizable".[1] Er schreibt aber auch, dass die Pelikane von 5.3 und 5.4 „much more comparable to those I get from OpenAI or Anthropic models" sind.[1] Zum Vorgänger GLM-5.3 gibt es Coding-Zahlen von Z.ai selbst, aber unabhängige Tests weichen davon ab. Die Zahlen lassen wir darum weg.[2]

Vorbehalt Ob „Loop" in der Praxis mehr Qualität pro Euro bringt, zeigt erst eine unabhängige Messung. Mehr Durchläufe heißen in der Regel mehr Rechenarbeit pro Token, also wahrscheinlich langsamere Antworten. Ohne Preise und Zahlen ist das heute eine Architektur-Meldung, kein Modell-Tipp.

Meine Sicht: Die Architektur ist interessant, der Zugang ist die eigentliche Nachricht. Für dich als jemand, der Gemma und Qwen lokal betreibt, ist GLM 5.4 im Moment nicht nutzbar. Du kannst es nicht herunterladen und nicht über eine normale API in deinen Harness hängen. Das Fragezeichen in Willisons „not (yet?)" ist der Punkt, den ich beobachten würde. Kommen die Gewichte später, ist ein Loop-Modell für lokale Hardware spannend: wenig Parameter heißt wenig Speicher, und auf einem Rechner mit begrenztem RAM ist Speicher meist der Engpass, nicht die Zeit. Bis dahin ist es ein Abo-Produkt wie jedes andere.

Claude Code: Code Mode kommt zu den Cloud-Anbietern

Claude Code v2.1.331 vom 23.11. bringt „Code Mode support in terminal sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude Platform on AWS".[1] Code Mode gibt es seit v2.1.323 vom 12.11. Dort heißt es: „an experimental opt-in in which Claude writes JavaScript to call its tools".[1]

Code Mode: Normalerweise ruft das Modell ein Tool auf, wartet auf das Ergebnis, liest es und ruft dann das nächste Tool auf. Jeder Schritt ist eine Runde mit dem Modell. Im Code Mode schreibt Claude stattdessen ein kleines Skript, das mehrere Tool-Aufrufe hintereinander macht, mit Schleifen und Bedingungen. Wie der Unterschied zwischen einem Kollegen, der für jede Datei einzeln fragt, und einem, der dir ein Shell-Skript schreibt.

Die Release-Liste zeigt, wie jung das Feature ist. Seit dem 12.11. haben fast alle Versionen Code-Mode-Fehler repariert. v2.1.331 allein behebt mehrere, zum Beispiel: „Fixed Code Mode losing the middle of a long script output; Claude now gets a path to the uncut text".[1] v2.1.329 stoppt jetzt „a runaway loop in Code Mode filling the machine's memory".[1]

Aus demselben Release für den Alltag nützlich:

  • claude doctor hat einen Abschnitt zur API-Verbindung. Er sagt, ob die API erreichbar ist, „with the HTTP status or the error".[1]
  • VS Code: „Fix with Claude Code" als Quick Fix für Fehler, Warnungen und fehlgeschlagene Tests, und „Resolve Merge Conflicts" in Dateien mit Konflikten.[1]
  • MCP: Tool-Aufrufe hängen nicht mehr bis zu 30 Minuten, wenn ein lokaler Server eine kaputte Antwort schickt.[1]
Frist „on or after November 30, 2026: plugin marketplaces in managed extraKnownMarketplaces will auto-update by default".[1] Wer einen Marketplace fest auf einem Stand halten will, setzt vorher "autoUpdate": false auf dessen Eintrag.

Meine Sicht: Der Schritt zu Bedrock und Co. zeigt, dass Anthropic Code Mode ernst meint. Firmen mit Cloud-Vertrag sollen es auch bekommen. Die Fehlerliste zeigt aber auch: „experimental" ist hier wörtlich gemeint. Ich würde es in einem Projekt mit vielen MCP-Tools testen, denn dort spart ein Skript die meisten Runden. In einem Repo, in dem ein Fehler wehtut, würde ich noch warten.

Ausprobieren Führe nach dem Update claude doctor aus. Warum: Wenn Claude Code hinter einem Proxy oder Gateway hängt, siehst du jetzt in einer Zeile, ob es an der Verbindung liegt.

Codex: Verschachtelte Agenten werden auffindbar

Codex CLI 0.172.0 kam heute, am 24.11. Zwei Änderungen betreffen Agenten, die andere Agenten starten. Erstens: „Follow thread links from search results and transcripts to open saved conversations and nested agents in the terminal".[1] Zweitens: „Interrupting a parent turn preserves queued replies from child agents for the next turn".[1] Die Version davor, 0.171.0 vom 20.11., hat GPT-6.2 Sol als Standard im Modell-Katalog gesetzt.[1]

Eltern- und Kind-Agenten: Ein Agent teilt eine große Aufgabe auf und startet für jeden Teil einen eigenen Helfer, etwa „suche alle Aufrufe dieser Funktion". Die Helfer arbeiten und schicken ihre Ergebnisse zurück. Bisher war das so: Wenn du den Haupt-Agenten unterbrochen hast, konnten die fertigen Antworten der Helfer verloren gehen. Wie ein Chef, der ein Meeting abbricht, und die Berichte der Kollegen landen im Papierkorb statt auf dem Stapel für morgen.

Meine Sicht: Das klingt klein, ist aber genau der Ärger, den man mit Unter-Agenten im Alltag hat. Du unterbrichst, weil der Haupt-Agent in die falsche Richtung läuft, und dabei geht die Arbeit der Helfer verloren. Die Thread-Links lösen das zweite Problem: Später willst du sehen, was ein Helfer wirklich gemacht hat, und findest das Transkript nicht.

OpenHands: Gespräche verweisen auf Gespräche

OpenHands v1.44.0 vom 23.11. bringt „conversation mentions, behind the conversation_mentions flag".[1] Drei Tage vorher hat v1.43.0 Automationen in den Setup-Assistenten gebracht: „create automations enabled from the setup wizard".[1]

Meine Sicht: Das Release-Feature ist kurz beschrieben, und hinter einem Flag ist es noch nicht für alle gedacht. Die Richtung passt aber zu Codex: Ein Gespräch mit einem Agenten soll auf ein früheres zeigen können, statt dass du den Kontext von Hand kopierst.

Harness-Vergleich: Alle bauen das Armaturenbrett

Legt man die Woche nebeneinander, arbeiten drei Harnesses am selben Problem. Agenten laufen länger, starten Helfer und wachen von selbst wieder auf, und du verlierst den Überblick.

  • Claude Code zeigt seit v2.1.329 in /tasks „scheduled tasks, /loop wakeups, the goal and this conversation's forks".[1]
  • Codex macht verschachtelte Agenten über Links auffindbar und behält ihre Antworten nach einem Abbruch.[2]
  • OpenHands testet Verweise zwischen Gesprächen.[3]

Meine Sicht: Bei den Modellen gibt es große Unterschiede, bei den Harnesses gleichen sich die Funktionen schnell an. Was jetzt zählt, ist die Frage: Findest du nach einer Stunde noch heraus, was dein Agent und seine Helfer getan haben? Wenn du ein Werkzeug wählst, achte darauf mehr als auf ein neues Kommando.

Willison: Agent mit Seitenleiste

Simon Willison hat heute datasette-agent 0.7a1 veröffentlicht. Neu: „chat sessions can open an iframe side panel, and that panel can then navigate to different pages".[1] Am 23.11. kam außerdem datasette-charts 0.1a0. Das Plugin „compiles each chart to a SQL query that aggregates across the entire result set".[1]

Meine Sicht: Das ist kein Coding-Agent im engen Sinn, aber ein gutes Muster. Ein Agent, der dir eine Seite neben dem Chat öffnet, zeigt sein Ergebnis, statt es nur zu beschreiben. Es ist eine Alpha, also nur etwas für Neugierige.
