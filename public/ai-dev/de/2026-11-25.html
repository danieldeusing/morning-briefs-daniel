Claude Code 2.1.332: Skills kommen vom MCP-Server

Claude Code 2.1.332 kam heute, am 25.11. Die erste Zeile im Changelog: „Added skills from MCP servers (beta). They show as server:skill in the / menu; other skills keep their names".[1] Ein MCP-Server kann damit nicht nur Tools anbieten, sondern auch fertige Arbeitsanleitungen für Claude.

MCP und Skills: MCP (Model Context Protocol) ist ein Standard, über den ein Programm einem Agenten Werkzeuge anbietet, etwa „lies dieses Ticket" oder „frag diese Datenbank ab". Ein Skill ist eine kleine Anleitung mit Text und manchmal Shell-Befehlen, die Claude bei Bedarf lädt. Bisher lagen Skills als Dateien auf deinem Rechner. Jetzt kann der Server sie mitliefern. Wie ein Werkzeugkasten, der nicht nur Schraubenzieher enthält, sondern auch gleich die Bauanleitung dazu.

Der zweite Punkt im selben Release ist der wichtigere: „Added a PreSkillShellCommand hook event that can refuse a skill or command's inline shell commands as it loads".[1] Ein Skill darf Shell-Befehle enthalten, die beim Laden laufen. Kommt der Skill von einem fremden Server, läuft also fremder Code. Mit dem Hook prüft dein eigenes Skript jeden dieser Befehle und kann ihn ablehnen.

Hook: Ein Hook ist ein Skript, das Claude Code an einem festen Punkt automatisch aufruft, zum Beispiel vor jedem Tool-Aufruf. Das Skript darf „ja" oder „nein" sagen. Wie ein Türsteher, der jeden Gast kurz ansieht, bevor er in den Club darf.
Achtung, zwei Rechner Der Changelog sagt: „on 2.1.331 and older, a settings file naming it opens a dialog at start".[1] Wenn du dieselben Settings auf mehreren Macs nutzt und einer noch auf einer älteren Version läuft, startet Claude Code dort mit einem Dialog. Erst alle Rechner aktualisieren, dann den Hook eintragen.

Aus demselben Release für den Alltag wichtig:

  • Token-Präfix: CLAUDE_CODE_OAUTH_TOKEN des Self-hosted Runners „can now end in oat02- as well as oat01-". Anthropic schreibt selbst: „Update proxy rules and log scrubbers that match oat01-".[1]
  • Cloud-Aliase: Auf Google Clouds Agent Platform und Microsoft Foundry zeigt sonnet jetzt auf Sonnet 5.5, Foundrys opus auf Opus 5.5. Auf Bedrock bleibt sonnet bei Sonnet 4.5.[1]
  • Auto-Modus: Sitzungen auf Sonnet 5 oder 5.5 bei Bedrock Mantle, Agent Platform und Foundry starten im Auto-Modus, wenn kein Modus gesetzt ist. Abschalten mit disableAutoMode auf "disable".[1]
  • Reservierter Name: computer-use ist auf Macs mit Computer Use ein reservierter Skill-Name. Ein eigener Skill mit diesem Namen lädt nicht mehr.[1]
  • MCP-Stabilität: SSE-Server hängen nicht mehr nach einem abgerissenen Event-Stream, und das Terminal friert nicht mehr ein, wenn ein lokaler Server seine Standardausgabe flutet.[1]
Frist Verwaltete Plugin-Marketplaces in extraKnownMarketplaces aktualisieren sich „on or after November 30, 2026" standardmäßig selbst (angekündigt seit 2.1.331 vom 23.11.).[1] Wer einen Stand festhalten will, setzt vorher "autoUpdate": false auf den Eintrag.

Meine Sicht: Skills vom Server sind ein echter Schritt für das MCP-Ökosystem. Ein Team kann seine Arbeitsweise einmal auf dem Server pflegen, statt Skill-Dateien in jedes Repo zu kopieren. Aber damit wird ein MCP-Server zu einer Quelle von ausführbarem Code, nicht nur von Daten. Gut ist, dass Anthropic den Hook im selben Release liefert und nicht drei Versionen später. Ich würde Server-Skills nur von Servern annehmen, die ich selbst betreibe oder genau kenne, und den Hook vorher aufsetzen. Für einen Server aus einem fremden Marketplace gilt dieselbe Vorsicht wie für ein npm-Paket mit postinstall-Skript.

Ausprobieren Schreib einen PreSkillShellCommand-Hook, der jeden Befehl in eine Log-Datei schreibt und dann erlaubt. Warum: Nach einer Woche weißt du, welche Skills überhaupt Shell-Befehle ausführen, und kannst erst danach gezielt sperren.

Willison: Drei Wendepunkte in zwölf Monaten

Simon Willison hat am 24.11. seine Keynote vom AI Engineer Code Summit aufgeschrieben. Die These: Es gab „three significant inflection points in the abilities of LLMs and coding agents in the past twelve months".[1]

  • November 2025, Opus 4.5 und GPT-5.1: „Opus 4.5 was the first model I had used with Claude Code where the default result was generally the right thing." Über Codex mit GPT-5.1: „it became reliably useful for many of my coding tasks."[1]
  • Juni und Juli 2026, Fable 5 und Mythos: Seine Faustregel für diese Modelle: „Give it a goal, give it the right tools, and watch it cook."[1]
  • September und Oktober 2026, Opus 5.5, GPT-5.6 Sol, GPT-6 Astra, Gemini 4: Die Modelle werden stark bei 3D-Modellen und Spielen. „Opus 5.5 was the first model I'd used that appeared to understand fun."[1]

Sein Fazit: „Software development has transformed beyond recognition in the last year."[1]

Meine Sicht: Der Text ist kein Nachrichten-Ereignis, aber eine gute Landkarte für deinen eigenen Werkzeugkasten. Für dich ist der zweite Wendepunkt der wichtigste, nicht der dritte. „Ziel plus richtige Tools" heißt: Die Qualität deines Agenten hängt heute stärker an den Tools, Skills und Hooks um ihn herum als am Modell-Namen. Das passt genau zur heutigen Claude-Code-Meldung. Und auffällig: Keiner der drei Punkte ist an einem Benchmark-Sprung festgemacht. Willison misst an der Frage „ist das Standard-Ergebnis richtig?", und das ist der Test, den du auch an deinem eigenen Repo machen kannst.

OpenHands 1.45: Der Agenten-Baum wird sichtbar

OpenHands v1.45.0 kam am 24.11., einen Tag nach v1.44.0.[1] Die für den Alltag wichtigste Zeile: „nest sub-agent conversations under their parent".[1] Startet ein Agent Helfer, siehst du deren Gespräche jetzt eingerückt unter dem Haupt-Gespräch, statt als lose Liste daneben.

Dazu kommen „OpenHands Projects in Canvas (experimental)" und Projekt-Gespräche in der Seitenleiste mit „files and PRs beside the chat".[1] Für die Factories, also wiederkehrende Automationen, zeigt die Seite jetzt die Arbeits-Logs, die neuesten zuerst.[1]

Update seit gestern Gestern hat Codex CLI 0.172.0 Links eingeführt, die „saved conversations and nested agents in the terminal" öffnen.[2] Am selben Tag (24.11.) macht auch OpenHands dasselbe in seiner Weboberfläche.

Meine Sicht: Drei Harnesses lösen in einer Woche dasselbe Problem: Wer hat was getan, als mein Agent fünf Helfer gestartet hat? Das ist ein gutes Zeichen. Es heißt, dass Unter-Agenten im Alltag angekommen sind und nicht mehr nur in Demos laufen. Für deine Wahl zwischen den Tools zählt das mehr als jedes neue Kommando. Projects im Canvas ist experimentell, das würde ich noch nicht für echte Arbeit nutzen.

Benchmarks: Der Harness verdreifacht den Score

In den letzten drei Wochen kamen Fable 5.2 und Mythos 5.2 (09.11.), GPT-6.2 Astra und Sol (17.11.) und Gemini 4 Neon (18.11.).[1][2] Für keines davon gibt es heute einen unabhängigen Eintrag auf SWE-bench Verified. Das unabhängige Board von Vals AI hat den Stand vom 01.09.2026. Damals lag Claude Opus 5 mit 97,00 % vorn, die ersten fünf liegen zwischen 95,40 und 97,00 %.[3] Das Board ist also alt und oben fast voll. Darum heute kein Chart.

Harness: Der Harness ist das Programm um das Modell herum. Er gibt dem Modell Tools, liest Dateien, führt Tests aus und entscheidet, wann die Aufgabe fertig ist. Claude Code, Codex und OpenHands sind Harnesses. Wie ein Rennwagen: Derselbe Motor fährt in einem guten Chassis viel schneller als in einem schlechten.

Wie stark der Harness wirkt, zeigt Google selbst. In Googles Ankündigung erreicht Gemini 4 Neon auf dem Benchmark SWE-sweep „a state-of-the-art 39.0% in Google Antigravity", im schlichten mini-SWE-Harness dagegen 12,8 %.[2] Das ist dasselbe Modell, mit einem Faktor von etwa 3 nur durch die Umgebung. Beide Zahlen meldet Google selbst. Eine unabhängige Messung gibt es nicht.

Vorbehalt Google nennt für Neon auch Platz 1 im Artificial Analysis Coding Agent Index mit 58,6.[2] Die Seite von Artificial Analysis lädt ihre Zahlen per JavaScript, wir konnten den Wert dort nicht selbst lesen. Er ist darum hier eine Anbieter-Angabe, keine geprüfte Messung.

Meine Sicht: Wenn ein Harness-Wechsel den Score verdreifacht, sagt ein Vergleich „Modell A gegen Modell B" wenig, solange der Harness nicht genannt wird. Für dich heißt das: Teste ein neues Modell in dem Harness, den du wirklich nutzt, an einer Aufgabe aus deinem Repo. Das ist auch genau Willisons Maßstab.

Es ist Mittwoch, der fünfundzwanzigste November. Die wichtigste Meldung kommt heute aus Claude Code: Version zwei Punkt eins Punkt drei drei zwei lädt Skills jetzt direkt von MCP-Servern.

Ein Skill ist eine kleine Anleitung für Claude, manchmal mit Shell-Befehlen darin. Bisher lagen Skills als Dateien auf deinem Rechner. Jetzt kann ein MCP-Server sie mitliefern, sie erscheinen im Schrägstrich-Menü mit dem Namen des Servers davor. Damit kann ein Server aber auch Code auf deinen Rechner bringen. Darum ist der zweite Teil des Releases wichtig: ein neuer Hook namens PreSkillShellCommand, mit dem dein eigenes Skript jeden dieser Befehle prüfen und ablehnen kann.

Ein Hinweis für mehrere Rechner: Ältere Versionen von Claude Code zeigen beim Start einen Dialog, wenn die Settings diesen Hook nennen. Also erst alle Macs aktualisieren. Außerdem kann das OAuth-Token des Self-hosted Runners jetzt mit oat null zwei beginnen, Log-Filter sollten das kennen. Und frühestens ab dem dreißigsten November aktualisieren sich verwaltete Plugin-Marketplaces von selbst.

Simon Willison hat seine Keynote aufgeschrieben, über drei Wendepunkte in zwölf Monaten. Erstens Opus vier Punkt fünf vor einem Jahr, das erste Modell, bei dem das Standard-Ergebnis meistens stimmte. Zweitens die Fable-Modelle im Sommer: Gib ihnen ein Ziel und die richtigen Werkzeuge. Drittens im Herbst Modelle, die bei 3D und Spielen stark sind. Für die tägliche Arbeit zählt vor allem der zweite Punkt: Die Werkzeuge um das Modell herum machen den Unterschied.

OpenHands Version eins Punkt vier fünf hängt die Gespräche von Unter-Agenten jetzt sichtbar unter ihr Eltern-Gespräch. Codex und OpenHands haben gestern Ähnliches gebracht. Drei Harnesses lösen damit in einer Woche dasselbe Problem: Du sollst sehen, was deine Agenten im Hintergrund tun.

Bei den Benchmarks gibt es weiter keine unabhängigen Zahlen für die neuen Modelle von Anthropic, OpenAI und Google. Google selbst zeigt aber, wie viel der Harness ausmacht: Gemini vier Neon kommt in Googles eigenem Harness auf neununddreißig Prozent, im schlichten Harness auf zwölf Komma acht. Das ist dasselbe Modell, nur in einer anderen Umgebung.

Cursor ist seit dem sechsten November still, Cline weiter auf dem Stand vom einundzwanzigsten, Continue und Aider ruhen. Gemini vier Carbon kostet ab dem ersten Dezember das Doppelte. Morgen schauen wir, ob die ersten MCP-Server ihre Skills schon ausliefern.
