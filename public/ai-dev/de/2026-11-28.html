Nachgereicht: Inkling 2 Mini läuft auf dem Laptop

Thinking Machines hat Inkling 2 Mini am 20.11. veröffentlicht. Der erste Satz der Ankündigung: „Today we are releasing Inkling 2 Mini, a fast, powerful model that's small enough to run on your laptop."[1] Wir haben das Modell bisher nicht gebracht. Das holen wir nach, denn es ist das interessanteste lokale Coding-Modell des Monats.

Mixture-of-Experts (MoE): Ein Modell aus vielen Teil-Netzen („Experten"). Pro Wort rechnet nur ein kleiner Teil davon. Wie ein Krankenhaus mit vielen Fachärzten: Für deinen Fall kommen nur zwei in den Raum, nicht alle. Darum ist das Modell schneller, als seine Gesamtgröße vermuten lässt.

Die Eckdaten laut Hersteller: „a Mixture-of-Experts model with 26.4B total parameters, 3.4B active".[1] Der Speicherbedarf liegt bei „~20GB", genug für „consumer laptops and desktop AI computers".[1] Zum Start läuft es per Ollama auf jedem Mac mit mindestens 32 GB RAM. Die Gewichte liegen auf Hugging Face, eine Lizenz nennt die Seite nicht.[1] In der Ollama-Bibliothek steht es als offizielles Modell inkling-2-mini, mit rund 148 900 Downloads und einem Update vor wenigen Stunden (Stand 28.11.).[2]

Widerspruch auf der Seite Der Text nennt 3,4 Mrd. aktive Parameter, die Vergleichstabelle „5.4/26.4". Die Seite erklärt die 5,4 Mrd. mit „looping": Ein Teil der Schichten läuft pro Wort mehrmals. Wie ein schwieriger Satz, den du zweimal liest: Du brauchst keine neuen Augen, aber mehr Zeit.[1] Für dich heißt das: Der Speicher richtet sich nach den 26,4 Mrd., die Geschwindigkeit eher nach den 5,4 Mrd.

Die Zahlen. Die Tabelle des Herstellers zeigt 79,2 % auf SWE-bench Verified (nur Bash), den besten Wert der Tabelle. Den zweitbesten Wert von 77,8 % ordnen wir nach der Spaltenposition Qwen3.8-27B zu; die Seite beschriftet das nicht.[1] Dazu 73,7 % auf SWE-bench Multilingual und 48,2 % auf DeepSWE v1.1.[1] Auf Terminal-Bench v4.0 schafft das Modell dagegen 5,6 %.[1]

„Bash only": Das Modell bekommt für den Test nur eine Kommandozeile, kein eigenes Agenten-Gerüst mit Spezial-Werkzeugen. Wie eine Fahrprüfung ohne Einparkhilfe. Das Ergebnis sagt also mehr über das Modell als über das Werkzeug drumherum.
Vorbehalt Alle Werte stammen vom Hersteller. Einen unabhängigen Messwert für Inkling 2 Mini haben wir nicht gefunden. SWE-bench Verified ist zudem fast ausgereizt: Große Modelle liegen dort laut Sekundärquellen über 90 %, die Werte haben wir aber nicht selbst geprüft. Ein Test, auf dem alle gut sind, trennt die Modelle schlecht. Und laut Seite ist das Modell schwächer bei langen Gesprächen und komplexen Anweisungen.[1]

Meine Sicht: Die 5,6 % auf Terminal-Bench v4.0 sind die ehrlichste Zahl im ganzen Datenblatt. Sie zeigen, wo ein Modell dieser Größe aufhört. Für kleine, klar umrissene Aufgaben auf deinem eigenen Rechner kann es trotzdem reichen. Der Hersteller nennt es „a strong choice for running multiple persistent agents on local hardware".[1] Ob das stimmt, zeigt nur ein Test an deinem eigenen Code. Die Schwäche bei komplexen Anweisungen ist dabei der Punkt, auf den ich achten würde: Agenten-Prompts sind lang und voller Regeln.

Ausprobieren Hat dein Mac 32 GB oder mehr, starte ollama run inkling-2-mini und gib ihm eine echte, kleine Aufgabe aus deinem Repo. Lass dieselbe Aufgabe vom Qwen-Modell laufen, das du schon nutzt. Warum: Ein Abend reicht, um zu sehen, ob die Tabelle an deinem Code hält.

Wer die Trainingsdaten für Coding-Modelle verkauft

Latent Space hat am 27.11. einen Text mit dem Titel „Inside the exploding Coding Data Market" veröffentlicht. Die Kernzahl: Es gibt „multiple ~1 year old statups all making $~100m/year in data contracts for frontier labs" (Tippfehler im Original).[1] Der Text ist der Vorspann zu einem Podcast mit Gabe Greenberg, CEO von G2i. Namen der Start-ups oder Belege für die 100 Mio. $ nennt er nicht.[1]

Verifier: Ein Programm, das automatisch prüft, ob die Lösung eines Modells stimmt, zum Beispiel über Tests. Wie der Lösungsschlüssel beim Rechentest: Der Lehrer muss nicht jede Rechnung lesen, er vergleicht nur das Ergebnis. Mit vielen solchen Aufgaben und Prüfern trainieren die Labore ihre Modelle.

Laut Text besteht die Arbeit aus drei Teilen: Aufgaben entwerfen, die Startdaten wählen und einen Verifier bauen, der die Ausgabe bewertet.[1] Manche Labore zahlen einen Aufschlag für Daten, die die Konkurrenz nicht kaufen kann.[1]

Meine Sicht: Das erklärt, warum ältere Coding-Benchmarks so schnell ausgereizt sind. Wenn Labore Millionen für Aufgaben zahlen, die wie „repariere diesen Bug, bis die Tests grün sind" aussehen, dann üben die Modelle genau das Format von SWE-bench. Das ist kein Betrug, aber die Zahl misst dann eher Übung als Können. Darum gewichte ich neue, schwere Tests wie Terminal-Bench v4.0 höher, und noch höher deinen eigenen Test am eigenen Code.

MCP: Skills kommen jetzt auch vom Server

Skill über MCP: Ein Skill ist ein Paket aus Anweisungen und Skripten, das ein Agent bei Bedarf lädt. Bisher lag es lokal bei dir. Jetzt kann ein MCP-Server es mitliefern. Wie ein Werkzeugkoffer, den der Lieferant gleich mit der Maschine schickt.

Skills über MCP sind seit dem 24.11. in der öffentlichen Beta, so berichtet es der Wochen-Rückblick von ThursdAI.[1] Claude Code unterstützt das seit 2.1.332 vom 25.11.: „Added skills from MCP servers (beta). They show as server:skill in the / menu".[2] Mit derselben Version kam ein neuer Hook: „Added a PreSkillShellCommand hook event that can refuse a skill or command's inline shell commands as it loads".[2]

Die Größe des Ökosystems: ThursdAI nennt „over 700 million" SDK-Downloads im Monat, vor einem Jahr 90 Mio.[1] Eine Primärquelle für diese Zahl haben wir nicht gefunden. Nimm sie als Größenordnung, nicht als Messwert.

Die Kehrseite liegt auf der Hand. Ein Skill vom fremden Server kann Shell-Befehle mitbringen. Ein Sicherheitsanbieter wirbt im selben Rückblick schon mit einem Klassifikator für „poisoned skill files", also präparierte Skill-Dateien; seine Trefferquote von 99,04 % ist eine Eigenangabe.[1] Dass es dafür schon ein Produkt gibt, zeigt: Das Risiko ist nicht theoretisch.

Meine Sicht: Der neue Hook ist das wichtigere Feature, nicht die Skills selbst. Wer Skills von Servern lädt, die er nicht selbst betreibt, sollte vorher eine PreSkillShellCommand-Regel setzen. Die Beta läuft seit drei Tagen ohne Folge-Release in Claude Code. Ich würde abwarten, bis die erste Korrektur-Version kommt, und bis dahin nur Skills von eigenen Servern laden.

Es ist Samstag, der achtundzwanzigste November. Ein ruhiger Tag: kein neues Modell und kein großes Release bei den Coding-Werkzeugen. Darum holen wir ein Modell nach, das wir vor gut einer Woche übersehen haben.

Thinking Machines hat am zwanzigsten November Inkling zwei Mini veröffentlicht. Das Modell hat offene Gewichte und braucht laut Hersteller rund zwanzig Gigabyte Speicher. Es läuft per Ollama auf jedem Mac mit mindestens zweiunddreißig Gigabyte Arbeitsspeicher und steht dort schon in der offiziellen Bibliothek.

Laut Hersteller erreicht es neunundsiebzig Komma zwei Prozent auf SWE-bench Verified, nur mit einer Kommandozeile. Das ist aber eine Herstellerzahl, und dieser Test ist fast ausgereizt. Viel ehrlicher ist ein anderer Wert aus demselben Datenblatt: Auf dem neuen, schweren Terminal-Bench vier schafft das Modell nur fünf Komma sechs Prozent. Der Tipp: Wer genug Speicher hat, testet es an einer kleinen Aufgabe aus dem eigenen Code, im Vergleich zum Qwen-Modell, das er schon nutzt.

Latent Space beschreibt einen neuen Markt: Junge Firmen verkaufen Trainingsaufgaben für Coding-Modelle an die großen Labore, angeblich mit rund hundert Millionen Dollar Umsatz im Jahr. Belege nennt der Text nicht. Die Geschichte erklärt aber, warum alte Benchmarks so schnell ausgereizt sind: Die Modelle üben genau dieses Format.

Beim Model Context Protocol können Server seit dem vierundzwanzigsten November auch Skills mitliefern, in einer öffentlichen Beta. Claude Code zeigt sie seit Version zwei Punkt eins Punkt drei drei zwei an und bringt einen neuen Hook mit, der Shell-Befehle solcher Skills blockieren kann. Wer Skills von fremden Servern lädt, sollte diesen Hook zuerst einrichten.

Am Montag laufen zwei Fristen ab. In Claude Code aktualisieren sich verwaltete Plugin-Marketplaces danach von selbst, außer man schaltet das ab. Und der Einführungspreis für Gemini vier Carbon endet, ab Dienstag kostet es das Doppelte.

Codex hat eine neunte Alpha-Version ohne Notizen gebracht, die stabile Version bleibt null Punkt eins sieben zwei. Cursor und Continue bleiben still. Morgen schauen wir, ob Codex endlich eine stabile neue Version bringt, und am Montag, was die Fristen auslösen.
