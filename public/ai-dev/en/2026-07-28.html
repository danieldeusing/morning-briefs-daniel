MCP throws out the session

The announcement leaves no room for interpretation: "The release candidate is locked as of May 21, 2026. The final specification will be published on July 28, 2026." Ten weeks of frozen validation window, and today's the deadline. And the core of the biggest revision MCP has ever had isn't an addition — it's a deletion: "The Mcp-Session-Id header and the protocol-level session that came with it are also removed." The initialization handshake goes away, and any request can now land on any server instance. The operational payoff is spelled out in the announcement itself: "This enables deployment behind a plain round-robin load balancer instead of requiring sticky sessions."

blog.modelcontextprotocol.io · accessed 2026-07-28, 05:13 UTC
MCP and "stateless": MCP is the plug-standard between an AI model and your tools — a server offers up tools (files, GitHub, a database), a client like Claude Code or Cursor plugs into it, and neither one needs to know the other beforehand. Stateful, until now, worked like a coat-check ticket: on first contact you get a number, and every follow-up question has to go to that exact same attendant, because only they still remember what it was about. If ten people are working the counter, you need someone routing you back to the right one every time — those are "sticky sessions." Stateless means every question brings everything it needs along with it, so anyone can answer it. Operationally, that's the difference between "the server is a pet" and "the server is a commodity."

Three features retire

At the same time, three capabilities are being deprecated — each with a named replacement, none with a shrug:

DeprecatedReplacement per spec
Rootstool parameters, resource URIs, or server configuration
Samplingdirect connections to model providers' APIs
Loggingstderr over stdio transport, OpenTelemetry for structured observability

Sampling in particular is a statement: it let a server ask the client to query the model on its behalf — elegant in theory, barely supported in practice, and a nice little attack surface. MCP handing that back to the provider APIs shrinks the attack surface; it isn't a functionality gap.

blog.modelcontextprotocol.io · accessed 2026-07-28, 05:13 UTC
No need to panic "Deprecated" isn't a shutoff date for MCP. The feature-lifecycle policy keeps deprecated features "for at least twelve months, or at least ninety days under the policy's expedited-removal exception" in the spec before they can even be removed. So if you're using Roots today, you've got at least a year, not a single night. modelcontextprotocol.io · accessed 2026-07-28, 05:13 UTC

The quieter, bigger change: Extensions

Alongside the deletion sits a framework that strikes me as more important long-term than losing the session: "Extensions are identified by reverse-DNS IDs, negotiated through an extensions map on client and server capabilities, live in their own ext-* repositories with delegated maintainers, and version independently of the specification." In plain terms: the spec stops trying to be everything itself. Extensions get their own repos, their own maintainers, and their own version numbers — things like MCP Apps or Tasks now move independently of the core. It's the same model that's kept HTTP headers workable for decades: a small hard core, a soft named periphery.

blog.modelcontextprotocol.io · accessed 2026-07-28, 05:13 UTC
Sourcing, honestly I checked today at 05:13 UTC: the protocol's versioning page still says "The current protocol version is 2025-11-25," and the blog index's most recent post is still the beta SDKs from Jun 29 — no final-release post. A curious detail on the side: the same page still describes version negotiation as happening "during initialization" — exactly the handshake the new revision removes. What's written here, then, is today's announced and frozen state, not a live version confirmed by the docs. The day is still young.

Why the date still holds up

Because two independent parties are already acting on it. GitHub's own MCP server has supported the new spec since Jul 23, unambiguously in the changelog: "The MCP protocol is going stateless on 28th July 2026, and the GitHub MCP Server supports the latest spec ahead of the official release." And the beta SDKs for Python, TypeScript, Go, and C# have been ready with support for the 2026-07-28 version since Jun 29. When the world's biggest MCP server switches over ahead of time, that's not an announcement anymore — it's a migration.

What to do with this

Three concrete moves, in this order. (1) If you're running an MCP server: the sticky-session crutch in your load balancer or ingress can go — but only once your SDK speaks the new version, so check the version instead of guessing at config. (2) If you use Roots, Sampling, or Logging: write down a migration path once, but no need for a weekend shift — you've got at least twelve months. (3) If you're only a client, i.e. running Claude Code or Cursor against someone else's server: do nothing today. This break hits server operators, not users.

The license, finally read in the original

Second-hand summaries of the license have been circulating since yesterday. Today I opened the LICENSE in the repo myself. Three clauses matter. First, the exemption that settles everything for most people: "internal use of the Software, defined as any use that does not make the Software, its outputs, or its underlying capabilities available to third parties" — internal use is exempt. Second, the separate agreement: only needed once a licensee "operates a Model as a Service business, and the aggregate revenue … exceeds 20 million US dollars." Third, the naming requirement: "Kimi K3" has to appear visibly in the interface — but only above 100 million monthly active users or $20 million in monthly revenue. For a one-person shop, that simply means: free to use. "Modified MIT" is still a misleading label for it, though — this is its own license with an MIT gesture, not MIT itself.

Harness: A model alone doesn't solve a coding task — it needs a scaffold that shows it files, runs commands, and feeds error messages back. That scaffold is called a harness. Think of a cooking exam: same chef, different kitchen, different result — and nobody would write two scores from two kitchens into one table without noting which kitchen was which. A benchmark score without a named harness, then, isn't a number — it's a claim.

67.5 versus 67.3. Two-tenths — that's nothing, and that's exactly why it's interesting. Yesterday the gap between the vendor's number and the board's number on Frontier-Bench was 3.1 points; today it's 0.2. What connects both days isn't the size of the gap — it's its direction: the vendor's number is always higher. At two-tenths, that's noise; at three points, it was narrative.

The real caveat sits elsewhere — in the line K3 is being sold with: "Kimi K3 achieved 42.0 on SWE-Marathon, evaluated with the Kimi Code harness, compared to Claude Opus 4.8's 40.0 and GPT-5.6 Sol's 39.0." So the competitors' comparison numbers also come from Moonshot's harness, not from Anthropic or OpenAI. That's not dishonest — the setup is clearly named, and a fair comparison actually requires running every model in the same scaffold. It just means: the three-point lead is a statement about K3 in Moonshot's kitchen. Until someone with no stake in the outcome measures the same thing, it isn't a ranking.

It's Tuesday, July twenty-eighth. Today is protocol deadline day: the protocol your tools use to talk to your agents is getting its biggest change ever — and at the heart of it is a deletion.

MCP is going stateless. The announcement says, in plain language, that the session header and the protocol-level session behind it are being removed. The initialization handshake goes away. That sounds technical, but it's an operational gift: servers can now sit behind an ordinary load balancer instead of routing every user back to the same instance every time. Until now, that worked like a coat-check ticket — only one attendant still remembered what you were there for. From now on, every request carries what it needs, and anyone can answer it.

At the same time, three capabilities are being retired: Roots, Sampling, and Logging. Each has a named replacement — Roots through tool parameters or server configuration, Sampling through direct connections to model providers, Logging through standard error output or OpenTelemetry. Important for your nerves: deprecated doesn't mean shut off at MCP. The project's rules keep features like this in the spec for at least twelve months, ninety days in an expedited case. If you're using Roots today, you've got a year, not overnight.
