MCP now negotiates per request

Update since yesterday Yesterday this space carried a candor note: the final spec was announced for July 28, but as of 05:13 UTC the versioning page still showed 2025-11-25 and there was no release post on the blog. Both are answered today — differently. The post exists: Anthropic published "Bringing MCP 2026-07-28 to Claude" on July 28, 2026. And the docs have been substantively updated: every deep link now points to /specification/2026-07-28/, there's a registry of deprecated features under this version, and a dedicated section covers compatibility with the "handshake-based protocol revisions (2025-11-25 and earlier)".

What replaces the handshake

This is the part that was still missing yesterday: back then, the same page explicitly described version negotiation as something that happens "during initialization." Today a different mechanism is documented there, verbatim: "Every request declares the protocol version it is using via the io.modelcontextprotocol/protocolVersion key in its _meta field, and the server accepts or rejects each request independently." Under Streamable HTTP, the MCP-Protocol-Version header carries the same value. And the sentence with the biggest consequences: "Clients and servers MAY support multiple protocol versions simultaneously." So a server can serve old and new at once, instead of switching over on a cutoff date.

modelcontextprotocol.io/specification/versioning · accessed Jul 29, 2026, 06:40 UTC
Per-request negotiation: Until now this worked like a phone call — you dial, you agree at the start on which language you'll speak, and the rest of the conversation builds on that. Anyone joining midway understands nothing. Now it's like postal mail: every envelope has the language written on it, and each letter is accepted or returned on its own. The upside isn't elegance, it's operations — there's no more state a server has to remember, so any request can land on any instance. The cost: every request carries a bit more baggage.

The new mandatory RPC with the optional call

New on top of that is server/discover, described as "a mandatory RPC that returns the server's supported protocol versions, capabilities, and identity in a single request. Calling it is optional." Not a contradiction, but deliberate asymmetry: every server must offer it, no client has to use it. The cautious approach: query it once upfront. The impatient approach: just send the request and handle the UnsupportedProtocolVersionError — which comes with the list of supported versions attached, so the client can immediately retry the same call. The normal case costs no extra round trip, the error case fixes itself.

modelcontextprotocol.io · accessed Jul 29, 2026, 06:40 UTC
The contradiction in the same document Two paragraphs below the description of the new negotiation, at 06:40 UTC, it still says unchanged: "The current protocol version is 2025-11-25." So the page describes the mechanics of 2026-07-28, links to its sub-pages — and names a different version as current. My reading: the content has been merged, the status flag just hasn't caught up. What holds up: the spec text is live. What doesn't hold up: that this version has officially been declared "current." Anyone whose SDK gates on that line is still waiting today.

Anthropic's post is an announcement, not a rollout

Anyone trying to pull a release date out of the Claude blog won't find one: "Support is being rolled out across Claude products soon." Instead it offers the adoption numbers that explain the push — "MCP recently surpassed 400M monthly SDK downloads, a 4x increase this year" and "Claude now lists over 950 MCP servers in the connectors directory". On top of that, two changes beyond statelessness: authorization now aligns with production-grade OAuth 2.0 and OIDC, so servers can "connect to enterprise identity systems like Entra or Okta without workarounds" — and MCP Apps and Tasks move into a versioned Extensions framework, out of the core.

claude.com/blog · published Jul 28, 2026

What you do today

(1) As a client user: nothing. Claude Code, Cursor, and Cline keep speaking whatever their SDKs speak; the break hits servers. (2) As a server operator: read the backward-compatibility section and take the sentence about multiple simultaneous versions seriously — there's no reason for a cutoff-date migration when your server is allowed to serve both versions. (3) On deprecated features: still no reason to panic. The policy keeps them "for at least twelve months, or at least ninety days under the policy's expedited-removal exception" per the spec. A year, not overnight — that line hasn't changed since yesterday.

And now the footnote that puts all of it in perspective

The same page breaks down its entries by origin — and the result is striking: 104 self-reported, 0 verified. Not a single value on a board whose name carries the word Verified has been independently remeasured by the platform. The "Verified" in the name actually means something else — it refers to SWE-Bench's hand-checked task set, not the checked measurement. Nobody reads it that way, though, and that mix-up is exactly why these numbers show up as proof in pitch decks.

llm-stats.com · accessed Jul 29, 2026
Self-reported vs. verified: Self-reported means the vendor tested its own model and submitted the number. Verified would mean someone with no stake in the outcome ran the same test and got the same result. Think of travel-time estimates: "I can do the route in forty minutes" versus "the ADAC drove it and clocked forty." Both can be true. But one is a claim and the other is a measurement — and when an entire board is made of claims, the ranking inside it is a ranking of claims.

Yesterday this space noted that Opus 5 still had no clean SWE-Bench Verified score. That was too quick a read — the accurate statement is just this: missing from the llm-stats board are Opus 5, Kimi K3 (weights out since the day before yesterday), Kimi K2.7, Grok 4.5, and GPT-5.6. That corrects the obvious reading: it's not proof that only Anthropic submits while the competition ducks out — it's a coverage difference between aggregators. They're not measuring differently, they're listing differently. So anyone drawing a ranking from a single board is mostly ranking that board's roster — and that goes for every one of these boards, not just llm-stats.

The Fable 5 follow-up you need to know operationally

The underlying story is old and ran here back in June: Fable 5 was shut down for all users on Jun 12 following an export-control order — Anthropic couldn't verify users' nationality in real time; the trigger was a jailbreak found by Amazon researchers. What matters in practice today is just the rebuild: a new classifier blocks the reported technique "in over 99% of cases," and blocked cyber requests aren't rejected but silently redirected — "the request will instead be sent to Opus 4.8." It's Wednesday, July twenty-ninth. Yesterday, this newsletter flagged a question mark hanging over the new MCP spec: it was supposed to go final that day, but the documentation still showed the old version and there was no release post. Today the answer is in, and it's a mixed one.

The content has been swapped over. Every link on the versioning page now points to the July twenty-eighth revision, there's a registry of deprecated features under that version, and a dedicated section spells out compatibility with the older, handshake-based revisions. Anthropic also published its own post about it yesterday. Only one line hasn't caught up: as of six forty a.m. UTC, that same page still calls the November twenty twenty-five version the current one. The content is there; the label isn't.

The real news is the mechanism that replaces the handshake. Every single request now carries its own protocol version, tucked into a metadata field, and the server accepts or rejects each one independently. It used to work like a phone call: you agree on a language up front, and the rest of the conversation builds on that. Now it's more like postal mail: the language is printed right on the envelope. Because of that, clients and servers are allowed to speak multiple versions at once. For anyone running a server, that means there's no hard cutover date to plan around.

On top of that comes a new call named server slash discover. The spec calls it mandatory and, in the same breath, calls using it optional. That's not a contradiction, it's by design: every server has to offer it, but no client is required to call it. The cautious move is to check first what the other side supports. The impatient move is to just send the request — and if the version doesn't match, you get an error back that lists the supported versions right along with it. Anthropic's own post gives no rollout date, but it does share two numbers for scale: more than four hundred million monthly SDK downloads, a fourfold jump this year, and more than nine hundred fifty servers listed in Claude's directory.
