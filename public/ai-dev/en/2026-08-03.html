Google is stuck — on code, of all things

Gemini 3.5 Pro was supposed to ship in June. It's August 3rd, and the model is still only in partner testing. The reason, as reported by Bloomberg, is uncomfortably precise for this newsletter: Google "changed the data used to train Gemini in order to improve its coding abilities" — and the results of that run were disappointing. Google itself puts it more neutrally in its official statement: it is "currently testing 3.5 Pro, an improved Flash model, and other models with partners."

That's not a generic schedule slip. A vendor whose coding fine-tuning comes out worse than the prior version has exactly the kind of problem you can't buy your way out of with more compute. For the toolbox, the plain read is this: anyone betting on Google in the coding stack today is betting on a model that hasn't yet passed its own quality bar.

9to5google.com · Jul 16, 2026, citing a Bloomberg report, retrieved Aug 3, 2026

The little brother has been here for a while — which makes this stranger

Gemini 3.5 Flash has been generally available since May 19, 2026, explicitly "stable and ready for scaled production use." The numbers: Terminal-Bench 2.1 76.2%, MCP Atlas 83.6%, GDPval-AA 1656 Elo, CharXiv 84.2% — which, per Google, means the fast, cheap model beats the old flagship Gemini 3.1 Pro on key benchmarks. These are vendor numbers; no independent board carries this exact combination.

That's exactly where the real bind comes from. If Flash has already overtaken the previous Pro, a new Pro can't just be a little better — it has to be a lot better, or it's simply the pricier model with no argument for itself. That explains, more plausibly than any rumor mill, why Google would rather delay than ship.

Blind-test arena (LMArena): a platform where two models answer the same question without the user knowing which is which — you just pick the better answer. Like a wine tasting with the labels covered: the name can't sway anyone, only what's in the glass counts. Vendors like to slip new models in there under code names to gather feedback before revealing the name. That's why a sighting in the arena is treated in the industry as an early sign of a release — but it's not proof of a release date.

Spotted yesterday A single report claims Gemini 3.5 Pro was repeatedly spotted in LMArena's blind-test pool as of Aug 2, 2026. Trying to load that page directly today failed with 403; there's no second independent source. That leaves it a clue, not proof — and it's explicitly carried as such here. If it's true, a release is more likely weeks away than months.

GitHub Copilot has been pulling Gemini 2.5 Pro and Gemini 3 Flash from the model picker since July 31, 2026 — users and admins are being steered to replacement models. On its own, that's routine model housekeeping. Three SWE-Bench boards, three different winners

There's a number on the table today that's never come up here before: GPT-5.6 Sol hits 64.6% on SWE-Bench Pro. That's not a bad score — but it's 15.7 points behind the leaders there, Claude Mythos 5 (80.3%) and Claude Fable 5 (80.0%). The same model simultaneously leads Terminal-Bench at 91.9%, marked there explicitly as "best verified." A small sign of how messily this field is labeled: the source lists that figure under version 2.0, while the comparison numbers for other models run under 2.1.

Two leaderboards, one model, opposite stories. Cite only one of them and you can write, without lying, either "OpenAI leads" or "OpenAI trails by fifteen points." Which is exactly why the only defensible phrasing is the one that names the board.

benchlm.ai/models/gpt-5-6-sol (Jul 2026, retrieved directly) · cross-checked against a techtimes.com writeup from Jul 7, 2026 (direct retrieval 403, search-result excerpt only) — both list 64.6%
The three boards that all say "SWE": SWE-Bench Verified is the hand-checked classic — 500 real GitHub bugs that people confirmed are actually solvable. Scores run high because the field has since been optimized for it. SWE-Bench Pro is the deliberately harder successor with bigger, multi-file changes and a task set that's partly non-public — which is why the numbers land twenty to thirty points lower. Terminal-Bench measures something else entirely: not "fix this bug," but "get by on your own in a real shell." That's like written driving theory, a road test, and reversing with a trailer hitched — three exams, three grades, one driver. Mix up the grades and you're comparing nothing.
SWE-Bench Verified — top of the field, board state Aug 3, 2026 (aggregator llm-stats, not swebench.com)

What 64.6% costs — and what 61.5% costs

The price comparison is what makes the Pro number interesting in the first place. GPT-5.6 Sol runs $5 input and $30 output per million tokens (blended, $17.50; cached input $0.50). Meta's Muse Spark 1.1 hits 61.5 on the same board — 3.1 points less — at an estimated $0.26 per task, and has raised its coding index in this version from 59 to 71. Terminal-Bench 2.1: 80.0.

My take: three points on a benchmark with a partly non-public task set aren't an argument for a twentyfold price tag. They're an argument for the one hard run nobody else can pull off. For the rest of the day — refactoring, writing tests, reviewing logs — the expensive model mostly buys you peace of mind.

Inkling: the number that matters isn't the score

Thinking Machines — Mira Murati's company — released its first open-weight model, Inkling, on Jul 15, 2026, under Apache-2.0, with 975 billion total parameters and 41 billion active. The model card lists 77.6% on SWE-Bench Verified. That would put it well behind the Anthropic block in the table above — and the company says so itself: Inkling is "not the strongest model available today, open or closed."

The other number is the interesting one: for the same coding performance, Inkling reportedly needs a third of the tokens of Nvidia's Nemotron 3 Ultra. That's the metric that actually drives the bill in agentic runs — a model that solves the same task in fewer reasoning steps costs less and waits less, regardless of list price. Try it Why try it: Apache-2.0 plus 41 billion active parameters means a single server node is enough — for anyone whose source code can't leave the building, this is currently the most realistic open option above the 32-billion class.
