Orchard: the training apparatus, not the model

Microsoft Research open-sourced Orchard on Aug 3, 2026. What's notable is what got released: not another weights package, but the apparatus you use to train an agent. The core idea is stated in one sentence on the blog: „a lightweight proxy records the harness's own model calls as training data while each rollout runs in its own container, so an agent can be trained end-to-end directly in the harness that it will be deployed with."

That sounds like infrastructure minutiae, and it isn't. Until now, you'd train an agent model in a purpose-built training environment and then set it loose in a completely different tool harness — different prompt structure, different tool names, different error messages. The model learns habits for a world it will never actually work in. Orchard flips that: the proxy hooks into the real harness and turns its actual calls into training material.

microsoft.com/research · Aug 3, 2026, retrieved directly Aug 5, 2026 · companion paper: arXiv 2605.15040
Harness: the scaffolding around the model — the part that tells it what tools exist, executes its calls, and hands back the results. Claude Code is a harness; Cursor's agent mode is one too. The model itself can't touch anything; it only proposes, and the harness carries it out. Training an agent model used to be like driving school in an empty parking lot: first cones and hand signals, then eventually your first taste of real traffic. Orchard's approach is to practice in the real car on the real road from the start — every driving lesson is already the road test.

Three recipes, and the numbers behind them

Three fully trained examples ship alongside it. The most interesting one for us is Orchard-SWE: 69.7% on SWE-bench Verified, which Microsoft calls „a new state of the art among open-source models of comparable size (roughly 3 billion active parameters)", and 73% with a downstream reranking round.

And „three attempts" means exactly that — it counts as solved if one of three tries lands. On a board with a single attempt, the number would sit noticeably lower.

Is this worth it for your own setup?

Worth trying Why look at it: Orchard is the first open path to fine-tune a small model to your own harness instead of renting someone else's general-purpose model — a 3-billion-parameter agent that knows your own tools, running on hardware you own. What argues against it: this is research infrastructure, not a weekend project — per-run containers, GPU time, reward functions. Anyone working today with a rented flagship model isn't switching away from it because of this. Still worth reading: the finding that the same model picks up 14 more points in a better harness is useful even without running a single training job.

MCP throws the session away

The new MCP version was released on Jul 28, 2026, and it's the hardest cut the protocol has had yet. Points one and two on the changelog read, verbatim: „Remove protocol-level sessions and the Mcp-Session-Id header from the Streamable HTTP transport" and „Make MCP stateless: remove the initialize/notifications/initialized handshake." Instead, every single request now carries its own protocol version and the client's capabilities — in the _meta field.

Anyone who needs server-side state doesn't get it handed to them anymore: servers now issue explicit identifiers for that, passed back and forth as ordinary tool arguments. Also new is server/discover — a call every server must offer, so a client can ask for version and capabilities upfront.

modelcontextprotocol.io · changelog for version 2026-07-28 versus 2025-11-25, retrieved directly Aug 5, 2026
Stateless: until now, an MCP connection was like a phone call. You dial in, the server remembers who's on the line, and you have to stay on it. If the call drops, everything's gone — and a second staffer can't pick it up, because they never heard the beginning. From now on it's postcard traffic: every card carries everything it needs, and it doesn't matter who processes it at the post office. For operations, that's the whole difference — a stateless server can run behind any load balancer, on a serverless platform, or in ten copies at once, without needing to route requests back to the same sender.

Three features now have an expiration date

The part that affects your own server sits further down the list, and it's the less pleasant one: Roots, Sampling, and Logging are deprecated. They still work, but the spec now gives them a formal minimum notice period of twelve months and maintains its own registry of deprecated features. The recommended workarounds are spelled out: pass directories and files as tool parameters or a resource URI instead of via Roots; go directly against the model vendor's API instead of Sampling; write to stderr or use OpenTelemetry instead of Logging.

Two more removals with consequences on top of that. Dynamic OAuth client registration per RFC 7591 is deprecated in favor of client ID metadata documents. And resuming broken streams — the Last-Event-ID header along with event numbers — is gone with no replacement: „A broken response stream loses the in-flight request; clients MUST re-issue it as a new request with a new request ID." That's a deliberate trade: simpler operation for less of a safety net when a connection drops. For a long tool call over a shaky line, that means retries are now the client's job.

modelcontextprotocol.io · sections „Major changes" and „Deprecated," retrieved Aug 5, 2026

What to actually do about this today

Not much, but not nothing. Anyone running an MCP server only locally over STDIO notices nothing for now. Anyone running one over HTTP comes out ahead: the requirement for sticky sessions was the reason MCP servers used to land on a permanently running machine rather than a serverless platform — and that constraint just disappeared. Anyone using one of the three deprecated features now has a clock running. And with the mandatory server/discover, migration work is coming for anyone maintaining a custom implementation instead of an official SDK.

Two figures currently circulating are deliberately absent here: an adoption claim of several hundred million SDK downloads per month, which appears only in a single aggregator report with no primary source, and a widely shared warning about supposedly massive numbers of vulnerable MCP servers — no CVE entry, no security advisory, and the cited page blocked retrieval. What can be documented, though, is this: a protocol that gives itself a formal deprecation policy with a twelve-month window and its own registry isn't reckoning with just a few dozen implementations anymore.

Qwen3.8-Max, two days later

Yesterday this newsletter said Alibaba's new giant model trails Claude Fable 5 on the comparable coding scores — 67.7 to 80.0 on SWE-bench Pro. That still holds. What's more interesting now is where it does lead, and the answer isn't programming, it's operating a computer: 86.1 on OSWorld-Verified, ahead of GPT-5.6 Sol Max (83.2), Fable 5 (85.0), and Gemini 3.1 Pro (76.2). OSWorld measures whether a model can carry real desktop tasks through to completion in real programs — windows, menus, file dialogs.

A word of caution on exactly these four numbers: direct retrieval of the report was blocked today, so they're only documented via a search summary — not verified verbatim against the primary page.

4th place on a board where humans vote

A more independent read comes from the Frontend Code Arena: there, per the official Arena account, Qwen3.8-Max entered in 4th place, with 1,668 points — behind Claude Opus 5 (Max) at 1,705 and Kimi K3 (Max) at 1,676, essentially tied with Claude Opus 5 (High) at 1,669. That's a more realistic placement than any vendor slide: top five, but not on top, with less than a three percent gap to the front.

On the widely cited claim that the model can carry software projects autonomously for more than ten days: that's a company demo, not a measurement. The reporting source itself writes that these demonstrations are „company-produced and have not yet been broadly replicated by independent evaluators". Until someone outside reproduces it, this is a statement of intent. The date that actually matters is a different one: in the week starting Aug 11, the open weights are supposed to arrive — for Qwen3.8-Max and for Qwen3.8-27B. That would be Alibaba's first-ever Max model with open weights, and the 27B version is the one that makes sense on your own hardware.
