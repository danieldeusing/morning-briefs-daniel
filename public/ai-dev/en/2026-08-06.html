The price cut — recounted at the source

Update since Aug 3 Three days ago, this brief reported the GPT-5.6 price cut for what it was at the time: a single-sourced number, unconfirmed by the vendor. That's now settled. OpenAI's own pricing page today lists GPT-5.6 Luna at $0.20 per million input tokens and $1.20 per million output tokens. That's exactly the minus 80% versus the previously reported $1.00 / $6.00. Terra sits at $2 / $12, the flagship Sol unchanged at $5 / $30.

What's notable isn't the discount — it's where it lands: at the bottom and in the middle, not at the top. Leaving the flagship's price untouched while cutting the cheap tier by four-fifths isn't a fight for the hardest task — it's a fight for the volume underneath: the mass calls an agent generates on the side — summarizing, classifying, cleaning up, digesting tool results.

developers.openai.com · pricing page retrieved directly Aug 6, 2026 · previous figures per yellow.com
Price per million tokens: A token is a scrap of text, roughly four characters. Billing splits what you send in (input) from what the model writes back (output) — and output costs five to six times as much everywhere. Like a copy shop that practically gives away scanning and makes its money on printing. For agents, that split is decisive: an agent reads a huge amount (files, tool output, error messages) and writes comparatively little. So the input price is what determines whether a long agent run actually hurts.

The date that actually belongs on your calendar

The same page carries the more uncomfortable number, and it's dated: Claude Sonnet 5's launch price of $2 / $10 holds „through August 31, 2026," after which the regular rate of $3 / $15 kicks in. Plus fifty percent on both sides, for the same model, in 26 days. And one more primary-source confirmation that lagged behind the Opus 5 announcement: from Claude 4.6 onward, the full million-token window is included at the standard rate — „A 900k-token request is billed at the same per-token rate as a 9k-token request." So there's no longer a surcharge for long context. That changes the economics of long agent runs far more than any decimal point on a benchmark.

Thirteen days of Opus 5 — and no board knows it

Claude Opus 5 launched on Jul 24, 2026. At launch, it was cited at 96.0% on SWE-bench Verified and 79.2% on SWE-bench Pro, plus 89.1% on Terminal-Bench 2.1 at the highest effort setting. Those are vendor figures, relayed through trade media — not an independent measurement.

Today, thirteen days later, the only independently maintained SWE-bench Verified board that's actually reachable looks like this: it's explicitly dated Aug 6, 2026, topped by Claude Fable 5 at 95.0%, followed by Claude Mythos Preview at 93.9% and Claude Opus 4.8 at 88.6%. There's no entry for Opus 5. None for GPT-5.6, in any tier. None for Qwen3.8-Max either.

llm-stats.com · board state per the site Aug 6, 2026, retrieved directly · Opus 5 figures per marktechpost.com from Jul 24, 2026 — vendor claim
SWE-bench Verified — the top six entries on the independently maintained board, as of Aug 6, 2026. Claude Opus 5, GPT-5.6, and Qwen3.8-Max aren't missing here by accident: they simply aren't listed. The claimed 96.0% for Opus 5 would be the first bar — it's deliberately left out of the picture.
SWE-bench Verified: a collection of real bug reports from open-source projects, each paired with the test that proves whether the bug is actually gone. The model gets the repository and the report and has to write the patch itself; the only thing that counts is whether the tests turn green afterward. "Verified" means humans have checked that each task is actually solvable and that the test is meaningful. Like a driving test with real cars instead of a multiple-choice form — which is why it's the board everyone watches. And that's exactly why it's also the number most worth dressing up.

The problem isn't the vendors, it's the measuring instruments

You could call that cherry-picking — it isn't, because the alternatives today are all dead ends. The official table on swebench.com still loads its values via JavaScript and comes back empty on retrieval. The corresponding results repository, where the actually-verified submissions live, holds 92 reviewed folders, the newest of which date from mid-2025 — nothing new has landed there in over a year. And the Aider Polyglot board still reads „last updated November 20, 2025," topped by gpt-5 (high) at 88.0%; it knows neither GPT-5.6 nor Opus 5 nor any Gemini 3.x.

That leaves the situation plain: for the three most important model releases of the past two weeks, there is currently no independent, dated measurement. There are vendor slides, there are aggregators copying those slides, and there's a board that doesn't yet have the newcomers. Anyone basing a model choice on a decimal point in this situation is basing it on marketing.

What to measure instead

The practical workaround is unglamorous: twenty real tasks from your own project, recorded with the expected result, run once with every model switch. That takes half an afternoon, measures exactly the tool harness you actually work in, and is immune to training contamination — unlike a public board whose tasks have been sitting online for years. It's especially worth it now, with the price gap between tiers at a factor of 25: the interesting question is rarely "which is the best model," but "at which tier does it stop getting better for my tasks."

Google: Flash is moving, Pro is stalled

For completeness, the figures for Gemini 3.6 Flash, out since Jul 21 — they explain why Google looks relaxed about the fast model and nervous about the big one. On DeepSWE, Google reports 49% against 37% for its predecessor, on MLE-Bench (tasks from ML research) 63.9% against 49.7%, and for operating a computer on OSWorld-Verified, 83.0% against 78.4%. The figure that matters most for the bill sits right beside those: the model „reduces output token usage by 17% compared to 3.5 Flash."

That 17% belongs in the same category as the pricing table on the left. Output tokens are the expensive half; a model that needs fewer of them for the same answer has effectively gotten cheaper, with nothing changing on the rate card. The reverse holds equally: Anthropic's new tokenizer, which turns the same text into roughly 30% more tokens, is a price increase that shows up on no rate card at all. Price tags are only half the truth — the other half is how frugally a model spends its tokens.

Local & open weights

Ollama released version 0.32.6 on Aug 4. The two points that matter: faster execution of Qwen models on Apple GPUs via speculative decoding — a small model guesses the next tokens ahead, and the large one only checks the guess, saving several tokens per pass when the guess is right — and a streaming format that aligns with OpenAI's interface. The latter is the quieter but more useful part: tools written against the OpenAI interface now run against the local server with no changes.

The date this all builds toward remains Qwen3.8-Max: the model has been available via the API since Aug 3, and the open weights are announced for the following week — the week of Aug 10, with no fixed day yet. It would be Alibaba's first-ever Max model with open weights. At 2.4 trillion parameters, that's not running on anyone's workshop machine — it's interesting anyway, because open weights at this scale create exactly the pricing pressure you can read off today's rate cards.
