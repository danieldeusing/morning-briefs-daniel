What got added this week is management

Copilot builds the command bridge

GitHub's weekly report from Aug 7 covers Aug 3–7 and reads like someone watched how a tool actually gets used and copied that. The session sidebar gets keyboard shortcuts (n for new, x for close) — only useful if you constantly jump between running sessions. /rewind now also works without Git, so the tool runs its own rollback alongside version control. Add a new /side command, an experimental /worktree, and — in VS Code 1.132 — multilingual dictation that runs locally on the device.

github.blog — weekly report from Aug 7, 2026, retrieved Aug 9, 2026
Git worktree: A second checked-out folder of the same project — different files on disk, but shared history. Like a second workbench in the same workshop: your own workpiece, the same toolbox. For agents, that's the most obvious partition you get for free: two agents in two worktrees can't overwrite each other's files, and you can discard each one individually without touching the other.

Worth trying If you run more than one agent at a time, /worktree is worth a shot — it replaces exactly the manual fiddling you'd otherwise do with git worktree add plus sorting windows by hand. It's marked experimental, so nothing for the client branch.

Claude Code hangs a door it forgot to install

Yesterday brought 2.1.225 and 2.1.226. The notable point sits quietly in the list: "Added a workspace trust prompt to claude agents for untrusted directories, matching the behavior of claude." So the main command had already been asking before it got to work in an unfamiliar directory — the agents subcommand hadn't. That's not a new feature, it's a door installed after the fact, and it was open in the wrong place: an agent you point at a freshly cloned repository reads configuration and instruction files there before any human has.

The second entry is a finding about context. The spending-limit warning now names "the cap, its reset time, and the operator's message" and assumes a gateway as of version 2.1.225. An "operator" setting a cap and leaving a message — that's Claude Code behind a corporate proxy, with a budget per team. That's the audience getting tooling first right now.

code.claude.com/docs/en/changelog — entries 2.1.225 and 2.1.226, both dated 2026-08-08, retrieved Aug 9, 2026

Cline ships on a four-day cadence

Early this morning between 02:33 and 04:16 UTC: v4.1.7, SDK v0.0.72, Desktop v0.0.11 — three days after the last package. Content-wise it fits the same drawer as the rest of the week: a "View Changes" button on the completion line, built on SDK checkpoints so you can see afterward what a run touched; execution context in scheduled-run reports — "readable headers, schedule metadata, durations, and lifecycle error details"; preserved input on cancellation; resilient session context across interruptions.

And one entry closes the MCP thread: "Support pre-registered OAuth clients for remote MCP servers, for setups where dynamic client registration isn't available." The spec from Jul 28 tightened sign-in for remote servers; anyone running MCP servers on a corporate network can rarely register dynamically there. Twelve days later, the workaround ships in the client. That's what spec work looks like when it works.

github.com/cline/cline/releases — versions, timestamps, and quotes retrieved directly Aug 9, 2026

Three tools, one layer

Put together, that's a clear picture. Isolation (worktree), rollback (/rewind, checkpoints), review (View Changes), trust boundary (directory prompt), budget (gateway cap), schedule (scheduled runs): that's not the feature list of an editor, it's the feature list of an operating system for concurrency. The tacit assumption has shifted — from "I'm talking to one agent" to "I have several running, and I need to be able to prove afterward who did what."

The honest objection: everyone is building this layer on their own. Checkpoints in Cline, rollback in Copilot, a trust model in Claude Code — six tools, six session managers, no shared view of what's actually happening on your disk right now. The worktree is the only one of these partitions that belongs to everyone, because it lives in Git, not in the product. That's exactly why the experimental /worktree command is the most interesting entry of the week.

Aggregator board: A website that collects and sorts benchmark results — not necessarily one that measures anything itself. Like a price-comparison site: it shows prices in a table but hasn't bought anything from any of the stores. Without a methodology note next to it, you can't tell from the number alone whether someone actually ran the model against the tasks or just retyped a press release. That's exactly why digit-for-digit agreement between boards isn't a seal of quality — it's a sign of a shared source.

It's also the reason to be suspicious: for a test that costs four figures per model to run, completeness isn't a mark of quality, it's a question that deserves an answer.

What to do with this: nothing

These numbers haven't been useful for choosing a tool for weeks now, and today even less so. The gap between first and fourth place is 3.6 points on a board whose provenance is unclear — that's noise with a decimal point. The solid alternative costs an afternoon: two real tasks from your own project, both models in the same harness, results checked yourself. That measures exactly one repository — yours.

Editorial assessment, not a claim from the source

Ollama's four new models aren't new

Trackers carried a report on Aug 8 that the Ollama library had gained four model families: qwen3.6, qwen3.5, gemma4, glm-4.7-flash. A look at the library itself says something different. It shows "Updated 1 month ago" for gemma4, and "Updated 2 months ago" for the other three. None of that is news this week; the entries are one to two months old.

That makes it the same mix-up as twice already in this brief: "it's on my list today" isn't the same as "it happened today." An aggregator that presents its own capture timestamp as an event date produces a fresh-looking report about a two-month-old state. Anyone who updates their local install based on that hasn't done anything wrong — anyone who reads a trend into it has.

github.com/All-Hands-AI/OpenHands/releases (retrieved Aug 9, 2026) · github.com/cline/cline/releases (retrieved Aug 9, 2026) · Cursor kernel via search summary of the Cursor blog, Aug 9, 2026 — primary page not read directly
Megakernel: Normally, a model run on a GPU breaks down into hundreds of small compute steps launched one at a time — each launch costs time. A megakernel packs as much of that as possible into a single large compute step. Like a cafeteria that cooks everything in one pot instead of switching the stove on and off a hundred times. For your local setup, that changes nothing: the kernel is built for data-center racks. What's interesting is who's behind it — an editor company publishing inference kernels is evidently running its own models and optimizing hardware, not just the product.
