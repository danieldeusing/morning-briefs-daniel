The Prompt Stops Being the Default

Anthropic's Week 32 digest (Aug 3–7, v2.1.220–v2.1.224) carries one sentence with a future date in it: "auto mode becomes the default permission mode for new sessions on Pro, Max, and Team plans starting August 14." That date is today. The wording is explicitly about new sessions — but the next time you type claude, what starts is not what started yesterday.

code.claude.com/docs/en/whats-new, Week 32 entry, read Aug 14, 2026
Permission mode: the rule your coding agent follows before it touches anything — write a file, run a command, push a branch. The default was "ask me every time," like a new intern knocking on your door before each step. Auto mode replaces that with a second, smaller AI that reads each proposed action and decides on the spot whether it's routine or dangerous. Anthropic's own description from the March preview: "a classifier handles your permission prompts so safe actions run without interruption and risky ones get blocked. The middle ground between approving everything and --dangerously-skip-permissions." Not a green light — a bouncer.

Read the Trail, Not the Announcement

What makes this defensible isn't the announcement — it's what came before it. Walk the digest backwards and auto mode has been getting fenced in for five straight months, always in the same direction:

March 23–27, research preview. May 4–8, hard deny rules that "block actions unconditionally regardless of allow exceptions." May 18–22, rollout to Pro. June 15–19, it "blocks destructive git commands when you didn't ask to discard local work." July 6–10, it "blocks transcript tampering and asks before rm -rf on unresolved variables." Then today, the default.

That's not a feature roadmap, that's an incident list read backwards. Someone deleted local work. Someone shipped an rm -rf $EMPTY_VAR. Each block exists because the classifier alone wasn't enough — and I'd rather a vendor ship the fence before it removes the gate than the other way round.

All quotes from code.claude.com/docs/en/whats-new, weekly entries W13, W19, W21, W25, W28, read Aug 14, 2026
What a classifier is not Auto mode is a model judging a model: a probabilistic guardrail, not a policy. It will be right almost always — exactly the failure profile that makes people stop paying attention. The deterministic layer is the one shipped in May: hard deny rules that hold regardless of allow exceptions, plus deny/ask rules matching tool parameters via Tool(param:value). If today is the day the prompt goes away, today is the day to write those down for your repos — deploy scripts, production credentials, anything with a --force in it. Ten minutes of deny rules beats a classifier's good judgement on the one Friday it matters. Grok 4.6: Built for Agents, Behind on Agent Benchmarks

On Aug 12, the company formerly known as xAI — it now posts as SpaceXAI, and the independent coverage has adopted the name — released Grok 4.6, pitched at long-running coding and agent work. $2 per million input tokens, $6 output — that's the base rate; pricing roughly doubles for a faster variant and, separately, for prompts over 200K tokens (no vendor page I could reach confirms a distinct "fast" SKU as its own priced tier, so treat the 2× as a premium, not a published price list). Context stays at 500,000 tokens, unchanged from 4.5. Day one in Cursor and in the vendor's own Grok Build, and in the API as grok-4.6.

Launch date and index score: testingcatalog.com · pricing: unite.ai · name confirmed via the official SpaceXAI post and venturebeat.com, all read Aug 14, 2026
Intelligence Index: not a benchmark, an average of several. An analyst firm runs a fixed set of tests — reasoning, maths, coding, tool use — and boils them into one number so models can be ranked in a single column. Like a school report reduced to a grade point average: useful for a rough sort, useless for "is this kid good at maths?" Grok 4.6 scores 61, up from 56 for Grok 4.5, level with GPT-5.6 Sol Max.

The Detail the Headline Skips

Underneath that average sits a split worth staring at. Grok 4.6 led on GDPVal-AA v2 and AA-Briefcase — and trailed on DeepSWE and Terminal-Bench. Those last two measure an agent doing multi-step work in a real shell, which is precisely what this model is sold for. Not a scandal, but the opposite of the press release.

Where the family sat before this release: Grok 4.5 is fifth on SWE-Bench Verified at 86.6%, about ten points behind the leaders; 4.6 isn't on that board yet. Try At $2/$6 it's cheap enough to point Cursor at it for a week of routine work and form your own opinion — cheaper than reading three more analyses of the index score.

Three Boards: One Number, One Range, One Asleep

The only SWE-Bench Verified board I got a dated table out of this pass is vals.ai, last updated Aug 12, 2026: Claude Opus 5 at 97.0%, DeepSeek V4 Pro 0813 at 96.4%, Kimi K3 at 93.4%, Claude Opus 4.8 at 88.6%, Grok 4.5 at 86.6%. A second aggregation sampled a day later puts Opus 5 near 96% — so read the leading edge as 96–97%, not as a decimal. And the second row doesn't survive a cross-check at all: see below.

vals.ai/benchmarks/swebench, "Last Updated: August 12, 2026", read Aug 14, 2026 · cross-check via llm-stats/benchlm aggregation, Aug 13, 2026 · swebench.com returned no usable table data on fetch
SWE-Bench Verified — top 5, vals.ai board as of Aug 12, 2026. Bar 2 is vendor-reported and disputed: unite.ai scores the same DeepSeek build at 80.6%.
Vendor-reported vs. independently reproduced: a benchmark score is only as good as who ran it. "Vendor-reported" means the company that sells the model ran the test on its own hardware, with its own harness, and published the result — like a restaurant printing its own hygiene rating. "Independently reproduced" means someone else ran the same tasks and got the same figure. Both numbers can be honest; only one of them is evidence.

The 96.4% That Is Also an 80.6%

Which brings us to second place. DeepSeek V4 Pro 0813 hit general availability on Aug 12 after a preview that started April 24 — 1.6 trillion parameters as a mixture-of-experts, roughly 49B active per token, 1M-token context, up to 384K output. And per the reporting as of Aug 12: "there is not one third-party benchmark result for DeepSeek-V4-Pro-0813; every number is vendor-reported or analyst-reported, with none independently reproduced. There was no official blog post, changelog entry, or press release for the release."

Then the two trackers stopped agreeing. vals.ai puts this model second on SWE-Bench Verified at 96.4%. Unite.AI, writing up the same GA build on the same benchmark on the same day, reports: "On SWE-bench Verified it lands at 80.6, level with Gemini-3.1-Pro and a fraction behind Claude Opus 4.6 at 80.8." That is a sixteen-point spread on one model on one named benchmark — the difference between "second in the world" and "mid-field". I can't tell you which is right; neither has been reproduced by anyone outside the vendor, and the two boards don't even share a comparison set. What I can tell you is that a single decimal from either one is not a fact about this model.

The claimed jumps over the preview demand exactly that scrutiny: DeepSWE from 12.8 to 62.7, CyberGym from 52.7 to 83.3, Terminal-Bench 2.1 from 72.1 to 87.9. A near-fivefold jump on an agentic coding benchmark between preview and GA isn't impossible — but it's the shape a number takes when the evaluation harness changed, not just the model. Until someone else runs it, that second bar is a claim standing next to a measurement.

Your Agent Is Bad at Fixing Security Bugs

On Aug 4, Innodata released the first stage of an "AI Cyber Training Suite": twelve datasets plus evaluation systems built from "thousands of real security flaws discovered over the past ten years" across Python, TypeScript, JavaScript, Rust, C and Go. Training data for coding agents, sold to model builders. Ordinarily a supplier announcement I'd skip — the evaluation numbers inside it are why I'm not.

accessnewswire.com (company release, Aug 4, 2026), cross-checked at stocktitan.net, read Aug 14, 2026

23 Percent, With the Answer in Hand

The line that should stop you: "The best open-weight AI models repaired at most 23% of flaws when shown exactly where each vulnerability was located." Shown the location. Not "find the bug" — "here is the bug, fix it." Fewer than one in four. The flip side: after one round of fine-tuning on the suite, a model's ability to patch without guidance rose from 18.4% to 41.2%. The gap is trainable — and the models we use off the shelf haven't been trained on it.

Both figures from the company release at accessnewswire.com, Aug 4, 2026, read Aug 14, 2026
Fine-tuning: taking a finished model through a short, focused extra course on one narrow subject. It keeps everything it knew and gets noticeably better at the one thing you drilled — like a working carpenter doing a two-week class on staircases. Cheap next to training from scratch, which is why a 22-point jump on one skill is plausible; it's also why that jump says nothing about what the course didn't cover.
Read the source before you quote the number Every one of these figures comes from a newswire press release by the publicly listed company selling the datasets — an investor-relations artefact as much as a technical one. It doesn't name which model went from 18.4% to 41.2%, and there is no third-party evaluation. Take the direction seriously and the decimals not at all. Assessment by the editors, based on the source cited above

What I'd Change Because of It

The consequence is narrow and specific. Letting an agent write a feature is a productivity question — you'll see it in review. Letting an agent close a security ticket is a different bet, because a plausible patch that doesn't actually close the hole passes review far more easily than broken code passes tests. On this evidence, every agent-authored security fix is a draft that needs the exploit reproduced before and after, by hand. Boring advice — and the only kind that survives a 23% repair rate.
