Two Top Scores, Zero Verified Entries

Terminal-Bench has become the test agentic tools point to — not SWE-bench, which no longer separates anything at the top. This test has a verified leaderboard: entries the maintainers themselves re-ran and attached an error bar to. I pulled it today. The top spot is 83.8% ± 1.2%, and the entry is literally named "Claude Code + Fable 5." Eighth place is "mini-SWE-agent + Muse Spark 1.1" at 76.2% ± 1.2%. Neither Muse Spark 1.2 nor DeepSeek V4-Pro is listed.

Harness: The program that actually lets the model work at all — it feeds in files, runs commands, reads back error messages, and decides when to stop. Think of the difference between a good cook and a good kitchen: the same cook turns out noticeably worse food in a badly equipped kitchen. That's why this leaderboard always names both — harness plus model. There's no such thing as a score for a model alone on this benchmark.

So the absence of both numbers isn't a technicality — it's the whole point. You could object that I only looked at the top spots, and that both figures sit further down. Except: a score of 87.9% wouldn't sit further down. It would sit four points above today's first place. And 82.9% would be third place — behind "Claude Code + Fable 5" (83.8%) and "Codex + GPT-5.5" (83.1%). For these two specific claims, the absence from the top isn't a weak counterargument — it's a sufficient one.

Terminal-Bench 2.1 — Vendor Claim vs. Independently Measured (pulled Aug 19, 2026)

What's revealing is the pattern across two generations. For Muse Spark 1.1, Meta had reported 80.0% — a figure that only circulates secondhand, because Meta's own page still shows the results as a bar chart with no methodology section. The verified leaderboard lists that same version at 76.2%, and Artificial Analysis measures it at 78%. For 1.2, Meta claims 82.9%, and Artificial Analysis measures 80%. Both times, every independent measurement lands below the vendor's figure, and both times the gap is roughly three points.

Some of that is honestly explainable and comes down to the harness: mini-SWE-agent is deliberately a minimal harness, and Meta, according to consistent secondhand summaries, ran its model in its own product, Muse Code. But that's exactly the point that can't be argued away — a vendor that measures its own model in its own agent, and the competition in theirs, is comparing products, not models. The fact that the gap between the most minimal and the best harness (76.2 versus 83.8) is larger than the gap between the top five models tells you which of the two factors matters more right now.

My rule of thumb Subtract roughly three points from any vendor figure on an agentic benchmark before you set it next to a verified number — and after that, only compare scores that name the same harness. This leaderboard doesn't answer "which model," at most it answers "which combination." The best combination verified today is Claude Code with Fable 5 — not with Opus 5, which leads on the rollup indices. If you're already working in Claude Code, a trial run with Fable instead of Opus is the cheapest insight available today.

What Muse Code Still Gets Right

So this doesn't read as a takedown: I still think the design of Meta's terminal agent is the most interesting among the new tools. It breaks large tasks into sub-agents, and each one automatically gets its own git worktree — parallel work without two agents in the same directory yanking files out from under each other. That's an answer to a real problem, not a marketing need.

Three sober operating details before you try it. Price: $1.25 per million input tokens, $4.25 for output, $0.15 for cached input. Platform: install with a one-line curl command, but macOS and Linux only — Windows isn't in the instructions. Lock-in: Muse Spark 1.2 also runs via Meta's own interface and via OpenRouter, so you're not tied to the tool for the model — and since Ollama added support on Aug 14, you're not tied to the model for the tool, either.

On Artificial Analysis's rollup index, Muse Spark 1.2 sits at 54 points, three above 1.1. What's notable in the same data set and never gets cited: on SciCode, 1.2 fell compared to 1.1, from 58 to 56. A new model isn't better on every axis — it's weighted differently.

DeepSeek V4-Pro: Available, Unverified — and Suddenly Expensive

DeepSeek moved V4-Pro (identifier V4-Pro-0813) from the preview it had been running since April into general availability on Aug 13. The headline specs deserve to be taken seriously: 1M token context, up to 384K token output, with or without reasoning steps. The output window is the genuinely rare number here — it lets you write a large refactor in one pass instead of stitching together twelve separate responses.

All the benchmark figures come from DeepSeek's own release announcement: 87.9 on Terminal-Bench 2.1, 62.7 on DeepSWE, 61.5 on NL2Repo. Everything worth saying about the first number is covered at left; I couldn't check the other two against any independent measurement.

More practically important than any of those figures is the price. V4-Pro costs $1.32 per million input tokens and $3.96 for output; the increase for the V4 line took effect on Aug 16 at 16:00 UTC.

Qwen Opens Up the Trillion-Parameter Class — Correction to Yesterday

Yesterday this brief said Qwen had launched its 2.4-trillion-parameter model as "hosted-only," with open weights limited to the small 27B version. That was too cautious. I checked Qwen's organization page at the primary source today: Qwen3.8-2.4T-A95B sits there with open weights, plus an FP8 version, timestamped "7 days ago" — meaning Aug 12. Qwen3.8-27B and its FP8 variant sit alongside it, timestamped "5 days ago."

2.4T total, 95B active (mixture of experts): The model consists of many sub-networks, and only a small portion of them switches on for any given word. Think of a law firm with three hundred specialists: three of them work on your case, but all three hundred get paid and trained. Hence the two numbers — 2.4 trillion is what has to be stored, 95 billion is what actually computes for each token. The first number determines whether you can even load the model; the second determines how fast it responds.

To stay honest about what that doesn't mean: this won't run on a workstation, not even in FP8. The 27B version is the one that lands on your machine. What the large model changes is something else: open weights in this class mean any hosting provider can offer it — the price gets set by competition instead of a price list. That's exactly the mechanism that makes DeepSeek's price increase, right next door, an uncomfortable piece of news: with an open model, you'd have the choice to switch providers instead of paying the new bill.

Claude Code: Two Leaks Closed, One Tool Gone

Nine point releases between Aug 10 and Aug 18, and three of them genuinely matter to you as a daily user. In order.

v2.1.233 (Aug 14), security: Windows paths using the NT device prefix \??\ could bypass the UNC path check — in plain terms: the path looked harmless to the check but pointed to a network location, and Windows automatically sends the logged-in credentials there on access. The classic route through which a password hash leaks out. Fixed — doesn't affect you on macOS, but affects every colleague on Windows.

v2.1.234 (Aug 17), security: MCP diagnostics were printing resolved secrets — warnings now show the configured ${VAR} form instead, and connection errors now show only the server origin. Anyone who's ever pasted diagnostic output into a ticket knows why this is more than cosmetic.

This one changes your daily workflow Since v2.1.233, the todo/task tools are disabled — TaskCreate, TaskGet, TaskUpdate, TaskList, and TodoWrite are no longer available on Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer. The reasoning is implicit but clear: the newer models hold their plan in their own head, and the tools were a crutch for weaker ones. If you've wired them into a playbook or your own workflow, it'll break silently — it won't throw an error, it'll just stop doing anything. Bring them back with CLAUDE_CODE_ENABLE_TODO_TOOLS=1. My recommendation: run without it once before you set the variable. It's entirely possible the visibility you're missing was just a habit.

v2.1.235 (Aug 18) adds optional spell-checking in the input field via your locally installed aspell/hunspell/ispell. Small, but a nice signal: using system software you already have offline instead of a model call for every little thing.

A clarification to yesterday: This brief said auto mode had become the default for Pro, Max, and Team since Aug 14. That figure comes from a report dated Aug 9; I find no corresponding entry in the official changelog for the Aug 10–18 period. The only documented auto-mode entry is from Jul 11 and applies exclusively to Bedrock, Vertex AI, and Foundry. As of today, I'm carrying the default for consumer plans as reported, not as confirmed.

MCP Goes Stateless

The spec dated Jul 28 locked in what's probably the biggest change since launch: the protocol is now stateless. The Python SDK followed with version 2.0 the same day.

Stateless: Previously, an MCP server remembered who it was talking to within a session — each request built on the one before it. Stateless means: each request carries everything it needs to be answered, and the server forgets afterward. Think of the difference between a regular's bartender, who knows your usual order, and a vending machine, where you have to specify everything from scratch every time. The bartender is more convenient, but you can put as many vending machines as you like wherever you like — and that's exactly the point: stateless servers can sit behind a load balancer, run in serverless environments, and restart without anyone noticing.

In concrete terms: if you run your own MCP server, operations get considerably simpler — if you built one around the old session assumption, a rework is coming. On the size of the ecosystem, the figure "over 9,800 servers" is circulating; it comes from a single directory aggregator, and I couldn't find an official count. An order of magnitude, not a measurement.
