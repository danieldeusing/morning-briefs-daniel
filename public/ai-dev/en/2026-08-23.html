The top 5 reshuffled — and not one move is a technical claim

LogRocket's August snapshot of the coding-tool power rankings reads like this: OpenCode holds No. 1 (model-agnostic access to over 75 providers, MIT-licensed), Claude Code climbs from 3 to 2, Cursor drops to 3, Windsurf holds 4, and a Grok CLI is new at 5.

Now the reasons: Claude Code climbs because Opus 5 now runs inside it. Cursor drops over "owner uncertainty." The newcomer at 5 gets in because it's free and open source. OpenCode sits on top because it isn't tied to any single model. That's notable: four of the five positions are explained by price, license, or ownership — not by a tool coding better this week.

I'm strict about the numbers here: this is an editorial ranking from a trade blog, not a measurement. For Claude Code it cites 1691 Elo on the WebDev Arena and calls that the highest score any model has hit on that board through any tool. A second, independent secondary source cites 1699 points for Opus 5 — but on the "Fullstack Code Arena," as of early August, so a different board and a different snapshot. The primary leaderboard itself loads its table via JavaScript and returns no numbers on fetch. Bottom line: I'd trust the ranking, not the decimal points.

Elo: A rating system borrowed from chess. Two models get the same task, a human sees both answers with no names attached and picks the better one; the winner takes points from the loser. After thousands of these blind duels, the number means something — but only within one board. Two boards with different tasks produce two different scales, and their numbers can't be lined up against each other.

The same caution applies to the ranking's second number: Claude Code's output is preferred 67% of the time in blind comparisons versus 25% for Codex. No sample size given, no word on who did the rating. Credible as a direction, unusable as a metric.

"Grok CLI" or "Grok Build"? The name is double-booked today

The newcomer at No. 5 is listed as "Grok CLI": free, open source, bring-your-own API key, powered by Grok 4.6, with subagents, a planning mode, a plugin marketplace and MCP servers. That description matches Grok Build almost point for point — xAI's own terminal agent CLI, open-sourced under Apache 2.0 in Rust since Jul 15, 2026, and currently running on Grok 4.6 by default.

The catch: there's a separate, unrelated community project literally named grok-cli, also an open-source coding agent for the Grok API. Which of the two the ranking actually means, I couldn't pin down today, and I won't guess. If you're going to try one: the name that provably matches the described features — subagents in isolated Git worktrees, TUI, Rust — is Grok Build. Try Worth an afternoon, if only for the worktree isolation: subagents work on their own branches instead of scribbling over your working directory.

Price war: OpenAI undercuts Opus 5 on both sides for the first time

On Aug 21, 2026, OpenAI cut developer pricing for GPT-5.6 Sol: input from $5 to $4 per million tokens (−20%), output from $30 to $20 (−33%), cached input from $0.50 to $0.40 (−20%). That makes what was until then the most expensive model in OpenAI's lineup cheaper than Claude Opus 5 ($5 / $25) — on both sides of the bill.

Output price per 1M tokens, as of 2026-08-23

Anthropic hasn't reacted to the cut — and hasn't had to, so far. Opus 5 launched Jul 24 at its predecessor Opus 4.8's price, with no markup for a new generation. And on Aug 11, Anthropic made Sonnet 5's launch pricing — $2 / $10 — permanent, scrapping the September increase it had announced.

Cached input: The start of your request — system prompt, project rules, the same files every time — is identical on every call. Think of it like a bottle-deposit receipt: the second time around, you pay only a fraction for the same part. In agent loops that resend the same 30,000 tokens of context a hundred times a day, that's the line item that actually drives the bill — not the headline output price.

My read, and I'll stand by it: per OpenAI's own announcement, the cut holds for the next three months, so at least through Nov 21, 2026. That's a promotion, not a new floor. If you rebuild your default model in agent pipelines around a time-limited deal, you'll rebuild it again in November — and pay the migration cost twice. The move that's actually plannable this week is the other one: Sonnet 5 at $2 / $10, permanently. That's the kind of thing you can build an architecture on.

Open weights are the real price floor

The pressure from below isn't coming from OpenAI — it's coming from Kimi K3. Moonshot released the weights on Jul 27, 2026; through the official API the model costs $3 / $15 per million tokens, with a $0.30 input rate on cache hits. On OpenRouter, the cheapest third-party listing as of Aug 20 was $2.60 / $13.00 (fp4 quantization, slightly trimmed context).

Open weights + fp4: "Open weights" means the model's trained numbers are available to download and anyone can run it themselves — which is why many providers can host the same model and undercut each other. "fp4" is a compression scheme, like JPEG for a photo: 4 bits per weight instead of 16, some quality loss, but noticeably cheaper and faster.

More important than the price is where the model shows up: since Aug 6, Kimi K3 has been rolling out in GitHub Copilot — across Pro, Pro+, Max, Business and Enterprise. One catch for enterprise customers: in Business and Enterprise, the model is off by default; it only shows up in the picker once plan admins enable the Kimi K3 policy in Copilot settings. Five days later, on Aug 11, MAI-Code-1.1-Flash was added separately — available via automatic model selection for Free and Student, and manually selectable on the paid tiers. Try Being an open model in the picker of the biggest enterprise tool moves default choices harder than any list price. That's exactly why Anthropic keeps Sonnet 5 cheap.

Cursor now belongs to SpaceX — and the brand name goes first

The reason for Cursor's drop in the rankings is sitting in the business pages: TechCrunch reported on Aug 15, 2026 that the acquisition of Anysphere, the company behind Cursor, by SpaceX had closed — valued at $60B. Cursor won't remain a standalone entity after that; staff and operations move into existing SpaceXAI structures. The brand name is set to be phased out over the coming months, existing tools keep it for now — and you can already see what the new naming order looks like: the general-purpose agent that ran internally as "Sand" has been out since Aug 11 as "Grok Bot," in a beta for desktop and iOS, for now limited to the top-tier subscriptions SuperGrok Heavy, Cursor Ultra, and Cursor Teams Premium.

The confusing part: the product is shipping quite well in the meantime. On Aug 13, Cursor unveiled "Builds" — pre-warmed copies of the dev environment that stand ready in the background; internally, the environment reportedly starts 10x faster as a result, with 3x faster time to first token. On Aug 3, plugins for Gmail, Drive and Calendar landed.

Still, I get the drop. For an editor you build your workflow around, the relevant question isn't "is it good today" but "who decides pricing, model choice, and data policy twelve months from now." That question has had a new and harder-to-read answer at Cursor since Aug 15. The practical takeaway is unglamorous but the right one: keep your agent configuration portable — prompts, rules, MCP servers in files another tool can read too. That's precisely what the No. 1 tool on the ranking stands for.

GitHub's 7 hours 47 — and the number the report is actually about

On Aug 17, 2026, GitHub was down from 13:28 to 21:15 UTC — 7h 47m, hitting github.com, sign-in, Actions, the APIs, pull requests, issues, and Copilot. The postmortem has been published, and the cause is unusually clearly stated: in the Central US data center, an infrastructure component hit its concurrency ceiling and didn't scale with traffic; the pressure cascaded through the load balancer into sign-in. GitHub states explicitly that neither incident was caused by a code or configuration change — both were, at their core, capacity failures.

Sidecar: Alongside every service runs a second, smaller process that handles all of its network traffic — like a passenger who takes every phone call for the driver. That's convenient, because encryption, retries, and metrics all live in one place. The catch: if the passenger can only handle eight calls at once, that's the ceiling for the whole car — no matter how strong the engine is.

The same report contains the number everyone's commentary is latching onto this week: monthly commits have grown from 1.4B to 2.9B since April. Here I draw a clean line: GitHub cites that as growth context and does not name AI tools as a cause in that post. The stronger claim circulating through the aggregators — AI-agent pull requests rising from roughly 4M in September 2025 to over 17M in March 2026 — comes from a secondary source and couldn't be independently confirmed today. I'm carrying it as their interpretation, not as a finding.

What holds regardless of how you attribute the cause: Copilot was inside the outage window, and agent loops that push and pull against origin at every step are the first thing to die in a situation like this. A local branch the agent can keep working on costs nothing and saves half a workday.
