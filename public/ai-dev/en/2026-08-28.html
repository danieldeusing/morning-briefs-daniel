The Flag That Ties Claude Code's Hands

As of version 2.1.248, which releasebot.io dates to today, there's --restricted (or, alternatively, the environment variable CLAUDE_CODE_RESTRICTED=1). What the flag does, per the original changelog, is a list of five very deliberate points: it removes every built-in tool that executes commands or code, plus WebFetch, unless it's explicitly listed in --tools. It keeps file tools confined to the working directory. It refuses bypassPermissions. And it ignores user, project, and local settings files.

The last point is the one worth sitting with. The first three you'd expect from any sandbox. The fourth closes the door a sandbox usually opens back up through: if a .claude/settings.json in the repository were allowed to widen permissions, then the very project you're eyeing with suspicion ends up controlling its own cage. That's now off the table. The difference between "a sandbox" and "a sandbox with a lever the test subject controls" is the entire point of the exercise.

The same version adds diagnostics for server-managed settings: a startup warning plus an explanatory line in /doctor and /status when they fail to load. A policy that fails silently is worse than no policy at all.

This is the capstone of ten days of incremental work. On Aug 18 (2.1.234), remote file access, session resumption, CLAUDE.md includes, and file uploads started rejecting Windows NT namespace paths. On Aug 20 (2.1.238), plugin marketplaces got headersHelper: a command that generates short-lived HTTP headers for catalog fetches, instead of the fetch inheriting credentials from the environment.

The \??\ path: alongside the path you know (C:\tmp), Windows has another address form one level deeper in the operating system, starting with \??\. Think of it as a house number that isn't on the street sign but still works — checks that only look at street signs miss it entirely. Point a path like that at a network share, and Windows automatically logs in there, sending along a login fingerprint (the NTLM hash) in the process. An attacker who tricks you into "just reading a file" gets your credentials handed over for free. That's why "this path form isn't accepted at all" is the right answer, not "we check it more carefully."

My reading, and I'll defend it: this is Claude Code moving from a single-user tool toward something that runs inside other people's organizations and on other people's code. In practical terms: Try reach for --restricted whenever you point Claude Code at a repository you didn't write yourself — a stranger's pull request, an open-source project you're evaluating, a client engagement on first contact. The mode costs you nothing as long as you only wanted to read and understand anyway. And the honest caveat: this is a mode, not a jail. It shrinks the tool's attack surface; it doesn't replace the process or container boundary around it.

75 Instead of 340 Megabytes

The least spectacular change of the week is the one you'll notice fastest. Version 2.1.239 (Aug 22) compresses the native binary with zstd: roughly 75 MB instead of 340 MB on Linux x64, plus about 2 MB less because embedded skill and prompt text is stored more compactly. That affects both first install and every automatic update.

More consequential for day-to-day use is version 2.1.243: code now loads on demand instead of keeping the whole bundle resident in memory — per the changelog, roughly 40–70 MB less per session. If you spread your work across multiple parallel sessions, which is exactly what the subagent pattern invites, that buys you two or three extra sessions on the same laptop.

Fixed in the same pass: disconnected MCP servers in non-interactive -p and SDK sessions never used to recover from a dropped connection; now they reconnect or report a clean failure. That's the bug people used to blame on their own server. And version 2.1.245 clears up a startup crash on distributions running glibc 2.44 (Arch, CachyOS, Fedora Rawhide).

Disconnected MCP server: the Model Context Protocol is the power strip between an AI tool and everything it's meant to operate. "Disconnected" means the outlet isn't on your own machine — and if the line to it gets cut without anyone noticing, the agent just keeps working merrily along, minus the tool.

Third Board, Third Winner — and Exactly One Number Everyone Agrees On

On Aug 25, this newsletter noted two trackers arguing over a 1.2-point gap at the top of SWE-Bench Verified. Since then, vals.ai has updated as of Aug 26 — and the situation hasn't gotten better, it's gotten worse.

On vals.ai, Claude Opus 5 leads with 97.00%, followed by DeepSeek V4 Pro 0813 at 96.40%, Kimi K3 at 93.40%, Claude Opus 4.8 at 88.60%, and Grok 4.5 at 86.60%. On llm-stats.com, which dates itself to Aug 28 — today — Claude Fable 5 leads with 95.0%, followed by Claude Mythos Preview at 93.9%, Claude Opus 4.8 at 88.6%, and, trailing at 80.6%, DeepSeek-V4-Pro-Max and Gemini 3.1 Pro.

SWE-Bench Verified — two trackers, two leaderboards. vals.ai as of Aug 26, 2026; llm-stats.com self-dated Aug 28, 2026. Secondary sources, not independently remeasured.

What's striking isn't the different winner. It's that the two fields barely overlap: vals.ai's top ranks include neither Fable 5 nor Mythos, and llm-stats's include neither Opus 5 nor Kimi K3. The only number where the two agree down to the decimal point is Opus 4.8 at 88.6% — a model that's a generation old. The trackers agree, in other words, exactly where nothing is at stake anymore.

SWE-Bench Verified: real bug reports from open-source projects, where humans have already confirmed the task is solvable and the test is fair. The model gets the repository plus the bug report and has to write a patch that turns the test suite green. The catch: to pass the same exam, every vendor gets to build their own car to take it in — tools, prompt scaffolding, number of attempts. Two testing bodies that score the same model differently may not be measuring the same thing at all.

Here's the number that explains the rest: vals.ai itself notes that seven of 86 rated models hit 95% or better, and the leader sits just 3.00 points from a perfect score. When almost everyone gets almost everything right, the course stops measuring skill and starts measuring residual noise.

Unresolved The official board at swebench.com loads its Verified table via JavaScript and was, as on Aug 25, unreadable today. So there's no primary source in this run that could adjudicate between the two trackers. Both sets of numbers above are secondary sources. Don't cite either one as "measured."

My reading, and I'll defend it: two dated leaderboards that agree on exactly one stale data point no longer have a measurement problem, they have a definition problem — they're visibly not running the same scaffolding, and in some cases not even the same model versions. As long as a tracker won't disclose its scaffolding, every SWE-Bench number you come across is a vendor or tracker claim, even the one with the nice bar chart next to it. The practical takeaway stays boring and correct: pick your coding model by spending two hours on your own repository. That costs less than a month of using the wrong one.

Anthropic's Scanner Gets the Flagship Model — and No Separate Bill

The Claude Security plugin got a brief mention here on Aug 23. The follow-up is the more interesting half: since Aug 21, enterprise repository scans run on Claude Mythos 5. Every finding carries a CWE category, a confidence and severity rating, and a fix suggestion that opens directly in Claude Code in the browser.

The sentence worth more than the model upgrade sits right next to it: the scans are billed as ordinary token usage under the existing plan — no separate add-on product, no dedicated license. Security scanning is traditionally sold per seat or per repository. Billed by token instead, the price scales with what you actually scan. For a one-person shop, that's the difference between a license you can't justify and a few euros for a deep pass over a repository.

Two-out-of-three review: a candidate finding gets passed to three independent reviewers, each looking through a different lens: reachability ("can an attacker even get to this piece of code?"), impact ("and what happens if they do?"), and mitigation ("does something upstream already block it?"). Only if two of the three agree does it get reported. That's the difference between a security tool and a false-alarm machine: the scarce resource isn't the ability to spot something suspicious, it's the willingness to throw most of it back out.

Source status, honestly: the Mythos 5 switch and the billing rule come from a single secondary source whose article itself carries no date; I did not fetch Anthropic's own product page today. The architecture — orchestrator on Opus, mapper and read-only explorer on Sonnet, three reviewer lenses — is documented in a report from Jul 22. Plausible, then, but thinly sourced.

Four Agents Move Into the Group Chat

Slack launched Slack Code on Aug 20: coding agents run in dedicated channels — namely Claude Code, Cognition's Devin, GitHub Copilot, and Vercel's agent. Conversation, the running plan, code diffs, and a live preview each sit in their own tab instead of a message wall. It's available on every Slack plan; you need to bring your own access to the agents themselves.

Not to be confused with GitHub's own Slack preview from Aug 21, covered here on Aug 25. The difference is the direction: there, one vendor puts its agent into someone else's chat. Here, Slack builds the container and invites four competitors in.

My view: the interesting part isn't the chat, it's the tabs. Plan, diff, and preview as equal-status panes are a harness UI — and when four competing agents draw into the same UI, the switching cost between them drops toward zero. That's good for you as a user. It's bad for every vendor whose moat was its own interface. The telling question over the next few months is who's first to stop wanting to draw into it at all.

Two caveats: "free on every plan" is the acquisition price, not the running cost. And your diff ends up under a chat product's retention rules — anyone touching client code should settle that before the first channel, not after.
