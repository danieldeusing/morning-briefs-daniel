Two Shutdown Dates, One Weekend in Between

OpenAI's documentation is unambiguous on this point: "GPT-5.4 and GPT-5.4 mini retire from Codex on August 31, 2026." As replacements, it names gpt-5.6-terra for gpt-5.4 and gpt-5.6-luna for gpt-5.4-mini. The sentence right next to it matters more: "The OpenAI API and Codex authenticated with your own API key aren't affected by the GPT-5.4 retirement." So what's affected is the convenient path — Codex via ChatGPT login. If you've set up your own key, you won't notice anything on Monday.

One day later, it's GitHub's turn. The changelog entry from Jul 31 says, verbatim: "GitHub is deprecating six AI models effective September 1st, 2026." The six are Gemini 3.1 Pro (→ Gemini 3.6 Flash), Claude Opus 4.5 and 4.6 (→ Opus 4.7, 4.8, or 5), Claude Sonnet 4.5 and 4.6 (→ Sonnet 5), and Raptor Mini (→ MAI-Code-1-Flash). One exception is explicitly stated: Sonnet 4.6 stays available to individual users on annual plans, "so they retain a Sonnet offering." In parallel, three new models are rolling into Copilot in August: Kimi K3 (Pro through Enterprise), MAI-Code-1.1-Flash with built-in image understanding, and Grok 4.6.

Two corrections to our own reporting. First: yesterday's brief listed Aug 31 as the Copilot date, because secondary sources disagreed. The original changelog says Sep 1 — that's the one that counts. Second, and this is the real trap: GitHub names MAI-Code-1-Flash as the replacement for Raptor Mini — and then deprecates that very model itself nine days later. A second changelog entry from Aug 11 ("Upcoming deprecation of MAI-Code-1-Flash") says it verbatim: "we will deprecate MAI-Code-1-Flash across all GitHub Copilot experiences on September 10, 2026," with MAI-Code-1.1-Flash as the successor. So if you're on Raptor Mini today, you're moving twice: to MAI-Code-1-Flash on Sep 1, then on to MAI-Code-1.1-Flash on Sep 10. Skip the intermediate step and switch straight to MAI-Code-1.1-Flash.

Weekend homework A grep over everything that carries a model name as a string: CI definitions, .env files, editor settings, agent configs, scripts that call an API directly. Look for gpt-5.4, opus-4-5, opus-4-6, sonnet-4-5, sonnet-4-6, gemini-3.1-pro. Twenty minutes today beats a baffling failure on Tuesday morning in a pipeline that's been green for weeks.

My take: both dates falling into the same forty-eight hours is coincidence. That they exist at all is not. A model name has become a component with a half-life of a few months — it behaves like a dependency, but everywhere it gets treated like a constant. The fix is boring: one place in the project where the name lives. Whoever has that reads announcements like these as a note, not a task.

125 Billion Weights, Six Billion at Work

On Aug 26, Alibaba released Qwen3.8-Flash as open weights — a multimodal MoE model with 125B parameters, of which, per MarkTechPost, around 6B per token are active, announced as an "early preview of the Qwen4 architecture." The production variant is priced via the QwenCloud API at $0.16 per million input tokens and $0.47 per million output tokens. Bloomberg frames the move as a "smaller, cost-effective" model.

MoE and "active parameters": picture a law firm with a hundred specialist attorneys. For any single question, not all hundred get called in — just the two or three who are actually relevant, while the rest sit around getting paid without doing any work right now. That's exactly what a "Mixture of Experts" does: for each word, only a small slice of the model does the math. The practical catch these announcements tend to gloss over: this saves compute time, not memory. All hundred attorneys still have to be in the office. In practice that means 125B weights need to sit in RAM as 125B weights, even though only 6B of them do the math per token. It's a server-class model with the response feel of a small one, not a laptop model.

If you want to run this locally, you'll want the smaller release instead: qwen3.8:27b has been in Ollama's library since mid-August, listed at around 18 GB of memory and a 256K context. Try it That's the size that actually runs on a well-equipped laptop — and the long context is exactly the part where local models usually fail first at agentic work. Ollama itself is at v0.33.2 from Aug 28.

Same bet, different scale: NVIDIA Nemotron 3.5 Lightning, from Aug 11, is an open 30B MoE model with 3B active parameters, marketed explicitly for "always-on agents" — agents that run continuously rather than getting queried once. For a background process, what matters isn't peak answer quality, it's what it costs while idling. The real signal is that two independent vendors released the same recipe at two different sizes within two weeks of each other.

The Cage Becomes a Product

On Aug 27, AccuKnox launched AgentZ — "a platform for building, running, and governing AI agents across teams and workflows." The feature list reads like someone read the past six months of agent incidents backward: every agent runs "inside its own sandbox with a dedicated computer and filesystem." The platform is model-agnostic ("support for OpenAI, Claude, Grok, and other models") and can run as SaaS, on-prem, or fully air-gapped, each with its own model. On top of that come visible execution graphs, run traces, and audit logs, plus permission management where organizations administer centrally and workspaces keep teams isolated from each other.

Air-gapped: the machine has no physical connection to the outside world — no cable, no Wi-Fi. Think of a vault room with no windows: whatever needs to go in gets carried in by hand. For agents, that means the model has to run in-house, because calling a vendor's API simply isn't possible. That's why "bring your own LLM" is on this feature list, and not just marketing.

My take: AgentZ is interesting less as a product than as a timestamp. Yesterday's brief covered Anthropic's --restricted — a tool that ties its own hands, free, for exactly one tool. Today, a security vendor sells the same idea as a platform for an entire fleet. These are two answers to the same question: who owns the boundary around an agent? One answer belongs to the tool maker; the other inserts another vendor between you and your agents.

For a one-person shop, neither answer is a direct purchase. What's valuable is the list itself — a sandbox per agent, an audit log, role-based access, no inherited credentials. That's now the baseline expectation an enterprise client brings the moment you hand them an agent — and you can check it off with your own tools too: a container instead of a platform, a log file instead of an audit view.

Try it There's a free tier at agentzharness.ai and an open repository on GitHub — enough to hold the interface up against your own idea of a "governed agent" for an hour, without talking to a sales rep.

MCP Cleans Up the Boring Parts

The Model Context Protocol project published an updated roadmap on Aug 22. The look back in it is more revealing than the look forward: the Jul 28 spec brought a stateless protocol core, multi-round-trip requests, header-based routing, cacheable list responses, and hardened authorization.

Stateless: a waiter who remembers your order is nice — as long as he isn't about to clock out. A stateless restaurant makes you restate what you want with every course; in exchange, any waiter can serve you, and at lunch rush you just add three more. For an MCP server, that means it's allowed to crash, restart, or run as five copies behind a load balancer without your session dying. "Header-based routing" is the matching second half — an ordinary gateway can forward the request without understanding its contents.

My take: this is the least spectacular and simultaneously most consequential step this protocol could take. As long as an MCP server was one long, sticky session, it was a thing you ran on your own laptop. Stateless plus header routing turns it into something you can hang behind the same load balancer, the same gateway, and the same monitoring as any other HTTP service of the last fifteen years. That makes tool servers ordinary infrastructure — and ordinary infrastructure is what ops teams wave through.

On the download numbers being passed around — both first-party SDKs supposedly past a billion combined — I'm keeping my distance: no primary source today, only a summarized secondhand account.
