For the first time, a lab's own risk scale reins a model in

On September 1, 2026, OpenAI announced that Astra is the company's first model to reach the "critical" tier of the Preparedness Framework in cybersecurity. The evidence is uncomfortably concrete: in an internal test set of 20 already-known, highly critical bugs in Google's V8 JavaScript engine, the model found two previously unknown vulnerabilities on its own — and chained them together. On ExploitBench, which measures whether working exploits can be built from known vulnerabilities, it scores a flat 100%. OpenAI puts its refusal rate on cyber jailbreak attempts at 91.5%, versus 59% for its predecessor GPT-5.6 Sol.

Preparedness Framework, "critical" tier: OpenAI's own self-written danger scale — a ladder of capability levels for which the lab pre-decided which safeguards kick in at which rung. Like a fire-rating code, except the builder writes the code and grades its own building. "Critical" is the top rung for cybersecurity: reached when a model can find and build working zero-day exploits against hardened real-world systems without human help. The news here isn't the rating itself — it's that a commitment like this has actually come due for the first time: Astra isn't going into general availability. It's going to a test cohort first, then into defensive use only via "Daybreak Blue."

Now for the numbers nobody has independently re-measured. A 100% isn't a top score — it's a saturation signal: a test where the subject earns full marks only tells you "at least as good as the hardest task in the catalog." The V8 test set is also explicitly internal — 20 tasks, assembled and graded by OpenAI itself. Unlike coding benchmarks, what's missing here isn't just the independent line item: for autonomous cyber capabilities, there's no public leaderboard at all. It's not that a row is missing — the whole table is missing.

I read the 91.5% differently than the press release does. That refusal rate means: out of a hundred disallowed requests, eight and a half get through. For a model that writes essays, that's annoying. For one that has demonstrably chained zero-days, roughly one in twelve successful requests is the whole story. The jump from 59 to 91.5 is real and large — but the number that matters isn't the rate, it's what comes out the other end of a successful request, and that can't be written as a percentage.

My take. Astra changes nothing about your workday, because you simply don't get it. What changes is the other side of the equation. If a model can work two unknown flaws out of twenty known V8 bugs, the question is no longer whether something like this eventually gets pointed at your dependency tree, but when and by whom — the capability is now demonstrably real, and access barriers in this industry have historically held for about a year. The one move that actually helps today is unglamorous: know what's in that dependency tree, and keep short the distance between a published finding and it reaching you as an updated package.

On sourcing: OpenAI's own posts return HTTP 403; every number above comes from SecurityWeek plus a second outlet reproducing the same OpenAI sentences. Two secondary sources citing the same primary document aren't a second piece of evidence — they're the same evidence twice.

Meta undercuts the market — five dollars for a terminal agent

Meta's developer blog reported on August 31, 2026, that Muse Code is leaving beta; The New Stack independently picked it up on September 1 — the Claude Code rival is exiting beta with three new subscription tiers, "and it's pushing hard on price." The prices sit on Meta's product page: $5/month for "Everyday Usage," $15 for "High Usage," $50 for "Power Usage." The backbone is Meta's own model, Muse Spark (the page cites versions 1.2 and 1.3), explicitly co-trained: "Built for Muse Spark. Co-trained for tight integration."

Fan-out into isolated worktrees: a Git worktree is a second, third, tenth working copy of the same repository — same history, its own folder, its own branch. "Fan-out" means the main agent spins up several sub-agents and gives each one its own copy, instead of letting them all scribble in the same directory. Like several cooks, each with their own cutting board. Meta's phrasing: parallel work "without mid-flight collisions." The real work, though, starts at the merge step — and the product page says nothing about that part.

A number that doesn't belong here. A claim is circulating around Muse Code that it runs "hundreds of agents on a single task." Meta's product page cites no such figure. That number comes from a completely different company: Cursor, in a blog post dated January 14, 2026, describes "hundreds of concurrent agents on a single project" that had written over a million lines of code — Cursor's claim about Cursor's own architecture, nearly eight months old, that migrated onto someone else's product.

My take. Worth trying The price is the headline, not the technology: $5 sits below the threshold where you'd even bother running the math — not a price war against Anthropic, but one meant to eliminate the "is this worth it?" question altogether. The line "Built for Muse Spark. Co-trained for tight integration" is simultaneously a selling point and the fine print: an agent co-trained on the house model is exactly as portable as that house model — which is to say, not at all. So test it as a secondary tool, not a replacement for your main setup. The honest test takes one evening: run the same task once in your usual harness, once in Muse Code, and afterward what matters isn't the result — it's how often you had to step in. On a $5 subscription, the scarce resource is your time, not your money.

Plus 25 percent that's actually minus 17 percent

Anthropic is raising Claude Code's weekly limits: "Starting September 14, we're permanently raising standard weekly limits in Claude Code by 25% for Pro, Max, Team, and seat-based Enterprise plans." That is, in fact, more than the old baseline. Except a temporary 50% increase has been running for months, and it ends on September 13, 2026, at 11:59 PM PT — right before the new permanent cap takes effect.

100 old baseline → 150 today (promo) → 125 from 09/14

The math is trivial, and that's exactly what makes it uncomfortable: if you have 150 today, you'll have 125 starting the 14th — roughly one-sixth less. Anthropic itself said as much after being pressed: "Compared to today, this works out to a 17% reduction in weekly limits on Claude Code." Affected: Pro, Max, Team, and seat-based Enterprise contracts.

Deadline converted to local time 09/13, 11:59 PM PT works out to 09/14 at 3:59 AM in Ribeirão Claro (Pacific Daylight Time is UTC−7 in September, Brazil is UTC−3 year-round). The conversion is mine, not the source's — only the PT time is documented.

My take. This isn't a trick — the new baseline is higher than the old one, and a temporary promo was never a promise. What bothers me is the reference point: "permanently raised by 25%" is measured against a state nobody has actually lived under for months. What you've lived under is 150. An announcement that measures against a reality its audience doesn't know isn't a lie — it just doesn't explain anything. That Anthropic went on to write out the 17% itself, I credit the company for. Practically: if you last hit your weekly limit, you hit it against the 150 — starting the 14th, the same working style runs out a sixth sooner. The nine days between now and then are the best window you'll get to measure where your tokens actually go: how much goes to repeated context, how much to real work.

Cursor lets you bring your own machine

The latest entry in Cursor's changelog is dated September 2, 2026, and it's the most interesting tooling news of the week — with no new model attached. Verbatim: "Cursor supports self-hosted machines, which let you keep tool execution entirely in your own network." Two flavors: "My Machines" connects a single laptop or VM to your account; "Team pools" are worker queues that scale with demand. Options listed: AWS Lambda, Coder, Cloudflare, Daytona, Modal, Namespace, Vercel, E2B. Until now, the rule was: the model thinks at the vendor, and execution happens there too — your client's source code lands inside someone else's container. That second half can now be pulled back in-house.

My take. Worth trying For a one-person shop, "My Machines" is the half that matters, and it solves a concrete sales problem: the agent still thinks at the vendor, but tool calls, tests, and file access happen on your own machine. That means the client's source code never leaves your network — the argument you need under a German contractor agreement, and the one that's failed at exactly this point until now. The catch is just as obvious: whatever runs on your machine runs with your permissions. An agent with tool access on your work computer is a different threat class than one in someone else's disposable container. Sovereignty and sandboxing at the same time only comes from a VM you can throw away yourself — meaning, work someone else already did for you.

Copilot retired six models on September 1

GitHub's changelog, effective September 1, 2026: "we have deprecated the following models across most GitHub Copilot experiences (including Copilot Chat, inline edits, ask and agent modes, and code completions)." Affected: Gemini 3.1 Pro, Claude Opus 4.5 and 4.6, Claude Sonnet 4.5 and 4.6, and Raptor Mini — four of them from Anthropic. With one exception: "Claude Sonnet 4.6 is still available to individual GitHub Copilot subscribers on annual plans."

My take. The exception is the instructive part: whether a model stays available to you depends not on what you do with it, but on which contract you signed. If you think of model choice as a property of your tool, you're wrong — it's a procurement decision made by the vendor, made without you, with a day's notice. If a model choice is business-critical for you, it doesn't belong in someone else's subscription — it belongs behind your own API key.

Gartner says in four months you'll be conducting more than you're typing

In Gartner's 2026 predictions package, published on October 21, 2025, sits the line that's been haunting every conference slide since: "by the end of 2026, 75% of developers will spend more time orchestrating and architecting than writing code directly." End of 2026 is barely four months away.

The forecast isn't wrong. It's unfalsifiable. Three things are missing before it can be held up against reality on 12/31: a definition of "orchestrating," a definition of "developer," and a measurement method. More time doing what — measured in keystrokes, calendar hours, or self-reported survey answers? A metric without a definition can be confirmed or refuted with equal ease on the deadline. Practically, that means it will be confirmed, because that's the more comfortable reading.

And yet it describes something real — the evidence is spread across three columns of this very brief: Meta's agent spins up sub-agents in their own worktrees, Cursor distributes execution across machine pools, Anthropic recalculates its prices around reused context. All of them are tools for someone distributing and collecting work, not for someone typing. The forecast is true not because Gartner said it, but to the extent that the tools are actually being built that way right now.

My take, and I'll defend it. The part of that sentence that matters isn't the 75% — it's the word "architecting." Orchestrating alone isn't a promotion: someone who spends all day waving agent output through has just traded one task for a more boring one — and one that pays worse, once someone notices. What's about to become scarce is exactly the skill you only build by writing code yourself: the ability to judge whether a design will hold up before it's built. If you type less in 2026, make sure the freed-up time goes into design and review, not queue-babysitting. The difference between "orchestrating" and "rubber-stamping" decides whether this forecast means a promotion or a devaluation for you — and no tool makes that call. Only you do.
