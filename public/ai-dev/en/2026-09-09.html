Five releases in six days — and where they're heading

09/03–09/08/2026 · Claude Code CLI, changelog and release page cross-checked

The count alone says little: v2.1.260 on 09/03 at 23:48, v2.1.261 on 09/04 at 19:58, v2.1.263 on 09/06 at 02:54, then last night v2.1.265 at 20:37 and v2.1.266 at 23:55. It gets interesting with the content of the last two. v2.1.266 has exactly one entry, and it reads, in substance: the undocumented environment variable CLAUDE_CODE_USE_GATEWAY, previously ignored unless a base URL and auth token were set at the same time, had started in v2.1.265 to force cloud gateway login on its own.

Three hours and eighteen minutes from regression to fix — hats off for that. But the other half deserves saying too: at this cadence, anyone auto-updating is the test coverage. For a solo setup, that's usually harmless. Anyone running Claude Code in CI or behind a corporate proxy should pin the version and read the changelog, rather than leaving both to the auto-updater.

More interesting is the direction. Tally up what actually got added across this series and the center of gravity shifts away from model capability: managedMcpServers, which lets organizations push HTTP/SSE MCP servers out to all users (v2.1.259); an "Organization policy" line in /status and claude doctor that explains why the company policy failed to load (v2.1.261); --permission-prompts none for unattended machines, where everything that would otherwise require confirmation gets auto-declined; machines with forceLoginGatewayUrl that count as a gateway session from the start. That's no longer tool development — that's fleet management.

For your own workbench, two things from the week are worth keeping, and both are small and immediately useful. Try it /skill-doctor shows which loaded skills go unused and what they cost in context — anyone who's collected skills over months pays for every single one on every call in the system prompt, without ever seeing it. Try it /diff opens a full-screen side pane with the uncommitted changes, updating live while the agent edits. On top of that, a quiet dial for long agent runs: bashOutputMaxChars and taskOutputMaxChars raise how much command output the model actually gets to see.

The MCP ecosystem: the marketplace grows, and so does the attack surface

Two escape fixes in one week — and a marketplace report that couldn't be confirmed

MCP server and "managed": An MCP server is a small adapter that lets a coding agent reach something outside its chat window — a ticketing system, a database, the logs. Like an attachment for a power drill: the machine stays the same, but the attachment is what turns it into a screwdriver. "Managed" means: you no longer attach it yourself — your company puts it in your toolbox for you, and can forbid you from adding others.

That split is exactly what's new. managedMcpServers delivers servers from the top down, while allowedMcpServers, as of the same version, only governs what users add themselves. Before, both were the same lever. Anyone working inside a company with a policy will notice; anyone working solo should know it anyway, because it shows the direction: MCP is moving from "what I plug in myself" to "what gets provisioned for me."

The other half of the same story is less comfortable. Per the documentation, plugins in Claude Code can bring skills, agents, hooks, MCP servers, and LSP servers, and organizations can run their own marketplaces — so a plugin is foreign code, installed with one command from a URL, that then sits in the same directory tree as the repository the agent is working on. In a single week, two escapes were fixed there: v2.1.265 closes off a plugin path with a backslash that bypassed the symlink confinement on macOS and Linux; shortly before that, the same series noted that plugins could read files outside their own folder via a declared path that was a symlink. Both are findings, not incidents — but they say what class of code this is. Plugin sources deserve the same skepticism as npm dependencies, and that means, above all: not an unlimited number of them.

Unconfirmed Secondary sources have been circulating a claim that, since 09/01/2026, official remote MCP servers from GitHub, Stripe, Render, PostHog, and Resend could be installed as ready-made plugins. The primary documentation on plugin marketplaces says nothing of the sort — it covers building and distributing your own marketplaces, and names no vendor other than Anthropic. Until this shows up at a primary source, it's a rumor here, not a report.

Copilot: the agent finishes the pull request

Weekly release from 09/04/2026, for the week starting 08/31

The most eye-catching line in GitHub's weekly release is called "Agent Merge," and it has landed in VS Code 1.136 as a public preview. Verbatim: it brings the pull request into a mergeable state by working through review feedback, fixing failing checks, and resolving merge conflicts.

That's more notable than the usual model announcement, because it targets a different part of the day. Agents have been able to write the first draft for over a year now. What actually eats time comes after: the third review pass, the red CI run, the conflict after the rebase. Automating that stretch goes after the less pleasant and more valuable part.

The caveat sits in exactly that spot, though. A review comment is often a shorthand opinion about architecture; a machine resolution tends to make the red marker disappear rather than address the objection. And an automatically resolved merge conflict is exactly the kind of change that no longer shows up in any review, because it happens after the review. Worth trying — but look at every commit it produces, individually.

Alongside that, in the same release: Claude Fable 5.1 is available for Copilot Pro+, Max, Business, and Enterprise, Gemini 3.8 Flash is rolling out for Pro, Pro+, Max, Business, and Enterprise, and the Copilot harness is generally available in JetBrains. The counterweight remains 10/02/2026: on that day, Gemini 3.5 and 3.6 Flash give way to 3.8 Flash, Kimi K2.7 Code gives way to K3, Claude Opus 4.7 gives way to Opus 5. Hardcoded model names in scripts are now definitively maintenance work with a due date.

Codex CLI: five versions in two days, for one model

09/03–09/04/2026 — what a version series reveals about a tool

On 09/03, v0.153.0, v0.153.1, and v0.153.2 came out in quick succession; on 09/04, v0.153.3 and v0.153.4 followed. The middle two exist essentially to retrofit support for GPT-6 Astra and then fix that retrofit; the two from the following day fix Astra not showing up properly, or not being the default, in the model picker.

This isn't mockery, it's a structural observation. At Claude Code, a model switch shows up as one line among fifty; at Codex, it's the whole week. A harness that clings this tightly to its own model is the fastest at model launches — and, for a few days after every OpenAI launch, the more turbulent tool.
