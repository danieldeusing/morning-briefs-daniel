OpenAI is putting its Codex harness behind an API, Cursor is turning it into a permanently running cloud project. Whoever built the same harness as a solo open-source project is on today's casualty list — Aider without a GitHub release for thirteen months, Plandex for fourteen, Continue.dev formally discontinued. OpenAI is now selling the loop, not the model

The developer changelog entry from 09/10 is two sentences long and still describes a shift in the business model: "Released the Agents API in public beta. Build agents with a managed Codex harness while OpenAI handles session orchestration, context compaction, and recovery." What's being sold here is explicitly not the intelligence — that already existed — but the bookkeeping around it.

Session orchestration, context compaction, recovery: An agent working on a task for an hour produces more text than fits in the model's head. So someone has to decide what can be summarized away from the conversation history and what has to stay (compaction), what happens if the run dies mid-step-40 (recovery), and who keeps track of where the agent currently stands (session). Like a contractor coming back from lunch: he doesn't need the whole morning's conversation, but he does need to know which wall is already up. These three unglamorous things are exactly what every team rebuilds when it builds its first agent — and usually gets wrong.

Technically this runs on gpt-6-astra. Per a write-up of the OpenAI docs, billing is by tokens, tool calls, and container runtime, with no separate subscription fee — container runtime is the new line item to get used to, since an agent that mulls something over for ten minutes now also costs ten minutes of machine time. Execution happens either in OpenAI sandboxes, in your own environment, or at nine partners: Blaxel, Cloudflare, Daytona, DigitalOcean, E2B, Modal, Oracle, Runloop, Vercel.

Heads up The same write-up quotes the docs: "Data stays US-only, and Zero Data Retention is unsupported." Zero Data Retention means the provider promises not to store the content it's sent at all once it has answered. Under OpenAI enterprise contracts, that's usually the clause that lets you send client code through a third-party API in the first place. Without it, the Agents API is off the table for engagements with data-residency or confidentiality requirements — regardless of how good it is.

Try it Worth running as a benchmark, not as a migration: running an existing, self-built agent loop against the managed version once shows pretty quickly how much your own recovery code is actually worth. For client projects, the paragraph above still applies until further notice.

Cursor "Projects": the agent that doesn't stop

On the same day, probably not by coincidence: Cursor launches "Projects" in beta, per its own blog post "available in beta and rolling out to all users starting today." A project isn't a chat — it's a permanently running coordinator agent on its own cloud machine that distributes work to — in Cursor's phrasing — "thousands of subagents." As an example, Cursor cites a project "on track to touch 20 to 100 PRs a day."

Subagent: Instead of having one agent do everything itself, it hands off subtasks to fresh copies of itself, each starting with a clean, empty head and reporting back only its small result. Like a site foreman who doesn't lay every pipe himself but sends out ten people and only hears back "done" or "stuck." The advantage isn't intelligence, it's context hygiene: the coordinator stays uncluttered because none of the small stuff ever lands on its desk.

The numbers deserve suspicion. Cursor writes that new users merge "30% more PRs," and users who work mostly with Projects merge "six times as many." That's a vendor number with no control group, no stated time frame, and an obvious selection bias: "users who work mostly with Projects" are, by definition, the ones for whom it worked. Anyone who set it aside after two days isn't in that group anymore. On top of that, merged PRs are a throughput measure — the same work split into ten small PRs instead of one big one doubles the metric without producing a single extra line of code.

More interesting than the percentages is the direction. Cursor added self-hosted execution machines on 09/02, so tool calls can stay "entirely in your own network." Put together, that's the same picture as OpenAI: the machine moves into the cloud, and the concession to companies with data requirements gets bolted on afterward as an option.

Open weights: DeepSeek tidies up its API, Qwen leads the web arena

DeepSeek released V4.1-Flash on 09/10 — per its own docs, "the smallest model in our new architecture family, with native multimodal visual understanding." The practically relevant part is in the fine print: the old API names deepseek-v4-flash and deepseek-v4-flash-vision-exp now point to the new model, at a lower price — DeepSeek's own changelog says API prices were cut accordingly with the release. Anyone with those names hardcoded in a script gets the switch delivered whether they've tested it or not.

Qwen3.8-Max-0902, dated 09/02, is nine days old and thus just outside the window, but it's the open-weights move of the week. Parameter count (2.4 trillion), context length (1M tokens), and price ($2 / $6 per million tokens) stay unchanged; what changed is the post-training on coding and agent work. Result, per an aggregator report: rank 1 in Code Arena WebDev with 1,691 points against 1,687 for Claude Opus 5 Max — and, much more telling, TerminalBench 3.0 jumping from 11.3 to 29.0.

Arena points vs. a real jump: Arena scores are Elo numbers, like chess: people see two anonymous answers and pick the better one, and a ranking emerges from that. A gap of 1,691 to 1,687 is statistically nothing — that's a tie with better PR. The jump from 11.3 to 29.0 on TerminalBench, by contrast, is a real one, because that measures whether the model actually finishes a task in a real shell. Going from "mostly fails" to "manages barely a third" is still a long way from usable, though.

For local use, neither matters: 2.4 trillion parameters don't run on Daniel's hardware. Qwen becomes relevant only once the smaller variants get the same post-training.

Laid side by side, that's an uncomfortably clear line, and it doesn't run between open and closed, it runs between funded and unfunded. A harness is maintenance-heavy for a structural reason: every model generation shifts the tool-calling format, context window, prices, and reasoning behavior, and every time, the loop has to be updated to match. That's not work a solo maintainer carries alongside a day job for years. Aider was the reference point everyone measured against for twelve months — today it's an archive.

And that's exactly the gap OpenAI and Cursor have been selling their product into since yesterday. That's today's thesis: the harness stops being a project you clone and becomes a bill you pay. Anyone who doesn't want that ends up with Cline or OpenHands — both open, both active, both with a company behind them.
