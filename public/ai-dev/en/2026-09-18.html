A tool ranking that's actually ranking models

The September edition of LogRocket's AI coding tool ranking puts Claude Code in first place, up from two. OpenCode drops to two, Cursor stays at three. The list is notably honest about its own mechanics: "September 2026 brought no new tools into the field, but reshuffled the top two," and OpenCode's drop "reflects Claude Code's growing quality lead, not any regression at OpenCode itself."[1] As the reason for the rise, it cites a parenthetical: Claude Code "now runs on Fable 5.1 (1762 Elo, the highest score of any model in any tool)."[1]

That parenthetical is the only hard number in the justification — and it no longer holds today. The board in question is Code Arena: WebDev. Its Sep 11 snapshot, from 679,295 votes across 128 models, looks like this:[2]

#ModelScore (confidence interval)
1gpt-6-astra-max1800 (±16)
2claude-fable-5.1-max1758 (±14)
3claude-opus-5-max1687 (±7)
4qwen3.8-max-09021681 (±15)
5kimi-k3-max1674 (±11)
Elo, arena points, confidence interval: The score isn't an exam grade, it's a chess rating. Two models get the same task, a human sees both answers side by side with no names attached and picks the better one; the winner takes points from the loser. Like a club table-tennis ranking: the absolute number means nothing, the gap to your neighbor means everything. The "±14" is the uncertainty — how far off the true value could be, because only a finite number of matches have been played.

That makes the parenthetical wrong twice over: Fable 5.1 isn't first on this board, and its own score sits at 1758, not 1762. How 1762 came about can be traced — a trade outlet reported on Sep 5 that Astra had built a "35-point lead" over Fable 5.1, 1797 against 1762,[3] and the same outlet had reported shortly before that Fable 5.1 led the board with 1765.[4] Three values for one model in two weeks: 1765, 1762, 1758. All three sit within the ±14 margin of error the board itself reports.

My reading, and it's an uncomfortable one for any such list: this is an argument over noise. A board that states its own uncertainty as ±14 can't resolve a four-point difference — what it can resolve is the forty-point gap to first place, and that gap points the other way. The real finding sits in the fine print anyway: the tools themselves haven't moved this month — only the models inside them. A ranking that reshuffles because someone else released a model isn't measuring the tool.

In practice that means: a harness's rank is the wrong purchasing signal. The right question is whether you can swap the model underneath without switching your tool. There's no bar chart in this brief for it — bars starting from zero across a range from 1674 to 1800 would all look the same, and would hide exactly the gap that matters.

Google Home gets an MCP server — behind a subscription

Since Sep 16, an early-access MCP server has been running for Google Home. An agent can use it to control devices around the house via natural language; named as compatible are "Claude, Hermes, OpenClaw, ChatGPT, and Google Antigravity." Access is initially limited to the US and tied to a subscription: Google Home Premium Advanced, $20 a month.[5]

MCP: A language model can't do anything on its own besides generate text. For it to actually trigger something, it needs an outlet to the outside world — and MCP is the standard plug for that: a provider describes once which functions it offers, and any model that knows the plug can call them. Like USB-C: not the interesting device itself, but the reason every device fits every cable.

Two things are new here, and only one of them is technology. First, MCP is leaving the developer niche: until now, what hung off that plug were databases, ticketing systems, repositories — things a developer sets up themselves. Now a living room hangs off it, set up by a corporation for consumers. Second, it's the first MCP port that requires a subscription. The protocol was sold as an open, vendor-neutral USB-C for tool access; a $20-a-month port is something else. Not yet a pattern, but a precedent: if the interesting servers require a subscription, openness shifts from the protocol to the price list.

The point where I get stuck as a developer is the blast radius. A wrong tool call in a repository costs a git revert. A wrong tool call that unlocks a door has no revert. The same protocol layer that used to mean "read this table" now needs a different approval logic — and that logic isn't part of the protocol, it's homework for every server.

862 bits, 233 agent sessions, $400,000

On Sep 3, Eric Lu at Cognition published the factorization of RSA-260 — a 260-digit, 862-bit number from the 1991 RSA Factoring Challenge, and the largest Challenge number publicly factored to date. The news for this brief isn't the number theory, it's how the program came to be: "As a proof of concept, and because I've enjoyed factoring numbers as a hobby for about ten years, I orchestrated a fleet of Devins to obtain a factorization of RSA-260."[6] What came out of it is "glas," a GPU-accelerated GNFS sieve, built over 233 Devin sessions; an independent write-up counts 3,328 messages across 192 of those sessions.[8]

Factoring, and why RSA depends on it: Multiplying two large primes is easy; getting the two factors back out of the product is hard. Like mixing paint: stirring two cans into one bucket takes ten seconds, separating that bucket back into the two cans is a life's work. In RSA, the public key is that product, and the two factors are the private key. Whoever can factor has the private key.
GNFS and "sieving": The fastest known method doesn't try divisors one by one — it collects millions of small random finds and solves one giant system of equations from them at the end. Like a puzzle where you spend hours sorting edge pieces first and the picture then falls into place in five minutes. The collecting part is called sieving — and because each find can be searched for independently of all the others, that's exactly the part a GPU farm is good at.

The math behind it, and it's the most honest part of the write-up:

StageGPU-daysShare
Polynomial selection64313.1%
Sieving3,81377.5%
Linear algebra4679.5%
Total4,923≈ 13.5 GPU-years

Lu himself rounds it to "about 4,900 GPU-days, or 13.5 GPU-years, which at current market prices is roughly $400,000."[6] The independent recalculation comes to 4,923 GPU-days and, at $3.50 per GPU-hour, scales the rental cost up to $413,532[8] — same order of magnitude, just one assumption about the hourly rate in between. A second independent source confirms the 4,900 GPU-days and the publication date.[7]

Not the headline "AI cracks RSA" would be wrong. Cognition writes itself: "RSA-2048 remains roughly a billion times harder than RSA-1024 and does not appear to be significantly impacted by this work."[6] Nobody's TLS connection changed today. 862 bits is a key length nobody has seriously used in decades.

What changed instead is the price of a piece of software that used to come only out of research groups. A GPU-scaling GNFS sieve was historically years of work by several people with the right PhD. Here, one person with a hobby and a budget delegated the implementation — and the binding constraint at the end wasn't skill, it was the GPU bill.

I'd be careful generalizing from this. The number theory didn't come from the agents: Lu has been factoring numbers for fun for ten years and knew which stage takes how long and how to check the result. The agents delivered throughput on execution, not judgment on approach. What does transfer, in this direction: agentic tools scale up what an expert can get running in a day out of their own head. They don't replace the head. Try this What's notable is the operating mode — 233 bounded sessions instead of one endless one. When a project breaks down into stages with a checkable intermediate result, that's exactly the shape agents deliver reliably in today.

Fable 5.1 has a regression too — and nobody knows into what

Claude Fable 5.1 and Mythos 5.1 came out on Sep 1, generally available on day one instead of a staggered preview.[9] The pricing side of that release — cache reads 75% cheaper at $0.25 per million tokens, up to roughly 45% savings on heavily agentic tasks[10] — was the headline story here on Sep 16 and won't be repeated. Today is about the benchmark table next to it, because it shows two things at once.

On the upside: Terminal-Bench-Science 0.1 jumps from 24.7% to 52.6%, more than doubling. CursorBench 3.2.0 sits at 73.4% at maximum effort. Terminal-Bench 4.0 shows 55.8% — and there, Mythos 5.1 from the same family sits above it at 60.9%.[10] All of these are vendor figures from the vendor's own page.

On the downside, and this doesn't show up on any marketing slide: a Sep 5 analysis, under a section it labels "Official Benchmarks," notes "Toolathon Verified shows a regression: 77.8% pass@1 versus 80.6%, and 81.5% pass@3 versus 87%."[11] That benchmark name doesn't actually appear on Anthropic's own release page[10] — so despite the "official" framing, its source and exact identity are unconfirmed. pass@1 means the first attempt solves the task; pass@3 means any one of three attempts solves it. Both numbers sit below predecessor Fable 5.

Open What "Toolathon Verified" actually is couldn't be pinned down today — whether it's a renamed or successor version of SWE-Bench Verified or its own benchmark, who maintains it, and where its leaderboard lives. Checked directly against Anthropic's own release page: this benchmark isn't listed there at all, despite one source framing it as part of "the official benchmarks." A direct search turned up only generic SWE-Bench material. The two number pairs are sourced; the authority behind them isn't. I'm carrying the regression as a delta, not as a grade.

Nothing about this release has been independently remeasured yet, either. The Verified table on swebench.com loads its values via JavaScript and returned only the empty shell on this retrieval — so there's no SWE-Bench Verified entry for Fable 5.1 to lean on here.

My skeptical read: a doubling on a science-terminal benchmark alongside a drop on a tool-use benchmark isn't the pattern of "better overall" — it's the pattern of a shifted training mix. That Fable 5.1, sold as a coding model, sits behind its own sibling model on Terminal-Bench 4.0 fits that picture. For practice, that doesn't mean "don't use it" — it means the jump is task-specific, and whether it hits your task is something only your own run on your own code can tell you.
