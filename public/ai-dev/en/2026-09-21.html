Ten Models, Seventeen Days

Within two weeks, GitHub posted two deprecation entries to its changelog, and read together they land differently than read apart. The first, published Sep 3, names the deadline as Oct 2, 2026: Gemini 3.5 Flash and Gemini 3.6 Flash give way to Gemini 3.8 Flash, Kimi K2.7 Code gives way to Kimi K3 — and Claude Opus 4.7 gives way to Claude Opus 5.[1] The second, published Sep 18, names Oct 19, 2026: Gemini 3.7 Flash also gives way to Gemini 3.8 Flash, GPT-5.5 and GPT-5.4 give way to GPT-5.6 Sol, GPT-5.4 mini and GPT-5 mini give way to GPT-5.6 Luna, Grok 4.5 gives way to Grok 4.6.[2]

"Deprecation" in a model menu: In ordinary software, a deprecation means: it still works, you get a warning, and it gets removed at some later point. In an IDE's model menu it means something harder — on the stated day, the entry disappears from the picker and requests to that model ID stop working. Not "this carton of milk is about to expire," but "this flavor is being discontinued and the shelf gets cleared on the second."

Laid side by side, what's actually happening becomes visible: three generations of Gemini Flash — 3.5, 3.6, and 3.7 — die within seventeen days, leaving 3.8 standing. Four OpenAI models collapse on the same day into two successors. For Copilot Enterprise and Business customers, GitHub turns on the replacement models automatically, "unless an administrator has disabled the global default or explicitly disabled the model."[2] Anyone who has the global default switched off has to enable the successors by hand in the model policies — otherwise the team hits the deadline facing a shorter list than expected.

My read: the headline here isn't "Copilot is unreliable." It's that the model layer has definitively become a rental. If a model ID is hardcoded anywhere in your setup — in an agent config, in an eval suite, in the team's prompt library, in a CI step that automates code review — you've got eleven days for one group and twenty-eight for the other. The useful response is cheap: configure model IDs in exactly one place, never scattered across the codebase, and test the eval suite against behavior, not against the name. What you own is the harness. The model inside it, you rent by the month.

The Successor Nobody Has Measured

This is where the cut list gets interesting. Claude Opus 4.7 has an independent number: 87.6% on SWE-Bench Verified, rank 4 on the llm-stats board, which today is stamped as last updated.[1] Claude Opus 5 — the model GitHub explicitly names as the replacement — has no entry at all on that same board. Fable 5.1, Anthropic's current coding flagship, doesn't either, for that matter; Fable 5 still sits at the top with 95.0%.

SWE-Bench Verified — Top 6, as of Sep 21, 2026 (llm-stats.com)

I'm not claiming Opus 5 is worse than Opus 4.7. In all likelihood it's better — it's a full major version younger. I'm claiming something narrower: the one number that could verify that doesn't exist, and it won't exist by Oct 2 either. Whatever runs through the timeline until then as "Opus 5 is X% better at coding" comes either from the vendor's own report or from a board that doesn't disclose how it evaluated. That's not a knock on Anthropic — vendor numbers are legitimate as long as they're labeled as such. It's a knock on the retelling.

And a second dose of skepticism belongs here, aimed against the direction I lean myself: this board is conspicuously Anthropic-heavy. Seven of the top ten spots are Claude models; the first non-Anthropic entry is Gemini 3.1 Pro at 80.6%, tied for rank 8 with DeepSeek-V4-Pro-Max.[1] A board where one vendor owns the top either shows a genuine lead — or that this vendor has optimized hardest for exactly this board. Both are possible, and the board itself can't tell you which. That's why the number here runs with a date and a source and no superlative attached.

208,938 Stars, Rank 15

As of this morning, OpenCode has 208,938 stars per the GitHub API and carries an MIT license — making it by far the most-starred open coding agent.[1] LogRocket puts it at #2 in its September ranking, behind Claude Code, and explicitly notes that the drop reflects "Claude Code's widening quality lead, not any regression in OpenCode itself."[2] Standard Compute, meanwhile, ranks the same tool #15 of 20, with a score of 8.0/10 and a 42% community win rate, as of Aug 26.[3] And Qodo's own fourteen-tool list has Qodo at #1, Claude Code at #2, Cursor at #3 — OpenCode doesn't appear on it at all; that article is dated Feb 25, 2026, so seven months old.[4]

Four sources, four axes. Stars measure how many people once bookmarked a repository — that's popularity and openness, not output quality. An editorial ranking measures the editors' taste plus whichever week they happened to test in. A vendor's own list measures the vendor. None of these four has touched your repository.

The rule I take from this is unspectacular and outlasts any single ranking: read rankings for their reasoning, not their position. LogRocket at least states a reason, and it's falsifiable — a "widening quality lead" can be checked against your own tasks. "Rank 15 of 20" isn't a claim you can test; it's a sort order. Anyone choosing a tool today gets more out of an afternoon with their own ugliest ticket than out of all four lists combined.

MCP: Docusign Opens Up on Sep 30

MCP (Model Context Protocol): An open standard for how an AI assistant talks to external tools and data. Like USB for programs: instead of writing a custom adapter for every assistant-and-system pairing, the system builds one connector to the spec — and any assistant that speaks the spec can use it.

Docusign announced on Sep 4 that it will make its MCP server generally available worldwide on Sep 30: callable from Claude, ChatGPT, Gemini, Copilot, Slack "and any MCP client," with account-level admin controls and multi-region infrastructure.[1] That puts Docusign in line behind Salesforce and ServiceNow.

For this newsletter, the point isn't Docusign — it's the pace gap. The enterprise-software layer is converging on a protocol faster than the IDE layer is converging on model names — see the cut list in the first column. In practice, that means: an MCP server you write today has a longer half-life than the model you call it from. If you have to prioritize between "integration work" and "prompt work," that's an argument that rarely sits this clearly on the table.

Claude Code: Quiet Since Saturday

As of today, it's v2.1.278 from Sep 19 — it switches auto mode for API and Enterprise users to a server-side classifier and adds a new line to /status.[1] Before that: v2.1.277 on Sep 18 with AGENTS.md support and expanded gateway and plugin controls, v2.1.276 the same day fixing a proxy regression from v2.1.275, v2.1.274 on Sep 17. Nothing is dated for Sep 20 or Sep 21.

Five point releases in three working days, then two days of nothing: that's a workweek cadence, not a continuous one. Anyone scheduling updates for a team can build a mundane but useful rule out of that — updating on Fridays means getting the fix for the Friday regression only on Monday. That's exactly what happened twice in September.

Try this AGENTS.md support kicks in when no CLAUDE.md is present. Anyone running multiple agent tools on the same repository can, for the first time, get by with one project-memory file instead of one per vendor — the experiment costs five minutes, and you'll know right away whether the tools actually read the same file the same way.
