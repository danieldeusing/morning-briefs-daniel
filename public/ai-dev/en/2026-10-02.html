DevDay: OpenAI sells the price, not the leap

At DevDay (Sep 29–30), OpenAI didn't show a new flagship model, but a cheaper one: GPT-6.1 Sol. According to InfoQ, "the model approaches GPT-6 Astra on several evaluations" while costing a fifth of Astra's standard input and output prices. Cached input runs $0.10 per million tokens.[1] The full price list — $2 input, $10 output per million tokens — I only have from a search summary by Dataconomy, not from a full page retrieval; the OpenAI page itself blocks the fetch (HTTP 403).[2] So read the 2/10 figures as "very likely," not confirmed.

Cached input: At every step, a coding agent sends off almost the same giant prompt — system instructions, tool definitions, the files it already read. The provider remembers this unchanged opening and bills it at a discount next time. Like at a copy shop: the master page is already on the glass, you only pay for the new pages. For agents, this is the price that actually matters, because most of every call is repetition.

More interesting than the model is what happened to Codex. Four building blocks:[1][3]

  • Reusable cloud environments — kick off a task on your laptop, keep it running from your phone.
  • New CLI with voice input, a /agents view for delegating and monitoring multiple parallel tasks, Git worktree support, and session resumption.
  • Code review for GitHub pull requests and GitLab merge requests.
  • Codex Security Cloud scans repositories and new commits, investigates findings, removes duplicates, and prepares fixes.

My read: this is the feature list of Claude Code plus Cursor plus a Snyk-style scanner, bundled together. Worktrees and a multi-agent view are now table stakes — whoever lacks them is behind. The real competitive move is the security scan, because it runs on every commit without you triggering it. That turns Codex from a tool you call into a service that sits permanently in your repo. That's convenient — and a question worth asking before you enable it: which service gets to read every commit of your client's code?

Worth trying The /agents view in the new Codex CLI is the piece that compares fastest against Claude Code: same task, two worktrees, two harnesses. Worth an evening to see which parallel-task control suits you better. Just a side note: the new ChatGPT workspaces ("Dots," Space) from the same DevDay belong in the applications brief, not here.

SWE-Bench Verified: the table nobody can check

New models, same old situation. llm-stats.com (dated per the page: Oct 2, 2026) has Claude Fable 5 leading at 0.950, followed by Claude Mythos Preview at 0.939 and Claude Opus 4.8 at 0.886.[1] morphllm.com and benchlm.ai — both dated "October 2026," which I've only read via search summaries — instead put Claude Opus 5 in front at 96%, ahead of Mythos 5 (95.5%) and Fable 5 (95%).[2]

Sources disagree — not checked against the primary table. The official table on swebench.com loads its values via JavaScript; two fetches today returned only navigation, no numbers. So neither the top spot nor the top score is confirmed. I'm not stating either one as fact.

Two things are conspicuously missing: none of the boards checked carry a Verified score for Opus 5.5, and none for GPT-6.1 Sol or Gemini 4 Argon either. That's why all three releases this week advertise with different benchmarks instead — SWE-bench Pro, DeepSWE, "several evaluations." That's not a conspiracy, it's a sign: at 95%, Verified is spent as a marketing instrument, so every vendor looks for a scale where it can still show daylight. For you, that means a different test every week, and not one of them is directly comparable across vendors.

Gemini 4 Argon: the model you don't get

Google DeepMind introduced Gemini 4 Argon on Sep 30. The figure that sticks: the output limit rises to 1M tokens, "up from 64K previously."[1] Alongside that, a new best score on DeepSWE v1.1 at 77.9% and a tied first place on CWE-bench v1 at 68%.[2] Launch pricing: $2 input, $10 output per million tokens, rising later to $4/$20.[2]

Output limit vs. context window: The context window is how much the model can read at once. The output limit is how much it's allowed to write in one go before it has to stop. Until now, writing was the bottleneck: a model could read an entire repo but only re-output a few files at a time. A million tokens of output means: roughly rewriting a medium-sized project in one pass, without the harness having to break it into chunks.

The catch is in the same paragraph: Argon "is currently being rolled out to a group of trusted cyber-defense teams through our Fairwind program."[2] No general API access, no Gemini CLI default. For you, Argon today is an announcement, not a tool.

A note of skepticism on the numbers: DeepSWE and CWE-bench are benchmarks Google chose for itself here, and the figures are vendor claims with no independent entry. What stands out, though, is the pricing. The $2/$10 launch price — if the Sol figures hold up — is identical to GPT-6.1 Sol. Two labs, two days apart, the same price: that's not a coincidence, it's the new reference point flagship models are currently settling around.

Opus 5.5: the same work, half the tokens

Catching up on this, since no issue appeared after Sep 22: Anthropic released Claude Opus 5.5 that same day. According to the announcement, it costs 40% less than Opus 5 on typical workloads and outputs text over 30% faster. The more interesting claim: on agentic coding, it matches Opus 5's quality with "roughly half the tokens" — cutting the cost of such tasks by 40 to 50%.[1]

One tester reportedly completed a 680,000-line code migration in under a day.[1] That's an anecdote from the vendor announcement, not a measurement — with no indication of how much of it was mechanical renaming.

On SWE-bench Pro, aggregator benchlm.ai has Opus 5.5 leading with a record 89.9%.[2] I only have this figure via a search summary, not checked against the official Pro table. There's still no SWE-bench Verified score for Opus 5.5 anywhere.

My take: the "half the tokens" line matters more to Claude Code users than any benchmark. It means not just lower cost but also that an agent hits the context limit less often and has to compact less often — and compacting is exactly the moment where long sessions lose the thread. Whether this holds in your repo is something /cost will show you after a week, faster than any leaderboard.

Claude Code Mods: powerful, and without a sandbox

Claude Code 2.1.287 was released on Oct 1; the changelog's headline item reads "Added Claude Mods: plugins may now modify deeper behavior" — plus a built-in Mod called "You should know," where a side agent reads along and flags things you or Claude might have missed.[1] Mods are JavaScript/TypeScript code that runs inside the Claude Code process itself.

Security: According to the Anthropic documentation cited by mixed-news, a Mod is "code that runs with your permissions" — it can read and write files, start processes, and make network requests. "Mods are not sandboxed": the sandbox only isolates the bash commands Claude executes — a process a Mod starts runs outside it. Mods can read your secrets, meaning environment variables and settings files, including an API key stored there.[2]
Sandbox: A fenced-off sandbox where code is allowed to play without reaching the rest of the house. Claude Code can put the agent's shell commands into such a box. A Mod, though, doesn't stand inside the box — it stands next to it. It's worth exactly as much trust as an npm package you install with full permissions.

This isn't a bug, it's an honestly documented design decision, and Anthropic deserves credit for stating it this clearly. The problem is the ecosystem that follows now: Mods will get shared like VS Code extensions, and the extension marketplace took years to get malicious code even halfway under control. Anyone running Claude Code with client credentials in the shell should treat Mods like any foreign dependency: read it before you turn it on.

The existing brakes: claude plugin validate run on the Mod directory shows, before installation, which permissions a Mod is requesting; Mods can be disabled individually, via --safe-mode, or with disableAllHooks: true in settings.[2] My recommendation for Daniel's setup: only use Mods from sources whose code you've read, and keep API keys out of settings files — pull them from a secret manager at runtime instead.

Two tools between the agents

Weave Router is an open-source proxy (Apache 2.0) that sits between your agents and the Anthropic, OpenAI, and Gemini APIs, "picking the best model for every single request." Promised: 40–70% lower costs with "just one endpoint changed," with the routing decision made by an ONNX model in under 50ms. Integrations exist for Claude Code (with /router-off and /router-on), Codex, OpenCode from v2 onward, Pi, and — in early beta — Cursor. The repo sits at 5.5K stars.[1]

Model routing: Not every agent request needs the most expensive model. "Read this file and summarize it" is within reach of a small model; "design the migration" needs the big one. A router is a dispatcher who glances at every request and hands it to the cheapest driver who can get it there safely.

Worth trying The 40–70% is a vendor claim, and the honest question is how often the dispatcher misjudges — a planning step routed to the wrong model costs more than it saves. That's exactly why the /router-off switch is the most valuable part of this: one day with it, one day without, same kind of task, compare costs. With Opus 5.5 already in your corner, though, the lever shrinks.

Google Stitch Skills is a collection of 14 agent skills across three plugins that connects the Stitch design tool to Codex, Antigravity, Gemini CLI, Claude Code, Cursor, and OpenCode. The "Stitch Loop" builds multi-page websites with automatic checking from a single prompt.[2] Useful for landing pages, more of a footnote for Daniel's day-to-day — what's notable above all is that Google is explicitly shipping its skills for Claude Code and Codex too. Skills are becoming a vendor-neutral format.
