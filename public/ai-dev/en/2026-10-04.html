GitHub writes: "Please update your workflows and integrations to use the supported models before this date." For Business and Enterprise customers with default settings, replacement models switch on automatically — unless the admin has disabled the global default or individual models.[2]

Model pinning: You write a fixed model name into a config file or script, say gpt-5.4. That's like placing an order by item number. If the store discontinues the item, the order fails — or you silently get a successor that behaves differently.

My read: ten models in seventeen days — Copilot now rotates its lineup almost as fast as the labs ship. For chat in the editor, that doesn't matter. For anything automated, it's a maintenance item: CI steps, the new code review API, agent configs with a fixed model. The automatic switch for Business is convenient, but a different model writes differently, and that's exactly what shows up only in review.

Worth trying Run grep -rn "gpt-5\|grok-4.5\|gemini-3" .github/ once in your own repo. Anyone with hits there should switch now, not on Oct 19.

Sonnet 5.5: from 10.3 to 70.6 percent — and what it means

Anthropic's own benchmark table for Claude Sonnet 5.5 (released Sep 28) lists for Terminal-Bench 4.0: Sonnet 5.5 70.6%, Sonnet 5 10.3%, Opus 5.5 66.4%.[1] The price stays at $2 input and $10 output per million tokens.[1]

Vendor figure: These numbers sit on Anthropic's product page. I couldn't find an independent Terminal-Bench entry for Sonnet 5.5. The Opus figure carries a footnote in the table — so the measurement conditions aren't identical.

A sevenfold jump in a point release is unusual. Three explanations are more plausible than "the model got seven times smarter":

  • Harness: Terminal-Bench measures the model and the tool loop together. According to coverage of the release, part of the gain comes from "more efficient tool-call batching."[2] That's a real benefit — but one your own harness might draw on differently.
  • Threshold effect: At 10%, a model often fails on one single recurring obstacle. Remove it, and many tasks flip at once.
  • Selection: The vendor decides which tests make it onto the page.
Harness: The program wrapped around the model — it gives the model tools (shell, files), collects the results, and decides when to move on. A benchmark like Terminal-Bench tests the driver and the car together. A better car doesn't make the driver smarter, but the lap time gets faster anyway.

My view: yesterday's recommendation stands — Sonnet 5.5 as the default in Claude Code, Opus 5.5 for planning. But the 70.6% isn't the reason for that. The reason is the same price with, per Anthropic, over 30% more speed — and you measure that yourself with /cost.

The official table at swebench.com loads its rows via JavaScript; the fetch returned only the navigation.[1] LiveCodeBench looks the same: different sub-boards and snapshot dates, different leaders.

My read: that's the real benchmark story of the week. When three sources covering the same test can't even agree on the leader, each one is measuring something different — different setup, different agent, different subset. Scores above 95% also suggest the test is saturated; the tasks have been public for years and easily end up in training data. For a tool decision, SWE-Bench Verified is barely useful anymore.

The Aider leaderboard still lists Nov 20, 2025 as its last update, with "gpt-5 (high)" on top at 88.0%.[2] Dated Nov 20, 2025 — not current.
