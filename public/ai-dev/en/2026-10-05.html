Security agents: the experiment becomes a category

On September 29, OpenAI introduced Codex Security Cloud at DevDay; Channel Insider covered it in detail on Oct 1.[1] The tool "runs scheduled security scans in the cloud" and reads a repository first to understand how the application is built. Only then does it look for vulnerabilities.[1]

Three details are more interesting than the announcement itself:

  • Threat model: Codex builds "an editable threat model around attacker entry points and trust boundaries." So you can correct it.[1]
  • Reproducing before reporting: every finding gets reproduced in an isolated environment first. Only then does a human see it. Confirmed findings come with a suggested patch, but "developers still decide what reaches the codebase."[1]
  • Billing: by the token — and "scans pause when funding is unavailable." Available for ChatGPT Pro, Business, Enterprise, and Edu, as a Research Preview.[1]
Threat model: A list of where an attacker could get into your software — login, API, file upload — and which boundaries they'd then have to cross. Like a floor plan of a house where you mark the doors, windows, and the path to the safe. Anyone who knows the floor plan searches with purpose instead of everywhere.

That makes OpenAI late to this, not early. This year's list:

My read: five vendors, one year, the same idea. Writing code is now a commodity; what's being sold is checking it. The decisive difference between these tools isn't how much they find, but whether they prove a finding before reporting it. A scanner that spits out 200 suspects costs you an afternoon. One that delivers three reproduced vulnerabilities with a patch saves you one. Codex and Devin promise the latter — nobody has measured that independently yet.

Worth trying Anyone testing one of these agents: take a repo with a known, already-fixed vulnerability, roll it back to the old state, and see whether the agent finds it. That's your own benchmark, and it's more honest than any vendor figure.

The other side: GitHub throttles automated bug reports

On Oct 1, two days after DevDay, GitHub published two changes to private vulnerability reports. The first caps how many reports a single account can submit. The reasoning is in the changelog: "Open source maintainers are receiving more low-quality and automated vulnerability reports, which can bury the reports that matter."[1]

The second replaces the free-text field with a form that asks for the details, "including a reproducible proof of concept."[2]

Private vulnerability report: A confidential channel on GitHub where someone reports a security flaw to the maintainers without making it public. Like a mailbox just for the building super, instead of a note on the bulletin board. Flood the mailbox with flyers, and the super can no longer find the one letter that matters.

GitHub doesn't say where the automated reports come from. But the timing is striking: vendors are currently selling mass vulnerability discovery, and the largest open-source platform builds in a brake on mass reporting the same day. The demand for a reproducible proof of concept is exactly the bar the security agents will have to clear.

My view: anyone who turns a security agent loose on someone else's open-source project and reports the findings unchecked is the problem, not the solution. The mandatory form is the right call. Nothing changes for your own repo — except that as a maintainer, you now have better tools against report spam.

1 million tokens: no longer a special feature

Per the model pages, Claude Opus 5.5 (since Sep 22) and Claude Sonnet 5.5 (since Sep 28) each take 1,000,000 tokens of input and output up to 128,000 tokens.[1] Gemini 3.8 Flash (since Sep 2) takes 1,048,576 tokens, at a launch price of $0.75 input and $3.75 output per million tokens; standard pricing kicks in on Jan 1, 2027.[2]

Context window: How much text the model has "in view" at once — code, docs, chat history. A million tokens is roughly a mid-sized repository. Like a desk: a bigger one holds everything at once, but that doesn't automatically help you find the right sheet of paper faster.

My read: size is no longer a differentiator. Three questions matter instead. First: does the model still find the right spot in a full window? There's no independent measurement for that this round. Second: what does re-reading cost? For Sonnet 5.5, a cache read costs $0.20 per million tokens, a tenth of normal input.[3] Third: does your agent even need this? A targeted grep plus 50,000 tokens often beats a million tokens of noise.

Sonnet 5.5 after one week: two benchmarks, two winners

The week didn't change the picture around Sonnet 5.5, but it sharpened it. On Terminal-Bench 4.0, Sonnet 5.5 leads Opus 5.5, 70.6% to 66.4%. On CursorBench 4.0, it's the reverse: Sonnet 5.5 (Low Effort) scores 55.5%, Opus 5.5 scores 57.8%.[1] Both are vendor figures from the release table, with no independent entry.

Sonnet 5.5 still costs $2 input and $10 output per million tokens, Opus 5.5 $4 and $20.[1][2] In GitHub Copilot, Sonnet 5.5 has been generally available since Sep 28; GPT-6.1 Sol followed on Sep 29.[3]

My view: two tests, two winners, a gap of a few points each way — that reads as "equally good, half the price." Sonnet 5.5 remains the sensible default in Claude Code. Opus pays off where a mistake is expensive: architecture, migrations, planning.

It's Monday, October fifth. The weekend was quiet: no lab and no coding tool shipped anything new since Friday. So today's issue steps back to look at a pattern that's been building all year.

OpenAI introduced Codex Security Cloud at DevDay. The tool scans repositories for security holes on an ongoing basis. It first builds a threat model — basically a map of where an attacker could get in. Every finding gets reproduced in an isolated environment before a human ever sees it. Billing runs by the token, and when the budget runs dry, the scans pause.

That makes OpenAI late to the party, not early. Anthropic launched Claude Code Security back in February, Replit rolled out its Security Agent in April, Cognition's Devin Security Swarm followed in July, and Cursor shipped its Security Review in September. Five vendors, one year, the same idea. The real question is whether an agent proves a finding before it reports it — and nobody's measured that independently yet.

The flip side of the story is sitting in GitHub's changelog. On October first, GitHub capped the number of private vulnerability reports each account can file. Its reasoning: maintainers are getting buried under low-quality, automated reports, and the important ones get lost in the pile. A new form now demands a reproducible proof of concept — exactly the bar the security agents should have to clear too.

A quick word on context: Claude Opus and Sonnet five point five now take in a million tokens each, and Gemini three point eight Flash matches that. Size on its own stopped being a selling point. What matters more is whether a model can still find the right spot in a full window, and what it costs to read that window again.

One week into Sonnet five point five: it leads Opus on Terminal-Bench, trails it a bit on CursorBench. Both numbers come from the vendor. At half the price, Sonnet stays the sensible default, with Opus reserved for the expensive decisions.

On SWE-Bench Verified, Vals AI ranks DeepSeek V4 Pro at ninety-six point four percent — the best open model, and second place overall. A different aggregator puts it in first. At gaps that small, the test is basically saturated.

In the toolbox, Cline was the busiest, with five releases on Friday; OpenHands' last update landed September twenty-fifth; Cursor's been quiet since September twenty-third. Tomorrow we'll see whether the new week brings any movement, and in two weeks Copilot drops its next round of models.
