OpenHands v1.25.0: the router gets a switch

Update since yesterday: Yesterday OpenHands was still at v1.24.0 from Sep 25. Today, Oct 6, v1.25.0 shipped.[1] Three items top the release notes:

  • Voice dictation: "add optional voice dictation to the chat input." You speak the task instead of typing it.[1]
  • Model router: a new switch, "Run at conversation start." You decide whether the router already picks a model when the conversation starts.[1]
  • Personas: "give a profile its own persona or extra instructions." Each agent profile gets its own instructions.[1]

There are smaller things too: LLM profiles can now be managed together per connection, canvas apps update, and the conversation drawer now has tabs. The notes list no breaking changes.[1]

Model router: A switchyard in front of the language models. It looks at the task and sends it to a matching model — the fast, cheap option for a rename, the expensive one for an architecture overhaul. Like a shop where the master mechanic decides whether the apprentice or the specialist works on the car. The new switch controls whether that decision gets made before you've even asked your first question.

The pace is notable. From v1.17.0 (Sep 9) to v1.25.0 (Oct 6), that's nine releases in four weeks.[1] v1.19.0 (Sep 16) added GPT-6 Astra support and the ability to scope MCP servers per agent profile.[1]

My take: profiles have become the actual product. A profile now bundles model, MCP servers, persona, and router behavior. That's exactly what you piece together in Claude Code through subagents and settings files — just in one interface, and model-neutral. Anyone switching between Anthropic, OpenAI, and local models gets the cleanest separation here.

Worth trying Set up two profiles: one with a local model (Ollama) and tight MCP access for routine refactors, one with a large cloud model for planning. After a week you'll notice how much of the expensive work can actually run cheap.

GitHub describes the two models differently. Sonnet 5.5 is "designed for well-scoped everyday work like building features and fixing bugs." GPT-6.1 Sol is "designed for agentic coding and terminal workflows."[1] That's marketing language, but a useful clue as to what GitHub itself uses them for.

Harness: Everything around the model — how the tool reads files, runs commands, summarizes context, asks follow-up questions, and fixes errors. The model is the engine, the harness is the car. Two cars with the same engine can still drive very differently.

My read: right now, a model lead lasts about a day. After that, every major tool has it too. For picking your tool, that means: don't ask "which model does it have?" but "what does it do with the context?" That's exactly where this week's releases aim — Cline with /compact, OpenHands with the router, Claude Code with Mods. Competition has shifted from the model to how it's used.

Copilot now operates desktop programs

On Oct 1, GitHub rolled out "Computer use" for Copilot: "now available in public preview in GitHub Copilot CLI and the GitHub Copilot app on macOS and Windows."[1] In the CLI you turn it on with /computer on, in the app under Settings → Computer Use.[1]

On safeguards, GitHub writes: "Copilot asks for approval before controlling an app." You can review and revoke "always allow" grants later. Organizations can disable the feature centrally.[1] The entry doesn't say which model powers it or which plans it covers.

Computer use: The model sees screenshots and operates the mouse and keyboard like a human. That lets an agent operate programs that have no API — a simulator, an admin tool, an installer. The cost: it's slow, and a wrong click is a real click.

My take: for developers, the use case is narrow but real — clicking through an app in the simulator after the agent has changed the code. The approval prompt is a requirement, not a convenience. Only give "always allow" to programs where a misclick costs nothing. No browser with a bank account logged in, no mail client.

Copilot cleans house: four models dropped

Since Oct 2, four models have been deprecated across all Copilot surfaces, each with a successor:[1]

  • Gemini 3.5 Flash and Gemini 3.6 Flash → Gemini 3.8 Flash
  • Kimi K2.7 Code → Kimi K3
  • Claude Opus 4.7 → Claude Opus 5.5

Admins have to enable the successors in Copilot's settings. The old models disappear on their own.[1] This also confirms that Gemini 3.8 Flash is available in Copilot.

My take: if you have scripts or workflows with a hardcoded model name, check them now. A model that quietly disappears is the classic reason an agent run suddenly starts behaving differently.

Claude Code: Sonnet 5.5 in the Sonnet tier, plus Mods

Per the changelog, v2.1.284 made Claude Sonnet 5.5 the default model of the Sonnet tier via the Anthropic API. Claude Code's own default model stays Opus 5.5. v2.1.287 brought "Claude Mods," with a built-in mod called "You should know." Further patches followed up to v2.1.291.[1] The changelog lists only version numbers, no dates. There's no way to tell from it which version shipped in the last 24 hours.

Mods: Extensions that change Claude Code's own behavior — not just an extra tool like an MCP server, but an intervention in prompts or the interface. Like a plugin for your editor, versus an external program you call from the editor.

Anthropic calls Sonnet 5.5 "30% faster" than its predecessor.[2] For everyday use: if you haven't configured anything, you're still working with Opus 5.5. You only get Sonnet 5.5 once you explicitly pick the Sonnet tier.

My take: Mods turn Claude Code into a platform, the way OpenHands is attempting with profiles and Cline with connectors. After updating, check quickly with /model that you land where you want — especially if you previously had Opus set as fixed.

Bench note: Pro isn't Verified

For Claude Sonnet 5.5 and Opus 5.5, the numbers making the rounds are mainly these: 81.3% and 89.9% on SWE-Bench Pro.[1] Those are vendor figures from Anthropic's release table, fetched here only through an aggregator. On SWE-Bench Verified, the test you've been tracking, Sonnet 5.5 still shows "Coming soon."[1] The official table at swebench.com returned no values on this fetch.[2]

SWE-Bench Verified vs. Pro: Both give the model real GitHub issues to solve. Verified is a human-checked set of known tasks. Pro is a newer, harder set. These are two different exams — like a high-school final and a university exam. You can't directly compare the grades.

The trap sits in the same aggregator: Sonnet 5 scored 85.2% on Verified, Sonnet 5.5 scored 81.3% on Pro.[1] Put those side by side and you'd read a regression. It isn't one — it's a different test. The only clean comparison is Pro against Pro: Sonnet 5 scored 63.2% there.[1] That's a vendor figure too.

The same holds for GPT-6 Astra (since Sep 3): OpenAI reports about 57.9% on Terminal-Bench 4.0, up from 37.3% for its predecessor — via secondary sources only, with no independent entry.[3]

  • Aider Leaderboard: dated Nov 20, 2025, topped by "gpt-5 (high)" at 88.0%. Nearly eleven months old.[4]
  • LiveCodeBench: the page shows only "Loading leaderboard data…" No number.[5]
  • LMArena Code Arena (WebDev): around Sep 5, GPT-6 Astra led at 1797 over Claude Fable 5.1 at 1762 — per a secondary source, a month old.[6]

My take: right now there's no independent, shared coding test for September's models. So no bar chart today. Until Verified entries land, your own repo is the most honest benchmark.
