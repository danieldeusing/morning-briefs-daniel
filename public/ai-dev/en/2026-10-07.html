The Number Behind This Week: Claude Code Pulls Well Ahead of Copilot

For its tenth Developer Ecosystem Survey, JetBrains polled "more than 15,000 professional developers worldwide" between May and July 2026. The coding-agent results have been on the JetBrains Research blog since August.[1] So the news is a few weeks old. It still belongs at the top, because it's the biggest shift in developer tools this year — and because it explains why GitHub and Cursor are shipping so fast right now.

Two more figures: in the US, Claude Code stands at 47%. For 31% of all respondents, it's the most-used tool. JetBrains calls that "an almost 80% conversion rate" — once people use it, they mostly make it their main tool.[1] Overall, 90% of respondents use coding agents at least weekly, 68% daily.[1]

Reweighted survey: Whoever takes a survey is never a perfect mirror of all developers — JetBrains customers, for instance, are more likely to respond than others. So JetBrains reweights the answers by region, experience, and other traits so the result "better represent[s] the global developer population".[1] Like a cook diluting a too-salty taste test before judging the whole dish. It helps, but it's still a sample.

My take: three things matter more than the ranking. First, Copilot is falling even though it's baked into every GitHub account — distribution alone no longer cuts it. Second, Codex is the other winner here: from 3% to 16% in half a year. The race is between two terminal agents, not two editors. Third, of all things, Cursor — the best-known AI editor — is losing ground. One caveat remains: JetBrains sells a competitor of its own in Junie, and these numbers are self-reported. As a direction, though, they're unambiguous.

How Much Code Do Agents Really Write?

A second JetBrains analysis from the same survey asks about the share of agent-written code. Averaged across all respondents:[1]

  • about 47% "fully written by agents,"
  • about 38% written with some AI help,
  • about 27% written entirely by hand.

That adds up to more than 100%. That's not an error: respondents picked ranges like "21–40%," and JetBrains uses the midpoints of those ranges. The methodology note itself says the total "could exceed 100%".[1] So read the three numbers as rough weights, not exact shares.

There are differences between tools. Cursor users let agents write 58% of their code; for 28% of them, it's over 80%. Among developers who use Claude Code as their main tool, about 32% let agents write over 80% of their code.[1]

For comparison, an older figure: in the Stack Overflow Developer Survey 2025 (49,000+ responses, published Jul 29, 2025), 84% said they use or want to use AI tools, up from 76% in 2024.[2] That measures usage, not code share.

What we're deliberately leaving out: the figure "41% of code is AI-written" circulates on many sites citing JetBrains. We couldn't trace it to any primary source in that form. JetBrains itself cites the figures above for 2026.

My take: the Cursor number is the interesting one. Cursor is losing users, but the ones who stay delegate more than average. That points to a tool shrinking from a broad mass to a core of power users.

Cursor: Control Local Agents From Your Phone

Update since yesterday: Yesterday, Cursor had been quiet since Sep 23. On Oct 6, "Remote control for local agents" arrived.[1] With the Cursor app for iOS, you can see what an agent on your machine is doing right now and send it messages.

  • The agent doesn't move: "It keeps running on your computer, and the app connects to it."[1]
  • Your machine has to stay "on and online." To keep a laptop from sleeping: "plugged in with the lid open".[1]
  • You confirm the pairing in the desktop app.[1]
  • On by default for everyone except Enterprise. There, admins enable it under "Org settings > Security and identity > Remote control".[1]

My take: this answers the pattern of "the agent works for two hours while I'm away from my desk." The upside over cloud agents: code, secrets, and local models stay on your machine. The downside: on by default means a lost, unlocked phone opens a path to your agent. Check what permissions the agent has on your machine before you let it keep running remotely.

Try it If you use Cursor: start a long refactoring run, walk away, and answer only the follow-up questions via the iOS app. That quickly shows you how often your agent really waits on you.

Copilot Ships Daily

When a survey shows you falling from 29% to 21%, you need to show you're moving. Copilot's entries in the GitHub changelog over the last ten days:[1]

DateEntry

Oct 1Computer Use in the CLI and app (Public Preview)
Oct 2Code Review: API access and a new default tier
Oct 6Update your IDE so agent activity shows up in usage metrics again

What's new for you is mainly Code Review: "You can now request a review from Copilot using the supported REST and GraphQL APIs."[2] The previous "Default" tier now runs as "Balanced"; the change "took effect September 28, 2026." Generally available for Pro, Pro+, Max, Business, and Enterprise.[2]

Effort level: How long the model gets to think before it answers. Low is fast and cheap, high is more thorough and more expensive. Like choosing between a colleague's quick glance at your pull request and a proper review over coffee.

The Oct 6 entry affects teams that measure Copilot usage: older IDE plugins no longer report agent activity correctly.[1] Anyone assigning licenses based on these metrics should update the plugins first.

My take: the API is the real lever here. It turns Copilot Review into a building block in your CI, not just a button in the UI. For teams already on GitHub, that's more convenient than any third-party tool.

Try it Build a CI step that requests a Copilot review via the API when the "ready" label is applied. In two weeks, compare what it finds against what your own Claude Code or Codex review catches.

Claude Code v2.1.292: Effort per Subagent, Many Security Fixes

Update since yesterday: Yesterday the changelog was at v2.1.291. Now it's at v2.1.292.[1] The changelog doesn't give dates.

  • Effort for subagents: "Added an effort parameter to the Agent tool, so Claude runs a sub-agent at the effort level you ask for".[1]
  • Plugins: claude plugin install now supports --marketplace <source>.[1]
  • Security: a fix for "PreToolUse hook approvals and auto mode bypassing the permission prompt for file reads from network (UNC) paths." Plus fixes for file access outside the approved scope via a symlink swapped mid-read (macOS, Windows), and for rm -rf on alternative Windows spellings of the home folder.[1]

My take: the effort parameter is the same idea as Copilot's "Balanced" — allocate compute time deliberately. A research subagent rarely needs the highest level, a planning subagent often does. The security fixes mainly affect Windows and network drives, but hook bypasses are exactly the gaps you're relying on in auto mode. So: update.

The Challengers: Meta on Price, Google on the Goal

Meta Muse Code has been out in beta since Aug 5, 2026, running on the Muse Spark 1.2 model.[1] On Terminal-Bench 2.1, Muse Code reportedly scores 82.9%, Claude Code with Opus 5 scores 86.7% — vendor figures from the announcement, not independently measured.[1] So Meta is playing the price card: a "contributor tier" costs $0.20 per million output tokens, "more than ten times cheaper." The condition is that you agree to share your feedback data.[2]

Google Jules takes a different path. At Google I/O on May 19, 2026, Google introduced Jules V2, internally called "Project Jitro": instead of step-by-step prompts, you give it a goal.[3] Jules runs on Gemini 3.1 Pro for Pro subscriptions, and on Gemini 3 Flash in the free tier.[3] Jules doesn't appear separately in the JetBrains survey; Google's Antigravity sits at 6% there.[4]

Goal instead of steps: Until now, you'd tell the agent "read file X, change function Y, run the tests." With a goal-driven agent, you just say "the tests should pass and login should use OAuth," and it plans the steps itself. Like giving a taxi driver the address instead of every turn.

My take: a gap of just under four points on a vendor benchmark is small in practice, a tenfold price difference is big. The catch is in the condition: go cheap, and you give up your data. Fine for a hobby repo, not for client code. Jules remains the day-to-day number three behind the two terminal agents.

Bench Note: the Table Stays Empty

The official SWE-Bench Verified table on swebench.com loads its values via JavaScript; today's fetch again returned no numbers. The aggregator llm-stats.com lists Claude Fable 5 at 95.0% and Claude Mythos Preview at 93.9% at the top.[1] We couldn't cross-check these figures against the verified table. Treat them as vendor or aggregator claims, not as a measurement.

Why 95% means little: SWE-Bench Verified is a fixed, public set of GitHub issues. The longer a test stays public, the more likely its tasks or solutions end up in the training data of newer models. Then the test measures memorization instead of skill — like an exam whose questions have been online for years. Above 90%, the gap between two models barely means anything anymore.
  • Aider Leaderboard: "Last updated" Nov 20, 2025, topped by "gpt-5 (high)" at 88.0%. Nearly eleven months old — useless as a current comparison.[2]
  • LiveCodeBench: only aggregator summaries, no primary data. We're not citing a number.

My take: the only solid coding number this week comes from a survey, not a benchmark. Developers voted with their feet while the leaderboards stood still. That's why there's no bar chart today.
