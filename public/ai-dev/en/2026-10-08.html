Claude Haiku 5.5: the cheap model for the grunt work

Yesterday, on Oct 7, Anthropic introduced Claude Haiku 5.5: "Our fastest, cheapest, and most capable small model yet."[1] The price depends on prompt length. Up to 100K tokens it costs $0.10 per million input tokens and $0.50 per million output tokens. Above that it is $0.50 and $2.50.[2] The model is called claude-haiku-5-5 in the API and also runs on AWS, Google Cloud and Microsoft Foundry.[2]

For you as a Claude Code user, the more important line is in the v2.1.293 changelog: "Added Claude Haiku 5.5 (claude-haiku-5-5) as the default Haiku model on the Anthropic API, with 1M context."[3] The product page itself names no context window — the 1M appears only in the changelog.

Price per million tokens: A token is a word fragment, roughly three quarters of a word. You pay separately for what you put in (input) and for what the model writes (output). Like at a copy shop: scanning costs little, printing costs more. At $0.10 per million input tokens, showing an agent a codebase of 100,000 tokens costs about 1 cent.

What is missing: any benchmark number. The product page shows the comparisons only as an image. The text says only that Haiku 5.5 is "a significant step up over Haiku 4.5 across coding, tool use, computer use, and agents".[2] For comparison, the page gives a value of 73.3% on SWE-Bench Verified for Haiku 4.5. Next to it are customer quotes: Box measures "11 points higher than Haiku 4.5 at about half the latency", HubSpot "92.8% averaged over three runs" on its own test suite.[2] These are customer statements on the vendor's page, not an independent measurement. No independent figure exists yet.

My view: Haiku is not the model you code with. It is the model for the subagents that search files, summarize logs and evaluate tests. Together with the effort parameter for subagents from v2.1.292 (in yesterday's brief), you can build a cost tier: Haiku searches, Sonnet or Opus decides. Before you use it widely, test it on your own repo — without published numbers, your own test is the only measurement that counts.

Try it Explicitly set one exploration subagent in Claude Code to Haiku and compare for a week how often the main agent has to double-check its findings. That shows whether the savings are real.

Anthropic says Opus 5.5 "performs at the level of Claude Fable 5.1 on most work and costs 40% less to run than Claude Opus 5". Sonnet 5.5 is supposed to be "30% faster" and cost "up to 30% less" than Sonnet 5.[5] Both are vendor claims.

Competition therefore runs on everyday quality and the tooling around the model, not on price anymore. Sonnet 5.5 re-measured: a six-point gap

For Sonnet 5.5 there is now something Haiku lacks: an independent measurement. Vals.ai measures 64.14% on Terminal-Bench 4.0 (rank 2 of 45).[1] Anthropic's own table at launch gives 70.6% at maximum effort.[2]

Terminal-Bench: A test in which the model has to solve real tasks in a command line — build packages, set up servers, find bugs in a script. So it measures "can the agent work" more than "can the model write a function". Like a driving test in city traffic instead of a theory exam.

One caveat on Vals.ai: the same site also names 53.03% on Terminal-Bench 4.0 (out of 37 models) and a different overall index in an update post.[1] Which value is current cannot be determined from outside. We use the table figure, but the spread shows how shaky such values are.

My view: A six-point gap between vendor and re-measurement is normal — the vendor takes the best setting, the tester a default setting. The problem is not Anthropic alone. It is that for Haiku 5.5 there is no number in the text at all, and for OpenAI almost only secondary sources. A vendor number is a promise, not a measurement.

OpenAI: GPT-6.1 Sol in Codex, GPT-5.5 leaves on Oct 14

At DevDay on Sep 29 came GPT-6.1 Sol, per slide "Near-Astra level intelligence at a fifth of the price".[1] It costs $2/$10 per million tokens, GPT-6 Astra $10/$50. Cached input tokens cost $0.10 instead of $1.00.[1] In Codex it is available as gpt-6.1-sol.[2]

For performance data we only have secondary sources, because openai.com blocked the request. One report puts Sol at roughly 75% on DeepSWE v1.1 (reports: 75.2%), on par with Astra (about 74.8%), at 80% lower cost per task.[3] Another aggregator lists 71.9%. Both are vendor claims at second hand. Treat them as a rough direction.

  • Ultrafast mode: up to 300 tokens per second at six times the price.[1]
  • Codex Security: per OpenAI slide, 53 critical findings fixed on day one, 1% rollback rate.[1] Vendor claim.
  • Long tasks: The share of 8- to 16-hour tasks completed without intervention rose, per slide, from 10% in January to 35% in July 2026.[1]
Deadline "On October 14, 2026, GPT-5.5 will retire from ChatGPT, ChatGPT Work, and Codex on all plans."[2] The API is not affected. If you hard-coded GPT-5.5 in Codex configurations or scripts, switch now. Already removed since Sep 5: the command codex mcp-server; the replacement is the Codex App Server.[2]

My view: Sol is OpenAI's direct answer to Sonnet — same price, same role. The slide with 35% long tasks without intervention is the most interesting number of DevDay, but also the hardest to verify. "Without intervention" says nothing about whether the result was good.

Pwn2Own Ireland: Codex falls to a single bug

On day one of Pwn2Own Ireland, on Oct 6, researchers exploited 32 zero-days and earned $388,500.[1] Among the targets was a coding agent: the researchers "took down the OpenAI Codex cloud-based AI coding agent" with "a single argument-injection bug".[1] The report names neither the team nor the prize money for this attack. Vendors now have 90 days for a patch before the Zero Day Initiative publishes details.[1]

Argument injection: A program assembles a command and inserts a value that an attacker controls — a file name, say. If that value starts with a hyphen, the called tool reads it as an option instead of a name. "Open the file -oProxyCommand=…" then becomes "run this command". Like a form where someone writes "and transfer €1,000" into the "Name" field, and the clerk reads out everything.

The protection is old and simple: put outside values behind a -- so that git, ssh and the like do not read them as options. An agent that assembles shell commands from repo contents, issue text or file names is exactly such a program.

My view: This is the most important security news of the week for you, even if Codex is not your tool. A coding agent with shell access is a tool that turns foreign input into commands — the classic injection pattern. Claude Code, Cursor and Copilot have the same attack surface. That is why the security fixes in every changelog matter, and why an agent belongs in a sandbox when it reads foreign repos.

Glasswing: new program, unclear numbers

On Oct 6 Anthropic expanded the Cyber Verification Program. It makes "advanced cyber capabilities and reduced blocking classifiers available to qualifying security professionals".[1] The Glasswing page points to it as the latest update.[2] Glasswing is the program in which partners use the non-public model Claude Mythos Preview to find vulnerabilities in important software.

Reports from Oct 7 cite a figure of 129,000 vulnerabilities found. We could not match this figure to any Anthropic source: the Glasswing page speaks only of "thousands of high-severity vulnerabilities".[2] The last documented status is Anthropic's May update: "more than ten thousand high- or critical-severity vulnerabilities" with about 50 partners.[3] We therefore do not state the 129,000 as fact.

My view: The number of findings is long past being the bottleneck — Anthropic already wrote in May that the limit is how fast findings can be verified, reported and patched.[3] For you as a maintainer this means: expect more AI-found bug reports, and plan time for triage.

MCP: Claude Code now speaks the new protocol

Claude Code v2.1.292 (Oct 6) "Changed local stdio MCP servers to negotiate protocol version 2026-07-28 by default."[1] If an older server has trouble with it, there is a way out: the environment variable MCP_PROTOCOL_NEGOTIATION=legacy.[1]

According to CData, spec version 2026-07-28 is the largest revision since launch: a stateless core and a framework for extensions, first MCP Apps and Tasks. Some changes are not backward compatible.[2]

Protocol negotiation (MCP): MCP is the shared language an agent uses to talk to external tools — database, browser, ticket system. When connecting, both sides first agree on a language version. Like two people on the phone briefly clarifying whether they speak German or English. Now Claude Code proposes the new version first.

My view: If a self-built MCP server behaves oddly after the update, this is the first suspect. Set the variable only as a stopgap and move the server to the new version — "stateless" makes servers easier to run, not harder.

Google: Gemini 3.8 Flash and a shut-down API

Gemini 3.8 Flash has been generally available since Sep 2, "engineered for long-horizon software engineering" according to Google.[1] On Terminal-Bench 2.1, DataCamp reports 90.8% versus 81.6% for 3.7 Flash — a vendor claim at second hand.[2]

More important for anyone using the Antigravity agent API: version antigravity-preview-09-2026 replaces 05-2026, and the latter "shuts down Oct 5, 2026" — so it has been off since Monday. Tools and parameters have changed.[1] If a script has been throwing errors since Monday, that is why.

Open weights: Mistral Large 4 is coming, with question marks

According to Simon Willison, Mistral showed Large 4 as an API preview on Oct 6: "A 1 trillion parameter model with 49 billion active parameters", trained on 3,800 NVIDIA Grace Blackwell GPUs. The weights are to follow "end of this month". On the Artificial Analysis index it scores 38, Large 3 scores 9.[1] We found no announcement from Mistral itself. License and price are open.

Active parameters (Mixture of Experts): The model consists of many specialists, but for each word only a few of them work. One trillion parameters sit in memory, 49 billion compute. Like a large hospital: all the doctors are in the building, but only two treat you.
  • Qwen3.8-27B (mid-August, Apache 2.0) — the size that fits on a 24 GB GPU. Try it if you work locally with Ollama: a dense 27B model is easier to run than an MoE giant.[2]
  • GLM-5.3-Flash (Aug 26): 320 billion parameters, 18 billion active, MIT license, 1M context.[2]
  • DeepSeek V4.1-Flash: The size is unclear — one source says 763 billion, another 552 billion parameters. We do not commit.[2][3]

My view: An open trillion-parameter model is irrelevant for your machine, but a real alternative for European companies with their own data center. Wait for the weights and the license before you take it seriously.

Bench note: no Verified number for the new generation

For none of the new models — Opus 5.5, Sonnet 5.5, Haiku 5.5, GPT-6.1 Sol — is there a SWE-Bench Verified value. Vendors now report SWE-Bench Pro, DeepSWE and Terminal-Bench 4.0. The official table on swebench.com again returned no values when retrieved. The last Verified value we know is Sonnet 5 at 85.2% from Jun 30 — only secondarily documented.

In LMArena's Code Arena ranking, according to a mirror site (data through September), Claude Opus 5.5 Max leads with 1815; the best open model is Kimi K3 with 1658.[1] This is not a primary source.

My view: That vendors quietly switch from Verified to new tests is meant honestly — Verified is maxed out and probably partly in the training data. But every vendor now picks the test on which it looks good. That is why there is no bar chart today.
