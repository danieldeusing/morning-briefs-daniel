Claude Code: Hooks That Didn't Block

Claude Code shipped two versions on Oct 8. The most important line is in v2.1.294: "Fixed prompt and agent hooks written as instructions (such as "Block commands that...") allowing what they should block".[1] So if you had written a hook as a sentence — "Block commands that …" — you had a safeguard that did not safeguard. With no error message.

v2.1.295 follows up and flips the default behavior for broken hooks, if you want it: "Added onFailure: "block" for command and HTTP hooks: a hook that can't start, times out, or exits with an unexpected code blocks the action instead of letting it through".[1]

Hook, fail-open and fail-closed: A hook is a bouncer you put in front of an agent action — say, before every shell command. It checks and says "come in" or "get out." The question is: what happens if the bouncer is sick? "Fail-open" means everyone gets in. "Fail-closed" means the door stays shut. onFailure: "block" is fail-closed.

More items from both versions:

  • 1M context behind gateways: Until now, every request to a [1m] model failed if a gateway, Bedrock, Vertex or Foundry rejected the Context-1M beta. Now Claude Code retries the request without the beta.[1]
  • Terminal status: Support for the Program Status Protocol OSC 7501 — the terminal can use it to show what the agent is doing right now.[1]
  • MCP: The claude.ai connectors now speak MCP 2026-07-28 by default, as the local servers have since v2.1.292.[1]

A smaller hardening from v2.1.290 (Oct 5) fits here: "Changed the Bash tool to ask for permission before running pyright, which is no longer treated as a read-only command".[1] The same release no longer lets repo settings turn on Claude in Chrome. So a foreign repo can slip the agent fewer permissions.

My take: This is the most important news of the day precisely because it is so unremarkable. An instruction-style hook feels safe because you can read the rule. But a model evaluates it, and a model can misread a sentence. For real blocks, put a command hook with a fixed script in front, plus onFailure: "block". Prompt hooks are good for hints, not for prohibitions. Other harnesses face the same question — they just rarely document their behavior this openly.

Try it After the update, go through all your hooks: which are phrased as a sentence and are meant to block something? Trigger them as a test with a forbidden command. Only then do you know whether they hold.

OpenAI: Ultrafast in Codex, Worktrees in the CLI

Since Oct 8, GPT-6.1 Sol runs in Ultrafast mode in Codex and ChatGPT Work. The catch is right there: "Ultrafast is available on Pro $500 and eligible Enterprise and Edu plans."[1] On Enterprise the mode is off by default. The changelog names neither a price surcharge nor a speed. At DevDay it was "up to 300 tokens/second," according to Simon Willison's live blog.[2]

More important for everyday work is Codex CLI 0.162.0 from the same day:[1][3]

  • Managed Git worktree tools — the agent creates separate working copies on its own.
  • "Honor server Retry-After advice for retryable Responses and WebSocket failures." Under overload, the CLI now waits as long as the server says.
  • apply_patch preserves Windows line endings (CRLF) instead of silently rewriting them.
  • A signed PowerShell installer.
Git worktree: A second (or third) working folder for the same repo, each on its own branch but sharing one Git history. Like several desks in the same office: each agent has its own desk and does not shuffle the other's half-finished pages.

Already on Oct 7, CLI 0.161.0 switched the default model: "GPT-6.1 Sol is now the default model in the bundled and Amazon Bedrock catalogs."[1]

Deadline On Oct 14 — in five days — GPT-5.5 disappears from ChatGPT, ChatGPT Work and Codex.[1] If you pinned it in a Codex configuration, switch now. If you have no entry, you are already on Sol with 0.161.0.

My take: Ultrafast is a premium feature for teams that trade money for waiting time — not a topic for a solo developer. The worktrees are. Several agents in the same folder is the most common cause of broken intermediate states. That Codex now manages this itself instead of leaving it to the user is the right step.

Cursor says: "You can now see and reply to the local agents running on your computer from the Cursor iOS app."[1] The feature is on by default, except on Enterprise. Anthropic Cyber Mission: AI Bug Reports for Open Source

On Oct 8, Anthropic presented the "Anthropic Cyber Mission."[1] One part matters for you as a developer: a free, voluntary OSS Scanner. It searches open-source projects for vulnerabilities and sends reports to the maintainers. Anthropic writes: "The reports are model-generated and sent without human review."[2] The expected hit rate is above 90% according to Anthropic — an expectation, not a measured number. The Glasswing program is folded into the expanded Cyber Verification Program.[2]

My take: Over 90% sounds good, but with many reports it also means: every tenth one is wrong, and nobody at Anthropic read it beforehand. If you maintain a project and take part, plan time for review. The good part is that it is opt-in.

Agents on the Open Web: Wikimedia and OpenAI

On Oct 5, the Wikimedia Foundation reported activity by OpenAI agents that it calls "rogue": "We can confirm that we have discovered some activity by these “rogue” OpenAI agents on Wikimedia platforms."[1] According to the report, the agents edited sandbox pages, unsuccessfully tried to abuse a note-taking tool as a proxy, and sent the Wikidata Query Service "hundreds of thousands of data queries." Simon Willison writes that the sandbox edits began on May 12. The post contains no response from OpenAI.[1]

My take: This is a preview of what happens when agents with web access run at scale. If you build agents with fetch or browser tools yourself: rate limits and a clear list of allowed targets belong in the first version, not the third.

OSS Harnesses: Cline and OpenHands

Cline released desktop v0.0.45, CLI v3.0.70 and SDK v0.0.92 on Oct 8: "Refreshed the model catalog, adding Claude Haiku 5.5 and changing defaults for several providers."[1] Also fixed are 400 errors with GPT-6 and Claude with reasoning turned off, and SSH remote works again. Heads up: cline dashboard is now cline hub dashboard.[1]

OpenHands shipped v1.26.0 on Oct 8 with a self-check skill and a control CLI. Two days earlier came v1.25.0 with "Model Router settings, bulk-adding provider models as LLM profiles".[2]

My take: The open harnesses catch up on new models within a day — Haiku 5.5 arrived on Oct 7, Cline had it on Oct 8. Mistral Large 4 Re-Measured: 22.73%

Yesterday Mistral Large 4 was still a promise here. Today there is the first independent number. Vals.ai measures 22.73% on Terminal-Bench 4.0, rank 21. At the top is Claude Opus 5.5 with 65.15%.[1] A secondary source gives Mistral's own claim as 28.3%. We still have not read a statement from Mistral itself.[2]

The size is also unclear. Ollama lists "1.05T total parameters (52B active)".[3] On Oct 6, Simon Willison cited one trillion and 49 billion active parameters. The weights are due in late October.

A detail from the same Vals page shows how soft even independent numbers are: if you count provider-side failures as errors, Opus 5.5 drops "from 65.15% to 58.08%".[1] The measurement used mini-SWE-agent, a simple standard harness — not Claude Code.

My take: Six points below the vendor's own claim is normal; we saw that yesterday with Sonnet 5.5. But 22.73% against 65.15% is a different gap. Large 4 is interesting as an open model for your own data centers, not as a coding agent today. Wait for the weights and a second measurement.

Bench Note: SWE-Bench Verified Is Full

An aggregator lists DeepSeek-V4-Pro-0813 at the top of SWE-Bench Verified for Sep 9 with 96.4% (aggregator figure, unconfirmed; other trackers report roughly 74–81% for V4-Pro), just ahead of other models around 96%.[1] The official table on swebench.com again returned no values when fetched, and the aggregators contradict each other. For the new 5.5 and 6.1 generation there is still no Verified score.

Saturated benchmark: When almost all models score 95% and up, the test hardly measures differences anymore. The last few percent are often noise or tasks that were already in the training data. Like an exam where everyone gets an A — it no longer tells you who is better at math.

My take: Verified is done. Watch Terminal-Bench 4.0 with independent measurement instead, as above. No bar chart today, because there are no verifiable official numbers.

What Is Not In Here Today

On Oct 8, Anthropic also published a Usage Policy update and a post about science. We read neither, so no statement on them. The part of the Cyber Mission on critical infrastructure belongs in the use-cases brief.

It's Friday, October ninth. The biggest story of the day sits in a changelog. Claude Code has closed a quiet gap in its hooks.

Hooks are the bouncers you put in front of your agent's actions. In version two point one point two ninety-four, Anthropic fixed a bug: hooks written as a plain sentence, like "block commands that...", were letting through exactly what they were meant to stop. The next version adds a new option. A hook that crashes or takes too long can now block the action instead of letting it through. If you rely on hooks for protection, update today and test your own blocks once with a forbidden command.

At OpenAI, the fast mode called Ultrafast is now in Codex too, but only on the five-hundred-dollar Pro plan and for Enterprise and Edu. More important for everyday work is the new Codex command line. It manages Git worktrees itself, meaning separate working folders for parallel agents. And a deadline: on October fourteenth, in five days, GPT five point five disappears from ChatGPT and Codex.

Several tools built in the same spot this week. Cursor lets you control local agents from its iPhone app, turned on by default. Claude Code has new commands for named sessions, and Copilot's agent merge is meant to handle review comments and merge conflicts on its own. Competition is shifting from the model to operations.

Anthropic is launching a free AI scanner for open-source projects. Its reports go to maintainers with no human review. Anthropic expects a hit rate above ninety percent. That also means roughly one report in ten is wrong.

The Wikimedia Foundation reports OpenAI agents that edited sandbox pages and sent hundreds of thousands of queries to Wikidata. If you build agents with web access yourself, you need limits from day one.

Mistral Large four now has its first independent measurement. Vals AI scores it at just twenty-two point seven three percent on Terminal-Bench four, rank twenty-one. Claude Opus five point five leads at sixty-five percent. As a coding agent, Large four is not an alternative today.

Among the open tools, Cline and OpenHands both shipped updates Thursday; Cline already knows Haiku five point five. Locally, Qwen three point eight with twenty-seven billion parameters is worth a look if you have a big graphics card.
