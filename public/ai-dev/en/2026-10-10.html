Week in review: prices fall, the top tier stays expensive — Opus 5.5 leads, Sol and Sonnet follow cheaply

Saturday, time for the big picture. This week Anthropic and OpenAI finished building their price ladders: Haiku 5.5 at 10 cents, GPT-6.1 Sol and Sonnet 5.5 at $2/$10 per million tokens. Thursday's new Code Arena leaderboard shows what you get for the money. The expensive Opus 5.5 is still on top, but the cheaper models sit close behind. My thesis for the week: for most agent work, "cheap" is now good enough. The money for the top model only pays off on the really hard steps.

The price ladder after this week

With Haiku 5.5 on Oct 7, the Anthropic lineup is complete. According to the docs, all four models have 1M context and up to 128K output.[1] With GPT-6.1 Sol on Sep 29, OpenAI placed a model right at Sonnet's level.[2]

Prices: Anthropic docs and OpenAI changelog, retrieved Oct 10.[1][2] Arena values: as of Oct 8, each model's strongest listed setting.[3]

Fable 5.1 stands out. It is the most expensive model in the table, yet it ranks behind Opus 5.5 and Sonnet 5.5 on this leaderboard. The WebDev Arena only measures one task, though: building web interfaces that people then rate. It says little about long agent runs.

At DevDay, OpenAI claims an even bigger gap in cost per task. According to a secondary source, a task costs $5.47 on average with Sol, $23.21 with Opus 5.5 and $23.80 with GPT-6 Astra.[4] These are OpenAI figures on an OpenAI benchmark. I believe the direction, not the magnitude, without checking.

Price per million tokens (MTok): A token is a word fragment, roughly three quarters of an English word. Providers bill separately for what you send in (input) and what the model writes (output). Like a taxi: a base fare for the route you bring along, and a higher price for every kilometer the driver drives on their own. For agents, input is usually the bigger item, because the whole context rides along at every step.

My take: Haiku 5.5 costs one twentieth of Sonnet 5.5. Sonnet and Sol cost half as much as Opus and sit only 39 and 58 points behind in the arena. For a solo developer that means: Sonnet or Sol as the default, Haiku for subagents doing grunt work (finding files, reading logs), Opus only for planning and hard bugs. After this week, Fable 5.1 is hardly worth it for coding anymore.

Claude Code 2.1.296: subagents compact themselves

On Friday, Oct 9, v2.1.296 arrived, the next release after 2.1.295 the day before.[1] The hook fixes from 2.1.294/295 were covered here yesterday. What's new, mainly:

  • autoCompactWindow in subagent frontmatter: Every subagent can now get its own threshold for automatic compaction.[1]
  • CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL: an environment variable that sets the model for workflow subagents.[1]
  • MCP: The default limit on MCP tool descriptions and MCP server instructions rose from 2,048 to 4,096 characters.[1]
  • Read with allow_large for big files, and a fix for Bash permissions around BASH_ARGV0.[1]
  • /cost: now counts cache reads for Sonnet 5.5 at $0.10 per million tokens instead of $0.20.[1]
Auto-compact: When an agent's context window is almost full, Claude Code summarizes the history so far and carries on with the summary. Like a notepad: when the page is full, you write the three most important points at the top of a new page and tear off the old one. With autoCompactWindow you decide how full the page may get before that happens.

On the /cost entry: the changelog does not say whether Anthropic cut the price or whether Claude Code had been calculating wrongly before. I read it as a correction to the display. It does not prove that your bill is cut in half.

My take: the doubled MCP limit cuts both ways. Servers can now describe their tools better. But every description lands in every context, and ten servers with long texts eat up space before you have written a single line of code.

Try it Give a subagent for long research runs its own autoCompactWindow. That way it does not break off mid-task and does not compact too early.

Arena score (Elo): Two models get the same task, and a person picks the better result without knowing which model produced it. Many such duels add up to a rating, as in chess. Like a sports league table: the gap matters more than the rank. 30 points are a lead, but not a difference in class.

Three things before you draw conclusions:

  • Uncertainty: The site shows confidence intervals for the values, around ±15 points. Places 2 and 3 are only 12 points apart. That is within the measurement error.
  • The setting matters: "max", "xhigh" and "high" are thinking levels. Sonnet 5.5 loses almost 60 points going from xhigh to high. But more thinking also means more tokens and more money.
  • Taste: What gets rated is what people like better. For web interfaces that makes sense, for a backend refactoring it does not.

My take: the leaderboard confirms the generational leap. The old Opus 5 sits 122 points behind Opus 5.5. It does not confirm a clear winner between Anthropic and OpenAI. No bar chart today: the values all fall between 1,688 and 1,813, and a bar starting at zero would hide the differences.

OpenAI: Ultrafast for all API customers

Yesterday was about Ultrafast in Codex, only for expensive subscriptions. Since Oct 8 the mode is available in the API too: Use service_tier: "ultrafast" with gpt-6.1-sol to cut the time between generated output tokens.[1] For DevDay, OpenAI cited "up to 8x faster" and about 300 tokens per second in Codex. That is a vendor claim at second hand.[2] The API changelog names no price for the mode.

Other API changes this week:[1]

  • Decisions API (beta, Oct 6) with gpt-6-luna: turns text and images into typed answers.
  • Three usage tiers instead of five (Build, Launch, Grow), also Oct 6.
  • Computer Use in the Agents API since DevDay on Sep 29.
Typed answers: Instead of running text, the model returns an answer in a fixed format, such as "yes/no" or an object with fixed fields. Like a form instead of a letter: your code can process the answer directly, without fishing it out of a sentence.

Codex CLI: 0.162.1 from Oct 9 is the current stable version, and 0.163.0-alpha.5 arrived today as a pre-release.[3] And the deadline stands: GPT-5.5 disappears from ChatGPT, ChatGPT Work and Codex on Oct 14. It stays in the API.[4]

My take: Ultrafast in the API is interesting for tools that generate a lot of text while a person waits, such as code review in the editor. For an agent that works alone for 20 minutes, the price per task matters more than speed. The Decisions API is more a topic for the applications brief, but useful for classifiers in CI pipelines.

Haiku 5.5: one number, but the wrong one

On Thursday we reported here that Haiku 5.5 arrived without a single benchmark number. Now there is one: OSWorld 2.1 offline, "72.4% for Haiku 5.5 versus 15.7% for Haiku 4.5".[1]

OSWorld: A test in which the model operates a real desktop: opening windows, clicking, typing, saving files. Like a driving test for an intern on an unfamiliar computer. It measures computer operation, not writing code.

Three caveats: the number comes from the vendor. We found it only in a secondary source, because the Anthropic announcement page returned a 404 error when fetched. And there is still no SWE-Bench value for Haiku 5.5. For coding, the model remains unmeasured.

Useful for configurations: the model ID is claude-haiku-5-5. According to the docs, retirement is "Not sooner than October 7, 2027".[2] So you can pin the version for a year.

My take: a jump from 15.7 to 72.4% is so big that I want to see an independent measurement first. For subagents with simple tasks I would still test Haiku 5.5 now. At $0.10 per million input tokens, a failed attempt costs almost nothing.

Google: Gemini Flash reroutes silently

On Oct 8, Google deprecated two Flash models: "Gemini 3.7 Flash and Gemini 3.5 Flash are deprecated and now route to Gemini 3.8 Flash and 3.6 Flash, respectively."[1] In addition, the preview agent deep-research-pro-preview-12-2025 ends on Oct 23; Google points to deep-research-preview-04-2026.[1]

Routing to a new model: Your code keeps calling "3.7 Flash", but Google answers the request with 3.8 Flash. Like a mail forwarding order at the post office: the letter arrives, but someone else reads it. No error, no warning in your code, just different answers.

For Gemini 2.5, a shutdown date of Oct 16 is circulating online. But on Sep 18 the official changelog says only that access is limited to existing users, and explicitly "not deprecated". We therefore treat Oct 16 as a rumor.[1]

My take: silent rerouting is convenient, but dangerous for coding pipelines. If you use Gemini Flash in tests, code review or for structured outputs, check this week whether the results still hold. A different model can format JSON differently or resolve edge cases differently.

Open weights: DeepSeek remains the benchmark

There was no big new open coding model this week. The reference point remains DeepSeek V4.1-Flash from early September: MIT license, 763B parameters, 1M token context, a score of 40 on the Artificial Analysis Intelligence Index.[1] On Hugging Face it is still the newest DeepSeek model.[2]

For local use it is too big. Ollama updated gemma4, gpt-oss and mistral-large-4 this week. The page shows only relative times such as "3 days ago", no version numbers.[3] Qwen now publishes its news at qwen.ai/research. The old blog at qwenlm.github.io has been silent since September 2025.[4]

My take: the gap between open and closed coding models has narrowed in quality, but not in operation. 763B parameters need a data center. For local use, gemma4 and Qwen in the 27B class remain the practical choice.

Weekend experiment: coding by voice

On Oct 9, Simon Willison built a new newsletter page for his blog. According to his blog, it came about almost entirely by voice, while cooking, with coding agents.[1] No product, no new feature, just a way of working.

Try it This weekend, pick a small, non-critical task and describe it to the agent by voice only. You learn how precise your instructions really are. If you can't type, you have to think more clearly.
