Sunday test: Haiku 5.5 as a subagent model

From the week. Two building blocks fit together. First, Claude Haiku 5.5 from Oct 7: $0.10 per million input tokens, $0.50 per million output tokens, 1M context.[1] For prompts above 100K tokens the price rises to $0.50 / $2.50.[2] Second, the variable CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL from Claude Code 2.1.296 of Oct 9. According to the changelog it runs "every workflow agent on one model".[2]

Subagent: A helper agent to which the main agent hands a sub-task, such as "search the repo for all calls to this function". Like a site foreman who sends an apprentice to fetch material. The apprentice does not need to be able to do everything, only to be fast and cheap. A small model is made for exactly that.

On the size ratio: Sonnet 5.5 costs $2 / $10, Opus 5.5 $4 / $20.[1] So Haiku 5.5 is 20 times cheaper than Sonnet. For coding, though, Haiku 5.5 still has no independent benchmark value. The only known figure measures computer use and comes from the vendor.

Try it Set the variable to claude-haiku-5-5 for a workflow of pure grunt work (finding files, summarizing logs). Compare the result with the same run on Sonnet. If Haiku keeps up there, you save on the biggest cost block. If not, you lost a few cents.

One caveat: the variable applies to all workflow agents. A workflow with a planning step then runs on Haiku there too. So the variable does not suit mixed workflows.

Claude Code becomes a platform

From the week, reframed. Individually the releases were small. Together, four versions in ten days show a clear direction:

  • 2.1.287 (Oct 1): "Claude Mods" let plugins reach deeper into behavior. An optional agent "You Should Know" comes with it.[1]
  • 2.1.292 (Oct 6): Install plugins straight from marketplaces and control how hard subagents work.[1]
  • 2.1.295 (Oct 8): onFailure: "block" for command and HTTP hooks.[2]
  • 2.1.296 (Oct 9): MCP tool descriptions and server instructions may now be 4,096 instead of 2,048 characters long. Edit and NotebookEdit now refuse changes to files that are not UTF-8 instead of corrupting them.[2]
Hook with "onFailure: block": A hook is a custom script that Claude Code runs before or after an action, such as a linter before saving. Until now a crashed hook could simply be skipped. With "block" the rule is: if the check itself is broken, nothing moves on. Like a smoke detector that locks the door when its battery is empty, instead of quietly giving up.

The details on 2.1.287 and 2.1.292 come from a release aggregator, not directly from the GitHub changelog. We treat them as a secondary source.

My view: Claude Code is no longer a pure CLI tool but a runtime for third-party extensions. That is powerful, but every plugin from a marketplace is a stranger's code in your terminal. Cursor goes in the same direction with Projects and Rollouts, but centrally in the cloud. The UTF-8 fix is the least conspicuous item and the most important one for old codebases with Windows-1252 or Shift-JIS.

Try it If you have a mandatory check as a hook (tests, secret scanner), switch it to onFailure: "block". A security check that fails silently is worse than none.

Local: mistral-large-4 on Ollama

Ollama lists mistral-large-4, according to the library an open multimodal model with "52B active of 1.05T total parameters".[1] The page shows only "about 4 days ago", no exact date.

Mixture of Experts (MoE): The model consists of many specialists. Per word, only a few of them work, here 52 billion parameters. Like a clinic with a hundred specialists of whom only two examine you. That makes every answer faster. But all hundred still need an office, and here that is the memory for 1.05 trillion parameters.

My view: this is nothing for your own machine, not even heavily compressed. For local use, gemma4 and Qwen in the 27B class remain the practical choice.
