Gemini 4 Argon: Generally Available, but No Clear Winner

Since Oct 13, the Gemini API changelog reads: "Gemini 4 Argon (gemini-4-argon) generally available (GA)."[1] Google had announced the model back on Sep 30. According to the trade press, though, the first users were not paying customers but "trusted cyber defenders inside its Fairwind Program."[2] Now anyone with an API key can call it.

Price: Simon Willison lists $2 input and $10 output per million tokens. That matches GPT-6.1 Sol and is half of Opus 5.5. He also writes: "on December 1st Argon is set to double in price."[3] Other sources describe an introductory price, after which $4 / $20 applies, with no fixed end date.[4] Google's changelog page shows no price. So plan on $4 / $20 if you are building something lasting today.

GA (General Availability): A model usually passes through three stages. First a few invited users test it, then there is a "preview" that may still change. With GA, the vendor says: this is stable, you can build products on it. Like a restaurant after its soft opening.

Performance: Google's own numbers are mixed. We know them only from an Android Headlines article, not from Google itself. According to the article, Google computed 10 of the 19 values itself.[2]

Benchmark (vendor claim)ArgonComparison

The only independent number we retrieved ourselves is the Intelligence Index from Artificial Analysis: Argon (High) sits at 53, Opus 5.5 (max) at 58, Sonnet 5.5 at 56.[5] According to Willison, the Artificial Analysis test run cost $2,407 for Argon.[3] According to Bloomberg, Google employees find that Argon "struggles when put to work on real-world coding tasks and front-end website design." Google disputes this.[2]

Vendor claim: The vendor measures its own model, picks the tests, and often recomputes the competition's values itself. That is not lying, but it is like a restaurant writing its own reviews. Only an outside measurement shows whether the number holds up.

My take: Argon is not an Opus killer. The interesting part is the pattern in Google's own table. On short coding tasks (DeepSWE) Argon leads; on long terminal tasks it trails Opus 5.5 by nine points. That fits the Bloomberg report exactly. For an agent working alone in the terminal for an hour, I would still pick Opus or GPT-6. For lots of small code questions at half the price, Argon is worth a test while the introductory price lasts.

Try it Willison's llm-gemini plugin already supports Argon.[3] Give Argon and your default model the same real task from your repo and compare result and cost.

Anthropic Replaces Git: What Happens When Agents Commit

The most interesting text of the day is an engineering post from Anthropic dated Oct 13: "In May 2026, Anthropic averaged around 2,500 code changes merged per day; as of September, we merged over 30,000 per day."[1] That is twelve times as many in four months. Git could not take it anymore. So Anthropic built its own version control system called Scion and migrated in five months.[1]

The scale: "The history of our main branch alone is almost 100 GB, and a compressed working copy is over 25 GB."[2] According to Anthropic, CI checks out code about 25 million times a day. With a normal git fetch, that would be over 600 PB of traffic per day, according to the post.[1][2] Willison suspects that agents at Fable or Mythos level are behind the jump. That is his guess; Anthropic does not say so.[2]

Agents write more code→12× more merges→CI checks out constantly→Git no longer scales
Why Git breaks here: Git is built so that everyone has a complete copy of the whole history. For a team of humans, that is great. But when millions of CI runs a day each fetch a huge repo, it is like a library that ships every visitor all its books just so they can read one page.

My take: For your daily work, Scion changes nothing; it is an internal tool. But the post is a glimpse of the future. When agents make most of the commits, the bottleneck shifts from "writing code" to "merging, testing, and reviewing code." Even small teams feel this: more PRs, more CI minutes, more merge conflicts. If you run agents in parallel today, look first at your CI costs and your review capacity.

Claude Code 2.1.299: Idle Compaction and One Sandbox Hole Fewer

2.1.299 shipped today.[1] Two points matter:

  • Idle compaction: "a 200K+ token conversation left idle for about 54 minutes is compacted before its one-hour prompt cache expires."[1] You can set the threshold via CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS.
  • Sandbox fix: "Fixed a sandboxed shell command being able to write into a --plugin-dir folder, whose code Claude Code reloads and runs outside the sandbox."[1]

Also: warnings in /usage, a new variable CLAUDE_CODE_DISABLE_FILE_MENTIONS, and a longer stream timeout (300 instead of 180 seconds) for custom ANTHROPIC_BASE_URL setups.[1] According to the tracker, this is the eleventh release in October. Versions 2.1.297 and 2.1.298 appear neither there nor on GitHub.[2]

Sandbox escape: The sandbox is a cage in which the agent's commands run. The bug: a command inside the cage could place files in the plugin folder. Claude Code later reloads that folder and runs it outside the cage. So the cage had a hatch through which code could be pushed outside.

My take: Idle compaction is clever. A full context that drops out of the cache after an hour costs full price on the next prompt. Better to summarize beforehand. The catch: after your lunch break you work with a summary instead of the full history. The sandbox fix is the more important part. If you work with --plugin-dir, update today.

Try it Update to 2.1.299. If you do not want to lose long sessions, raise CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS and check whether the behavior suits you.

Agent Practice: Two Patterns from Willison and Huntley

On Oct 13 Willison released web-edit 0.1a1. Opus 5.5 wrote the optimizations, based on a profiling report produced by GPT-6 Astra.[1] Two models, two roles: one measures, one builds. The new sampling profiler in Python 3.15, released on Oct 12, fits in here.[1]

Geoffrey Huntley describes a trick with pre-commit hooks. If the agent breaks a rule, the commit fails, and the hook hands it an instruction: "Boom: fail the commit, inject a prompt telling the agent to use the diagnostics library."[2]

My take: Huntley's idea is the counterpart to the blocking hooks in Claude Code 2.1.295 from yesterday. Rules in a CLAUDE.md are requests. A hook that stops the commit and states the reason is a guardrail. It works with any agent because Git hooks are tool-neutral.

Try it Take the rule your agent breaks most often. Build a pre-commit hook that checks exactly that and prints a clear error message.

Cursor Origin: An App Marketplace for the Agent

On Oct 13 Cursor launched an app marketplace for Origin: "Origin now integrates with over 20 apps for deployments, CI, code review, security, monitoring, and project management."[1] Among them are Cloudflare, Linear, Sentry, Socket Security, Vercel, and CodeRabbit. Anyone can submit their own apps.[1]

Marketplace for agent integrations: An agent can only do what it has tools for. A marketplace is like an app store for those tools: instead of building every connection yourself, you click "Sentry" and the agent can read error reports. Technically it resembles MCP servers, just curated by the tool vendor.

My take: Claude Code has had plugin installation from marketplaces since 2.1.292 (Oct 6), and now Cursor follows.[2] All the big harnesses end up at the same model. The difference will lie less in the agent than in the question of who vets the integrations. "Open for submissions" also means: every app gets access to your code. Having Socket Security on the list is almost ironic here.

Local and Isolated: Ollama with Fly.io

Ollama writes on Oct 13: "AI agents can now use Ollama's cloud models safely inside Fly.io's cloud computers."[1] So the agent runs in a throwaway machine at Fly.io and uses Ollama's cloud models there.

On Hugging Face today, a coder variant of Qwen3.8-27B sits at rank 13 in trending, a community upload. No big new open coding model is in the top 10.[2] According to Willison, Mistral Large 4 is due to get open weights by the end of October.[3]

My take: The Ollama offering is not a local LLM in the strict sense; the models run in Ollama's cloud. The value lies in the sandbox: an agent that may run commands is better off on someone else's machine than on your laptop.
