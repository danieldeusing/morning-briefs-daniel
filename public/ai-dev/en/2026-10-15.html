Gemini 4 Argon arrives in Copilot

Yesterday was about the Gemini API, today is about distribution. According to GitHub, Argon has been "now generally available in GitHub Copilot" since Oct 13.[1] It is enabled for "Copilot Pro+, Max, Business, and Enterprise". The catch is in the same text: "Rollout will be gradual."[1] So if you don't see Argon in your model menu today, you did nothing wrong.

In the Gemini API the model is called gemini-4-argon. Google calls it "our most capable model built for complex coding, agentic, math, and science tasks".[2]

Price, still from a single source: Simon Willison puts it at $2 input and $10 output per million tokens at launch. And: "on December 1st Argon is set to double in price - so it will be the same price as Opus 5.5."[3] Google's changelog lists no price. Other pricing trackers describe an intro rate that later goes to $4/$20 with no stated date, so the Dec 1 date comes only from Willison. Until Google confirms it itself, my advice from yesterday stands: plan for the doubled price if you are building something long-lived.

Model in Copilot vs. in the API: In the API you pay per token, directly to Google. In Copilot you pay your Copilot subscription, and GitHub counts the usage against your quota. For you that means: in Copilot you can try Argon without setting up a Google account or key. Whether the December price changes anything there, GitHub does not say.

Performance: Nothing has changed since yesterday. Google's own numbers, read only through secondary sources: DeepSWE v1.1 77.9% against 74.2% for Opus 5.5, but Terminal-Bench 4.0 57.4% against 66.4%.[4] The only independent figure is the Artificial Analysis Intelligence Index: Argon (high) 53, Opus 5.5 (max) 58.[5] Per task, the AA run cost $1.99 for Argon and $5.98 for Opus 5.5.[5]

My take: Copilot is the channel that really matters for Argon. That is where the developers sit who would never create a Gemini key. Anyone with Copilot Pro+ now gets a free A/B test: the same task once with Argon, once with your default model. For long agent runs in the terminal I stay skeptical; the nine-point Terminal-Bench gap is Google's own number.

Try it If Argon shows up in your Copilot menu: take one real bug-fix task from your repo, run two models, and compare the result and the number of correction rounds.

GitHub blocks Anthropic keys on push

Since Oct 13, GitHub's Secret Scanning detects two new types: anthropic_service_api_key and anthropic_user_api_key. According to GitHub, both are "blocked with push protection by default".[1] This applies to all repos with Secret Scanning enabled, "including free public repositories".[1]

Push Protection: GitHub looks at your commit before it lands on the server. If it contains something that looks like an API key, GitHub rejects the push. It is like a bouncer who won't let you into a public photo with your house key in your hand.

My take: this is not a side issue. Agents write a lot of commits today, and they like to create .env files, test scripts or debug logs. A Claude key in such a file can cost real money in the worst case. The block helps but does not replace a .gitignore. Heads up for agent runs: if the push is rejected, the agent must not try to get around the block. Make that a rule in your hooks or instructions.

Try it Check whether Secret Scanning is active in your private repos. For public repos, GitHub says it is included anyway.

Claude Code 2.1.300: advisor on AWS, better cost telemetry

Two versions arrived on Oct 14. We wrote about 2.1.299 yesterday: idle compaction for conversations of 200K tokens or more after about 54 minutes of idleness.[1] Then came 2.1.300:[1]

  • /advisor on Claude Platform on AWS: "no advisor runs until you pick one with /advisor, advisorModel or --advisor".
  • OpenTelemetry: new fields for tokens incurred when the prompt cache is created.
  • Exit: "Changed exit to force-kill background commands still running 1.5 seconds after being asked to stop".
Cache creation tokens: When Claude sees a long context for the first time, it creates a cache. That costs a bit more once, and every later call gets cheaper. If you only measure "total tokens", you can't see where the money goes. The new fields make this item visible.

My take: for most people this is an unspectacular release. But anyone monitoring Claude Code in a team with OTel finally gets the number that goes with the idle compaction from 2.1.299: how much does it cost to rebuild the cache? The force-kill after 1.5 seconds is good against hanging dev servers, but it can cut off a job that is still cleaning up on exit.

Claude Code 2.1.293 (Oct 7) added Haiku 5.5, now the default Haiku model, with 1M context ($0.10/$0.50 per Mtok).[1]

Try it If you use OTel export: add a dashboard panel for cache creation tokens and watch it for a week.

Copilot HydraFusion Max: the model picks the model

GitHub expanded HydraFusion on Oct 14. The idea: "HydraFusion orchestrates multiple models to produce a single response."[1] You no longer choose a model per task. The new Max variant is, according to GitHub, "tuned for frontier capability on more demanding tasks" and uses more reasoning where it counts.[1] Both run in VS Code, in the Copilot app and in the Copilot CLI, for Pro, Pro+, Business and Enterprise. Requirement: preview features are enabled. Both "remain in research preview".[1]

Model orchestration: Instead of one model, a small team works. A conductor hands out subtasks to different models and assembles the answers. Good for quality, bad for predictability: you don't know exactly who did what.

My take: this is a counter-trend to the model menu. Copilot takes the choice away from you, while Claude Code and Codex give you more dials. The post does not say what HydraFusion Max costs. With "research preview" and unclear billing, I would use it only for individual hard tasks, not as a default.

Harness round: Cline and OpenHands move

Cline 4.1.24 (Oct 13) changes the default: "With no model chosen, the Cline and OpenRouter providers now use Claude Sonnet 5.5."[1] Haiku 5.5 and three new providers come with it. Cline Desktop 0.0.46 was released in parallel.[1]

OpenHands 1.27.0 and 1.27.1 (Oct 12) bring "OpenCode and Pi as built-in ACP agents on local backends".[2]

ACP (Agent Client Protocol): MCP connects an agent to tools. ACP connects an interface to an agent. That makes OpenHands a shell in which third-party agents like OpenCode also run. Like a TV to which you can connect different receivers.

Codex CLI sits stable at 0.162.1 from Oct 9, a TUI crash fix. The 0.163.0 alphas came on Oct 13 and 14, up to alpha.11.[3] Cursor had the Origin Marketplace with more than 20 apps on Oct 13, and remote control of local agents from the iOS app on Oct 6.[4]

My take: Cline's switch to Sonnet 5.5 as default shows where the market is heading. The open-source harnesses bet not on the cheapest model but on the solid mid-range one. OpenHands takes a different path and becomes a platform for other agents. For you as a user, ACP means less lock-in, because you can swap the agent without changing the interface.

Try it If you run OpenHands locally: plug in OpenCode as an ACP agent and compare it with the built-in agent on the same task.

API deadlines: Google cleans up, OpenAI gets faster

Google announced deprecations on Oct 8: gemini-3.7-flash is replaced by 3.8-flash. deep-research-pro-preview-12-2025 "will be shut down on October 23, 2026".[1] If you hard-coded the preview model in a script, you have a good week left.

At OpenAI, since Oct 8 there is an Ultrafast mode for GPT-6.1 Sol in the Responses API, meant to cut the time between output tokens. On Oct 6 a Decisions API arrived in beta with gpt-6-luna, according to OpenAI "10x faster than the Responses API".[2]

My take: at OpenAI, speed is becoming a product of its own. For agents that make many small tool calls, latency per step often matters more than one more point on a benchmark.
