Copilot turns security into agent work

On Oct 15, GitHub made two security features generally available. Both move the same work from the human to the agent.

Agentic Autofix for code-scanning alerts. According to GitHub, it "remediates alerts by working across your codebase the way a developer would".[1] Copilot reads the relevant files, proposes a fix, reruns CodeQL and then opens a draft PR. You can select up to 25 alerts, and Copilot fixes them in one PR. This only applies to alerts on the default branch. It's available to customers with Code Security or Advanced Security on GitHub Enterprise Cloud. Billing goes through AI Credits from the Code Security budget plus Actions minutes. GitHub doesn't name concrete prices.[1]

AI Scan for pull requests. The tool looks for vulnerabilities in PR changes, mainly in languages and frameworks CodeQL doesn't cover yet. It runs on public repos of organizations and individuals. Private repos need Code Security or Advanced Security, but not a Copilot license. Important: the findings "do not fail the code scanning check and cannot block pull request merges".[2] The scan doesn't run on PRs from forks or from Dependabot.

CodeQL as the checker: CodeQL is GitHub's rule-based code scanner. It doesn't guess, it looks for fixed patterns. With Autofix, the language model writes the fix, and CodeQL then checks whether the alert is really gone. It's like an apprentice who repairs and a master who then measures with a gauge.

My take: Autofix has the right pattern. A model proposes, a deterministic tool checks, a human merges. That's how agent workflows should look in general. I'm more cautious about the AI Scan. An AI finding that blocks nothing is a hint, not a gate. That's honest of GitHub, but it also means it's a second opinion, not a replacement for tests. The open question is the price. "AI Credits" without a number turns any budget planning into guesswork.

Try it Turn on the AI Scan on a public repo with active code scanning and count for a week how many findings are real.

Copilot cleans house: three models go on Nov 16

On Nov 16, 2026, GitHub removes three models "across all GitHub Copilot experiences":[1]

  • Claude Opus 4.8 → replacement: Claude Opus 5.5
  • Claude Opus 5 → replacement: Claude Opus 5.5
  • GPT-5.6 Terra → replacement: GPT-6.1 Sol or GPT-6 Luna

There is one exception: Opus 4.8 stays for individual subscribers on an annual plan. For Copilot Business and Enterprise, GitHub enables the replacement models automatically.[1]

My take: One month of lead time is tight, but fair. Mainly affected are scripts and team configurations that hard-code a model. If you get good results with Opus 5 in agent mode, compare with Opus 5.5 now, not on Nov 15. The test is worthwhile even without the deprecation: on Terminal-Bench 4.0, Anthropic cites 66.4% for Opus 5.5 versus 52.3% for Opus 5. That is, however, a vendor number.[2]

Scion: Anthropic builds its own Git

On Oct 13, Anthropic described why it replaced Git for its monorepo. The numbers are the real point. In May, Anthropic was at "around 2,500 code changes merged per day". In September it was "over 30,000 per day".[1] The history of the main branch is "almost 100 GB". For CI, about 25 million checkouts run per day, not counting agent sandboxes.[1]

Git assumes every client works offline and has a full copy. Anthropic's clients, though, are mostly agents and jobs that are always online. Scion is therefore server-centric. A team of seven people built it and finished the migration in five months. Anthropic doesn't plan to release Scion: it diverges too far from Git and depends on internal tooling. Instead, Anthropic shares the design so others can apply the ideas to Git.[1]

Monorepo and merge rate: A monorepo is a single repository for an entire company's code. Every change that lands on the main branch is a merge. Twelve times more merges in four months is like a country road that suddenly carries highway traffic. At some point the problem is no longer the car but the road.

My take: This isn't a tool for you, but it's a glimpse of the future. When agents write the code, the bottleneck shifts from code to versioning, CI and review. You already feel this on a small scale: many worktrees, many parallel branches, long CI queues. The numbers are Anthropic's own and not independently verified. I still find the direction credible.

Claude Code 2.1.301: Grep no longer lies

Version 2.1.301 arrived on Oct 15 with a long list of fixes.[1] The most important ones for everyday use:

  • Grep and Glob: Until now they reported "no matches" when the search program crashed beforehand. Now you get an error saying the search failed.
  • Retry watchdog: New is CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS. In unattended retry mode, Claude Code aborts a request if the usage limit resets too late. Before, it waited.
  • Worktrees: On exit, a worktree from a WorktreeCreate hook was deleted without asking, even with unpushed commits. That's fixed.
  • Model switching: Switching to a model with a smaller context could burn credits on a summary without asking. Also fixed.
  • OpenTelemetry: tool_decision events now carry classifier_verdict and permission_mode. So you can see whether the auto-mode classifier or a rule made the decision.
False "nothing found": An agent trusts its tools. If the search reports "no matches", it concludes: this function doesn't exist. Then it rewrites it, and you have duplicate code. An honest error is much better than an empty answer.

My take: The Grep fix is the most important entry, even if it looks small. Silent false negatives are the most expensive kind of bug with agents, because nobody notices them. The retry watchdog matters to anyone who runs Claude Code via cron or in CI. A run that waits for hours on a limit otherwise blocks everything behind it.

Also worth adding from the same week: the default limit for MCP tool descriptions rose from 2,048 to 4,096 characters, and hooks now support onFailure: "block".[1]

Try it If you run Claude Code unattended: set the new variable and check that your job aborts cleanly at a limit instead of hanging.

The "± 3": That's the uncertainty of the measurement. 74% ± 3 means roughly: somewhere between 71 and 77. Three models at 74% each with such wide ranges are practically equally good. You can read a ranking into it, but it isn't there.

My take: Even if the attributed 77.9% holds, Argon is only slightly above a top group that can't be separated statistically. On top of that comes a Bloomberg report saying Google employees find Argon weaker in real coding than in benchmarks. We only have that secondhand. Until the DeepSWE board catches up: test on your own code. I'm skipping a chart today because the new models are missing from the board.

On price: Argon costs $2 input and $10 output per million tokens in the API at launch. According to Simon Willison, "on December 1st Argon is set to double in price".[2] Google itself doesn't confirm the date.

Haiku 5.5: cheap and now the default Haiku

Claude Haiku 5.5 arrived on Oct 7. Anthropic lists $0.10 input and $0.50 output per million tokens for prompts up to 100,000 tokens, and $0.50/$2.50 above that.[1] The model ID is claude-haiku-5-5. On Terminal-Bench 4.0, Anthropic cites 39.2%, and on FrontierCode 1.1 46.4%. Both are vendor numbers, and Anthropic gives no SWE-Bench value.[1]

Confirmation of yesterday: We wrote that Claude Code 2.1.293 made Haiku 5.5 the default Haiku, with 1M context. That holds: the GitHub release notes for 2.1.293 (Oct 7) call Haiku 5.5 the default Haiku on the Anthropic API with 1M context.[2] Anthropic's launch page does not state the context window.

My take: The price is the story. Haiku 5.5 costs one-twentieth of GPT-6.1 Sol or Argon on input. For sub-agents that read files, summarize logs or write commit messages, it's a clear candidate. For the actual planning in long agent runs, I wouldn't use it after 39.2% on Terminal-Bench.

Try it Switch a sub-agent that runs on Sonnet today to claude-haiku-5-5 for a week and compare cost against rework.

OpenAI: Sol becomes the Codex default

GPT-6.1 Sol arrived on Sep 29, according to OpenAI "for complex coding and professional work at a lower cost than GPT-6 Astra". The price: $2 input and $10 output per million tokens for prompts up to 272K.[1] Since Oct 8 there has been an Ultrafast mode. According to a release tracker, Sol has been the default model since Codex CLI 0.161.0 (Oct 7). Version 0.162.0 brought pinnable tasks and worktrees, and 0.162.1 (Oct 9) a crash fix.[2]

In addition, a Decisions API has been running in beta on gpt-6-luna since Oct 6, according to OpenAI "10x faster than the Responses API".[1]

My take: Sol and Argon cost exactly the same at launch. The price war in the midrange is thus open, and Haiku 5.5 undercuts both by a wide margin. For you, that means the model in the harness is more interchangeable than ever. The real difference lies in the harness itself.

It's Friday, October sixteenth. Yesterday belonged to GitHub, and almost everything was about giving agents more work.

Copilot can now fix code-scanning alerts on its own. The agent reads the code, proposes a fix, has CodeQL check it again, and opens a draft pull request. Up to twenty-five alerts go into a single pull request. On top of that, the AI Scan for pull requests is now generally available. It looks for vulnerabilities even in languages CodeQL doesn't know, but it doesn't block merges. What that costs in AI Credits, GitHub doesn't say.

Important for all Copilot users: on November sixteenth, Claude Opus four point eight, Claude Opus five and GPT five point six Terra go away. The recommended replacements are Opus five point five and GPT six point one Sol, respectively.

Anthropic has explained why it replaced Git with its own system called Scion. In May, the company was at around twenty-five hundred merges a day, and in September at over thirty thousand. Git is built for people who work offline. Agents are always online and produce far more changes. Scion won't be released, but the design offers a look at where the next bottleneck is.

Claude Code is at version two point one point three-oh-one. The most important fix: Grep and Glob now report an error when the search fails, instead of wrongly reporting no matches. Also new is a setting that lets unattended runs abort at a usage limit instead of waiting for hours.

Benchmarks stay thin. For Gemini four Argon, seventy-seven point nine percent on DeepSWE is attributed to Google, with no primary source. The independent board is from September twenty-second, and there the top models are tied at seventy-four percent.

A confirmation of yesterday: per the Claude Code two point one point two nine three release notes on GitHub, Haiku five point five is the default Haiku with a one-million-token context. What is certain is the price: ten cents per million input tokens. That makes it a good candidate for cheap sub-agents.

At OpenAI, GPT six point one Sol is now the default in the Codex CLI and costs exactly the same as Argon at launch. Cursor, Cline and OpenHands had quiet days, and there were no new coding models locally. Tomorrow we'll see whether the DeepSWE board finally lists the new models.
