Claude Code 2.1.302: Forks become the default

Four releases in three days, from 2.1.299 (Oct 14) to 2.1.302 (Oct 16).[1] The most important entry is in the newest version. Fork sub-agents (subagent_type: "fork") are now on by default in claude -p, in the Agent SDK, in the desktop app and in VS Code, "as they already are in the terminal".[1]

Fork sub-agent: A normal sub-agent starts with an empty head. You have to explain everything it should know. A fork is a copy of the running conversation. It already knows everything that has happened so far, and then works on a subtask on its own. It is like a colleague who sat through the whole meeting, instead of a new temp who only gets a note.

What else came:

  • Idle compaction in the terminal (2.1.299): A conversation with more than 200K tokens that rests for about 54 minutes is compacted before the one-hour prompt cache expires. That way your next message does not have to reprocess everything.[1]
  • /advisor on Claude Platform on AWS (2.1.300): No advisor runs until you pick one with /advisor, advisorModel or --advisor. CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1 turns it off.[1]
  • fable alias (2.1.301): If the newest Fable model is not enabled for your organization, Claude Code tries the previous Fable model once instead of failing with an error.[1]
  • Hooks (2.1.302): At most 12 hooks run at the same time for a prompt or agent hook event. CLAUDE_CODE_AUTO_MODE_MODEL is also new.[1]
Prompt cache and compaction: The provider remembers the start of a long conversation for a while. As long as it does, the next request is cheap and fast. After an hour that memory is gone, and all 200K tokens cost full price again. Compaction summarizes the conversation into a short version beforehand. It is like a memo before the file goes into the archive.

My take: Forks in headless mode matter for everyone who runs Claude Code from scripts or cron. Until now the same prompt behaved differently in the terminal than in claude -p. Now it is the same, and that is good. But it also means a fork inherits the full context, and that costs tokens. Anyone running pipelines with many sub-agents should watch their costs over the next few days. I find idle compaction clever, but it is a trade-off. You save money and lose details from the conversation. If you pick up at a delicate spot after lunch, check whether the summary kept what matters.

Try it Run an existing claude -p job with 2.1.302 and compare runtime and token usage with the last run.

Anthropic lets auditors inside

On Oct 15 Anthropic described how external evaluators test its models.[1] The core: six METR staff get access like Anthropic employees. Anthropic "can't veto publication", but may demand redactions in predefined categories. SecureBio reviews the chemistry and biology chapter of the August 2026 Risk Report. Accenture and Faculty are added, and there are first talks with Hugging Face. Access is organized in three tiers.[1]

The same day Simon Willison quoted a Financial Times report: Anthropic's third-quarter revenue is $16.8B, up from $11.5B in the second.[2] We did not read the FT article itself, which is behind a paywall. So the figure is secondhand.

My take: Nothing changes for your daily work. For the question of which provider you trust with code and access, it does. An evaluator who cannot be censored is worth more than one who only has a test account. The catch is the "predefined categories" for redactions. How broad they are decides how much the promise is worth. Read that closely in the first real report.

Cursor: Agents build interfaces

On Oct 16 Cursor released three things together. "Cloud agents can build interactive canvases, the Environments API is in beta, and environments support up to 300 repositories."[1] Three days earlier, on Oct 13, the Origin App Marketplace opened to public submissions. It works with over 20 partner apps.[1]

Environment for cloud agents: A cloud agent does not run on your laptop but on a server. There it needs a ready-made workbench: repos, dependencies, access. An environment is that workbench as a template. With an API you can create it by script instead of clicking it together in the UI.

My take: 300 repos in one environment show where Cursor is headed: large companies with distributed codebases. For a solo developer the Environments API is more interesting than the canvases. If you can describe your agent environment as code, you can also version and reproduce it. It is the same principle as dev containers, just for agents. The canvases are a nice demo until we know what they do in daily use. We did not take exact details from the entries, only the summary on the changelog page.

Codex CLI 0.163.0: Redirect without waiting

Version 0.163.0 arrived on Oct 15.[1] Three changes stand out:

  • Steering during a response: "A follow-up sent during a response steers Codex immediately." You no longer have to wait or cancel to correct course.
  • Parallel read tools: "Independent read-only tools can run in parallel." So reading or searching several files happens at the same time.
  • /config: Settings are searchable, and supported values take effect immediately.

On Oct 16 and 17, three alpha versions of 0.164.0 followed, without release notes.[1]

My take: Redirecting mid-response is the best change of the week among the big-lab harnesses. The biggest annoyance with agents is the moment you see it turning the wrong way and still have to wait. Parallel read tools are purely a speed matter, but one you feel on every run. Both exist in similar form in other harnesses already. Codex is catching up here, not leading.

Try it In a longer Codex run, send a correction mid-response and see whether it really picks it up immediately.

Cline: GPT-6 works again, Sonnet 5.5 is the default

Today, Oct 17, three releases landed at once: SDK v0.0.95, Desktop v0.0.48 and CLI v3.0.73.[1] The most important fix: "GPT-6 models such as gpt-6-sol now work on OpenAI and Azure OpenAI-compatible endpoints, which previously rejected every request." The fix concerns the max_completion_tokens parameter. Also: "With no model chosen, the Cline provider defaults to Claude Sonnet 5.5 again."[1]

My take: A bug where "every request" was rejected is not an edge case. Anyone running Cline through Azure with GPT-6 simply had no working setup until now. It shows the basic problem of multi-provider harnesses: every new model family changes a parameter somewhere, and the tool has to follow. The "again" on the default model suggests it was something else in between. If you use Cline without a fixed model, check briefly what is running.

Benchmarks: still only vendor numbers

The independent DeepSWE board from Datacurve is still from Sept. 22, 2026. Opus 5.5, Sonnet 5.5, Haiku 5.5, Argon and GPT-6.1 Sol are not on it.[1] The top looks unchanged: gpt-6-astra, gemini-3.8-flash and claude-opus-5 are each at 74%, with ± 1 to ± 4. Costs per task range from $2.36 (Flash) to $11.84 (Opus 5).[1]

For the new Claude models there is only Anthropic's own table. For Sonnet 5.5 on Terminal-Bench 4.0, Anthropic reports 70.6%, for Opus 5.5 at Xhigh 66.4%.[2] On FrontierCode 1.1, Anthropic reports 46.2% (Max) and 52.1% (Xhigh) for Sonnet 5.5. The page gives no SWE-Bench value. The price: $2 input and $10 output per million tokens.[2]

Effort levels: Max, Xhigh or High say how long the model may think before it answers. More thinking costs more tokens and usually brings better results. Comparing two numbers from different levels is like comparing two runners when one got to train ten minutes longer.

My take: Sonnet ahead of Opus on Terminal-Bench sounds like a sensation. I read it cautiously. The numbers come from the vendor, the effort levels are not cleanly equal, and an independent measurement is missing. What is certain: Sonnet 5.5 costs less than Opus, and for many agent tasks it apparently suffices. I am leaving out a chart until the board lists the new models.
