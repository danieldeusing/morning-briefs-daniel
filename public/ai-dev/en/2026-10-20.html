DeepSeek-V4.1-Flash-1017: a big jump for a "minor update"

DeepSeek calls it "a minor update to DeepSeek-V4.1-Flash".[1] The numbers on the model card don't look small. On Terminal-Bench 4.0 the score rises from 31.2 to 42.3, on ProgramBench from 20.3 to 29.1. On DeepSWE v1.1 it goes from 74.2 to 77.0.[1] The weights are under the MIT license, and the card lists 763B parameters and 1M context. No release date appears on the card. The "1017" in the name points to Oct 17. Today the model is #1 on Hugging Face trending.[2]

Open weights: The vendor releases the finished, trained numbers of the model for download. You can run it on your own hardware or with a host of your choice. It is like a recipe you may cook at home instead of only eating at the restaurant. The license decides what you may do with the dish. MIT means: almost anything.

DeepSeek puts itself next to closed models in the same table:[1]

Benchmark (vendor table)V4.1-Flash-1017Opus 5GPT-5.6 Sol
DeepSWE v1.177.074.073.0
Terminal-Bench 4.042.351.839.9
ProgramBench29.137.023.0

One detail speaks for the table: for Opus 5 and GPT-5.6 Sol, DeepSeek lists 74.0 and 73.0 on DeepSWE. Datacurve's independent board measures 74% and 73% for the same models.[3] So the comparison values are not flattered. The value for DeepSeek itself, however, is not independently measured. The board is from Sep 22 and lists only the older deepseek-v4-flash at 53%.[3]

My take: read the whole table, not just the first row. DeepSeek wins exactly one of four benchmarks against Opus 5, and narrowly. On the other three, Opus 5 is clearly ahead. A 77 against a 74 is not a clear gap on DeepSWE. The board states uncertainties of ± 1 to ± 4 for the top places. The model is still interesting: an MIT license and near-top scores rarely come together. For running locally it is not an option, as 763B fits on no workstation. It is a candidate for a cheap host inside a harness like Cline or OpenHands.

Try it If a host offers the model: run a real task from your repo on it and compare against your default model. The vendor table is no substitute.

Meta Muse Spark Open: big, open with a form, not in front

On Oct 15, 2026, Meta put Muse Spark Open on Hugging Face.[1] The model has 816B parameters, 42B of them active, and 1M context. The license is the "Muse Model License". To download, you have to fill in a form with your full name, date of birth and organization.[1]

"816B total, 42B active" (Mixture of Experts): The model consists of many specialists. For each word, a router picks only a few of them. So only 42B do the computing, but all 816B must be stored. It is like a large clinic: you see only two doctors, but the building has to house them all. Fast at computing, hungry for memory.

The hardware spec shows this: at least 700 GB VRAM with NVFP4 and 2 TB with BF16. Meta also writes that the model runs optimized on two Mac Studios with M5 Ultra via MLX.[1]

NVFP4 and BF16: These are precisions at which each number in the model is stored. BF16 takes 16 bits per number, NVFP4 only 4 bits. It is like a photo as RAW or as a heavily compressed JPG: the small format fits into less memory and loses some quality.

The coding numbers on Meta's own card (effort "xhigh", vendor data): DeepSWE 1.1: 60, SWE-Atlas-QnA: 58, Terminal-Bench 2.1: 76.4. The same table lists GLM 5.3 at 67 and Kimi K3 at 68 on DeepSWE. On Terminal-Bench 2.1, GLM 5.3 has 83.9 and Kimi K3 has 85.0.[1]

My take: this is unusually honest. Meta shows a table in which its own model trails two open competitors on the coding scores. A cross-check fits: DeepSeek's card lists 66.9 for GLM 5.3 and 67.5 for Kimi K3 on DeepSWE, Meta lists 67 and 68.[1][2] For coding, Muse Spark Open is no reason to switch. Be careful when comparing with DeepSeek: Meta measures Terminal-Bench 2.1, DeepSeek Terminal-Bench 4.0. Those are different versions, so the numbers are not comparable. And a license with an ID form is not open source in the usual sense.

Claude Code 2.1.304: two fixes that save data

On Oct 18, 2.1.303 arrived with "Bug fixes and reliability improvements", and on Oct 19 2.1.304 followed.[1] Two entries in 2.1.304 concern data loss:

  • claude --worktree: Fixed a bug where Claude Code removed the worktree and its branch on exit without asking when HEAD was detached or on a different branch. That "could lose commits".[1]
  • rm -r on drives: An rm -r on a mounted drive or its top level (/Volumes, /media, WSL's /mnt/c) did not get the safety prompt that rm -rf /Applications gets. Now it does.[1]
Git worktree: A second working folder for the same repository, with its own branch. That way an agent can work on task B while you stay in task A. It is like a second workbench in the same workshop. If the workbench is cleared away along with the branch before the work is saved, the work is gone.

On top comes /auto-mode-setup: a guided setup that reads your project and recent sessions to teach auto mode your environment. It now also runs on Bedrock, Vertex, Foundry, the Claude Apps gateway and in sessions without telemetry.[1] New for mod authors: decider: "person" in a tool.check response. Then only the permission dialog or a callback from the host may approve the request.[1]

My take: the worktree fix is the most important entry of the week for anyone running parallel agents. An agent that silently deletes commits is worse than a slow agent. A detached HEAD happens easily, for example after a git checkout to a tag. If you use worktrees with Claude Code, update today. The rm -r fix shows the same pattern: safety prompts grow case by case, after real accidents. A list of protected paths is never complete. A backup stays mandatory.

Try it Check claude --version and move to 2.1.304 if you work with --worktree.

GitHub Copilot: six models out, policies via API

On Oct 19, 2026, GitHub deprecated six models "across most GitHub Copilot experiences".[1] The suggested successors:

GPT-5.4 mini, GPT-5 miniGPT-6 Luna
Gemini 3.7 FlashGemini 3.8 Flash
Grok 4.5Grok 4.7

Copilot Enterprise admins may first have to enable the successors in the model policies.[1] Fittingly, the model policy API became generally available on the same day. GET and PATCH endpoints exist on four levels: enterprise, enterprise teams, enterprise apps and organization.[2]

Model policy: A company setting for which AI models people may use in Copilot. It is like a list of approved suppliers in accounting. With the API you can maintain this list by script instead of clicking through the interface.

My take: if you set a script, an action or an integration to a fixed model name like gpt-5-mini, check it now. Silently falling back to another model is often worse than an error. The API is aimed mainly at companies. But it shows where things are heading: model choice becomes a governance question, not a matter of taste. That GPT-5.5 is already out shows the pace. Expect any model to live only a few months in a tool.

Benchmarks: two tables, no referee

The independent DeepSWE board is still from Sep 22, 2026 and has 113 tasks.[1] The top: gpt-6-astra, gemini-3.8-flash and claude-opus-5 at 74% each, gpt-5.6-sol at 73%. Costs per task range across the top four from $2.36 (Flash) to $11.84 (Opus 5). Among the top rows, gpt-5.6-luna has the best value with 67% for $0.61. glm-5.3-flash (63%, $0.24) and deepseek-v4-flash (53%, $0.46) are cheaper.[1]

The DeepSeek 77.0 and the Meta 60 are not on the board. Meta writes on its card, verbatim, that it measured with the "preferred harness". DeepSeek does not name the harness in its table. Both are legitimate, but not the same as a measurement under equal conditions.[2][3]

Harness: The program around the model that gives it tools, runs commands and reports results back. Claude Code, Codex and OpenHands are harnesses. The same model can do differently well in two harnesses, just as the same driver sets different lap times in two cars.

My take: I'm still leaving a chart out. The new numbers all come from the vendors and with different harnesses. Turning them into a bar chart would show a comparability that doesn't exist. The board is now four weeks old. In that time, Sonnet 5.5, Haiku 5.5, Argon and now two large open models have appeared. An update is overdue.

It's Tuesday, October twentieth. The big labs didn't ship a new coding model. Instead, two large open models have shown up, and both Claude Code and GitHub Copilot delivered important changes.

DeepSeek released an update to V four point one Flash, with the suffix ten seventeen. The weights are under the MIT license. On the model card, DeepSeek reports seventy-seven point zero on DeepSWE, up from seventy-four point two. That's a vendor number. In the same table, though, Opus five is clearly ahead on three of four benchmarks. Today the model sits at number one on Hugging Face trending.

Meta released Muse Spark Open on October fifteenth. The model has eight hundred sixteen billion parameters, of which only forty-two billion do the computing for each word. It needs at least seven hundred gigabytes of video memory. On Meta's own card it scores sixty on DeepSWE, which puts it behind GLM five point three and Kimi K three. To download it, you have to fill out a form with your name and date of birth.

Claude Code is at version two point one point three oh four. Two fixes deal with data loss. The worktree command used to delete the worktree and branch on exit without asking when the repository's head was detached, and commits could be lost. And a recursive delete on a mounted drive now triggers a safety prompt. If you work with worktrees, update today.

On October nineteenth, GitHub pulled six models from Copilot, including GPT five point five, GPT five mini and Gemini three point seven Flash. As replacements, GitHub mostly names GPT six point one Sol and GPT six Luna. The same day, a model policy API became generally available. Companies can use it to set by script which models are allowed.

Codex CLI shipped three alpha versions without notes, and OpenHands shipped version one point twenty-eight. With version zero point forty point six, Ollama brings something called clef to its cloud.

On benchmarks, there's still no referee. The independent DeepSWE board is from September twenty-second and doesn't include any of the new models. That's why there's no chart today.

Tomorrow we'll see whether Codex version zero point one six four ships as stable, and whether anyone measures the new open models independently.
