Today · Claude Code 2.1.306

Claude Code 2.1.305: two guardrails get looser

Claude Code 2.1.305 arrived on Oct 20, and 2.1.306 followed on Oct 21.[1] Most entries are fixes. But two entries in 2.1.305 change what your setup allows. Both are stated openly in the notes, with a warning. You just have to read them.

1. The sandbox switch. New is sandbox.allowNestedUserNamespaces. It lets commands in the sandbox create their own user namespaces on Linux. Chromium and rootless podman, for example, need this. Anthropic itself says it “lets them get around the sandbox's file protections”.[1]

User namespace: A Linux trick that lets a program build its own small world. Inside it, the program can feel like an administrator without being one on the real system. Browsers and containers use this to wall themselves off. The problem: from inside that world, a program can get around the rules the sandbox sets from outside. It is like a child in a playpen who is allowed to build their own box. The box can get tall enough to climb over the bars.

2. The MCP allowlist. allowedMcpServers now no longer filters stdio servers from managed-mcp.json if they use ${VAR} only in the env block. The note says it plainly: a server your allowlist left out “now loads on upgrade”. If you still want it off, you must add it to deniedMcpServers.[1]

MCP server and allowlist: An MCP server is an add-on program that gives the agent tools, such as access to a database or a ticket system. The allowlist is the guest list: only those on it get in. Until now, certain guests were turned away at the door even though they were not on the list. Now they get in. If you do not want them, you now need a list of banned guests.

My take: The sandbox switch is built honestly. It is off until you turn it on, and the warning is in the text. Turn it on only in an environment that is disposable anyway, such as a container or a VM. The MCP change is trickier. It takes effect silently on update, without you doing anything. Fail-open behavior in an allowlist is exactly the kind of change a security team must not miss. For you as a solo developer, the risk is small if you do not use managed-mcp.json. In a team with managed settings, check today which servers run after the update.

Try it After the update, look at the loaded servers with /mcp and compare them with your intended list.

Claude Code: the rest of the week in fixes

2.1.304 from Oct 19 introduced a bug. On Vertex, Bedrock and other providers, every request failed if the endpoint or a gateway rejected tool search. 2.1.305 then retries without tool search.[1] The background: 2.1.304 had turned tool search on by default behind a custom ANTHROPIC_BASE_URL.[1]

Tool search: With many connected tools, the agent does not load all the descriptions into context at once. It picks out only the ones it needs right now. This saves space in context. But it requires that the server on the other end knows this feature.

More fixes in 2.1.305: Bash commands on a full disk now clearly report that the disk is full and nothing ran, instead of showing a raw ENOSPC path.[1] 2.1.306 fixes a bug where, in sessions with many MCP tools, an API error appeared as “prompt is too long” and triggered an unnecessary compaction.[1]

My take: Three versions in three days, and one of them repairs the previous one. That is the pace you know from Claude Code. If you work through Bedrock, Vertex or your own gateway and have 2.1.304, move on to 2.1.306 right away. If you work directly with the Anthropic API, you were not affected.

OpenAI: prompt cache now lasts 12 hours

The API changelog says on Oct 20 for v1/responses: “You can now choose 12-hour prompt caching in the API.”[1] On Oct 16 it added that the OpenAI-hosted sandboxes in the Agents API include the Artifact SDK and skills for spreadsheets.[1]

Prompt caching: A coding agent sends the same long beginning with every request: system prompt, tool descriptions, often large parts of the repo. The provider can cache this beginning. Then it does not have to process it again each time, and you pay less. It is like a waiter who remembers your regular order. The longer he remembers, the more often you save yourself the recital.

My take: For agents this is more useful than it sounds. An agent that works in the morning, pauses at noon and continues in the afternoon still hits the cache at 12 hours. What the option costs and how long the cache lasted before is not in the changelog entry; it only says cached-input pricing is lower, with no figure. We did not check that. Read the pricing page before you turn it on. A longer cache only pays off if you really reuse the beginning.

Try it If you build your own agents on the Responses API: compare the cache hits in the usage data for a day with and without the 12-hour option.

Gemini 4 Argon: a week out, still no measurement

Google released Gemini 4 Argon to developers on Oct 13, 2026. According to the Google blog, the model is available on the paid tier of the Gemini API in AI Studio and Android Studio. Google AI Ultra subscribers also get access to Antigravity, an “agent-first development platform”.[1] The blog post gives no benchmark numbers or prices.[1]

Secondary sources cite an introductory price through the end of November. On the price after that, they contradict each other, and we did not check Google's pricing page. So we give no number here. We have not verified a headline claiming Argon beats GPT-6 and Claude at coding.

My take: A major model with no coding number on its own page is unusual. Either Google is being reserved, or the model targets science and agents more than repo work. Argon is not yet on the DeepSWE board. Until then, it is an option to test yourself, not a proven leader.

Local: Ollama 0.40.7 is stable

Ollama v0.40.7 from Oct 18 is now the current version.[1] New is the model pplx-decider. According to the note it is “a 27B decision model from Perplexity”. Of interest to Claude Code users: the version limits CLAUDE_CODE_AUTO_COMPACT_WINDOW for ollama launch claude. Also, the order of tool-call events is now correct when streaming over the Responses API.[1]

My take: The compact fix is the practical part. A local model usually has a much smaller context window than Claude. If Claude Code compacts too late, the local model overflows. If you test Claude Code with a local model through Ollama, update. How good pplx-decider is at coding is open. A “decision model” sounds more like routing than writing code. 27B fits quantized on a 24 GB card.

OpenHands 1.29.0: profiles with their own toolbox

OpenHands released version 1.29.0 on Oct 20, one day after 1.28.0.[1] According to the release summary, skills, condensers, verification and model router can now be set per agent profile. 1.28.0 had brought a verification tool “verify-openhands”.[1] Note from OpenHands: the macOS app is not signed. Gatekeeper may report it as “damaged”.[1]

Condenser: A component that summarizes long agent histories so they fit into the context window. It is what Claude Code calls “compaction”.

My take: Profiles with their own model and their own rules are the right way. A review agent needs different settings than a refactoring agent. Claude Code solves this with subagents, OpenHands now with profiles. I would take the note about the unsigned app seriously: download it only from the official GitHub release.
