Cline: three releases on one Monday

Yesterday Cline was still on our quiet list. Today the project published three packages at once, all on Oct 26.[1] That makes Cline the only coding tool with real movement since Friday.

Desktop 0.0.49 (marked "Latest") is becoming more of an IDE. There is a Changes button for the agent's edits, and "an integrated terminal panel opens at the bottom of the window".[1] If the hub does not start, the app now shows its own error page instead of just hanging.

CLI 3.0.74 fixes a problem everyone knows who has several windows open: "Opening a task that's already running in another Cline app now attaches to that run."[1] Before, this could spawn a second run. In addition, hub status and doctor no longer hang, and Kimi K3 gets the reasoning level max for the Extra High and Max tiers.[1]

SDK 0.2.0 matters for anyone building their own agents on Cline. "Model requests retry at most 3 times after the first attempt (down from 5)."[1] The SDK can now also reattach to a running session. And the Gemini provider no longer sends native Google Search along.[1]

Retry cap: When a model call fails, the tool automatically tries again. The cap says how many times. It is like calling a busy hotline: after three tries you hang up instead of burning money in the queue five times. With an agent, every try costs tokens and time.

My take: The desktop app is the interesting part. A terminal and a diff view in the same app show where Cline is headed: away from a pure VS Code plugin and toward its own interface, like Cursor and the Claude app. Whether that holds up against Cursor is open. Cutting retries from 5 to 3 is small but right. Five retries hide a broken provider for too long and cost money. If you built your own logic in the SDK around many retries, check it after the update.

Try it Open Desktop 0.0.49 alongside the CLI once and start the same task in both. If attaching to the running run works, Cline is finally usable for work across several windows.

A ranking for harness plus model

Most benchmarks measure a model on its own. The Coding Agent Index v2.0 from Artificial Analysis instead measures the combination of tool and model.[1] The comparison page showed three entries when we retrieved it:

  • Claude Code with Opus 5.5 (max): 62
  • Codex with GPT-6 Astra (max): 55
  • Opencode with GLM-5.3: 49
Harness: The program around the model. It reads files, calls tools, runs commands and decides what the model sees next. The model is the engine, the harness is the car. A strong engine in a bad car does not win a race.

Three caveats. First, the page shows no date, and the table loads via JavaScript. We saw only these three values, not the whole list. Cline, Cursor or Aider may be missing only in our excerpt. Second, the index does not separate how much of the gap comes from the model and how much from the harness. Third, the Codex entry uses GPT-6 Astra. But according to secondary reports, the default model of the Codex CLI has been GPT-6.1 Sol since version 0.161.0 (a later version removed the default label from the model picker).[2] We did not check that in a primary source.

My take: Still, this is the more honest question. You never work with a bare model, always with a harness. The 7-point gap between Claude Code and Codex is clear. But it does not say that Codex could not catch up with a different model. For your own choice it works as a hint, not a verdict.

Local: Ollama passes context on to coding tools

Ollama 0.40.11 from Oct 24 is still the current stable version.[1] For coding, an older change matters more: since 0.40.9 from Oct 22, ollama launch passes the context length and capabilities of cloud models on to coding tools.[1] The tool then does not have to guess how big the window is.

0.40.10 from Oct 23 added Nemotron 3.5 Bolt E4B from NVIDIA: an image-and-text model based on Gemma 4, with 128K context and tool use. It ships with a DFlash draft for speculative decoding.[1]

Speculative decoding: A small, fast model guesses the next words ahead of time. The large model checks the whole draft in one step and keeps what is right. It is like an intern who drafts a letter and the boss crosses out only the wrong parts. The answer is just as good, but arrives faster.

My take: With tool use and 128K context, Bolt E4B is a candidate for small local agent tasks. We found no coding measurements for it.

In brief

  • OpenHands 1.33.0 (Oct 23) enforces a rule: third-party packages must be seven days old before they enter the project ("enforce seven-day third-party release-age policy"). It also adds a dialog for installing MCP servers and masking of secrets.[1] The waiting period is a simple brake against supply-chain attacks. You can build it into your own project too.
  • OpenAI API: Since Oct 20, prompt caching in the Responses API lasts up to 12 hours. Since Oct 16, the Agents API sandboxes have the Artifact SDK and Skills.[2] For coding agents with a long system prompt and large repo context, the longer cache can cut costs.
  • Agent Skills have been at the Agentic AI Foundation under the Linux Foundation since Oct 22. The AAIF also hosts MCP.[3] Keep your own skills vendor-neutral.
Prompt caching: The provider remembers the unchanging start of your request, for example system prompt and repo overview. On the next request you pay less for that part. It is like a loyalty card: on the second visit you do not have to introduce yourself again.
