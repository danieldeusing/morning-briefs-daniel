Claude Code 2.1.312: the fix that saves files

Version 2.1.312 arrived on Oct 27 and, with 39 entries, is a sizeable release.[1] One entry matters more than all the others: “Fixed Claude overwriting a very large CLAUDE.md, rules file or @-included file in a subdirectory after seeing only its start; Write now asks Claude to read it all or edit in place”.[1]

In practice, this means Claude read only the start of a large file, then rewrote the whole file, and the rest was gone. The affected files were exactly the ones you put the most work into: CLAUDE.md, rules and included files. Now the Write tool requires Claude to read the file in full or to edit it in place.

Three more points matter for everyday work:[1]

  • Per-directory skills and skills with paths: were not found after a cd deeper into the repo. Fixed.
  • A command with an invalid name could block all commands, and claude -p then printed nothing. Fixed. This affects scripts and CI.
  • Prompt and agent hooks now run at most 24 at a time per session, sub-agents included. A timeout under one second counts as one second.
Hook: A custom script that Claude Code starts automatically on an event, for example before every tool call. It is like a Git pre-commit hook, but for the agent. The new limit of 24 means that with many parallel sub-agents, hooks wait in a queue instead of all running at once.

There is a quiet change for Bedrock, Vertex, Foundry and Mantle. For model names that Claude Code does not recognize, it now uses the shorter system prompt, even when Sonnet or Haiku sits behind the name. If you want to keep the full prompt, set CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0.[1] Claude Code also no longer sends the OpenTelemetry event claude_code.safety_event.[1]

My take: the CLAUDE.md fix is a must-have update. An agent that rewrites a file after reading only the first lines is a data-loss bug, not a comfort issue. After the update, use git diff to check whether your large rules files shrank in the last few days. The Bedrock change is the one you can easily miss: if you work through a custom deployment name, the behavior changes without warning.

Try it After the update, run git log --stat over your CLAUDE.md and rules files. A large block of deletions in an agent commit is the warning sign.

Codex CLI 0.165.0: memory as the default

After several alphas, OpenAI published a stable Codex release again on Oct 27.[1] Three new features:[1]

  • “Added a built-in Google Cloud Vertex AI provider, configured with model_provider = "gcp".”
  • “Enabled reasoning effort changes during a conversation by default for supported models.”
  • “Enabled memory v2 by default for fresh profiles and added support for importing external-agent memories into it.”
Reasoning effort: How long the model thinks before it answers. More effort means better answers on hard tasks, but more time and cost. It is like a colleague you ask for either a quick answer or a thorough review.

There is also a fix from the same family as the ones in Claude Code and Cline in recent days: Codex no longer retries a request when the provider reports that the model does not exist.[1] Overnight, 0.166.0-alpha.4 and alpha.5 were added.[1]

My take: the import of other agents’ memories is the interesting part. With it, OpenAI builds a way to switch from another tool to Codex without losing the project knowledge it learned. The notes do not say which formats the import reads. The Vertex provider is a second signal: Codex is meant to run with models from outside OpenAI too. Together with changing effort mid-session, which Claude Code also has, the harnesses are becoming more and more alike.

Kimi K3.1 Pro: the independent number is lower

Moonshot reports 65.7% on Terminal-Bench 4.0 for Kimi K3.1 Pro, against 66.4% for Claude Opus 5.5.[2] That is a vendor claim, and we only know it second-hand. Vals tested the model itself on Oct 24 and gets 63.64% (±1.75), rank 3 of 56.[1] On the Vals Index, which mixes several tasks, Kimi stands at 62.52% in rank 8 of 28.[1]

Terminal-Bench: A test in which an agent must solve real tasks in a command line, for example building a project or setting up a server. It is closer to working with Claude Code or Codex than a test that only has the model write single functions. The ±1.75 means that on a new run the value can vary by about that much.

Two notes of caution. First: the Vals page is not fully consistent. The text names 56 and 28 models, while the Oct 24 entry names 55 and 27.[1] So the rank is a snapshot. Second: on Artificial Analysis, Kimi stands at 55 points on the Intelligence Index, Opus 5.5 at 58 in its highest mode.[3] That is an overall index, not a coding score. We could not retrieve SWE-bench Verified today.

My take: a gap of a good two points between vendor and Vals is normal. Vendors test with the best setup, independent testers with a fixed one. The statement is still strong: a model whose weights are meant to become open sits in the top group on an agent benchmark. No leaderboard tells you whether that holds on your repos. The weights are announced for Nov 4 and are not here today. Only then can we check whether the self-hosted version delivers the same numbers.

Local: Ollama 0.40.12 is stable

Yesterday’s pre-release is now the stable 0.40.12.[1] Three points from the notes: “Faster prompt processing on Apple silicon for Gemma 4, Flint and Laguna models”, “Speculative decoding now supports DFlash2 draft models on MLX” and “Fixed tool-only assistant turns from Kimi CLI”.[1]

My take: the faster prompt processing matters more for coding than DFlash2. A coding agent sends a lot of context at every step, meaning files, diffs and tool output. On the Mac, reading that in is exactly the slow part. If you run Gemma 4 locally as an agent model, you should notice the difference right away.

Try it Install the update and time the same agent task with Gemma 4 before and after. Time to first token is the number that counts.

OpenHands 1.34.0: one container per conversation

OpenHands published version 1.34.0 on Oct 27.[1] The main feature: “per-conversation Docker runtime and Settings → Runtime page”. There is also a security fix: the session API key now goes to the static server through an environment variable, no longer as a command-line argument.[1]

My take: the second point is small, but right. Every process on the machine can see command-line arguments, for example with ps. A dedicated container per conversation fits the trend of the week: Cursor is building cloud environments, Cline a local-cloud switch. Every tool now separates the agents’ working environments more cleanly from each other.
