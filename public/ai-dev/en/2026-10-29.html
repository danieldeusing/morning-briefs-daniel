Copilot Fusion: The Router Becomes a Product

On Oct. 28, GitHub announced: “GitHub Copilot Fusion is generally available.”[1] Fusion is available on all Copilot plans, in VS Code, in the Copilot app, in the Copilot CLI and in JetBrains IDEs.[1] You no longer pick the model yourself. You only say how hard the task is, and Copilot “intelligently route[s] and orchestrate[s]” the models for you.[1]

Model router: A layer in front of the models that decides per request which model handles it. Think of a repair shop where the master hands the oil changes to the apprentice and does the transmission repair himself. Cheap tasks go to cheap models, hard ones to expensive models.

There are three effort levels. Standard prefers “versatile models for everyday coding,” High “capable models for challenging tasks,” and Max “the most capable models for the most demanding tasks.”[1] The working modes are more interesting:

  • Single: one model does the task.
  • Cascade: a quality check decides whether the task moves on to a stronger model.[1]
  • Critique: “One model drafts an initial response, another model reviews it, and the original model revises.”[1]

On price: you pay “for each model it uses, at each model's standard rate.” On paid plans there is a 30% discount on model costs with Fusion “for a limited time.”[1] The changelog does not say how long the discount runs.

My take: Critique is the real news. Until now you built this yourself, for example one model writes and a second reviews via a sub-agent. Now it is a switch. The catch is the billing rate: with Critique you pay for at least two models per task. The discount cushions that at first, after that you have to do the math. The second catch is control. If you want to know why a result was bad, you need to know which model wrote it. Check whether Fusion shows you that per answer before you set it to Max.

Try it Run the same medium-difficulty refactoring task once with a fixed model and once with Fusion on High. Compare result and cost while the discount lasts.

Copilot App: Projects and Computer Use

The same Universe package brings two features to the Copilot app as a public preview.[1] Projects collect work in one place: “Projects in the GitHub Copilot app give that work one home, with its context, agents, and results together.”[1] Computer Use runs on macOS and Windows.[1]

Computer Use: The agent operates your screen like a person: it sees screenshots, moves the mouse and types. Think of a colleague working on your computer via remote access. Useful when a program has no API, but risky because the agent sees everything you see.

Other changelog titles from Oct. 28: “GitHub Enterprise now includes access to GitHub Copilot,” “Security extension for the GitHub Copilot app” and “Build shared workflows for your team with Copilot Automations.”[2] We did not open the details.

My take: GitHub is building the Copilot app into a workspace of its own, next to the IDE. That is the same direction as Cursor with cloud agents and canvases. For you as a Claude Code user, Projects is the interesting part: context, agents and results in one place is roughly what you hold together today with CLAUDE.md, sub-agents and Git branches. I would not yet enable Computer Use on a work machine with client credentials. A preview with full screen access belongs in a VM.

Octoverse 2026: Agents Triple the Volume

Simon Willison summarizes the Octoverse report like this: “merged pull requests tripled in less than a year to 220 million per month.”[1] Commits more than tripled, to 7.38 billion per month. New repositories doubled, to 30.3 million per month.[1] We did not open GitHub's original report ourselves.

My take: No human team growth can explain these numbers. This is agent volume. Two consequences for you. First, review becomes the bottleneck, not writing. That is exactly what Critique in Fusion targets. Second, more PRs does not mean more finished work. Part of it is agent PRs that get closed or overwritten. The summary does not say how big that part is.

Terminal-Bench 4.0: The Independent Leaderboard

Vals updated the leaderboard on Oct. 27. All models run in the same harness there: “All models were benchmarked using mini-swe-agent, a minimal, model-agnostic agent harness.”[1] That makes the scores comparable with each other, but not with the vendor claims.

Terminal-Bench 4.0 — Top 10 at Vals, as of Oct. 27, 2026
Harness: The program around the model that gives it tools, runs commands and reports results back. Claude Code, Codex and Copilot are harnesses. Think of a car around an engine: the same engine goes faster in a race car than in a delivery van. Mini-SWE-agent is deliberately a very simple car.

The gap between vendor and Vals is similar across the board:

  • Claude Opus 5.5: Anthropic claims 66.4%, Vals measures 65.15%.[1][2]
  • Kimi K3.1 Pro: Moonshot claims 65.7%, Vals measures 63.64% (±1.75).[1][3]
  • Claude Fable 5.1: Anthropic claims 55.8%, Vals measures 58.08%. Here Vals is even higher.[1][2]

In fourth place is “Gemini 4 Carbon” with 63.13%.[1] According to our sources, Google has not officially announced this model. It is considered a test version from the Arena, but that is only a rumor. The released Gemini 4 Argon is in eighth place with 57.58%.[1] We could not retrieve SWE-bench Verified today; the page returned no numbers.

My take: The top 4 are within a little over two points. With a variation of about ±1.75, that is not a clear gap, it is a leading pack. Sonnet 5.5 in second place is the real number for you: nearly Opus level at a lower price. The leaderboard tells you which models to test, not which one wins on your repo. And remember the car image: with Claude Code instead of Mini-SWE-agent, the order may look different.

GPT-6.1 Terra: Cheap, but Still Unmeasured

OpenAI released GPT-6.1 Terra on Oct. 26, in ChatGPT, Codex and in the API as gpt-6.1-terra.[1] The price: $1 per million input tokens and $5 per million output tokens, almost half as much as GPT-6.1 Sol.[2][3] The context window is 1.05 million tokens, with up to 128,000 tokens of output.[3]

On Terminal-Bench 4.0, OpenAI reports 50.3% at the highest effort setting, versus 21.5% for GPT-5.6 Terra.[1] Decrypt writes: “All performance figures are OpenAI's own.”[1] Terra is still missing from the Vals list of Oct. 27.[4]

My take: 50.3% would be a big jump over the previous version. Even if the number holds, Terra stays below GPT-6.1 Sol (55.05% at Vals) and well below the leading pack.[4] For the hardest coding tasks, OpenAI itself reportedly points to Sol and Astra.[5] Terra is a candidate for simple agent steps, for example as the cheap model in a cascade. That is exactly what GitHub is building Fusion for right now.

Agent Skills Now Belong to the Foundation

On Oct. 22, Anthropic gave the Agent Skills format to the Agentic AI Foundation, which operates under the Linux Foundation.[1] Anthropic promises to keep Skills “open, community-driven, and vendor-neutral.”[1] According to Anthropic, the format is integrated into more than 70 platforms, with around 1 million published skills and about 280 million installs.[1] Anthropic founded the Foundation with Block and OpenAI. MCP already lives there.[1]

Agent Skill: A folder with instructions (SKILL.md) and optional scripts that an agent loads when needed. Think of a recipe-card box in the kitchen: the cook reads only the card they need right now.

My take: Technically, nothing changes for you. Strategically it means your skills for Claude Code are no longer lock-in. If Copilot, Cursor and Codex read the same format, you can take your skill collection with you. The figure of 280 million installs is an Anthropic claim with no independent check.

We covered the file fix from 2.1.312 yesterday. It's Thursday, October twenty-ninth. Yesterday was day one of GitHub Universe in San Francisco, and GitHub gave Copilot a major overhaul. Day two of the conference is today.
