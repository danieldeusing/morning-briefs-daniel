Gemini 4 Carbon: strong, but locked

Correction to yesterday: We wrote that Google had not officially announced Carbon. That is not true. The Google blog post "Introducing Gemini 4 Carbon" is dated Oct. 28, 2026.[1]

Access is narrow: "Starting this week, we will make Carbon available to a subset of cyber defenders", then step by step to more trusted partners through the Fairwind program.[1] For developers, companies and end customers, Google names no date. Google wants to gather more feedback first and keep working on the safeguards.[1]

Pricing is already set: at launch $2 per million input tokens and $10 per million output tokens, then $4 and $20.[1] A price list at CometAPI shows $60 and $240. That fits no other source, so we ignore it.

The performance numbers need a careful read:

  • Artificial Analysis Intelligence Index v5.0: 1st place with 59, according to Google.[1] This is a general index, not a coding test.
  • AA Coding Agent Index: 59, measured only in Google's Antigravity CLI. Claude Code with Opus 5.5 scores 62 there.[2]
  • WebDev Arena: 4th place with 1,768 Elo, up 89 points.[1]
  • Terminal-Bench 4.0: Google gives no success rate, only "cheating" of 0.0%. Vals independently measures 63.13%, 4th place.[1][3]
  • Cyber tests: CWE-bench 71.0%, SEC-bench Pro 88.2%, ExploitGym 54.8% with a 10-hour time limit. According to NeuralTrust, none of these values has been independently verified.[2]
Staged rollout: The maker gives a model first to a small, vetted group. It is like a new drug that is given only in clinics before it reaches the pharmacy. With Carbon the reason is the cyber capability: a model that finds security holes can also exploit them.

My take: For your daily work, Carbon changes nothing this week, because you cannot get it. The numbers still show two things. First, Carbon is in the top group for coding, but not ahead of it: 63.13% at Vals against 65.15% for Opus 5.5. Second, the Coding Agent Index shows again that the harness matters. 59 in Antigravity against 62 for Claude Code with Opus 5.5 is a comparison between two complete systems, not between two models. The entry price will be interesting once Carbon opens up: $2/$10 for a model of this class would put pressure on everyone. Nobody knows whether the price will still hold at launch for everyone.

OpenAI follows with API credit

Subscribers of the ChatGPT plans at $100, $200 and $500 a month now get matching API credit. Simon Willison writes on Oct. 29: "OpenAI have now launched pretty much exactly the same deal" — meaning the offer Anthropic launched in early October for Max and Team.[1]

My take: This is the most practical news of the day for you. If you have an expensive subscription, you can now run your own scripts, evals and agents against the API without a second bill. The line between "chat subscription" and "developer account" is blurring. For comparison tests this means a Terra-versus-Sonnet test on your own repo may cost you nothing extra. We did not check the exact terms (expiry, limits). Read them before you upgrade a subscription because of this.

Try it If you have a matching subscription: run the same task through the API on Terra and Sol once, and note the cost per solved ticket.

Terminal-Bench 4.0: Terra now measured

Vals updated the leaderboard again on Oct. 29, two days after the last version. All models run in the same simple harness, Mini-SWE-agent.[1] The top is unchanged. New is 11th place: GPT-6.1 Terra with 49.49%.[1]

Terminal-Bench 4.0 — Top 12 at Vals, as of Oct. 29, 2026

OpenAI had reported 50.3% for Terra in the highest effort mode.[2] Vals is only slightly below. That is a good sign for OpenAI's claim. For Kimi K3.1 Pro the gap stays larger: Moonshot reports 65.7%, Vals measures 63.64%.[1][3]

Vendor claim vs. independent measurement: The vendor tests its model in its best harness and with its best settings. Vals tests all models the same way. It is like a car's official rated mileage against its mileage in a consumer test: both numbers are right, but only the second is comparable.

My take: Terra in 11th place confirms what we suspected yesterday. Terra is not a main coding model but a cheap worker for simple steps. At $1/$5 per million tokens it is still interesting as a cheap tier in a cascade. At the top the picture stays: Opus 5.5, Sonnet 5.5, Kimi K3.1 Pro and Carbon sit within a little over two points. That is a top group, not a ranking.

We leave out SWE-bench Verified today. The page returned no numbers, and the aggregators contradict each other with values from Sept. 9.

Kimi K3.1 Pro: weights not out yet

Kimi K3.1 Pro has been available through the API since Oct. 23, at $2 per million input tokens and $10 per million output tokens. According to Simon Willison, the model scores 55 on the Artificial Analysis index, behind Opus 5.5 at 58.[1] Moonshot promises: "Full model weights will be released by Nov 4, 2026".[1] One aggregator already reported open weights for Oct. 24. That is wrong; the weights have not been published yet.

Open weights: The weights are the learned numbers inside the model. If they are open, you can download the model and run it yourself. It is like a recipe you can cook at home instead of only eating in the restaurant.

My take: 3rd place at Vals with 63.64% makes Kimi the strongest candidate for open weights at top level. But the full model will be too big for Ollama on your machine. Wait for quantized versions and for an independent measurement of the weights, not only of the API.

Claude Code 2.1.314: write lock

Version 2.1.314 from Oct. 30 "locks writes to working directories, routes gateway traffic by IdP group, and compacts long idle chats".[1] The source is a third-party mirror of the changelog. We did not open the official changelog today.

Before it came 2.1.312 (Oct. 27, custom OIDC claims for the user ID, safer edits of large files) and 2.1.310 (Oct. 23, Monitor tool on Bedrock, Vertex and Foundry).[1] Since 2.1.293 from Oct. 7, Haiku 5.5 is the default Haiku model, with 1M tokens of context.[1]

Compaction: When a chat gets too long, Claude Code summarizes the old part and replaces it with the summary. It is like meeting minutes instead of an audio recording: you lose details but keep the thread and save space.

My take: The write lock is the important part. An agent that may write only in its working directory cannot change your dotfiles or a neighboring repo by accident. After the update, check whether your workflows with paths outside the project (e.g. /tmp files) still run. Routing by IdP group mainly affects companies with their own gateway.

My take: codex queue --resume is the useful part. Long task queues that keep going after an interruption are exactly what you need for overnight agent runs. Terra in the catalog means you can now deliberately switch to the cheaper model in Codex for routine tasks.
