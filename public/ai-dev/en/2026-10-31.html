Claude Code 2.1.316: Fast Mode for Opus 4.8 Ends

The Oct 31 release contains one line you should know: "Deprecated fast mode for Opus 4.8 as of October 30, 2026; it will be removed on November 30, 2026."[1] Also new is the environment variable CLAUDE_CODE_DISABLE_ULTRATHINK.[1]

Fast Mode: A switch that makes the same model respond faster. It's like paying for express shipping: same letter, faster delivery. When the switch goes away, Opus 4.8 runs only at normal speed.

My take: This is a cleanup signal. Opus 4.8 is no longer the top model; this week's leaderboards are led by Opus 5.5. Anthropic apparently no longer wants to maintain special paths for older models. If you have Opus 4.8 with Fast Mode hard-coded in a script, a CI pipeline or your settings, plan the switch now. Otherwise something breaks on Nov 30, probably at night in a run nobody is watching.

Try it Run grep -rn "4-8" ~/.claude .claude across your configs. Five minutes now saves you a broken run on Nov 30.

Addendum: Write Lock Is Now Official

Yesterday we relied on a third-party mirror for 2.1.314. The official changelog now confirms it with the exact name: "Added permissions.blockWritesOutsideWorkingDirectories: Write, Edit and NotebookEdit refuse paths outside the working directories in every permission mode".[1] The important part is "in every permission mode": the lock applies even when you otherwise let the agent run freely.

A smaller detail from 2.1.312 (Oct 27): the usage limit is now called "5-hour limit" in messages instead of "session limit".[1] It's only a new name, but a more honest one. The limit is tied to a time window, not to your session.

My take: Turn on the write lock if you run Claude Code with broad permissions. It only costs you something if your workflow deliberately writes outside the project, for example to /tmp. In that case, add the directory as another working directory.

Gemini 4 Carbon: Ahead, but Only by a Nose

As of Saturday, nothing has changed about access. According to press reports, Carbon goes only to selected cyber-defense companies, through Google's Fairwind program. There is no public timeline.[1] The Google primary source returned no text today; the facts come from secondary press.

Three leaderboards put Carbon in first place. The margins are small, though:

  • Artificial Analysis Intelligence Index: Carbon 59, Opus 5.5 58, GPT-6 Astra 57, GPT-6.1 Sol 55, Sonnet 5.5 54.[2] A general index, not a coding test, and undated on the page.
  • LMArena Text: Carbon 1528 ±9, marked "preliminary". Behind it Gemini 4 Argon 1520 and Opus 5.5 1509.[3] The page is dated Oct 27, so before the announcement. We couldn't read the coding tab.
  • Vals: Vals Index 70.36% (rank 2), Terminal-Bench 4.0 63.13% (rank 4).[4] So for coding, Carbon is in the top group, not at the top.

Google also reports its own safety numbers: 88.2% on SEC-bench Pro and 0% successful prompt-injection attacks in the Grey Swan test. Opus 5.5 is at 1% there, GPT-6 Astra at 8.5%.[1] These are vendor claims. We found no independent measurement.

Prompt Injection: An attacker hides commands in text the agent reads, for example in a README or an issue. The agent takes it for an assignment and carries it out. It's like a forged note saying "Please open the safe" smuggled into the office mail.

My take: A one-point gap in the AA index and 8 Elo points with a margin of error of ±9 are not a lead but a tie. The more interesting number for you is the prompt-injection figure. If it holds up independently, that matters more for agents that read other people's repos than one more point in the index. Until then it remains a claim from the vendor's own test.

GPT-6.1 Terra: Weekly Recap

Terra arrived on Oct 26, at $1 per million input tokens and $5 per million output tokens. The API ID is gpt-6.1-terra, and the model is also available in Codex.[1] OpenAI reports 50.3% on Terminal-Bench 4.0 at the highest effort setting, versus 21.5% for its predecessor GPT-5.6 Terra.[1] OpenAI itself says that for the hardest coding tasks, GPT-6.1 Sol or GPT-6 Astra remain the recommendation.[1]

Independently, Vals puts Terra at 60.17% on the general Vals Index, rank 10 of 28.[2] We only have this number from a search snippet, not from the page itself.

For comparison in the budget tier: according to Anthropic, Claude Haiku 5.5 costs $0.10 and $0.50 per million tokens, for prompts up to 100,000 tokens.[3] Anthropic gives no SWE-bench Verified figure for Haiku 5.5.

Model Cascade: You send every task to a cheap model first. Only if it fails or is unsure does the task go to an expensive one. It's like a help hotline: the first tier solves the easy cases, and the specialists get only the rest.

My take: Terra is exactly what OpenAI promises, a cheap worker. For routine work like renaming, adding tests or summarizing logs, that's enough. For architecture questions it isn't. The real question is whether Terra is worth it over Haiku 5.5 as the first tier of a cascade. By list price, Haiku is ten times cheaper. Without a joint measurement on the same test, that can't be decided. Test it on your own repo.

The Week of Background Agents

Three platforms have taken the same direction in the last twelve days:

  • Cursor Agent SDK (Oct 20): "Agents are defined as code projects, tested with evals, and deployed to Cursor or your own infrastructure." Triggers are GitHub, GitLab, Bitbucket, Slack, webhooks or cron.[1]
  • GitHub Copilot (Oct 28, Universe): Copilot Fusion for routing between models, a standalone Copilot app, Copilot Automations for shared team workflows. Copilot is now included in GitHub Enterprise.[2] We did not open the details of the entries.
  • Cline 4.1.26 (Oct 26): a toggle between local and cloud execution. The default model is now Claude Sonnet 5.5.[3]
Agents as Code: Instead of telling an agent in a chat what to do, you write its task as a small project with tests. An event starts it, for example a new issue or a schedule. It's like the difference between calling a handyman and having a maintenance contract.

My take: This is the most important trend of the week, even though it makes no headlines. The agent moves out of your editor and into the pipeline. For that you need evals, otherwise you won't notice when a model switch makes your agent worse. Cursor's SDK is the clearest approach here, because it ships with evals built in.

Try it Cursor Agent SDK with a cron trigger for a boring task, such as a weekly dependency report. Why: you learn the eval part on a case where a mistake costs nothing.
