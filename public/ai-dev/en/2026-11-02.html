Claude Code: the switch you should set today

Over the weekend the story was the effort dial for subagents. More important, I think, is one line from 2.1.314 on Oct 30: "Added permissions.blockWritesOutsideWorkingDirectories: Write, Edit and NotebookEdit refuse paths outside the working directories in every permission mode".[1] With this setting, the agent can only write in the folders where you started it.

Working directory: The folder where you start Claude Code, plus any folders you add on purpose. The switch puts a fence around exactly those folders. It is like a contractor who may only remodel the kitchen and has no key to the bedroom.

The core is the "in every permission mode". The lock also applies in auto mode, where the agent works without asking. Until now this depended on your allow and deny rules. One forgotten path, and the agent wrote to ~/.zshrc or to a neighboring repo. The lock covers only the file tools. A shell command through the Bash tool is not covered; the sandbox is still responsible for that.

Try it Set the switch to true in your global settings. Why: it costs nothing, and for the rare cases where the agent really should write outside, you add the folder on purpose.

More small things from the week

  • Turn off ultrathink: 2.1.316 brings CLAUDE_CODE_DISABLE_ULTRATHINK, "which turns the ultrathink keyword off".[1] Since 2.1.311 (Oct 26), a turn with ultrathink runs at xhigh effort, on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1. If you manage teams with a cost cap, you can now make the word have no effect.
  • Idle compaction in VS Code and in the Code tab of Claude Desktop: a conversation over 200K tokens that sits idle gets summarized. The summary is used when the prompt cache has expired by the next prompt.[1] That saves a lot of tokens when you come back. The price: details from early in the conversation can be missing.
  • Fast Mode for Opus 4.8: from Nov 30, such requests return an error, with no fallback to regular Opus 4.8. The recommended replacement is Opus 5.5.[1] 28 days left. Check scripts and CI jobs that hard-code the model.

Kimi K3.1 Pro: what to watch on Wednesday

Moonshot has offered Kimi K3.1 Pro through its API since Oct 23, at $2 per million input tokens and $10 per million output tokens. The weights are "planned for release on November 4".[1] According to latent.space, the model has 2.8 trillion parameters, of which 104 billion are active.[2]

Active parameters: Large open models often consist of many specialist parts. For each word, only a small share of them computes, here 104 billion out of 2.8 trillion. It is like a hospital with a hundred doctors, of whom you only see three. That makes it faster, but the whole hospital still has to fit in memory.

My view: this will not run on your machine. 2.8 trillion parameters need several server GPUs even when heavily compressed. Kimi becomes interesting to you as a cheap option at hosting providers. Three things decide on Wednesday whether the release is any good:

  • License: Can you use it commercially, and is there a user limit? The announcement says nothing about this.[1]
  • Completeness: A report in a search snippet says the open version does not include the cyber capabilities. We did not verify that ourselves. If it is true, the open model is not the same as the API model, and API benchmarks do not carry over 1:1.
  • Host pricing: How quickly do third parties offer it below the Moonshot price?

Terminal-Bench scores for Kimi are circulating, but only from snippets we could not load. The announcement itself gives no benchmark number.[1] So no number today.

Terminal-Bench 4.0: a leaderboard of self-promotion

Terminal-Bench 4.0 is the new standard currency for coding models. The problem: for the current models, it lists almost only values the vendor measured itself. On Sonnet 5.5, Mixed writes that all the numbers "come from Anthropic's own page and not from an independent public leaderboard".[2]

ModelTerminal-Bench 4.0Who measures
Claude Sonnet 5.5 (max)70.6%[2]Anthropic
Claude Opus 5.5 (xhigh)66.4%[1]Anthropic
Gemini 4 Carbon65.2%[3]Google, via aggregator
GPT-6.1 Terra (max)50.3%[4]OpenAI

For Opus 5.5, Anthropic gives a margin of error of ±2.6 points.[1] That puts Opus 5.5 and Carbon statistically level. The gaps also come from different effort levels and custom harnesses. Sonnet "max" against Opus "xhigh" is not a fair comparison.

Harness: The program that walks a model through the test tasks: which tools it gets, how often it may retry, how much time it has. A different harness gives a different score. It is like a driving test where every manufacturer brings its own car and its own course.

My view: read the table as two groups. At the top are the three models around 65–70%, and one step below is Terra, which in return costs $1 / $5 per million tokens.[4] If you want the order within the top group, you have to test it on your own tasks. We found no dated SWE-bench Verified score for any of these models. So no chart today.

Octoverse: three times as many pull requests

Simon Willison summarizes GitHub's Octoverse 2026: "Merged PRs reached 220 million per month, roughly tripling in under a year."[1] We did not read the report itself. The number comes from Willison's summary of Oct 28.

My view: a large part of this growth very likely comes from agents opening PRs. The bottleneck moves from writing to reviewing. If you use agents on a team, you should now invest in review tools and tests, not in even more generation.

It's Monday, November second. No new model and no new tool release over the weekend. So we're looking at what from last week is still worth your time, and at the date on Wednesday.

My tip for today is a switch in Claude Code. Since the October thirtieth release, you can set the agent to write files only inside your project folders. That holds in every mode, including auto mode. One caveat: the switch does not cover shell commands. It costs nothing, so turn it on.

Two smaller items. The ultrathink keyword can now be turned off, which helps teams with a cost cap. And fast mode for Opus four point eight goes away on November thirtieth. That's twenty-eight days from now.

On Wednesday, Moonshot plans to release the weights of Kimi K three point one Pro. The model is huge, about two point eight trillion parameters, and won't run on an ordinary computer. On Wednesday, watch the license first, and whether the open version is the same model as the one in the API.

On Terminal-Bench four, keep skepticism. According to Anthropic, Sonnet five point five scores just over seventy percent, and Opus five point five just over sixty-six. GPT six point one Terra comes in around fifty percent, according to OpenAI. These are all vendor-reported numbers with different settings. Read them as groups, not as a ranking.

According to Simon Willison's summary of the Octoverse report, GitHub now sees two hundred twenty million pull requests merged per month, about three times as many as a year ago. The bottleneck is now reviewing, not writing.

Nothing new at Cursor, Cline, OpenHands, Continue, or Aider. Tomorrow we'll see whether Kimi confirms the Wednesday date.
