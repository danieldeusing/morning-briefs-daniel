Claude Code 2.1.318: a release for cron jobs and CI

Today's release has a long list, but almost all of it revolves around one question: what happens when nobody is sitting at the terminal?[1] This matters to you because you run Claude Code as a scheduled task.

1 · The login expiry becomes visible

claude auth status now shows the expiry date of the stored claude.ai login (loginExpiresAt). In the JSON results of claude -p it appears as credential_expires_at. On top of that comes "a one-line stderr warning to claude -p text output, starting 10 days before a stored claude.ai sign-in ends".[1] If the login does expire anyway, the error message now names claude auth login and claude setup-token as the way out.

Try it Run claude auth status once and put the date in your calendar. Or read credential_expires_at in your wrapper script and send yourself a message. Why: an expired login is the most boring reason a morning job fails. Until now, you only noticed when nothing arrived anymore.

2 · No more false success

Two fixes concern exit codes. claude -p and Agent SDK sessions reported success when an API error cut off a response while a mod was stuck on turn.step. That is fixed.[1] And jobs that aborted with Not logged in because another terminal re-authenticated with the same account now keep running.[1] Together with the exit code 1 on a full disk from 2.1.317, that means: your cron job lies less often.

3 · Background shells and the prompt cache

Background subagents now push a shell command into the background after three minutes on all providers, "so the prompt cache doesn't expire while it runs".[1]

Prompt cache: The provider remembers the long beginning of your conversation (system prompt, files) for a few minutes. If you send the next request in that time, it doesn't pay for the beginning in full again. It's like a waiter who still has your order in his head. If you wait too long, you have to list everything again, and that costs money.

My take: this is a quiet cost brake. An npm test that runs for ten minutes used to let the cache expire, and the next round got expensive.

4 · Smaller items that can affect you

  • IDE extension: Claude Code no longer installs or updates it on its own when you start it in the IDE terminal. Use /ide from an external terminal or your editor's extension panel.[1]
  • deniedMcpServers: URL entries now also block servers provided by Anthropic if their upstream URL matches.[1] If you maintain a blocklist, take a quick look at it.
  • claude mcp add and remove now wait for the config file lock or end with exit code 1.[1] Important if scripts call them in parallel.

From 2.1.317 (yesterday), what we didn't have yet

  • The Read tool stub is removed: "reading an unchanged file again returns its content".[1] That is more honest for the model, but can cost more tokens if an agent reads the same large file often.
  • Fixed: "Claude treating partial Grep and Glob results as complete when a search hit its time limit".[1] That was a real bug. The agent concluded from an aborted search that something doesn't exist.

Kimi K3.1 Pro: the day is here, the weights aren't

Moonshot wrote on Oct 23: "Full model weights will be released by Nov 4, 2026."[1] That is today. When we checked this morning, Moonshot's Hugging Face page still showed no K3.1 repo. The newest Kimi model there is Kimi-K3 from Sep 2.[2] "By Nov 4" can also mean the evening in Chinese time. So we don't count this as a delay yet.

Open weights: The model itself, meaning the billions of learned numbers, is available to download. You or a host can run it on your own hardware. It's like a recipe instead of a restaurant: you no longer depend on one kitchen.

For context: in the API, Kimi K3.1 Pro costs $2 per million input tokens and $10 per million output tokens.[1] On Oct 23, Artificial Analysis gave the model an index value of 55, "only Claude Opus 5.5 scored higher, at 58".[1] Since then, Gemini 4 Carbon has moved above it. Moonshot has not published a license, a parameter count or a SWE-bench value.

My take: the model is too big for your laptop. It gets interesting through the hosts. If the weights arrive, the license and the question of whether the open version is the same as the one in the API will decide. An open model at frontier level would push down the price of coding agents, including for Claude users. We'll check again tomorrow.

Benchmarks: one point apart, and none of it measures coding

On the Artificial Analysis Intelligence Index, Gemini 4 Carbon (effort "high") stands at 60, Claude Opus 5.5 ("max with fallback") at 59 and GPT-6 Astra ("max") at 57.[1] On Oct 31 we had read Carbon 59 and Opus 5.5 58 in the same place. So both rose by one point, probably through new variants or test runs. The page carries no date.

Intelligence Index: An independent company runs every model through the same mix of tests and sums up the result in one number. It's like a report card grade across all subjects. It tells you who is good overall, but not who is best at math.

More interesting for you is the second column, the cost per test run. Carbon comes to $7.76, Opus 5.5 to $10.04 at "max" and to $6.05 at "xhigh" (index 57).[1] If you go down one level on Opus, you lose two points and save about 40% per run.

For coding there are only vendor numbers. On Terminal-Bench 4.0, Anthropic reports 66.4% for Opus 5.5 at xhigh.[2] For Carbon, an aggregator cites 65.2% under Google's own method.[3] We found no SWE-bench Verified value for either. My take: a one-point difference on a composite index is noise. And as long as Carbon is not public, nobody can test it on real repos. That's why there is no chart today.

Carbon has been available since Oct 28 only to cyber defenders in the Fairwind program. According to DevelopersDigest it costs $2 / $10 per million tokens at launch, later $4 / $20.[4] That would be the same list price as Opus 5.5 ($4 / $20).[2] We could not retrieve anything on this from Google itself.

Local: an LLM writes weights, and Qwen 3.8 can too

The paper "Sparks of Weight-Space Programming" (Takehi, Teoh, Zhang, Khattab) claims that LLMs can directly read and write the weights of small neural networks without training them.[1] Simon Willison rebuilt an example and writes: "Qwen 3.8 27B running on my laptop can do this as well!"[1]

Weights: The numbers in a neural network that determine what it does. Normally you find them through training, meaning long trial and error. Here the model writes them down directly, like someone who writes a melody straight into notes instead of searching for it on the piano.

Try it If you already have Qwen 3.8 27B locally, Willison's example makes a nice evening test. Why: it shows how far a model of this size can now go on your own hardware. For your daily work, the paper changes nothing.
