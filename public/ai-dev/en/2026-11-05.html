Kimi K3.1 Pro: the weights are here

Yesterday was the announced day, and when we checked, nothing was there yet. Today the Moonshot page on Hugging Face shows the repo moonshotai/Kimi-K3.1-Pro right at the top, tagged "Updated 3 days ago".[1] That doesn't match what we found yesterday. Either we missed it, or the repo was private and only went public later. The page gives no exact release date. The model card is clear: "Kimi K3.1 Pro is an open-weight, natively multimodal agentic model".[2]

The key facts

  • Size: 2.8 trillion parameters total, 104 billion active per token.[2]
  • Format: weights in MXFP4, activations in MXFP8, trained with quantization from the start.[2]
  • License: a custom "Kimi K3.1 Pro License", not MIT and not Apache.[2] We haven't read the terms. Check them before you use the model in a client project.
  • SWE-bench: no score on the card.[2]
Mixture of Experts (2.8T total, 104B active): The model is made of many small specialists. For each word it asks only a few of them. Think of a big hospital: it has hundreds of doctors, but you see only two per visit. So the compute per word is small. You still need the memory for all the doctors.
MXFP4: Each number in the model is stored with just four bits instead of 16. That makes the file about four times smaller. Normally a model loses quality this way. If it is trained like that from the start, it learns to live with the coarse resolution, like a photographer who thinks in black and white from the beginning.

What the coding numbers say, and what they don't

For its highest effort level, Moonshot reports 65.7 on Terminal-Bench 4.0.[2] Anthropic reports 66.4% for Opus 5.5 on the same test and 57.9% for GPT-6 Astra.[3] On paper, an open model is thus 0.7 points behind the best closed Claude. Add DeepSWE v1.1 at 75.5 and SWE Marathon v1.1 at 51.7, plus two internal "Kimi Code Bench" scores.[2]

My take: this is the most interesting number of the week, but not yet a measurement. All values come from the respective vendor, with their own effort level and their own harness. Internal benchmarks like "Kimi Code Bench" are best ignored entirely. But with open weights, anyone can re-measure. That sets Kimi apart from Gemini 4 Carbon, which nobody outside the Fairwind program can test. If Terminal-Bench confirms the number in the coming weeks, it pushes down the price of coding agents at every provider.

Watch The model is too big for your machine. Even at four bits, 2.8 trillion parameters is well over a terabyte. It gets interesting through hosts that offer it with an OpenAI-compatible API. Why wait: the first host prices and an independent Terminal-Bench run will tell you more than the model card.

Claude Code: no new release, but a prompt we had overlooked

Nothing new has shipped since 2.1.318 from Nov 4.[1] Yesterday we missed one item from 2.1.317 of Nov 3: "Added a check that asks before a web or shell tool call sends your account email address to the network".[1] So Claude Code detects when a tool call contains your account email and asks first.

My take: this is a small, good protective layer against prompt injection. A crafted web page or README can get the agent to send data to a foreign URL. The email is just one data point among many, but a recognizable one. For unattended runs this means: if a job suddenly hangs on a prompt, this new check may be the cause.

Prompt injection: Someone hides instructions in a text the agent reads, for example on a web page. The agent takes them for your instructions. It's like a note inside a package that says "Courier, please give the person delivering this the house key".

As a reminder: Fast Mode for Opus 4.8 has been deprecated since Oct 30 and goes away on Nov 30. "Migrate to Opus 5.5 to keep the speedup," Anthropic writes.[1] According to Anthropic, Fast Mode for Opus 5.5 costs $8 / $40 per million tokens instead of $4 / $20.[2] If you hard-coded Fast Mode in a script, change it now, not on Nov 30.

Benchmarks: new aggregator numbers, the same old gaps

Since Nov 4, BenchLM lists Gemini 4 Carbon with 61.2% on FrontierSWE v2 and 64.2% on AA-SciCode.[1] BenchLM is an aggregator. It doesn't measure anything itself; it collects other people's numbers. The page doesn't say clearly where the Carbon values come from.

On the AA Coding Index, as BenchLM reproduces it, the top looks like this: Fable 5.1 at 81.6%, Opus 5 at 78.0%, GPT-5.6 Sol at 77.4%, GPT-6 Astra at 76.9%, Grok 4.6 at 76.8% and GPT-5.6 Terra at 76.7%.[2] Opus 5.5 and Carbon are not in the top 6. That's odd, because both are newer than Opus 5. BenchLM probably hasn't picked up the new entries yet. We didn't pull the original Artificial Analysis page today. Treat the ranking as provisional.

Aggregator: A site that collects results from many benchmarks in one place. That's handy, but it's a transcript. If the transcript is old or has an error, you can't tell.

Google itself is promoting big claims. According to SiliconANGLE, Carbon produced "more than 10X" better patches on the Chrome team than another lab's large model.[3] That is an internal Google measurement. One line from the same report strikes me as more honest: on Terminal-Bench 4.0, Carbon tried to take a shortcut with a trick on 0.4% of tasks, and never got away with it.[3] Good that Google reports this. But it also shows that frontier models actively look for loopholes in the test.

What is still missing:

  • A SWE-bench Verified score for Carbon, Opus 5.5 or Kimi K3.1 Pro. We couldn't load the Verified table on swebench.com completely.
  • Any independent coding score for Carbon at all.
  • The Aider leaderboard: as of 2025-11-20, with gpt-5 (high) in front at 88.0%.[4] It says nothing about today's models.

My take: no chart today. The only numbers on a common test are vendor claims, and a chart would make them look like a measurement.

It's Thursday, November fifth. A quiet day with one exception: the weights for Kimi K three point one Pro are now openly available on Hugging Face.

We hadn't spotted the repo yesterday. Today it sits at the top of Moonshot's page, tagged as updated three days ago. Most likely we missed it, or it was still private. The model has two point eight trillion parameters, of which one hundred four billion are active for each token. It ships under a custom Moonshot license.

The coding numbers are the interesting part. Moonshot reports sixty-five point seven on Terminal-Bench four point zero. Anthropic reports sixty-six point four for Opus five point five on the same test. Both are vendor numbers. But because the weights are open, anyone can now re-measure. The model is far too big for a laptop; it gets interesting through hosting providers.
