Codex CLI 0.167.0: one command center for many agents

The release landed overnight at 01:40 (timestamp from GitHub). The note is terse: "Adds an agent command center (codex agents --no-daemon), plus backend switching and Vertex AI setup in the TUI".[1] So that's three things at once.

  • Agent command center: one place in the terminal where you see and control several running Codex agents. The --no-daemon switch suggests it otherwise runs through a background service. We have not tested the exact usage.
  • Backend switching: you can switch in the interface where the model runs.
  • Vertex AI setup: Codex can be set up directly through Google's cloud. For companies that already have their AI budget at Google, this is the most important point.
TUI (Text User Interface): An interface that runs entirely in the terminal, with menus and windows made of text characters. It's like a ticket machine from the nineties: no mouse, but everything on one screen.
Daemon: A program that keeps running invisibly in the background, even when you close the window. It's like a janitor who stays in the building at night.

My take: the trend is clear. All the big harnesses are building a control room for parallel agents right now. Cursor has its cloud agents and, since Oct 20, an Agent SDK, Copilot has Fusion, and Codex now has the command center. The bottleneck is no longer a single agent, but keeping track of five at once. I like that Codex builds its own command for this instead of a web interface. It stays scriptable.

Try it codex agents --no-daemon in a test repo. Why: in five minutes you'll see whether the command center really makes parallel work clearer for you than several terminal tabs.

The rest of the OpenAI changelog from recent weeks fits in here: GPT-6.1 Terra arrived on Oct 26, described as "a fast, efficient model for visual reasoning, precise computer use, and clear, natural writing".[2] Since Oct 20 there has been prompt caching for 12 hours. Writing to the cache costs 2.5 times the normal input price, though.[2] That only pays off if you reuse the same long context several times a day, for example a large repo for many agent runs.

Prompt caching: The provider remembers the beginning of your request, for example your whole codebase. Next time you pay less for that part. It's like a copy shop that scans your original once: the scan costs extra, every further copy is cheap.

Cursor now builds and hosts entire apps

The new entry in the Cursor changelog from Nov 5 is titled "Build Live Apps in Cursor". According to Cursor, you can "build live apps directly in Cursor and share them with a link".[1] Cursor handles the scaffolding, the database, the login and the hosting. The key sentence for me: "Nothing goes live until the checks pass and you explicitly publish the app."[1] Which checks those are, the summary doesn't say.

My take: this puts Cursor in direct competition with Bolt, Lovable and Replit. Until now, Cursor was an editor for developers. Now it also wants to be the place where the app runs. For quick prototypes and internal tools that's convenient. For client projects I see three questions the changelog doesn't answer:

  • Where does the data live, and can I export it?
  • Can I later move the app to my own host, or am I stuck with Cursor?
  • What do the security checks cover, and what don't they?

An automatic check before publishing is good. But it doesn't replace a review. Generated apps with login and database are exactly the kind of code where missing authorization checks slip through.

Try it Build a small internal tool, for example a form with a list. Why: that shows you how much control over database and login you really keep, before you plan it for clients.

For context: on Oct 16, Cursor shipped Cloud Agent Canvases and an Environments API in beta, for up to 300 repos. On Oct 20 came the Agent SDK.[1] So Cursor is quickly building an entire platform around the editor.

GitHub Copilot: Xcode, JetBrains Air and model routing

Three entries in the Copilot changelog that we hadn't covered before:[1]

  • Nov 4: "GitHub Copilot is now available in Xcode's coding assistant". So Copilot now lives inside Apple's own assistant, not just in an extension.
  • Nov 3: Copilot in JetBrains Air.
  • Oct 28: "Route and orchestrate models with GitHub Copilot Fusion".
Model routing: A dispatcher decides for each task which AI model gets it. Simple questions go to a small, cheap model, hard ones to a big one. It's like an emergency room: the nurse at the entrance sends the sniffles to the family doctor and the broken leg to the surgeon.

My take: Copilot doesn't win with the best model, but by being everywhere. Xcode was a gap for a long time because Apple keeps its IDE tightly closed. Fusion is the more interesting news for you. If GitHub itself decides which model gets your request, cost and quality change without you noticing. We did not read the details on Fusion today. Check whether you can turn the routing off or pin a specific model.

GPT-6-Cyber: a model only for security work

Since Nov 5, the OpenAI changelog says: "Use GPT-6-Cyber to investigate vulnerabilities, reproduce them in an authorized test environment, and verify fixes."[1] So the model is meant to find vulnerabilities, reproduce them in authorized test environments and check whether a fix really closes them.

My take: this is the answer to Gemini 4 Carbon, which according to Latent Space Google also launched "for cyber defenders".[2] For you as a developer, the third point is the most useful: fix verification. A model that, after a security patch, deliberately tries to exploit the hole again is a good complement to your tests. The changelog entry gives neither access conditions nor price. Expect that it is not simply open to everyone.

Gemini 4 Carbon: two numbers, two measures

Latent Space wrote on Oct 29: "Gemini 4 Carbon tops leaderboards, launches for cyber defenders."[1] A week later, the data is still thin.

  • Terminal-Bench 4.0: the aggregator BenchLM lists 65.2%, the model score from Google's launch table, which Artificial Analysis also lists.[2] The 64% in other reports is a Coding Agent Index figure for the Antigravity CLI harness, a different measure.[3] So the two numbers do not contradict each other.
  • FrontierSWE v2: 61.2%, FrontierCode 2.0: 40.0%, both per BenchLM.[2]
  • AA Coding Agent Index: according to reports, Carbon scores 59 in the Antigravity CLI, Claude Code with Opus 5.5 at the highest setting scores 62.[3] We did not retrieve the original page.
  • SWE-bench Verified: no value, neither for Carbon nor for Opus 5.5.
  • Availability: in the Gemini API, according to one report, only Gemini 4 Argon is generally available, Carbon is not yet.[3] We did not find an official Google page on this.
Terminal-Bench: A test where an agent has to solve real tasks on a command line, for example building a project or finding an error on a server. It's like a practical driving test instead of a theory test: what counts is whether the car ends up in the parking spot.

My take: apart from Artificial Analysis, nobody has reproduced Google's launch figures yet. In the Artificial Analysis Intelligence Index v5, Carbon scores 59 and Opus 5.5 scores 58, according to secondary sources (aicybr, braindetox). For Opus 5.5, llm-stats.com lists 89.9% on SWE-bench Pro, a vendor claim. The site itself writes: "None of the launch scores are LLM Stats verified yet."[4] SWE-bench Pro is also a different test from SWE-bench Verified, so the numbers are not comparable.

No chart today. There is still no SWE-bench Verified value for either Carbon or Opus 5.5. A chart would fake a ranking that nobody has measured.

Claude Code: quiet, but Nov 30 is coming

The current version is still 2.1.318 from Nov 4.[1] Two points from the latest releases matter for everyday work:

  • 2.1.316 (Oct 31): "Deprecates fast mode for Opus 4.8, which is removed on November 30, 2026".[1] If a script or setting of yours uses fast mode with Opus 4.8, you have 24 days left.
  • 2.1.314 (Oct 30): the new setting permissions.blockWritesOutsideWorkingDirectories.[1] With it, the agent can't write files outside the working folder.

Try it Set blockWritesOutsideWorkingDirectories for unattended runs. Why: an agent that goes astray because of a crafted README then can't write into ~/.ssh or your shell configuration.

From the rest of Anthropic, only one point is relevant for coding: on Oct 22, Anthropic handed its Agent Skills over to the Agentic AI Foundation.[2] That makes skills, similar to MCP, an open standard instead of a Claude feature. The Anthropic news page shows no entries newer than Oct 28.

All the major tools are building this kind of control room right now, because the bottleneck is no longer a single agent, but keeping track of five at once.

Cursor goes a step further. Since yesterday, you can build entire web apps in Cursor, with a database, login and hosting, and share them with a link. But for client projects, questions remain, such as where the data lives and whether you can move later.

For Gemini four Carbon, the picture is clearer now. The sixty-five point two percent on Terminal-Bench is Google's figure, which Artificial Analysis also lists.
