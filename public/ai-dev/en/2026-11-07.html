Claude Code 2.1.319: the agent no longer waits

Yesterday we wrote here that Claude Code had been silent since Nov 4. On Friday 2.1.319 did arrive after all, at 17:04 according to GitHub.[1] The note is long, but three points change your daily routine.

  • MCP tasks in the background: “when an MCP server runs a tool call as a task, Claude Code moves it to the background right away and tells Claude the result when it finishes”.[1] If you want the old behavior, set CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND.
  • Deny instead of asking: With permissions.denyInsteadOfPrompting, a tool call that would wait for a prompt is denied, “and the turn continues, in terminal sessions, subagents and teammates”.[1]
  • Auto Mode behind gateways: Behind an LLM gateway, or with telemetry turned off, there is no longer a fallback to the built-in classifier. Calls the server cannot check are prompted or denied. CLAUDE_CODE_AUTO_MODE_SERVER=0 brings back the old behavior. Bedrock, Vertex and Foundry are not affected, according to the note.[1]
MCP task: MCP is the standard through which an agent calls external tools, for example a database or a build server. A “task” is a call that takes a long time and delivers its result later. It's like a package at the post office: You drop it off and leave, and the post office gets in touch when it has arrived.
Auto Mode: Claude Code decides for itself which actions may run without a prompt. A checker on the server evaluates risky actions. It's like a doorman who opens the gate for familiar faces and calls up for strangers.

My take: denyInsteadOfPrompting is the most important line for anyone who runs Claude Code unattended. Until now, an overnight run got stuck on a prompt nobody answers. Now the agent gets a no and carries on. That is the right default for automation: better a denied action in the log than a run that waits eight hours. A second change fits with this: claude -p now exits with code 1 when Auto Mode denies actions for lack of a safety check. Before, it returned code 0.[1] A script that used to report “green” can now turn red. That is more honest, but check your cron jobs.

The gateway change is the riskier one. It is meant to be safer, but if you run Claude Code through your own gateway, you suddenly get more prompts or denials. Together with denyInsteadOfPrompting that means: silently denied actions. After the update, read the log of an automated run once.

Try it permissions.denyInsteadOfPrompting in the settings for an overnight run. Why: In the morning you see in the log which actions the agent wanted and was not allowed to do. That makes a good list for your permission rules.

From the two releases before:

  • 2.1.318 (Nov 4): Background subagents push a shell command to the background after 3 minutes, “so the prompt cache doesn't expire while it runs”.[1] That saves money on long builds.
  • 2.1.317 (Nov 3): onFailure: "block" for hook callbacks in the Agent SDK. A failing hook now blocks the action instead of letting it through.[1] In addition, subagents on a different model now use that model's own effort level instead of the session's.
  • Fast Mode for Opus 4.8 is removed on Nov 30.[1] 23 days left.

According to Latent Space, the claude-code repo has 16,060 open issues, of which 15,766 have no assignee.[2] We did not count that number ourselves. But it fits the picture: The tool grows faster than anyone can triage the bug reports.

Kimi K3.1 Pro: the weights are really there

Moonshot had promised the weights for Nov 4. On Oct 24 they were not there yet.[1] Today the repo moonshotai/Kimi-K3.1-Pro is on Hugging Face, with Safetensors files, 2.8 trillion parameters in total and 104 billion active.[2] The page shows no exact release date, the organization page only says “updated 2 days ago”.

Mixture of Experts (active parameters): The model consists of many sub-networks, the “experts”. For each word only a small part of them works, here 104 billion of 2.8 trillion. It's like a hospital with a hundred specialists: Each patient sees only two or three, but all hundred still need an office. So for memory the big number counts, for speed the small one.

The numbers, as far as independently measured:

  • Terminal-Bench 4.0 at Vals: 63.64% (±1.75), rank 3 of 61. Claude Opus 5.5 is at 65.15%.[3] The gap of 1.5 points is within the margin of error. Vals is an independent evaluator, so this is the most reliable number here.
  • Arena WebDev: rank 8 with 1,692 points, the predecessor K3 had 1,655.[1] That is a vote by humans, not a test.
Terminal-Bench: A test in which an agent has to solve real tasks in a command line, for example build a project or find a bug on the server. It's like a practical driving test instead of a theory test.

My take: An open model one and a half percentage points behind the best closed one is the real news of the week. For your laptop it makes no difference. 2.8 trillion parameters only run on a server cluster. It matters for price: Any host can now offer K3.1 Pro, and that pushes down what Anthropic and OpenAI can charge for agent runs. One caveat: The license is called “Kimi K3.1 Pro License”, so not a standard license like Apache 2.0.[2] Read it before you plan the model into client work.

Rumors for next week: Inkling 2 and Qwen 4

Two announcements are circulating, both only secondhand. I mention them so you can place them when they come. Not because they are true already.

  • Inkling 2 Small from Thinking Machines: according to Latent Space an MoE model with 594 billion parameters, 17 billion active, weights “next week” under Apache 2.0. In Code Arena WebDev it is said to stand at rank 8 with 1,648 points.[1] We did not find a page from Thinking Machines itself.
  • Qwen 4: Qwen teasers are being read as hints of a Qwen 4 release. Nothing is confirmed, and I found no sourced quote for it.[1]

My take: Inkling 2 Small is the more interesting size. 17 billion active parameters are fast, but 594 billion in total won't fit on a normal machine either. If the Apache license holds, it is still a candidate for companies that want to self-host. For local work, until then, Qwen 3.8 in the 27B size remains the realistic candidate, the one Simon Willison wrote about on Nov 3.[2]

89.9% on SWE-bench Pro: a number without witnesses

The aggregator BenchLM updated its SWE-bench Pro board on Nov 6. At the top is Claude Opus 5.5 with 89.9%, then Sonnet 5.5 with 81.3% and Fable 5.1 with 81.2%.[1] Yesterday we saw the same number at llm-stats.com as a vendor claim. Two aggregators copying the same vendor number are not two measurements, though.

Three reasons why I'm not putting the number in a chart:

  • No independent measurement. Neither Anthropic nor an independent evaluator has confirmed it, as far as we could retrieve.
  • The test itself wobbles. BenchLM writes on the same page: “a July 2026 audit estimated about 30% of the public split is broken”.[1] If a third of the tasks are faulty, a value near 90% mostly measures how well a model copes with the broken tasks.
  • Mixed setups. Each vendor tests with its own agent harness. So the board compares model plus tooling, not the model alone.
SWE-bench Pro: A collection of real bug reports from software projects. The model has to fix the bug, and the project's tests check the result. It's like a workshop exam with real broken cars. But if a third of the exam cars were already mislabeled beforehand, the grade says little.

The more interesting number comes from the same Latent Space issue: Opus 5.5 costs $1.64 per task there, about 29 times GPT-6.1 Sol, and needs around 27 turns instead of about 8.[2] The summary doesn't say which benchmark that is, and I could not verify the number. So I take the number only as a direction. But the direction matters: With agents, it's not only percentage points that count, but also how many turns and dollars a model needs to reach a solution. A model that is three percentage points better and costs 29 times as much is the wrong model for a batch of 200 tickets.

For SWE-bench Verified there is no value today: The leaderboard page loads its table via JavaScript, and the fetch returned no rows. Hence no chart.

Agents leave the editor: Cursor by voice, Copilot in chat

Two small items from Friday show the same direction.

  • Cursor “Voice Chat with Agents” (Nov 6): You talk to your agents. The feature “runs on Grok Voice, with several voices to choose from”.[1] A day earlier came “Build Live Apps”: Cloud agents build web apps with a Postgres database and Cursor login and put them online.[1]
  • Copilot in Slack and Teams has been generally available since Nov 6.[2] Add to that Xcode (Nov 4) and JetBrains Air (Nov 3), which we wrote about yesterday.

My take: The editor is no longer the only place where code gets made. You hand off a task in the team chat or by voice, and a cloud agent works through it. For you as a solo developer, voice is more of a gimmick. For teams, Copilot in Slack is more serious: Then anyone in the channel can point an agent at the repo. Clarify beforehand who has which permissions. That Cursor relies on Grok for voice and not on OpenAI or Google is a remarkable choice. On data, the changelog says only this: with Privacy Mode on, voice chat runs with zero data retention.

Small tools: LLM 0.37 and a sentence about trust

Simon Willison's command-line tool llm can handle GPT-6.1 Sol and Terra in version 0.37 (Nov 2). The new default model is GPT-6 Luna.[1] If you use llm in scripts without a fixed model, you get a different model after the update. Pin the model with -m.

Try it llm for small shell tasks next to your agent. Why: For “summarize this log” you don't need a whole agent run, and llm switches the model with a flag.

On Nov 1, Willison quoted the developer Kyle Kingsbury: LLMs undermine the old signals by which you recognized mature software and good documentation.[1] For me that is the most important thought of the week. My reading: A well-kept README and lots of commits prove little if an agent produces both in an hour. So check a new library by its users, issues and maintainers, not by the length of its docs.

It's Saturday, November seventh. It's the weekend for the vendors, but two things are new since yesterday.

Claude Code did ship a new version on Friday after all, two point one point three one nine. Long MCP calls now run in the background right away, and the agent gets the result when it's done. With a new setting, Claude Code denies an action instead of waiting for a prompt, and keeps going. For overnight runs, that's exactly the right behavior.

A word of caution for anyone running Claude Code through their own gateway. There, Auto Mode no longer falls back to the local checker. And the command claude dash p now reports an error when actions are denied for safety reasons. So a script that used to be green can turn red. Fast Mode for Opus four point eight goes away in twenty-three days.

The second story: Moonshot's Kimi K three point one Pro is now really out as an open model on Hugging Face. It has two point eight trillion parameters, of which one hundred four billion are active. The independent evaluator Vals measures sixty-three point six four percent on Terminal-Bench, and Opus five point five sits at sixty-five point one five. The model is far too big for a laptop, but it puts pressure on the prices of the closed models. The license is a custom one, not a standard license.

Two rumors are making the rounds for next week. Thinking Machines is said to release the weights of Inkling 2 Small under an Apache license, and Alibaba is said to bring Qwen four. Both are so far only secondhand.

One number I don't trust: eighty-nine point nine percent for Opus five point five on SWE-bench Pro. It only shows up at aggregators, and the site itself warns that about a third of the tasks are faulty. A more interesting figure is a cost number from Latent Space: Opus five point five is said to cost about twenty-nine times as much per task as GPT six point one Sol. With agents, turns and dollars count too, not just percentages.

Also: Cursor now lets you talk to agents by voice, built on Grok Voice. Copilot is generally available in Slack and Teams. The editor is no longer the only place where code gets made. And Simon Willison's tool llm has a new default model, so pin your model in scripts.

Among the open-source agents, OpenHands already has another new version. Cline, Continue and Aider stay quiet. Next week we'll see whether Inkling 2 and Qwen four really arrive, and whether anyone independently re-measures Opus's SWE-bench number.
