SWE-2 Flash: Devin trades depth for speed

Cognition, the company behind Devin, has released SWE-2 Flash. Cognition's original post is dated Nov 4.[1] All numbers below are Cognition's own claims.[1]

  • Speed and price: 3× faster and 1/5 the price of SWE-2.[1]
  • FrontierCode 2.0: 24.0 versus 23.8 for SWE-2. On par here.[1]
  • Terminal-Bench 4.0: 20.0 versus 27.3 for SWE-2.[1]
  • DeepSWE 1.1: 60.1 versus 73.0 for SWE-2.[1]
  • Base: built on Inkling-Small.[1]
  • Access: only in Devin Desktop and Devin CLI, "free through 11/30". Cognition names no API. The weights are not public yet; Cognition plans to share them with partners and research labs, details "in a few weeks".[1]
Terminal-Bench: A test where the model has to solve real tasks on a command line: install packages, hunt down errors, fix scripts. Many steps in a row, with no help. It is like a driving test in city traffic instead of a written exam.

My take: The numbers are more honest than they first look. Cognition itself shows where Flash loses. And it loses exactly where long, multi-step tasks are measured: 7 points on Terminal-Bench, 13 on DeepSWE. On FrontierCode, which means shorter coding tasks, it keeps up. That fits the pattern of all "Flash" models: good for the quick loop, weaker on the long haul. Use it for small fixes and tests, not for a refactor across ten files.

Try it SWE-2 Flash in Devin, while it costs nothing until Nov 30. Why: You can spend a week measuring how often the fast model is enough for your daily work. That tells you more than any vendor number. Without a Devin account, it is not worth the effort.

Kimi K3.1 Pro: open weights, and the number holds up

Moonshot AI has put the weights of Kimi K3.1 Pro on Hugging Face. IT之家 reports this on Nov 5; it had been promised for Nov 4.[1] The model itself arrived via API back on Oct 23.[2] It is an MoE model with 2.8 trillion parameters and 1 million tokens of context. In BF16 the weights are about 5.6 TB.[3]

MoE (Mixture of Experts): The model is made of many sub-networks, and for each word only a small part of them does the computing. It is like a hospital with many specialists: you only see two of them, but the building still needs room for all of them. That is why an MoE model is fast but huge on disk.

Now the interesting part, the cross-check:

  • Moonshot reports 65.7 on Terminal-Bench 4.0; Opus 5.5 has 66.4 in the same table.[3]
  • Vals.ai independently measures 63.64% (±1.75), rank 3. The page was last updated on Oct 24.[2]
  • On Vibe Code Bench v1.1, Vals.ai measures 84.89%, only rank 18 of 125 there.[2]
  • In a table that ThursdAI shows, Kimi scores 31.5 on Program Bench, Opus 5.5 scores 65.0.[4] We only know this number from the summary.

My take: A gap of a little over two points between vendor and independent measurement is close to the margin of error. That is a good sign for Moonshot's numbers. But the other benchmarks show an uneven profile: strong in the terminal, clearly weaker elsewhere. So it is an open model on par with Opus 5.5 on only one benchmark. It will not run on your laptop anyway. For you, it counts as price pressure: any provider can host it.

Heads up on the license: Large products must display the Kimi name, and large API resellers need their own contract.[4] For an internal tool, that does not matter. For a product, read the license first.

Cursor: publish apps online and talk to the agent

Cursor had a full week. On Nov 5 came "Build Live Apps": cloud agents build an app, set up a database and login, and put it online. According to the changelog, "you can build live apps directly in Cursor and share them with a link". Every publication has to pass security checks.[1]

On Nov 6 came Voice Chat: "You can now talk with your agents in a realtime voice call." It works in the Agents Window, in the IDE, on the web and on iOS.[1]

My take: Cursor is going after Bolt and Lovable directly here, not Claude Code. The security check before every publication is the most important sentence in the changelog. An app with a login that an agent builds and publishes on its own is otherwise an attack target with a shareable link. I find voice chat of little use for code. But it can help when reviewing a long agent run from your phone.

Claude Code and Codex: a weekend without a new stable version

Claude Code is still at 2.1.319. The tracker havoptic gives Nov 6; releasebot first saw the version on Nov 7. We found no newer version on either site.[1][2] As a reminder: in 2.1.319, MCP tasks run in the background, and an environment variable restores the old waiting behavior. The permissions.denyInsteadOfPrompting setting is new as well.[1][2]

MCP (Model Context Protocol): A standard through which an agent talks to external tools, for example a database or Jira. It is like a wall socket with a fixed shape: any device with the matching plug works right away.

At OpenAI, Codex CLI 0.167.0 from Nov 6 remains the stable version. It opens a command center for agents with codex agents --no-daemon. You can switch between connected backends in the terminal and keep your drafts.[3] On Nov 6 and Nov 7, 0.169.0-alpha.2 and alpha.3 arrived without release notes.[3]

My take: Two tools, one goal. Both are building a control room for many agents running side by side. A weekend without a stable release is normal, not a sign of stagnation.

PR descriptions: the underrated agent task

Simon Willison writes today: "Most of the changes I make to my projects these days come in the form of PRs opened for me by Claude Code or Codex."[1]

My take: This is the best task for an agent that hardly anyone uses. The agent knows the diff, the tests and the reason for the change, because it just made them. A human writes "fix stuff" after three hours of work. Still, read the text before you submit. An agent sometimes describes what it meant to do, not what it did.

Try it On your next PR, let the agent write the description, with the diff and the test command as context. Why: It costs nothing, and your reviewer saves time.

Open weights and local: Ripple, DeepSeek, inferd

  • Ripple-65B Preview (Ricursive): a dense 65B model under Apache 2.0. Self-reported: 80.5% on TerminalBench 2.1, just ahead of Reflection Beam at 80.1%. It trails on DeepSWE and SWE-bench Verified.[1] Quantized, it fits a workstation better than a laptop.
  • DeepSeek Harness Creator Mode: an update to DeepSeek's coding harness that turns prompts into plugins. There are no benchmark numbers.[1]
  • inferd (Incept5): an open-source inference engine for the Mac that, according to a presentation slide, serves up to 128 agents at once.[1] We have no measurement of our own.
Dense model: The opposite of MoE. For every word, all parameters take part in the computing. It is like a family doctor who does everything personally: smaller than a hospital, but every request costs their full time.

My take: Ripple is the most interesting model here, because Apache 2.0 has no naming requirement, unlike Kimi. But the 80.5% is self-reported on an older benchmark version. Wait for an independent measurement.
