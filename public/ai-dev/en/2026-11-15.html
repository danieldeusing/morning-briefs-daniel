Claude Code: four security fixes in one week

Yesterday was about the zstd fix in 2.1.325. But it was not the first security fix of the week. Version 2.1.321 from Nov 10 had already closed three holes in the permissions system, according to labmemo's summary:[1]

  • MCP OAuth: When an MCP server redirected an OAuth request, Claude Code sent secrets such as refresh tokens to a different host.
  • Bash outside the sandbox: Commands that Claude Code classified as "read-only" sometimes ran outside the sandbox and without a prompt.
  • cp and mv: Deny rules and the protection of protected files did not apply to files these commands wrote into a directory.
  • zstd (2.1.325, Nov 13): a security problem when decoding compressed responses.[2]
Refresh token: When you log in via OAuth, your client gets two keys. The access token opens the door for a short time. The refresh token keeps fetching a new access token, often for weeks. Whoever holds the refresh token is effectively you until someone revokes it. That is why a leak of exactly this key is serious.

The most important sentence is not in the release notes, though. According to labmemo, npm latest pointed to 2.1.321 on Nov 10, but the stable channel of the native installer was still on 2.1.311. No official document said when stable would catch up.[1] So anyone on stable had none of the three fixes that day. We did not check the current state of stable today.

My take: three of the four fixes hit exactly the boundaries you rely on with an agent: what it may do without asking, where its tokens go, and which files it must not touch. If you use third-party MCP servers with OAuth, you should seriously consider revoking the affected tokens. There is no evidence of abuse, but a fresh login takes two minutes.

Try it Run claude --version and make sure at least 2.1.325 is running. If it shows a version below 2.1.321, switch to latest or update by hand. Why: stable is the slow channel here, and these fixes should not wait.

Two deadlines on Nov 30

Opus 4.8 Fast Mode. Since Claude Code 2.1.316, Fast Mode for Opus 4.8 has been deprecated. It is due to go away on Nov 30, 2026. After that, Fast Mode requests to Opus 4.8 return an error and do not fall back to normal speed. The recommendation: switch to Opus 5.5 to keep the speed advantage.[1] This comes from a third-party source dated Nov 4. We did not read the official notice ourselves today.

Gemini 4 Carbon and Argon. Both cost $2 / $10 per million tokens through Nov 30, and $4 / $20 from Dec 1.[2] According to Willison, that is the same price as Opus 5.5.[3]

My take: the first deadline is the more dangerous one. A price that doubles shows up on the bill. A script that silently fails with an error after Nov 30 only shows up when a nightly run delivers nothing. If you set Fast Mode anywhere in a config or script, go looking for it now.

Try it Search scripts, CI jobs and settings for Fast Mode combined with Opus 4.8. Why: after the deadline there is no fallback, only an error.

Fable 5.2: the vendor numbers, read skeptically

Anthropic's official Fable 5.2 page returned a 404 when we fetched it. The following numbers come from the benchmark table that labmemo took from the announcement. All of them are vendor-reported, not independently measured:[1]

  • FrontierCode 2.0 (agentic coding): Fable 5.2 49.1% (Xhigh tier), Opus 5.5 45.5%, GPT-6 Astra 42.8%, Gemini 4 Carbon 41.1% (Medium tier), Fable 5.1 32.4%.
  • FrontierSWE v2 (agentic coding): Fable 5.2 69.9%, GPT-6 Astra 65.5%, Opus 5.5 62.3%, Gemini 4 Carbon 61.2%, Fable 5.1 56.3%.
  • AutomationBench (business workflows): Here Gemini 4 Carbon leads with 53.9%, ahead of Fable 5.2 at 51.4%.
Effort tiers (Medium, High, Xhigh, Max): You tell the model how long it may think before it answers. A higher tier means more thinking tokens, so better answers on hard tasks, but more time and more cost. A comparison of "Fable on Xhigh against Carbon on Medium" is therefore not a fair like-for-like comparison.

Independently measured is only the general Intelligence Index from Artificial Analysis: Fable 5.2 (Max) 65, Fable 5.2 (Xhigh) 62, Gemini 4 Carbon (High) 60, Opus 5.5 (Max) 59.[2] The page shows no date and no coding index. We did not retrieve SWE-bench Verified, LiveCodeBench or Aider today. That is why there is no chart.

My take: the jump from 32.4% to 49.1% on FrontierCode is big, if it holds. Two things make me cautious. First, the vendor picks the benchmarks and the effort tier itself, and the rivals partly run on lower tiers. Second, AutomationBench shows that Fable is not ahead everywhere. For everyday work that means: Fable 5.2 is probably the strongest coding model of the week. How much stronger, these numbers do not tell you. Only your own repo does.

The price map after this week

Three vendors set new prices this week. All prices are per million tokens, input / output:

  • Claude Fable 5.2 — $8 / $40, 20% below Fable 5.1 at $10 / $50.[1] Fast Mode costs $16 / $80, according to labmemo.[2]
  • Gemini 4 Carbon and Argon — $2 / $10 through Nov 30, then $4 / $20.[3]
  • Gemini 4 Hydrogen — $1.50 / $7.50, cached input $0.075.[3]
  • Meta Muse Ember — $0.10 / $0.50 for inputs under 200,000 tokens.[4]

My take: an agent does not need the most expensive model for every step. The range from $0.10 to $8 input is a factor of 80. A model like Fable can handle planning and hard decisions. A model like Ember can do routine work such as finding files, reading logs or evaluating tests. Splitting your harness this way saves more than any price cut.

Meta Muse Ember: small, cheap, built for agents

On Nov 10, Meta showed Muse Ember, a small model for agentic tasks. It costs $0.10 input and $0.50 output per million tokens. On the Artificial Analysis index it scores about 34 points, according to Simon Willison, at roughly $0.12 per task on the Xhigh tier. Meta's claim, as Willison reports it: "no model scores higher for less per task".[1]

For context: 34 is far below the 65 of Fable 5.2. Ember is not a replacement for a frontier model but a candidate for the cheap steps in an agent. We found no coding measurement.

Try it Use Ember as the model for a sub-agent that only reads and summarizes, for example logs or diffs. Why: at this price a test costs almost nothing, and you learn where a small model is enough.

It's Sunday, November fifteenth. It's a quiet day. There's been no new release from any of the big coding tools since yesterday. So today we're looking at three things that got lost this week.

Claude Code picked up not one but four security fixes this week. Version two point one point three two one closed three holes in the permissions system. An MCP server could use a redirect to send refresh tokens to a foreign host. Supposedly harmless Bash commands sometimes ran outside the sandbox and without a prompt. And protection rules didn't apply to files copied with cp or mv.

The key point here: according to labmemo, the stable channel was still on version two point one point three one one on November tenth, without these fixes. So check your version. If you use MCP servers with OAuth, you can reissue the tokens as a precaution.

Two deadlines expire on November thirtieth. According to a third-party source, Fast Mode for Opus four point eight goes away, and after that you get an error instead of a fallback. And Gemini four Carbon and Argon cost double starting December first: four dollars input and twenty dollars output per million tokens.

For Fable five point two there are strong benchmark numbers, around forty-nine point one percent on FrontierCode and almost seventy percent on FrontierSWE. But all of them come from Anthropic itself. On AutomationBench, Gemini Carbon is even ahead. Only the general index from Artificial Analysis is independently measured, and there Fable leads with sixty-five points.

At the other end of the price scale is Meta Muse Ember, a small agent model at ten cents input and fifty cents output per million tokens. According to Meta, as Simon Willison reports, no model scores higher for less money per task. A good candidate for the cheap steps in an agent.

Among open models there are names like Inkling two Small and Kimi K three point one Pro, but hardly any solid data. OpenAI and Cursor stay quiet.
