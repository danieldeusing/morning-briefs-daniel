Claude Code 2.1.326: An End to Silent Failures

Version 2.1.326 arrived Monday evening. The release notes on GitHub are so long that the page truncates them.[1] There are hardly any new features. There are dozens of fixes, though. Read in one go, they show a pattern: many errors used to happen silently. Now Claude Code reports them. The most important ones for you:

  • Incomplete tool rules: At startup, Claude Code now warns when a value in --allowedTools, --disallowedTools or --tools does not look like a complete rule.
  • Broken settings file: If a settings file was saved with an error in the middle of a session, Claude Code skipped it silently. Now a warning with the file name appears.
  • Rules that only looked saved: Rules from /permissions and folders from /add-dir looked saved even when the file was not writable. Now the terminal warns.
  • Wrong summary: Commands like find -delete, cat a > b or sort -o delete or overwrite files. In the transcript they still appeared as "search" or "read". Fixed.
  • claude purge: With redirected standard output, the confirmation prompts were invisible. A single unseen Enter could delete a project's data. The prompts now always appear in the terminal.
  • Folder trust: Arrow up and Enter answered the trust question for a subfolder with yes. Fixed.
  • Gateway after a crash: Background sessions lost the LLM gateway from your shell after a crash. Now they stop before sending a model request.
Fail-closed vs. fail-open: A door with a broken lock can stay shut (fail-closed) or swing open (fail-open). For security you always want the first. Many of this week's fixes move Claude Code from "the lock is broken, but nobody notices" to "the lock is broken, and a light comes on".

My take: This is a boring release, and that is a good thing. Last week was about gaps in the permissions system. This week is about the question behind it: how do you know your rules apply at all? The warning for incomplete --allowedTools rules is most valuable for scripts and CI. A typo in a rule used to simply mean no rule, and nobody noticed. The transcript fix is subtler, but also important. Anyone reading an agent's log relies on "read" actually meaning read.

Try it Update to 2.1.326 and start claude once in every project that has its own settings. Ctrl+O shows hidden startup messages. Why: the new warnings show you rules and settings that have not worked for a long time.

Code Mode Now Also Works with Agent Teams

Code Mode arrived on Nov 12 with 2.1.323 as an experimental opt-in. In it, Claude writes JavaScript to call its tools.[1] With 2.1.326 it can also be enabled when Agent Teams are active. If you already had Code Mode on, sessions with teams now start directly in it.[1] Two more fixes concern skills with inline ! commands in Code Mode. They did not load under Auto Mode or made background sub-agents fail.

Agent Teams: Instead of a single agent, a small crew works together. One agent hands out the work, others handle parts of it in parallel. Code Mode here means: each team member writes a small program for its tool calls, instead of ordering each call one by one.

My take: Four days after launch, already the first combination with teams and two skill fixes. That shows Anthropic is serious about Code Mode. It also shows how many rough edges the feature still has. I would stay in a test repo for now.

Code Arena: Fable 5.2 Ahead, but Only Barely

For Fable 5.2 there have mostly been vendor numbers for coding so far. The Code Arena for web development is an independent source. The snapshot from Nov 13:[1]

Arena score: People see two anonymous answers to the same task and pick the better one. From that, the arena computes a score, like in chess. The "±19" is the uncertainty: the true value is probably somewhere between 1807 and 1845. If two such ranges overlap, the ranking is not certain.

The gap between Fable 5.2 and Opus 5.5 is 10 points. The uncertainty on Fable 5.2 (±19) is almost twice that gap. Fable 5.2 also has only about a third of the votes Opus 5.5 has. Statistically, that is a tie. The real jump is a different one: Fable 5.2 sits 83 points above its predecessor Fable 5.1.

In the general Intelligence Index from Artificial Analysis, the gap is bigger: Fable 5.2 (Max) 65, Gemini 4 Carbon (High) 60, Opus 5.5 (Max) 59.[2] The page gives no date. A vendor figure on top: 49.1% on FrontierCode 2.0 at Xhigh effort, per the announcement.[3]

My take: three caveats. First, the arena measures taste in web apps, not fixing bugs in a large repo. Second, both Claude models run at high effort levels. In Claude Code the default is Medium.[3] Third, we again could not retrieve SWE-bench Verified and LiveCodeBench, because both load their data via JavaScript. Still, the picture fits Anthropic's own sentence: "Claude Opus 5.5, our strongest daily driver"[3] Fable 5.2 costs $8 / $40 per million tokens.[3] For everyday work, Opus 5.5 is therefore the sensible choice. Fable 5.2 stays for the hard cases.

Correction: Codex Did Ship in November

Yesterday this brief said OpenAI had no Codex entry in November. That was true only for the API changelog. On GitHub, Codex 0.169.0 from Nov 13 is the current stable release. Among other things, it brings multiple side-chat tabs in the optional terminal workspace.[1] According to releasebot, 0.168.0 arrived the same day with a choice of model providers ("Browse model providers under Sessions → Model providers") and chats side by side.[2] Since Nov 13, several alphas a day of 0.171.0 have also appeared, today already alpha.11. Their notes are empty.[1]

My take: the choice of model providers is the interesting part. A harness that is not tied to its maker's model becomes comparable to OpenHands or Cline. How open it really is, meaning which providers and whether local endpoints work, the note does not say. We will check as soon as 0.171 is stable.

Try it If you have an OpenAI subscription: try the side-chat tabs in 0.169 for a side question while the main agent works. Why: a side question in its own tab does not disturb the main agent's context.

Qwen4 Max: Strong in the Arena, but Not for Your Home Setup

Alibaba released a preview of Qwen4 Max on Nov 11. According to two secondary sources, it is only available in the Token Plan, without pay-per-use billing, and it ends on Nov 25. Official benchmarks and open weights were not announced.[1] In the Code Arena, Qwen4-Max (xHigh) provisionally stands in 6th place with 1750, just ahead of Fable 5.1.[2]

Open weights: The "weights" are the learned numbers inside the model, in other words the model itself. If they are open, you can download the file and run it on your own machine with Ollama. Without open weights, the model is only a service in Alibaba's cloud, like Claude or GPT.

My take: for a local workflow, this is not news today. The direction is what is interesting: a Chinese lab sits within sight of Anthropic, Google and OpenAI in an independent coding ranking. Whether open variants of Qwen4 will follow later, we do not know.
