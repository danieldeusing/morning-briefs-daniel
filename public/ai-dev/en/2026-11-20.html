Gemini 4 Neon: the third model, and the pricing is confusing

Google released Gemini 4 Neon on Nov 18. We could not retrieve a Google page on it. All numbers here come from Simon Willison's post on his llm-gemini 0.38 plugin. He reproduces Google's own comparison table.[1] That is a secondary source, so read the numbers with that caveat.

ModelPrice per million tokens (in / out)AA index
Gemini 4 Carbon$4 / $20 (until Nov 30: $2 / $10)60
Gemini 4 Neon$3 / $1561
Gemini 4 Hydrogen$1.50 / $7.5054

On paper, Neon is cheaper than Carbon and a touch better. Right now that is not true: Carbon is half price until Nov 30. That is why Willison writes that Neon is "the most expensive of the three".[1] Access is through the paid API in Google AI Studio, Gemini for business, the Gemini app for Pro and Ultra subscriptions, and the paid Antigravity.[1]

Artificial Analysis Index: A company has every model take many different tests and boils the results down to a single grade. Like a report-card average: handy for a first comparison, but it does not tell you how good someone is in one particular subject. For coding, the index is only a rough hint.

A one-point gap on the overall index is noise. Willison's own non-standardized drawing test puts Neon below Carbon and above Hydrogen.[1] Latent Space calls Neon an "Opus/Sol Contender" in its headline.[2] There is no independent coding measurement yet.

My take: Google now has three models that sit close together, and a promotion that flips the price order for ten days. Willison calls the pricing "hard to follow", and that is right. For agents through the end of November, Carbon at half price is the better deal. After that, Neon is worth a look, but only with your own measurement of cost per task. A cheap token price alone means nothing, as yesterday's GPT-6.2 table showed.

Try it If you already pay for Antigravity or the Gemini API: run the same task from your repo once with Carbon and once with Neon while Carbon is still discounted. Why: you get the comparison at the cheapest moment, and from Dec 1 you know which model pays off.

Codex CLI 0.171.0: Sol becomes the default

Three days after the launch of GPT-6.2, OpenAI's terminal agent follows. The release note from Nov 20: "Added GPT-6.2 Sol and Astra to model catalogs, with Sol as the default catalog selection."[1] As a reminder: Sol 6.2 costs $2 / $10 per million tokens, Astra 6.2 $8 / $40.

Three more changes come with it:[1]

  • TUI workspace on by default, "with searchable document previews".
  • codex exec --remote <ADDR> starts or resumes non-interactive sessions on an existing app server.
  • Enterprise fix: MCP sign-in now also works with identity providers that issue ID tokens without a refresh token.
Non-interactive on an app server: codex exec is the mode without a chat: you give it a task, the agent works through it and finishes, good for scripts and CI. With --remote it does not run on your laptop but on a server that is already running. Like a print job you send to the office printer instead of setting up your own.

My take: OpenAI making Sol the default rather than the stronger Astra is the right call. Most terminal tasks are routine, and at max effort Astra 6.2 was more expensive than its predecessor in Willison's test. Whoever wants Astra picks it on purpose. That is how a default should work.

Try it If you use Codex in CI: start an app server once and send the jobs there with codex exec --remote. Why: sessions can be resumed, and you do not need to spin up a new environment for every job.

Claude Code 2.1.329: where do the hooks come from?

The second version of the day arrived on Nov 19 at 22:14. The most important line: "Added a trust dialog warning that says where a folder's hooks are declared".[1]

Hooks in the project folder: Hooks are small commands that Claude Code runs automatically on certain events, for example before every tool call. They can live in your own settings, but also in a file in the repo. If you clone someone else's repo, it brings its hooks along. It is like a USB stick that launches a program when you plug it in: handy if it is yours, dangerous if not.

The two fixes matter almost more for everyday use:[1]

  • ~/.claude.json was sometimes reset to defaults when a network hiccup or a file lock made the file unreadable during a save.
  • On macOS there were repeated sign-outs when Claude Code could read the keychain but not write to it.

According to the havoptic release tracker, /tasks now also shows scheduled tasks and forks.[2]

Correction to yesterday We had dated 2.1.328 to Nov 18 or 19. GitHub now shows "19 Nov" at 01:14.[1] So both versions came on the same day. 2.1.328 brought auto mode for Opus 4.6 and Sonnet 4.6 on Bedrock, Google Cloud, Foundry and the Claude Apps gateway, plus "onFailure": "block" for mcp_tool hooks.

My take: This week Anthropic gave the agent more freedom while also securing the edges. First the bash permissions fix (Nov 13), then the hook switch that blocks on failure, now the origin of hooks in the trust dialog. The new warning is small, but it closes a real gap: anyone who opens many foreign repos has so far clicked "Trust" without seeing what they were allowing.

Try it Open a repo you do not fully trust in a fresh folder and read the trust dialog before you click. Why: you now see whether and where the repo brings its own hooks.

curl and the Rust rewrites: the code keeps moving

Simon Willison quotes curl maintainer Daniel Stenberg on the attempts to translate curl to Rust with AI agents. The agents translated "185,000 lines of C code into 340,000 lines of Rust code".[1] In the same period the real curl project merged "over 300 commits" and landed "A little over 200 bugfixes", in "a little more than three weeks". His conclusion: "200 bugfixes that none of those rust rewrites have."[1]

My take: This is the best counter-narrative to the rewrite demos of recent weeks. An agent can translate a codebase, yes. But it translates a snapshot. A living project keeps moving, and every fix afterward has to land in two codebases. On top of that: 185,000 lines became 340,000, almost twice as much code that someone has to read and maintain. For your own projects that means: a migration with agents only pays off if you truly freeze the old version afterward or keep the port continuously in sync.

Local: two big newcomers on Ollama

Two new coding candidates have been in the Ollama library for about a week.[1] inkling-2-small is a mixture-of-experts model with 594 billion parameters, 17 billion of them active. ripple-preview is a dense model with 65 billion parameters and 1 million tokens of context. Ripple's maker reports high agent scores that we could not verify independently.

Mixture of Experts (MoE): The model has many specialists but calls only a few per word. That is why it computes as fast as a small model. But it needs memory like a big one: 594 billion parameters do not fit on a normal computer.

My take: For your Mac, ripple-preview is the more realistic candidate; inkling-2-small is more for a big server.
