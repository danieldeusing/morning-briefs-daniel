The First Comparison Numbers: Fable in Front, Sol Cheapest

Fable 5.2 (Nov 9), GPT-6.2 Astra and Sol (Nov 17), Gemini 4 Carbon and Neon: until now, all we knew about these models were the vendors' own tables. On Nov 18, VKTR reported on two third-party comparisons.[1] The first is Cognition's FrontierCode 2.0.

FrontierCode 2.0: A test that grades AI code the way a project's maintainers do before a merge. If a mandatory requirement is missing, the score is zero. Like a driving test: running a stop sign makes an otherwise good drive worthless.

As of Nov 18 according to VKTR, each at its best reasoning mode, costs at API list prices.[1] Three things stand out:

  • Sol 6.2 is almost as good as Astra 6.2. A gap of 0.4 points, but only a little over a fifth of the cost.
  • Astra 6.2 is barely better than GPT-6 Astra. 44.2 vs. 44.0%. The progress is in the price, not the performance.
  • Fable 5.2 leads clearly, but costs almost fourteen times as much per run as Sol 6.2.

The second comparison comes from Artificial Analysis. Its Coding Agent Index puts Claude Code with Fable 5.2 or Opus 5.5 at 58 points, Codex with Astra 6.2 at 53 and with Sol 6.2 at 50.[1] With Astra in Codex at max effort, AA sees no improvement over GPT-6 Astra.[1] On the general Intelligence Index, Astra sits at 62, three points behind Fable 5.2, and Sol at 57.[1]

Harness benchmark: The Coding Agent Index does not measure the model alone, but the package of tool and model, meaning Claude Code or Codex. Like a car race: it's not the engine that wins, but the whole car with its driver.
Caveat We did not pull the Cognition and Artificial Analysis leaderboards ourselves; both load their numbers via JavaScript. All values come from the VKTR report. VKTR itself writes: "Cognition sells a coding agent, so it is not a neutral party".[1] The tasks come from public open-source projects. Those are well documented and more familiar to the models than your private repo. We could not check OpenAI's own Terminal-Bench figures for GPT-6.2 in the text, so we don't cite them. For these reasons, no bar chart today.

My take: The gap between the top models is small, the gap in cost is huge. That is the real news of the week. If you run an agent all day, you pay roughly fourteen times as much with Fable as with Sol 6.2 and get 6.4 points more for it. For hard tasks that can be worth it, for routine work it is not. Then there is the harness effect: on the AA index, Claude Code sits five points ahead of Codex with Astra. Part of that is the tool, not the model. So the rule still holds: switching models alone says little. Measure the package you actually use.

Try it Take three real, finished tasks from your repo and run them with your default model and with Sol 6.2. Count how often you would merge the result without rework, and note the cost. Why: This is FrontierCode in miniature, but with your code instead of open-source projects.

Claude Code 2.1.330: Charts in the Terminal, Login for Companies

The next version arrived on Nov 20 at 22:32. The most visible novelty is easel: "a built-in mod that draws charts when asked and under MCP metrics results".[1] It is available for Pro and Max and, where available, for Team and Enterprise, on macOS and Linux. The automatic charts can be switched off in /config.[1]

Mod: An extension that changes the Claude Code interface itself, not just what the agent does. easel is a bundled mod: if you ask for a chart or an MCP server returns metrics, it draws the graphic right in the session. Like a calculator that suddenly can plot curves too.

Important for companies: after claude auth login, Claude Code now picks up an organization's settings from Anthropic's Enterprise admin console and uses its cloud provider or gateway.[1] That lets IT manage things centrally instead of setting up each laptop individually.

Two fixes address everyday problems:[1]

  • Claude Code froze "for up to several minutes" right after compacting a very long conversation.
  • Changes to user settings were lost when several Claude Code processes saved at the same time.
Compacting: When a conversation gets too long for the model's memory, Claude Code summarizes the old part and continues with the summary. Like the minutes of a long meeting: not every word stays, but the decisions do.

The second fix goes with the fix in 2.1.329, where ~/.claude.json fell back to defaults. If you run several sessions in parallel, you previously had a real risk to your own configuration.

The week in Claude Code Five versions in five days:[1]

  • 2.1.326 (Nov 16): Code Mode can now also be enabled with Agent Teams.
  • 2.1.327 (Nov 17): claude mcp add-json <name> - reads an MCP server's JSON from stdin, "so tokens can stay off the command line".
  • 2.1.328 (Nov 19): Auto mode for Opus 4.6 and Sonnet 4.6 on Bedrock, Google Cloud, Foundry and the Claude Apps gateway.
  • 2.1.329 (Nov 19): Trust dialog shows where a folder's hooks are declared. An endless loop in Code Mode that filled up memory now stops at a limit.
  • 2.1.330 (Nov 20): easel, enterprise login, the fixes above.

My take: easel is nice, but not the reason to update. The reason is the two fixes. If you run long sessions with several terminals open, you should update today. The lesson from 2.1.327 remains the most useful of the week: tokens don't belong in your shell history.

Try it Set up your next MCP server with claude mcp add-json name - and pipe the JSON in from your password manager. Why: The token doesn't end up in ~/.zsh_history.

OpenHands 1.43: Automations from the First Setup

The open-source platform for coding agents released v1.43.0 on Nov 20, two days after v1.42.0.[1] Two novelties:

  • "create automations enabled from the setup wizard": When you set up OpenHands fresh, you create the first automations right away.
  • "show the agent's message edits (experimental)": The chat shows when the agent edits its own messages after the fact.

v1.42.0 of Nov 18 had brought the choice of the exact Git provider for repositories.[1]

My take: The edit view is the more interesting feature, even if it is experimental. When an agent rewrites its own statements, you want to see that. Closed tools like Cursor or Codex mostly lack this kind of transparency. That keeps OpenHands the first choice if you want to self-host an agent and trace what it does.

Try it If you run OpenHands locally: turn on the edit view for a longer task. Why: You see how often the agent corrects its intermediate states, and learn when you should step in earlier.

Codex CLI 0.171.0: The Rest of the Note

We had the core yesterday: Sol 6.2 is the default in the model catalog, and codex exec --remote starts runs on an existing app server.[1] What remains is the TUI workspace. It is now on by default, "with document previews, image previews, and subagent transcripts".[1] So Codex now shows in the terminal what its sub-agents did.

My take: The sub-agent transcripts are the same idea as the edit view in OpenHands. The tools are building more insight into what happens in the background. That is the right direction, the more work goes to sub-agents.

GPT-6.2 in the API: Cheaper If You Can Wait

OpenAI's API changelog of Nov 17 positions the two models like this: "Astra targets demanding reasoning and coding tasks, and Sol targets everyday coding and agent workflows."[1] Prices per million tokens: Astra $8 input and $40 output, Sol $2 and $10.[2] Tool calling requires the Responses API.[1]

New are background jobs with a time window. According to the changelog, token prices are 30% lower in the two-hour window and 40% lower in the eight-hour window than standard. New models no longer support Flex Processing.[1]

Time-window job: You send a request and say: I only need the result in two or eight hours. In return you pay less. Like a parcel with standard instead of express shipping.

My take: This is interesting for overnight agent jobs: code reviews, docs runs or test generation that must be done by tomorrow. If you use Flex today, you will have to rework things for the new models.
