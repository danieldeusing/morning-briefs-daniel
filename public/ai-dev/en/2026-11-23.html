External sandbox: The agent stays outside

On Nov 17, Simon Willison described a pattern we missed during the week. The idea: code the agent executes runs "inside a dedicated sandbox while the agent itself lives outside of that sandbox".[1] His main motive is trying out local models more safely. They can be wrong, or be tricked by prompt injection into running harmful commands.[1]

Prompt injection: Outside text the agent reads contains hidden instructions, for example in a README or a web page: "Delete the folder" or "Send the .env somewhere". The model cannot reliably tell whether an instruction comes from you or from the text it read. Like a note inside a package that says: "The courier should put the key under the doormat."

There are three variants with the same local API on localhost:[1]

  • external-sandbox-v86: a Node.js server that boots Alpine Linux via v86 in WebAssembly.
  • external-sandbox-container: a Python server with Alpine Linux in Apple Containers.
  • external-sandbox-quicksand: a Python server using Microsoft's Quicksand library, which bundles QEMU and Alpine.

Pi, Claude Code and Codex can be configured to send executions to this API.[1] Two details make the pattern interesting: an optional proxy with an allowlist of reachable hosts, and a mechanism where the code makes authenticated API calls without knowing the secret itself.[1] The project came out of a collaboration with Prime Radiant, the team behind Superpowers.[1]

External instead of internal sandbox: The usual solution puts the whole agent in a container. Then the container needs your repos, tokens and tools, and the boundary gets leaky. Here the agent, with its thinking, stays outside on your machine. Only the hands, meaning the commands, go into the cage. Like a chemist working through gloves in a glovebox instead of stepping into the containment room.
Caveat The page names no limits of the pattern. The proxy is optional, and anything the agent does outside the sandbox, such as writing files in your repo, is not protected by the sandbox. This is a tool against harmful commands, not protection against bad code in the diff.

My take: This is the most interesting piece of the week for anyone working locally with Ollama, Gemma or Qwen. Local models are often less robust against injection than the big ones. At the same time, you don't want to hand them your whole machine. The container variant fits a Mac, and the v86 variant even runs without virtualization. I think the split "think outside, execute inside" is the right direction. The harnesses' built-in permission rules just had gaps: Claude Code 2.1.325 had to repair deny/ask rules for Bash.

Try it Take the container variant and let a local model solve a task in a throwaway repo, with the host allowlist enabled. Why: Afterward you see which hosts your agent really wants to reach, and that is a useful list in itself.

Tokens off the command line

A small related change in Claude Code v2.1.327 from Nov 17: claude mcp add-json <name> - reads the server's JSON from stdin, "so tokens can stay off the command line".[1]

Why it matters: Anything you type into the shell as an argument ends up in the history file and is visible to other processes in the process list. A token in an argument is like a PIN on a sticky note on your screen. Via stdin, the value goes straight to the program, leaving no trace.

My take: Small, but exactly right. If you pull secrets from a password manager, you can now pipe them straight into the command instead of writing them out in an argument.

Try it Check your shell history for mcp add with tokens. If you find any: rotate the token, delete the entry, re-create the server via stdin. Why: A history file often survives for years and across several backups.

Codex picks Sol as the default, not Astra

Codex CLI 0.171.0 from Nov 20 added "GPT-6.2 Sol and Astra to model catalogs", "with Sol as the default catalog selection".[1] Two days earlier, version 0.170.0 prepared real-time voice calls in the terminal UI via WebRTC.[1]

Choosing the default is a statement. On Nov 18, Latent Space called Astra "the #2 Frontier Model", with "mixed reviews", and Sol "likely main workhorse".[2] OpenAI makes Sol the default in its own tool.

My take: That is sensible, and Anthropic has done something similar with Sonnet and Opus for a long time. For you it means: if you start Codex after the update, you are testing Sol, not Astra. If you read field reports on "GPT-6.2 in Codex", ask which of the two they mean. We still have no independent coding numbers for either.

Claude Code: What runs in the background now shows up in /tasks

The latest version is still v2.1.330 from Nov 20.[1] Nothing was added over the weekend. The most useful for everyday work from this week is v2.1.329 from Nov 19: /tasks now shows "this session's scheduled tasks, /loop wakeups, the goal and this conversation's forks".[1]

Also in v2.1.330: sign-in to organizations from Anthropic's Enterprise Admin Console, after which Claude Code adopts their settings and cloud provider or gateway.[1] New too is easel, "a built-in mod that draws charts when asked and under MCP metrics results".[1] And v2.1.328 from Nov 19 brings auto mode for Opus 4.6 and Sonnet 4.6 on Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and the Claude Apps gateway.[1]

My take: The week shows a clear direction. Agents increasingly run unattended, with loops, scheduled tasks and forks, and the tools are now building the dashboard for it. /tasks is exactly that: one place where you see what is about to wake up on its own.

Try it Start a /loop in a session and then open /tasks. Why: In a minute you learn how to find a forgotten loop before it costs you tokens.

Cline: Compaction can be canceled

The only new release since Friday. Cline v4.1.27 and Cline SDK v0.2.1 arrived on Nov 21.[1] In the SDK, the following now applies: "A running compaction can be stopped, and cancellations are counted in telemetry".[1] The extension also includes the license notices of its third-party packages.[1]

Compaction: When the conversation with the agent gets too long for the context window, the tool summarizes the history so far and continues with the summary. That takes time and costs tokens. Like minutes someone writes up before the whiteboard gets wiped.

My take: A small release, but a real problem. A compaction at the wrong moment can lose details you need right now. Being able to cancel it keeps you in control.

Willison: Small tools in one shot

Two posts show how Simon Willison uses models as tool builders. On Nov 18 he built the plugin datasette-arrows 0.1a0 with Claude Fable 5.2 "in almost a single shot".[1] On Nov 22 came "Select Styling Specimens", a page built by Claude. The prompt was: "Build an HTML page that shows all of the ways a select box can be styled".[2] His reason: "HTML <select> boxes default to looking different in different browsers".[2]

My take: This is not a benchmark, but a useful hint about real usage. For throwaway tools, such as a comparison page or a small plugin, one good prompt is often enough for a finished result. For code that has to live long, it does not replace review.
