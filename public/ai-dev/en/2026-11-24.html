GLM 5.4: Loops instead of more parameters

Z.ai unveiled GLM 5.4 on Nov 23. The announcement is titled "Toward Generalized Coding with Our First Loop Transformer".[1] Simon Willison tried the model right away. His two most important sentences concern access: "GLM 5.4 is not (yet?) available as open weights" and "5.4 cannot currently be accessed through the regular API".[1] He signed up for Z.ai's Coding Plan subscription, and its API key got him to the new model.[1]

Loop Transformer: A normal language model sends each word through a stack of layers once, from bottom to top. Z.ai describes it like this: "a group of weight-shared layers runs for multiple iterations".[1] So part of the stack runs several times in a row, with the same weights. The result according to Z.ai: "a deeper network without increasing the parameter count".[1] Like a text you read three times instead of once: you don't need a bigger brain, but more time.

What we don't know: prices and benchmark numbers. The page lists neither.[1] Willison's own test is his well-known pelican on a bicycle, so a gut-feeling test, not a benchmark. His verdict on the maximum-effort version: "It's not great to be honest - the pelican is recognizable".[1] But he also writes that the pelicans from 5.3 and 5.4 are "much more comparable to those I get from OpenAI or Anthropic models".[1] For the predecessor GLM-5.3 there are coding numbers from Z.ai itself, but independent tests differ from them. So we leave the numbers out.[2]

Caveat Whether "loop" delivers more quality per euro in practice will only show in an independent measurement. More passes usually mean more compute per token, so probably slower answers. Without prices and numbers, this is an architecture story today, not a model recommendation.

My take: The architecture is interesting, but access is the real news. For you, someone who runs Gemma and Qwen locally, GLM 5.4 is not usable right now. You can't download it and you can't plug it into your harness through a regular API. The question mark in Willison's "not (yet?)" is the point I would watch. If the weights come later, a loop model is exciting for local hardware: few parameters mean little memory, and on a machine with limited RAM, memory is usually the bottleneck, not time. Until then it is a subscription product like any other.

Claude Code: Code Mode comes to the cloud providers

Claude Code v2.1.331 from Nov 23 brings "Code Mode support in terminal sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude Platform on AWS".[1] Code Mode has existed since v2.1.323 from Nov 12. There it is described as "an experimental opt-in in which Claude writes JavaScript to call its tools".[1]

Code Mode: Normally the model calls a tool, waits for the result, reads it and then calls the next tool. Each step is a round trip with the model. In Code Mode, Claude instead writes a small script that makes several tool calls in a row, with loops and conditions. Like the difference between a colleague who asks about every file one by one and one who writes you a shell script.

The release list shows how young the feature is. Since Nov 12, almost every version has fixed Code Mode bugs. v2.1.331 alone fixes several, for example: "Fixed Code Mode losing the middle of a long script output; Claude now gets a path to the uncut text".[1] v2.1.329 now stops "a runaway loop in Code Mode filling the machine's memory".[1]

Useful for everyday work from the same release:

  • claude doctor has a section on the API connection. It says whether the API is reachable, "with the HTTP status or the error".[1]
  • VS Code: "Fix with Claude Code" as a quick fix for errors, warnings and failed tests, and "Resolve Merge Conflicts" in files with conflicts.[1]
  • MCP: Tool calls no longer hang for up to 30 minutes when a local server sends a broken response.[1]
Deadline "on or after November 30, 2026: plugin marketplaces in managed extraKnownMarketplaces will auto-update by default".[1] Anyone who wants to pin a marketplace to a fixed version should set "autoUpdate": false on its entry beforehand.

My take: The step to Bedrock and friends shows that Anthropic is serious about Code Mode. Companies with a cloud contract should get it too. But the bug list also shows that "experimental" is meant literally here. I would test it in a project with many MCP tools, because that's where a script saves the most round trips. In a repo where a bug hurts, I would wait.

Try it Run claude doctor after the update. Why: if Claude Code sits behind a proxy or gateway, you now see in one line whether the connection is the problem.

Codex: Nested agents become discoverable

Codex CLI 0.172.0 arrived today, Nov 24. Two changes concern agents that start other agents. First: "Follow thread links from search results and transcripts to open saved conversations and nested agents in the terminal".[1] Second: "Interrupting a parent turn preserves queued replies from child agents for the next turn".[1] The previous version, 0.171.0 from Nov 20, made GPT-6.2 Sol the default in the model catalog.[1]

Parent and child agents: An agent splits a big task and starts a separate helper for each part, say "find all calls to this function". The helpers work and send their results back. Until now it went like this: if you interrupted the main agent, the helpers' finished replies could get lost. Like a boss who breaks off a meeting, and the colleagues' reports end up in the trash instead of on the pile for tomorrow.

My take: It sounds small, but it is exactly the annoyance you get with sub-agents in daily use. You interrupt because the main agent is heading in the wrong direction, and the helpers' work is lost in the process. The thread links solve the second problem: later you want to see what a helper actually did, and you can't find the transcript.

OpenHands: Conversations point to conversations

OpenHands v1.44.0 from Nov 23 brings "conversation mentions, behind the conversation_mentions flag".[1] Three days earlier, v1.43.0 brought automations into the setup wizard: "create automations enabled from the setup wizard".[1]

My take: The release feature is described briefly, and behind a flag it is not yet meant for everyone. But the direction fits Codex: a conversation with an agent should be able to point to an earlier one, instead of you copying the context by hand.

Harness comparison: Everyone is building the dashboard

Put the week side by side and three harnesses are working on the same problem. Agents run longer, start helpers and wake up on their own, and you lose track.

  • Claude Code has shown "scheduled tasks, /loop wakeups, the goal and this conversation's forks" in /tasks since v2.1.329.[1]
  • Codex makes nested agents discoverable through links and keeps their replies after an interruption.[2]
  • OpenHands is testing references between conversations.[3]

My take: Among models there are big differences, while harness features converge quickly. What counts now is this question: after an hour, can you still find out what your agent and its helpers did? When you pick a tool, look for that more than for a new command.
