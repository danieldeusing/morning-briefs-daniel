Claude Code 2.1.332: Skills come from the MCP server

Claude Code 2.1.332 arrived today, 11/25. The first line in the changelog: "Added skills from MCP servers (beta). They show as server:skill in the / menu; other skills keep their names".[1] An MCP server can now offer not just tools, but also ready-made work instructions for Claude.

MCP and skills: MCP (Model Context Protocol) is a standard through which a program offers tools to an agent, such as "read this ticket" or "query this database". A skill is a small instruction with text and sometimes shell commands that Claude loads when needed. Until now, skills lived as files on your computer. Now the server can ship them along. Like a toolbox that holds not just screwdrivers, but also the assembly manual.

The second point in the same release is the more important one: "Added a PreSkillShellCommand hook event that can refuse a skill or command's inline shell commands as it loads".[1] A skill may contain shell commands that run on load. If the skill comes from someone else's server, that means someone else's code runs. With the hook, your own script checks each of these commands and can refuse it.

Hook: A hook is a script that Claude Code calls automatically at a fixed point, for example before every tool call. The script may say "yes" or "no". Like a bouncer who glances at each guest before they get into the club.
Heads up, two computers The changelog says: "on 2.1.331 and older, a settings file naming it opens a dialog at start".[1] If you use the same settings on several Macs and one still runs an older version, Claude Code starts there with a dialog. Update all computers first, then add the hook.

Also from the same release, relevant for daily work:

  • Token prefix: the self-hosted runner's CLAUDE_CODE_OAUTH_TOKEN "can now end in oat02- as well as oat01-". Anthropic itself writes: "Update proxy rules and log scrubbers that match oat01-".[1]
  • Cloud aliases: on Google Cloud's Agent Platform and Microsoft Foundry, sonnet now points to Sonnet 5.5, and Foundry's opus to Opus 5.5. On Bedrock, sonnet stays at Sonnet 4.5.[1]
  • Auto mode: sessions on Sonnet 5 or 5.5 on Bedrock Mantle, Agent Platform and Foundry start in auto mode when no mode is set. Turn it off with disableAutoMode set to "disable".[1]
  • Reserved name: computer-use is a reserved skill name on Macs with Computer Use. A custom skill with this name no longer loads.[1]
  • MCP stability: SSE servers no longer hang after a dropped event stream, and the terminal no longer freezes when a local server floods its standard output.[1]
Deadline Managed plugin marketplaces in extraKnownMarketplaces update themselves by default "on or after November 30, 2026" (announced since 2.1.331 on 23 Nov).[1] If you want to pin a version, set "autoUpdate": false on the entry beforehand.

My take: server-side skills are a real step for the MCP ecosystem. A team can maintain its way of working once on the server instead of copying skill files into every repo. But that turns an MCP server into a source of executable code, not just data. The good part is that Anthropic ships the hook in the same release and not three versions later. I would accept server skills only from servers I run myself or know well, and set up the hook first. For a server from a third-party marketplace, the same caution applies as for an npm package with a postinstall script.

Try it Write a PreSkillShellCommand hook that writes every command to a log file and then allows it. Why: after a week you know which skills run shell commands at all, and only then can you block selectively.

Willison: Three turning points in twelve months

Simon Willison wrote up his keynote from the AI Engineer Code Summit on 11/24. The thesis: there were "three significant inflection points in the abilities of LLMs and coding agents in the past twelve months".[1]

  • November 2025, Opus 4.5 and GPT-5.1: "Opus 4.5 was the first model I had used with Claude Code where the default result was generally the right thing." About Codex with GPT-5.1: "it became reliably useful for many of my coding tasks."[1]
  • June and July 2026, Fable 5 and Mythos: his rule of thumb for these models: "Give it a goal, give it the right tools, and watch it cook."[1]
  • September and October 2026, Opus 5.5, GPT-5.6 Sol, GPT-6 Astra, Gemini 4: the models get strong at 3D models and games. "Opus 5.5 was the first model I'd used that appeared to understand fun."[1]

His conclusion: "Software development has transformed beyond recognition in the last year."[1]

My take: the text is not a news event, but a good map for your own toolbox. For you, the second turning point matters most, not the third. "Goal plus the right tools" means: the quality of your agent now depends more on the tools, skills and hooks around it than on the model name. That fits today's Claude Code news exactly. And notably: none of the three points is pinned to a benchmark jump. Willison measures by the question "is the default result right?", and that is the test you can run on your own repo too.

OpenHands 1.45: The agent tree becomes visible

OpenHands v1.45.0 arrived on 11/24, one day after v1.44.0.[1] The line that matters most for daily use: "nest sub-agent conversations under their parent".[1] When an agent starts helpers, you now see their conversations indented under the main conversation, instead of as a loose list beside it.

In addition there are "OpenHands Projects in Canvas (experimental)" and project conversations in the sidebar with "files and PRs beside the chat".[1] For Factories, meaning recurring automations, the page now shows the work logs, newest first.[1]

Update since yesterday Yesterday Codex CLI 0.172.0 introduced links that open "saved conversations and nested agents in the terminal".[2] On the same day (24 Nov) OpenHands does the same in its web interface.

My take: three harnesses solve the same problem in one week: who did what when my agent started five helpers? That is a good sign. It means sub-agents have arrived in daily work and no longer run only in demos. For your choice between tools, that counts more than any new command. Projects in Canvas is experimental, and I would not use it for real work yet.

Benchmarks: The harness triples the score

In the past three weeks came Fable 5.2 and Mythos 5.2 (11/09), GPT-6.2 Astra and Sol (11/17) and Gemini 4 Neon (11/18).[1][2] For none of them is there an independent entry on SWE-bench Verified today. The independent board from Vals AI has the state of 09/01/2026. Back then Claude Opus 5 led with 97.00%, and the top five lie between 95.40% and 97.00%.[3] So the board is old and nearly full at the top. That is why there is no chart today.

Harness: The harness is the program around the model. It gives the model tools, reads files, runs tests and decides when the task is done. Claude Code, Codex and OpenHands are harnesses. Like a race car: the same engine goes much faster in a good chassis than in a bad one.

Google itself shows how much the harness matters. In Google's announcement, Gemini 4 Neon reaches "a state-of-the-art 39.0% in Google Antigravity" on the SWE-sweep benchmark, but 12.8% in the plain mini-SWE harness.[2] That is the same model, with a factor of about 3 from the environment alone. Google reports both numbers itself. There is no independent measurement.

Caveat Google also cites first place for Neon in the Artificial Analysis Coding Agent Index with 58.6.[2] The Artificial Analysis page loads its numbers via JavaScript, so we could not read the value there ourselves. It is therefore a vendor claim here, not a verified measurement.

My take: if a harness switch triples the score, a "model A versus model B" comparison says little as long as the harness is not named. For you that means: test a new model in the harness you actually use, on a task from your repo. That is also exactly Willison's yardstick.

It's Wednesday, November twenty-fifth. The biggest news today comes from Claude Code: version two point one point three three two now loads skills directly from MCP servers.

A skill is a small set of instructions for Claude, sometimes with shell commands inside. Until now, skills lived as files on your computer. Now an MCP server can ship them, and they show up in the slash menu with the server's name in front. That also means a server can bring code onto your machine. So the second half of the release matters: a new hook called PreSkillShellCommand, which lets your own script check and refuse each of those commands.

One note if you work on several computers: older versions of Claude Code show a dialog at startup if your settings name this hook. So update all your Macs first. Also, the OAuth token of the self-hosted runner can now start with oat zero two, and log filters should know about that. And starting no earlier than November thirtieth, managed plugin marketplaces update themselves.

Simon Willison wrote up his keynote, about three turning points in twelve months. First, Opus four point five a year ago, the first model where the default result was mostly right. Second, the Fable models this summer: give them a goal and the right tools. Third, models this fall that are strong at 3D and games. For daily work, the second point matters most: the tools around the model make the difference.

OpenHands version one point four five now nests sub-agent conversations visibly under their parent conversation. Codex and OpenHands shipped something similar yesterday. So three harnesses are solving the same problem in one week: you should be able to see what your agents are doing in the background.

On benchmarks, there are still no independent numbers for the new models from Anthropic, OpenAI and Google.
