Catching up: Inkling 2 Mini runs on a laptop

Thinking Machines released Inkling 2 Mini on Nov 20. The first sentence of the announcement: “Today we are releasing Inkling 2 Mini, a fast, powerful model that's small enough to run on your laptop.”[1] We have not covered the model so far. We are catching up, because it is the most interesting local coding model of the month.

Mixture-of-Experts (MoE): A model made of many sub-networks ("experts"). For each word, only a small part of them does the math. Like a hospital with many specialists: for your case only two come into the room, not all of them. That is why the model is faster than its total size suggests.

The key facts according to the maker: “a Mixture-of-Experts model with 26.4B total parameters, 3.4B active”.[1] Memory need is “~20GB”, enough for “consumer laptops and desktop AI computers”.[1] At launch it runs via Ollama on any Mac with at least 32 GB of RAM. The weights are on Hugging Face; the page names no license.[1] In the Ollama library it is listed as the official model inkling-2-mini, with about 148,900 downloads and an update a few hours ago (as of Nov 28).[2]

Contradiction on the page The text says 3.4B active parameters, the comparison table says “5.4/26.4”. The page explains the 5.4B with “looping”: some of the layers run several times per word. Like a hard sentence you read twice: you don't need new eyes, but you need more time.[1] For you that means: memory follows the 26.4B, speed follows the 5.4B more closely.

The numbers. The maker's table shows 79.2% on SWE-bench Verified (bash only), the best value in the table. We assign the second-best value of 77.8% to Qwen3.8-27B based on column position; the page does not label it.[1] Also 73.7% on SWE-bench Multilingual and 48.2% on DeepSWE v1.1.[1] On Terminal-Bench v4.0, by contrast, the model scores 5.6%.[1]

"Bash only": For the test, the model gets only a command line, no agent scaffold of its own with special tools. Like a driving test without parking assist. So the result says more about the model than about the tool around it.
Caveat All values come from the maker. We found no independent measurement for Inkling 2 Mini. SWE-bench Verified is also nearly maxed out: large models score above 90% there according to secondary sources, though we have not checked those values ourselves. A test everyone does well on separates models poorly. And according to the page, the model is weaker at long conversations and complex instructions.[1]

My take: the 5.6% on Terminal-Bench v4.0 is the most honest number in the whole datasheet. It shows where a model of this size stops. For small, well-defined tasks on your own machine it can still be enough. The maker calls it “a strong choice for running multiple persistent agents on local hardware”.[1] Only a test on your own code shows whether that holds. The weakness with complex instructions is the point I would watch: agent prompts are long and full of rules.

Try it If your Mac has 32 GB or more, run ollama run inkling-2-mini and give it a real, small task from your repo. Run the same task on the Qwen model you already use. Why: one evening is enough to see whether the table holds on your code.

Who sells the training data for coding models

Latent Space published a piece on Nov 27 titled “Inside the exploding Coding Data Market”. The key number: there are “multiple ~1 year old statups all making $~100m/year in data contracts for frontier labs” (typo in the original).[1] The piece is the intro to a podcast with Gabe Greenberg, CEO of G2i. It names no start-ups and gives no evidence for the $100M.[1]

Verifier: A program that automatically checks whether a model's solution is correct, for example through tests. Like the answer key in a math test: the teacher doesn't have to read every calculation, they just compare the result. The labs train their models with many such tasks and checkers.

According to the piece, the work has three parts: design tasks, choose the starting data, and build a verifier that scores the output.[1] Some labs pay a premium for data that competitors cannot buy.[1]

My take: this explains why older coding benchmarks get maxed out so fast. If labs pay millions for tasks that look like “fix this bug until the tests are green”, then the models practice exactly the SWE-bench format. That is not cheating, but the number then measures practice more than skill. That is why I weight new, hard tests like Terminal-Bench v4.0 higher, and your own test on your own code higher still.

MCP: skills now come from the server too

Skill over MCP: A skill is a package of instructions and scripts that an agent loads when needed. Until now it lived locally on your machine. Now an MCP server can ship it along. Like a toolbox that the supplier sends together with the machine.

Skills over MCP have been in public beta since Nov 24, as the weekly recap from ThursdAI reports.[1] Claude Code has supported this since 2.1.332 from Nov 25: “Added skills from MCP servers (beta). They show as server:skill in the / menu”.[2] The same version brought a new hook: “Added a PreSkillShellCommand hook event that can refuse a skill or command's inline shell commands as it loads”.[2]

The size of the ecosystem: ThursdAI cites “over 700 million” SDK downloads a month, versus 90M a year ago.[1] We did not find a primary source for this number. Treat it as an order of magnitude, not a measurement.

The downside is obvious. A skill from a foreign server can bring shell commands with it. A security vendor already advertises, in the same recap, a classifier for “poisoned skill files”, meaning tampered skill files; its hit rate of 99.04% is self-reported.[1] That a product for this already exists shows the risk is not theoretical.

My take: the new hook is the more important feature, not the skills themselves. Anyone who loads skills from servers they don't run themselves should set a PreSkillShellCommand rule first. The beta has been running in Claude Code for three days without a follow-up release. I would wait for the first fix release, and until then load only skills from your own servers.

It's Saturday, November twenty-eighth. A quiet day: no new model and no major release among the coding tools. So we're catching up on a model we missed a little over a week ago.

Thinking Machines released Inkling 2 Mini on November twentieth. The model has open weights and, according to the maker, needs about twenty gigabytes of memory. It runs through Ollama on any Mac with at least thirty-two gigabytes of RAM, and it's already in the official library there.

The maker says it scores seventy-nine point two percent on SWE-bench Verified, using just a command line. But that's the maker's own number, and that test is nearly maxed out. A far more honest figure comes from the same datasheet: on the new, hard Terminal-Bench four, the model manages only five point six percent. The tip: if you have enough memory, try it on a small task from your own code, side by side with the Qwen model you already use.

Latent Space describes a new market: young companies sell training tasks for coding models to the big labs, reportedly pulling in around a hundred million dollars a year. The piece offers no evidence. Still, the story helps explain why older benchmarks get maxed out so quickly: the models practice exactly that format.

In the Model Context Protocol, servers have been able to ship skills since November twenty-fourth, in a public beta. Claude Code has shown them since version two point one point three three two, and it includes a new hook that can block shell commands from those skills. If you load skills from servers you don't control, set up that hook first.
