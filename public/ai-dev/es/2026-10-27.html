GPT-6.1 Terra: el modelo de gama media para agentes con ojos

OpenAI llevó un nuevo modelo a la API el 26/10. El changelog lo describe como "a fast, efficient model for visual reasoning, precise computer use, and clear, natural writing".[1] La palabra código no aparece en la descripción.

Los datos clave de la página del modelo: 1.050.000 tokens de contexto, hasta 128.000 tokens de output, conocimiento hasta el 01/06/2026.[2] El precio es de US$ 1 por millón de tokens de input y US$ 5 por millón de tokens de output. El input en caché cuesta US$ 0,05.[2] Simon Willison lo pone en contexto: "almost half the price of GPT-5.6 Terra and GPT-6.1 Sol, and around 10x the price of GPT-6 Luna."[3]

La valoración más honesta viene de la propia OpenAI. Ted Sanders, empleado de OpenAI, escribe que Terra es probablemente mejor que Astra y Sol en comunicación técnica, parecido en visión y computer use, "but much faster", y "a bit worse on most other things".[3] Para desarrolladores de API es "a nice midrange option if you want something cheaper than Sol but a lot smarter than Luna".[3]

Computer use: El modelo ve una captura de pantalla, decide dónde hacer clic o qué escribir, y después recibe la siguiente captura. Así opera una interfaz como una persona. Es como un colega que controla tu mouse por pantalla compartida. Para coding significa recorrer pruebas de UI o revisar una app web sin un script de Selenium.

Lo que falta: benchmarks. La página del modelo no lista valores, y Terra no aparece en SWE-bench Verified de llm-stats.[2][4] La prueba del pelícano de Willison en el modo de razonamiento más alto costó 11,3161 centavos y tardó 4 minutos con 11 segundos.[3] Eso dice algo sobre el costo de pensar mucho tiempo, nada sobre la calidad del código. Una búsqueda también nos devolvió páginas que afirman que Terra aún no se ha lanzado. Están desactualizadas: el changelog, la página del modelo y Willison confirman el lanzamiento el 26/10.

Mi opinión: Terra no reemplaza tu modelo principal de coding. OpenAI no lo vende para eso, y su propio empleado lo describe como algo más débil en la mayoría de las tareas. Es interesante como segundo modelo en el harness. Un agente que revisa la app en el navegador después de escribir código necesita ojos rápidos y baratos, no un modelo de primera línea. El precio encaja. El contexto de 1,05 M suena grande, pero con output a US$ 5 por millón, leer es barato y escribir es lo que encarece.

Pruébalo Si ya tienes un agente con un paso de navegador o de capturas de pantalla: cambia solo ese paso a Terra y compara tiempo y costo por ejecución. La parte de coding déjala en tu modelo actual.

Claude Code 2.1.311: dos bloqueos menos

Tras tres días de pausa, la versión 2.1.311 llegó el 26/10.[1] Dos arreglos afectan el día a día:

  • Entradas de lista muy largas en un CLAUDE.md podían congelar el arranque por mucho tiempo. Esto ya está arreglado.[1]
  • Claude Code repetía solicitudes que la API había marcado como "no repetir". Según las notas, esto podía retener un turno "for minutes or, in unattended retry mode (CLAUDE_CODE_RETRY_WATCHDOG), indefinitely".[1]

También hay una novedad para runners self-hosted: "Added --hold-idle-file and --max-hold-min to self-hosted-runner, to keep an idle session while your host reports processes it left running".[1] Es decir: la sesión sigue abierta mientras siga corriendo un proceso que el agente inició, por ejemplo un servidor de desarrollo o una prueba larga.

Un recordatorio de la semana pasada: la 2.1.309 del 22/10 cerró brechas de sandbox. Los archivos de arranque del shell se ejecutaban fuera del sandbox antes de cada comando, y los comandos en sandbox podían modificar el archivo --mcp-config.[1] Quien siga en la 2.1.308 o anterior debería actualizar.

Mi opinión: el arreglo del retry es el más importante. Va con la reducción de 5 a 3 reintentos de Cline ayer. Ambas herramientas aprenden lo mismo: los agentes sin supervisión no pueden esperar eternamente una respuesta que nunca llega. Si corres Claude Code de noche en CI, la 2.1.311 es una actualización obligatoria.

Pruébalo Si corres un runner self-hosted con un servidor de desarrollo en segundo plano, fija --max-hold-min en un valor concreto. Así la sesión no queda abierta para siempre.

Corrección: Cursor no estaba callado

Ayer escribimos que Cursor estaba callado desde el 16/10. Eso no es cierto. El changelog tiene una entrada del 20/10 titulada "Agent SDK".[1] La pasamos por alto.

La idea según el changelog: un agente es una carpeta con código y evals. Puedes ejecutarlo en Cursor o en tu propia infraestructura.[1] No pudimos citar el texto exacto de las notas; el resumen proviene de nuestra consulta. Desde el 20/10 no hay una entrada nueva. Antes llegaron Cloud Agent Canvases el 16/10 (Environments API en beta, hasta 300 repos) y un marketplace de apps con más de 20 apps de socios el 13/10.[1]

Evals: Una colección de tareas de prueba con resultado esperado que ejecutas contra tu agente. Son pruebas unitarias para el comportamiento de un modelo. Cuando cambias el prompt o el modelo, ves de inmediato si el agente empeoró.

Mi opinión: este es el paso más interesante de Cursor en el mes. Agente más evals en una carpeta significa que el agente se vuelve versionable y probable como código normal. El despliegue en infraestructura propia importa para empresas que no quieren poner código en nubes ajenas. Con eso Cursor compite directamente con el Cline SDK y el Agent SDK de Anthropic. Qué formato se impondrá está abierto. Una comparación solo vale la pena cuando quieras construir tus propios agentes fuera del IDE.

Cline: la cuarta pieza del lunes

Los tres paquetes de Cline del 26/10 los comentamos ayer. Ese mismo día llegó además la extensión v4.1.26.[1] Trae un interruptor: "Settings > API Configuration has a Local | Cloud toggle when cloud sessions are on."[1]

Mi opinión: con esto eliges por configuración si el agente corre en local o en la nube de Cline. Junto con la app de escritorio, el CLI y el SDK, Cline está armando la misma mezcla de local y nube que Cursor tiene con Cloud Agents y Anthropic con Claude Code en la web. Lo que te importa: si el código no puede salir del dispositivo, revisa después de actualizar que el interruptor esté en Local.

Local: Ollama prueba DFlash2 en la Mac

Ollama publicó hoy la 0.40.12-rc0 como versión preliminar.[1] Tres puntos: DFlash2 en el backend MLX ("mlx: add DFlash2 support"), detección más precisa de imágenes pequeñas en Gemma 4 Vision y una nueva versión de llama.cpp (b11901).[1] La estable sigue siendo la 0.40.11 del 24/10.[1]

MLX: La biblioteca propia de Apple para ejecutar modelos directamente en el chip de las Mac M. DFlash es la variante de Ollama de speculative decoding: un modelo pequeño escribe por adelantado y el grande lo revisa. La versión 2 sobre MLX significa que los modelos locales en la Mac deberían responder más rápido.

Mi opinión: para coding local en la Mac, la velocidad es el cuello de botella, no la calidad. Pero un rc es para probar, no para el trabajo diario. Espera la versión estable, o pruébala en una segunda instalación.

Hoy es martes veintisiete de octubre. La gran noticia viene de OpenAI. Desde ayer, GPT-seis punto uno Terra está en la API. Es rápido, barato y está hecho para comprensión de imágenes y computer use. Para coding, OpenAI no ha publicado ni una sola cifra.

Terra cuesta un dólar por millón de tokens de entrada y cinco dólares por millón de tokens de salida. Según Simon Willison, es casi la mitad del precio de Sol. El contexto alcanza poco más de un millón de tokens. Un empleado de OpenAI dice que Terra es tan bueno como los modelos grandes en visión, pero mucho más rápido, y algo más débil en la mayoría de las demás tareas. Mi consejo: no uses Terra como modelo de coding, úsalo como ojos rápidos y baratos para un agente que revisa una app en el navegador.

Claude Code ya va en la versión dos punto uno punto trescientos once. Dos bloqueos desaparecieron. Las listas largas en un archivo CLAUDE ya no congelan el arranque. Y Claude Code ya no repite solicitudes que la API marcó como no repetibles. En modo sin supervisión, eso podía dejar una ejecución atorada para siempre. Si dejas Claude Code corriendo de noche, deberías actualizar.

Ahí, un agente es una carpeta con código y pruebas que corre en Cursor o en tu propia infraestructura. Eso hace que los agentes sean versionables como código normal.
