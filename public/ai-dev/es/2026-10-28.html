Claude Code 2.1.312: la corrección que salva archivos

La versión 2.1.312 salió el 27/10 y, con 39 entradas, es una versión extensa.[1] Una entrada pesa más que todas las demás: “Fixed Claude overwriting a very large CLAUDE.md, rules file or @-included file in a subdirectory after seeing only its start; Write now asks Claude to read it all or edit in place”.[1]

En concreto: Claude leía solo el principio de un archivo grande, lo reescribía por completo y el resto se perdía. Los afectados eran justo los archivos en los que más trabajo inviertes: CLAUDE.md, reglas y archivos incluidos. Ahora la herramienta Write exige que Claude lea el archivo completo o lo edite de forma puntual.

Otros tres puntos importan en el día a día:[1]

  • Los skills por directorio y con paths: no se encontraban después de un cd más adentro del repo. Corregido.
  • Un comando con nombre inválido podía bloquear todos los comandos, y claude -p no devolvía nada. Corregido. Esto afecta a scripts y CI.
  • Los hooks de prompt y de agente ahora corren como máximo 24 a la vez por sesión, incluidos los sub-agentes. Un timeout menor a un segundo cuenta como un segundo.
Hook: Un script propio que Claude Code ejecuta automáticamente ante un evento, por ejemplo antes de cada llamada a una herramienta. Es como un pre-commit hook de Git, pero para el agente. El nuevo límite de 24 significa que, con muchos sub-agentes en paralelo, los hooks esperan en una fila en lugar de correr todos al mismo tiempo.

Para Bedrock, Vertex, Foundry y Mantle hay un cambio silencioso. Con nombres de modelo que Claude Code no reconoce, ahora usa el system prompt más corto, aunque detrás haya un Sonnet o un Haiku. Quien quiera conservar el prompt completo debe definir CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0.[1] Además, Claude Code ya no envía el evento de OpenTelemetry claude_code.safety_event.[1]

Mi opinión: la corrección de CLAUDE.md es una actualización obligatoria. Un agente que reescribe un archivo tras leer solo las primeras líneas causa pérdida de datos, no una simple incomodidad. Después de actualizar, revisa con git diff si tus archivos de reglas grandes se encogieron en los últimos días. El cambio de Bedrock es el que se puede pasar por alto: si trabajas con un nombre de deployment propio, el comportamiento cambia sin aviso.

Probar Después de actualizar, ejecuta git log --stat sobre tu CLAUDE.md y tus archivos de reglas. Un bloque grande de líneas eliminadas en un commit de un agente es la señal de alerta.

Codex CLI 0.165.0: memoria por defecto

Tras varias alphas, OpenAI publicó el 27/10 una nueva versión estable de Codex.[1] Tres funciones nuevas:[1]

  • “Added a built-in Google Cloud Vertex AI provider, configured with model_provider = "gcp".”
  • “Enabled reasoning effort changes during a conversation by default for supported models.”
  • “Enabled memory v2 by default for fresh profiles and added support for importing external-agent memories into it.”
Reasoning Effort: Cuánto tiempo piensa el modelo antes de responder. Más esfuerzo significa mejores respuestas en tareas difíciles, pero más tiempo y más costo. Es como un colega al que le pides una respuesta rápida o una revisión a fondo.

Además, una corrección de la misma familia que las de Claude Code y Cline de los últimos días: Codex ya no repite una solicitud cuando el proveedor avisa que el modelo no existe.[1] Esta noche se sumaron 0.166.0-alpha.4 y alpha.5.[1]

Mi opinión: lo interesante es la importación de memorias de otros agentes. Con ello OpenAI construye una vía para pasar de otra herramienta a Codex sin perder el conocimiento del proyecto. Las notas no dicen qué formatos lee la importación. El proveedor Vertex es una segunda señal: Codex quiere funcionar también con modelos ajenos a OpenAI. Junto con el cambio de esfuerzo en plena sesión, que Claude Code también tiene, los harnesses se parecen cada vez más.

Kimi K3.1 Pro: la cifra independiente es más baja

Moonshot reporta para Kimi K3.1 Pro un 65,7 % en Terminal-Bench 4.0, frente al 66,4 % de Claude Opus 5.5.[2] Es un dato del fabricante y solo lo conocemos de segunda mano. Vals probó el modelo por su cuenta el 24/10 y obtiene 63,64 % (±1,75), lugar 3 de 56.[1] En el Vals Index, que mezcla varias tareas, Kimi está con 62,52 % en el lugar 8 de 28.[1]

Terminal-Bench: Una prueba en la que un agente debe resolver tareas reales en una línea de comandos, por ejemplo compilar un proyecto o configurar un servidor. Se acerca más al trabajo con Claude Code o Codex que una prueba que solo pide escribir funciones sueltas. El ±1,75 significa que, en una nueva ejecución, el valor puede variar más o menos esa cantidad.

Dos advertencias. Primero: la página de Vals no es del todo consistente. El texto menciona 56 y 28 modelos; la entrada del 24/10 menciona 55 y 27.[1] Por eso el lugar es una instantánea. Segundo: en Artificial Analysis, Kimi tiene 55 puntos en el Intelligence Index y Opus 5.5 en su modo más alto tiene 58.[3] Es un índice general, no una cifra de coding. Hoy no pudimos consultar SWE-bench Verified.

Mi opinión: una diferencia de poco más de dos puntos entre el fabricante y Vals es normal. Los fabricantes prueban con la mejor configuración; los evaluadores independientes, con una fija. Aun así, la conclusión sigue siendo fuerte: un modelo cuyos pesos se abrirán está en el grupo de cabeza de un benchmark de agentes. Si eso se sostiene en tus repos, ningún ranking te lo dice. Los pesos están anunciados para el 04/11 y hoy todavía no están. Solo entonces se podrá comprobar si la versión para autoalojar da los mismos valores.

Local: Ollama 0.40.12 ya es estable

La versión preliminar de ayer ya es la estable 0.40.12.[1] Tres puntos de las notas: “Faster prompt processing on Apple silicon for Gemma 4, Flint and Laguna models”, “Speculative decoding now supports DFlash2 draft models on MLX” y “Fixed tool-only assistant turns from Kimi CLI”.[1]

Mi opinión: el procesamiento de prompts más rápido importa más para coding que DFlash2. Un agente de coding envía mucho contexto en cada paso: archivos, diffs y salidas de herramientas. En la Mac, justo la lectura de ese contexto es la parte lenta. Quien use Gemma 4 localmente como modelo de agente debería notar la diferencia de inmediato.

Probar Instala la actualización y cronometra la misma tarea de agente con Gemma 4 antes y después. El tiempo hasta el primer token es la cifra que cuenta.

OpenHands 1.34.0: un contenedor por conversación

OpenHands publicó el 27/10 la versión 1.34.0.[1] La función principal: “per-conversation Docker runtime and Settings → Runtime page”. Además, una corrección de seguridad: la API key de sesión ahora llega al servidor estático por variable de entorno y ya no como argumento de línea de comandos.[1]

Mi opinión: el segundo punto es pequeño, pero correcto. Cualquier proceso de la máquina puede ver los argumentos de la línea de comandos, por ejemplo con ps. Un contenedor propio por conversación encaja con la tendencia de la semana: Cursor construye entornos en la nube, Cline un interruptor local-nube. Cada herramienta separa ahora mejor los entornos de trabajo de los agentes.

Hoy es miércoles veintiocho de octubre. No hay ningún modelo nuevo. En cambio, ayer cuatro herramientas de programación publicaron actualizaciones al mismo tiempo: Claude Code, Codex, Ollama y OpenHands.

La actualización más importante es la de Claude Code, versión dos punto uno punto trescientos doce. Claude podía sobrescribir un archivo CLAUDE muy grande, o un archivo de reglas en un subdirectorio, después de haber leído solo el principio. El resto del archivo se perdía. Ahora Claude tiene que leer el archivo completo o editarlo de forma puntual. Mi consejo: actualiza de inmediato y revisa con Git si tus archivos de reglas grandes se encogieron en los últimos días.

En la misma actualización, los hooks corren como máximo veinticuatro a la vez por sesión. Los skills se vuelven a encontrar después de cambiar de carpeta. Y quien trabaja con Bedrock o Vertex con nombres de modelo propios recibe ahora un system prompt más corto, sin aviso.

Codex, después de varias versiones de prueba, vuelve a tener una versión estable: cero punto ciento sesenta y cinco. La memoria ahora viene activada por defecto, y Codex puede importar recuerdos de otros agentes. Además suma Google Vertex como proveedor. Es decir, Codex quiere funcionar también con modelos que no son de OpenAI.

Para Kimi K tres punto uno Pro ya hay una cifra independiente. El fabricante reporta sesenta y cinco punto siete por ciento en Terminal-Bench cuatro. Vals hizo su propia prueba y obtiene sesenta y tres punto seis cuatro por ciento, lugar tres. La diferencia es normal. Los pesos abiertos están anunciados para el cuatro de noviembre.

Ollama cero punto cuarenta punto doce ya es estable y procesa los prompts más rápido en la Mac, entre otros para Gemma cuatro. OpenHands ahora arranca un contenedor de Docker propio por conversación. Y un recordatorio: Gemini cuatro Argon costará el doble a partir del primero de diciembre.
