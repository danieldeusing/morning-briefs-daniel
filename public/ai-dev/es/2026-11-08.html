La semana en una frase: agentes sin supervisión

Mira los changelogs de esta semana y casi cada cambio responde la misma pregunta: ¿qué hace el agente cuando nadie lo ve?

  • Claude Code lanzó tres versiones en cinco días. En 2.1.319 las tareas MCP corren “in the background by default”.[1] La nueva opción permissions.denyInsteadOfPrompting “denies tool calls that would wait on a prompt”.[1] La fecha varía por un día: havoptic indica el 06/11, releasebot el 07/11.[1][2]
  • Agent SDK: desde 2.1.317 existe onFailure: "block" para los callbacks de hooks.[2] Un hook que falla bloquea entonces la acción, en vez de dejarla pasar.
  • Codex CLI 0.167.0 (06/11) tiene un centro de mando para agentes, que se inicia con codex agents --no-daemon. Marca los resultados sin leer.[3]
  • OpenAI Agents API (30/10): las sesiones pueden cambiar herramientas a mitad de la ejecución y, por defecto, compactan el contexto en segundo plano.[4]
  • Cursor: los agentes en la nube construyen una app web con base de datos e inicio de sesión y la publican en un enlace que se puede compartir (05/11).[5]
Hook: Un script pequeño que el agente llama antes o después de una acción, por ejemplo un linter antes de cada commit. Es como un portero. La pregunta hasta ahora era: ¿qué pasa si el portero se desmaya? Con "block" la puerta se queda cerrada.

Mi opinión: es la dirección correcta, y tiene un precio. Antes, la seguridad de una ejecución con agentes era que tú estabas al lado y hacías clic en “Sí”. Ahora está en un archivo JSON. Eso es mejor para automatizar, pero una línea equivocada en la configuración solo la notas en el log. Mi consejo para esta semana: después de cada ejecución sin supervisión, lee el log de las acciones rechazadas. Esa lista te muestra qué reglas faltan o son demasiado estrictas.

Pruébalo permissions.blockWritesOutsideWorkingDirectories en Claude Code. Según el changelog, la opción bloquea Write, Edit y NotebookEdit fuera de las carpetas de trabajo, “in every permission mode”.[2] Por qué: un agente que corre solo de noche no debería poder escribir en ~/.ssh ni en otro repositorio. Es una línea de configuración para un riesgo real.

Fecha límite 30/11: el Fast Mode de Opus 4.8 desaparece

Según Anthropic, el Fast Mode de Opus 4.8 está obsoleto “and will be removed on November 30, 2026”. Anthropic recomienda cambiar a Opus 5.5.[1] A partir de hoy faltan 22 días.

Qué conviene revisar antes:

  • Scripts y configuraciones de agentes que fijan Opus 4.8 con Fast Mode.
  • Definiciones de subagentes con un ID de modelo fijo en vez de un alias.
  • Costos: otro modelo necesita un número distinto de rondas para la misma tarea. Mide una ejecución real antes de borrar la configuración anterior.

Mi opinión: es una noticia aburrida, pero a partir del 01/12 puede romper en silencio tus cron jobs. Busca ahora, una sola vez, el ID del modelo con grep en tus archivos de agentes. Toma dos minutos.

Haiku 5.5: barato, pero no para todo

Haiku 5.5 salió el 07/10. Aun así importa esta semana: cuando cada vez más subagentes corren en segundo plano, cuenta el precio por ejecución. Haiku 5.5 cuesta US$ 0,10 de entrada y US$ 0,50 de salida por millón de tokens, hasta 100.000 tokens de contexto.[1]

Las cifras son datos del fabricante; no encontramos una medición independiente:

  • Terminal-Bench 4.0: Haiku 5.5 tiene 39,2 %, Sonnet 5.5 tiene 70,6 %.[1]
  • FrontierCode 1.1: Haiku 5.5 tiene 46,4 %.[1]
  • Anthropic no indica ningún valor de SWE-bench.
Subagente: Un segundo agente, más pequeño, que el agente principal inicia para una tarea parcial, por ejemplo “busca todos los lugares que llaman a esta función”. Es como un aprendiz que trae la herramienta mientras el maestro hace el trabajo.

Mi opinión: Anthropic mismo dice que Sonnet y Opus 5.5 “remain better choices” para tareas complejas de programación con agentes.[1] Es honesto, y concuerda con la distancia en Terminal-Bench. Usa Haiku para buscar, resumir y leer logs. Para cambios en el código, no. Un subagente barato que edita el archivo equivocado te sale más caro al final que uno caro.

OpenAI: Codex en alfa el sábado, un modelo de seguridad el jueves

La Codex CLI estable sigue siendo la 0.167.0 del 06/11. El sábado salió la 0.169.0-alpha.3 como versión preliminar.[1] No revisamos las notas de la alfa. Para el trabajo diario, quédate con la versión estable.

En el changelog de la API no hubo una entrada propia de Codex en octubre ni en noviembre. Los modelos nuevos son GPT-6.1 Terra (26/10) y GPT-6-Cyber (05/11).[2] GPT-6-Cyber está hecho para trabajo de seguridad: “finding vulnerabilities, reproducing them in authorized test environments, and verifying fixes”.[2]

Mi opinión: GPT-6-Cyber pertenece más al área de software y seguridad que a esta. Pero la parte de “verifying fixes” es interesante para desarrolladores. Un modelo que comprueba si tu parche de verdad cierra la vulnerabilidad es un buen contrapeso para un agente de programación que escribió el parche. El lado de seguridad corresponde al brief de software.

Local: Qwen3.8 27B para el domingo

Qwen3.8 está en Ollama en el tamaño 27B, con 18 GB y 256K de contexto. Procesa texto e imágenes.[1] No está claro cuándo se actualizó el modelo por última vez: la página dice “hace 5 horas”, la lista de tags “hace 1 mes”. Simon Willison mostró el 03/11 que Qwen 3.8 27B puede incluso leer e interpretar pesos de una red neuronal en su laptop.[2]

Ventana de contexto (256K): La cantidad de texto que el modelo puede “tener en la cabeza” a la vez, aquí unos 256.000 tokens. Es como un escritorio: mientras más grande, más archivos pueden estar abiertos al mismo tiempo. Pero un escritorio lleno también necesita más memoria.

Además, son nuevos en la biblioteca de Ollama kimi-k3.1-pro (hace 3 días) y mimo-v2.6 (hace 4 días), al 08/11.[3] No comprobamos si Kimi K3.1 Pro corre ahí como modelo local o solo como variante en la nube. Con 2,8 billones de parámetros, de todos modos no cabe en ninguna laptop.

Pruébalo ollama pull qwen3.8:27b. Por qué: 18 GB caben en una computadora con 32 GB de memoria, y para explicar código o redactar mensajes de commit no necesitas un agente en la nube.

LiveCodeBench escribe en su repo que están “in the process of updating the leaderboard scores”, sin fecha.[1] Para Opus 5.5, Sonnet 5.5 o GPT-6 no encontramos valores de SWE-bench medidos de forma independiente.

A esto se suma un reporte que solo conocemos de segunda mano: los evaluadores automáticos de SWE-bench Pro clasificarían mal alrededor de un tercio de los intentos.[2] Ayer ya apareció aquí una advertencia similar de BenchLM.

Mi opinión: una semana sin cifras nuevas de benchmarks no es una pérdida. Para elegir tus herramientas importa más lo que describe este brief arriba: ¿cómo se comporta un agente cuando algo no le está permitido, y cuánto cuesta una ejecución? Eso no lo mide ningún leaderboard.

Hoy es domingo, ocho de noviembre, y hay calma. Desde ayer solo salió una versión preliminar de Codex CLI. Por eso hoy miramos hacia atrás, a la semana.

El tema de la semana se llama: agentes sin supervisión. Claude Code publicó tres versiones en cinco días. Las llamadas largas a MCP ahora corren en segundo plano, y una nueva opción rechaza acciones en lugar de esperar una confirmación. Codex CLI recibió un centro de mando para agentes, y en Cursor los agentes en la nube publican aplicaciones web completas. Así, la seguridad ya no está en tu clic, sino en tu configuración. Por eso, después de cada ejecución sin supervisión, lee la lista de acciones rechazadas.

Un consejo concreto: Claude Code tiene una opción que bloquea la escritura fuera de la carpeta de trabajo, en cualquier modo. Para ejecuciones nocturnas, es una línea de configuración contra un riesgo real.

Una fecha límite: el treinta de noviembre desaparece el modo rápido de Opus cuatro punto ocho. Anthropic recomienda Opus cinco punto cinco. Faltan todavía veintidós días. Busca ahora en tus scripts y archivos de agentes el ID del modelo anterior.

Si quieres correr subagentes de forma barata, mira Haiku cinco punto cinco. Cuesta diez centavos de dólar por millón de tokens de entrada. Pero, según Anthropic, solo alcanza treinta y nueve punto dos por ciento en Terminal-Bench, mientras que Sonnet cinco punto cinco alcanza setenta punto seis. Usa Haiku para buscar y resumir, no para modificar código.

En OpenAI, lo nuevo es GPT seis Cyber, un modelo para trabajo de seguridad que encuentra vulnerabilidades y verifica parches. Para la laptop, Qwen tres punto ocho en el tamaño veintisiete B es un buen candidato: dieciocho gigabytes, doscientos cincuenta y seis mil tokens de contexto, a través de Ollama.

Hoy no hay cifras nuevas de benchmarks, y por eso tampoco hay gráfica. Entre los agentes de código abierto, OpenHands fue el más activo, con tres versiones en cuatro días. Cline, Continue y Aider siguen callados. La próxima semana veremos si alguien mide los modelos nuevos de forma independiente en SWE-bench.
