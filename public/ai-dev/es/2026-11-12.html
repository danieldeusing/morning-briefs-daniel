Gemini 4 Carbon: precio × 2

llm 0.37.2: tu API key de OpenAI podía irse por otro lado

Simon Willison publicó el 11/11 una versión de seguridad de su herramienta de línea de comandos llm. Su descripción: „Two bugs could send a configured OpenAI API key to other OpenAI-compatible providers.“[1] Hay dos avisos de seguridad al respecto, GHSA-v9h7-jj4g-f862 y GHSA-r639-rr7r-x72w.[1]

Proveedor compatible con OpenAI: Muchos servicios y servidores locales hablan el mismo “idioma” que la API de OpenAI, para que las mismas herramientas funcionen con ellos. Por ejemplo, servidores locales de modelos o hosters baratos. Es como un cable de carga universal. El error aquí: la herramienta, al conectarse a clavijas ajenas, enchufaba también tu llave de OpenAI.

Por qué te importa: quien usa llm junto con un modelo local o un proveedor externo con interfaz de OpenAI tiene justo la configuración en la que se activa el error. El destinatario no tiene que ser malicioso. Pero una key en logs ajenos es una key que ya no controlas.

Mi opinión: es la segunda falla de este tipo en una semana. Claude Code 2.1.321 del 09/11 corrigió un error parecido: las solicitudes MCP-OAuth enviaban secretos como refresh tokens a otro host si un servidor las redirigía.[2] El patrón es el mismo. Las herramientas que hablan con muchos proveedores confunden quién puede recibir qué llave. Mientras más proveedores reúnas en una herramienta, más importantes se vuelven estas actualizaciones.

Probar Actualiza llm a 0.37.2 y revisa después en el dashboard de OpenAI el uso de tu key para detectar llamadas desconocidas. Por qué: la actualización cierra la falla solo hacia adelante. Si la key ya se filtró, solo lo ves ahí.

Gemini 4 Carbon en Copilot: elegir modelo se vuelve cuestión de precio

GitHub informa el 10/11: „Gemini 4 Carbon is available to Copilot Pro+, Max, Business, and Enterprise users.“[1] El despliegue es gradual, así que quizá todavía no veas el modelo en el menú de selección. Se cobra „at provider list pricing under usage-based billing“.[1] Un día antes llegó Claude Fable 5.2 a Copilot.[2] No leímos el contenido de ese aviso, solo el título.

  • Carbon hoy: 2 $ / 10 $ por millón de tokens de input/output.[3]
  • Carbon desde el 01/12: 4 $ / 20 $.[3]
  • Fable 5.2: 8 $ / 40 $.[4]
Situación de las fuentes: Los precios de Carbon siguen apareciendo solo con Simon Willison. Tampoco hoy encontramos una fuente primaria de Google. GitHub no da ninguna cifra, solo “precio de lista del proveedor”. Verifica el precio antes de darlo por fijo en tus planes.

Mi opinión: el detalle del “precio de lista” importa más que el modelo nuevo. Con cobro por uso al precio del proveedor, cada elección de modelo en Copilot se vuelve una cuestión de costos. Entonces en Copilot rige la misma cuenta que en Claude Code o Cursor. La ventaja para ti: puedes probar Carbon y Fable 5.2 lado a lado en el mismo editor, sin dos cuentas. La desventaja: desde diciembre pagas el doble por Carbon, y Copilot simplemente te traslada el aumento.

Probar Si tienes una suscripción de Copilot compatible: dale la misma tarea una vez a Carbon y otra a Fable 5.2, y compara los costos en el resumen de uso. Por qué: así pruebas sin una API key nueva mientras dure el precio de lanzamiento.

Claude Code: en silencio, pero con un plazo a la vista

Sin versión nueva desde ayer. La vigente es la 2.1.322 del 10/11, con Fast Mode en Vertex AI en las regiones global, us y eu. Si Vertex lo rechaza, Claude Code vuelve a la velocidad normal.[1] La versión anterior, 2.1.321, convierte a Fable 5.2 en el modelo Fable predeterminado, con 1 millón de tokens de contexto.[1]

Plazo: Según las notas de release de Claude Code, el Fast Mode de Opus 4.8 está obsoleto desde el 30/10 y desaparece el 30/11/2026. Después, las solicitudes en Fast Mode devuelven un error, sin respaldo al Opus 4.8 estándar. Anthropic recomienda migrar a Opus 5.5. Verifícalo si tienes Opus 4.8 con Fast Mode fijado en scripts.
Fast Mode: El modelo responde más rápido y tú pagas más por token. Es como el envío exprés: el mismo paquete, llega antes, cuesta más.

Mi opinión: la calma en Claude Code después de tres releases entre el 06 y el 10/11 es normal. Si el plazo de Opus 4.8 es real, solo te afecta donde un nombre de modelo está fijo en una configuración. Justo ahí, una baja así se nota hasta que falla una ejecución nocturna.

Probar Busca en tus repos y scripts IDs de modelo escritos a mano, por ejemplo con grep -rn "opus-4-8". Por qué: un minuto de búsqueda te ahorra una ejecución rota del agente el 01/12.
