Claude Code: el sistema de permisos, hueco por hueco

Ayer dijimos aquí que Claude Code recibió cuatro correcciones de seguridad esta semana. Una revisión más cuidadosa de las notas de release en GitHub muestra que son más. Solo 2.1.323 (12/11) y 2.1.325 (13/11) incluyen seis correcciones que afectan directamente al sistema de permisos o al sandbox:[1]

  • Comandos compuestos (2.1.325): Algunas cadenas de Bash se ejecutaban sin preguntar. Ahora Claude Code pregunta.
  • Regla Allow, programa equivocado (2.1.325): Una regla Allow de Bash podía iniciar un programa distinto del que nombra.
  • Reglas Deny después de cd (2.1.325): Reglas relativas como Read(./.env) dejaban de proteger el proyecto en cuanto el agente cambiaba de directorio.
  • zstd (2.1.325): un problema de seguridad al decodificar respuestas comprimidas.
  • Write y Edit frente a Read-Deny (2.1.323): Las dos herramientas podían escribir en una ruta cubierta por una regla Deny de Read.
  • Sandbox en claude -p (2.1.323): Si fallaba la validación de --settings o de los settings del SDK que activan el sandbox, Bash corría sin sandbox. Esto afecta también al Agent SDK.
Reglas Allow, Ask y Deny: Imagina a un portero con tres listas. En la lista Allow están los comandos que el agente puede ejecutar sin preguntar. En la lista Ask, el portero te toca el timbre. La lista Deny es tabú. Las correcciones de esta semana muestran que el portero a veces leyó el nombre en la lista, pero no verificó quién estaba realmente en la puerta. O que, después de mudarse a otro cuarto, olvidó la lista.

A eso se suma 2.1.321 con la fuga de MCP OAuth sobre la que escribimos ayer. GitHub fecha ese release el 09/11, labmemo el 10/11. En la práctica no importa. Una nota por completitud: la página de releases de GitHub recorta las notas largas. Puede haber más correcciones de las que aparecen aquí.

Mi opinión: la corrección más crítica es la de claude -p. En modo interactivo ves lo que hace el agente. En modo headless, en CI o en un script del Agent SDK nadie está mirando. Justo ahí Bash corría sin sandbox si un archivo de settings tenía un error. Es lo contrario de «fail closed». La corrección de cd es la segunda candidata: proteger .env con una regla Deny es una receta estándar, y la receta tenía un hueco.

Probar Verifica con claude --version en cada computadora y en cada imagen de CI que corra al menos 2.1.325. Por qué: las versiones fijadas en imágenes Docker y lockfiles no se actualizan solas, y ahí nadie está mirando.

Probar Escribe las reglas Deny para secretos además con ruta absoluta. Por qué: las rutas relativas dependen del directorio actual, y justo eso fue la debilidad esta semana.

Code Mode: la parte discreta de 2.1.323

El mismo release trae una función experimental: Code Mode. Con opt-in, Claude escribe JavaScript para llamar a sus herramientas en lugar de formular cada llamada por separado.[1]

Code Mode: Normalmente el agente pide cada herramienta por separado: «Lee el archivo A.» Respuesta. «Lee el archivo B.» Respuesta. En Code Mode escribe un programita que lee diez archivos, los filtra y devuelve solo el resultado. Eso ahorra rondas y tokens. El precio: más lógica corre en código que no autorizas paso a paso.

Mi opinión: la idea es buena y otros harnesses van en la misma dirección. Pero en la misma semana en que el sistema de permisos tuvo seis huecos, yo probaría Code Mode solo en un repo desechable. Todavía no encontramos reportes de experiencia ni cifras.

ripple-preview: un modelo abierto de código con una gran promesa

En Ollama está desde hace unos seis días ripple-preview de Ricursive Intelligence. Según la página del modelo, es un modelo denso de 65 mil millones de parámetros, «built for agentic coding», con licencia Apache 2.0 y hasta 1 millón de tokens de contexto.[1] El propio listado muestra en un punto 2 millones. El proveedor reporta 80,5 en Terminal-Bench 2.1. No encontramos una medición independiente.

Denso contra MoE: Un modelo denso calcula con todos los parámetros en cada token, aquí 65 mil millones. Un modelo MoE («Mixture of Experts») tiene muchos más parámetros, pero activa solo una parte por token. Para ti en casa significa: 65B denso necesita mucha memoria y calcula lento, pero es más fácil de operar que un MoE gigante como Inkling 2 Small con 594B.

Mi opinión: 80,5 en Terminal-Bench de un laboratorio que no conocíamos es una cifra que solo creeré cuando alguien más la mida. Las contradicciones sobre la longitud de contexto en la misma página me hacen ser aún más cauteloso. Aun así es interesante: Apache 2.0 y un enfoque en programación con agentes es justo la combinación que falta en local. Pero con 65B denso necesitas, incluso con cuantización de 4 bits y como regla general, unos 40 GB de memoria. Eso es una pregunta de Mac Studio, no de laptop.

Probar Si tienes el hardware: dale a ripple-preview una tarea de tu repo que Claude Code resolvió la semana pasada y compara. Por qué: tu propio repo es el único benchmark que ningún proveedor puede manipular.

Google: Hydrogen en Antigravity, Agent Swarm en prueba

Gemini 4 Hydrogen llegó el 12/11 para usuarios Pro y Ultra, en AI Studio y a través de la Gemini API. Según TestingCatalog hay además acceso de pago en Antigravity, el IDE de agentes de Google, y una nueva opción de orquestador.[1] Hydrogen cuesta 1,50 $ / 7,50 $ por millón de tokens.[2] Desde el 10/11 Google prueba además un modo Agent Swarm para Antigravity.[1]

Orquestador y swarm: Un orquestador es el jefe de proyecto: descompone una tarea y reparte las partes a otros agentes. Un swarm son muchos de esos agentes trabajando en paralelo. Claude Code ya hace esto hoy con subagentes. Google se está poniendo al corriente.

Mi opinión: Hydrogen está en 54 en el índice de AA, es decir, once puntos detrás de Fable 5.2, pero cuesta menos de una quinta parte. Ese es el perfil del trabajador bajo un orquestador, no del orquestador mismo. Sobre el orquestador solo tenemos un titular. Cómo funciona, aún no lo sabemos.

Y las reglas Deny relativas, por ejemplo para el archivo de secretos, dejaban de valer en cuanto el agente cambiaba de directorio.

El error más serio afecta al modo headless y al Agent SDK. Si un archivo de configuración que activa el sandbox tenía un error, Bash corría sin ningún sandbox. Justo donde nadie está mirando. Por eso, verifica en cada computadora y en cada imagen de CI que corra al menos la versión dos punto uno punto tres dos cinco.

El mismo release trae el Code Mode experimental. Con él, Claude escribe JavaScript para llamar a sus herramientas. Eso ahorra rondas y tokens. Pero en una semana con tantos huecos de permisos, yo solo lo probaría en un repo de pruebas.
