Claude Code 2.1.328: el modo automático se vuelve estándar

La nueva versión salió el 18 o el 19/11. El rastreador de releases havoptic indica el 18, la página de releases de GitHub dice "19 Nov". Lo central está en la nota del release: "Added auto mode for Claude Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude apps gateway; interactive sessions with no permission mode start in it".[1]

Eso significa dos cosas. Primero, el modo automático ahora también existe para empresas que no contratan Claude directamente con Anthropic, sino a través de su nube. Segundo, cambia el comportamiento al arrancar: quien no define un modo de permisos termina en modo automático, y ya no en el modo que pregunta en cada acción. Si esto aplica solo a las configuraciones de nube mencionadas o a todas, la frase no lo aclara.

Modo automático: Normalmente Claude Code pregunta antes de muchas acciones, por ejemplo antes de ejecutar un comando de shell. En modo automático no pregunta cada vez. Una revisión automática decide qué puede correr sin preguntar. Imagina a un practicante que puede resolver tareas de rutina sin firma, pero que aun así te consulta cuando se trata de algo mayor.

La segunda novedad encaja con esta: "onFailure": "block" ahora también existe para los hooks mcp_tool, como ya existía para los hooks de comando y HTTP. La nota dice: "a hook whose call fails blocks the action".[1] Un hook de seguridad que falla por sí mismo ya no deja pasar la acción en silencio.

Fail-closed en lugar de fail-open: Un portero enfermo puede tener dos consecuencias. O la puerta queda abierta y entra cualquiera. O la puerta queda cerrada hasta que él regrese. "onFailure: block" elige la puerta cerrada.

Mi lectura: esta semana muestra un patrón claro en Claude Code. El 13/11 llegó una corrección para una brecha por la que algunos comandos Bash encadenados corrían sin preguntar.[1] Ahora el modo automático se vuelve estándar de forma más amplia y, al mismo tiempo, llega un interruptor de hook que bloquea en caso de falla. Anthropic le da más libertad al agente y construye la protección en el mismo movimiento. Para ti, como desarrollador individual con acceso directo a Anthropic, probablemente cambie poco. Para equipos en Bedrock o Foundry cambia mucho: quien hasta ahora trabajaba a propósito con confirmaciones debería definir ahora el modo de permisos de forma explícita, en lugar de confiar en el valor predeterminado.

Pruébalo Si usas hooks de seguridad mediante herramientas MCP: define "onFailure": "block" y haz que el hook falle a propósito una vez. Por qué: solo así sabrás si tu protección realmente aguanta ante un error.

Claude Code 2.1.327, ahora leído por completo

Actualización desde ayer Ayer el resumen de la opción de stdin se cortó. Ahora está claro a qué comando se refiere: "Added claude mcp add-json <name> - to read the server's JSON from stdin, so tokens can stay off the command line".[1]

En el mismo release hay una corrección que es fácil pasar por alto. claude mcp add y claude mcp remove con alcance de proyecto borraban otras claves de nivel superior del .mcp.json.[1] Quien mantenga ahí entradas propias debería revisar el archivo contra Git una vez.

Para completar la semana: la 2.1.321 (09/11) convirtió a Fable 5.2 en el modelo predeterminado, la 2.1.323 (12/11) trajo el Code Mode experimental, en el que Claude escribe JavaScript para llamar a sus herramientas. La 2.1.326 (16/11) permite el Code Mode junto con Agent Teams.[1][2] Ocho versiones en diez días.

Pruébalo Pasa las configuraciones MCP con tokens por pipe, por ejemplo desde 1Password: op read … | claude mcp add-json name -. Por qué: así el token nunca aparece en el historial del shell.

OpenHands: dos releases en tres días

El harness de código abierto OpenHands entregó dos veces esta semana.[1]

  • v1.42.0 (18/11): "pick the exact connected git provider for repositories". Importante si tienes GitHub y GitLab conectados en paralelo.
  • v1.41.0 (16/11): "choose the reasoning effort from what the agent reports" vía ACP.
Reasoning effort (esfuerzo de razonamiento): Cuánto tiempo piensa un modelo antes de responder. Más esfuerzo significa mejores respuestas en tareas difíciles, pero más tokens y más costo. OpenHands ahora muestra los niveles que reporta el propio agente conectado, en lugar de imponer una lista fija.

Mi lectura: releases pequeños, pero muestran hacia dónde va OpenHands. Se está volviendo una interfaz neutral a la que se conectan distintos agentes. Eso encaja con un mercado donde el mejor modelo cambia cada semana.

GPT-6.2, día dos: tokens más baratos, no siempre tareas más baratas

Actualización desde ayer Los precios ya se conocen: Astra 6.2 cuesta US$ 8 / US$ 40 por millón de tokens, Sol 6.2 se queda en US$ 2 / US$ 10.[1] Lo nuevo es la mirada al costo real por tarea. Simon Willison hace que cada modelo dibuje la misma imagen de prueba en varios niveles de esfuerzo, su conocido pelícano. Sus costos por imagen:[1]

ModeloHighXhighMax
GPT-6.2 Astra11,55 ¢17,70 ¢88,71 ¢
GPT-6 Astra18,37 ¢33,85 ¢63,21 ¢
GPT-6.2 Sol2,41 ¢6,74 ¢13,69 ¢
GPT-6.1 Sol3,66 ¢5,39 ¢13,48 ¢

En High y Xhigh, Astra 6.2 es claramente más barato que su predecesor. En Max, en cambio, cuesta más, aunque el precio del token bajó un 20%. Es decir, el modelo consume muchos más tokens ahí. Es una sola prueba con una sola tarea, no estadística.

Sobre la calidad: la prueba propia y no estandarizada de Willison pide a los modelos convertir Yonkers en un gran mecha. Su veredicto: "Neither of them did a good enough job", "at least in comparison to Claude Fable 5.2 and Gemini 4 Carbon".[1] Latent Space resume el ánimo así: Astra 6.2 sería "better and 20%-600% cheaper, but has mixed reviews", y Sol 6.2 sería "likely main workhorse".[2]

Estado de los benchmarks Para GPT-6.2, Fable 5.2 y Gemini 4 Carbon sigue sin haber número independiente. En el repositorio SWE-bench Experiments, el último envío Verified es del 01/09/2026.[3] El tablero de Aider no indica fecha. Las cifras de Anthropic para Fable 5.2 (FrontierCode 2.0: 49,1%, FrontierSWE v2: 69,9%) son reportadas por el proveedor.[4] Por eso hoy no hay gráfica de barras.

Mi lectura: la tabla es la lección más importante del día, más que el ranking. Para los agentes no cuenta el precio por token, sino el precio por tarea terminada. Y eso depende mucho de cuánto piensa el modelo. Quien pone Astra 6.2 en Max porque "ya se abarató" puede terminar pagando más. Para el día a día, hay poco en contra de Sol 6.2 en High. Para los casos difíciles, yo me quedaría con el modelo que ya se probó en tu propio repositorio.

Pruébalo En tu próxima corrida de agente, mide el costo por tarea en dos niveles de esfuerzo. Por qué: solo ese número te dice qué nivel vale la pena en tu repositorio.

Gemini 4 Carbon: abierto a desarrolladores de pago

Google abrió Gemini 4 Carbon a desarrolladores el 10/11: "Starting today, developers can build with Gemini 4 Carbon." El acceso va por el nivel de pago de la API en Google AI Studio y Android Studio, además de en Antigravity.[1] En la página no hay precios ni cifras de benchmark. Por eso no citamos un precio de fuentes secundarias.

Según una fuente secundaria, Antigravity recibió una vista previa de /swarm con varios agentes y un orquestador con Gemini 4 Carbon. Esto no lo comprobamos en la fuente primaria. Google además está llevando a los usuarios de Gemini CLI hacia Antigravity CLI.[2]

Mi lectura: Carbon destaca de forma positiva en la prueba de Willison e incluso quedó por delante de Fable 5.2 en AutomationBench en la propia tabla de Anthropic. Sin precio oficial, sin embargo, no se puede decir si es la alternativa barata. Quien todavía use Gemini CLI debería planear el cambio a Antigravity CLI.

Hoy es jueves diecinueve de noviembre. Después del gran día de OpenAI el martes, hoy hay calma. La noticia principal viene de Claude Code.

Claude Code dos punto uno punto tres dos ocho lleva el modo automático a Amazon Bedrock, Google Cloud, Microsoft Foundry y el gateway de las apps de Claude, para Opus cuatro punto seis y Sonnet cuatro punto seis. Las sesiones interactivas sin modo de permisos definido ahora arrancan en él. En modo automático, Claude Code no pregunta antes de cada acción; una revisión automática decide. Quien trabaja a propósito con confirmaciones debería definir ahora el modo de forma explícita.

Además hay un nuevo interruptor de seguridad. Los hooks que pasan por herramientas MCP ahora pueden bloquear la acción cuando ellos mismos fallan. Es decir, un vigilante descompuesto ya no deja pasar nada en silencio. La versión anterior ya permite leer configuraciones MCP con tokens por la entrada estándar, para que no queden en el historial del shell.

Sobre GPT seis punto dos hay primeras impresiones. Latent Space habla de reseñas mixtas. En la prueba propia de Simon Willison, ninguno de los nuevos modelos de OpenAI supera a Claude Fable cinco punto dos ni a Gemini cuatro Carbon. Más interesante es su tabla de costos. En el nivel más alto de esfuerzo, Astra seis punto dos cuesta unos ochenta y nueve centavos por imagen de prueba, y su predecesor unos sesenta y tres centavos. El precio del token bajó, pero la tarea sale más cara, porque el modelo piensa más.

No hay cifras independientes de benchmark para ninguno de los nuevos modelos de punta. Los envíos a SWE-bench están detenidos desde principios de septiembre. Mi consejo sigue igual: mide en tu propio repositorio, y mide el costo por tarea, no por token.

Google abrió Gemini cuatro Carbon a desarrolladores de API de pago, pero no indica precio en la página. El harness de código abierto OpenHands sacó dos releases pequeños. Cursor está callado desde el seis de noviembre, y Continue incluso desde junio.

Mañana veremos si aparece la primera medición independiente de GPT seis punto dos y cómo reaccionan los equipos al nuevo modo automático.
