Las primeras cifras comparativas: Fable al frente, Sol el más barato

Fable 5.2 (09/11), GPT-6.2 Astra y Sol (17/11), Gemini 4 Carbon y Neon: hasta ahora, de todos estos modelos solo conocíamos las tablas de los proveedores. VKTR reporta el 18/11 dos comparaciones de terceros.[1] La primera es el FrontierCode 2.0 de Cognition.

FrontierCode 2.0: Una prueba que evalúa el código de IA como lo hacen los mantenedores de un proyecto antes del merge. Si falta un requisito obligatorio, la calificación es cero. Como un examen de manejo: pasarse un alto anula un recorrido que, por lo demás, fue bueno.

Corte según VKTR: 18/11, en cada caso el mejor modo de razonamiento, costos a precios de lista de la API.[1] Tres cosas llaman la atención:

  • Sol 6.2 es casi tan bueno como Astra 6.2. Diferencia de 0,4 puntos, pero solo poco más de una quinta parte del costo.
  • Astra 6.2 es apenas mejor que GPT-6 Astra. 44,2 contra 44,0 %. El avance está en el precio, no en el rendimiento.
  • Fable 5.2 lidera con claridad, pero cuesta por corrida casi catorce veces lo que Sol 6.2.

La segunda comparación viene de Artificial Analysis. Su Coding Agent Index sitúa a Claude Code con Fable 5.2 u Opus 5.5 en 58 puntos, a Codex con Astra 6.2 en 53 y con Sol 6.2 en 50.[1] Con Astra en Codex a esfuerzo máximo, AA no ve mejora frente a GPT-6 Astra.[1] En el Intelligence Index general, Astra está en 62, tres puntos detrás de Fable 5.2, y Sol en 57.[1]

Benchmark de harness: El Coding Agent Index no mide solo el modelo, sino el paquete de herramienta y modelo, es decir, Claude Code o Codex. Como una carrera de autos: no gana el motor, gana el carro completo con su piloto.
Reserva No consultamos nosotros mismos los leaderboards de Cognition y Artificial Analysis; ambos cargan sus cifras mediante JavaScript. Todos los valores provienen del reporte de VKTR. VKTR mismo escribe: "Cognition sells a coding agent, so it is not a neutral party".[1] Las tareas provienen de proyectos open source públicos. Están bien documentados y los modelos los conocen mejor que tu repositorio privado. No pudimos verificar en el texto las cifras propias de OpenAI en Terminal-Bench para GPT-6.2, por eso no las mencionamos. Por estas razones, hoy no hay gráfica de barras.

Mi opinión: La distancia entre los modelos de punta es pequeña, la distancia en costos es enorme. Esa es la verdadera noticia de la semana. Quien deja un agente trabajando todo el día paga con Fable cerca de catorce veces lo que pagaría con Sol 6.2 y recibe 6,4 puntos más. Para tareas difíciles puede valer la pena, para la rutina no. A eso se suma el efecto del harness: en el índice de AA, Claude Code está cinco puntos por delante de Codex con Astra. Parte de eso es la herramienta, no el modelo. Por eso sigue valiendo: cambiar solo el modelo dice poco. Mide el paquete que realmente usas.

Pruébalo Toma tres tareas reales ya terminadas de tu repositorio y córrelas con tu modelo estándar y con Sol 6.2. Cuenta cuántas veces harías el merge del resultado sin retrabajo y anota el costo. Por qué: Es FrontierCode en pequeño, pero con tu código en lugar de proyectos open source.

Claude Code 2.1.330: gráficas en la terminal, inicio de sesión para empresas

El 20/11 a las 22:32 salió la siguiente versión. La novedad más visible es easel: "a built-in mod that draws charts when asked and under MCP metrics results".[1] Está disponible para Pro y Max y, donde exista, para Team y Enterprise, en macOS y Linux. Las gráficas automáticas se pueden desactivar en /config.[1]

Mod: Una extensión que cambia la propia interfaz de Claude Code, no solo lo que hace el agente. easel es un mod incluido: si pides una gráfica o un servidor MCP entrega métricas, dibuja la imagen directo en la sesión. Como una calculadora que de pronto también traza curvas.

Importante para empresas: después de claude auth login, Claude Code ahora toma los ajustes de una organización desde la consola de administración Enterprise de Anthropic y usa su proveedor de nube o su gateway.[1] Así TI administra de forma central, en lugar de configurar cada laptop por separado.

Dos correcciones atacan problemas cotidianos:[1]

  • Claude Code se congelaba "for up to several minutes" justo después de compactar una conversación muy larga.
  • Los cambios en los ajustes del usuario se perdían cuando varios procesos de Claude Code guardaban al mismo tiempo.
Compactar: Cuando una conversación se vuelve demasiado larga para la memoria del modelo, Claude Code resume la parte antigua y sigue con el resumen. Como la minuta de una junta larga: no se conserva cada palabra, pero sí los acuerdos.

La segunda corrección va con la de 2.1.329, en la que ~/.claude.json volvía a los valores predeterminados. Quien corre varias sesiones en paralelo tenía hasta ahora un riesgo real para su propia configuración.

La semana en Claude Code Cinco versiones en cinco días:[1]

  • 2.1.326 (16/11): Code Mode ahora también se puede activar con Agent Teams.
  • 2.1.327 (17/11): claude mcp add-json <name> - lee el JSON de un servidor MCP por stdin, "so tokens can stay off the command line".
  • 2.1.328 (19/11): modo automático para Opus 4.6 y Sonnet 4.6 en Bedrock, Google Cloud, Foundry y el gateway de Claude Apps.
  • 2.1.329 (19/11): el diálogo de confianza muestra dónde se declaran los hooks de una carpeta. Un bucle infinito en Code Mode que llenaba la memoria ahora se detiene en un límite.
  • 2.1.330 (20/11): easel, inicio de sesión Enterprise, las correcciones de arriba.

Mi opinión: easel es bonito, pero no es el motivo para actualizar. El motivo son las dos correcciones. Quien maneja sesiones largas con varias terminales abiertas debería actualizar hoy. La lección de 2.1.327 sigue siendo la más útil de la semana: los tokens no pertenecen al historial del shell.

Pruébalo Configura tu próximo servidor MCP con claude mcp add-json name - y pasa el JSON por pipe desde tu administrador de contraseñas. Por qué: El token no termina en ~/.zsh_history.

OpenHands 1.43: automatizaciones desde la primera configuración

La plataforma open source para agentes de código publicó la v1.43.0 el 20/11, dos días después de la v1.42.0.[1] Dos novedades:

  • "create automations enabled from the setup wizard": quien configura OpenHands desde cero crea de una vez las primeras automatizaciones.
  • "show the agent's message edits (experimental)": el chat muestra cuando el agente modifica después sus propios mensajes.

La v1.42.0 del 18/11 había traído la selección del proveedor Git exacto para los repositorios.[1]

Mi opinión: La vista de ediciones es la función más interesante, aunque sea experimental. Cuando un agente reescribe sus propias afirmaciones, uno quiere verlo. En herramientas cerradas como Cursor o Codex suele faltar esa transparencia. OpenHands sigue siendo así la primera opción si quieres alojar un agente por tu cuenta y poder rastrear lo que hace.

Pruébalo Si corres OpenHands localmente: activa la vista de ediciones en una tarea más larga. Por qué: Ves con qué frecuencia el agente corrige sus estados intermedios y aprendes cuándo conviene intervenir antes.

Codex CLI 0.171.0: el resto de la nota

Lo esencial lo tuvimos ayer: Sol 6.2 es el predeterminado en el catálogo de modelos, y codex exec --remote inicia corridas en un app server existente.[1] Falta agregar el workspace de la TUI. Ahora viene activado por defecto, "with document previews, image previews, and subagent transcripts".[1] Codex muestra, pues, en la terminal lo que hicieron sus subagentes.

Mi opinión: Los registros de subagentes son la misma idea que la vista de ediciones en OpenHands. Las herramientas están construyendo más visibilidad de lo que pasa en segundo plano. Es la dirección correcta, mientras más trabajo pase a los subagentes.

GPT-6.2 en la API: más barato si puedes esperar

El changelog de la API de OpenAI del 17/11 posiciona los dos modelos así: "Astra targets demanding reasoning and coding tasks, and Sol targets everyday coding and agent workflows."[1] Los precios por millón de tokens: Astra US$ 8 de entrada y US$ 40 de salida, Sol US$ 2 y US$ 10.[2] Tool calling requiere la Responses API.[1]

Lo nuevo son los trabajos en segundo plano con ventana de tiempo. Según el changelog, los precios de tokens son 30 % más bajos en la ventana de dos horas y 40 % más bajos en la de ocho horas que el estándar. Los modelos nuevos ya no admiten Flex Processing.[1]

Trabajo con ventana de tiempo: Envías una solicitud y dices: el resultado lo necesito hasta dentro de dos u ocho horas. A cambio pagas menos. Como un paquete con envío estándar en lugar de exprés.

Mi opinión: Para trabajos nocturnos de agentes esto es interesante: code reviews, corridas de documentación o generación de pruebas que deben estar listas para mañana. Quien usa Flex hoy tendrá que reajustar para los modelos nuevos.

El reporte es de VKTR y cita la prueba FrontierCode dos punto cero, de Cognition. La prueba evalúa el código como lo hacen los mantenedores antes del merge. Claude Fable cinco punto dos va al frente con poco más de cincuenta por ciento, Opus cinco punto cinco queda en poco más de cuarenta y siete. Una corrida con Sol cuesta alrededor de un dólar con treinta centavos, con Fable casi dieciocho dólares.

Artificial Analysis mide además el paquete de herramienta y modelo. Claude Code alcanza cincuenta y ocho puntos, Codex con Astra cincuenta y tres y con Sol cincuenta. Es decir, parte de la ventaja se debe a la herramienta. La reserva es importante: solo conocemos todas las cifras de segunda mano, y la propia Cognition vende un agente de código. Mi consejo: prueba el económico Sol con tres tareas reales de tu propio repositorio.

Claude Code dos punto uno punto trescientos treinta trae un mod integrado llamado easel, que dibuja gráficas directo en la sesión. Las empresas ahora pueden configurar Claude Code de forma central desde la consola de administración. Más importantes son dos correcciones: Claude Code ya no se congela por minutos después de resumir conversaciones largas, y los ajustes ya no se pierden con sesiones en paralelo.
