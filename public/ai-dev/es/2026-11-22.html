Gemini 4 Neon: las cifras de coding del propio Google

El viernes solo conocíamos Neon por la publicación de Simon Willison. Ahora pudimos leer directamente el anuncio de Google del 18/11.[1] La frase que importa: Neon está en "#1 overall on the Artificial Analysis Coding Agent Index (58.6)".[1] InfoWorld repite la misma cifra el 19/11, pero también solo como una declaración de Google.[2]

El problema: ayer el reporte de VKTR decía que Claude Code con Fable 5.2 u Opus 5.5 llega a 58 puntos en este índice.[3] 58,6 contra 58 es una diferencia que puede surgir solo por redondeo. La página de Artificial Analysis muestra sus valores únicamente mediante JavaScript. Nuestra consulta devolvió el encabezado "Coding Agent Index v2.1" y la indicación "15 of 40 models", pero ninguna cifra.[4] Por lo tanto, no podemos confirmar directamente ninguna de las dos cifras.

Terminal-Bench: Una prueba en la que el modelo debe resolver tareas reales en una línea de comandos: compilar paquetes, analizar logs, configurar servidores. Como un examen práctico en el taller en lugar de una prueba de opción múltiple.

La fila más interesante es la última. En SWE-sweep, una prueba que Google no explica en las frases que leímos, Neon logra 12,8 % con el harness ligero mini-SWE. En su propia herramienta, Antigravity, "more than triples to a state-of-the-art 39.0%".[1] El propio Google escribe que esto muestra "what the Antigravity harness unlocks".[1]

Harness: El programa que rodea al modelo: le da herramientas, lee archivos, ejecuta pruebas y decide cuándo terminó un intento. mini-SWE es un harness deliberadamente mínimo, Antigravity es la herramienta completa de agentes de Google. Como el mismo cocinero, una vez con una estufa de campamento y otra en una cocina profesional.

Lo que Google dice sobre el precio, en cambio, es claro: US$ 3 por millón de tokens de entrada, US$ 0,15 por entrada en caché, US$ 15 por millón de tokens de salida y un contexto de un millón de tokens.[1] Neon debería costar 32 % menos por tarea que Carbon.[1] Hasta el 30/11 probablemente no se cumple, porque Carbon todavía tiene el precio promocional de US$ 2 / US$ 10.[5] Neon está disponible en la Gemini API a través de AI Studio y, para clientes de pago de AI Pro y Ultra, en Antigravity.[1]

Mi opinión: la frase "#1 overall" es marketing para un empate. La noticia real está en la nota al pie del propio Google: el mismo modelo logra tres veces más cuando la herramienta que lo rodea es mejor. Eso confirma lo que el índice de AA ya mostró ayer. Para ti, esto significa: probar Neon en Antigravity dice poco sobre cómo funciona Neon en tu Claude Code o en tu propio harness. Quien quiera comparar debe dejar la herramienta igual y cambiar solo el modelo. Con US$ 3 / US$ 15, Neon queda en precio entre Sol y Fable. Eso lo hace interesante para ejecuciones largas de agentes, si la calidad se confirma de forma independiente.

Pruébalo Si tienes un harness que soporte varios proveedores: ejecuta una tarea real una vez con Neon y otra con tu modelo habitual, en la misma herramienta. Por qué: solo así separas el efecto del modelo del efecto del harness, que el propio Google muestra con tanta claridad.

Experimento dominical: Code Mode en Claude Code

Desde la v2.1.323 del 12/11, Claude Code tiene el Code Mode: "an experimental opt-in in which Claude writes JavaScript to call its tools".[1] Desde la v2.1.326 del 16/11, también se puede activar con Agent Teams.[1] Entre semana muchas veces falta tiempo para probar algo así. Hoy sí hay.

Code Mode: Normalmente el modelo llama a una herramienta, espera el resultado, lo lee y llama a la siguiente. Cada paso es una ronda aparte. En Code Mode, en cambio, el modelo escribe un pequeño programa que llama a varias herramientas en secuencia y procesa los resultados por sí mismo. Como la diferencia entre cinco llamadas sueltas al plomero y una nota con los cinco trabajos.

La posible ventaja: menos rondas y menos resultados intermedios en el contexto cuando una tarea requiere muchas llamadas pequeñas a herramientas. El riesgo se ve en la nota de la 2.1.329: un ciclo infinito en Code Mode que llenaba la memoria fue detenido con un límite.[2] Es decir, la función es realmente experimental.

Mi opinión: Code Mode conviene sobre todo en tareas con muchos pasos similares, por ejemplo "lee estos veinte archivos y junta todos los TODOs". Para cambios puntuales y cuidadosos en código de producción me quedaría con el modo normal. Ahí ves cada paso por separado.

Pruébalo Activa Code Mode en un repositorio desechable y dale la misma tarea de recopilación una vez con él y otra sin él. Compara la duración y el consumo de tokens. Por qué: después sabrás si el opt-in vale la pena para tu día a día, antes de que se vuelva estándar.

Claude Code: ¿estás al menos en la 2.1.325?

La versión más reciente sigue siendo la v2.1.330 del 20/11; en la consulta del domingo no había nada más nuevo.[1] Pero el motivo más importante para actualizar tiene una semana. La v2.1.325 del 13/11 incluye dos correcciones de seguridad:[1]

  • "Fixed a security issue in how zstd-compressed responses are decoded."
  • "Fixed some deny and ask rules not applying to certain Bash commands."
Reglas deny/ask: En la configuración defines qué comandos Claude Code nunca puede ejecutar (deny) y sobre cuáles debe preguntar antes (ask). Como un seguro para niños en la estufa. La corrección significa: en algunos comandos de Bash, el seguro no funcionaba.

A esto se suma la v2.1.329 del 19/11: el diálogo de confianza ahora muestra dónde están declarados los hooks de una carpeta.[1] Quien abre un repositorio ajeno ve, entonces, de dónde vienen los comandos que se ejecutan automáticamente.

Mi opinión: quien confía en las reglas deny para mantener a un agente bajo control y sigue en una versión anterior a la 2.1.325 tiene una falsa sensación de seguridad. claude --version toma un segundo.

Hoy es domingo, veintidós de noviembre. Un día tranquilo: durante el fin de semana no hubo lanzamientos nuevos de las grandes empresas. Lo único nuevo es que ahora pudimos leer la página del propio Google sobre Gemini cuatro Neon.

Google afirma que Neon está en primer lugar en el Coding Agent Index de Artificial Analysis, con cincuenta y ocho punto seis puntos. Ayer, el reporte de VKTR decía que Claude Code tiene cincuenta y ocho en el mismo índice. En la práctica, es un empate. Y no pudimos verificar ninguna de las dos cifras directamente en el índice, porque la página solo carga sus valores con JavaScript.

Más interesante es otro dato de Google. En la prueba SWE-sweep, Neon logra casi trece por ciento con una herramienta ligera y treinta y nueve por ciento en Antigravity, la herramienta del propio Google. El mismo modelo, tres veces más aciertos. O sea que la herramienta que rodea al modelo pesa por lo menos tanto como el modelo mismo. Neon cuesta tres dólares por millón de tokens de entrada y quince dólares por millón de tokens de salida.

Para el domingo, un experimento: desde mediados de noviembre, Claude Code tiene un Code Mode experimental. Claude escribe un pequeño programa en JavaScript que llama a varias herramientas a la vez. Pruébalo en un repositorio desechable con una tarea de recopilación y compara el tiempo y el consumo de tokens.

Algo importante de seguridad: la versión dos punto uno punto trescientos veinticinco, del trece de noviembre, cerró una vulnerabilidad al decodificar respuestas comprimidas. Además, algunas reglas de bloqueo y de confirmación no se aplicaban a ciertos comandos de Bash. Si tienes una versión anterior, actualiza.

Cursor está en silencio desde el seis de noviembre, y OpenHands y Codex no tienen novedades desde el viernes. El treinta de noviembre termina el precio promocional de Gemini cuatro Carbon. En la próxima edición veremos si Neon aparece en alguna medición independiente.
