Un martes tranquilo con una novedad de verdad. Z.ai presentó GLM 5.4, en sus propias palabras el primer "Loop Transformer" de la empresa. Hoy no tenemos cifras de benchmarks independientes, así que no hay gráfica ni puntuaciones.

  • OpenAI Codex CLI 0.172.0 (24/11): los enlaces de hilo abren conversaciones guardadas y agentes anidados. Una interrupción ya no pierde las respuestas de los agentes hijos.
  • Tool OpenHands v1.44.0 (23/11): las conversaciones se pueden mencionar en otras conversaciones, todavía detrás de un feature flag.

GLM 5.4: bucles en lugar de más parámetros

Z.ai presentó GLM 5.4 el 23/11. El título del anuncio es "Toward Generalized Coding with Our First Loop Transformer".[1] Simon Willison probó el modelo de inmediato. Sus dos frases más importantes tratan del acceso: "GLM 5.4 is not (yet?) available as open weights" y "5.4 cannot currently be accessed through the regular API".[1] Contrató la suscripción Coding Plan de Z.ai y, con la clave de API de esa suscripción, llegó al nuevo modelo.[1]

Loop Transformer: Un modelo de lenguaje normal manda cada palabra una sola vez por una pila de capas, de abajo hacia arriba. Z.ai lo describe así: "a group of weight-shared layers runs for multiple iterations".[1] Es decir, una parte de la pila corre varias veces seguidas, con los mismos pesos. El resultado según Z.ai: "a deeper network without increasing the parameter count".[1] Como un texto que lees tres veces en lugar de una: no necesitas un cerebro más grande, sino más tiempo.

Lo que no sabemos: precios y cifras de benchmarks. La página no menciona ninguno.[1] La prueba del propio Willison es su conocido pelícano en bicicleta, o sea, una prueba de impresión, no un benchmark. Su veredicto sobre la versión de esfuerzo máximo: "It's not great to be honest - the pelican is recognizable".[1] Pero también escribe que los pelícanos de 5.3 y 5.4 son "much more comparable to those I get from OpenAI or Anthropic models".[1] Del predecesor GLM-5.3 hay cifras de coding de la propia Z.ai, pero las pruebas independientes se desvían de ellas. Por eso omitimos las cifras.[2]

Reserva Si el "loop" da más calidad por euro en la práctica, solo lo mostrará una medición independiente. Más pasadas suelen significar más trabajo de cómputo por token, o sea, probablemente respuestas más lentas. Sin precios ni cifras, hoy esto es una noticia de arquitectura, no una recomendación de modelo.

Mi opinión: la arquitectura es interesante, pero el acceso es la verdadera noticia. Para ti, que corres Gemma y Qwen en local, GLM 5.4 no se puede usar por ahora. No lo puedes descargar ni conectarlo a tu harness por una API normal. El signo de interrogación en el "not (yet?)" de Willison es lo que yo vigilaría. Si los pesos llegan después, un modelo en bucle es interesante para hardware local: pocos parámetros significan poca memoria, y en una máquina con RAM limitada la memoria suele ser el cuello de botella, no el tiempo. Mientras tanto es un producto de suscripción como cualquier otro.

Claude Code: el Code Mode llega a los proveedores de nube

Claude Code v2.1.331 del 23/11 trae "Code Mode support in terminal sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude Platform on AWS".[1] El Code Mode existe desde la v2.1.323 del 12/11. Allí se describe como "an experimental opt-in in which Claude writes JavaScript to call its tools".[1]

Code Mode: Normalmente el modelo llama a una herramienta, espera el resultado, lo lee y luego llama a la siguiente herramienta. Cada paso es una ronda con el modelo. En Code Mode, Claude escribe en cambio un pequeño script que hace varias llamadas a herramientas seguidas, con bucles y condiciones. Como la diferencia entre un colega que pregunta por cada archivo por separado y otro que te escribe un shell script.

La lista de releases muestra qué tan joven es la función. Desde el 12/11, casi todas las versiones han corregido errores del Code Mode. Solo la v2.1.331 corrige varios, por ejemplo: "Fixed Code Mode losing the middle of a long script output; Claude now gets a path to the uncut text".[1] La v2.1.329 ahora detiene "a runaway loop in Code Mode filling the machine's memory".[1]

Del mismo release, útiles para el día a día:

  • claude doctor tiene una sección sobre la conexión con la API. Dice si la API está al alcance, "with the HTTP status or the error".[1]
  • VS Code: "Fix with Claude Code" como quick fix para errores, advertencias y pruebas fallidas, y "Resolve Merge Conflicts" en archivos con conflictos.[1]
  • MCP: las llamadas a herramientas ya no se quedan colgadas hasta 30 minutos cuando un servidor local manda una respuesta rota.[1]
Plazo "on or after November 30, 2026: plugin marketplaces in managed extraKnownMarketplaces will auto-update by default".[1] Quien quiera mantener un marketplace fijo en una versión debe poner antes "autoUpdate": false en su entrada.

Mi opinión: el paso hacia Bedrock y compañía muestra que Anthropic se toma en serio el Code Mode. Las empresas con contrato de nube también deben recibirlo. Pero la lista de errores muestra que "experimental" aquí va en serio. Yo lo probaría en un proyecto con muchas herramientas MCP, porque ahí un script ahorra más rondas. En un repositorio donde un error duele, todavía esperaría.

Pruébalo Ejecuta claude doctor después de actualizar. Por qué: si Claude Code está detrás de un proxy o gateway, ahora ves en una línea si el problema es la conexión.

Codex: los agentes anidados se pueden encontrar

Codex CLI 0.172.0 salió hoy, 24/11. Dos cambios afectan a agentes que inician otros agentes. Primero: "Follow thread links from search results and transcripts to open saved conversations and nested agents in the terminal".[1] Segundo: "Interrupting a parent turn preserves queued replies from child agents for the next turn".[1] La versión anterior, 0.171.0 del 20/11, puso GPT-6.2 Sol como estándar en el catálogo de modelos.[1]

Agentes padre e hijo: Un agente divide una tarea grande e inicia un ayudante propio para cada parte, por ejemplo "busca todas las llamadas a esta función". Los ayudantes trabajan y mandan sus resultados de vuelta. Hasta ahora era así: si interrumpías al agente principal, las respuestas ya terminadas de los ayudantes podían perderse. Como un jefe que corta una junta, y los informes de los colegas acaban en la basura en lugar de en la pila para mañana.

Mi opinión: suena pequeño, pero es justo la molestia que se tiene con subagentes en el día a día. Interrumpes porque el agente principal va en la dirección equivocada, y con eso se pierde el trabajo de los ayudantes. Los enlaces de hilo resuelven el segundo problema: más tarde quieres ver qué hizo realmente un ayudante y no encuentras la transcripción.

OpenHands: conversaciones que apuntan a conversaciones

OpenHands v1.44.0 del 23/11 trae "conversation mentions, behind the conversation_mentions flag".[1] Tres días antes, la v1.43.0 llevó las automatizaciones al asistente de configuración: "create automations enabled from the setup wizard".[1]

Mi opinión: la función del release está descrita brevemente y, detrás de un flag, todavía no es para todos. Pero la dirección encaja con Codex: una conversación con un agente debe poder apuntar a una anterior, en lugar de que copies el contexto a mano.

Comparación de harnesses: todos construyen el tablero

Si pones la semana lado a lado, tres harnesses trabajan en el mismo problema. Los agentes corren más tiempo, inician ayudantes y despiertan solos, y tú pierdes la visión de conjunto.

  • Claude Code muestra desde la v2.1.329 en /tasks "scheduled tasks, /loop wakeups, the goal and this conversation's forks".[1]
  • Codex hace que los agentes anidados se puedan encontrar por enlaces y conserva sus respuestas tras una interrupción.[2]
  • OpenHands prueba referencias entre conversaciones.[3]

Mi opinión: entre los modelos hay grandes diferencias, mientras que en los harnesses las funciones se igualan rápido. Lo que cuenta ahora es esta pregunta: ¿puedes averiguar después de una hora qué hicieron tu agente y sus ayudantes? Al elegir una herramienta, fíjate en eso más que en un comando nuevo.

Willison: agente con barra lateral

Simon Willison publicó hoy datasette-agent 0.7a1. Novedad: "chat sessions can open an iframe side panel, and that panel can then navigate to different pages".[1] El 23/11 salió además datasette-charts 0.1a0. El plugin "compiles each chart to a SQL query that aggregates across the entire result set".[1]

Mi opinión: no es un agente de coding en sentido estricto, pero es un buen patrón. Un agente que te abre una página junto al chat muestra su resultado en lugar de solo describirlo. Es una alfa, así que solo para curiosos.
