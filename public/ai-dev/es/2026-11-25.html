Claude Code 2.1.332: Las skills llegan desde el servidor MCP

Claude Code 2.1.332 salió hoy, 25/11. La primera línea del changelog: "Added skills from MCP servers (beta). They show as server:skill in the / menu; other skills keep their names".[1] Un servidor MCP ahora puede ofrecer no solo herramientas, sino también instrucciones de trabajo listas para Claude.

MCP y skills: MCP (Model Context Protocol) es un estándar mediante el cual un programa ofrece herramientas a un agente, por ejemplo "lee este ticket" o "consulta esta base de datos". Una skill es una pequeña instrucción con texto y a veces comandos de shell que Claude carga cuando la necesita. Hasta ahora, las skills estaban como archivos en tu computadora. Ahora el servidor puede entregarlas junto con todo lo demás. Como una caja de herramientas que no solo trae desarmadores, sino también el instructivo de armado.

El segundo punto del mismo release es el más importante: "Added a PreSkillShellCommand hook event that can refuse a skill or command's inline shell commands as it loads".[1] Una skill puede contener comandos de shell que se ejecutan al cargarla. Si la skill viene de un servidor ajeno, se ejecuta código ajeno. Con el hook, tu propio script revisa cada uno de esos comandos y puede rechazarlo.

Hook: Un hook es un script que Claude Code llama automáticamente en un punto fijo, por ejemplo antes de cada llamada a una herramienta. El script puede decir "sí" o "no". Como un cadenero que le echa un vistazo a cada invitado antes de dejarlo entrar al antro.
Atención, dos computadoras El changelog dice: "on 2.1.331 and older, a settings file naming it opens a dialog at start".[1] Si usas la misma configuración en varias Mac y una todavía corre una versión anterior, Claude Code arranca ahí con un diálogo. Primero actualiza todas las computadoras y después registra el hook.

Del mismo release, importante para el día a día:

  • Prefijo del token: el CLAUDE_CODE_OAUTH_TOKEN del runner autoalojado "can now end in oat02- as well as oat01-". La propia Anthropic escribe: "Update proxy rules and log scrubbers that match oat01-".[1]
  • Alias de nube: en la Agent Platform de Google Cloud y en Microsoft Foundry, sonnet ahora apunta a Sonnet 5.5, y el opus de Foundry a Opus 5.5. En Bedrock, sonnet se queda en Sonnet 4.5.[1]
  • Modo automático: las sesiones en Sonnet 5 o 5.5 en Bedrock Mantle, Agent Platform y Foundry arrancan en modo automático cuando no hay un modo definido. Se desactiva con disableAutoMode en "disable".[1]
  • Nombre reservado: computer-use es un nombre de skill reservado en Mac con Computer Use. Una skill propia con ese nombre ya no se carga.[1]
  • Estabilidad de MCP: los servidores SSE ya no se cuelgan tras un event stream interrumpido, y la terminal ya no se congela cuando un servidor local inunda su salida estándar.[1]
Plazo Los marketplaces de plugins administrados en extraKnownMarketplaces se actualizan solos por defecto "on or after November 30, 2026" (anunciado desde 2.1.331 del 23.11.).[1] Quien quiera fijar una versión, debe poner antes "autoUpdate": false en la entrada.

Mi opinión: las skills desde el servidor son un paso real para el ecosistema MCP. Un equipo puede mantener su forma de trabajar una sola vez en el servidor, en lugar de copiar archivos de skill a cada repositorio. Pero con eso un servidor MCP se vuelve una fuente de código ejecutable, no solo de datos. Lo bueno es que Anthropic entrega el hook en el mismo release y no tres versiones después. Yo solo aceptaría skills de servidor de servidores que yo mismo opero o conozco bien, y configuraría el hook antes. Para un servidor de un marketplace ajeno aplica la misma cautela que con un paquete de npm con script postinstall.

Pruébalo Escribe un hook PreSkillShellCommand que anote cada comando en un archivo de log y luego lo permita. Por qué: después de una semana sabrás qué skills ejecutan comandos de shell y solo entonces podrás bloquear de forma dirigida.

Willison: Tres puntos de inflexión en doce meses

Simon Willison puso por escrito el 24/11 su keynote del AI Engineer Code Summit. La tesis: hubo "three significant inflection points in the abilities of LLMs and coding agents in the past twelve months".[1]

  • Noviembre de 2025, Opus 4.5 y GPT-5.1: "Opus 4.5 was the first model I had used with Claude Code where the default result was generally the right thing." Sobre Codex con GPT-5.1: "it became reliably useful for many of my coding tasks."[1]
  • Junio y julio de 2026, Fable 5 y Mythos: su regla práctica para estos modelos: "Give it a goal, give it the right tools, and watch it cook."[1]
  • Septiembre y octubre de 2026, Opus 5.5, GPT-5.6 Sol, GPT-6 Astra, Gemini 4: los modelos se vuelven fuertes en modelos 3D y juegos. "Opus 5.5 was the first model I'd used that appeared to understand fun."[1]

Su conclusión: "Software development has transformed beyond recognition in the last year."[1]

Mi opinión: el texto no es una noticia de última hora, pero sí un buen mapa para tu propia caja de herramientas. Para ti, el segundo punto de inflexión es el más importante, no el tercero. "Meta más las herramientas correctas" significa: la calidad de tu agente hoy depende más de las herramientas, skills y hooks que lo rodean que del nombre del modelo. Eso encaja justo con la noticia de hoy de Claude Code. Y llama la atención: ninguno de los tres puntos se apoya en un salto de benchmark. Willison mide con la pregunta "¿el resultado por defecto es correcto?", y esa es la prueba que tú también puedes hacer en tu propio repositorio.

OpenHands 1.45: El árbol de agentes se hace visible

OpenHands v1.45.0 salió el 24/11, un día después de v1.44.0.[1] La línea más importante para el día a día: "nest sub-agent conversations under their parent".[1] Cuando un agente lanza ayudantes, ahora ves sus conversaciones con sangría bajo la conversación principal, en lugar de una lista suelta al lado.

Además hay "OpenHands Projects in Canvas (experimental)" y conversaciones de proyecto en la barra lateral con "files and PRs beside the chat".[1] Para las Factories, es decir, automatizaciones recurrentes, la página ahora muestra los logs de trabajo, los más recientes primero.[1]

Actualización desde ayer Ayer Codex CLI 0.172.0 introdujo enlaces que abren "saved conversations and nested agents in the terminal".[2] El mismo día (24.11.) OpenHands hace lo mismo en su interfaz web.

Mi opinión: tres harnesses resuelven el mismo problema en una semana: ¿quién hizo qué cuando mi agente lanzó cinco ayudantes? Es una buena señal. Significa que los subagentes ya llegaron al día a día y no corren solo en demos. Para tu elección entre herramientas, eso pesa más que cualquier comando nuevo. Projects en Canvas es experimental, yo todavía no lo usaría para trabajo real.

Benchmarks: El harness triplica el puntaje

En las últimas tres semanas salieron Fable 5.2 y Mythos 5.2 (09/11), GPT-6.2 Astra y Sol (17/11) y Gemini 4 Neon (18/11).[1][2] Para ninguno hay hoy una entrada independiente en SWE-bench Verified. El tablero independiente de Vals AI tiene el estado del 01/09/2026. En ese entonces Claude Opus 5 iba al frente con 97,00 %, y los primeros cinco quedan entre 95,40 y 97,00 %.[3] O sea, el tablero es viejo y arriba está casi lleno. Por eso hoy no hay gráfica.

Harness: El harness es el programa alrededor del modelo. Le da herramientas al modelo, lee archivos, ejecuta pruebas y decide cuándo la tarea está terminada. Claude Code, Codex y OpenHands son harnesses. Como un carro de carreras: el mismo motor va mucho más rápido en un buen chasis que en uno malo.

Cuánto pesa el harness lo muestra el propio Google. En el anuncio de Google, Gemini 4 Neon alcanza en el benchmark SWE-sweep "a state-of-the-art 39.0% in Google Antigravity", pero en el sencillo harness mini-SWE solo 12,8 %.[2] Es el mismo modelo, con un factor de alrededor de 3 solo por el entorno. Ambas cifras las reporta Google mismo. No hay medición independiente.

Reserva Google también menciona el primer lugar de Neon en el Artificial Analysis Coding Agent Index con 58,6.[2] La página de Artificial Analysis carga sus cifras con JavaScript, así que no pudimos leer el valor ahí por nuestra cuenta. Por eso aquí es un dato del proveedor, no una medición verificada.

Mi opinión: si un cambio de harness triplica el puntaje, una comparación "modelo A contra modelo B" dice poco mientras no se nombre el harness. Para ti significa: prueba un modelo nuevo en el harness que realmente usas, con una tarea de tu repositorio. Esa es también justo la vara de medir de Willison.

Hoy es miércoles veinticinco de noviembre. La noticia principal llega de Claude Code: la versión dos punto uno punto tres tres dos ahora carga skills directamente desde servidores MCP.

Una skill es una pequeña instrucción para Claude, a veces con comandos de shell adentro. Hasta ahora, las skills estaban como archivos en tu computadora. Ahora un servidor MCP puede entregarlas, y aparecen en el menú de diagonal con el nombre del servidor por delante. Pero eso también permite que un servidor meta código en tu máquina. Por eso importa la segunda parte del release: un nuevo hook llamado PreSkillShellCommand, con el que tu propio script revisa y rechaza cada uno de esos comandos.

Un aviso si usas varias computadoras: las versiones anteriores de Claude Code muestran un diálogo al arrancar si la configuración menciona este hook. Así que primero actualiza todas tus Mac. Además, el token OAuth del runner autoalojado ahora puede empezar con oat cero dos, y los filtros de log deben conocerlo. Y a partir del treinta de noviembre, como pronto, los marketplaces de plugins administrados se actualizan solos.

Simon Willison puso por escrito su keynote, sobre tres puntos de inflexión en doce meses. Primero, Opus cuatro punto cinco hace un año, el primer modelo cuyo resultado por defecto casi siempre era correcto. Segundo, los modelos Fable este verano: dales una meta y las herramientas correctas. Tercero, este otoño, modelos fuertes en 3D y juegos. Para el trabajo diario cuenta sobre todo el segundo punto: las herramientas alrededor del modelo marcan la diferencia.

OpenHands versión uno punto cuatro cinco ahora cuelga las conversaciones de subagentes de forma visible bajo su conversación madre. Codex trajo algo parecido ayer. Es decir, tres harnesses resuelven el mismo problema en una semana: tú debes poder ver lo que tus agentes hacen en segundo plano.

En los benchmarks sigue sin haber cifras independientes para los modelos nuevos de Anthropic, OpenAI y Google. Pero el propio Google muestra cuánto pesa el harness: Gemini cuatro Neon llega a treinta y nueve por ciento en el harness de Google, y a doce punto ocho en el harness sencillo. Es el mismo modelo, solo en otro entorno.

Cursor está callado desde el seis de noviembre, Cline sigue en la versión del veintiuno, y Continue y Aider están inactivos. Gemini cuatro Carbon cuesta el doble a partir del primero de diciembre. Mañana veremos si los primeros servidores MCP ya entregan sus skills.
