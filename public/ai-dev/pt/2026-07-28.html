MCP descarta a sessão

O anúncio não deixa margem para interpretação: "The release candidate is locked as of May 21, 2026. The final specification will be published on July 28, 2026." Dez semanas de janela de validação congelada, e hoje é o prazo final. E o núcleo da maior revisão que o MCP já teve não é uma adição, e sim uma exclusão: "The Mcp-Session-Id header and the protocol-level session that came with it are also removed." O handshake de inicialização desaparece, e qualquer requisição pode cair em qualquer instância do servidor. O ganho operacional está escrito, literalmente, no próprio anúncio: "This enables deployment behind a plain round-robin load balancer instead of requiring sticky sessions."

blog.modelcontextprotocol.io · dados de 28/07/2026, 05:13 UTC
MCP e "sem estado": MCP é a norma de tomada entre um modelo de IA e suas ferramentas — um servidor oferece ferramentas (arquivos, GitHub, banco de dados), um cliente como o Claude Code ou o Cursor se conecta a ele, e nenhum dos dois precisa conhecer o outro de antemão. Com estado, até agora, funcionava como uma ficha de guarda-volumes: no primeiro contato você recebe um número, e toda pergunta seguinte precisa ser feita exatamente ao mesmo atendente, porque só ele ainda lembra do que se tratava. Se tem dez pessoas no balcão, você precisa de alguém que te mande de volta para a pessoa certa toda vez — isso são as "sticky sessions". Sem estado significa: cada pergunta já traz consigo tudo o que é necessário, então qualquer um pode respondê-la. Para a operação, é a diferença entre "o servidor é um bichinho de estimação" e "o servidor é substituível".

Três recursos se aposentam

Ao mesmo tempo, três capacidades são descontinuadas — cada uma com um substituto nomeado, nenhuma com dar de ombros:

DescontinuadoSubstituto segundo a spec
Rootsparâmetros de ferramenta, URIs de recurso ou configuração do servidor
Samplingconexão direta com as APIs dos provedores de modelo
Loggingstderr no transporte stdio, OpenTelemetry para observabilidade estruturada

O Sampling, em especial, é um recado: com ele, um servidor conseguia pedir ao cliente que consultasse o modelo em seu lugar — uma ideia elegante, pouco suportada na prática e uma bela porta de entrada para ataques. O MCP devolver isso para as APIs dos provedores é uma redução da superfície de ataque, não uma lacuna de funcionalidade.

blog.modelcontextprotocol.io · dados de 28/07/2026, 05:13 UTC
Sem motivo para correria "Deprecated" não é uma data de desligamento no MCP. A política de ciclo de vida dos recursos mantém os recursos descontinuados "for at least twelve months, or at least ninety days under the policy's expedited-removal exception" na spec, antes que possam sequer ser removidos. Quem usa Roots hoje tem, portanto, pelo menos um ano, não uma noite. modelcontextprotocol.io · dados de 28/07/2026, 05:13 UTC

A mudança mais silenciosa e maior: Extensions

Ao lado da exclusão, existe um framework que me parece mais importante no longo prazo do que a perda da sessão: "Extensions are identified by reverse-DNS IDs, negotiated through an extensions map on client and server capabilities, live in their own ext-* repositories with delegated maintainers, and version independently of the specification." Em bom português: a spec deixa de querer ser tudo sozinha. As extensões ganham repositórios próprios, mantenedores próprios e números de versão próprios — coisas como MCP Apps ou Tasks passam a se mover de forma independente do núcleo. É o mesmo modelo que sustenta os cabeçalhos HTTP há décadas: um núcleo pequeno e rígido, uma periferia flexível e nomeada.

Base de evidências, com honestidade Eu conferi hoje às 05:13 UTC: a página de versionamento do protocolo ainda diz "The current protocol version is 2025-11-25," e o índice do blog traz como post mais recente os SDKs beta de 29/06 — nenhum post sobre o lançamento final. Um detalhe curioso à parte: essa mesma página continua descrevendo que a negociação de versão acontece "during initialization" — justamente no handshake que a nova revisão elimina. O que está registrado aqui, portanto, é o estado anunciado e congelado de hoje, não uma versão ao vivo confirmada pela documentação. O dia ainda é longo.

Por que o prazo é confiável mesmo assim

Porque duas partes independentes já estão agindo de acordo com ele. O próprio servidor MCP do GitHub oferece suporte à nova spec desde 23/07, de forma inequívoca no changelog: "The MCP protocol is going stateless on 28th July 2026, and the GitHub MCP Server supports the latest spec ahead of the official release." E os SDKs beta para Python, TypeScript, Go e C# estão disponíveis desde 29/06 com suporte à versão de 2026-07-28. Quando o maior servidor MCP do mundo já muda antecipadamente, isso deixa de ser um anúncio e vira uma migração.

github.blog (23/07/2026) · blog.modelcontextprotocol.io (29/06/2026)

O que fazer com isso

Três providências concretas, nesta ordem. (1) Se você opera um servidor MCP: a muleta da sticky session no seu load balancer ou ingress pode sair — mas só quando o seu SDK falar a nova versão, então confira a versão em vez de chutar a configuração. (2) Se você usa Roots, Sampling ou Logging: anote o caminho de migração uma vez, sem precisar de plantão de fim de semana — o prazo é de pelo menos doze meses. (3) Se você é só cliente, ou seja, roda Claude Code ou Cursor contra servidores de terceiros: não faça nada hoje. A quebra atinge quem opera servidores, não os usuários.

A licença, finalmente lida no original

Desde ontem circulam resumos de segunda mão sobre a licença. Hoje eu mesmo abri o LICENSE no repositório. Três cláusulas importam. Primeira, a exceção que resolve tudo para a maioria: "internal use of the Software, defined as any use that does not make the Software, its outputs, or its underlying capabilities available to third parties" — o uso interno fica isento. Segunda, o acordo especial: só é necessário quando um licenciado "operates a Model as a Service business, and the aggregate revenue … exceeds 20 million US dollars." Terceira, a obrigação de citar o nome: "Kimi K3" precisa aparecer de forma visível na interface — mas só a partir de mais de 100 milhões de usuários ativos mensais ou US$ 20 milhões de receita mensal. Para uma operação de uma pessoa só, isso significa simplesmente: uso livre. Ainda assim, "Modified MIT" é uma etiqueta enganosa — é uma licença própria com jeitão de MIT, não uma MIT de verdade.

Harness: Um modelo sozinho não resolve uma tarefa de programação — ele precisa de uma estrutura ao redor que mostre arquivos, execute comandos e devolva mensagens de erro. Essa estrutura se chama harness. É como numa prova de culinária: mesmo cozinheiro, cozinha diferente, resultado diferente — e ninguém colocaria duas notas de duas cozinhas na mesma tabela sem anotar qual cozinha era qual. Um número de benchmark sem um harness identificado, portanto, não é um número — é uma afirmação.

67,5 contra 67,3. Dois décimos — isso não é nada, e por isso mesmo é interessante. Ontem, no Frontier-Bench, havia uma diferença de 3,1 pontos entre o número do fabricante e o do ranking; hoje são 0,2. O que une os dois dias não é o tamanho da diferença, mas a sua direção: o número do fabricante sempre fica por cima. Com dois décimos, isso é ruído; com três pontos, era narrativa.

A ressalva de verdade está em outro lugar — na frase com que o K3 é vendido: "Kimi K3 achieved 42.0 on SWE-Marathon, evaluated with the Kimi Code harness, compared to Claude Opus 4.8's 40.0 and GPT-5.6 Sol's 39.0." Ou seja, os números de comparação da concorrência também vêm do harness da Moonshot, não da Anthropic ou da OpenAI. Isso não é desonesto — a configuração está claramente identificada, e uma comparação justa exige rodar todos os modelos na mesma estrutura. Só significa que a vantagem de três pontos é uma afirmação sobre o K3 na cozinha da Moonshot. Até que alguém sem interesse no resultado meça a mesma coisa, isso não é um ranking.

Hoje é terça-feira, 28 de julho. É o dia marcado para o protocolo: o protocolo que suas ferramentas usam para conversar com seus agentes está recebendo a maior mudança da sua história — e o centro dela é uma exclusão.

O MCP está deixando de ter estado. O anúncio diz, em bom português, que o cabeçalho de sessão e a sessão em nível de protocolo por trás dele estão sendo removidos. O handshake de inicialização desaparece. Isso soa técnico, mas é um presente operacional: os servidores agora podem ficar atrás de um balanceador de carga comum, em vez de mandar cada usuário de volta sempre para a mesma instância. Até agora, isso funcionava como uma ficha de guarda-volumes — só um atendente ainda lembrava do que se tratava. A partir de agora, cada requisição carrega o que precisa, e qualquer um pode responder.

Ao mesmo tempo, três recursos se aposentam: Roots, Sampling e Logging. Cada um tem um substituto nomeado — Roots via parâmetros de ferramenta ou configuração do servidor, Sampling via conexão direta com os provedores de modelo, Logging via saída padrão de erro ou OpenTelemetry. Importante para acalmar os nervos: descontinuado não quer dizer desligado no MCP. As regras do projeto mantêm recursos assim na especificação por pelo menos doze meses, noventa dias em caso de urgência. Quem usa Roots hoje tem um ano, não uma noite.

Uma nota de honestidade: eu conferi hoje às cinco e treze da manhã, horário universal coordenado. A página de versionamento do protocolo ainda lista a versão de novembro de dois mil e vinte e cinco como atual, e não há post no blog sobre o lançamento final. Ou seja, o que está neste boletim é o estado anunciado e, desde 21 de maio, congelado — não uma versão ao vivo confirmada pela documentação. Ainda assim, o prazo se sustenta, porque duas partes já estão agindo de acordo com ele: o próprio servidor MCP do GitHub apoia a nova versão desde 23 de julho, e as bibliotecas beta para Python, TypeScript, Go e C sharp estão prontas desde o fim de junho.

A segunda história fecha a pergunta em aberto de ontem. Os pesos do Kimi K três realmente chegaram. O Hugging Face lista cento e sessenta e dois itens no repositório, noventa e seis deles arquivos de modelo; Simon Willison contabiliza um vírgula cinquenta e seis terabyte. De quebra, a categoria do modelo mostra que ele também aceita imagens — nada trivial para agentes que precisam ler capturas de tela.

Um ponto contra a maré da cobertura: em muitos lugares se lê que a Moonshot lançou os pesos um dia antes, na noite do dia vinte e seis. Isso não bate com a nossa própria checagem. Ontem, às cinco e vinte e dois da manhã, horário universal coordenado, ainda havia ali uma página de contagem regressiva sem um único arquivo, e o próprio Hugging Face indica como última alteração o dia vinte e sete de julho às dezesseis e vinte e nove. Ou seja, os pesos chegaram no dia vinte e sete — na hora certa, não antes.

Mais interessante na prática do que o terabyte é o quão curto é o caminho até ele. Pelo Ollama Cloud, um único comando coloca o K três por baixo do seu Claude Code ou OpenCode de sempre. Esse é o teste mais barato para saber se a sua cadeia de agentes é realmente independente de modelo ou só funciona com o Claude por coincidência. É preciso ter uma assinatura paga, e isso consome créditos de uso extras. Sobre a licença, hoje eu li o texto original em vez dos resumos: o uso interno fica isento, um acordo especial só é necessário para quem opera um negócio de Model-as-a-Service com mais de vinte milhões de dólares em receita, e o nome só precisa aparecer na tela a partir de cem milhões de usuários ativos mensais. Para uma operação de uma pessoa só, em outras palavras: uso livre. Deixei de fora, de propósito, dois números que andam circulando — uma suposta taxa de alucinação de cinquenta e um por cento sem fonte primária localizável, e três valores contraditórios para o tamanho do download.

A terceira história é, de novo, uma história de benchmark, dessa vez mais leve. No DeepSWE, o harness do próprio fabricante reporta sessenta e sete vírgula cinco; o harness do ranking independente reporta sessenta e sete vírgula três para o mesmo modelo. Dois décimos não são nada. O interessante é a direção: assim como ontem, o número do fabricante fica por cima. A ressalva de verdade está em outro lugar, porém. Na própria frase de venda, o K três supera o Claude Opus quatro vírgula oito e o GPT cinco vírgula seis Sol no SWE-Marathon com quarenta e dois — só que esses números de comparação também vêm do harness da própria Moonshot. Isso não é desonestidade, é até a forma metodologicamente correta de fazer isso. Só significa que a vantagem é uma afirmação sobre o K três na cozinha da Moonshot, não um ranking.

Vamos à rodada geral. O Claude Code na versão dois ponto um ponto duzentos e dezenove torna o Opus cinco o modelo padrão, com um milhão de tokens de contexto e um modo rápido a dez e cinquenta dólares por milhão de tokens. A linha mais importante: subagentes agora podem iniciar novos subagentes até três níveis de profundidade, em vez de só um. Quem define limites de custo deveria atualizá-los hoje. O Cursor tem um roteador para o modo Auto e lança hoje um plano barato para a Índia. O JetBrains Air agora deixa entrar agentes de terceiros, incluindo Copilot e Cline. E o ranking do Aider continua parado em vinte de novembro de dois mil e vinte e cinco.

Amanhã vamos ver se a página de documentação finalmente chegou na nova revisão do MCP, se as bibliotecas beta se estabilizam — e se alguém fora da Moonshot faz, enfim, uma medição independente do K três.
