Nesta semana, as ferramentas aprendem gestão, não talento

Nos últimos quatro dias, nenhuma das grandes ferramentas lançou algo que torne um modelo melhor. O que chegou nesta semana é gestão

Copilot constrói a ponte de comando

O relatório semanal do GitHub de 07/08 cobre o período de 03 a 07/08 e parece ter sido escrito por alguém que observou como a ferramenta é realmente usada e copiou isso. A barra lateral de sessões ganha atalhos de teclado (n para nova, x para fechar) — algo útil só para quem fica pulando entre sessões em execução o tempo todo. O /rewind agora funciona também sem Git, ou seja, a ferramenta mantém seu próprio histórico paralelo ao controle de versão. Além disso, um novo comando /side, um /worktree experimental e — no VS Code 1.132 — ditado multilíngue que roda localmente no dispositivo.

github.blog — relatório semanal de 07/08/2026, acessado em 09/08/2026
Git worktree: Uma segunda pasta do mesmo projeto, já com checkout feito — arquivos diferentes no disco, mas o mesmo histórico. Como uma segunda bancada na mesma oficina: peça própria, mesma caixa de ferramentas. Para agentes, essa é a divisória mais óbvia que existe de graça: dois agentes em duas worktrees não conseguem alterar os arquivos um do outro por baixo dos panos, e você pode descartar cada uma individualmente sem mexer na outra.

Vale testar Se você roda mais de um agente ao mesmo tempo, vale a pena testar o /worktree — ele substitui exatamente a gambiarra que, do contrário, você faria com git worktree add e organizando janelas na mão. Está marcado como experimental, então nada de usar no branch do cliente.

Claude Code instala uma porta com atraso

Ontem saíram as versões 2.1.225 e 2.1.226. O ponto notável está discreto na lista: "Added a workspace trust prompt to claude agents for untrusted directories, matching the behavior of claude." Ou seja, o comando principal já perguntava havia tempos antes de começar a trabalhar em um diretório desconhecido — o subcomando de agentes, não. Isso não é um recurso novo, é uma porta instalada com atraso, e ela estava aberta no lugar errado: um agente que você coloca em um repositório recém-clonado lê ali configurações e arquivos de instrução antes de qualquer pessoa tê-los lido.

A segunda entrada é uma constatação sobre o contexto de uso. O aviso do limite de gastos agora informa "the cap, its reset time, and the operator's message" e pressupõe um gateway a partir da versão 2.1.225. Um "operador" que define um teto e deixa uma mensagem — isso é Claude Code atrás de um proxy corporativo, com orçamento por equipe. É esse público que está recebendo ferramentas primeiro agora.

A Cline lança no ritmo de quatro em quatro dias

Hoje de madrugada, entre 02:33 e 04:16 UTC: v4.1.7, SDK v0.0.72, Desktop v0.0.11 — três dias depois do último pacote. No conteúdo, isso entra na mesma gaveta do resto da semana: um botão "View Changes" na linha de conclusão, apoiado em checkpoints do SDK, para se ver depois o que uma execução mexeu; contexto de execução nos relatórios de execuções agendadas — "readable headers, schedule metadata, durations, and lifecycle error details"; entradas preservadas em caso de cancelamento; contexto de sessão resistente a interrupções.

E uma entrada que fecha o fio do MCP: "Support pre-registered OAuth clients for remote MCP servers, for setups where dynamic client registration isn't available." A especificação de 28/07 endureceu o login em servidores remotos; quem opera servidores MCP em rede corporativa raramente consegue se registrar de forma dinâmica ali. Doze dias depois, o contorno já está no cliente. É assim que trabalho de especificação parece quando funciona.

Três ferramentas, uma camada

Juntando tudo, o quadro fica claro. Isolamento (worktree), reversão (/rewind, checkpoints), verificação (View Changes), limite de confiança (confirmação de diretório), orçamento (teto do gateway), agenda (execuções programadas): essa não é a lista de recursos de um editor, é a de um sistema operacional para concorrência. A suposição implícita mudou — de "estou falando com um agente" para "tenho vários rodando, e preciso conseguir comprovar depois quem fez o quê".

A objeção honesta a isso: cada um está construindo essa camada sozinho. Checkpoints na Cline, reversão no Copilot, modelo de confiança no Claude Code — seis ferramentas, seis gerenciadores de sessão, nenhuma visão compartilhada do que está acontecendo no seu disco agora. A worktree é a única dessas divisórias que pertence a todo mundo, porque vive no Git, não no produto. É por isso que justamente o comando experimental /worktree é a entrada mais interessante da semana.

Até lá, vale: o número não é confiável.

O que você faz com isso: nada

Esses números já não servem para escolher ferramenta há semanas, e hoje ainda menos. A distância entre o 1º e o 4º lugar é de 3,6 pontos em um board de origem incerta — isso é ruído com casa decimal. A alternativa confiável custa uma tarde: duas tarefas reais do seu próprio projeto, os dois modelos na mesma estrutura, resultado conferido por você mesmo. Isso mede exatamente um repositório — o seu.

Os quatro novos modelos da Ollama não são novos

Circulou pelos trackers em 08/08 a notícia de que a biblioteca da Ollama teria ganhado quatro famílias de modelos: qwen3.6, qwen3.5, gemma4, glm-4.7-flash. Um olhar na própria biblioteca diz outra coisa. Lá está escrito, para gemma4, "Updated 1 month ago", e para os outros três, "Updated 2 months ago". Nada disso é novidade desta semana; as entradas têm de um a dois meses.

É a mesma confusão de já duas vezes neste boletim: "está na minha lista hoje" não é o mesmo que "aconteceu hoje". Um agregador que apresenta o próprio momento de captura como data do evento produz um relato com cara de novo sobre um estado de dois meses atrás. Quem, a partir disso, atualiza a própria instalação local não fez nada de errado — quem lê uma tendência nisso, sim.

github.com/All-Hands-AI/OpenHands/releases (acessado em 09/08/2026) · github.com/cline/cline/releases (acessado em 09/08/2026) · kernel da Cursor via resumo de busca do blog da Cursor, 09/08/2026 — página primária não lida diretamente
Megakernel: Normalmente, uma execução de modelo na placa de vídeo se fragmenta em centenas de pequenos passos de cálculo disparados um a um — cada disparo custa tempo. Um megakernel empacota o máximo possível disso em um único passo de cálculo grande. Como uma cantina que cozinha tudo em uma panela só, em vez de acender e apagar o fogão cem vezes. Para o seu uso local, isso não muda nada: o kernel é feito sob medida para racks de data center. O interessante é quem está por trás disso — uma empresa de editor de código que publica kernels de inferência claramente opera os próprios modelos e otimiza o hardware, não só o produto.
