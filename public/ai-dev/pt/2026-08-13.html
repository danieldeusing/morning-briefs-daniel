O agente da Meta cria árvores de trabalho para si mesmo

Em 05/08, a Meta lançou duas coisas ao mesmo tempo: o Muse Spark 1.2, um modelo para programação com 1 milhão de tokens de contexto que, segundo a própria descrição da Meta, suporta "asynchronous and parallel tool calls for extended development tasks" — e o Muse Code, a ferramenta construída em torno dele. Este último roda exclusivamente no terminal, em macOS e Linux, depois de um único comando de instalação; não existe aplicativo próprio. O status é beta.

developer.meta.ai, publicação de 05/08/2026 · dados de plataforma via macrumors.com de 05/08/2026, ambas lidas em 13/08/2026

O interessante não é o modelo, é a estrutura. A Meta descreve o Muse Code como "purpose-built coding agent designed for long-horizon, multi-agentic coding workflows and transparent auditability" — e o mecanismo concreto por trás disso é a verdadeira diferença: o agente inicia subagentes, e cada um recebe automaticamente sua própria árvore de trabalho do git. Além disso, um registro de eventos sobre tudo o que aconteceu.

Árvore de trabalho do git (worktree): Normalmente você tem um diretório de projeto, e nele existe exatamente um estado do seu código. Uma árvore de trabalho é uma segunda cópia de trabalho completa do mesmo projeto, numa pasta própria, com seu próprio branch — conectada ao mesmo histórico. Como duas mesas com os mesmos papéis: duas pessoas podem mexer em algo ao mesmo tempo sem embaralhar as folhas uma da outra. É exatamente esse o gargalo com agentes paralelos: sem cópias separadas, dois ajudantes escrevem no mesmo arquivo, e depois é você quem organiza os estilhaços.

Por que isso é mais do que uma linha de funcionalidade

Quem trabalha com Claude Code conhece o padrão: as subtarefas até rodam lado a lado, mas compartilham o diretório de trabalho. Quem quer paralelismo de verdade constrói a separação na mão — criando árvores de trabalho, subindo containers, juntando tudo depois. Com o Muse Code, esse trabalho manual passa a ser parte da própria ferramenta. Não é um passe de mágica, mas é o ponto onde os harnesses vão se diferenciar no próximo ano: não no modelo, e sim em isolamento e rastreabilidade serem produto ou tarefa de casa.

Minha parte cética: é beta, é só terminal, e vem de uma empresa cujas ferramentas para desenvolvedores não se destacaram exatamente pela longevidade nos últimos anos. Testar, sim — trocar o fluxo de trabalho por causa disso, não. Try A entrada barata transforma isso num experimento de fim de semana de baixo custo: paralelizar de uma vez uma refatoração ampla e ver se, no fim, a junção sai limpa.

O MCP fica sem estado — e você percebe isso na operação

A spec do MCP de 28/07/2026 é, no fundo, uma reescrita do protocolo: de um protocolo bidirecional e com estado, vira um simples protocolo de requisição-resposta. A frase prática do anúncio: um servidor MCP remoto "can now run behind a plain round-robin load balancer" — sem sessões grudadas, sem cache compartilhado.

blog.modelcontextprotocol.io, publicação de 28/07/2026
Com estado vs. sem estado: Com estado é o chapelaria do teatro — a pessoa atrás do balcão lembra qual casaco é seu, e é exatamente essa pessoa que precisa te atender de novo depois. Sem estado é a chapelaria com ficha numerada: cada pedido traz consigo tudo que é necessário para ser atendido, e não importa nem um pouco quem o recebe. Para a operação, isso significa: você pode colocar cinco servidores iguais e distribuir os pedidos como quiser, em vez de ter que grudar cada usuário numa única instância.

A spec já chegou também à OpenAI: o Codex CLI elevou seu SDK do MCP para 3.0.0 e assim passa a dar suporte à versão de 28/07. No mesmo changelog há um detalhe para quem tem scripts: --full-auto sumiu e foi substituído por --sandbox workspace-write, e chega de novo --approve-for-me. Quem tiver algum desses numa linha de CI deve mexer nisso antes da próxima atualização.

developers.openai.com, changelog, posição de 13/08/2026 (via trecho de busca, página primária não carregada por completo nesta rodada)

Claude Code: cinco versões em cinco dias — uma delas conta

Entre 08/08 e 12/08 saíram cinco versões, de v2.1.225 até v2.1.229. A maior parte é conserto: uma sessão que parou de se redesenhar depois de um bug raro de layout; chaves de funcionalidade que eram avaliadas sem o nível de assinatura quando as credenciais de login estavam expiradas. Mas uma linha da v2.1.229, de 12/08, não é conserto, e sim mudança de postura: flags perigosas do git — --force, --amend, --no-verify — deixam de ser liberadas automaticamente no /commit-push-pr.

code.claude.com, changelog, entrada "2.1.229 (August 12, 2026)", lido em 13/08/2026

O timing não é coincidência. Depois de amanhã, em 14/08, o modo automático passa a ser padrão — a confirmação antes de cada ação deixa de existir. Quem derruba a cerca primeiro e só depois percebe que existe um push forçado liberado automaticamente tem um problema que aparece exatamente uma vez e depois não tem mais volta. O fato de as duas coisas caírem na mesma semana sugere que alguém pensou nisso.

Duas linhas menores da mesma leva são úteis na prática: claude remote-control --continue retoma uma sessão remota, e marketplaces de plugins agora podem resolver comandos de forma dinâmica via uma fonte command, em vez de listá-los de forma estática. github.blog, publicação de 06/08/2026
Pesos abertos: Os valores numéricos treinados do modelo estão liberados para download — então dá para você mesmo rodá-lo, em vez de só alugá-lo pela interface do fornecedor. Não confundir com open source: a receita (dados de treinamento, método) geralmente continua em segredo, o que é entregue é o prato pronto. Para você, o que mais importa: um modelo de pesos abertos não pode ser desligado de um dia para o outro.

O fato de um modelo de pesos abertos estar em pé de igualdade na lista de seleção da integração de IDE mais usada do mundo é um acontecimento maior do que a maioria dos anúncios de modelo desta semana. Ele ganha a sua graça pelo sentido contrário: em 01/09, o Copilot desativa vários modelos, e o Claude Sonnet 4.6 fica disponível só para usuários individuais com assinatura anual. Amanhã vamos ver se o modo automático no Claude Code de fato vira padrão como anunciado — e se finalmente aparece alguém disposto a publicar números reais em vez de gráficos de barras para o Muse Code.
