Fast Mode do Opus 4.8 é removido

Claude Code 2.1.316: o Fast Mode do Opus 4.8 chega ao fim

A versão de 31/10 traz uma linha que você precisa conhecer: "Deprecated fast mode for Opus 4.8 as of October 30, 2026; it will be removed on November 30, 2026."[1] Também é novidade a variável de ambiente CLAUDE_CODE_DISABLE_ULTRATHINK.[1]

Fast Mode: Um interruptor que faz o mesmo modelo responder mais rápido. É como pagar o frete expresso nos Correios: mesma carta, entrega mais rápida. Sem o interruptor, o Opus 4.8 passa a rodar só na velocidade normal.

Minha opinião: isso é um sinal de faxina. O Opus 4.8 não é mais o modelo de ponta, os rankings desta semana são liderados pelo Opus 5.5. Pelo visto, a Anthropic não quer mais manter caminhos especiais para modelos antigos. Se você fixou o Opus 4.8 com Fast Mode em um script, em um pipeline de CI ou nas suas configurações, planeje a troca agora. Caso contrário, algo quebra em 30/11, provavelmente de madrugada, em uma execução que ninguém está acompanhando.

Experimente Rode grep -rn "4-8" ~/.claude .claude nas suas configurações. Cinco minutos agora evitam uma execução quebrada em 30/11.

Adendo: trava de escrita agora é oficial

Ontem nos baseamos, para a 2.1.314, apenas em um espelho de terceiros. O changelog oficial agora confirma, com o nome exato: "Added permissions.blockWritesOutsideWorkingDirectories: Write, Edit and NotebookEdit refuse paths outside the working directories in every permission mode".[1] O importante é "in every permission mode": a trava vale mesmo quando você deixa o agente rodar solto no resto.

Um detalhe menor da 2.1.312 (27/10): o limite de uso agora se chama "5-hour limit" nas mensagens, em vez de "session limit".[1] É só um nome novo, mas mais honesto. O limite depende de uma janela de tempo, não da sua sessão.

Minha opinião: ative a trava de escrita se você roda o Claude Code com permissões amplas. Ela só lhe custa algo se o seu fluxo grava de propósito fora do projeto, por exemplo em /tmp. Nesse caso, inclua o diretório como mais um diretório de trabalho.

Gemini 4 Carbon: na frente, mas por um fio

Até sábado, nada mudou no acesso. Segundo a imprensa, o Carbon vai apenas para empresas selecionadas de defesa cibernética, pelo programa Fairwind do Google. Não há cronograma público.[1] A fonte primária do Google não retornou texto hoje; os fatos vêm da imprensa secundária.

Três rankings colocam o Carbon em 1º lugar. As diferenças, porém, são pequenas:

  • Artificial Analysis Intelligence Index: Carbon 59, Opus 5.5 58, GPT-6 Astra 57, GPT-6.1 Sol 55, Sonnet 5.5 54.[2] Um índice geral, não um teste de programação, e sem data na página.
  • LMArena Text: Carbon 1528 ±9, marcado como "preliminary". Atrás vêm o Gemini 4 Argon com 1520 e o Opus 5.5 com 1509.[3] A página é datada de 27/10, ou seja, antes do anúncio. Não conseguimos ler a aba de programação.
  • Vals: Vals Index 70,36 % (2º lugar), Terminal-Bench 4.0 63,13 % (4º lugar).[4] Em programação, portanto, o Carbon está no grupo de cima, não no topo.

O Google ainda informa números próprios de segurança: 88,2 % no SEC-bench Pro e 0 % de ataques de prompt injection bem-sucedidos no teste Grey Swan. O Opus 5.5 fica em 1 %, o GPT-6 Astra em 8,5 %.[1] São números do fabricante. Não encontramos medição independente.

Prompt Injection: Um atacante esconde comandos em um texto que o agente lê, por exemplo em um README ou em uma issue. O agente acha que é uma tarefa e a executa. É como um bilhete falso "Favor abrir o cofre" que alguém joga na correspondência interna.

Minha opinião: um ponto de diferença no índice AA e 8 pontos de Elo com margem de erro de ±9 não são liderança, são empate. Mais interessante para você é o número de prompt injection. Se ele se sustentar de forma independente, é mais importante para agentes que leem repositórios de terceiros do que um ponto a mais no índice. Até lá, continua sendo uma afirmação feita no próprio teste.

GPT-6.1 Terra: balanço da semana

O Terra chegou em 26/10, a US$ 1 por milhão de tokens de entrada e US$ 5 por milhão de tokens de saída. O ID da API é gpt-6.1-terra, e o modelo também está disponível no Codex.[1] A OpenAI informa 50,3 % no Terminal-Bench 4.0 no modo de maior esforço, contra 21,5 % do antecessor GPT-5.6 Terra.[1] A própria OpenAI diz: para as tarefas de programação mais difíceis, a recomendação continua sendo o GPT-6.1 Sol ou o GPT-6 Astra.[1]

De forma independente, a Vals coloca o Terra em 60,17 % no Vals Index geral, 10º lugar de 28.[2] Temos esse número apenas de um trecho de busca, não da própria página.

Para comparar com a faixa barata: o Claude Haiku 5.5 custa, segundo a Anthropic, US$ 0,10 e US$ 0,50 por milhão de tokens, para prompts de até 100.000 tokens.[3] A Anthropic não informa um número de SWE-bench Verified para o Haiku 5.5.

Cascata de modelos: Você manda toda tarefa primeiro para um modelo barato. Só se ele falhar ou ficar em dúvida, ela vai para um caro. É como um call center: o primeiro nível resolve os casos simples, e os especialistas ficam só com o resto.

Minha opinião: o Terra é exatamente o que a OpenAI promete, um trabalhador barato. Para rotina, como renomear, acrescentar testes ou resumir logs, basta. Para questões de arquitetura, não. A pergunta de verdade é se o Terra compensa em relação ao Haiku 5.5 como primeiro nível de uma cascata. Pelo preço de tabela, o Haiku é dez vezes mais barato. Sem uma medição conjunta no mesmo teste, isso não dá para decidir. Teste no seu próprio repositório.

A semana dos agentes em segundo plano

Três plataformas tomaram a mesma direção nos últimos doze dias:

  • Cursor Agent SDK (20/10): "Agents are defined as code projects, tested with evals, and deployed to Cursor or your own infrastructure." Os gatilhos são GitHub, GitLab, Bitbucket, Slack, webhooks ou cron.[1]
  • GitHub Copilot (28/10, Universe): Copilot Fusion para rotear entre modelos, um app próprio do Copilot, Copilot Automations para fluxos de trabalho compartilhados em equipe. O Copilot agora está incluído no GitHub Enterprise.[2] Não abrimos os detalhes dos itens.
  • Cline 4.1.26 (26/10): um seletor entre execução local e na nuvem. O modelo padrão agora é o Claude Sonnet 5.5.[3]
Agents as Code: Em vez de dizer a um agente no chat o que fazer, você escreve a tarefa dele como um pequeno projeto com testes. Um evento o dispara, por exemplo uma nova issue ou um agendamento. É como a diferença entre chamar um encanador e ter um contrato de manutenção.

Minha opinião: essa é a tendência mais importante da semana, mesmo sem virar manchete. O agente sai do seu editor e vai para o pipeline. Para isso você precisa de evals; senão não percebe quando uma troca de modelo piora o seu agente. O SDK do Cursor é a abordagem mais clara, porque já traz evals embutidos.

Experimente Cursor Agent SDK com um gatilho cron para uma tarefa chata, como um relatório semanal de dependências. Por quê: você aprende a parte de evals em um caso em que errar não custa nada.
