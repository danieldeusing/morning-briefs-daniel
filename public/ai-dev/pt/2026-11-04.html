Claude Code 2.1.318: um release para cron jobs e CI

O release de hoje tem uma lista longa, mas quase tudo gira em torno de uma pergunta: o que acontece quando ninguém está na frente do terminal?[1] Isso importa para você, porque você roda o Claude Code como tarefa agendada.

1 · A expiração do login fica visível

claude auth status agora mostra a data de expiração do login salvo do claude.ai (loginExpiresAt). Nos resultados JSON de claude -p, ela aparece como credential_expires_at. Além disso, há “a one-line stderr warning to claude -p text output, starting 10 days before a stored claude.ai sign-in ends”.[1] Se o login expirar mesmo assim, a mensagem de erro agora indica claude auth login e claude setup-token como saída.

Experimente Rode claude auth status uma vez e anote a data no calendário. Ou leia credential_expires_at no seu script wrapper e mande uma mensagem para você mesmo. Por quê: um login expirado é o motivo mais banal para um job matinal falhar. Até agora você só percebia quando nada chegava.

2 · Chega de falso sucesso

Duas correções mexem nos exit codes. claude -p e as sessões do Agent SDK reportavam sucesso quando um erro de API cortava uma resposta enquanto um mod ficava preso em turn.step. Isso foi corrigido.[1] E os jobs que terminavam com Not logged in porque outro terminal com a mesma conta fez login de novo agora continuam rodando.[1] Junto com o exit code 1 para disco cheio do 2.1.317, o resultado é: seu cron job mente menos.

3 · Shells em segundo plano e o prompt cache

Subagentes em segundo plano agora mandam um comando de shell para o background após três minutos, em todos os provedores, “so the prompt cache doesn't expire while it runs”.[1]

Prompt cache: O provedor guarda por alguns minutos o início longo da sua conversa (prompt de sistema, arquivos). Se você mandar a próxima requisição nesse intervalo, ele não cobra o início inteiro de novo. É como um garçom que ainda lembra do seu pedido. Se você demora demais, precisa repetir tudo, e isso custa.

Minha leitura: é um freio de custo silencioso. Um npm test que roda dez minutos até agora deixava o cache expirar, e a rodada seguinte ficava cara.

4 · Pontos menores que podem te afetar

  • Extensão de IDE: o Claude Code não a instala nem a atualiza mais sozinho quando você o inicia no terminal da IDE. Use /ide a partir de um terminal externo ou a seção de extensões do seu editor.[1]
  • deniedMcpServers: entradas de URL agora também bloqueiam servidores fornecidos pela Anthropic, se a URL upstream coincidir.[1] Quem mantém uma lista de bloqueio deveria dar uma olhada rápida nela.
  • claude mcp add e remove agora esperam o lock do arquivo de config ou terminam com exit code 1.[1] Importante se scripts os chamam em paralelo.

Do 2.1.317 (ontem), o que ainda não tínhamos

  • O stub da ferramenta Read foi removido: “reading an unchanged file again returns its content”.[1] Isso é mais honesto para o modelo, mas pode custar mais tokens se um agente lê o mesmo arquivo grande várias vezes.
  • Corrigido: “Claude treating partial Grep and Glob results as complete when a search hit its time limit”.[1] Era um erro real. O agente concluía, de uma busca interrompida, que algo não existia.

Kimi K3.1 Pro: o dia chegou, os pesos ainda não

A Moonshot escreveu em 23/10: “Full model weights will be released by Nov 4, 2026.”[1] Esse dia é hoje. Na nossa consulta desta manhã, a página da Moonshot no Hugging Face ainda não mostrava nenhum repositório K3.1. O modelo Kimi mais recente lá é o Kimi-K3, de 02/09.[2] “By Nov 4” também pode significar a noite no horário da China. Por isso, ainda não contamos isso como atraso.

Open weights: O modelo em si, ou seja, os bilhões de números aprendidos, fica disponível para download. Você ou um provedor de hospedagem pode rodá-lo em hardware próprio. É como ter a receita em vez do restaurante: você não depende mais de uma cozinha só.

Para contextualizar: na API, o Kimi K3.1 Pro custa US$ 2 por milhão de tokens de input e US$ 10 por milhão de tokens de output.[1] A Artificial Analysis deu ao modelo, em 23/10, um valor de índice de 55, “only Claude Opus 5.5 scored higher, at 58”.[1] Desde então, o Gemini 4 Carbon está acima. A Moonshot não publicou licença, número de parâmetros nem valor de SWE-bench.

Minha leitura: o modelo é grande demais para o seu notebook. O interessante virá pelos provedores de hospedagem. Se os pesos saírem, o que decide são a licença e a questão de a versão aberta ser a mesma da API. Um modelo aberto no nível de ponta pressionaria o preço dos agentes de coding, inclusive para usuários do Claude. Vamos conferir amanhã.

Benchmarks: um ponto de diferença, e nenhum deles mede coding

No Intelligence Index da Artificial Analysis, o Gemini 4 Carbon (esforço “high”) está em 60, o Claude Opus 5.5 (“max with fallback”) em 59 e o GPT-6 Astra (“max”) em 57.[1] Em 31/10 tínhamos lido, no mesmo lugar, Carbon 59 e Opus 5.5 58. Os dois subiram um ponto, provavelmente por novas variantes ou novas rodadas de teste. A página não traz data.

Intelligence Index: Uma empresa independente faz cada modelo passar pela mesma mistura de testes e resume o resultado em um número. É como a média das notas de todas as matérias. Ela diz quem é bom no geral, mas não quem é o melhor em matemática.

Mais interessante para você é a segunda coluna, o custo por rodada de teste. O Carbon chega a US$ 7,76, o Opus 5.5 a US$ 10,04 em “max” e a US$ 6,05 em “xhigh” (índice 57).[1] Quem desce um nível no Opus perde dois pontos e economiza cerca de 40% por rodada.

Para coding, há apenas números dos fabricantes. No Terminal-Bench 4.0, a Anthropic reporta para o Opus 5.5 66,4% em xhigh.[2] Para o Carbon, um agregador cita 65,2% pelo método do próprio Google.[3] Não encontramos valor de SWE-bench Verified para nenhum dos dois. Minha leitura: um ponto de diferença num índice agregado é ruído. E enquanto o Carbon não for público, ninguém pode testá-lo em repositórios reais. Por isso, hoje, sem gráfico.

O Carbon existe desde 28/10 só para defensores de cibersegurança no programa Fairwind. Segundo o DevelopersDigest, custa no lançamento US$ 2 / US$ 10 por milhão de tokens, e depois US$ 4 / US$ 20.[4] Seria o mesmo preço de tabela do Opus 5.5 (US$ 4 / US$ 20).[2] Não conseguimos consultar o próprio Google sobre isso.

Local: um LLM escreve pesos, e o Qwen 3.8 também consegue

O paper “Sparks of Weight-Space Programming” (Takehi, Teoh, Zhang, Khattab) afirma: LLMs podem ler e escrever diretamente os pesos de pequenas redes neurais, sem treiná-las.[1] Simon Willison reproduziu um exemplo e escreve: “Qwen 3.8 27B running on my laptop can do this as well!”[1]

Pesos: Os números de uma rede neural que definem o que ela faz. Normalmente são encontrados por treinamento, ou seja, muita tentativa e erro. Aqui o modelo os escreve direto, como quem anota uma melodia em partitura em vez de procurá-la no piano.

Experimente Se você já tem o Qwen 3.8 27B rodando localmente, o exemplo do Willison é um bom teste para a noite. Por quê: mostra até onde um modelo desse tamanho chega hoje em hardware próprio. Para o seu trabalho diário, o paper não muda nada.
