A semana em uma frase: agentes sem supervisão

Olhe os changelogs desta semana, e quase toda mudança responde à mesma pergunta: o que o agente faz quando ninguém está olhando?

  • Claude Code lançou três releases em cinco dias. No 2.1.319, as tarefas MCP rodam “in the background by default”.[1] A nova configuração permissions.denyInsteadOfPrompting “denies tool calls that would wait on a prompt”.[1] A data varia em um dia: o havoptic cita 06/11, o releasebot cita 07/11.[1][2]
  • Agent SDK: desde o 2.1.317 existe onFailure: "block" para callbacks de hook.[2] Um hook que falha passa a bloquear a ação, em vez de deixá-la passar.
  • Codex CLI 0.167.0 (06/11) tem uma central de comando para agentes, iniciada com codex agents --no-daemon. Ela marca resultados não lidos.[3]
  • OpenAI Agents API (30/10): as sessões podem trocar ferramentas no meio da execução e compactam o contexto em segundo plano por padrão.[4]
  • Cursor: agentes na nuvem constroem um app web com banco de dados e login e o colocam no ar em um link compartilhável (05/11).[5]
Hook: Um pequeno script que o agente chama antes ou depois de uma ação, por exemplo um linter antes de cada commit. É como um porteiro. A pergunta até agora era: o que acontece se o porteiro desmaiar? Com "block", a porta fica fechada.

Minha visão: essa é a direção certa, e ela tem um preço. Antes, a segurança de uma execução de agente era você sentar ao lado e clicar em “Sim”. Agora ela está em um arquivo JSON. Isso é melhor para automação, mas uma linha errada na configuração você só percebe no log. Meu conselho para esta semana: depois de cada execução sem supervisão, leia o log das ações recusadas. Essa lista mostra quais regras faltam ou estão rígidas demais.

Experimente permissions.blockWritesOutsideWorkingDirectories no Claude Code. Segundo o changelog, a configuração bloqueia Write, Edit e NotebookEdit fora das pastas de trabalho, “in every permission mode”.[2] Por quê: um agente que roda sozinho à noite não deveria poder escrever em ~/.ssh nem em outro repositório. É uma linha de configuração para um risco real.

Prazo 30/11: o Fast Mode do Opus 4.8 será removido

Segundo a Anthropic, o Fast Mode do Opus 4.8 está descontinuado “and will be removed on November 30, 2026”. A Anthropic recomenda migrar para o Opus 5.5.[1] A partir de hoje, são 22 dias.

O que você deve verificar antes:

  • Scripts e configurações de agentes que fixam o Opus 4.8 com Fast Mode.
  • Definições de subagentes com um ID de modelo fixo em vez de um alias.
  • Custos: outro modelo precisa de um número diferente de rodadas para a mesma tarefa. Meça uma execução real antes de apagar a configuração antiga.

Minha visão: é uma notícia chata, mas pode quebrar seus cron jobs em silêncio a partir de 01/12. Procure agora, uma vez, com grep o ID do modelo nos seus arquivos de agentes. Leva dois minutos.

Haiku 5.5: barato, mas não para tudo

O Haiku 5.5 saiu já em 07/10. Mesmo assim, importa nesta semana: quando cada vez mais subagentes rodam em segundo plano, o preço por execução conta. O Haiku 5.5 custa US$ 0,10 de entrada e US$ 0,50 de saída por milhão de tokens, até 100.000 tokens de contexto.[1]

Os números são dados do fabricante; não encontramos uma medição independente:

  • Terminal-Bench 4.0: o Haiku 5.5 tem 39,2 %, o Sonnet 5.5 tem 70,6 %.[1]
  • FrontierCode 1.1: o Haiku 5.5 tem 46,4 %.[1]
  • A Anthropic não informa nenhum valor de SWE-bench.
Subagente: Um segundo agente, menor, que o agente principal inicia para uma tarefa parcial, por exemplo “ache todos os lugares que chamam esta função”. É como um aprendiz que busca a ferramenta enquanto o mestre faz o trabalho.

Minha visão: a própria Anthropic diz que o Sonnet e o Opus 5.5 “remain better choices” para tarefas complexas de programação com agentes.[1] Isso é honesto e combina com a distância no Terminal-Bench. Use o Haiku para buscas, resumos e leitura de logs. Para alterar código, não use. Um subagente barato que edita o arquivo errado acaba custando mais do que um caro.

OpenAI: Codex em alpha no sábado, um modelo de segurança na quinta

O Codex CLI estável continua sendo o 0.167.0 de 06/11. No sábado saiu o 0.169.0-alpha.3 como versão prévia.[1] Não analisamos as notas do alpha. Para o trabalho diário, fique na versão estável.

No changelog da API não houve entrada própria do Codex em outubro e novembro. Os novos modelos são o GPT-6.1 Terra (26/10) e o GPT-6-Cyber (05/11).[2] O GPT-6-Cyber foi feito para trabalho de segurança: “finding vulnerabilities, reproducing them in authorized test environments, and verifying fixes”.[2]

Minha visão: o GPT-6-Cyber pertence mais à área de software e segurança do que a esta. A parte “verifying fixes” é interessante para desenvolvedores. Um modelo que verifica se o seu patch realmente fecha a brecha é um bom contrapeso a um agente de programação que escreveu o patch. O lado da segurança pertence ao brief de Software.

Local: Qwen3.8 27B para o domingo

O Qwen3.8 está no Ollama no tamanho 27B, com 18 GB e contexto de 256K. Ele processa texto e imagens.[1] Quando o modelo foi atualizado pela última vez não está claro: a página diz “há 5 horas”, a lista de tags diz “há 1 mês”. Simon Willison mostrou em 03/11 que o Qwen 3.8 27B consegue, no notebook dele, até ler e interpretar pesos de uma rede neural.[2]

Janela de contexto (256K): A quantidade de texto que o modelo consegue manter “na cabeça” de uma vez, aqui cerca de 256.000 tokens. É como uma mesa: quanto maior, mais arquivos ficam abertos ao mesmo tempo. Mas uma mesa cheia também exige mais memória.

Também são novidade na biblioteca do Ollama o kimi-k3.1-pro (há 3 dias) e o mimo-v2.6 (há 4 dias), em 08/11.[3] Se o Kimi K3.1 Pro roda ali como modelo local ou só como variante na nuvem, não verificamos. Com 2,8 trilhões de parâmetros, ele não cabe em nenhum notebook de qualquer forma.

Experimente ollama pull qwen3.8:27b. Por quê: 18 GB cabem em uma máquina com 32 GB de memória, e para explicações de código ou textos de commit você não precisa de um agente na nuvem.

Hoje é domingo, oito de novembro, e o dia está tranquilo. Desde ontem, só saiu uma versão prévia do Codex CLI. Por isso, hoje olhamos para a semana que passou.

O tema da semana é: agentes sem supervisão. O Claude Code lançou três versões em cinco dias. Chamadas MCP longas agora rodam em segundo plano, e uma nova configuração recusa ações em vez de esperar por uma confirmação. O Codex CLI ganhou uma central de comando para agentes, e no Cursor agentes na nuvem colocam aplicativos web inteiros no ar. A segurança, portanto, não está mais no seu clique, e sim na sua configuração. Então, depois de cada execução sem supervisão, leia a lista de ações recusadas.

Uma dica concreta: o Claude Code tem uma configuração que bloqueia gravações fora da pasta de trabalho, em qualquer modo. Para execuções noturnas, é uma linha de configuração contra um risco real.

Um prazo: no dia trinta de novembro, o modo rápido do Opus quatro ponto oito deixa de existir. A Anthropic recomenda o Opus cinco ponto cinco. Faltam vinte e dois dias. Procure agora, nos seus scripts e arquivos de agentes, o ID do modelo antigo.

Quem quer rodar subagentes de forma barata deve olhar o Haiku cinco ponto cinco. Ele custa dez centavos de dólar por milhão de tokens de entrada. Mas, segundo a Anthropic, ele chega a apenas trinta e nove vírgula dois por cento no Terminal-Bench, contra setenta vírgula seis do Sonnet cinco ponto cinco. Use o Haiku para buscar e resumir, não para alterar código.

Na OpenAI, a novidade é o GPT seis Cyber, um modelo para trabalho de segurança, que encontra brechas e verifica patches. Para o notebook, o Qwen três ponto oito no tamanho vinte e sete B é um bom candidato: dezoito gigabytes, duzentos e cinquenta e seis mil tokens de contexto, pelo Ollama.

Hoje não há números novos de benchmark, e por isso também não há gráfico. Entre os agentes de código aberto, o OpenHands foi o mais ativo, com três versões em quatro dias. Cline, Continue e Aider continuam quietos. Na próxima semana, vamos ver se alguém mede os novos modelos de forma independente no SWE-bench.
