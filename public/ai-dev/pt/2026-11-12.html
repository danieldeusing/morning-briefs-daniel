llm 0.37.2: a sua chave da OpenAI podia vazar

Simon Willison publicou em 11/11 uma versão de segurança da sua ferramenta de linha de comando llm. A descrição dele: “Two bugs could send a configured OpenAI API key to other OpenAI-compatible providers.”[1] Há dois avisos de segurança sobre o caso, GHSA-v9h7-jj4g-f862 e GHSA-r639-rr7r-x72w.[1]

Provedor compatível com a OpenAI: Muitos serviços e servidores locais falam a mesma “língua” da API da OpenAI, para que as mesmas ferramentas funcionem com eles. Isso inclui, por exemplo, servidores de modelos locais ou hospedagens baratas. É como um carregador universal. O erro aqui: a ferramenta, ao plugar em tomadas alheias, levava junto também a sua chave da OpenAI.

Por que isso importa para você: quem usa o llm ao lado de um modelo local ou de um provedor terceiro com interface OpenAI tem exatamente a configuração em que o erro age. O destinatário não precisa ser mal-intencionado. Mas uma chave em logs de terceiros é uma chave que você não controla mais.

Minha opinião: é a segunda falha desse tipo em uma semana. O Claude Code 2.1.321, de 09/11, corrigiu um erro parecido: requisições MCP-OAuth enviavam segredos como refresh tokens a outro host quando um servidor as redirecionava.[2] O padrão é o mesmo. Ferramentas que falam com muitos provedores confundem quem pode receber qual chave. Quanto mais provedores você reúne em uma ferramenta, mais importantes ficam essas atualizações.

Experimente Atualize o llm para a 0.37.2 e depois confira no painel da OpenAI o uso da sua chave, procurando chamadas desconhecidas. Por quê: a atualização fecha a brecha só daqui para frente. Se a chave já vazou, só dá para ver ali.

Gemini 4 Carbon no Copilot: a escolha do modelo vira questão de preço

O GitHub informa em 10/11: “Gemini 4 Carbon is available to Copilot Pro+, Max, Business, and Enterprise users.”[1] A liberação é gradual, então talvez você ainda não veja o modelo no menu de seleção. A cobrança é “at provider list pricing under usage-based billing”.[1] Um dia antes, o Claude Fable 5.2 chegou ao Copilot.[2] Não lemos o conteúdo desse aviso, só o título.

  • Carbon hoje: US$ 2 / US$ 10 por milhão de tokens de entrada/saída.[3]
  • Carbon a partir de 01/12: US$ 4 / US$ 20.[3]
  • Fable 5.2: US$ 8 / US$ 40.[4]
Situação das fontes: Os preços do Carbon continuam só no blog de Simon Willison. Também hoje não achamos uma fonte primária do Google. O GitHub não cita número, apenas “preço de tabela do provedor”. Confira o preço antes de contar com ele.

Minha opinião: o detalhe do “preço de tabela” importa mais do que o modelo novo. Com cobrança por uso ao preço do provedor, toda escolha de modelo no Copilot vira uma questão de custo. Aí vale no Copilot a mesma conta do Claude Code ou do Cursor. A vantagem para você: dá para testar Carbon e Fable 5.2 lado a lado no mesmo editor, sem duas contas. A desvantagem: a partir de dezembro você paga o dobro pelo Carbon, e o Copilot simplesmente repassa o salto de preço.

Experimente Se você tem uma assinatura do Copilot compatível: dê a mesma tarefa uma vez ao Carbon e uma vez ao Fable 5.2 e compare os custos no resumo de uso. Por quê: assim você testa sem nova chave de API, enquanto vale o preço de lançamento.

Claude Code: quieto, mas com um prazo à vista

Nenhuma versão nova desde ontem. A atual é a 2.1.322, de 10/11, com Fast Mode no Vertex AI nas regiões global, us e eu. Se o Vertex recusar, o Claude Code volta à velocidade normal.[1] A versão anterior, 2.1.321, torna o Fable 5.2 o modelo Fable padrão, com 1 milhão de tokens de contexto.[1]

Prazo: Segundo as notas de release do Claude Code, o Fast Mode do Opus 4.8 está obsoleto desde 30/10 e acaba em 30/11/2026. Depois disso, pedidos em Fast Mode retornam erro, sem fallback para o Opus 4.8 padrão. A Anthropic recomenda migrar para o Opus 5.5. Verifique, caso você tenha fixado o Opus 4.8 com Fast Mode em scripts.
Fast Mode: O modelo responde mais rápido, e você paga mais por token. É como frete expresso: o mesmo pacote, chega antes, custa mais.

Minha opinião: a calma no Claude Code depois de três releases entre 06 e 10/11 é normal. Se o prazo do Opus 4.8 se confirmar, ele só importa para você onde um nome de modelo está fixo numa configuração. É justamente ali que o fim só aparece quando uma execução noturna falha.

Experimente Procure nos seus repositórios e scripts por IDs de modelo fixos, por exemplo com grep -rn "opus-4-8". Por quê: um minuto de busca evita uma execução quebrada do agente em 01/12.
