Claude Code 2.1.325: correção de segurança ao descompactar

O único release novo de programação desde ontem de manhã: Claude Code 2.1.325. O GitHub mostra 13/11 às 20h40, mas sem ano e sem fuso horário. O rastreador de releases releasebot viu primeiro em 14/11/2026. As notas de release dizem: "Fixed a security issue in how zstd-compressed responses are decoded".[1]

Compressão zstd: zstd (Zstandard) é um formato de compactação como o ZIP, só que mais rápido. Servidores compactam as respostas com ele para que menos dados trafeguem pela rede. O seu cliente precisa descompactá-las de novo. É justamente na descompactação que surgem as falhas clássicas: um pacote manipulado pode derrubar o descompactador, consumir muita memória ("bomba zip") ou provocar algo pior.

O que as notas não dizem: qual era a gravidade do problema, quem podia explorá-lo e se existe um número de CVE. Não encontramos CVE nem aviso de segurança. Por isso não o chamamos assim. Só o local é claro: trata-se das respostas que o Claude Code recebe. Isso afeta toda sessão, não um recurso exótico.

Minha visão: um agente que executa código e grava arquivos é um alvo vantajoso. Qualquer falha no caminho pelo qual os dados entram nele é mais séria do que em uma ferramenta de linha de comando comum. Acho bom que a Anthropic cite a correção em uma linha própria do release, em vez de escondê-la em "bug fixes". Um aviso com nível de gravidade seria melhor. Até haver um, trato isso como "atualizar já" e não como "um dia".

Experimente Execute claude update e confira com claude --version que pelo menos a 2.1.325 está rodando. Por quê: custa um minuto, e correções de segurança são o caso em que "depois" é a resposta errada. Vale especialmente se você roda o Claude Code atrás de um gateway ou proxy próprio.

Balanço da semana: o que ela significa para o seu setup

Quatro releases do Claude Code em uma semana, um novo modelo de ponta e uma nova família Gemini. Aqui está o que fica, na ordem em que muda o seu trabalho diário.

  • Fable 5.2 como novo padrão (09/11) — o Claude Code 2.1.321 torna claude-fable-5-2 o modelo Fable padrão: 1M de contexto, US$ 8 / US$ 40 por milhão de tokens, leituras de cache US$ 0,20.[1] No índice geral da Artificial Analysis ele lidera com 65 pontos.[2]
  • Code Mode (12/11) — no modo opt-in, o Claude escreve JavaScript para chamar suas ferramentas.[1] Dois dias depois, ainda não há números de velocidade ou custo. Minha avaliação de ontem continua: a ideia de harness mais interessante da semana, mas teste primeiro em um repositório descartável.
  • Auto Mode atrás de gateways (06/11) — quando telemetria ou feature flags estão desligadas, por exemplo atrás de um gateway de LLM, o Claude Code agora pergunta ou recusa se o servidor não consegue verificar uma chamada. Não há mais retorno ao classificador embutido.[1] Quem roda o Claude Code por um proxy próprio verá mais perguntas por isso. É intencional, não um erro.
  • Fast Mode no Vertex (10/11) — nas regiões global, us e eu, com retorno à velocidade normal.[1]
  • Managed Agents self-hosted (12/11) — beta privado.[3] Nada para você testar hoje, mas um argumento para clientes com regras de dados rígidas.

Minha visão: a semana é da Anthropic, mas não por causa do Fable 5.2. Um modelo mais forte você percebe em sessões isoladas. O Code Mode e a regra mais rígida do Auto Mode, por outro lado, mudam como o agente trabalha e o que ele pode fazer sem você. Essas são as mudanças que você deve conhecer antes que elas o surpreendam.

Gemini 4: o Hydrogen agora tem preço completo

Ontem nos faltava o preço de saída do Gemini 4 Hydrogen. Simon Willison o informa na entrada do llm-gemini 0.37 de 12/11: US$ 1,50 de entrada, US$ 0,075 para entrada em cache e US$ 7,50 de saída por milhão de tokens. Ele chama o Hydrogen de "the lowest cost member of the Gemini 4 family".[1] O Hydrogen é o novo modelo do plano gratuito e, segundo Willison, move os recursos de IA da Pesquisa Google.[1]

Para Carbon e Argon vale US$ 2 / US$ 10 até 30/11, a partir de 01/12 US$ 4 / US$ 20.[1] O teste do pelicano de Willison (pedir que desenhe um SVG) mostra a diferença no dia a dia: o Hydrogen em nível alto custou 3,99 centavos em 19 segundos, o Carbon 20,31 centavos em 4 minutos e 11 segundos.[1] É uma única tarefa, não um benchmark, mas uma noção honesta da ordem de grandeza.

"Gemini 4 mais barato" não significa barato. Segundo Willison, o Hydrogen custa cerca de 15 vezes mais do que os modelos de US$ 0,10 / US$ 0,50, ou seja, o Claude Haiku 5.5 e o GPT-6 Luna.[1]

Minha visão: o Hydrogen fica num meio-termo incômodo. Para as etapas de rotina de um agente há modelos bem mais baratos, para decisões difíceis há modelos mais fortes. Só fica interessante se for claramente melhor em programação do que o Haiku 5.5 ou o Luna. Não temos número para isso. O Carbon continua sendo o objeto de teste mais interessante até o fim do mês, porque depois o preço dobra.

Experimente Dê ao Carbon e ao Hydrogen a mesma tarefa pequena do seu backlog e compare resultado, tempo e custo. Por quê: até 30/11 a parte do Carbon no teste custa metade, e os números de Willison mostram que a diferença pode ser grande.

Open weights: muitos nomes, poucos dados confirmados

Vários modelos de programação circulam esta semana no tópico de open weights. O problema: para a maioria temos apenas resultados de busca, sem data confirmada e sem medição independente.

  • Poolside Laguna S 2.1 — 118 bilhões de parâmetros, pesos abertos no Hugging Face, licença OpenMDW-1.1, para programação agêntica. Deve caber em um único DGX Spark.[1] A fonte não mostra a data.
  • JetBrains Mellum 2 — um modelo de programação MoE, agora open source.[2] Data também incerta.
  • Ripple-65B Preview (04/11) — Apache 2.0, pesos no Hugging Face. Os 80,5% no TerminalBench 2.1 vêm do próprio fornecedor.[3]
MoE (Mixture of Experts): Um modelo grande feito de muitos submodelos pequenos ("especialistas"). Para cada palavra, só alguns deles calculam. Assim o modelo tem muito conhecimento, mas precisa de apenas uma fração do tempo de computação por resposta. Para você, rodando localmente, isso significa: precisa de muita memória, mas roda mais rápido do que o tamanho total sugere.

Minha visão: 118 bilhões de parâmetros em um único aparelho é o número mais interessante aqui para programação local. Para um laptop comum com Ollama, ainda é grande demais. Para Qwen, DeepSeek e Ollama não encontramos nenhum release novo de programação esta semana. Quem trabalha localmente não perde nada se esperar até haver builds do Ollama e os primeiros testes independentes.
