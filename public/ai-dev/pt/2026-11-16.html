Claude Code: o sistema de permissões, furo por furo

Ontem registramos aqui que o Claude Code recebeu quatro correções de segurança nesta semana. Um olhar mais atento às notas de versão no GitHub mostra: são mais. Só a 2.1.323 (12/11) e a 2.1.325 (13/11) trazem seis correções que afetam diretamente o sistema de permissões ou o sandbox:[1]

  • Comandos compostos (2.1.325): algumas cadeias de Bash rodavam sem confirmação. Agora o Claude Code pergunta.
  • Regra de allow, programa errado (2.1.325): uma regra de allow de Bash podia iniciar um programa diferente do que ela nomeia.
  • Regras de deny após cd (2.1.325): regras relativas como Read(./.env) deixavam de proteger o projeto assim que o agente mudava de diretório.
  • zstd (2.1.325): um problema de segurança ao decodificar respostas comprimidas.
  • Write e Edit contra Read-deny (2.1.323): as duas ferramentas podiam escrever em um caminho coberto por uma regra de deny de Read.
  • Sandbox em claude -p (2.1.323): se a validação de --settings ou das configurações do SDK que ativam o sandbox falhava, o Bash rodava sem sandbox. Isso também afeta o Agent SDK.
Regras de allow, ask e deny: Imagine um porteiro com três listas. Na lista de allow estão os comandos que o agente pode executar sem perguntar. Na lista de ask, ele toca a campainha para você. A lista de deny é proibida. As correções desta semana mostram: às vezes o porteiro leu o nome na lista, mas não conferiu quem realmente estava na porta. Ou, depois de mudar de sala, esqueceu a lista.

Soma-se a isso a 2.1.321 com o vazamento de MCP OAuth, sobre o qual escrevemos ontem. O GitHub data esse release em 09/11, o labmemo em 10/11. Na prática, isso não importa. Uma observação por completude: a página de releases do GitHub corta notas longas. Pode haver, portanto, mais correções do que as listadas aqui.

Minha visão: a correção mais crítica é a de claude -p. No modo interativo, você vê o que o agente faz. No modo headless, em CI ou em um script do Agent SDK, ninguém está olhando. Era exatamente ali que o Bash rodava sem sandbox quando um arquivo de configuração tinha um erro. Isso é o oposto de "fail closed". A correção do cd é a segunda candidata: proteger o .env com uma regra de deny é uma receita padrão, e a receita tinha um furo.

Experimente Confira com claude --version, em cada máquina e em cada imagem de CI, se a versão em uso é pelo menos a 2.1.325. Por quê: versões fixadas em imagens Docker e lockfiles não se atualizam sozinhas, e ali nenhum humano está olhando.

Experimente Escreva as regras de deny para segredos também com caminho absoluto. Por quê: caminhos relativos dependem do diretório atual, e foi exatamente essa a fragilidade desta semana.

Code Mode: a parte silenciosa da 2.1.323

No mesmo release há um recurso experimental: o Code Mode. Com opt-in, o Claude escreve JavaScript para chamar suas ferramentas, em vez de formular cada chamada de ferramenta individualmente.[1]

Code Mode: Normalmente o agente pede cada ferramenta separadamente: "Leia o arquivo A." Resposta. "Leia o arquivo B." Resposta. No Code Mode, ele escreve um pequeno programa que lê dez arquivos, filtra e devolve só o resultado. Isso poupa rodadas e tokens. O preço: mais lógica roda em código que você não aprova passo a passo.

Minha visão: a ideia é boa, e outros harnesses seguem na mesma direção. Mas na mesma semana em que o sistema de permissões teve seis furos, eu só testaria o Code Mode em um repositório descartável. Ainda não encontramos relatos de experiência nem números.

ripple-preview: um modelo aberto de código com grande anúncio

No Ollama está há cerca de seis dias o ripple-preview, da Ricursive Intelligence. Segundo a página do modelo, é um modelo denso com 65 bilhões de parâmetros, "built for agentic coding", sob Apache 2.0, com até 1 milhão de tokens de contexto.[1] A própria listagem mostra 2 milhões em um ponto. O fornecedor informa 80,5 no Terminal-Bench 2.1. Não encontramos medição independente.

Denso versus MoE: Um modelo denso calcula cada token com todos os parâmetros, aqui 65 bilhões. Um modelo MoE ("Mixture of Experts") tem muito mais parâmetros, mas ativa só uma parte deles por token. Para você em casa, isso significa: 65B denso exige muita memória e calcula devagar, mas é mais simples de operar do que um MoE gigante como o Inkling 2 Small com 594B.

Minha visão: 80,5 no Terminal-Bench, vindo de um laboratório que não conhecíamos até agora, é um número em que só acredito quando outra pessoa o medir de novo. As contradições sobre o tamanho do contexto na mesma página me deixam ainda mais cauteloso. Mesmo assim é interessante: Apache 2.0 e foco em código agêntico são exatamente a combinação que falta no local. Com 65B denso, porém, mesmo com quantização de 4 bits, como regra prática você precisa de cerca de 40 GB de memória. Isso é uma questão de Mac Studio, não de notebook.

Experimente Se você tem o hardware: dê ao ripple-preview uma tarefa do seu repositório que o Claude Code resolveu na semana passada e compare. Por quê: seu próprio repositório é o único benchmark que nenhum fornecedor consegue manipular.

Google: Hydrogen no Antigravity, Agent Swarm em teste

O Gemini 4 Hydrogen chegou em 12/11 para usuários Pro e Ultra, no AI Studio e pela Gemini API. Segundo o TestingCatalog, há também acesso pago no Antigravity, a IDE de agentes do Google, e uma nova opção de orquestrador.[1] O Hydrogen custa US$ 1,50 / US$ 7,50 por milhão de tokens.[2] Desde 10/11, o Google também testa um modo Agent Swarm para o Antigravity.[1]

Orquestrador e swarm: Um orquestrador é o gerente de projeto: ele divide uma tarefa e distribui as partes para outros agentes. Um swarm são muitos desses agentes trabalhando em paralelo. O Claude Code já faz isso hoje com subagentes. O Google está correndo atrás.

Minha visão: o Hydrogen fica em 54 no índice da AA, ou seja, onze pontos atrás do Fable 5.2, mas custa menos de um quinto. Esse é o perfil do trabalhador sob um orquestrador, não do orquestrador em si. Detalhes sobre o orquestrador temos só de uma manchete. Como ele funciona, ainda não sabemos.

Hoje é segunda-feira, 16 de novembro. O fim de semana foi tranquilo. Na Anthropic, na OpenAI e na Cursor, não encontramos nada de novo para sábado e domingo. Isso dá tempo para olhar com mais atenção o Claude Code.

Ontem falamos de quatro correções de segurança. Só que as notas de versão no GitHub mostram mais. Apenas as versões de 12 e 13 de novembro fecham seis brechas no sistema de permissões e no sandbox. Alguns comandos compostos de Bash rodavam sem pedir confirmação. Uma regra de allow podia iniciar um programa diferente do que ela nomeia. E regras de deny relativas, por exemplo para o arquivo de segredos, deixavam de valer assim que o agente mudava de diretório.

O erro mais sério atinge o modo headless e o Agent SDK. Se um arquivo de configuração que ativa o sandbox tinha um erro, o Bash rodava totalmente sem sandbox. Justamente onde ninguém está olhando. Por isso, confira em cada máquina e em cada imagem de CI se a versão em uso é pelo menos a dois ponto um ponto três dois cinco.

No mesmo release vem o Code Mode, ainda experimental. Nele, o Claude escreve JavaScript para chamar suas ferramentas. Isso poupa rodadas e tokens. Mas, numa semana com tantas brechas de permissão, eu só o testaria num repositório de teste.

Em catorze dias, em 30 de novembro, o Fast Mode do Opus quatro ponto oito deixa de existir. Depois disso, haverá um erro em vez de um retorno ao modo normal. Em primeiro de dezembro, o Gemini quatro Carbon e o Argon dobram o preço, para quatro dólares de entrada e vinte dólares de saída por milhão de tokens.

Para o Fable cinco ponto dois, continuam sem aparecer medições independentes de código. No índice geral da Artificial Analysis, ele lidera com sessenta e cinco pontos. Os números fortes de código vêm da própria Anthropic. E, no Claude Code, o Fable roda por padrão no nível médio de raciocínio.

No lado local, há um novo candidato: o ripple-preview, no Ollama, um modelo denso com sessenta e cinco bilhões de parâmetros para código agêntico, sob a licença Apache. O fornecedor informa oitenta vírgula cinco no Terminal-Bench, mas ninguém mediu de novo. Para notebooks, serve melhor o pequeno mimo, com nove bilhões de parâmetros.

O OpenHands lançou três releases em três dias. O Google leva o Gemini quatro Hydrogen para o Antigravity, sua IDE de agentes, e testa ali um modo de enxame. O Cline está parado desde 26 de outubro, e o Continue, desde junho.

Amanhã vamos ver se a OpenAI responde ao Fable e se alguém confere de forma independente os números do ripple-preview.
