Claude Code 2.1.326: chega de erros silenciosos

Na noite de segunda-feira saiu a versão 2.1.326. As notas de release no GitHub são tão longas que a página as corta.[1] Funcionalidades novas, quase nenhuma. Em compensação, há dezenas de correções. Lidas em sequência, mostram um padrão: muitos erros passavam em silêncio até agora. Agora o Claude Code os reporta. As mais importantes para você:

  • Regras de ferramenta incompletas: na inicialização, o Claude Code agora avisa quando um valor em --allowedTools, --disallowedTools ou --tools não parece uma regra completa.
  • Arquivo de settings quebrado: se um arquivo de settings fosse salvo com erro no meio da sessão, o Claude Code o ignorava em silêncio. Agora aparece um aviso com o nome do arquivo.
  • Regras que só pareciam salvas: regras de /permissions e pastas de /add-dir pareciam salvas mesmo quando o arquivo não era gravável. Agora o terminal avisa.
  • Resumo errado: comandos como find -delete, cat a > b ou sort -o apagam ou sobrescrevem arquivos. Mesmo assim, apareciam na transcrição como "busca" ou "leitura". Corrigido.
  • claude purge: com a saída padrão redirecionada, as perguntas de confirmação ficavam invisíveis. Um único Enter não visto podia apagar os dados de um projeto. Agora as perguntas sempre aparecem no terminal.
  • Confiança em pastas: seta para cima e Enter respondiam "sim" à pergunta de confiança de uma subpasta. Corrigido.
  • Gateway após falha: sessões em segundo plano perdiam o gateway de LLM do seu shell depois de uma falha. Agora elas param antes de enviar uma requisição ao modelo.
Fail-closed versus fail-open: Uma porta com a fechadura quebrada pode ficar fechada (fail-closed) ou abrir (fail-open). Em segurança, você sempre quer a primeira variante. Muitas correções desta semana movem o Claude Code de "a fechadura está quebrada, mas ninguém percebe" para "a fechadura está quebrada, e uma luz acende".

Minha visão: este é um release chato, e isso é bom. Na semana passada, o assunto eram falhas no sistema de permissões. Esta semana é a pergunta por trás: como você sabe que suas regras estão valendo? O aviso para regras --allowedTools incompletas é o mais valioso para scripts e CI. Um erro de digitação numa regra simplesmente não era regra, e ninguém notava. A correção da transcrição é mais sutil, mas também importante. Quem lê o log de um agente confia que "leitura" signifique leitura.

Experimente Atualize para a 2.1.326 e inicie claude uma vez em cada projeto com settings próprios. Com Ctrl+O você vê mensagens de inicialização escondidas. Por quê: os novos avisos mostram regras e settings que há muito tempo não funcionavam.

Code Mode agora também com Agent Teams

O Code Mode chegou em 12/11 com a 2.1.323 como opt-in experimental. Nele, o Claude escreve JavaScript para chamar suas ferramentas.[1] Com a 2.1.326, ele também pode ser ligado quando Agent Teams estão ativos. Quem já usava o Code Mode agora inicia sessões com times diretamente nele.[1] Duas outras correções dizem respeito a skills com comandos inline ! no Code Mode. Elas não carregavam no Auto Mode ou faziam subagentes em segundo plano falharem.

Agent Teams: Em vez de um agente, trabalha uma pequena equipe. Um agente distribui o trabalho, outros executam partes dele em paralelo. Code Mode significa aqui: cada membro do time escreve um pequeno programa para suas chamadas de ferramenta, em vez de pedir cada chamada individualmente.

Minha visão: quatro dias após o lançamento, já temos a primeira combinação com times e duas correções de skills. Isso mostra que a Anthropic leva o Code Mode a sério. Mas também mostra quantas arestas a funcionalidade ainda tem. Eu continuaria num repositório de teste.

Correção: o Codex entregou em novembro

Ontem escrevemos aqui que a OpenAI não tinha nenhuma entrada do Codex em novembro. Isso valia apenas para o changelog da API. No GitHub, o Codex 0.169.0 de 13/11 é o release estável atual. Ele traz, entre outras coisas, várias abas de side chat no workspace de terminal opcional.[1] Segundo o releasebot, no mesmo dia saiu a 0.168.0 com uma seleção de provedores de modelo ("Browse model providers under Sessions → Model providers") e chats lado a lado.[2] Desde 13/11, também aparecem várias alphas por dia da 0.171.0, hoje já a alpha.11. As notas estão vazias.[1]

Minha visão: a seleção de provedores de modelo é a parte interessante. Um harness que não está preso ao modelo do seu fabricante passa a ser comparável ao OpenHands ou ao Cline. Quão aberto isso é de verdade, ou seja, quais provedores e se endpoints locais funcionam, a nota não diz. Vamos conferir assim que a 0.171 ficar estável.

Experimente Se você tem uma assinatura da OpenAI: teste as abas de side chat da 0.169 para uma pergunta lateral enquanto o agente principal trabalha. Por quê: uma pergunta lateral numa aba própria não atrapalha o contexto do agente principal.

Qwen4-Max: forte na Arena, mas não para você em casa

A Alibaba lançou em 11/11 uma prévia do Qwen4-Max. Segundo duas fontes secundárias, ela existe só no Token Plan, sem pagamento por uso, e termina em 25/11. Benchmarks oficiais e pesos abertos não foram anunciados.[1] Na Code Arena, o Qwen4-Max (xHigh) está provisoriamente em 6º lugar com 1750, logo à frente do Fable 5.1.[2]

Pesos abertos: Os "pesos" são os números aprendidos dentro do modelo, ou seja, o próprio modelo. Se são abertos, você pode baixar o arquivo e rodá-lo com o Ollama na sua máquina. Sem pesos abertos, o modelo é só um serviço na nuvem da Alibaba, como o Claude ou o GPT.

Minha visão: para um workflow local, hoje isso não é notícia. O interessante é a direção: um laboratório chinês aparece num ranking independente de programação ao alcance da vista de Anthropic, Google e OpenAI. Se haverá variantes abertas do Qwen4 mais tarde, não sabemos.
