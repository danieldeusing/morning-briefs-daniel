Claude Code 2.1.328: o modo automático vira padrão

A nova versão saiu em 18 ou 19/11. O rastreador de releases havoptic indica o dia 18, a página de releases do GitHub diz "19 Nov". O essencial está na nota de release: "Added auto mode for Claude Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude apps gateway; interactive sessions with no permission mode start in it".[1]

Isso significa duas coisas. Primeiro, o modo automático agora também existe para empresas que não contratam o Claude direto da Anthropic, e sim pela nuvem delas. Segundo, muda o comportamento na inicialização: quem não define um modo de permissão cai no modo automático, e não mais no modo que pergunta a cada ação. Se isso vale só para os setups de nuvem citados ou para todos, a frase não deixa claro.

Modo automático: Normalmente o Claude Code pergunta antes de muitas ações, por exemplo antes de executar um comando de shell. No modo automático ele não pergunta toda vez. Uma verificação automática decide o que pode rodar sem perguntar. Imagine um estagiário que pode resolver tarefas de rotina sem assinatura, mas ainda assim procura você para algo maior.

A segunda novidade combina com essa: "onFailure": "block" agora também existe para hooks mcp_tool, como já existia para hooks de comando e HTTP. A nota diz: "a hook whose call fails blocks the action".[1] Um hook de segurança que ele mesmo trava, portanto, não deixa mais a ação passar em silêncio.

Fail-closed em vez de fail-open: Um porteiro doente pode ter duas consequências. Ou a porta fica aberta e todo mundo entra. Ou a porta fica fechada até ele voltar. "onFailure: block" escolhe a porta fechada.

Minha leitura: esta semana mostra um padrão claro no Claude Code. Em 13/11 veio uma correção para uma brecha pela qual alguns comandos Bash encadeados rodavam sem perguntar.[1] Agora o modo automático se torna padrão de forma mais ampla e, ao mesmo tempo, chega um interruptor de hook que bloqueia em caso de falha. A Anthropic dá mais liberdade ao agente e constrói a proteção no mesmo movimento. Para você, desenvolvedor individual com acesso direto à Anthropic, provavelmente muda pouco. Para times no Bedrock ou no Foundry, muda bastante: quem trabalhava de propósito com confirmações deve agora definir o modo de permissão explicitamente, em vez de confiar no padrão.

Experimente Se você usa hooks de segurança via ferramentas MCP: defina "onFailure": "block" e faça o hook falhar de propósito uma vez. Por quê: só assim você sabe se a sua proteção realmente se sustenta em caso de erro.

Claude Code 2.1.327, agora lido por completo

Atualização desde ontem Ontem o resumo da opção de stdin foi cortado. Agora está claro qual comando é: "Added claude mcp add-json <name> - to read the server's JSON from stdin, so tokens can stay off the command line".[1]

No mesmo release há uma correção fácil de passar batida. claude mcp add e claude mcp remove com escopo de projeto apagavam outras chaves de nível superior do .mcp.json.[1] Quem mantém entradas próprias ali deve conferir o arquivo no Git uma vez.

Para completar a semana: a 2.1.321 (09/11) tornou o Fable 5.2 o modelo padrão, a 2.1.323 (12/11) trouxe o Code Mode experimental, em que o Claude escreve JavaScript para chamar suas ferramentas. A 2.1.326 (16/11) permite o Code Mode junto com o Agent Teams.[1][2] Oito versões em dez dias.

Experimente Passe configurações MCP com tokens por pipe, por exemplo do 1Password: op read … | claude mcp add-json name -. Por quê: assim o token nunca aparece no histórico do shell.

OpenHands: dois releases em três dias

O harness de código aberto OpenHands entregou duas vezes esta semana.[1]

  • v1.42.0 (18/11): "pick the exact connected git provider for repositories". Importante se você tem GitHub e GitLab conectados em paralelo.
  • v1.41.0 (16/11): "choose the reasoning effort from what the agent reports" via ACP.
Reasoning effort (esforço de raciocínio): Quanto tempo um modelo pensa antes de responder. Mais esforço significa respostas melhores em tarefas difíceis, mas mais tokens e mais custo. O OpenHands agora mostra os níveis que o próprio agente conectado informa, em vez de impor uma lista fixa.

Minha leitura: releases pequenos, mas mostram para onde o OpenHands vai. Ele está virando uma interface neutra à qual se conectam diferentes agentes. Isso combina com um mercado em que o melhor modelo muda toda semana.

GPT-6.2, dia dois: tokens mais baratos, nem sempre tarefas mais baratas

Atualização desde ontem Os preços são conhecidos: o Astra 6.2 custa US$ 8 / US$ 40 por milhão de tokens, o Sol 6.2 continua em US$ 2 / US$ 10.[1] A novidade é o olhar para o custo real por tarefa. Simon Willison faz cada modelo desenhar a mesma imagem de teste em vários níveis de esforço, o seu conhecido pelicano. Os custos por imagem:[1]

ModeloHighXhighMax
GPT-6.2 Astra11,55 ¢17,70 ¢88,71 ¢
GPT-6 Astra18,37 ¢33,85 ¢63,21 ¢
GPT-6.2 Sol2,41 ¢6,74 ¢13,69 ¢
GPT-6.1 Sol3,66 ¢5,39 ¢13,48 ¢

Em High e Xhigh, o Astra 6.2 é claramente mais barato que o antecessor. Em Max, porém, custa mais, embora o preço do token tenha caído 20%. Ou seja, o modelo gasta bem mais tokens ali. Este é um único teste com uma única tarefa, não estatística.

Sobre a qualidade: o teste próprio e não padronizado de Willison pede que os modelos transformem Yonkers em um grande mecha. Seu veredito: "Neither of them did a good enough job", "at least in comparison to Claude Fable 5.2 and Gemini 4 Carbon".[1] O Latent Space resume o clima assim: o Astra 6.2 seria "better and 20%-600% cheaper, but has mixed reviews", e o Sol 6.2 seria "likely main workhorse".[2]

Situação dos benchmarks Para GPT-6.2, Fable 5.2 e Gemini 4 Carbon ainda não há número independente. No repositório SWE-bench Experiments, a última submissão Verified é de 01/09/2026.[3] O placar do Aider não informa data. Os valores da Anthropic para o Fable 5.2 (FrontierCode 2.0: 49,1%, FrontierSWE v2: 69,9%) são informados pelo fornecedor.[4] Por isso, hoje sem gráfico de barras.

Minha leitura: a tabela é a lição mais importante do dia, mais importante que o ranking. Para agentes, não conta o preço por token, e sim o preço por tarefa concluída. E isso depende muito de quanto o modelo pensa. Quem coloca o Astra 6.2 em Max porque "ficou mais barato" pode acabar pagando mais. No dia a dia, há pouco contra o Sol 6.2 em High. Para os casos difíceis, eu ficaria com o modelo que já se provou no seu próprio repositório.

Experimente Na sua próxima execução de agente, meça o custo por tarefa em dois níveis de esforço. Por quê: só esse número diz qual nível compensa no seu repositório.

Gemini 4 Carbon: aberto a desenvolvedores pagantes

O Google abriu o Gemini 4 Carbon para desenvolvedores em 10/11: "Starting today, developers can build with Gemini 4 Carbon." O acesso é pela faixa paga da API no Google AI Studio e no Android Studio, além do Antigravity.[1] A página não traz preços nem números de benchmark. Por isso, não citamos preço de fontes secundárias.

Segundo uma fonte secundária, o Antigravity ganhou uma prévia do /swarm com vários agentes e um orquestrador com o Gemini 4 Carbon. Isso não foi conferido na fonte primária. O Google também está levando os usuários do Gemini CLI para o Antigravity CLI.[2]

Minha leitura: o Carbon chama atenção positiva no teste de Willison e, na tabela da própria Anthropic, ficou até à frente do Fable 5.2 no AutomationBench. Sem preço oficial, porém, não dá para dizer se é a alternativa barata. Quem ainda usa o Gemini CLI deve planejar a migração para o Antigravity CLI.

Hoje é quinta-feira, dezenove de novembro. Depois do grande dia da OpenAI na terça, hoje o clima é calmo. A principal notícia vem do Claude Code.

O Claude Code dois ponto um ponto três dois oito traz o modo automático para o Amazon Bedrock, o Google Cloud, o Microsoft Foundry e o gateway dos apps do Claude, para o Opus quatro ponto seis e o Sonnet quatro ponto seis. Sessões interativas sem modo de permissão definido agora começam nele. No modo automático, o Claude Code não pergunta antes de cada ação; uma verificação automática decide. Quem trabalha de propósito com confirmações deve agora definir o modo explicitamente.

Há ainda um novo interruptor de segurança. Hooks que passam por ferramentas MCP agora podem bloquear a ação quando eles mesmos falham. Ou seja, um vigia quebrado não deixa mais nada passar em silêncio. A versão anterior já permite ler configurações MCP com tokens pela entrada padrão, para que não fiquem no histórico do shell.

Sobre o GPT seis ponto dois, há as primeiras impressões. O Latent Space fala em avaliações mistas. No teste próprio de Simon Willison, nenhum dos novos modelos da OpenAI supera o Claude Fable cinco ponto dois ou o Gemini quatro Carbon. Mais interessante é a tabela de custos dele. No nível mais alto de esforço, o Astra seis ponto dois custa cerca de oitenta e nove centavos por imagem de teste, e o antecessor, cerca de sessenta e três centavos. O preço do token caiu, mas a tarefa ficou mais cara, porque o modelo pensa mais.

Não há números independentes de benchmark para nenhum dos novos modelos de ponta. As submissões do SWE-bench estão paradas desde o início de setembro. Meu conselho continua: meça no seu próprio repositório, e meça o custo por tarefa, não por token.

O Google abriu o Gemini quatro Carbon para desenvolvedores de API pagantes, mas não informa preço na página. O harness de código aberto OpenHands lançou dois pequenos releases. O Cursor está quieto desde seis de novembro, e o Continue, desde junho.

Amanhã vamos ver se aparece a primeira medição independente do GPT seis ponto dois e como os times reagem ao novo modo automático.
