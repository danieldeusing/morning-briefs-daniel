Os primeiros números comparativos: Fable na frente, Sol o mais barato

Fable 5.2 (09/11), GPT-6.2 Astra e Sol (17/11), Gemini 4 Carbon e Neon: até agora, desses modelos só conhecíamos as tabelas dos fornecedores. A VKTR relata em 18/11 duas comparações de terceiros.[1] A primeira é o FrontierCode 2.0 da Cognition.

FrontierCode 2.0: Um teste que avalia o código de IA como os mantenedores de um projeto fazem antes do merge. Se falta um requisito obrigatório, a nota é zero. Como uma prova de direção: furar um sinal de pare anula uma prova de resto boa.

Posição segundo a VKTR: 18/11, sempre o melhor modo de raciocínio, custos a preços de tabela da API.[1] Três coisas chamam a atenção:

  • O Sol 6.2 é quase tão bom quanto o Astra 6.2. Diferença de 0,4 ponto, mas só pouco mais de um quinto do custo.
  • O Astra 6.2 é pouco melhor que o GPT-6 Astra. 44,2 contra 44,0 %. O avanço está no preço, não no desempenho.
  • O Fable 5.2 lidera com folga, mas custa por execução quase catorze vezes o Sol 6.2.

A segunda comparação vem da Artificial Analysis. Seu Coding Agent Index coloca o Claude Code com Fable 5.2 ou Opus 5.5 em 58 pontos, o Codex com Astra 6.2 em 53 e com Sol 6.2 em 50.[1] Com o Astra no Codex em esforço máximo, a AA não vê melhora em relação ao GPT-6 Astra.[1] No Intelligence Index geral, o Astra está em 62, três pontos atrás do Fable 5.2, e o Sol em 57.[1]

Benchmark de harness: O Coding Agent Index não mede só o modelo, mas o pacote de ferramenta e modelo, ou seja, Claude Code ou Codex. Como uma corrida de carros: não ganha o motor, ganha o carro inteiro com o piloto.
Ressalva Não consultamos nós mesmos os leaderboards da Cognition e da Artificial Analysis; ambos carregam seus números por JavaScript. Todos os valores vêm da reportagem da VKTR. A própria VKTR escreve: "Cognition sells a coding agent, so it is not a neutral party".[1] As tarefas vêm de projetos open source públicos. Eles são bem documentados e mais familiares aos modelos do que o seu repositório privado. Não conseguimos conferir no texto os valores próprios da OpenAI no Terminal-Bench para o GPT-6.2, por isso não os citamos. Por essas razões, hoje sem gráfico de barras.

Minha visão: A distância entre os modelos de ponta é pequena, a distância nos custos é enorme. Essa é a notícia de verdade da semana. Quem deixa um agente rodando o dia todo paga com o Fable cerca de catorze vezes o que pagaria com o Sol 6.2 e recebe 6,4 pontos a mais. Para tarefas difíceis pode valer a pena, para a rotina não. Soma-se o efeito do harness: no índice da AA, o Claude Code está cinco pontos à frente do Codex com Astra. Parte disso é a ferramenta, não o modelo. Por isso continua valendo: trocar só o modelo diz pouco. Meça o pacote que você realmente usa.

Experimente Pegue três tarefas reais e já concluídas do seu repositório e rode-as com o seu modelo padrão e com o Sol 6.2. Conte quantas vezes você faria o merge do resultado sem retrabalho e anote o custo. Por quê: É o FrontierCode em miniatura, mas com o seu código em vez de projetos open source.

Claude Code 2.1.330: gráficos no terminal, login para empresas

Em 20/11, às 22:32, saiu a versão seguinte. A novidade mais visível é o easel: "a built-in mod that draws charts when asked and under MCP metrics results".[1] Está disponível para Pro e Max e, onde houver, para Team e Enterprise, em macOS e Linux. Os gráficos automáticos podem ser desligados em /config.[1]

Mod: Uma extensão que muda a própria interface do Claude Code, não só o que o agente faz. O easel é um mod que já vem incluso: se você pede um gráfico ou um servidor MCP entrega métricas, ele desenha a imagem direto na sessão. Como uma calculadora que de repente também desenha curvas.

Importante para empresas: depois de claude auth login, o Claude Code agora assume as configurações de uma organização a partir do console de administração Enterprise da Anthropic e usa o provedor de nuvem ou o gateway dela.[1] Assim a TI administra de forma central, em vez de configurar cada notebook individualmente.

Duas correções atingem problemas do dia a dia:[1]

  • O Claude Code congelava "for up to several minutes" logo depois de compactar uma conversa muito longa.
  • Alterações nas configurações do usuário se perdiam quando vários processos do Claude Code salvavam ao mesmo tempo.
Compactar: Quando uma conversa fica longa demais para a memória do modelo, o Claude Code resume a parte antiga e continua com o resumo. Como a ata de uma reunião longa: nem toda palavra fica, mas as decisões ficam.

A segunda correção combina com a da 2.1.329, em que o ~/.claude.json voltava ao padrão. Quem roda várias sessões em paralelo tinha até agora um risco real para a própria configuração.

A semana no Claude Code Cinco versões em cinco dias:[1]

  • 2.1.326 (16/11): o Code Mode agora também pode ser ativado com Agent Teams.
  • 2.1.327 (17/11): claude mcp add-json <name> - lê o JSON de um servidor MCP via stdin, "so tokens can stay off the command line".
  • 2.1.328 (19/11): modo automático para Opus 4.6 e Sonnet 4.6 no Bedrock, Google Cloud, Foundry e no gateway do Claude Apps.
  • 2.1.329 (19/11): o diálogo de confiança mostra onde os hooks de uma pasta são declarados. Um loop infinito no Code Mode que enchia a memória agora para em um limite.
  • 2.1.330 (20/11): easel, login Enterprise, as correções acima.

Minha visão: o easel é legal, mas não é o motivo para atualizar. O motivo são as duas correções. Quem roda sessões longas com vários terminais abertos deveria atualizar hoje. A lição da 2.1.327 continua a mais útil da semana: tokens não pertencem ao histórico do shell.

Experimente Configure seu próximo servidor MCP com claude mcp add-json name - e passe o JSON por pipe a partir do seu gerenciador de senhas. Por quê: O token não vai parar no ~/.zsh_history.

OpenHands 1.43: automações desde a primeira configuração

A plataforma open source para agentes de código lançou a v1.43.0 em 20/11, dois dias depois da v1.42.0.[1] Duas novidades:

  • "create automations enabled from the setup wizard": quem configura o OpenHands do zero já cria as primeiras automações junto.
  • "show the agent's message edits (experimental)": o chat mostra quando o agente altera depois as próprias mensagens.

A v1.42.0 de 18/11 tinha trazido a escolha do provedor Git exato para os repositórios.[1]

Minha visão: a visão de edições é o recurso mais interessante, mesmo sendo experimental. Quando um agente reescreve as próprias afirmações, você quer ver isso. Em ferramentas fechadas como Cursor ou Codex, essa transparência costuma faltar. O OpenHands continua, assim, a primeira escolha se você quer hospedar um agente por conta própria e rastrear o que ele faz.

Experimente Se você roda o OpenHands localmente: ative a visão de edições numa tarefa mais longa. Por quê: Você vê com que frequência o agente corrige seus estados intermediários e aprende quando deveria intervir mais cedo.

Codex CLI 0.171.0: o resto da nota

O essencial já tínhamos ontem: o Sol 6.2 é o padrão no catálogo de modelos, e codex exec --remote inicia execuções em um app server existente.[1] Falta incluir o workspace da TUI. Agora ele vem ativado por padrão, "with document previews, image previews, and subagent transcripts".[1] O Codex mostra, portanto, no terminal o que seus subagentes fizeram.

Minha visão: os logs de subagentes seguem a mesma ideia da visão de edições no OpenHands. As ferramentas estão construindo mais visibilidade do que acontece em segundo plano. É a direção certa, quanto mais trabalho vai para subagentes.

GPT-6.2 na API: mais barato se você puder esperar

O changelog da API da OpenAI de 17/11 posiciona os dois modelos assim: "Astra targets demanding reasoning and coding tasks, and Sol targets everyday coding and agent workflows."[1] Os preços por milhão de tokens: Astra US$ 8 de entrada e US$ 40 de saída, Sol US$ 2 e US$ 10.[2] Tool calling exige a Responses API.[1]

Novidade são os trabalhos em segundo plano com janela de tempo. Segundo o changelog, os preços de token ficam 30 % menores na janela de duas horas e 40 % menores na janela de oito horas em relação ao padrão. Os novos modelos não oferecem mais suporte ao Flex Processing.[1]

Trabalho com janela de tempo: Você envia uma solicitação e diz: só preciso do resultado em duas ou oito horas. Em troca, paga menos. Como uma encomenda com frete normal em vez de expresso.

Minha visão: Para jobs noturnos de agentes isso é interessante: code reviews, execuções de documentação ou geração de testes que precisam ficar prontos até amanhã. Quem usa Flex hoje terá de reestruturar para os novos modelos.

Hoje é sábado, vinte e um de novembro. Depois de três semanas cheias de modelos novos, chegam as primeiras comparações de terceiros. Há ainda uma atualização do Claude Code e outra do OpenHands.

A reportagem é da VKTR e cita o teste FrontierCode dois ponto zero, da Cognition. O teste avalia o código como os mantenedores fazem antes do merge. O Claude Fable cinco ponto dois lidera com pouco mais de cinquenta por cento, o Opus cinco ponto cinco fica em pouco mais de quarenta e sete. O GPT seis ponto dois Astra chega a pouco mais de quarenta e quatro, e o barato Sol a quase quarenta e quatro por cento. A grande diferença está no custo. Uma execução com o Sol custa cerca de um dólar e trinta centavos, com o Fable quase dezoito dólares.

A Artificial Analysis mede ainda o pacote de ferramenta e modelo. O Claude Code chega a cinquenta e oito pontos, o Codex com Astra a cinquenta e três e com Sol a cinquenta. Ou seja, parte da vantagem vem da ferramenta. A ressalva é importante: só conhecemos todos os números de segunda mão, e a própria Cognition vende um agente de código. Meu conselho: teste o barato Sol com três tarefas reais do seu próprio repositório.

O Claude Code dois ponto um ponto trezentos e trinta traz um mod embutido chamado easel, que desenha gráficos direto na sessão. As empresas agora podem configurar o Claude Code de forma central pelo console de administração. Mais importantes são duas correções: o Claude Code não congela mais por minutos depois de resumir conversas longas, e as configurações não se perdem mais com sessões em paralelo.

O OpenHands um ponto quarenta e três cria automações já na primeira configuração. Também é novidade uma visão experimental que mostra quando o agente altera depois as próprias mensagens. O Codex agora mostra no terminal os logs dos seus subagentes. E a OpenAI deixa os trabalhos da API até quarenta por cento mais baratos se você puder esperar até oito horas pelo resultado.
