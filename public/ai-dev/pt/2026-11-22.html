Gemini 4 Neon: os números de coding do próprio Google

Na sexta-feira só conhecíamos o Neon pelo post de Simon Willison. Agora conseguimos ler o anúncio do Google de 18/11 diretamente.[1] A frase que importa: o Neon está em "#1 overall on the Artificial Analysis Coding Agent Index (58.6)".[1] A InfoWorld repete o mesmo número em 19/11, mas também apenas como declaração do Google.[2]

O problema: ontem o relatório da VKTR dizia que o Claude Code com Fable 5.2 ou Opus 5.5 chega a 58 pontos nesse índice.[3] 58,6 contra 58 é uma diferença que pode surgir só de arredondamento. A página da Artificial Analysis mostra seus valores apenas via JavaScript. Nossa consulta trouxe o título "Coding Agent Index v2.1" e a indicação "15 of 40 models", mas nenhum número.[4] Portanto não podemos confirmar diretamente nenhum dos dois números.

Fonte de todas as linhas: blog do Google de 18/11, acessado em 22/11.[1]

Terminal-Bench: Um teste em que o modelo precisa resolver tarefas reais em uma linha de comando: montar pacotes, analisar logs, configurar servidores. Como uma prova prática na oficina em vez de um teste de múltipla escolha.

A linha mais interessante é a de baixo. No SWE-sweep, um teste que o Google não explica nas frases que lemos, o Neon chega a 12,8 % com o harness enxuto mini-SWE. Na própria ferramenta, o Antigravity, ele "more than triples to a state-of-the-art 39.0%".[1] O próprio Google escreve que isso mostra "what the Antigravity harness unlocks".[1]

Harness: O programa em volta do modelo: dá ferramentas ao modelo, lê arquivos, roda testes e decide quando uma tentativa terminou. O mini-SWE é um harness propositalmente mínimo, o Antigravity é a ferramenta completa de agentes do Google. Como o mesmo cozinheiro, uma vez com um fogareiro de camping e outra numa cozinha profissional.
Ressalva Todo número desta seção vem do Google. Não encontramos registro do Neon no SWE-bench Verified, LiveCodeBench ou LMArena. Os valores da AA não estão acessíveis porque a página carrega via JavaScript. Nas frases que lemos, o Google não diz com qual harness os 58,6 foram medidos. Por isso, hoje, sem gráfico de barras.

O que o Google diz sobre o preço, por outro lado, é claro: US$ 3 por milhão de tokens de entrada, US$ 0,15 para entrada em cache, US$ 15 por milhão de tokens de saída e um contexto de um milhão de tokens.[1] O Neon deve custar 32 % menos por tarefa do que o Carbon.[1] Até 30/11 isso provavelmente não vale, porque o Carbon ainda roda com o preço promocional de US$ 2 / US$ 10.[5] O Neon está disponível na Gemini API via AI Studio e, para clientes pagantes AI Pro e Ultra, no Antigravity.[1]

Minha visão: a frase "#1 overall" é marketing para um empate. A notícia de verdade está na nota de rodapé do próprio Google: o mesmo modelo consegue três vezes mais quando a ferramenta ao redor é melhor. Isso confirma o que o índice da AA já mostrou ontem. Para você, isso significa: testar o Neon no Antigravity diz pouco sobre como o Neon funciona no seu Claude Code ou no seu próprio harness. Quem quer comparar precisa manter a ferramenta igual e trocar só o modelo. Com US$ 3 / US$ 15, o Neon fica no preço entre o Sol e o Fable. Isso o torna interessante para execuções longas de agentes, caso a qualidade seja confirmada de forma independente.

Experimente Se você tem um harness que aceita vários provedores: rode uma tarefa real uma vez com o Neon e outra com seu modelo padrão, na mesma ferramenta. Por quê: só assim você separa o efeito do modelo do efeito do harness, que o próprio Google mostra de forma tão clara.

Experimento de domingo: Code Mode no Claude Code

Desde a v2.1.323 de 12/11, o Claude Code tem o Code Mode: "an experimental opt-in in which Claude writes JavaScript to call its tools".[1] Desde a v2.1.326 de 16/11, ele também pode ser ativado com Agent Teams.[1] Durante a semana muitas vezes falta tempo para testar algo assim. Hoje cabe.

Code Mode: Normalmente o modelo chama uma ferramenta, espera o resultado, lê e chama a próxima. Cada passo é uma rodada própria. No Code Mode, em vez disso, o modelo escreve um pequeno programa que chama várias ferramentas em sequência e processa os resultados por conta própria. Como a diferença entre cinco ligações separadas para o encanador e um bilhete com os cinco serviços.

A vantagem possível: menos rodadas e menos resultados intermediários no contexto quando uma tarefa exige muitas chamadas pequenas de ferramentas. O risco aparece na nota da 2.1.329: um loop infinito no Code Mode que enchia a memória foi interrompido por um limite.[2] Ou seja, o recurso é realmente experimental.

Minha visão: o Code Mode compensa mais em tarefas com muitos passos parecidos, por exemplo "leia estes vinte arquivos e junte todos os TODOs". Para alterações pontuais e cuidadosas em código de produção, eu ficaria no modo normal. Ali você vê cada passo individualmente.

Experimente Ative o Code Mode em um repositório descartável e dê a mesma tarefa de coleta uma vez com e uma vez sem. Compare duração e consumo de tokens. Por quê: depois você sabe se o opt-in vale a pena para o seu dia a dia, antes de ele virar padrão.

Claude Code: você está pelo menos na 2.1.325?

A versão mais recente continua sendo a v2.1.330 de 20/11; na consulta de domingo não havia nada mais novo.[1] Mas o principal motivo para atualizar está uma semana atrás. A v2.1.325 de 13/11 traz duas correções de segurança:[1]

  • "Fixed a security issue in how zstd-compressed responses are decoded."
  • "Fixed some deny and ask rules not applying to certain Bash commands."
Regras deny/ask: Nas configurações você define quais comandos o Claude Code nunca pode executar (deny) e sobre quais ele precisa perguntar antes (ask). Como uma trava de segurança no fogão. A correção significa: em alguns comandos Bash, a trava não funcionava.

Combina com isso a v2.1.329 de 19/11: o diálogo de confiança agora mostra onde os hooks de uma pasta estão declarados.[1] Quem abre um repositório de terceiros vê, portanto, de onde vêm os comandos que rodam automaticamente.

Minha visão: quem confia nas regras deny para manter um agente sob controle e ainda está em uma versão anterior à 2.1.325 tem uma falsa sensação de segurança. claude --version leva um segundo.

Hoje é domingo, vinte e dois de novembro. Um dia tranquilo: no fim de semana, nenhum lançamento novo das grandes empresas. A única novidade é que agora conseguimos ler a página do próprio Google sobre o Gemini quatro Neon.

O Google afirma que o Neon está em primeiro lugar no Coding Agent Index da Artificial Analysis, com cinquenta e oito vírgula seis pontos. Ontem, o relatório da VKTR dizia que o Claude Code está com cinquenta e oito no mesmo índice. Na prática, é um empate. E não conseguimos conferir nenhum dos dois números diretamente no índice, porque a página só carrega os valores por JavaScript.

Mais interessante é outro dado do Google. No teste SWE-sweep, o Neon chega a quase treze por cento com uma ferramenta enxuta e a trinta e nove por cento no Antigravity, a ferramenta do próprio Google. Mesmo modelo, três vezes mais acertos. Ou seja, a ferramenta em volta do modelo pesa pelo menos tanto quanto o próprio modelo. O Neon custa três dólares por milhão de tokens de entrada e quinze dólares por milhão de tokens de saída.

Para o domingo, um experimento: desde meados de novembro, o Claude Code tem um Code Mode experimental. Nele, o Claude escreve um pequeno programa em JavaScript que chama várias ferramentas de uma vez. Teste num repositório descartável com uma tarefa de coleta e compare o tempo e o consumo de tokens.

Um ponto importante de segurança: a versão dois ponto um ponto trezentos e vinte e cinco, de treze de novembro, corrigiu uma falha na decodificação de respostas comprimidas. Além disso, algumas regras de bloqueio e de confirmação não valiam para certos comandos Bash. Quem está numa versão mais antiga deve atualizar.

O Cursor está em silêncio desde seis de novembro, e OpenHands e Codex não têm novidades desde sexta-feira. Em trinta de novembro termina o preço promocional do Gemini quatro Carbon. Na próxima edição, vamos ver se o Neon aparece em alguma medição independente.
