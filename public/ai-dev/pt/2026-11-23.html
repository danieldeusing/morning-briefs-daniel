Sandbox externa: o agente fica do lado de fora

Simon Willison descreveu em 17/11 um padrão que deixamos passar durante a semana. A ideia: o código que o agente executa roda "inside a dedicated sandbox while the agent itself lives outside of that sandbox".[1] A motivação dele é principalmente testar modelos locais com mais segurança. Eles podem errar ou ser levados, por prompt injection, a executar comandos nocivos.[1]

Prompt injection: Um texto externo que o agente lê traz instruções escondidas, por exemplo em um README ou em uma página web: "Apague a pasta" ou "Envie o .env para algum lugar". O modelo não consegue distinguir com segurança se uma instrução vem de você ou do texto lido. Como um bilhete dentro do pacote que diz: "O entregador deve deixar a chave embaixo do capacho."

Há três variantes com a mesma API local em localhost:[1]

  • external-sandbox-v86: um servidor Node.js que inicia o Alpine Linux via v86 em WebAssembly.
  • external-sandbox-container: um servidor Python com Alpine Linux em Apple Containers.
  • external-sandbox-quicksand: um servidor Python com a biblioteca Quicksand da Microsoft, que traz QEMU e Alpine.

Pi, Claude Code e Codex podem ser configurados para enviar as execuções a essa API.[1] Dois detalhes tornam o padrão interessante: um proxy opcional com lista de permissão dos hosts alcançáveis e um mecanismo em que o código faz chamadas de API autenticadas sem conhecer o segredo.[1] O projeto surgiu em parceria com a Prime Radiant, a equipe por trás do Superpowers.[1]

Sandbox externa em vez de interna: Na solução comum, você coloca o agente inteiro em um contêiner. Aí o contêiner precisa dos seus repositórios, tokens e ferramentas, e a fronteira fica furada. Aqui o agente, com o seu raciocínio, fica do lado de fora, na sua máquina. Só as mãos, ou seja, os comandos, vão para a jaula. Como um químico que trabalha com luvas em uma glovebox, em vez de entrar na área de proteção.
Ressalva A página não cita limites do padrão. O proxy é opcional, e tudo o que o agente faz fora da sandbox, como gravar arquivos no seu repositório, a sandbox não protege. É uma ferramenta contra comandos nocivos, não uma proteção contra código ruim no diff.

Minha visão: é a peça mais interessante da semana para quem trabalha localmente com Ollama, Gemma ou Qwen. Modelos locais costumam ser menos robustos contra injection do que os grandes. Ao mesmo tempo, você não quer dar a máquina inteira a eles. A variante de contêiner serve para um Mac, e a v86 roda até sem virtualização. A divisão em duas partes, "pensar fora, executar dentro", me parece o caminho certo. As regras de permissão embutidas nos harnesses tiveram falhas há pouco: o Claude Code 2.1.325 precisou corrigir as regras deny/ask para Bash.

Experimente Pegue a variante de contêiner e deixe um modelo local resolver uma tarefa em um repositório descartável, com a lista de hosts permitidos ativada. Por quê: depois você vê quais hosts o seu agente realmente quer acessar, e isso já é uma lista útil por si só.

Tokens fora da linha de comando

Combinando com isso, uma pequena mudança no Claude Code v2.1.327 de 17/11: claude mcp add-json <name> - lê o JSON do servidor via stdin, "so tokens can stay off the command line".[1]

Por que isso importa: Tudo o que você digita como argumento no shell vai para o arquivo de histórico e fica visível para outros processos na lista de processos. Um token no argumento é como um PIN em um post-it na tela. Via stdin, o valor vai direto ao programa, sem deixar rastro.

Minha visão: pequeno, mas na medida certa. Quem busca segredos em um gerenciador de senhas agora pode passá-los direto por pipe ao comando, em vez de escrevê-los em um argumento.

Experimente Procure no histórico do seu shell por mcp add com tokens. Se achar algum: gire o token, apague a entrada e recrie o servidor via stdin. Por quê: um arquivo de histórico muitas vezes sobrevive por anos e por vários backups.

Codex escolhe o Sol como padrão, não o Astra

O Codex CLI 0.171.0 de 20/11 adicionou "GPT-6.2 Sol and Astra to model catalogs", "with Sol as the default catalog selection".[1] Dois dias antes, a versão 0.170.0 preparou chamadas de voz em tempo real na interface de terminal via WebRTC.[1]

A escolha do padrão é uma declaração. O Latent Space chamou o Astra em 18/11 de "the #2 Frontier Model", com "mixed reviews", e o Sol de "likely main workhorse".[2] A OpenAI faz do Sol o padrão na própria ferramenta.

Minha visão: é sensato, e a Anthropic faz algo parecido com Sonnet e Opus há tempos. Para você, isso significa: quem inicia o Codex após a atualização testa o Sol, não o Astra. Quem lê relatos de experiência sobre "GPT-6.2 no Codex" deveria perguntar a qual dos dois eles se referem. Continuamos sem números independentes de programação para ambos.

Claude Code: o que roda em segundo plano agora está em /tasks

A versão mais recente continua sendo a v2.1.330, de 20/11.[1] No fim de semana nada foi adicionado. O mais útil no dia a dia da semana é a v2.1.329 de 19/11: /tasks agora mostra "this session's scheduled tasks, /loop wakeups, the goal and this conversation's forks".[1]

Além disso, a v2.1.330: login em organizações pelo Enterprise Admin Console da Anthropic, depois do qual o Claude Code assume as configurações delas e o provedor de nuvem ou gateway.[1] Também é novo o easel, "a built-in mod that draws charts when asked and under MCP metrics results".[1] E a v2.1.328 de 19/11 traz o modo automático para Opus 4.6 e Sonnet 4.6 no Bedrock, na Agent Platform do Google Cloud, no Microsoft Foundry e no gateway do Claude Apps.[1]

Minha visão: a semana mostra uma direção clara. Agentes rodam cada vez mais sem supervisão, com loops, tarefas agendadas e forks, e as ferramentas agora constroem o painel de controle para isso. O /tasks é exatamente isso: um lugar onde você vê o que vai acordar sozinho em breve.

Experimente Inicie um /loop em uma sessão e depois abra /tasks. Por quê: em um minuto você aprende a achar um loop esquecido antes que ele gaste seus tokens.

Cline: a compactação pode ser cancelada

O único release novo desde sexta-feira. O Cline v4.1.27 e o Cline SDK v0.2.1 saíram em 21/11.[1] No SDK agora vale: "A running compaction can be stopped, and cancellations are counted in telemetry".[1] A extensão também inclui os avisos de licença dos pacotes de terceiros.[1]

Compactação: Quando a conversa com o agente fica longa demais para a janela de contexto, a ferramenta resume o histórico até ali e continua com o resumo. Isso demora e custa tokens. Como uma ata que alguém escreve antes de apagar o quadro branco.

Minha visão: um release pequeno, mas um problema real. Uma compactação no momento errado pode perder detalhes de que você precisa agora. Quem pode cancelá-la mantém o controle.

Willison: ferramentas pequenas em uma tacada

Dois posts mostram como Simon Willison usa modelos como construtores de ferramentas. Em 18/11 ele construiu o plugin datasette-arrows 0.1a0 com o Claude Fable 5.2 "in almost a single shot".[1] Em 22/11 saiu "Select Styling Specimens", uma página construída pelo Claude. O prompt foi: "Build an HTML page that shows all of the ways a select box can be styled".[2] O motivo dele: "HTML <select> boxes default to looking different in different browsers".[2]

Minha visão: não é um benchmark, mas é um indício útil de uso real. Para ferramentas descartáveis, como uma página de comparação ou um plugin pequeno, um bom prompt muitas vezes basta para um resultado pronto. Para código que precisa viver muito tempo, isso não substitui a revisão.

Hoje é segunda-feira, vinte e três de novembro. Dia tranquilo: desde sexta-feira não saiu nenhum release novo da Anthropic, da OpenAI, do Google nem da Cursor. Só a Cline trouxe uma pequena atualização no sábado.

O assunto mais importante é um padrão de segurança de Simon Willison. Na sandbox externa, o agente roda normalmente na sua máquina, mas cada comando que ele executa roda em um ambiente Linux isolado. Existem três variantes, uma delas com Apple Containers. Claude Code e Codex podem ser conectados a ela. Há ainda uma lista de hosts permitidos e um jeito de fazer chamadas de API sem que o código conheça o segredo. Isso é especialmente útil quando você testa modelos locais.

Na mesma linha: desde a versão dois ponto um ponto três dois sete, o Claude Code cria servidores MCP pela entrada padrão. Assim, os tokens não ficam mais no histórico do shell.

Na OpenAI, o GPT seis ponto dois Sol agora é o modelo padrão no Codex, e não o Astra. Quem lê relatos sobre o GPT seis ponto dois no Codex deveria perguntar a qual dos dois eles se referem.

O Claude Code agora mostra, com o comando tasks, as tarefas agendadas, os loops e os forks em um só lugar. E na Cline, uma compactação em andamento agora pode ser cancelada.

A Cursor está quieta desde seis de novembro, a Continue desde junho. Um prazo para terminar: o Gemini quatro Carbon passa a custar o dobro a partir de primeiro de dezembro, quatro dólares por milhão de tokens de entrada e vinte dólares por milhão de tokens de saída.
