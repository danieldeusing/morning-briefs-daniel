Claude Code 2.1.332: Skills vêm do servidor MCP

O Claude Code 2.1.332 saiu hoje, 25/11. A primeira linha do changelog: "Added skills from MCP servers (beta). They show as server:skill in the / menu; other skills keep their names".[1] Um servidor MCP agora pode oferecer não só ferramentas, mas também instruções de trabalho prontas para o Claude.

MCP e skills: MCP (Model Context Protocol) é um padrão pelo qual um programa oferece ferramentas a um agente, por exemplo "leia este ticket" ou "consulte este banco de dados". Uma skill é uma pequena instrução com texto e, às vezes, comandos de shell que o Claude carrega quando precisa. Até agora, as skills ficavam como arquivos no seu computador. Agora o servidor pode entregá-las junto. Como uma caixa de ferramentas que traz não só chaves de fenda, mas também o manual de montagem.

O segundo ponto do mesmo release é o mais importante: "Added a PreSkillShellCommand hook event that can refuse a skill or command's inline shell commands as it loads".[1] Uma skill pode conter comandos de shell que rodam ao carregar. Se a skill vem de um servidor de terceiros, isso significa que código de terceiros roda. Com o hook, o seu próprio script examina cada um desses comandos e pode recusá-lo.

Hook: Um hook é um script que o Claude Code chama automaticamente em um ponto fixo, por exemplo antes de cada chamada de ferramenta. O script pode dizer "sim" ou "não". Como um segurança que dá uma olhada em cada convidado antes de ele entrar na balada.
Atenção, dois computadores O changelog diz: "on 2.1.331 and older, a settings file naming it opens a dialog at start".[1] Se você usa as mesmas configurações em vários Macs e um deles ainda roda uma versão mais antiga, o Claude Code inicia nele com um diálogo. Primeiro atualize todos os computadores, depois registre o hook.

Do mesmo release, importante para o dia a dia:

  • Prefixo do token: o CLAUDE_CODE_OAUTH_TOKEN do runner self-hosted "can now end in oat02- as well as oat01-". A própria Anthropic escreve: "Update proxy rules and log scrubbers that match oat01-".[1]
  • Aliases de nuvem: na Agent Platform do Google Cloud e no Microsoft Foundry, sonnet agora aponta para o Sonnet 5.5, e o opus do Foundry para o Opus 5.5. No Bedrock, sonnet continua no Sonnet 4.5.[1]
  • Modo automático: sessões no Sonnet 5 ou 5.5 no Bedrock Mantle, Agent Platform e Foundry começam no modo automático quando nenhum modo está definido. Desative com disableAutoMode em "disable".[1]
  • Nome reservado: computer-use é um nome de skill reservado em Macs com Computer Use. Uma skill própria com esse nome não carrega mais.[1]
  • Estabilidade do MCP: servidores SSE não travam mais após um event stream interrompido, e o terminal não congela mais quando um servidor local inunda sua saída padrão.[1]
Prazo Marketplaces de plugins gerenciados em extraKnownMarketplaces se atualizam sozinhos por padrão "on or after November 30, 2026" (anunciado desde a 2.1.331, de 23.11.).[1] Quem quiser travar uma versão define antes "autoUpdate": false na entrada.

Minha opinião: skills vindas do servidor são um passo real para o ecossistema MCP. Um time pode manter seu jeito de trabalhar uma vez no servidor, em vez de copiar arquivos de skill para cada repositório. Mas com isso um servidor MCP vira fonte de código executável, não só de dados. O bom é que a Anthropic entrega o hook no mesmo release, e não três versões depois. Eu só aceitaria skills de servidor de servidores que eu mesmo opero ou conheço bem, e configuraria o hook antes. Para um servidor de um marketplace de terceiros vale o mesmo cuidado que para um pacote npm com script postinstall.

Experimente Escreva um hook PreSkillShellCommand que grava cada comando em um arquivo de log e depois o permite. Por quê: depois de uma semana você sabe quais skills de fato executam comandos de shell e só então pode bloquear de forma direcionada.

Willison: Três pontos de virada em doze meses

Simon Willison escreveu em 24/11 a sua keynote do AI Engineer Code Summit. A tese: houve "three significant inflection points in the abilities of LLMs and coding agents in the past twelve months".[1]

  • Novembro de 2025, Opus 4.5 e GPT-5.1: "Opus 4.5 was the first model I had used with Claude Code where the default result was generally the right thing." Sobre o Codex com GPT-5.1: "it became reliably useful for many of my coding tasks."[1]
  • Junho e julho de 2026, Fable 5 e Mythos: sua regra prática para esses modelos: "Give it a goal, give it the right tools, and watch it cook."[1]
  • Setembro e outubro de 2026, Opus 5.5, GPT-5.6 Sol, GPT-6 Astra, Gemini 4: os modelos ficam fortes em modelos 3D e jogos. "Opus 5.5 was the first model I'd used that appeared to understand fun."[1]

Sua conclusão: "Software development has transformed beyond recognition in the last year."[1]

Minha opinião: o texto não é um acontecimento noticioso, mas é um bom mapa para a sua própria caixa de ferramentas. Para você, o segundo ponto de virada é o mais importante, não o terceiro. "Meta mais as ferramentas certas" significa: a qualidade do seu agente hoje depende mais das ferramentas, skills e hooks ao redor dele do que do nome do modelo. Isso combina exatamente com a notícia de hoje do Claude Code. E chama a atenção: nenhum dos três pontos se apoia em um salto de benchmark. Willison mede pela pergunta "o resultado padrão está certo?", e esse é o teste que você também pode aplicar ao seu próprio repositório.

OpenHands 1.45: A árvore de agentes fica visível

O OpenHands v1.45.0 saiu em 24/11, um dia depois do v1.44.0.[1] A linha mais importante para o dia a dia: "nest sub-agent conversations under their parent".[1] Quando um agente inicia ajudantes, você agora vê as conversas deles recuadas sob a conversa principal, em vez de uma lista solta ao lado.

Além disso há "OpenHands Projects in Canvas (experimental)" e conversas de projeto na barra lateral com "files and PRs beside the chat".[1] Para as Factories, ou seja, automações recorrentes, a página agora mostra os logs de trabalho, os mais novos primeiro.[1]

Atualização desde ontem Ontem o Codex CLI 0.172.0 introduziu links que abrem "saved conversations and nested agents in the terminal".[2] No mesmo dia (24.11.) o OpenHands faz o mesmo na sua interface web.

Minha opinião: três harnesses resolvem o mesmo problema em uma semana: quem fez o quê quando meu agente iniciou cinco ajudantes? É um bom sinal. Significa que subagentes chegaram ao dia a dia e não rodam mais só em demos. Para a sua escolha entre as ferramentas, isso conta mais do que qualquer comando novo. Projects no Canvas é experimental, eu ainda não usaria para trabalho real.

Benchmarks: O harness triplica o score

Nas últimas três semanas saíram o Fable 5.2 e o Mythos 5.2 (09/11), o GPT-6.2 Astra e Sol (17/11) e o Gemini 4 Neon (18/11).[1][2] Para nenhum deles existe hoje uma entrada independente no SWE-bench Verified. O board independente da Vals AI tem a situação de 01/09/2026. Naquela época o Claude Opus 5 liderava com 97,00%, e os cinco primeiros ficam entre 95,40% e 97,00%.[3] Ou seja, o board é antigo e está quase cheio no topo. Por isso hoje sem gráfico.

Harness: O harness é o programa em volta do modelo. Ele dá ferramentas ao modelo, lê arquivos, executa testes e decide quando a tarefa está pronta. Claude Code, Codex e OpenHands são harnesses. Como um carro de corrida: o mesmo motor anda muito mais rápido em um bom chassi do que em um ruim.

O quanto o harness pesa, o próprio Google mostra. No anúncio do Google, o Gemini 4 Neon alcança no benchmark SWE-sweep "a state-of-the-art 39.0% in Google Antigravity", mas no simples harness mini-SWE apenas 12,8%.[2] É o mesmo modelo, com um fator de cerca de 3 só pelo ambiente. Os dois números são do próprio Google. Não há medição independente.

Ressalva O Google também cita o primeiro lugar do Neon no Artificial Analysis Coding Agent Index com 58,6.[2] A página do Artificial Analysis carrega seus números via JavaScript, por isso não conseguimos ler o valor lá por conta própria. Aqui ele é, portanto, uma informação do fornecedor, não uma medição verificada.

Minha opinião: se uma troca de harness triplica o score, uma comparação "modelo A contra modelo B" diz pouco enquanto o harness não for citado. Para você isso significa: teste um modelo novo no harness que você realmente usa, em uma tarefa do seu repositório. É exatamente também a régua do Willison.

Hoje é quarta-feira, vinte e cinco de novembro. A principal notícia vem do Claude Code: a versão dois ponto um ponto três três dois passa a carregar skills diretamente de servidores MCP.

Uma skill é uma pequena instrução para o Claude, às vezes com comandos de shell dentro. Até agora, as skills ficavam como arquivos no seu computador. Agora um servidor MCP pode entregá-las, e elas aparecem no menu da barra, com o nome do servidor na frente. Só que isso também permite que um servidor traga código para a sua máquina. Por isso a segunda parte do release importa: um novo hook chamado PreSkillShellCommand, com o qual o seu próprio script examina e recusa cada um desses comandos.

Um aviso para quem usa vários computadores: versões mais antigas do Claude Code mostram um diálogo na inicialização se as configurações citarem esse hook. Então atualize todos os Macs primeiro. Além disso, o token OAuth do runner self-hosted agora pode começar com oat zero dois, e os filtros de log precisam conhecer isso. E a partir de trinta de novembro, no mínimo, os marketplaces de plugins gerenciados se atualizam sozinhos.

Simon Willison escreveu a sua keynote, sobre três pontos de virada em doze meses. Primeiro, o Opus quatro ponto cinco, há um ano, o primeiro modelo em que o resultado padrão quase sempre estava certo. Segundo, os modelos Fable neste verão: dê a eles uma meta e as ferramentas certas. Terceiro, neste outono, modelos fortes em 3D e jogos. Para o trabalho diário, o que mais conta é o segundo ponto: as ferramentas em volta do modelo fazem a diferença.

O OpenHands versão um ponto quatro cinco agora pendura as conversas de subagentes de forma visível sob a conversa-mãe. O Codex e o OpenHands trouxeram algo parecido ontem. Ou seja, três harnesses resolvem o mesmo problema em uma semana: você precisa ver o que os seus agentes fazem em segundo plano.

Nos benchmarks, continua sem números independentes para os novos modelos da Anthropic, da OpenAI e do Google. Mas o próprio Google mostra o quanto o harness pesa: o Gemini quatro Neon chega a trinta e nove por cento no harness do próprio Google, e a doze vírgula oito no harness simples. É o mesmo modelo, só em outro ambiente.

O Cursor está quieto desde seis de novembro, o Cline continua na versão de vinte e um, e o Continue e o Aider estão dormentes. O Gemini quatro Carbon custa o dobro a partir de primeiro de dezembro. Amanhã vamos ver se os primeiros servidores MCP já entregam suas skills.
