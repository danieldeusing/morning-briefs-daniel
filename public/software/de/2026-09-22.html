Plugin4Shell: Der Pin hält — aber nicht wegen dir

Die Sicherheitsfirma Air Security hat am 17.09. einen Fehler offengelegt, den sie Plugin4Shell nennt und der in der Plugin-Aktualisierung von gleich vier Coding-Agenten steckt: Claude Code, OpenAI Codex, GitHub Copilot und Gemini CLI. Die Hersteller wurden bereits im Juni informiert. Das Ergebnis im schlimmsten Fall ist Code-Ausführung auf dem Entwickler-Rechner, ohne dass der Nutzer irgendetwas anklickt.

Der Mechanismus ist kein Speicherfehler und keine exotische Kryptografie, sondern eine Namensverwechslung. Ein Plugin-Marktplatz legt fest: nimm genau diesen Commit. Der Agent holt sich diesen Commit — und prüft anschließend nie nach, ob er tatsächlich von dort stammt, wo er stehen sollte. The Register formuliert es knapp: Der Agent „checkt exakt den Commit aus, den der Marktplatz gepinnt hat, verifiziert aber nie, dass er dort gelandet ist". Wer das Repository kontrolliert, kann einen Branch anlegen, dessen Name aussieht wie ein Commit-Hash. Git löst die Anfrage dann auf den Branch auf statt auf den Commit — und liefert anderen Code aus, während der Pin nach außen unverändert eingehalten aussieht.

Commit-Pinning: Eine Abhängigkeit nicht auf „neueste Version" festzulegen, sondern auf eine exakte, unveränderliche Kennnummer eines bestimmten Standes — der Commit-Hash. Wie eine Bestellung, die nicht „das Buch von Autor X" sagt, sondern die ISBN nennt: Es soll unmöglich sein, dass ein anderes Buch ankommt. Der Trick hier funktioniert, weil in der Bibliothek ein Regalfach stehen darf, das genauso heißt wie eine ISBN — und der Bote nimmt, was schneller zur Hand ist.

Und jetzt der Teil, der aus dem Bug eine Lehre macht: GitHub verbietet Branch-Namen, die wie Commit-Hashes aussehen. Alles, was aus dem GitHub-Marktplatz installiert wird, war deshalb nie angreifbar. Betroffen sind Plugins, die auf Hostern liegen, die solche Namen erlauben — Bitbucket, eigene Git-Server. Die Sicherheit der Pinnung kam also nicht von der Prüfung im Agenten, sondern von einer Namensregel bei genau einem Anbieter. Das ist dieselbe Klasse wie ein Lockfile ohne Integritäts-Hash: Es sieht aus wie eine Zusage und ist in Wahrheit eine Absichtserklärung.

Marktplatz pinnt Commit→Repo-Besitzer legt Branch mit Hash-Namen an→Git löst auf den Branch auf→Code-Ausführung ohne Klick
Stand der Fixes Claude Code ab 2.1.179, OpenAI Codex ab 0.146.0. Für GitHub Copilot gab es zum Zeitpunkt der Offenlegung keinen Fix; Gemini CLI soll laut The Hacker News gar keinen mehr bekommen, weil das Werkzeug ausläuft.

Meine Sicht: Das gehört nicht in den KI-Ordner, sondern in den Lieferketten-Ordner. Die Agenten-Schicht ist inzwischen ein zweiter, viel jüngerer Paketmanager neben npm und PyPI — eigene Marktplätze, eigene Auto-Update-Logik, deutlich weniger Betriebsjahre an Härtung. Der ChainDrop-Wurm vom August hat gezeigt, wie weit das trägt. Nur hatte npm zwanzig Jahre Zeit, seine Integritätsprüfungen zu lernen.

Pi-hole: vier Lücken, null CVE-Nummern

Am 19.09. ist FTL 6.7.1 erschienen und schließt vier Schwachstellen. Drei davon stuft heise mit CVSS 7,2 ein: Code-Ausführung und Lesen beliebiger Dateien über webserver.advancedOpts, Code-Ausführung über Optionen in misc.dnsmasq_lines, die ihrerseits Befehle ausführen können, und ein Umgehen der Konfigurations-Prüfung über einen Teleporter-Import in Verbindung mit einem verschobenen Dokumenten-Wurzelverzeichnis. Dazu kommt ein Stack-Pufferüberlauf im Pfad für geblockte Antworten (_FTL_make_answer()) mit 6,5. Update wie immer per sudo pihole -up.

Die für den Alltag interessanteste Zeile steht nicht im Score, sondern in den Release-Notes: misc.dnsmasq_lines und webserver.advancedOpts lassen sich ab sofort nicht mehr über die API oder das Web-Interface ändern. Beide bleiben konfigurierbar — über pihole.toml, Umgebungsvariablen und die Kommandozeile. Wer sein Pi-hole per Container-Env oder Ansible bestückt, merkt nichts. Wer die beiden Felder im Browser gepflegt hat, steht nach dem Update vor einem grauen Formularfeld und sollte wissen, warum.

Achtung Für keine der vier Lücken ist bislang eine CVE-Nummer vergeben. Das heißt: Kein Schwachstellen-Scanner, kein Dependabot, keine SBOM-Auswertung wird dich darauf stoßen. Die einzige Erkennungsmethode ist heute die Versionsnummer — und die schaut sich bei einem Gerät, das seit zwei Jahren still im Regal blinkt, niemand freiwillig an.

Es ist die zweite Patch-Runde dieser Art in gut zehn Wochen: Anfang Juli schloss Pi-hole bereits sechs Lücken über FTL, Web und Core, darunter eine Rechteausweitung auf root mit CVSS 8,8 (CVE-2026-50130). Kein Grund, das Projekt schlechtzureden — das ist der Preis dafür, dass jemand ernsthaft hinschaut. Aber Pi-hole gehört damit ins normale Patch-Fenster, nicht ins „läuft ja".

LMU München: 52.000 Datensätze, und niemand fordert etwas

Die Ludwig-Maximilians-Universität München hat am 16.09. einen Angriff auf ihre Systeme bemerkt und ihn am Wochenende öffentlich gemacht. Kopiert wurden nach Darstellung der Universität die vollständigen Immatrikulations-Datensätze von bis zu rund 52.000 Studierenden: Name, Geburtsdatum, Anschrift, E-Mail, Kontoinhaber und IBAN, BAföG-Nummern, Angaben zur Krankenversicherung. Das bayerische Landeskriminalamt ermittelt.

Der Nachtrag vom 21.09. ist der eigentlich bemerkenswerte Teil: Der Angreifer hat sich bis dahin nicht bei der Universität gemeldet. Keine Lösegeldforderung, kein Kontaktversuch, und nach Angaben der LMU auch kein Hinweis darauf, dass die Daten veröffentlicht wurden oder werden sollen.

Warum „keine Forderung" nicht beruhigend ist: Bei einem Erpressungs-Angriff ist der Kontakt der Geschäftszweck — man will bezahlt werden. Bleibt er aus, fallen zwei Erklärungen übrig: Die Daten werden still weiterverkauft, oder sie waren von Anfang an für etwas anderes gedacht. Es ist der Unterschied zwischen einem Einbrecher, der einen Zettel hinterlässt, und einem, der nur das Türschloss fotografiert hat.

Für die Betroffenen ist die IBAN die unangenehmste Zeile. Name, Anschrift, Kontonummer plus die Gewissheit, dass diese Person an der LMU eingeschrieben ist — daraus baut man sehr glaubwürdige Lastschrift-Betrügereien oder eine maßgeschneiderte Mail vom vermeintlichen Studierendenwerk. Kontoauszüge lesen wirkt hier besser als Passwörter wechseln.

Und im Großen: Universitäten sind strukturell weich — zehntausende wechselnde Nutzer, gewachsene Verwaltungssysteme, ein Auftrag zur Offenheit, kein DAX-Budget. Dass Bankdaten dort in derselben Datenbank liegen wie Immatrikulationsdaten, ist keine Nachlässigkeit, sondern die Bauweise. Deshalb war das nicht der letzte Fall dieser Art.

Zwei Verwaltungs-Werkzeuge, zwei Wege hinein

Beide Meldungen von gestern betreffen Software, die man installiert, um Ordnung zu haben — und die dabei mit hohen Rechten im Netz steht.

Zyxel GS1900: neu im KEV-Katalog

Die CISA hat am 21.09. CVE-2026-7273 in ihren Katalog der nachweislich ausgenutzten Schwachstellen aufgenommen — ein Stack-Pufferüberlauf in den Zyxel-GS1900-Switches mit CVSS 8,8. Über eine präparierte HTTP-Anfrage an das CGI-Programm kann ein nicht angemeldeter Angreifer Betriebssystem-Befehle ausführen. Betroffen ist die Firmware bis einschließlich 2.90(ABTQ.1)C0 über die ganze Modellreihe (GS1900-8 bis -48HPv2), behoben in 2.90(ABTQ.2)C0.

„AV:A" — benachbartes Netz: Der CVSS-Vektor sagt hier nicht „aus dem Internet", sondern „aus demselben Netzsegment". Der Angreifer muss also schon im Haus sein — im WLAN, an einer Netzwerkdose, oder auf irgendeinem anderen Gerät im selben Switch. Das senkt die Dringlichkeit und ändert zugleich ihren Charakter: Es ist keine Lücke, über die man hereinkommt, sondern eine, mit der man sich im Inneren ausbreitet.

Diese Switches sind die typische Wahl für kleine Büros, Praxen und Vereinsheime — gekauft, montiert, vergessen. Ein Firmware-Stand von 2.90(ABTQ.1)C0 ist dort die Regel, nicht die Ausnahme.

SolarWinds ARM: ein Schlüssel, der im Programm steht

Ebenfalls am 21.09.: Im Access Rights Manager von SolarWinds steckt CVE-2026-28326 — laut heise können „entfernte Angreifer ohne Authentifizierung ansetzen und Schadcode auf Systeme schieben" — der CVSS-Vektor zeigt allerdings AV:A (adjacent network): der Angreifer muss bereits im selben Netzsegment sitzen, nicht übers offene Internet. Ursache ist ein fest einkompilierter statischer Krypto-Schlüssel. Betroffen sind die ARM-Versionen 2023.2 bis 2023.2.4, die seit Mai 2026 ohnehin das Support-Ende erreicht haben; der Fix liegt in 2026.2.1. Hinweise auf aktive Ausnutzung gibt es laut Hersteller nicht; eine Punktzahl nennt der Bericht nicht, die Einstufung lautet „hoch".

Ein Rechte-Verwalter ist per Definition das System, das weiß, wer worauf darf. Ein Schlüssel, der in jeder Installation derselbe ist, heißt: Wer ihn einmal extrahiert, hat ihn überall. Dass die betroffenen Versionen seit Mai aus dem Support sind, macht es nicht besser — es macht es wahrscheinlicher, dass sie noch laufen.

Spring: 9,8 gegen LOW — wer hat recht?

Update seit Sa Am Samstag stand hier, dass Spring die SSE-Lücke CVE-2026-59313 im funktionalen Web-Framework selbst als LOW einstuft und der freie Fix nur in der 7er-Linie liegt. Was dazugekommen ist: Automatische Bewertungs-Quellen führen dieselbe Lücke als 9,8 kritisch. Das ist keine Kleinigkeit — 9,8 ist der Wert, bei dem Compliance-Werkzeuge Tickets mit Frist erzeugen.

Der Widerspruch ist erklärbar. Der Mechanismus: Ein nacktes Wagenrücklauf-Zeichen in angreifer-kontrolliertem SSE-Text kann Ereignisse im Strom eines anderen Nutzers fälschen oder abschneiden. Bewertet man das mechanisch — über Netzwerk erreichbar, keine Anmeldung, Integrität betroffen —, kommt eine hohe Zahl heraus. Bewertet man die Voraussetzungen, braucht es eine Anwendung, die das funktionale Web-Framework benutzt, und SSE, und ungefilterten Fremdtext im Ereignis-Inhalt. Das ist ein schmaler Pfad.

CVSS vs. EPSS: CVSS misst, wie schlimm es wäre, wenn jemand die Lücke ausnutzt — eine Bauschadens-Bewertung. EPSS schätzt, wie wahrscheinlich es ist, dass es in den nächsten 30 Tagen tatsächlich passiert — eine Wetterprognose. Für diese Lücke liegt die EPSS-Schätzung bei rund 0,39 %. Hoher Schaden, sehr geringe Wahrscheinlichkeit.

Meine Sicht: Der Hersteller hat recht, und der Scanner ist trotzdem nicht kaputt. CVSS war nie als Priorisierungs-Werkzeug gedacht, wird aber überall als eines benutzt — und ein 9,8-Ticket, das man nicht schließen kann, weil der Fix für 6.x hinter einem Support-Vertrag liegt, erzeugt genau den Frust, der Leute beim nächsten Mal gar nicht mehr hinschauen lässt. Wer Spring 6.x fährt: Prüf, ob du überhaupt SSE-Endpunkte auf RouterFunction-Basis hast.

Firefox 156 — und der Wald aus Forks dahinter

Firefox 156 ist laut Mozillas Release-Notes am 15.09. erschienen. Inhaltlich zwei Punkte, die man merkt: Der PDF-Betrachter startet „bis zu 45 % schneller", und WebRTC nutzt auf Windows-ARM64-Geräten jetzt die Hardware-Dekodierung für H.264. Das ist ein solides, unaufgeregtes Release.

Die eigentliche Geschichte erzählt The Register am 19.09. daneben: Mozilla liefert jetzt im Zwei-Wochen-Takt, und ein wachsender Teil der Nutzerschaft will das nicht. Die Liste der Ausweichmöglichkeiten ist mittlerweile lang — LibreWolf, Waterfox (sitzt auf der ESR-153-Basis), Mullvad Browser, Zen Browser, Floorp, dazu Betterbird auf der Thunderbird-Seite. Das Verkaufsargument von Waterfox fasst die Stimmung zusammen: keine KI-Funktionen, eingebauter Werbeblocker, Tab-Bäume, langsamerer Rhythmus.

Für Daniel ist das keine Browser-Wahl, sondern eine CI-Frage. Wenn Firefox, Chrome und Edge alle im Zwei-Wochen-Takt laufen, altert ein gepinnter Playwright-Stand doppelt so schnell wie früher — und die Forks sind Zielumgebungen auf einer anderen Engine-Version als der, gegen die getestet wird. Keine neue Aufgabe, aber eine schnellere Uhr.

Gartner setzt der VMware-Abwanderung eine Zahl vor

The Register zitiert heute, am 22.09., eine Gartner-Prognose: Bis 2029 würden 55 % der Unternehmen Machbarkeitsstudien für Alternativen zu ihren VMware-Installationen starten — heute sind es 25 %. Treiber ist die Umstellung auf Abrechnung pro CPU-Kern nach der Broadcom-Übernahme, die laut Gartner zu „erheblichen Kostensteigerungen" geführt hat. Die 2029er-Marke ist kein Zufall: Dann laufen die ersten Drei-Jahres-Abos aus der Umstellungswelle aus.

Interessant ist, dass Gartner die Alternativen nicht schönredet: AWS Local Zones kosten 15 bis 35 % mehr als die zugehörige Hauptregion, Nutanix' Lizenzmodelle seien „komplex und weniger wettbewerbsfähig", und bei Microsoft braucht man für Alltagsaufgaben „mehrere unzusammenhängende Verwaltungskonsolen". Genannt werden außerdem Oracle, HPE — und Proxmox.

Dass ein Open-Source-Hypervisor in einer Gartner-Liste neben AWS und Microsoft steht, ist die eigentliche Nachricht — vor drei Jahren wäre das eine Fußnote für Bastler gewesen. Das Muster lohnt sich zu merken: Die stärkste Werbung für quelloffene Infrastruktur macht selten die Community, sondern fast immer der Lizenzvertrag der kommerziellen Alternative.

Der Aufmacher heißt Plugin for Shell, Plugin4Shell, und betrifft vier Coding-Agenten: Claude Code, OpenAI Codex, GitHub Copilot und Gemini CLI. Alle vier pinnen ihre Plugins auf einen exakten Commit-Hash, damit beim automatischen Update garantiert derselbe Code ankommt. Nur prüft keiner nach, ob dieser Commit auch wirklich von dort stammt, wo er stehen sollte. Wer das Repository kontrolliert, legt einen Branch an, dessen Name aussieht wie ein Commit-Hash — und Git liefert dann den Branch aus statt des Commits.

Das Bild dazu: Man bestellt nicht das Buch von Autor X, sondern nennt die ISBN, damit garantiert nichts anderes ankommt. Der Trick funktioniert, weil in der Bibliothek ein Regalfach stehen darf, das genauso heißt wie eine ISBN. Die Sicherheit kam also nicht aus der Prüfung im Agenten, sondern aus einer Namensregel bei einem einzigen Anbieter. Claude Code ist ab Version zwei Punkt eins Punkt einhundertneunundsiebzig gepatcht, Codex ab null Punkt einhundertsechsundvierzig. Nebenbei lassen sich zwei der betroffenen Felder ab jetzt nicht mehr über die Web-Oberfläche ändern, sondern nur noch über die Konfigurationsdatei.
