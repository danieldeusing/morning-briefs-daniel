PHP, Teil drei: eine Lücke ohne Patch, aber mit schmaler Angriffsfläche [1][2]

Seit gestern Am Freitag, 23.10., hat das PHP-Team CVE-2026-115560 gemeldet, eine Lücke rund um den Upload-Fortschritt von Sessions. Laut BleepingComputer gibt es noch keinen Patch; PHP will die Lücke im normalen Release-Zyklus schließen und mit dem nächsten Release ein volles Advisory veröffentlichen.[1] Eine Ausnutzung meldet der Artikel nicht, einen CVSS-Wert auch nicht.

Betroffen ist nur eine seltene Kombination. Eine App setzt session.serialize_handler in der Konfiguration auf php_binary oder php_serialize und schaltet ihn zur Laufzeit per ini_set() auf php um, bevor sie session_start() aufruft. Zusätzlich muss der Upload-Fortschritt aktiv sein.[1] Wer den Handler nie zur Laufzeit ändert, ist nicht betroffen.

Session-Serializer: Das Format, in dem PHP die Daten einer Sitzung auf die Platte schreibt und wieder einliest. Schreibt man in einem Format und liest im anderen, ist das wie ein Brief auf Deutsch, den jemand als Code für einen Tresor liest. Dabei kann Unsinn entstehen, den ein Angreifer steuert.

Die Abhilfe ist dieselbe Einstellung, die php.net schon für PHP2Shell empfohlen hat: session.upload_progress.enabled=0. Wer sie diese Woche schon gesetzt hat, lässt sie stehen.[1][2]

Unsere Sicht Nach einer Woche mit Notfall-Patches ist das ein gutes Zeichen, kein schlechtes. Die Leute schauen sich den Session-Code jetzt genau an, und PHP kommuniziert offen statt still. Für die meisten Frameworks ist das ein Grep auf serialize_handler, mehr nicht.

HPE ArubaOS: 72 Lücken, acht der Maximal-Stufe [1]

HPE hat am 23.10. Fixes für 72 Lücken in ArubaOS veröffentlicht, dem Betriebssystem für Aruba-Controller, Access Points und Gateways. Acht davon sind in der höchsten Stufe: Umgehung der Anmeldung, Command Injection, SQL-Injection und Pufferüberläufe, jeweils mit Code-Ausführung, verteilt auf AOS-8 und AOS-10 (CVE-2026-79844 bis -79851).[1]

Ausnutzung ist nicht bekannt. HPE schreibt: „HPE Networking is not aware of any public discussion or exploit code that targets the listed vulnerabilities“. Als Übergang rät HPE, CLI und Web-Oberfläche auf ein eigenes VLAN zu beschränken oder per Firewall abzuschirmen.[1] Konkrete Fix-Versionen nennt der Artikel nicht; die stehen im HPE-Advisory.

Unsere Sicht Acht unauthentifizierte Wege zur Code-Ausführung in einem WLAN-Controller sind eine Einladung. Noch gibt es keinen Exploit. Erfahrungsgemäß ändert sich das bei Netzwerk-Hardware schnell, sobald jemand die Patches vergleicht.
[1] bleepingcomputer.com (23.10.)

Lieferkette I: die verwaiste Update-Domain [1]

Time4Popcorn, ein Fork des BitTorrent-Clients Popcorn Time, holte Updates über unverschlüsseltes HTTP von einer verlassenen Domain. Laut BleepingComputer „accepted executables without verifying digital signatures“. Wer die Domain besaß, konnte Code mit SYSTEM-Rechten unter Windows und root unter macOS ausführen (CVE-2026-30612).[1]

Eye Security hat die Domain registriert und sah „up to 3 million Windows and 350,000 macOS client connections“. Zwischen November 2025 und März 2026 schob das Team über den Updater Code, der den Updater stoppt und abschaltet. Die Domain liegt jetzt bei der Shadowserver Foundation. Android-Nutzer bleiben laut Artikel exponiert.[1]

Verwaiste Domain: Eine Web-Adresse, die der frühere Besitzer nicht verlängert hat. Jeder kann sie neu kaufen. Fragt eine alte Software dort noch nach Updates, ist das wie ein Briefkasten, den der Nachmieter leert, und die Post sind Programme.
Unsere Sicht Das ist der billigste Lieferketten-Angriff, den es gibt: ein paar Euro für eine Domain. Für eigene Projekte heißt das: Update-Kanäle signieren und Domains nicht auslaufen lassen, auch nicht die vom alten Marketing-Microsite.
[1] bleepingcomputer.com (23.10.)

Lieferkette II: GitHub Package Firewall für npm [1][2]

GitHub hat die Package Firewall als öffentliche Vorschau freigegeben; im Changelog steht der Eintrag am 20.10.[1] Laut iX ist sie für Enterprise-Cloud-Kunden gedacht und prüft Paket-Abfragen und Downloads, um schädliche npm-Pakete zu blockieren.[2] Wie genau sie entscheidet, was schädlich ist, haben wir nicht nachgelesen.

Das passt zu Cargos neuer Option, zu frische Pakete abzulehnen (gestern hier). Der Trend ist klar: Registries und Plattformen bauen Schranken vor npm install, weil Lockfiles allein nicht reichen.

Lieferkette III: LiteLLM und die Lehre mit den Tokens [1][2]

Kurz zum Stand: Die vergiftete Version LiteLLM 1.107.0 lag am 21.10. laut Datadog etwa zwei Stunden auf PyPI und in den offiziellen Docker-Images. Der Credential-Stealer startete über einen .pth-Hook. Es ist der zweite LiteLLM-Vorfall 2026.[1] Wie die Angreifer reinkamen, ist umstritten: gestohlene OAuth-Tokens der GitHub CLI oder Trivy in der CI.[1] Details zur KI-Seite im ai-dev-Brief.

Passend dazu kann die GitHub CLI seit 21.10. auf Wunsch ablaufende, sich selbst erneuernde OAuth-Tokens nutzen.[2] Ein Token, das nach Stunden verfällt, ist für einen Dieb viel weniger wert als eines, das jahrelang gilt. Das ist eine Einstellung, die man diese Woche aktiviert.

.pth-Hook: Python liest beim Start jede .pth-Datei im Paket-Ordner und führt Zeilen darin aus. Ein Paket kann so Code starten, ohne dass ihn je jemand importiert. Wie ein Zettel im Briefkasten, den der Hausmeister jeden Morgen automatisch vorliest.
[1] socket.dev / securitylabs.datadoghq.com (21./22.10.) · [2] github.blog/changelog (21.10.)

Oracle-CPU: viele Patches, wackelige Java-Details [1][2]

Oracle hat am 20.10. das Critical Patch Update für Oktober veröffentlicht: laut endoflife.ai 1295 neue Patches, davon 55 für Java SE.[1] Die Oracle-Seite selbst lieferte uns einen 403, die Zahlen stammen deshalb aus zweiter Hand.

Die japanische IPA führt 8u503, 11.0.32.1, 17.0.20.1, 21.0.12.1, 25.0.4.1 und auch 26.0.2 als betroffene Versionen auf, nicht als gefixte.[2] Das passt zu endoflife.ai: „JDK 26 got no fix.“[1] Oracles Vorab-Hinweis nannte 1.283 Patches; die 1.295 stammen von endoflife.ai. JDK 17 ist laut endoflife.ai seit September in Oracles Extended Support; das nächste CPU kommt am 19.01.2027.[1]

Achtung Wer Temurin, Corretto oder ein anderes OpenJDK-Build nutzt, wartet auf die Builds seines Anbieters. Die Oracle-Nummern gelten nur für Oracle-JDK. Für Spring-Projekte ist der Weg einfach: Basis-Image heben, sobald es da ist.

Quad9 verlässt Frankreich [1]

Der DNS-Dienst Quad9 zieht sich laut heise aus Frankreich zurück. Grund ist ein Sperr-Urteil, das der katarische Sender beIN erstritten hat.[1]

Unsere Sicht Sport-Rechteinhaber zwingen die Infrastruktur-Schicht zum Sperren, und der Resolver geht lieber, als zum Zensor zu werden. Für Europa ist das ein schlechtes Signal. Wer Quad9 in Router oder Pi-hole eingetragen hat, sollte in Frankreich auf Ausweich-Resolver achten.
[1] heise.de (22.10.)

CRA: die erste echte Melde-Woche [1]

Seit 11.09.2026 gilt die Meldepflicht des Cyber Resilience Act: Hersteller melden aktiv ausgenutzte Lücken über die Plattform der ENISA, mit Frühwarnung binnen 24 Stunden und Meldung binnen 72 Stunden. Der Rest des CRA gilt ab 11.12.2027.[1]

Diese Woche war voll mit ausgenutzten Lücken: PHP, Plex, Arista, Collabora. Jeder Hersteller, der so ein Produkt in der EU verkauft, musste die Uhr laufen lassen.

Unsere Sicht Die Pflicht trifft Hersteller, nicht ehrenamtliche OSS-Projekte wie PHP selbst. Aber jeder, der PHP in ein kommerzielles Produkt packt, ist jetzt Hersteller mit Meldepflicht. Spannend wird, ob ENISA nach dieser Woche Zahlen veröffentlicht.
[1] crowell.com (11.09.)

Der Rest kann bis Montag warten.

Es ist Samstag, der vierundzwanzigste Oktober. Nach der PHP2Shell-Woche kommt kein ruhiges Wochenende. PHP hat eine weitere Lücke gemeldet, HPE schließt zweiundsiebzig Lücken in ArubaOS, und am Montag laufen zwei Fristen der US-Behörde CISA ab.

Zuerst PHP. Die neue Lücke hat noch keinen Patch. Sie trifft aber nur Anwendungen, die den Session-Serializer zur Laufzeit umschalten. Die Abhilfe ist bekannt: den Upload-Fortschritt für Sessions abschalten. Für die großen PHP2Shell-Lücken gilt weiter: Nur das Update auf die Versionen vom einundzwanzigsten Oktober hilft wirklich.

CISA hat Collabora Online und den Arista VeloCloud Orchestrator in den Katalog der aktiv ausgenutzten Lücken aufgenommen. Die Frist ist schon Montag. Wer Collabora selbst betreibt, etwa mit Nextcloud, sollte vorher nach einem Update sehen.

Bei HPE sind acht der zweiundsiebzig ArubaOS-Lücken in der höchsten Stufe. Angriffe sind noch nicht bekannt. Bis zum Update sollen die Verwaltungs-Oberflächen in ein eigenes Netz.

Das Thema der Woche bleibt die Lieferkette. Eine alte Popcorn-Time-Variante holte Updates von einer verlassenen Domain, ohne Signatur. Forscher haben sie gekauft und den Updater auf Millionen Rechnern abgeschaltet. GitHub testet eine Firewall gegen schädliche npm-Pakete. Und die GitHub CLI kann jetzt Tokens, die von selbst ablaufen. Nach dem LiteLLM-Vorfall ist das eine gute Idee.

Oracle hat sein Quartals-Update mit eintausendzweihundertfünfundneunzig Patches veröffentlicht. Welche Java-Versionen genau gefixt sind, ist noch nicht sauber geklärt.

Außerdem: GoDaddy widerruft rund vierhunderttausend Zertifikate wegen Formfehlern, Chrome warnt jetzt standardmäßig vor unverschlüsselten Seiten, und der DNS-Dienst Quad9 verlässt Frankreich nach einem Sperr-Urteil.

Schönes Wochenende. Am Montag schauen wir, ob die KEV-Fristen halten und ob PHP einen Termin für den nächsten Patch nennt.
