DIGIT: eine Lücke, zehn Länder

DIGIT ist laut The Register „a modular suite that offers common services", etwa Anmeldung und Zahlungseingang für Behörden.[1] Betreut wird die Plattform von eGov India. Neun Länder setzen sie in Teilen ein, mit Indien sind es zehn; dort nutzen sie über 20.000 lokale Verwaltungen.[1] Der Register-Satz dazu: „DIGIT is therefore used by governments that serve over two billion people."[1]

Die Lücke heißt CVE-2026-136706, eine „9.3-rated SQL injection flaw" in den Komponenten „User and Access Control Service".[1] Das indische CERT-In warnt in CIVN-2026-0570: „An unauthenticated remote attacker could exploit this vulnerability by sending specially crafted input through the affected API endpoint."[1] eGov India hat den Fix als Quellcode veröffentlicht, im Release v2.9.3.[1][2] CERT-In stuft die Lücke am 25.11. als „HIGH" ein; betroffen ist laut Advisory „DIGIT Core - version v2.9", die Lösung ist das Upgrade auf v2.9.3.[3] Ob schon jemand angreift, sagen weder der Bericht noch CERT-In.[1][3]

SQL-Injection: Das Programm baut eine Datenbank-Abfrage aus Text zusammen, den ein Nutzer schickt. Schickt der Angreifer statt eines Namens selbst ein Stück SQL, führt die Datenbank es aus. Wie ein Bestellzettel, auf den jemand unten „und gib mir den Kassenschlüssel" schreibt, und der Kellner liest einfach alles vor.
Unsere Sicht Zwei Dinge sind hier peinlich. Erstens: SQL-Injection ist seit zwei Jahrzehnten gelöst, mit parametrisierten Abfragen; dass sie 2026 im Anmelde-Dienst steckt, ist ein Review-Versagen. Zweitens: Eine gemeinsame Plattform für viele Staaten spart Geld, aber jeder Fehler trifft alle gleichzeitig. Wer DIGIT betreibt, braucht v2.9.3. Wer selbst einen Baukasten für viele Kunden baut, sollte den Auth-Pfad zuerst prüfen.

PAN-OS: die Kernel-Fixes sind da

Update seit Do heise beschreibt am 26.11. die Kette, die wir gestern erklärt haben: „Derzeit kombinieren Angreifer zwei Sicherheitslücken, um Firewalls von Palo Alto zu attackieren."[1] Erst PHP2Shell (CVE-2026-109618, „kritisch") über ein Management-Interface, das aus dem Internet erreichbar ist. Dann Fragnesia (CVE-2026-46300, „hoch").[1] Palo Alto selbst bewertet CVE-2026-109618 mit CVSS 4.0 9,2 (kritisch); Fragnesia führt der Hersteller im Bulletin PAN-SA-2026-0015 als „Informational", ohne CVSS-Wert.[2][3] Wichtig zur Einordnung: Fragnesia ist keine PAN-OS-eigene Lücke, sondern ein Fehler im Linux-Kernel, auf dem PAN-OS läuft. Allein lässt er sich nicht aus der Ferne ausnutzen, er hebt nur die Rechte eines Angreifers, der schon drin ist.[1]

Laut heise hatten Forscher von Dream im Oktober 25 übernommene Firewalls gemeldet, mutmaßlich durch chinesische Angreifer. CISA nahm CVE-2026-46300 am 28.10. in den KEV-Katalog auf.[1] Neu ist die Liste der Builds mit Kernel-Fix: heise nennt 20 Stände über alle Linien, von 10.2.7-h41 bis 12.2.4-h3.[1] Wer den PHP2Shell-Patch schon hat, ist gegen diesen Angriffsweg geschützt. Den Kernel-Fix empfiehlt heise trotzdem.[1]

Achtung Auch Dataplane-Interfaces mit Management-Profil zählen als offenes Management. heise rät: öffentlichen Zugang abschalten; wenn es nicht anders geht, nur HTTPS und SSH und nur von vertrauenswürdigen internen IPs.[1]

Rackspace Spot: der Weg hinein war die Überwachung

Update seit Do The Register nennt neue Details zum Einbruch bei Rackspaces Kubernetes-Dienst Spot. Der Angreifer hatte am 17.11. fast 22 Stunden lang Zugriff, über gestohlene Zugangsdaten.[1] Er „could have read any Secret in an affected user's clusters, and any Spot API token or refresh token that user held".[1] Die Ursache laut einem Mitgründer von Platform9: „An observability system was breached using a compromised credential."[1] Wie viele Kunden betroffen sind, sagt Rackspace nicht. Spot endet am 08.12. um 17:00 Uhr Central Time, also 20:00 Uhr Brasília.[1]

Observability-System: Die Software, die Logs, Metriken und Traces aus allen Clustern einsammelt, damit das Betriebsteam sieht, was läuft. Damit sie alles sehen kann, bekommt sie weite Leserechte. Wie der Hausmeister mit dem Generalschlüssel: Er muss überall rein, und wer seinen Schlüssel klaut, auch.
Unsere Sicht Zweiter Fall in zwei Tagen nach 1Password, bei dem nicht das Produkt, sondern das Werkzeug drumherum der Eingang war. Monitoring-Agenten brauchen Metriken, keine Secrets. Wer Prometheus, Grafana Agent oder Datadog im Cluster hat: Prüfen Sie, ob deren ServiceAccount secrets lesen darf. Für Metriken braucht er das selten.

Windows Server 2025: Hotpatch für den Hotpatch

Microsoft hat am 25.11. außer der Reihe KB5138318 veröffentlicht.[1] Es repariert einen Fehler aus dem November-Hotpatch KB5131077 (OS Build 26100.33730) vom 10.11.[1][2] Server mit aktivierten Router Advertisements, die zeitlich begrenzte IPv6-Routen bekommen, stürzen ab, sobald der Timer einer Route abläuft. Der Stop-Code: „0x139 (KERNEL_SECURITY_CHECK_FAILURE)".[1] Der Fix „takes effect without requiring a restart".[1] Den eigentlichen Programmierfehler erklärt Microsoft nicht.[1]

Hotpatch: Ein Update, das den laufenden Code im Speicher austauscht, ohne Neustart. Wie ein Reifenwechsel während der Fahrt: praktisch, solange der neue Reifen passt. Hier passte er nicht, und der Server blieb stehen, sobald eine IPv6-Route auslief.
Unsere Sicht Hotpatching spart Wartungsfenster, aber nicht das Testen. Ein Fehler, der erst beim Ablauf eines Routen-Timers auftritt, zeigt sich nicht im Smoke-Test direkt nach dem Update. Für IPv6-Netze mit RA heißt das: erst einen Canary-Server einen Tag laufen lassen.

Zstandard 1.6.0: Speicherreste im Output

Das Zstandard-Team hat Version 1.6.0 vorgezogen, um CVE-2026-124851 zu schließen.[1] Betroffen sind die Versionen 1.5.1 bis 1.5.7: „Beim Entpacken manipulierter Daten können betroffene Versionen Speicherinhalte preisgeben."[1] Beim Streaming-Entpacken kann der Inhalt eines internen Puffers (standardmäßig 64 KiB) in die Ausgabe gelangen, auch Reste einer früheren Entpackung im selben Kontext. Der Angreifer muss komprimierte Daten liefern und die Ausgabe sehen können.[1] Einen CVSS-Wert nennt heise nicht.[1]

Dazu bringt 1.6.0 schnelleres Entpacken auf AArch64 und RVV-Unterstützung auf RISC-V. Achtung beim Upgrade: Ein Standard-Build liest keine Dateien mehr, die mit Zstd vor 0.8.0 komprimiert wurden; ZSTD_LEGACY_SUPPORT holt das zurück.[1]

Unsere Sicht Relevant ist das für Dienste, die fremde komprimierte Daten entpacken und das Ergebnis zurückgeben, etwa Upload-Vorschau oder Proxy. Zstd steckt meist als Systembibliothek oder in Language-Bindings; der Fix kommt also über die Distribution, nicht über Ihr package.json.

Es ist Freitag, der siebenundzwanzigste November, der Tag nach Thanksgiving. Die Nachrichtenlage ist ruhig, aber eine Geschichte sticht heraus. Sie kommt aus Indien.

DIGIT ist ein Baukasten für digitale Verwaltung, mit Diensten wie Anmeldung und Zahlungen. Laut The Register nutzen ihn zehn Länder, deren Regierungen zusammen über zwei Milliarden Menschen bedienen. In den Diensten für Nutzer und Zugriffskontrolle steckt eine SQL-Injection mit neun Komma drei von zehn Punkten. Ein Angreifer braucht keine Anmeldung, nur eine präparierte Anfrage an die Schnittstelle. Der Fix steckt in Version zwei Punkt neun Punkt drei. Ob schon jemand angreift, ist nicht bekannt.

Heute endet die Frist der US-Behörde CISA für die Drupal-Lücke. Die Fixes sind Drupal elf Punkt vier Punkt dreizehn, elf Punkt drei Punkt zweiundzwanzig und zehn Punkt sechs Punkt zweiundzwanzig. Angriffe laufen seit dem neunzehnten November. Morgen enden weitere Fristen, unter anderem für Mitel MiCollab, Danfoss, Xen Orchestra und Juniper. Neue Einträge gab es seit Mittwoch nicht.

Zu den Palo-Alto-Firewalls nennt heise jetzt die Versionen mit dem Kernel-Fix gegen Fragnesia. Fragnesia ist eine Lücke im Linux-Kernel, auf dem PAN-OS läuft. Zusammen mit PHP2Shell gibt sie Angreifern die volle Kontrolle, aber nur, wenn die Verwaltung aus dem Internet erreichbar ist.

Rackspace nennt die Ursache des Einbruchs bei Spot. Der Angreifer kam über ein Überwachungssystem mit einem gestohlenen Zugang und war fast zweiundzwanzig Stunden drin. Er konnte alle Secrets der betroffenen Cluster lesen. Spot wird am achten Dezember abgeschaltet.

Microsoft repariert einen Hotpatch mit einem Hotpatch. Der November-Patch für Windows Server zweitausendfünfundzwanzig ließ Server abstürzen, sobald eine zeitlich begrenzte IPv6-Route auslief. Der Fix braucht keinen Neustart. Außerdem schließt Zstandard in Version eins Punkt sechs eine Lücke, durch die beim Entpacken Speicherreste in die Ausgabe gelangen.

In Deutschland meldet Deichmann einen Zugriff auf Kundendaten aus dem Online-Shop, mit Namen, Adressen und Rechnungen, aber ohne Passwörter und Kartendaten. Auch die FIFA bestätigt einen Angriff. Und der Browser Ladybird läuft jetzt auf Rust, gibt aber ausdrücklich keine Sicherheits-Garantie.

Zum Schluss eine Erinnerung: PostgreSQL vierzehn bekommt keine Updates mehr. Das nächste Sicherheits-Update im Februar kommt ohne diese Version. Morgen schauen wir, ob es zu DIGIT erste Angriffe gibt und ob CISA nach dem Feiertag neue Einträge nachliefert.
