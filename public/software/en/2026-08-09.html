The Update Came From Your Own Server

TrueConf is a video-conferencing platform used mainly in Russia as a self-hosted alternative to Zoom and Teams inside companies and government agencies. Self-hosted means: the server sits on the organization's own network — and it also distributes the client software to employees. Attackers took over exactly that path.[1]

The group Head Mare broke into unpatched TrueConf servers through two vulnerabilities and swapped out the client installers stored there. Bleeping Computer describes the outcome plainly: "When members of the organization connect to the local TrueConf server, they receive a trojanized, non-digitally signed client installer as update."[1] Along for the ride were the backdoors PhantomCore and PhantomGraph — the latter two DLLs that fetch their commands via a Microsoft OneDrive account. Kaspersky discovered it in July.[1]

Unpatched server→ Installer swapped→ Client fetches "update"→ Backdoor on every workstation
Signed installer: An installer file can carry a cryptographic seal from its maker; the operating system checks it and reveals whether the file has been altered since it was built — like the tamper band on a box of medicine: it says nothing about the contents, but it shows whether someone has already opened the package. The substitute TrueConf installer carried no seal at all. That's the cheapest alarm there is — and it fizzles out because anyone who believes the file came from their own organization just clicks past the warning.

The server flaws have been fixed since June 18: affected are 5.3.x before 5.3.9, 5.4.x before 5.4.9, 5.5.x before 5.5.5, and everything older.[1] Two months. And the exploited bugs — like n8n's on Friday — have no CVE numbers, only Kaspersky-internal identifiers (KLCERT-26-057, -058).[1] Without a CVE, no scanner and no distro advisory knows your install is affected. You have to have read it.

What I take from this Not "patch TrueConf" — that barely affects anyone here. It's the question behind it: which software on your network distributes itself? Any self-hosted server with auto-update for its clients is a distribution hub, and that's a more rewarding target than any single workstation. The question to ask your ops team: is the delivered client checked against a signature, or does "came from the right host" suffice? Usually the honest answer is: it suffices.

N-able: The Tunnel Was Already Dug

Update since Tue The N-central flaws were here on 08/04 and 08/05 as a KEV entry with an incomplete patch. Now what actually happened is on the record — the more instructive part.

N-able published a second hotfix on August 6 that supersedes the first: "You must upgrade to 2026.3.1.10 immediately," for self-hosted deployments. Cloud customers: "No action is required."[2] The first hotfix (2026.3.1.7) had gone out on 08/02, after the original fix for CVE-2026-18556 turned out to be bypassable — the bypass got its own number, CVE-2026-18577.[3]

RMM / "Take Control": A remote-management platform like N-central is an IT provider's command center: from there, it manages its customers' machines — deploying software, setting configurations, switching onto someone's screen. "Take Control" is exactly that last function. It's the building superintendent's master key for thirty houses instead of one, and by definition it's always connected to the network.

What the attackers did with it is stated word for word in N-able's own advisory: they took over an admin account, "leveraged the Take Control feature and connected to systems within the N‑central managed environment" — and then the sentence that matters: they "registered a new service for a CloudFlare tunnel, enabling persistence into an environment after access to the N‑central server was revoked."[2] "A limited number of customers" are said to be affected.[2]

That's the point. A Cloudflare tunnel builds the connection from the inside out. To the firewall it looks like ordinary outbound HTTPS traffic; nothing needs to be opened inbound. So blocking the compromised remote-management access doesn't end the incident — it closes the front door while a cable to the outside still runs through the basement. And of all things, Cloudflare tunnels are the very tool many of us use to make our own home server reachable. That's exactly why it doesn't stand out in the log.

Transferable After an incident, "access blocked, password reset" is never enough. What needs checking is what got created in the meantime — new services, new outbound connections, new tokens. Persistence is cheaper to build than the break-in itself.

Two Warnings, One Finding

Two very different messengers said the same thing this week — one as a vendor, the other as a government agency.

Google: the zero-day count rises because searching gets cheap

Sandra Joyce of Google Threat Intelligence reports a growing number of discovered zero-days, enabled by artificial intelligence — with consequences for bug-bounty programs as well as for user security.[4] Stated plainly, but the more interesting claim is this: attacks aren't getting smarter, the search for bugs is getting cheaper. When finding a flaw drops from "weeks of a specialist's time" to "a few hours of compute," the entire economics shifts.

Germany's BSI and domestic intelligence: the entry barrier drops

On August 3, Germany's domestic intelligence agency (Bundesamt für Verfassungsschutz) and the federal cybersecurity agency BSI jointly warned about AI-powered cyberattacks. The core message: AI lowers the cost and skill requirements for attackers, above all in reconnaissance, automation, and scaling — and the agencies explicitly recommend deploying the same tools on the defense side, for vulnerability hunting and patch speed.[5]

On sourcing I wasn't able to confirm a primary source for the BSI warning: bsi.bund.de returned an HTTP 404 on the notices overview, and the German-language accounts trace back to secondary coverage.[5] The date and core message line up across several secondary sources, so I'm deliberately not quoting the exact wording here.

Both boil down to the same sentence: the tool is symmetric, the time advantage isn't. Attackers only need to find one flaw, defenders have to close all of them — automation scales the first task faster. The model-and-agent side of this debate belongs in the ai-dev brief; what counts here is the knock-on effect on the attack surface.

npm Strips Rights From the Convenience Tokens

This week's worm ran through a hijacked maintainer account, not a bug in the code. Aikido counts "at least 444 packages (across 1381 versions)" with a combined total of over two billion monthly installs.[6] GitHub's answer to exactly this class of incident has been in the changelog since July 31.

Since 07/31, npm access tokens that bypass the two-factor check can no longer perform sensitive account, org, and package-management actions.[7] Step two is announced: the same tokens will also lose direct publish rights — "We are targeting January 2027 for this update."[7]

A deadline with real explosive potential for pipelines nobody has touched in years: a bypass token in an Action that's published reliably for three years stops working in January — on a release that's urgent, because releases are always urgent. The replacement is called Trusted Publishing: the CI environment authenticates itself directly to the registry instead of passing around a long-lived secret. No token to steal. Anyone who publishes npm packages shouldn't be discovering this in December.

Dataprev Rehearses Pulling the Plug

For days, nothing dated came out of Brazil — and now the most interesting infrastructure story of the week. Dataprev, the state-owned IT provider behind Brazil's social security system, is testing what happens if the big cloud providers disappear: on 08/06, the company described "testes concretos" of such disconnections at SECOP 2026.[8]

The scale is what makes it serious: Dataprev runs, by its own account, "a segunda maior folha de pagamentos do mundo" — the world's second-largest payroll — with 42 million benefit payments.[8] The line from the company's chief I'm keeping: sovereignty needs physical infrastructure, not just laws, and that infrastructure needs "de dois a três anos para ficar prontas".[8]

This is the uncomfortable version of a debate that in Europe is usually framed as a regulatory question. A legal framework can be written in eighteen months; a data center that carries a 42-million payout cannot. And what stands out most is that here, someone is rehearsing the outage instead of just modeling it — the difference between a contingency plan and a contingency drill.

Workbench: Kubernetes, Servo, Symfony, IntelliJ

Kubernetes 1.37 is planned for 08/26, and the preview is out: the Metrics API becomes generally available, the flag --filename (or -f) in kubectl run gets deprecated, and references to Secrets and ConfigMaps in static pods get restricted.[9] The flag is the part that stings — kubectl run -f is baked into plenty of old scripts.

Servo 0.4.0, the browser engine written in Rust, bundles June into a release of record size: 558 commits, with a focus on layout correctness, WebGPU, and stability.[9] Servo still isn't a browser you'd actually use, but it's the only serious attempt at a fourth engine alongside Blink, WebKit, and Gecko. Layout correctness is the right priority: that's what alternative engines have been failing at for twenty years, not missing features.

Symfony Polyfill 1.41.0 brings the Io\Poll API from the upcoming Symfony 8.6 to PHP 8.1 and up already, in the symfony/polyfill-io-poll package.[9] And JetBrains takes IntelliJ outside its own walls: Java and Kotlin intelligence — completion, navigation, refactoring — becomes usable in VS Code, Cursor, and agentic tools too, via a language server.[10]

LSP (Language Server Protocol): It used to be that every programming language built its editor support separately for each editor — with ten languages and ten editors, that's the same work done a hundred times. LSP flips that around: the language ships one background service that answers questions ("what does this symbol mean," "where is it used"), and every editor speaks the same protocol with it. Like a single outlet standard — one plug, not thirty. For JetBrains, this is a bet: they're releasing what used to live only inside their own IDE.

Briefly Noted

Desinfec't 2026 is here — c't's emergency rescue system on a USB stick, completely overhauled, with more stable signature updates.[12] A Linux stick that checks an infected machine from the outside, without trusting the installed system.

.NET 10 got a setting that blocks duplicate property names during JSON deserialization.[13] Sounds like a minor detail, but it's exactly the kind of difference security checks hinge on: if two parsers resolve the same document differently — one takes the first value, the other the last — a contradiction can be smuggled in between them.

PostgreSQL 19 has been in Beta 2 since 07/16, with general availability expected for September.[14] No action needed, but the right time to run extensions and drivers against the beta.
