JDK 27 Is Here — and Quietly Changes Your Container JVMs

After a week where every day started with a new edge device landing in the KEV catalog, today finally brings a story that doesn't break anything: JDK 27 has shipped on schedule as the final release. At first glance the release looks boring — no major language feature, lots of "preview," lots of "incubator." The interesting part sits in two changes nobody actively switches on, yet they affect every JVM in every container: G1 becomes the default collector everywhere, and object headers go compact by default. Alongside that, two fresh security stories that hadn't come up yet this week: a Cisco switch that hands out root without a login, and an attack path through the EDR agent that's supposed to protect you.

JDK 27: The Release You Don't Notice — Until the Container Runs Differently

The date had been set for months, and it held: the official OpenJDK schedule lists 2026-09-15 as General Availability for JDK 27 — that's today. Anyone who just skims the headlines of the shipped JEPs sees a thin release — Lazy Constants third preview, Primitive Types in Patterns fifth preview, Structured Concurrency seventh preview, the Vector API's twelfth incubator round. There's a lot of "not done yet" in there.

But that's the wrong angle. The two changes that actually do something sit unassumingly in between, because they aren't language features — they're defaults. And you don't hit a default by reading about it; you hit it when you deploy.

JEP 523: G1 Becomes the Default Everywhere

Until now, the JVM picked its garbage collector based on the environment: G1 on beefy machines, falling back to the Serial collector in small, CPU- and memory-constrained environments. That's exactly where most Spring Boot containers live, though. JEP 523 makes G1 the default in every environment. For a small service, that means different pause behavior, a different memory footprint, different GC logs — without anyone changing a single line.

Garbage Collector: The JVM's cleanup program. It finds objects nobody's using anymore and reclaims their memory. Think of a waiter clearing empty plates: the Serial collector is a waiter who briefly stops the whole restaurant to do it; G1 is several waiters clearing tables section by section while everyone keeps eating. More overhead, but much shorter pauses.

My take: this is the right call, ten years late. The Serial default was a heuristic from a time when "low CPU" meant a weak machine, not a deliberately tight cgroup limit sitting next to 40 siblings. Even so, anyone running a tight per-container memory limit should watch the first JDK 27 build under real traffic rather than pushing it straight to production.

JEP 534: Compact Object Headers by Default

Every Java object carries an administrative header around with it — a type pointer, lock state, hash. Compact Object Headers shrink that header, for every object at once. For object-heavy applications, that's the rare case of "less heap with no code change." In JDK 27 the feature is no longer opt-in; it's the default. Combined with JEP 523, that means your services' memory curve looks different after the upgrade. Not worse — just different, and your alert thresholds don't know that yet.

JEP 527: Post-Quantum in the TLS Handshake

The hybrid key exchange for TLS 1.3 has shipped as finished, not a preview. That lets a JVM negotiate a TLS handshake that still holds up even once someone, eventually, has a large enough quantum computer.

Post-Quantum Hybrid Key Exchange: Two locks on the same door instead of one. One is the classic, well-tested lock; the other is designed to defeat even a quantum computer. To get in, you'd have to break both. If the new lock later turns out to be weak, the old one still protects you — hence "hybrid."

The practical reason this matters now, not only once quantum computers exist: "harvest now, decrypt later." Encrypted traffic someone captures and stores today gets opened with tomorrow's key. Anything that needs to stay secret for a long time is affected as of today.

The rest of the stack: JFR gets in-process data redaction (JEP 536) — interesting for anyone who has to hand out Flight Recorder dumps from production without shipping personal data along with them. PEM encoding of cryptographic objects is in its third preview (JEP 538). And the Vector API enters its twelfth incubator round, which you can read as a running joke or as a memorial.

Cisco Nexus 9000: Root Without a Login, on Ten Switch Models

CVE-2026-20212, CVSS 9.8. Ten Nexus 9000 models based on Cisco's Silicon One chips are affected. They run a service reachable over two ports; anyone who can reach the switch's address connects straight to it. Crafted input sent to that service gets executed with root privileges — with no login required beforehand. Cisco tracks this as CWE-1327 (a service bound to an insecure default address) in advisory cisco-sa-n9k-s1-rce-EH8dEtr, published on 2026-09-02.

Exploitation in the wild hasn't been observed so far, so the bug isn't in the KEV catalog either. That's the difference from MikroTik and Cisco FMC this week — there's still time here. What still makes it nasty: a data-center switch isn't a device you just casually reboot, and by definition it sits where all the east-west traffic passes through. Whoever has root on the switch no longer needs a single vulnerability in any application.

For Daniel's setup this isn't a call to action — there's no Nexus 9000 sitting in a solo operator's basement. But it's the third time in two weeks that the most severe flaw isn't in software someone wrote, but in the box that carries it.

CrowdStrike Falcon: The Guard Dog as a Ladder Upward

On 2026-09-03, a researcher going by "Nightmare Eclipse" published a proof-of-concept that turns a normal user account into a command line with SYSTEM privileges — via the CrowdStrike Falcon sensor itself. The path runs through the function Falcon uses to clean up malicious Office macros: that function runs with full privileges, and it can be made to load a planted DLL. The researcher states this works on a fully updated Windows 11 25H2 and Windows Server 2025. CrowdStrike says it's investigating the claims; as of this writing there's no CVE number and no patch.

EDR Agent: A protection program that runs on every company machine and reports when something behaves suspiciously. So it can see everything and, if needed, clean up everything, it runs with the system's highest privileges — like a janitor with a master key. That master key is exactly the problem here.

This is "only" a local privilege escalation, not remote access — someone already has to be on the machine. But after a successful phishing attempt, that's exactly the missing step, and here it's trivial. The structural point is more uncomfortable: EDR agents are the most widely deployed software running everywhere with maximum privileges. Any vulnerability in that layer is automatically a vulnerability across the entire fleet, and the defense mechanism against "unknown binary gets SYSTEM" is, of all things, the very product being exploited here.

Until there's a patch, only monitoring helps: if the Falcon sensor spawns a command line, that's an event that belongs in an alert — even when it comes from the "good" process.

MikroTik: 122,500 Open SSH Ports Are Not 100,000 Hijacked Routers

The MikroTik story has been running here since Thursday, but one number has gone unnoticed so far — and it's the only solid one in this whole topic. The ShadowServer Foundation counted 122,500 MikroTik devices with an SSH interface reachable from the internet on 2026-09-05. The same report explicitly states that the exact number of devices actually vulnerable was not determined.

That matters because German-language coverage since 2026-09-08 has been running the headline "over 100,000 routers are under active attack." The number is roughly right — but it measures something different from what the headline claims. Reachable SSH is exposure, not compromise, and not even necessarily vulnerability: anyone who patched on 2026-09-03 is still in this count. Stated cleanly, the picture is: over a hundred thousand devices are in the line of fire, active exploitation has been confirmed by CERT Polska since 2026-09-02, and the overlap between the two is unknown.

Heads up The primary source for the numbering that's been circulating since last week is now available. The CVE entry for CVE-2026-67276 (CVSS 9.2) describes it like this: when matching an SSH login attempt against a stored user key, RouterOS doesn't compare the full RSA key, only the type and modulus — the exponent is left out. That's the auth bypass, and thus the first link in the "MikroTrick" chain, together with CVE-2026-86060 (privilege escalation via crafted usernames). CVE-2026-67277 (CVSS 8.8), by contrast, is a separate bug in the bandwidth test: a "related" connection is accepted before the main session is authenticated. CISA added -67277 and -86060 to the catalog on 2026-09-10; the attack chain in press coverage is -67276 plus -86060. Both readings are supportable; for operations it doesn't matter, because the same patched versions cover all three: 7.25beta3, 7.24.2, 7.23.4, and 6.49.21, released on 2026-09-03.

Firefox: A 9.8 Nobody's Talking About

CVE-2026-84134 carries a CVSS of 9.8 and was published on 2026-09-01. It affects Firefox's profile backup component; it's fixed in Firefox 155, Firefox ESR 153.2, and Thunderbird 155 and 153.2. The flaw is not in the KEV catalog, and its EPSS score — the estimate of how likely exploitation is in the next 30 days — sits under one percent.

That's why it's here: as a counterexample. A 9.8 is a statement about the damage in a successful exploit, not about the likelihood. This week saw several flaws with lower scores that were actively exploited, and this one, near the top of the scale, that nobody's touching. Anyone who sorts their patch order by CVSS alone is working through the wrong list — the question "is it in the KEV catalog?" is a much better first filter. Firefox updates itself anyway; restarting the browser is enough.

Tailscale Operator 1.102, and a Separate Client Security Fix

The Tailscale Kubernetes operator has shipped as version 1.102. Three things are in it: peer relays that run inside the cluster, IPv6 support, and an easing of Let's Encrypt rate limits. The first point is the interesting one — until now, traffic that two nodes couldn't negotiate directly had to go through an external relay. With the relay running inside the cluster, the detour stays within your own network.

Separately — and unrelated to the operator release — Tailscale's regular client fixed TS-2026-011 in version 1.102.3: the client now rejects host-scoped IPv4 destinations (loopback, link-local, multicast, broadcast) at every point that resolves to an unmapped 4via6 address. Anyone running 4via6 subnet routers should update those routers to 1.102.3 or later; the operator announcement doesn't say whether its image bundles a client at that version, so check your own image's Tailscale version rather than assume the operator update covers it.

What's Worth Twenty Minutes Today

The week was loud, but for a small, self-operated setup it distills down to four moves:

JDK 27 into CI → Watch the GC curve → Adjust alert thresholds

One: put JDK 27 into a test build today, not production. The two default changes are exactly the kind that stay invisible in CI and show up under real load. Two: if a self-hosted GitLab instance is still running anywhere — check the patch level, then rotate the CI tokens afterward. Three: get MikroTik devices on your own network to 7.24.2 or higher, and honestly answer why SSH needs to be reachable from the internet at all. Four: fully restart your browser — Chrome and Firefox both have pending fixes that only take effect after a restart.

What doesn't belong on the list: Cisco Nexus, Citrix NetScaler, CrowdStrike Falcon. All serious, none of it present in this setup. A patch list that includes things you don't own is the fastest way to get the whole list ignored.
