A security feature locks machines out of their own domain

Microsoft's September rollup already stood out by sheer size: KB5124008 landed on 2026-09-08 as part of a Patch Tuesday closing 966 flaws, including two actively exploited zero-days. Two weeks later, the story isn't the scope — it's a feature bundled into that update: Machine Identity Isolation.

Microsoft's own wording in the Known Issues entry is the key sentence: the update doesn't turn on enforcement itself, it only makes "Windows start honoring settings that were already present or deployed via policy." So wherever a policy was ever set, it now fires retroactively. The result on machines running Credential Guard against domain controllers below the Windows Server 2025 functional level: the machine account loses its secure channel, and interactive login fails despite valid domain credentials, with a message that the trust relationship between the device and the domain has failed.

Machine account & secure channel: In a Windows domain, it's not just every human who has a password — every machine does too, a secret that the PC and the domain regularly swap with each other so both know who they're talking to. Like a house key the building quietly re-cuts by mutual agreement. If that exchange goes wrong, the machine stands at the door and the doorman says he doesn't know it — even though the human in front of it has valid ID.

The good news is in the details: AD replication and services keep running, and offline logon with cached credentials can still work. So operations don't go down, but the user at the machine can't get in — and that's the call that comes in Monday morning.

Status Microsoft has so far named only a workaround: disable Machine Identity Isolation via whatever path enabled it (Intune, Group Policy, or the registry), then repair the channel with Test-ComputerSecureChannel -Repair -Credential (Get-Credential). A real fix is due "in a future Windows update" — no date given.

My take: this isn't a regular regression, it's a delayed detonation. A security update doesn't switch on anything new — it just starts taking old switches seriously. For anyone running configuration as code, that's the most unpleasant kind of trigger, because the cause isn't in this month's changelog but in a policy object from two years ago. Anyone managing a domain should go looking for it before the next update wave, rather than waiting for the fix.

And the same patch cycle hung Remote Desktop

A second regression comes out of the same Patch Tuesday cycle, but from separate Server KBs (KB5122876/82/71): Remote Desktop Services ran normally for hours after the patch, then new connections started failing and sessions couldn't be cleanly logged off. Microsoft already shipped emergency out-of-band fixes on Sep 14 — a week before this brief — (KB5129238 for Server 2019, KB5129237 for Server 2022, KB5129235 for Server 2025); anyone who hasn't installed that week's update should catch up.

Caddy 2.11.4: when a rewrite reads attacker text twice

This one hits Daniel's own stack directly. On 2026-09-17, CVE-2026-77281 was published, CVSS 6.5, affecting all versions up to and including 2.11.3, fixed in 2.11.4. The advisory bundles three things: a double placeholder evaluation in the rewrite module, an unbounded body buffer (memory exhaustion), and a case-sensitivity bug in fileHidden that can still serve up hidden files.

Placeholders in Caddy: A Caddy configuration contains fields like {http.request.uri} that get swapped for real values when processed — like the mail-merge fields in a form letter. The bug here: whatever got inserted was then read as a template again. So anyone who puts curly braces into their own request gets them evaluated as a field — the recipient re-inserts text from the letter back into the letter.

Technically, the advisory spells out the exact path: in modules/caddyhttp/rewrite/rewrite.go, Rewrite.Rewrite() can route attacker-controlled replacement bytes through buildQueryString into a second placeholder expansion when the rewrite URI ends in a literal question mark. So the precondition is a specific rewrite shape — not every Caddy instance is affected.

6.5 looks like "can wait," and score-based prioritization would agree. Except the reverse proxy is the one component every single request passes through before any application ever sees it. The effort is out of proportion to the risk: run caddy version, and in a container setup, bump the tag to 2.11.4. It's the cheapest patch of the week.

Confluence: this time it's Atlassian's own code

Friday's item here noted that Atlassian's bulletin lists 144 high and 17 critical entries, but almost none of them come from Atlassian's own code — they were bundled libraries. Two entries from the 2026-09-15 bulletin are the exception, which is why they're worth flagging again.

CVE-2026-21580 is a stored cross-site scripting flaw in Confluence Data Center and Server, CVSS 8.6, exploitable without authentication, affecting several non-contiguous version lines from 7.19.27 up to 10.2.0 — fixed in 9.2.21 and 10.2.13 and newer. CVE-2026-21586 is a broken authorization check, 7.1, letting a logged-in attacker reach things they shouldn't — fixed separately, in 9.2.24 and 10.2.17 and newer.

Why this is more than an XSS note: a wiki is the opposite of a hardened system. It sits internally, everyone is permanently logged in, and the most-read pages are exactly the ones holding runbooks and access paths. A script planted there once, reachable without login, then runs in every session that comes by afterward — including the admin's.

When the protection layer is the vulnerability

Two items this week belong together, even though they come from different vendors. Both affect products you buy in order to be secure — and both run with the highest privileges on the network.

Check Point: root in the management server, no login required

CVE-2026-91843 sits, per Check Point, in Security Management Servers, Log Servers, and Multi-Domain Servers, affecting R82.20 down to older R8x branches. The vendor rates it itself at 9.8; it's a stack buffer overflow leading to unauthenticated code execution as root. The fix ships as a LivePatch (sk1000155). Active exploitation was not confirmed as of the 2026-09-17 reporting.

The management server isn't the firewall — it's the machine that tells every firewall what to do. Whoever gets root there doesn't need to bypass a single rule anymore. They write them.

Acronis's Backup plugin for hosting panels: local privilege escalation, already in the KEV

On 2026-09-16, CISA added two entries to its catalog of known exploited vulnerabilities: the already-known Cisco ISE flaw and CVE-2026-87886, CVSS 7.8, in Acronis's Backup plugin for cPanel & WHM, Plesk, and DirectAdmin on Linux. The remediation deadline for US federal agencies expired on 2026-09-19.

This isn't a generic agent flaw: it takes an already-authenticated, low-privilege local user on the hosting server, who then escalates to root — relevant mainly to shared-hosting panels, not to every Acronis Backup install.

CrowdSec follow-up: a token that outlived the employee

Friday's item here had heise's numbers: over 300 repositories exfiltrated, roughly 130 of them from the already open-source Security Engine, and — per CrowdSec's own assessment — no user data. The more detailed writeup of the disclosure sharpens that picture, and corrects part of it.

What was copied on 2026-05-22 was around 170 private repositories; combined with the public ones, that matches Friday's number, so the two figures don't actually contradict each other. Inside were the web console's source code, data-science and automation scripts — but also data on 83 CrowdSec users and the names, email addresses, and investment context of 51 prospective investors from 2020. The line "no user data" doesn't fully hold up.

More interesting is how they got in. The key was a former employee's GitHub OAuth token, stolen in the supply-chain attack on the TanStack packages: on 2026-05-11, 84 malicious versions of 42 npm packages appeared, and the token was used eleven days later. The ex-employee's account wasn't removed until 2026-05-25 — three days after the theft.

npm package compromised→ex-employee's token→170 private repos→117 days unnoticed

Two lessons, both uncomfortable. First: deleting an account isn't the same as revoking its tokens — OAuth grants often live on, and the offboarding checkbox gets ticked while access stays open. Second: 117 days passed between theft and discovery, and it wasn't found through monitoring but because the code surfaced on a criminal forum. The exact same detection gap as the Shai-Hulud pattern two weeks ago. CrowdSec says infrastructure and databases weren't touched and no code was altered; credentials were rotated on September 16 and 17.

2025 kernel bug: the deadline ends today

Quick reminder from Sunday's entry: CVE-2025-39682 in the Linux kernel's TLS receive path — a missing check for unusual conditions, CVSS 9.8 — has been in the KEV catalog since 2026-09-18, and the remediation deadline expires today, 2026-09-21. It's binding only for US federal agencies, but it's the date distributions and operators tend to follow anyway. Anyone using kernel TLS — typical for high-throughput offload — should check their kernel version today; everyone else has until the next regular window.

Portainer freezes the Community Edition

heise reported on 2026-09-20: starting with version 3.0, Portainer is pointing itself toward Kubernetes, with Docker relegated to a side role — and the Community Edition stays on the 2.x codebase. No shutdown date, no license change, just the end of the shared development line.

This is a familiar move: a tool gets big because it makes things easy for small setups, then migrates toward where the budgets are. For Daniel's scale — a handful of containers on one host — that doesn't mean "migrate immediately." 2.x keeps running and will presumably still get security fixes. It means: stop expecting new features, and treat the web UI from now on as a convenience, not part of the operational baseline. Anyone who already describes their services in Compose files loses nothing in a switch but a few clicks.
