NetScaler: a number, a patch, a deadline, and the September patch isn't enough

On Saturday, admins reported mass spontaneous reboots of their NetScaler devices, even on fully patched systems. On Sunday at 12:52 p.m., heise updated the article: the flaw now has a name, CVE-2026-88779, with CVSS 4.0: 8.7 ("high").[1] It's a buffer overflow in NetScaler instances configured as a SAML service provider or identity provider. According to heise, updates have been available since early Sunday morning.

CISA added the flaw to its KEV catalog on Oct 4, with a deadline of Wednesday, Oct 7.[2] The KEV entry describes only a denial of service. The researcher reports at heise go further: crashes and, in the worse case, code execution. I'm assuming the worse case until Citrix proves otherwise. The advisory is called CTX697174.

The point that's easy to miss: the fixed versions are 14.1-73.41 and 13.1-64.28 (FIPS: 14.1-73.41; 13.1-FIPS/NDcPP: 13.1-37.282).[1] The patch level from Sep 27 was 14.1-73.37 and 13.1-64.23.[3] So anyone who did everything right last week is still vulnerable. Anyone using SAML on the gateway, and that's many for corporate VPNs, should check the build number, not just the date of the last update.

My take: this was the third NetScaler zero-day in eight days. Citrix delivered fast this time, and that's good. But anyone running NetScaler at the network edge now needs a fixed weekly slot for it, not an emergency reflex.

Buffer overflow: A program reserves a fixed-size box for data. If someone sends more data than fits, it spills into the neighboring memory. In the harmless case, the program crashes. In the bad case, the attacker overwrites exactly the spot that determines which code runs next.
Heads up The version list comes from the heise update. The Citrix page itself wasn't accessible to me (HTTP 403). The CVE number, date, and deadline, however, are confirmed via CISA's KEV catalog.

Deadline corner: Zammad today, FortiMail overdue

Zammad CVE-2026-102489 and -102490

Today marks the end of the KEV deadline for the two Zammad flaws: CVE-2026-102489 is individually rated CVSS 8.7, CVE-2026-102490 at CVSS 8.5 — only chaining both flaws reaches CVSS 9.4.[1] This is the chain an agentic AI tool used on Sep 21 to take over the Dutch DIVD: first session hijacking with code execution as the zammad user, then privilege escalation to root, "in seconds" according to the report.[2] The full story ran here on Saturday. Vulnerable to the first flaw: Zammad 6.3.0 through 6.5.4. The second ranges from 1.5.0 to the pre-release 7.1.0-alpha, so it affects practically every installation.

Zammad is a German product popular with mid-sized businesses. Anyone self-hosting it should check Zammad's release page today and the community thread on active exploitation.

FortiMail CVE-2026-104286

The deadline for FortiMail passed yesterday. The flaw (CVSS 9.8) lets an unauthenticated attacker write arbitrary files to the system via crafted HTTP requests.[1] Affected: FortiMail 8.0.0–8.0.1, 7.6.0–7.6.6, 7.4.0–7.4.8, and 7.2.0–7.2.9 — Fortinet's own advisory says no 7.2.10 fix is planned, so 7.2.x admins must move to 7.4+. The Register reported on Oct 2 that some admins were still waiting for patches.[3] Whether Fortinet has since shipped fixes for all branches, I couldn't verify. Fortinet's advisory is called FG-IR-26-175.

Zimbra: attacks two weeks before the CVE

Microsoft described attacks on a Zimbra flaw that ran before the flaw was public.[1] CVE-2026-73570 is an unauthenticated command injection: a crafted email to a vulnerable server is enough. The fix came with Zimbra 10.1.20 on Jul 20, disclosure only on Aug 13. Microsoft saw scans between Jul 28 and Aug 7, followed by webshells, privilege escalation, and password theft.

The good news: only servers with the optional SNMP monitoring package and active notifications are affected. Still, the lesson is a general one. Attackers read release notes and diffs. A silent fix without an advisory only protects those who update immediately anyway.

Spectre is back, this time in the JIT compiler

Researchers from Vrije Universiteit Amsterdam and Scuola Superiore Sant'Anna in Pisa demonstrate a new Spectre variant: Branch Target Reuse (BTR).[1] When a program rewrites its own code, as every JIT compiler does, the CPU correctly updates the code. But it doesn't forget the old branch predictions. From that, the researchers build a "speculative execute-after-free."

Affected are the Intel cores Raptor Cove and Lion Cove, as well as the JIT engines Linux cBPF, Oracle GraalVM, and Mozilla SpiderMonkey. The leak rate is 5.7 KB/s (Raptor Cove) and 5.4 KB/s (Lion Cove). That's enough for an unprivileged user to read out, for example, password hashes. The CVEs: CVE-2026-64507 and CVE-2026-64508. Linux and Oracle have patched it, Mozilla relies on site isolation. The paper is coming to CCS in November in The Hague.

For Java people, GraalVM is the interesting part. Anyone building Native Images or running Truffle languages on shared hosts should pick up the next GraalVM update. It's no reason to panic though: the attacker already needs to be running code on the same machine.

Speculative execution: The CPU guesses where a jump in the program goes and keeps computing ahead. If it guesses wrong, it throws away the result. But traces remain in the cache, and an attacker can measure those. With BTR, the CPU guesses based on code that technically no longer exists.

Azure: maintenance knocks out gateways, and nobody knows why

On Sep 30 starting at 20:30 UTC (17:30 in Ribeirão Claro), Azure ExpressRoute gateways, VPN gateways, and Azure VMware Service went down. Azure Firewall, Application Gateway, and WAF followed later.[1] 18 regions were affected, including West Europe, North Europe, Germany North, and Switzerland North. Microsoft sees a connection to infrastructure OS updates and has paused that maintenance. According to The Register, Microsoft hasn't named a root cause.

My take: this is the case you plan a second connection into the data center for, and then cut for cost reasons. Anyone running hybrid should know whether the failover path runs over an independent network or through the same gateway layer.

Ubuntu 26.04.1: the upgrade comes knocking

Canonical is now offering Ubuntu 24.04 LTS users the upgrade to 26.04.1 LTS, via Update Manager or do-release-upgrade.[1] The offer came later than usual. Canonical wanted to fix regressions in rust-coreutils first, the new Rust implementation of the basic Unix tools. On the desktop, GNOME 50 now runs under Wayland only.

For servers and Docker hosts, the old rule applies: don't click on day one. The rust-coreutils are the part that can surprise shell scripts, since small details in the behavior of ls, cp, and friends differ. Staging first, then production.

Netherlands: a government desktop built on NixOS

The Dutch Ministry of the Interior (BZK) is having three state IT providers build a sovereign workplace: DAWO, "Digitaal Autonome Werkomgeving Overheid."[1] NixOS won out as the operating system, after tests with openSUSE and Fedora. The reason: declarative configuration and reproducible deployments for large device fleets. For collaboration, MijnBureau is added, meaning Nextcloud, Collabora, Element, and OpenProject. The project coordinates with France's La Suite and Germany's openDesk. According to the municipal association, tests are running in 8 municipalities.

This is still a pilot, not a rollout. But the choice is notable. NixOS was long seen as a tool for enthusiasts. When a government chooses it for reproducibility, that's a signal for anyone who takes infrastructure as code seriously.

Declarative: Instead of running commands one after another ("install this, change that"), you describe in a file what the finished machine should look like. NixOS builds it from that, the same way on every device. Like a blueprint instead of a list of manual steps.

Met Police halts phone forensics software

Scotland Yard has paused the use of software for extracting data from phones. According to The Register, US prosecutors traced the supposedly American tool back to Moscow.[1] This is a supply-chain story in miniature: the origin of the software apparently wasn't verifiable for the buyer.
