Cisco: CVSS 10 in the License Server, Five Critical Flaws in NX-OS

On Oct. 7, Cisco published two sets of advisories. The first covers NX-OS on Nexus 3000 and Nexus 9000 switches in standalone mode. BleepingComputer speaks of "five critical vulnerabilities in its NX-OS data center" software.[1] The flaws sit in different services:

  • CVE-2026-76471: NX-API, via crafted HTTP requests. NX-API is off by default.
  • CVE-2026-76485, -76486, -76501: NGOAM. -76486 additionally affects SRv6 and NV Overlay, -76501 also SRv6.
  • CVE-2026-76465: MPLS echo request packets.

Nexus 7000 and Nexus 9000 in ACI mode are not affected. Cisco found the bugs itself and knows of no attacks.[1]

The second set covers Cisco License, the license server formerly called Smart Software Manager. According to BleepingComputer:[1]

According to the report, Cisco recommends version 10-202609, "with no workarounds available". Older releases branded Smart Software Manager will not be patched, per the report; Cisco recommends migrating to a supported release.[1] Cisco lists a second License On-Prem advisory the same day (CVE-2026-76437, -76452, -20328, -76454), also rated 10.0.

Unconfirmed I did not check the NX-OS fix versions. Per Cisco's Oct. 7 advance notice, the NX-OS flaws (MPLS OAM CVE-2026-76465, NGOAM CVE-2026-76485, -76486, -76501, NX-API CVE-2026-76471) are remote code execution rated CVSS 9.8; the same notice confirms the Cisco License scores. I did not check the NVD. So read the advisories in the Cisco Security Center before patching.
NGOAM / SRv6: Two network features in data centers. NGOAM is a diagnostic tool, like a ping for the overlay network. SRv6 is a method where a packet carries its own route. If you have not enabled these features, you are probably less exposed to the affected flaws. The exact picture is in the advisories.

My take: The NX-OS flaws are serious at CVSS 9.8 with remote code execution, but they affect fewer teams than the number suggests. The affected services are special features or off by default, and switches don't belong on the open internet. The license server is the bigger issue. A broken signature check with CVSS 10 on a server that many companies have forgotten somewhere on their network is exactly the kind of flaw that lands in the KEV catalog in a few weeks.

CISA KEV: Five Flaws From the Attic

Since yesterday: The standstill is over. New catalog version 2026.10.08.

After three days with no entries, CISA added five flaws to its catalog of actively exploited vulnerabilities on Oct. 8. The catalog now has 1,739 entries. US federal agencies must patch by Oct. 11. Whether ransomware groups use the flaws is listed as "Unknown" for all five.[1]

KEV catalog: The list from the US agency CISA of flaws that are demonstrably being attacked. An entry does not mean "new", it means "is being used now". Like a wanted poster: the culprit may be old, but he is out and about again.

The Atlassian flaw CVE-2026-21589 is not in the entries from Oct. 4 to Oct. 8, even though attacks have been reported (see below).[1]

My take: Flaws from 2015 and 2016 in a 2026 catalog say more about our infrastructure than about the attackers. Somewhere a ten-year-old BIND and Struts are still running. Strapi is the most interesting entry for Node teams, because the headless CMS often sits in small projects nobody maintains anymore.

Shai-Hulud Hits Tensorlake: Eleven Minutes to Detection

The npm package of the Tensorlake SDK was malicious in version 0.5.144. According to The Register, the package gets around 12,000 downloads per week. The company Socket detected the version eleven minutes after publication. npm removed it; 0.5.145 is clean.[1]

According to The Register, the malicious code resembles the ChainDrop campaign, an offshoot of the Shai-Hulud worm that hit packages like keyv and flat-cache in August. It steals crypto wallets, browser passwords, GitHub Actions secrets and cloud credentials. One nasty detail: it can delete the home directory if the stolen token is revoked.[1]

Supply-chain worm: The malicious code steals a developer's npm credentials and uses them to publish new, infected versions of that developer's packages. That's how it jumps from package to package. Like a chain letter that forwards itself.
Mind the order If you had 0.5.144 installed: clean the machine first, then rotate tokens. Because of the delete function, the reverse order is risky. That is how The Register describes it; I have not read the primary analyses from Socket and SafeDep.

My take: Tensorlake is a company from the AI space, but that's beside the point here. The pattern is the same as in August: a stolen publish token, an install script, and everything on the build machine is gone. Eleven minutes to detection is good. But if you ran npm install without a lockfile in those eleven minutes, you're out of luck. So: lockfiles, npm ci, and Trusted Publishing instead of long-lived tokens.

[1] theregister.com (Oct. 8)

Veeam: Code Execution Flaw in the Backup Server

Veeam has updated Backup & Replication. The most severe flaw according to heise: CVE-2025-64393, a deserialization flaw in the mount service with CVSS4 9.4. An attacker needs "Backup Viewer" role privileges for it. Also included are CVE-2026-93026 (6.1) and an XSS, CVE-2025-64392 (4.8). Fix: 12.3.2.4934 (12.3.2 Patch 4).[1]

Another flaw affects Cloud Connect: CVE-2026-58069 (CVSS4 8.3) lets a tenant read arbitrary files. Fix in 13.1.0.411, 13.0.3.63 and 12.3.2.4934. Support for version 12 ends on Feb. 28, 2027.[1]

One source All values come from heise. I did not check the Veeam KB or the NVD. The report says nothing about attacks.
Deserialization: A program rebuilds an object from received data. If the check is weak, an attacker smuggles in an object that runs code while being rebuilt. Like a flat-pack kit with a set of instructions inside that you follow blindly.

My take: Backup servers are the favorite target of ransomware groups, because whoever has the backups holds the ransom. That a login is required is only half reassuring: the "Backup Viewer" role sounds harmless and is handed out accordingly generously.

[1] heise.de (Oct. 8)

FortiBleed: Attackers Lock Out the Admins

Since yesterday: New detail from the FBI on the method.

According to BleepingComputer, the FBI warns that the ongoing FortiBleed attacks on publicly reachable FortiGate firewalls and SSL VPNs are locking out the real administrators ("locking out legitimate administrators"). There is still no CVE.[1] The Register writes of "tens of thousands more victims".[2] Yesterday we cited the figure of over 86,644 valid credentials (as of June 19).

My take: If you are locked out, you have a problem that one click won't solve. Check now whether you have console access or a local emergency admin, before you need it.

Malware Campaigns: Fake Repos and Open AI Servers

FakeGit: 17,610 Fake GitHub Repos

The FakeGit campaign is back. According to BleepingComputer, more than 17,000 fake repositories, exactly 17,610, distribute the SmartLoader loader, which downloads the StealC info-stealer.[1] The repos disguise themselves as useful tools. If you run code from an unknown repo with little history, think twice.

PoeLLM: Over 3,000 Servers With Crypto Miners

According to The Register, the PoeLLM malware has infected more than 3,000 openly reachable AI servers and mines cryptocurrency on them.[2] This is a classic infrastructure problem: a service with no login on the open internet. The AI is just the software that happens to run on the server.

Chrome 155: JPEG XL for Everyone

According to heise, JPEG XL has arrived in Chrome 155, without a flag. The decoder is called jxl-rs and is written in Rust. Google cites 30 to 50% better compression than JPEG. In Chrome 145 the format was only available behind a flag.[1]

JPEG XL: An image format that can pack old JPEGs smaller without loss and compresses new images better. Like a suitcase that fits the same clothes, just folded.

My take: Google removed JPEG XL from Chrome a few years ago, and now it's back, with a decoder in a memory-safe language. That's the real point: image decoders have been a source of browser vulnerabilities. For frontend teams: <picture> with a JXL source becomes interesting, but heise does not give the stable release date, and I could not check the Chrome page.

Europe: BSI Against McEliece, Criticism of d-you

BSI Advises Against McEliece

According to heise, the BSI is concerned about the post-quantum scheme Classic McEliece and "advises against its use – at least for new projects".[1] Until now, McEliece was considered a conservative choice with very large keys.

Post-quantum cryptography (PQC): Encryption that even a future quantum computer should not be able to crack. McEliece is one of these schemes, very old and well studied, but with huge keys.

My take: For most teams this changes nothing, because TLS libraries rely on ML-KEM. But if you're planning for German agencies and chose McEliece because of its closeness to the BSI, check it now.

EUDI Wallet "d-you": Heavy Criticism in the Bundestag

At the hearing in the Digital Committee, "hardly any invited expert was satisfied with the German implementation of the EUDI Wallet," according to heise.[2] Yesterday's brief had more on this.

If you run Veeam: move to 12.3.2.4934 and clean out the "Backup Viewer" role. And if you've forgotten Strapi, BIND or ProFTPD somewhere: now is a good time to find them.
