Python 3.15.0: the release worth upgrading for

Since yesterday: Yesterday the release page was still a 404. Now it is online.

According to python.org, Python 3.15.0 has been final since 2026-10-09.[1] The list of changes is long. Four points matter most for everyday work:

  • PEP 810, explicit lazy imports, per python.org "for faster startup times".[1]
  • PEP 686: Python now uses UTF-8 as the default encoding.[1]
  • PEP 814: frozendict as a built-in type, plus PEP 661 with a built-in sentinel type.[1]
  • The experimental JIT compiler is "significantly upgraded" according to the release page, and there is a new sampling profiler called Tachyon (PEP 799).[1]
Lazy import: The module is loaded only when the code actually uses it, not at startup. Like a toolbox where you only fetch the hammer when a nail shows up. Result: CLI tools and servers start faster.

There are also typing improvements (TypedDict with typed extra keys, TypeForm), a stable ABI for free-threaded builds, and frame pointers by default (PEP 831), which makes system-level profiling easier.[1] According to python.org/downloads, bugfix support runs until October 2031.[2]

My take: this is the first Python release in years that you will notice directly in server code. The UTF-8 switch, though, is the part that can bite. Code that silently relied on cp1252 under Windows now reads files differently. For FastAPI projects, I would wait for the first wheels of the big dependencies before switching, so a few weeks.

To check If you call open() without encoding= and run on Windows, test those spots before the upgrade.

SonicWall SMA1000: attacked or not?

Since yesterday: Yesterday this said "still no attacks reported". That is no longer entirely true.

The flaw CVE-2026-102255 in the SMA1000 series (models 6210, 7210, 8200v) is an unauthenticated SSRF in the WorkPlace interface. Trade press cites CVSS 10.0; we had no NVD score. The hotfix came on Oct 6; builds 12.4.3-03670 and 12.5.0-03082 or newer are clean.[1]

SSRF (Server-Side Request Forgery): The attacker gets the server to send requests to internal systems on their behalf. Like a visitor asking the doorman to fetch a file from an archive the visitor is not allowed into.

The contradiction: On Oct 9, BleepingComputer headlined "now exploited in attacks".[2] But there is only one source: Ryan Dewhurst of Previdian says his honeypot network saw "exploitation attempts". Whether the attempts compromised any systems is left open, according to the article. SonicWall itself has not yet marked the flaw as actively exploited in advisory SNWLID-2026-0017.[2] Help Net Security quotes the vendor: "no evidence" of attacks.[1]

My take: attempts against honeypots three days after the patch are exactly what you expect for a VPN appliance with CVSS 10. For the decision, the dispute does not matter. If you have an SMA1000 on the network, treat it as if it is being scanned right now. It is.

Citrix NetScaler: SAML again

Citrix has added a new flaw: CVE-2026-107406 (advisory CTX697191). According to BleepingComputer, it is a "memory overflow weakness" that allows code execution or a crash. Only ADC and Gateway systems configured as a SAML Identity Provider or Service Provider are affected. Citrix says: "not aware of any unmitigated exploits".[1] The article gives no CVSS score.

Important for context: this is not the same flaw as CVE-2026-88779 from last weekend. The old flaw has been in CISA's KEV catalog since Oct 4[2], and Citrix had observed targeted attacks.[3] The fix builds are different too:

  • CVE-2026-88779: 14.1-73.41 and 13.1-64.28.[3]
  • CVE-2026-107406: 14.1-73.46 and 13.1-64.29 or newer, FIPS 14.1-73.46, FIPS/NDcPP 13.1.37.283.[1]

So anyone who moved to 14.1-73.41 last week has to patch again. heise puts it this way: "Last weekend Citrix closed a zero-day flaw in Netscaler", and now comes the follow-up.[4]

My take: NetScaler's SAML component is the weakest spot this fall. CVE-2026-107406 is already the second NetScaler bulletin within a week, after CVE-2026-88779. The details come from BleepingComputer; we did not check the Citrix bulletin ourselves. If you run SAML on NetScaler, plan for the next patch before it is announced.

AhsayCBS: attacks on a backup server with no safe patch

The MDR firm Huntress saw attacks on AhsayCBS, a backup platform, on Oct 7. The attackers chain two flaws: CVE-2026-105133 bypasses the login, and a public exploit exists for it. CVE-2026-105134 then allows command execution on the operating system. At least five organizations were targeted.[1]

Next come JSP web shells and an XMRig miner, disguised as "edge.exe" and as the service "MicrosoftEdgeUpdateSvc". A PowerShell script stops the mining as soon as someone opens Task Manager.[1]

The problem: the flaws count as fixed in version 10.3.2. But Huntress found that the current 10.3.4 is affected too. The vendor had not replied to BleepingComputer by publication.[1] There is no CVSS number; the article speaks of one critical and one medium-severity flaw.

Heads up Without a confirmed fix, all that remains is: do not expose the web interface openly to the internet, and look for the service "MicrosoftEdgeUpdateSvc" on the backup server.
[1] bleepingcomputer.com (Oct 9)

Atlassian Data Center: attacks are running, the picture is clear

No new details since yesterday. CVE-2026-21589 allows reading files without a login. Atlassian internally rates the flaw CVSS 9.3 (CVSS 4.0).[1] Attack attempts began shortly after the warning and watchTowr's technical analysis (Oct 6); heise reported them on Oct 8.[2]

The fix versions for the three most important products (per Help Net Security):[1]

  • Confluence DC: 9.2.26 or 10.2.19.
  • Jira Software DC: 9.12.40, 10.3.26 or 11.3.12.
  • Bitbucket DC: 9.4.26, 10.2.8 or 10.5.1.

Jira Service Management, Bamboo, Crowd and Crucible/Fisheye also have fixes; the list is in the source.

CISA KEV: tomorrow the deadline for the museum pieces runs out

On Oct 8, CISA added five old flaws to the KEV catalog. US federal agencies must close them by Oct 11:[1]

  • ProFTPD, CVE-2015-3306
  • ISC BIND, CVE-2015-5477
  • Apache Struts, CVE-2016-3081
  • ONLYOFFICE Docs, CVE-2021-3199
  • Strapi, CVE-2023-22894
KEV catalog: The US cybersecurity agency's list of flaws that are demonstrably being attacked. Like a wanted board: not every flaw makes it on, only the ones where someone has already broken in.

My take: a 2015 flaw in the KEV does not mean it is new. It means servers are still running with it somewhere and someone finds them. Strapi from 2023 is the entry a web developer is most likely to meet in their own basement.

Cisco NX-OS: reminder for Monday

Covered at length here yesterday, so only briefly. The most severe of the new NX-OS flaws is CVE-2026-76471 in the NX-API: an attacker without a login can execute code as root, per a tracker, CVSS 9.8, published Oct 7.[1] The score comes from a secondary tracker; we did not read the Cisco advisory (cisco-sa-napi-rce-r2shwu2j) ourselves. No attacks are known.

My take: the NX-API does not belong on the open internet and rarely on the office network. If you do not need it, switch it off. That is the fastest mitigation.

Windows: old certificates, less protection at boot

On Oct 9, BleepingComputer headlined that outdated Windows devices would stop receiving security updates.[1] A link to Secure Boot is unproven. The Microsoft page on Secure Boot certificates, which began expiring in June 2026, sounds narrower. It says affected devices could no longer receive new protections "for the early boot process".[2] We could not load the BleepingComputer article itself, so the headline is either a sharpening or means more than we could check.

Secure Boot: At startup, the computer uses certificates to check that the bootloader is genuine. Like a bouncer with a guest list. If the list expires and no new one arrives, the bouncer lets no new guests in.

My take: for servers and family laptops this is an item for the inventory, not an emergency. If you run old hardware with Windows, check over the next few months whether the new certificates arrive.

ClickFix via Google ads

Attackers use genuine Bing redirects as the click target in Google search ads. Users end up at fake Claude installers.[1] The software lesson: the URL in the ad looks clean, the destination is not.

Cheap Android with proxy malware from the factory

What twenty minutes this weekend are worth

Run Python 3.15 in a throwaway venv against your own project and watch for encoding warnings. If you run NetScaler with SAML: check the build number, 14.1-73.41 is no longer enough. If you have AhsayCBS or an SMA1000 on the network: put the web interface behind a VPN. The rest can wait until Monday.

It's Saturday, October tenth. The good news first: Python three point fifteen officially came out on Friday. The rest of the day is security cleanup.

Python three point fifteen brings explicit lazy imports, meaning modules that load only when the code actually needs them. It also makes UTF-8 the default encoding and adds a built-in frozendict and a much improved JIT compiler. The UTF-8 change is where older code on Windows can trip. According to python.org, bugfixes run through October twenty thirty-one.

At SonicWall, there's a conflict. The flaw in the SMA one-thousand appliances carries the maximum score of ten, according to trade press. BleepingComputer reports attacks, but it relies on a single honeypot operator who saw attack attempts. SonicWall itself reports no attacks. For admins, the dispute changes nothing: patch, and keep the interface off the open internet.

Citrix has closed another flaw in NetScaler. It affects only systems configured as SAML providers. According to Citrix, no attacks are known. The key point: this is a new flaw, not the one from last weekend. If you patched last week, you have to do it again.

On the AhsayCBS backup server, the firm Huntress is observing attacks with web shells and a crypto miner disguised as a Microsoft Edge service. The ugly part: even the newest version is said to still be affected, and the vendor has not responded.

Attacks on Atlassian Data Center continue, with no new details. And tomorrow, the deadline from the US agency CISA runs out for five old flaws in BIND, Struts, Strapi, ONLYOFFICE and ProFTPD.
