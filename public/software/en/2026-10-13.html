GitLab: Top Score in the CI/CD Regex Compiler

GitLab published patch releases on Monday: "On October 12, 2026, we released versions 19.4.2, 19.3.5, 19.2.8".[1] The reason is CVE-2026-97229, an "Integer Overflow issue in CI/CD Regular Expression Compiler impacts GitLab CE/EE". GitLab rates the flaw CVSS 3.1 10.0, vector AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H.[1] Affected are 19.2 before 19.2.8, 19.3 before 19.3.5 and 19.4 before 19.4.2.[1]

Integer Overflow: A counter has a fixed size, like an odometer with six digits. Drive past 999,999 and it rolls over to 0. In code, that means the program thinks it needs little memory, then writes far more into it. With carefully built input, here a regular expression in the CI configuration, the worst case is attacker code running on the server.

According to BleepingComputer, the report came in through HackerOne. GitLab.com is already patched, and GitLab Dedicated customers need to do nothing. There is no mention of attacks.[2] BleepingComputer names 19.3.4 as the fix for the 19.3 branch. We follow GitLab's own page: 19.3.5.[1][2] The flaw is not in CISA's KEV catalog.[3]

The pattern is the problem. On Sep 23, versions 19.4.1, 19.3.3 and 19.2.7 arrived with two flaws in the same place: CVE-2026-93577 (also an integer overflow) and CVE-2026-89078 (double free), both CVSS 9.9, both code execution through crafted regex in CI/CD.[4] Back then the attacker needed a login, hence 9.9. The vector now says PR:N: no privileges required.

To check Self-managed instance? Look up the version under Admin → Overview. If you skipped the Sep 23 update, 19.4.2 catches up on both rounds. If you are still on 19.1 or older, the advisory lists no fix version for your branch.

My take: three critical flaws in three weeks in the same component usually mean that many researchers are now looking exactly there. I would expect a fourth round. A GitLab that is reachable from the internet and has open registration is a bad idea right now. If you can, put the instance behind Tailscale or a VPN. It costs an afternoon and takes much of the sting out of the next flaw.

Windows 11 23H2: One Month Left

For the Enterprise, Education and IoT Enterprise editions of Windows 11 23H2, security updates end in 30 days, counted from Oct 12, according to BleepingComputer.[2] The November Patch Tuesday is therefore the last update. Microsoft also warns: after a change of update certificates next year, outdated, unsupported Windows devices will no longer receive updates.[3]

My take: for developers, 23H2 matters mostly in corporate images and build agents. These machines often run for years without major updates. Now is a good time to count your own Windows runners once.

Bootstrap 6: The First Alpha, and It Looks Like Tailwind

Bootstrap released the first alpha of version 6 on Oct 8, the first major release in five years.[1] The most striking change concerns the responsive classes. .d-md-none becomes .md:d-none, and .col-lg-6 becomes .lg:col-6.[1] The screen-size prefix now comes first, just like in Tailwind.

More points according to heise: accordion and dialog build on the native HTML elements, and theming runs through CSS variables. Only current browsers are supported, from Chrome/Edge 130, Firefox 132 and Safari 18.[1] New is also an llms.txt file with a migration guide for AI agents.[1]

Native <dialog>: A popup window used to need a lot of JavaScript: trapping focus, locking the background, catching the Escape key. The HTML element <dialog> now does that itself. Bootstrap no longer has to ship that code, and screen readers understand the element out of the box.

My take: this is a sensible decision with a high cost. Every template with d-md-none must be adjusted, and in large Angular or Thymeleaf projects that means thousands of places. A search-and-replace script handles most of it, but not classes assembled in code. For new projects, the alpha makes Bootstrap interesting again. For existing projects, I would wait for the beta and hope for an official migration tool.

[1] heise.de (Oct 9)

Apple: CISA Deadline Ends Today

CVE-2026-86950 is, according to The Register and Dark Reading, an out-of-bounds write flaw in CoreGraphics. The flaw was used in an "extremely sophisticated attack" against selected individuals, on iOS versions before 27. Meta Product Security reported it.[1][2] According to these reports, the fixes arrived on Sep 28 in iOS/iPadOS 26.7.1, macOS Tahoe 26.7.1 and macOS Sequoia 15.8.1. iOS 27 and macOS 27 are not affected.[1][2] We did not open the Apple advisory itself.

CISA added the flaw to the KEV catalog on Sep 29. The deadline for US federal agencies ends today, Oct 13.[3]

KEV deadline: The KEV catalog of the US agency CISA lists flaws that are proven to be under attack. US federal agencies must close them by a fixed date. For everyone else, the deadline is a good signal: there are real attacks here, not just a theory.

My take: targeted attacks rarely hit ordinary developers. Still, test iPhones and old Macs that cannot move to 27 are exactly the devices people forget to update.

[1] theregister.com · [2] darkreading.com · [3] cisa.gov KEV (as of Oct 13)

Chrome 155: 247 Security Fixes

Google moved Chrome 155 to the stable channel on Oct 7: desktop 155.0.8059.39/.40, Android .39, iOS 155.0.8059.37.[1] According to Deskmodder, "247 security flaws are closed", and "four of the flaws were rated critical".[1] There is no mention of attacks in the wild. Extended Stable stands at 152.0.7977.158.[1]

My take: 247 is an unusually high number for a single release. We could not load the Chrome release blog, so the number comes from one source. One thing matters most for us: headless Chrome in CI images and Playwright and Puppeteer containers do not update themselves. If you pin a fixed Chrome in a Docker image, rebuild it.

The latest entries in the KEV catalog are still from Oct 8, including ProFTPD (CVE-2015-3306) and ISC BIND (CVE-2015-5477). Nothing was added between Oct 9 and today.[1] Neither the Atlassian flaw nor the GitLab flaw appears in the newest entries.[1]

Atlassian Data Center: Attacks, but No KEV Entry

CVE-2026-21589 (CVSS 4.0: 9.3) allows reading files without a login if the path is known. All versions of the Data Center products Jira, Confluence, Bitbucket, Bamboo and Crowd are affected. On Oct 8, heise reported "156 attack attempts from 25 IP addresses in eight countries".[2] The fix versions are in the Atlassian advisory, which we did not check at the source.

Citrix NetScaler: SAML Flaw with 9.5

CVE-2026-107406 has CVSS 4.0 9.5 according to Citrix and affects only systems with a SAML SP or IdP configuration. Fix from 14.1-73.46 and 13.1-64.29. No attacks known.[3]

AhsayCBS: Still No Patch

For the attacked flaws CVE-2026-105133 and CVE-2026-105134, there was no fix at last check, and 10.3.4 is affected too.[4] We did not re-check this today. The admin interface still does not belong on the internet.

Yandex: War Hits Data Centers

According to The Register, Ukrainian drone strikes damaged three Yandex data centers, two of which had to be shut down. Cloud services and payments went down.[1] According to BleepingComputer, Yandex confirmed the outage, and users could no longer reach their cloud files.[2]

My take: Yandex itself hardly matters to us. The lesson does: "two data centers in the same region" is not a disaster plan if both can be hit by the same event. That applies to war as much as to flooding or a power outage across a whole city.

Rust 1.99.0 and the End of i686 Windows

Rust 1.99.0 has been out since Oct 1. The day after, the project announced it would downgrade the i686 Windows targets to "std-only".[1] That means less support for 32-bit Windows. If you still build 32-bit Windows binaries from Rust, read the blog post.

My take: the next version is 1.100. A purely numeric event, but surely a few tools compare versions as text and then work out "1.100 < 1.99". A test for that in your own build scripts does no harm.
