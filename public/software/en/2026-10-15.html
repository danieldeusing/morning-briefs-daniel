Cloudflare buys Deno and lets the runtime wind down

On Oct 9, Deno announced on its own blog: "Deno is joining Cloudflare!"[1] heise summarized what that means in practice on Oct 14. The Deno runtime gets one more year of monthly updates, then development ends. It stays open source, and Deno invites the community to carry it on. The commercial hosting service Deno Deploy shuts down in just six months. Paying customers get help migrating to Cloudflare Workers.[2]

JavaScript runtime: The program that runs JavaScript outside the browser, on the server or in the terminal. Node.js is the best known, Deno and Bun are the challengers. Think of a car's engine: the code is the body, the runtime makes it go.

Why Cloudflare is buying is fairly clear according to heise: it is about celld. The tool brings Cloudflare Workers and Durable Objects into your own infrastructure and distributes them across several machines. The Deno team joins the Workers team, celld moves into the Workers platform, and the Rust bindings rusty_v8 move into the Workers runtime workerd. The package registry JSR is supposed to keep running.[2] Nobody names the purchase price. It is also unclear whether Cloudflare will continue Deno's trademark dispute with Oracle over the name "JavaScript". heise has asked.[2]

Self-hosted Workers: Workers normally run only in Cloudflare's data centers. celld is meant to run the same programs on your own servers. Like a franchise recipe that you are suddenly allowed to cook in your own kitchen.

My take: this is an acqui-hire for a product, not for a runtime. For Cloudflare it is smart, because "Workers on-prem" is exactly the answer to the sovereignty question from European customers. For everyone who bet on Deno, it is a hard cut. If you use Deno Deploy, you have six months, and that is short. If you only use the runtime, you have time, but should check now whether the code also runs under Node or Bun. The good news: Deno's path toward web-standard APIs makes exactly this move easier than it was five years ago. Keeping JSR as a registry is the right call, because packages that Node users pull in also live there.

To check grep -r "deno" .github/workflows and Dockerfiles: where does Deno run today as a build or script tool? Those spots are the first candidates for migration.

A piquant detail: Deno Desktop, experimental since Deno 2.9 (Jun 25, 2026), was still a topic at heise developer on Oct 13.[3] Whether it still has a future is open.

curl 8.23.0: 24 CVEs at once, SMB is out

curl 8.23.0 has been out since Oct 14.[1] The same day, the project published 24 CVEs. curl rates 23 of them "low" and one "high": CVE-2026-92392, a use-after-free during HTTP/2 upload. According to curl, versions 8.12.0 through 8.22.0 are affected.[2] According to heise, an attack needs a user who is uploading something at that moment. Daniel Stenberg nevertheless calls it, per heise, "one of the most serious security vulnerabilities in a long time".[3]

Use-after-free: A program frees a piece of memory and then keeps using it anyway. Like a hotel guest who, after checkout, still walks into the room with the old key, where someone new is already staying.

The second piece of news sits unobtrusively in the changelog: "SMB: drop support".[1] As of 8.23.0, curl no longer supports SMB and SMBS. Hardly anyone is affected, but it shows a direction: fewer protocols, less attack surface. According to heise, Stenberg continues to reject a rewrite in Rust.[3]

My take: 24 CVEs sounds dramatic, but it is only partly so. Many of the low findings are the result of more and better analysis tools, not of worse code. According to heise, Anthropic found the high-severity bug. How AI tools make such finds is covered in the ai-dev brief. What matters for us: curl is in almost every container image. The system package arrives with the next distro update. Statically linked copies in your own images only update if you rebuild yourself.

Ledger: tampered wallets, damage bigger than thought [1]

The supply chain of Ledger hardware wallets was attacked. According to heise, tampered devices contained an extra chip with an LTE modem and eSIM. According to heise/Bitquery, as of Oct 13 around $102M has flowed out of 324 wallets; an earlier Bitquery count came to $93M from 315 wallets. Ledger has not confirmed the figures. Tether froze $10M in USDT. MediaMarkt Saturn has stopped selling Ledger devices. Ledger's own statement from Oct 9 names, per heise, only one retailer, Cryptobilis, and a period of 90 days.

Supply-chain attack (hardware): The attacker does not attack the finished device at the customer's site, but tampers with it on the way there. Like a safe in which someone drilled a second keyhole before delivery.

My take: a hardware wallet promises exactly one thing, namely that the key never leaves the device. A built-in radio modem breaks that promise completely. That MediaMarkt Saturn is stopping sales makes this a German story, even though Ledger names only a French retailer. The figures here have a single source, heise with Bitquery as the data provider. If you bought a wallet through third parties, run the manufacturer's authenticity check and, when in doubt, move your coins to a new device with a new seed phrase.

[1] heise.de (Oct 14)

CISA KEV: four new entries, plus some very old acquaintances [1]

On Oct 14, CISA added four vulnerabilities to the KEV catalog: CVE-2026-0322 in Palo Alto PAN-OS, CVE-2026-76519 in Cisco Secure Email Gateway, and CVE-2026-105133 and CVE-2026-105134 in AhsayCBS, a backup software. On Oct 13, the Windows Shell vulnerability CVE-2026-96951 and Ivanti's CVE-2026-104935 were added.

KEV catalog: The list from the US cyber agency CISA of vulnerabilities that are demonstrably being attacked. Theoretically dangerous flaws are not on it. Like a police alert "a break-in is happening on this street right now" instead of "windows can break".

On the new entries: according to Palo Alto, CVE-2026-0322 is an authenticated remote code execution in the PAN-OS management interface, CVSS 4.0 8.6, published Oct 14. Palo Alto reports "very limited exploitation". Cloud NGFW and Prisma Access are not affected.[3] This is not the older CVE-2026-0300 in the User-ID authentication portal, which according to Unit 42 is being exploited by a state-backed group.[2] For AhsayCBS, Huntress has seen attacks with webshells and the XMRig crypto miner since Oct 7. On Oct 10, Ahsay said that patch v10.3.4.0 did not fully fix the two CVEs; the corrective hotfix is 10.3.4.45 (per Huntress, BleepingComputer and SecurityWeek). For Cisco CVE-2026-76519 we found only the KEV entry.

More interesting is the round from Oct 8: ProFTPD (CVE-2015-3306), BIND (CVE-2015-5477), Apache Struts (CVE-2016-3081), ONLYOFFICE Docs (CVE-2021-3199) and Strapi (CVE-2023-22894) landed in the catalog. These are vulnerabilities up to eleven years old that are now demonstrably being attacked. On Oct 4, Citrix NetScaler (CVE-2026-88779) was added, on Oct 2 the helpdesk Zammad (CVE-2026-102489 and CVE-2026-102490). Zammad comes from Germany and runs in many German companies and agencies. DE

My take: the old entries are the real lesson. Nobody attacks a 2015 ProFTPD in 2026 because it is hard, but because those servers still exist. Inventory beats patch speed.

PostgreSQL: three security updates, but still no RC [1]

postgresql.org lists three security announcements from the ecosystem. PgBouncer 1.26.1 (Oct 14) "Fixes three CVEs". psqlODBC 18.00.0005 (Oct 14) closes CVE-2026-109448. The PostgreSQL JDBC driver 42.7.14 is, per the announcement, a "Security update for multiple CVE's" and dates from Oct 7.[1] We have not checked the individual vulnerabilities and their severity.

PgBouncer: A connection pooler that sits in front of PostgreSQL and bundles many short connections from apps into a few real database connections. Like a switchboard that routes a hundred callers onto ten lines.

For Spring projects, JDBC is the most important point. The driver usually comes in via Spring Boot, so it is worth checking which version your Boot BOM currently pins. PgBouncer often runs as a sidecar in Docker Compose and is easily forgotten during updates.

The latest status there is "PostgreSQL 19 Beta 4 Released!" from Sep 24.[1] We will check again tomorrow.

BSI-CS 154: Small systems do not belong on the internet [1]

Yesterday this was only a one-liner, now more. The BSI published the recommendation BSI-CS 154 on Oct 13. It is aimed at operators of small networked systems: solar inverters, refrigeration systems, small wind turbines, water technology. The trigger was attacks on the refrigeration of French supermarkets. The core advice according to heise: "The most important and at the same time simplest protection is to disconnect the systems from the internet." With the Cyber Resilience Act, stricter obligations for manufacturers follow from December 2027.

Cyber Resilience Act (CRA): An EU law that imposes security obligations on makers of products with software, such as updates over the whole lifetime. Like the CE mark for electrical goods, only for security vulnerabilities.

My take: the advice sounds banal and is still right. Many of these devices have a web interface from 2015 and have never seen an update. If you have an inverter or a heat pump with an app in your homelab: remote access through a VPN such as Tailscale or WireGuard, no port forwarding.

[1] heise.de (Oct 13)

Firefox Enterprise: Mozilla's business browser launches in DACH [1]

Update since Wed Yesterday we only had the name, now the details. Mozilla launched Firefox Enterprise 158.0 on Oct 13. It includes a self-hosted management console, single sign-on via OIDC, a login that checks the device's state, and controls for pasting, uploading, downloading and printing. According to heise, the browser can, for example, prevent "employees from copying sensitive data into unapproved AI services". It is sold first in France, Germany, Austria and Switzerland, with a prior access request.

My take: the choice of countries is the signal. Mozilla is aiming at companies and agencies that want a browser with no US corporation behind it and a self-hosted console. Against Chrome Enterprise and Edge that is hard, but in DACH there is a real market for it.

It's Thursday, October fifteenth. The biggest story today isn't a security hole, it's an acquisition: Cloudflare is buying Deno.

Deno is a JavaScript runtime, a challenger to Node. According to heise, it gets one more year of monthly updates, then development ends and the community is supposed to take over. The hosting service Deno Deploy shuts down in just six months. The package registry JSR keeps running. What Cloudflare really wants is a tool called celld, which lets Workers run on your own servers. If you use Deno Deploy, start planning your move now.

curl has released version eight point twenty-three and closed twenty-four security holes in the process. Twenty-three are minor, one is serious: a memory bug when uploading over HTTP two. curl also no longer supports SMB. If you bake curl into your own container images, rebuild them.

At Ledger, hardware wallets were tampered with in transit, with an extra radio chip added. According to heise and the analytics firm Bitquery, about one hundred two million dollars has flowed out of three hundred twenty-four wallets. MediaMarkt and Saturn have stopped selling Ledger devices.

The U.S. agency CISA has added four more actively exploited vulnerabilities to its catalog, including ones at Palo Alto and Cisco. Worth noting is an earlier round with flaws up to eleven years old. The lesson: if you don't know your old servers, you can't patch them.

Around PostgreSQL, there are security updates for PgBouncer, the ODBC driver and the JDBC driver. The release candidate for PostgreSQL nineteen, which we had announced for today yesterday, isn't showing up on the project site yet.

Germany's BSI advises operators of small systems like solar inverters and refrigeration units to disconnect the devices from the internet. And Mozilla is launching Firefox Enterprise, first in Germany, Austria, Switzerland and France.

Tomorrow the CISA deadline for Ivanti runs out, and on Tuesday Oracle's patch update for Java arrives. We'll check tomorrow whether PostgreSQL delivers.
