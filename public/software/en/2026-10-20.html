PwnEscape: from the VM into the host [1][2][3][4]

A flaw in the Linux kernel's networking code lets a guest break out of its KVM VM. The flaw is called PwnEscape, identifier CVE-2026-99999; heise and The Register both report CVSS 9.3.[1][2] We have not confirmed the score in the NVD. The Debian Security Tracker confirms the identifier and the fix versions.[3]

VM escape: A virtual machine is a sealed-off computer on a real server that many customers share. An escape means the guest gets out of its box and controls the whole server. Like a hotel guest whose room key suddenly opens every door in the building.

The bug sits in skb_checksum_help. A guest sends malformed IPv4 packets, and according to The Register, "untrusted checksum metadata" can overwrite security-relevant fields in the packet.[2] Debian's title for the fix: "ipv4: validate checksum_start before completing checksum".[3] Paulos Yibelo discovered it.[2]

Where the fixes stand: the fix (commit 6785011f8b16) landed upstream in October, and seven stable kernels with the fix followed on Oct 15.[4] Debian has it in bookworm (6.1.190-1) and trixie (6.12.113-1). Ubuntu and RHEL still had no packages on Oct 19.[1] According to heise, Hetzner is using an eBPF mitigation and Netcup is rebooting hosts. AWS says EC2 is not affected.[2] Attacks in the wild are not confirmed; the researchers expect exploits "within a few weeks".[1]

Context For ordinary Docker boxes this is not a weekend emergency: the flaw hits KVM hosts that run foreign guests. If you run your own Proxmox or KVM hosts, do not wait for Ubuntu; plan a stable kernel with the fix. If you only rent VPS, ask your provider. A CVSS vector and the affected kernel range are still missing from both reports.

ConnectWise Cloud Backup: MFA doesn't help when the app logs in itself [1][2]

Attackers got into customers' Microsoft 365 tenants through ConnectWise Cloud Backup (formerly SkyKick). ConnectWise confirms "unauthorized access to application identities".[2] Huntress counts at least 162 compromised tenants; Microsoft calls it an "active supply-chain attack".[1]

App identity: An account a program uses, instead of a human, to sign in to Microsoft 365, with a secret key instead of a password plus phone code. Like a spare key you give the cleaning service: whoever hijacks the service no longer needs a fingerprint.

Discovered on Oct 15, advisory on Oct 16. ConnectWise shut down seven app identities; per the Oct 18 update, the shared credentials are invalid. According to the vendor, there are no signs that backup data was exfiltrated. Cloud Backup, SaaS Security and Cloud Management were still offline on Oct 18. There is no CVE, and ConnectWise is silent on the attackers' origin.[1][2]

Our view: this is the pattern of the season. Every SaaS service with broad Graph API permissions is a master key to hundreds of tenants. Anyone who manages M365 should look at the list of enterprise apps with write permissions more often than once a year.

Supply chain, twice from the vendor itself

Rank Math PRO: backdoor in the official download

Version 3.0.123 of the WordPress SEO plugin Rank Math PRO shipped with a backdoor from the vendor's server. The window ran from Oct 15, 20:02 UTC to Oct 16, 07:12 UTC, about eleven hours. The command-and-control domain is rank1cdn[.]com. 3.0.124 is clean; the free plugin (over 4 million sites) is not affected. The vendor does not say how the attackers got in or how many sites pulled the update.[1]

AOMEI Backupper: hijacked update servers

According to BleepingComputer, the group UNC7017 modified the update server's configuration files and swapped the checksum at the same time. That way the server delivered a downloader (CROSSROAD) and a backdoor via Radmin (SHINYROAD). The windows were tiny: 10 minutes on May 28, 6 on Jul 16, 5 on Jul 20. Victims were in the USA, Australia, India, Singapore, Spain and Switzerland. ManageEngine disputes AOMEI's version of tampering in transit: "The evidence did not support AOMEI's explanation".[2]

Checksum: A digital fingerprint of a file. The installer compares it to detect tampering. If the forger swaps the fingerprint in the same folder, the check never fires.

Our opinion: both cases show that a checksum served from the same server as the file only protects against transmission errors, not against attackers. Only a signature made with a key that does not sit on the download server protects here.

GitHub also warns about malware in Maven, PyPI and more [1]

GitHub's malware alerts used to apply only to npm. They now cover eight ecosystems (heise look-back of Oct 19; per Help Net Security the alerts have run since summer): crates.io, Go, Maven, NuGet, npm, Composer, PyPI and RubyGems. The data comes from the OpenSSF malware database, which now holds 238,000 reports; at launch in 2023 it had just over 15,000. More than 28,000 reports come from GitHub itself. You have to enable the alerts per repository.[1] OSS

For a Java and Python stack this is a useful look-back: free, one click, and Maven and PyPI are included.

NGINX: three critical flaws, out-of-band patch [1]

On Oct 19, F5 released out-of-band patches for NGINX Plus, NGINX OSS, Ingress Controller, Gateway Fabric and Instance Manager:

  • CVE-2026-15176 in ngx_http_v3_module. Mitigation: avoid alias or $request_filename.
  • CVE-2026-97205, also HTTP/3. Mitigation: disable AIO or SSI.
  • CVE-2026-93479 in the map directive. Mitigation: use named captures.

According to the report, code execution is possible if ASLR is off or bypassed. F5 reports no attacks.[1] We could not verify CVSS scores and fix versions; the F5 advisories (K000162416, K000162608, K000162607) did not load. Caddy users are not affected, but many Kubernetes clusters have an NGINX ingress somewhere.

Drupal: RCE in core, exploit "in hours or days" [1]

CVE-2026-108097 sits in the core module Field UI, CVE-2026-108099 in the contrib module Entity List. Fixed in core 10.6.19, 11.3.19 and 11.4.10 as well as Entity List 3.0.10 (SA-CORE-2026-014, SA-CONTRIB-2026-218). Core alone is not exploitable. With contrib modules, however, there is at least one path without a login. If you cannot patch immediately, uninstall field_ui. There are no attacks yet; the Drupal team warns that exploits could come "within hours or days". The report gives no CVSS score.[1]

The WAF as an entry point: SiteGuard under attack [1]

The WAF SiteGuard Server Edition contains a command injection, CVE-2026-106931. It sits in the statistics feature, which is on by default, and runs commands as root or SYSTEM. Fixed in 8.00 Update 5 (FreeBSD: 7.00 Update 6). The vendor informed customers on Sep 29; according to the report, exploitation is "already confirmed". It is not yet in the KEV catalog.[1] After BeyondTrust last week, another security product that is itself the door.

KEV: Fortinet details filled in, no new entries [1][2]

Update since Oct 17 The KEV catalog stands at version 2026.10.16 with 1,748 entries; nothing has been added since Friday.[1] The deadlines for BeyondTrust and Fortinet expired yesterday.

We lacked the details on Fortinet CVE-2025-61624 on Saturday; heise supplies them. It is a path traversal with CVSS 6.5 (NVD) or 6.0 (Fortinet), and it requires an admin profile with write permissions. Fixed in FortiOS 7.6.5 and 7.4.10, FortiPAM 1.7.1, FortiProxy 7.6.5 and 7.4.12, FortiSwitchManager 7.2.8 and 7.0.7. Unit 42 describes an attack on a telecom provider using the memory-resident malware "Peerstitch". Initial access came as early as 2024 via FortiJump (CVE-2024-47575).[2] So the low score is deceptive: the flaw is one building block in a long chain.

Patches that need patches [1]

A study by the startup Terra Security shows that the share of GitHub security fixes that need a follow-up fix within 90 days rose from about 0.2% (2019–2025) to 2.3% in 2026. CVEs with a bypassed fix land in the KEV catalog about four times as often. In the Linux kernel, 3.2% of CVEs arose from the fix for another CVE; in fs/smb and net/sched about 10%.[1]

A caution on interpretation: it is a single study by a vendor, not independently checked. The direction does fit PwnEscape, though: networking code in the kernel is tough to repair.

Exchange after the October update: cause and workaround [1][2]

Update since Oct 17 The Exchange problems have a cause. The October updates for Windows Server 2019 and newer limit the Endpoint Mapper's memory, by default to 512 concurrent calls. The results are failed OWA logins, stuck outboxes and "MapiExceptionMdbOffline".[1]

Endpoint Mapper: A Windows service that tells programs which port another service is listening on. Like a company's switchboard: when it is overloaded, no call gets through, even if every employee is at their desk.

Microsoft's workaround (then restart; do not uninstall the update):

reg add HKLM\SOFTWARE\Microsoft\Rpc /v EpmapSavedContextCap /t REG_DWORD /d 65536 /f

A fix is in progress.[1] For planning: Server 2016 loses support on January 12, 2027; ESU via Azure Arc is available from January 13, 2027 until 2030.[2]

CRA: the reporting clock has been running since September [1][2]

The Cyber Resilience Act's reporting duties have applied since Sep 11, 2026. For actively exploited vulnerabilities this means: early warning within 24 hours, notification within 72 hours, final report 14 days after the fix. For severe incidents a month applies. The rest of the CRA follows from Dec 11, 2027.[1] EU

Cyber Resilience Act (CRA): An EU law that makes manufacturers of software and connected devices responsible for their security. Like the recall duty for cars: whoever knows about a defect must report and fix it.

Whether ENISA's reporting platform worked from day one is unconfirmed; the sources contradict each other.[2] For the cases above this means: a vendor like Rank Math or AOMEI that sells in the EU now has a legal clock around its neck.

  • M365 tenant? Review enterprise apps with write permissions; cloud backup vendors first.
  • WordPress with Rank Math PRO? Check the version; 3.0.123 means: update to 3.0.124 and investigate the site.

  • Java: Read the Oracle CPU this evening and schedule the JDK updates.

It's Tuesday, October twentieth. The weekend brought two kinds of trouble: a kernel flaw at the boundary between virtual machines and their host, and three separate supply-chain attacks.

The kernel flaw is called PwnEscape. According to heise and The Register, it scores nine point three out of ten. A guest in a KVM machine sends crafted IPv4 packets and can break out of its box. Debian has already shipped fixes; Ubuntu and Red Hat still had none on Sunday. Attacks aren't confirmed, but the researchers expect exploits within a few weeks. If you run your own virtualization hosts, don't wait long.

At ConnectWise Cloud Backup, attackers took over the service's app identity. According to Huntress, that got them into at least one hundred sixty-two Microsoft three sixty-five tenants. Multifactor authentication didn't help, because here a program signs in, not a person. As of Sunday, the services were still offline.

Twice, the malware came straight from the vendor. The WordPress plugin Rank Math PRO was distributed with a backdoor for eleven hours; version three point zero point one two four is clean. And at AOMEI Backupper, hijacked update servers delivered a backdoor in short windows. The good news: GitHub warns about malware in eight package ecosystems, including Maven and PyPI.

F5 patched three critical NGINX flaws out of band, with no known attacks so far. Drupal closed a hole in its core and warns that exploits could arrive in hours or days. And the SiteGuard web firewall is already under attack.

Exchange admins have a workaround. The October updates limit Windows' Endpoint Mapper. Microsoft advises a registry entry and a restart, not uninstalling the update.

On the release front, Linux seven point three is out, likely the next long-term kernel. Oracle's patch day for Java is today, and Node.js security updates follow on Wednesday. PostgreSQL nineteen is at its first release candidate.

In Europe, the Cyber Resilience Act's reporting duties are in force: twenty-four hours for an early warning, seventy-two for the notification. In Germany, the building automation vendor Loxone reports a cyberattack.
