PHP: two critical flaws, fix today at 14:00 UTC [1][2]

The PHP security team has announced a release for today, Oct 21, 14:00 UTC. That is 11:00 a.m. in Ribeirão Claro and 4:00 p.m. in Germany. It fixes two critical flaws, both rated CVSS v4.0 9.2 according to php.net.[1] PHP reserves the right to release earlier if details leak or attacks appear. The team will name affected and fixed versions only with the release.[1]

The finders say more. According to BleepingComputer, watchTowr names the identifiers CVE-2026-109618 and CVE-2026-109619, rates both CVSS 10 and considers PHP 5, 6, 7 and 8 affected. watchTowr has not seen attacks in the wild.[2] The two scores contradict each other, and the version list so far is only the researchers' assessment, not a vendor statement.

CVSS v4.0: A scale from 0 to 10 that says how bad a flaw is. Version 4.0 calculates slightly differently than the old 3.1, which is why two people sometimes end up at 9.2 and 10 for the same flaw. Like two referees who both show "red" but write a different reason on the sheet.

The last regular security state is from Sep 24: 8.5.11, 8.4.26, 8.3.35 and 8.2.34.[1] If watchTowr is right about PHP 5 through 7, old versions stay without a fix, because those branches no longer get updates.

Context Two flaws in the runtime itself, not in a framework: that hits every WordPress, every Laravel, every shared host. Our view: this afternoon is no reason to panic, but a good reason to have the pipeline ready. Rebuild container images with a pinned PHP version today, as soon as the official image is out. Anyone still running PHP 7 now has the argument for migration they always wanted.

eMudhra: eight intermediate certificates, one key is called "4" [1][2][3]

The Indian certificate authority eMudhra has revoked eight intermediate certificates. All eight used P-384 keys from April 2025 whose values were smaller than 256.[1] heise puts it bluntly: "One of the private keys was simply '4'."[2] According to heise, nothing was stolen; the keys were simply generated insecurely.

Intermediate certificate: A CA does not sign website certificates directly with its root key, but with an intermediate key. Browsers trust everything this intermediate key signs. Like a master key from the janitor: if the combination code is "4", anyone can open a lock in the building.

The response was quick. Mozilla blocked the certificates on Oct 17 via OneCRL, Chrome blocked the six TLS-capable ones among them the same day, and Apple followed on Oct 19. On Oct 20 came Firefox 158.0.1 plus ESR updates.[1] According to heise, Mozilla has removed eMudhra's roots.[2] Go has released 1.27.3 and 1.26.10, identifier CVE-2026-111943; Python's certifi is clean from 2026.10.19.[1]

According to BleepingComputer, Debian ca-certificates, FreeBSD ca_root_nss, Node.js and Bun are still open. The built-in /usr/bin/curl on macOS may continue to trust the certificates.[1] For end users, heise rates the risk as low: an attacker also needs control over DNS or IP routing.[2]

Our view This is not a hack, it is a failure of a CA's basic craft, and that is exactly why the roots are being thrown out. For Daniel's stack the server side counts: build Go services on 1.27.3, bump certifi in Python projects. Node.js ships its own CA store; whether today's release touches it is open.

OVHcloud CLI: backdoor in the official release [1]

Attackers hijacked a GitHub account and distributed tampered releases through the official repository of the OVHcloud CLI. v0.11.0 through v0.15.0 are affected; 0.10.0 and 0.16.0 are clean. The malicious release appeared on Oct 19 at 14:47 and was blocked by 16:21 (the source states no time zone). Release immutability was turned off in the repo.[1] OVHcloud writes: "If you are affected, please change all the secrets on your disk."[1] EU

Release immutability: A GitHub setting that freezes a release once published. After that, nobody can swap the files in it, not even with a hijacked account. Like a sealed envelope: whoever opens it leaves traces.

Our view: the time window was short, but the consequence is broad, because a cloud CLI has access to everything. Anyone who installed or updated the CLI in that window rotates not just the OVH tokens but everything in ~/.config, ~/.ssh and in .env files. And anyone who distributes binaries via GitHub Releases themselves: turning on immutability takes a minute.

PAN-OS: ransomware groups have been knocking since June [1][2]

According to Unit 42, via The Register, several ransomware groups have been attacking Palo Alto's firewall operating system PAN-OS since June.[1] According to The Register, the flaw is CVE-2026-0257, a GlobalProtect authentication bypass that Palo Alto patched on May 13.[1] So what is new is not the flaw but the duration: anyone who patched GlobalProtect only after mid-May should look for traces from May onward, not just tick off the patch.

KEV: Plex four times over, plus Siemens and SiteGuard [1][2][3]

On Oct 20, CISA added six flaws to the catalog of actively exploited vulnerabilities:[1]

  • Plex Media Server: CVE-2026-96652, -96654, -96655, -96656. The deadline for -96654 and -96656 is Oct 23, for the others Nov 3. CVE-2026-96652 is an SSRF via /player/timeline in versions before 1.43.3.10861.[2] Whether an attacker needs a Plex token for this is disputed: the NVD says yes, one report describes a chain without authentication. We will not resolve that today.
  • Siemens Software Center: CVE-2026-110936, deadline Nov 3.
  • SiteGuard Server Edition: CVE-2026-106931, deadline Oct 23. The command injection in this WAF was already covered here yesterday.

From the previous week: BeyondTrust Remote Support (CVE-2026-102764, CVSS 4.0 9.3, affected up to 26.2.3) and Fortinet (CVE-2025-61624, path traversal, CVSS 6.5 per NVD) ran with a deadline of Oct 19.[1][3] Fortinet is interesting despite the medium score: according to heise, Unit 42 links it to the in-memory malware "Peerstitch".[3] Plex sounds like a living room, but often runs on the same home server as everything else. Anyone exposing Plex to the internet updates today.

Google Cloud London: one power outage, many banks [1][2]

On Oct 20, one of three zones in Google's London region europe-west2 went down, europe-west2-b. The outage began at 06:08 UTC. Google gives "A power event" as the cause.[1] Cloud Run, GKE, App Engine, Filestore and Managed Kafka were among the services affected. By 14:03 UTC it was running again for most customers, according to Google. In the UK, Lloyds, HSBC, Royal Mail, Revolut, BT and DPD had hiccups.[1][2] EU

Availability Zone: A separate data center within a cloud region, with its own power and its own cooling. A region usually has three of them. Like three checkouts in a supermarket: if one fails, the others should keep running.

Our view: one zone of three fails, and banks still stand still. That means many workloads ran in only one zone, although multi-zone should be the standard. Anyone running GKE or Cloud Run services checks today whether they are really spread regionally or only called that.

curl: minor flaws to go public [1]

From Oct 26, reports of low and medium severity are to go straight to curl's public GitHub repository. High and Critical stay private via HackerOne. Daniel Stenberg justifies this with an "avalanche of vulnerability reports" and writes: "We must act to survive."[1] According to Stenberg, over 90 percent of reports in recent years were quickly recognizable as below HIGH. curl had already ended its bug bounty earlier this year because of AI-generated submissions.[1] OSS

Our view: the right call. The downside is real, attackers see small bugs earlier. But a project suffocating on triage fixes nothing at all anymore. This is the honest answer to the flood of reports, and other small OSS projects will follow.

It's Wednesday, October twenty-first. Today is a patch day with advance notice. PHP and Node.js are shipping security updates, and a certificate authority in India delivers the punchline of the week.

First, PHP. The security team is releasing fixes today at 2 p.m. UTC for two critical flaws. That's 11 a.m. for us in Ribeirão Claro. PHP rates both at nine point two out of ten, while the finders at watchTowr say ten and consider PHP five through eight affected. There are no attacks yet. PHP will name affected versions only with the release.

Then eMudhra. The certificate authority generated eight intermediate certificates with keys that can be guessed. According to heise, one of the private keys was simply the number four. Firefox, Chrome and Apple are blocking the certificates, Mozilla is removing the roots, and Go has new versions. Debian, Node.js and Bun were still open as of Oct 20.

Node.js is releasing new versions of the twenty-six, twenty-four and twenty-two lines today. The most severe flaw is rated high. If you build Node containers, plan a rebuild for tonight.

Supply chain, once again. Through a hijacked GitHub account, tampered versions of the OVHcloud command line tool, zero point eleven through zero point fifteen, got out. If you're affected, OVHcloud says to replace all secrets on your disk.

On the attack front: several ransomware groups have been targeting Palo Alto firewalls since June, The Register reports. The US agency CISA has flagged four flaws in Plex Media Server, one in Siemens, and one in the SiteGuard web firewall as actively exploited.

In infrastructure, one zone of Google's London region went down yesterday because of a power problem. Banks like Lloyds and HSBC had disruptions. It shows how many services run in only one zone. And curl will handle minor flaws in public on GitHub starting Monday, because the flood of reports is overwhelming the team.
