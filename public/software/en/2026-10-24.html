PHP, part three: a flaw with no patch, but a narrow attack surface [1][2]

Since yesterday On Friday, Oct 23, the PHP team reported CVE-2026-115560, a flaw around session upload progress. According to BleepingComputer there is no patch yet; PHP plans to close the flaw in the normal release cycle and publish a full advisory with the next release.[1] The article reports no exploitation and no CVSS score.

Only a rare combination is affected. An app sets session.serialize_handler in its configuration to php_binary or php_serialize and switches it to php at runtime via ini_set() before calling session_start(). Upload progress must also be enabled.[1] If you never change the handler at runtime, you are not affected.

Session serializer: The format in which PHP writes a session's data to disk and reads it back. Writing in one format and reading in another is like a letter in German that someone reads as the code to a safe. That can produce nonsense that an attacker controls.

The mitigation is the same setting php.net already recommended for PHP2Shell: session.upload_progress.enabled=0. If you already set it this week, leave it in place.[1][2]

Our take After a week of emergency patches, this is a good sign, not a bad one. People are now looking closely at the session code, and PHP is communicating openly instead of quietly. For most frameworks this is a grep for serialize_handler, nothing more.

PHP2Shell: where things stand on Saturday [1][2][3]

The two main flaws CVE-2026-109618 and CVE-2026-109619 affect, according to BleepingComputer, "all PHP installations that serve web requests, including PHP-FPM, Apache with mod_php, php-cgi, FrankenPHP, and LiteSpeed".[1] Fixes have been available since Oct 21 in 8.5.12, 8.4.27, 8.3.36 and 8.2.35; per php.net the update is the only complete mitigation.[2] According to a VirusTotal estimate cited by BleepingComputer, more than 5.1 million PHP hosts are reachable.[1]

On Oct 22, heise published an overview, "Who has to do what now": all PHP versions of the last 20 years are at risk, and updates are the only effective protection.[3] Don't forget: PHP 8.2 receives security fixes only until Dec 31, 2026.[2]

KEV: Collabora Online and Arista VeloCloud, deadline Monday [1][2]

On Oct 23, CISA added two actively exploited flaws to the KEV catalog. Both have the deadline Oct 26, just three days away:[1]

  • CVE-2026-110447, Collabora Online, listed in the catalog as "Built-in CODE Server". We found no technical details.
  • CVE-2026-114625, Arista VeloCloud Orchestrator. On Oct 22, BleepingComputer reported that Arista patched an actively exploited zero-day in on-prem installations.[2] We could not read the article itself; we therefore do not name fix versions.
KEV catalog: The US cyber agency CISA's list of flaws that are demonstrably being attacked. US federal agencies must patch by the deadline. For everyone else the list is a good filter: what is on it is not a theoretical risk.
Heads up The short deadline on Collabora is the point. Many self-hosted Nextcloud instances use Collabora for office documents. We have not confirmed whether the built-in variant there is exactly the affected product. If you run such a setup, check your package's update on Monday.

HPE ArubaOS: 72 flaws, eight at the maximum level [1]

On Oct 23, HPE released fixes for 72 flaws in ArubaOS, the operating system for Aruba controllers, access points and gateways. Eight of them are at the highest level: authentication bypass, command injection, SQL injection and buffer overflows, each with code execution, spread across AOS-8 and AOS-10 (CVE-2026-79844 through -79851).[1]

Exploitation is not known. HPE writes: "HPE Networking is not aware of any public discussion or exploit code that targets the listed vulnerabilities". As a stopgap, HPE advises restricting the CLI and web interface to a dedicated VLAN or shielding them with a firewall.[1] The article names no specific fix versions; those are in the HPE advisory.

Our take Eight unauthenticated paths to code execution in a Wi-Fi controller are an invitation. There is no exploit yet. In our experience that changes quickly with network hardware once someone diffs the patches.

Supply chain I: the orphaned update domain [1]

Time4Popcorn, a fork of the BitTorrent client Popcorn Time, fetched updates over unencrypted HTTP from an abandoned domain. According to BleepingComputer it "accepted executables without verifying digital signatures". Whoever owned the domain could run code with SYSTEM rights on Windows and root on macOS (CVE-2026-30612).[1]

Eye Security registered the domain and saw "up to 3 million Windows and 350,000 macOS client connections". Between November 2025 and March 2026, the team pushed code through the updater that stops and disables the updater. The domain now belongs to the Shadowserver Foundation. According to the article, Android users remain exposed.[1]

Orphaned domain: A web address that the previous owner did not renew. Anyone can buy it again. If old software still asks there for updates, it is like a mailbox that the new tenant empties, and the mail is programs.
Our take This is the cheapest supply-chain attack there is: a few dollars for a domain. For your own projects that means: sign update channels and don't let domains lapse, not even the one from the old marketing microsite.
[1] bleepingcomputer.com (Oct 23)

Supply chain II: GitHub Package Firewall for npm [1][2]

GitHub released the Package Firewall as a public preview; the changelog entry is dated Oct 20.[1] According to iX it is meant for Enterprise Cloud customers and checks package requests and downloads in order to block malicious npm packages.[2] We did not look up exactly how it decides what is malicious.

This fits Cargo's new option to reject packages that are too fresh (here yesterday). The trend is clear: registries and platforms are building barriers in front of npm install because lockfiles alone are not enough.

Supply chain III: LiteLLM and the lesson about tokens [1][2]

A quick status: according to Datadog, the poisoned version LiteLLM 1.107.0 sat on PyPI and in the official Docker images for about two hours on Oct 21. The credential stealer started via a .pth hook. It is the second LiteLLM incident of 2026.[1] How the attackers got in is disputed: stolen GitHub CLI OAuth tokens or Trivy in CI.[1] Details on the AI side are in the ai-dev brief.

Fittingly, since Oct 21 the GitHub CLI can optionally use expiring, self-renewing OAuth tokens.[2] A token that expires after hours is worth much less to a thief than one that is valid for years. It is a setting you turn on this week.

.pth hook: At startup, Python reads every .pth file in the package folder and executes lines in it. A package can thus start code without anyone ever importing it. Like a note in the mailbox that the janitor reads aloud automatically every morning.

Oracle CPU: many patches, shaky Java details [1][2]

On Oct 20, Oracle published the Critical Patch Update for October: according to endoflife.ai 1,295 new patches, 55 of them for Java SE.[1] The Oracle page itself returned a 403 for us, so the numbers are secondhand.

Japan's IPA lists 8u503, 11.0.32.1, 17.0.20.1, 21.0.12.1, 25.0.4.1 and also 26.0.2 as affected versions, not fixed ones.[2] That agrees with endoflife.ai: "JDK 26 got no fix."[1] Oracle's pre-release notice gave 1,283 patches; the 1,295 figure comes from endoflife.ai. According to endoflife.ai, JDK 17 has been in Oracle's Extended Support since September; the next CPU arrives on Jan 19, 2027.[1]

Heads up If you use Temurin, Corretto or another OpenJDK build, wait for your vendor's builds. The Oracle numbers apply only to Oracle JDK. For Spring projects the path is simple: bump the base image as soon as it is available.

Certificates: GoDaddy revokes 404,607 of them [1]

According to heise from Oct 22, GoDaddy must revoke 404,607 certificates because they do not conform to its own documentation.[1] That is a formal error, not a key leak like with eMudhra. Still: a revoked certificate breaks HTTPS just the same. If you install GoDaddy certificates by hand, check GoDaddy's emails. With ACME and automatic renewal this is a non-issue.

Chrome now warns about HTTP by default [1]

According to heise from Oct 22, Chrome warns before the first visit to unencrypted websites, and Google has turned this on by default for all users.[1] For public sites that is no longer an issue. It gets interesting with internal tools: admin interfaces on the LAN, routers, test servers on http://. Caddy with automatic HTTPS or Tailscale certificates solve this quickly.

Quad9 leaves France [1]

According to heise, the DNS service Quad9 is withdrawing from France. The reason is a blocking ruling won by the Qatari broadcaster beIN.[1]

Our take Sports rights holders force the infrastructure layer to block, and the resolver prefers to leave rather than become a censor. For Europe that is a bad signal. If you have Quad9 set in a router or Pi-hole, watch for fallback resolvers in France.

CRA: the first real reporting week [1]

Since Sep 11, 2026, the Cyber Resilience Act's reporting obligation applies: manufacturers report actively exploited flaws via ENISA's platform, with an early warning within 24 hours and a report within 72 hours. The rest of the CRA applies from Dec 11, 2027.[1]

This week was full of exploited flaws: PHP, Plex, Arista, Collabora. Every manufacturer that sells such a product in the EU had to run the clock.

Our take The obligation hits manufacturers, not volunteer OSS projects like PHP itself. But anyone who packs PHP into a commercial product is now a manufacturer with a reporting duty. It will be interesting to see whether ENISA publishes figures after this week.

The rest can wait until Monday.

It's Saturday, October twenty-fourth. After PHP2Shell week, there's no quiet weekend. PHP has reported another flaw, HPE is closing seventy-two flaws in ArubaOS, and on Monday two deadlines from the US agency CISA run out.

First, PHP. The new flaw doesn't have a patch yet. But it only hits applications that switch the session serializer at runtime. The workaround is known: turn off upload progress for sessions. For the big PHP2Shell flaws, the same advice holds: only updating to the October twenty-first versions really helps.

CISA has added Collabora Online and the Arista VeloCloud Orchestrator to its catalog of actively exploited flaws. The deadline is already Monday. If you run Collabora yourself, say with Nextcloud, check for an update before then.

At HPE, eight of the seventy-two ArubaOS flaws are at the highest severity. No attacks are known yet. Until you update, the management interfaces should go on their own network.

The theme of the week remains the supply chain. An old Popcorn Time variant pulled updates from an abandoned domain, with no signature check. Researchers bought it and shut down the updater on millions of computers. GitHub is testing a firewall against malicious npm packages. And the GitHub CLI can now use tokens that expire on their own. After the LiteLLM incident, that's a good idea.

Oracle has released its quarterly update with one thousand two hundred ninety-five patches. Exactly which Java versions are fixed hasn't been cleanly sorted out yet.

Also: GoDaddy is revoking roughly four hundred thousand certificates over formatting errors, Chrome now warns about unencrypted sites by default, and the DNS service Quad9 is leaving France after a blocking ruling.

Have a great weekend. On Monday we'll see whether the KEV deadlines hold and whether PHP names a date for the next patch.
