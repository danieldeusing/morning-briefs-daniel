BlackX: a bootkit that simply skips the 2022 patch [1]

New since Saturday On Oct 24, BleepingComputer reports on BlackX, a UEFI bootkit that bypasses Secure Boot. It exploits Baton Drop (CVE-2022-21894), a flaw Microsoft already patched in 2022. The catch: the patch does not automatically revoke the old, vulnerable boot managers. According to the article, all BlackX victims Kaspersky has seen were running fully patched Windows, just without revocations enabled.[1]

According to the article, BlackX has been known since early 2026. Its predecessor BlackLotus has used the same technique since October 2022. There is also a dated detail: the "Windows Production PCA 2011" certificate expired on Oct 19, 2026.[1] The article gives no CVSS score.

Bootkit and revocation: Secure Boot checks at startup whether the boot code has a valid signature. But an old, flawed boot manager also has a valid signature. The update fixes the new code but does not automatically put the old one on the blocklist. It is like a new lock on the door while the old key still fits until you explicitly block it.
Heads up If you manage Windows servers or dev machines, check that the Secure Boot revocations from Microsoft's guidance are actually applied. This is a deliberate step with a risk: old boot media will no longer start afterward. That is why it never happened on many machines.
Our take This is the story of the week in miniature. "Patched" is a status on a dashboard, not a security state. With firmware that is doubly true, because the last step is manual and can hurt.

PHP2Shell: the week in review [1][2][3][4][5]

The two flaws CVE-2026-109618 and CVE-2026-109619 allow code execution without login. Since Oct 21 they are fixed in 8.5.12, 8.4.27, 8.3.36 and 8.2.35; the release candidate 8.6.0 RC4 also contains the fixes.[1] The PHP security team rates both at 9.2 under CVSS v4.0 (php.net, Oct 20); the NVD has no entry for them yet.[2]

What made the week so unpleasant: according to Amazon, the first exploitation attempts began on Saturday, Oct 17, four days before the patch.[3] In the UK, tech minister Baroness Lloyd told the House of Lords on Oct 22 that 32 government services were unavailable and 4 partly unavailable. This was largely due to precautionary measures; she is not aware of any confirmed compromise of central government systems.[4]

For Germany, heise reports on Oct 23, citing Censys scans, millions of vulnerable PHP services.[5] According to heise, the remedy stays the same: install updates, nothing else really helps.[5]

Our take A four-day head start for attackers means: even if you patched right away on Oct 21, you should still look at the logs. A patch closes the door, but it does not throw out anyone who is already inside. This applies especially to shared hosting and old client projects nobody has on their radar anymore.

PHP CVE-2026-115560: not an emergency, but a setting [1][2]

On Oct 23, php.net reported a follow-up flaw involving session upload progress. PHP writes: "We suggest you set session.upload_progress.enabled=0 until the next regular bugfix release, to fully protect from an unlikely RCE vector." A full advisory is due with the next regular release.[1]

The Register confirmed on Oct 23: PHP has reserved the identifier CVE-2026-115560 for this third RCE flaw, and there will be no emergency patch.[2] Only setups with session upload progress enabled are affected.

GitLab: code execution without login, twelve years of releases [1][2][3]

On Oct 21, GitLab closed CVE-2026-110264; GitLab itself rates the flaw CVSS 10.0, the highest level.[3] According to BleepingComputer, an integer overflow in the regex compiler allowed "an unauthenticated user" to execute arbitrary code on the server. Fixes are available for CE and EE in 19.5.1, 19.4.3, 19.3.6, 19.2.9, 19.1.9, 19.0.10 and 18.11.13; GitLab.com is already patched.[1]

Shadowserver counts more than 2,700 openly reachable CE instances.[1] The Register writes of "12 years of releases", while heise reports twelve flaws fixed in total in the same update.[2] No exploitation has been reported.

Integer overflow: A number grows larger than its storage space can hold and then wraps around to a small value, like an odometer after 999,999. If code then calculates with the wrong size, it writes past the edge of a buffer.
Our take Self-hosted GitLab is where source code, CI secrets and deploy keys all sit together. An unauthenticated RCE there is worse than on almost any other internal service. If your instance is not behind a VPN or Tailscale, do that after the update.
[1] bleepingcomputer.com (Oct 22) · [2] theregister.com / heise.de (Oct 22) · [3] docs.gitlab.com (Oct 21)

Node.js: ten CVEs, one of them in the Brotli decoder [1]

The security release of Oct 21 closes ten flaws: four high, three medium, three low. Fixed in 22.23.4, 24.22.1 (current LTS) and 26.12.1 (current release). According to Node.js, EOL versions are always affected and get nothing.[1]

The four high ones: truncation at a NUL byte in dns.resolve (CVE-2026-105482), two bypasses of the TLS certificate check tls.checkServerIdentity() via oddly written IP addresses (CVE-2026-105483 with full-width digits, 26.x and 24.x only; CVE-2026-106069 with leading zeros read as octal, such as 0127.0.0.1), and an out-of-bounds write in the Brotli decoder (CVE-2026-111497). According to Node.js, the latter can lead to a crash, disclosure of process memory or code execution.[1]

Heads up The two TLS flaws hit clients that connect to a server by IP address instead of hostname: a certificate issued for a different address can then still be accepted. If your Node code talks to internal services over IP and TLS, upgrade and check that the target addresses are written cleanly.
[1] nodejs.org (Oct 21)

ConnectWise breach: attacks on 2,250 cloud tenants [1]

According to Microsoft, the China-linked espionage group Storm-0940 targeted more than 2,250 Microsoft 365 tenants. The route: stolen ConnectWise application credentials and the permissions customers had granted to ConnectWise cloud services. Most attempts failed, but some attackers gained persistent privileged access. Microsoft has not said how many customers were compromised.[1]

Our take Managed-service tools are master keys. If you give a service provider admin access to your own tenant, you should know which app registrations and partner relationships are in place there. A look at the Entra ID partner list takes five minutes.
[1] theregister.com (Oct 22)

Certificates: eMudhra exits [1]

The Indian CA eMudhra is leaving the global SSL/TLS business after its weak private keys came to light. According to The Register, revocation and status services keep running until every issued certificate has expired or been replaced, and eMudhra says it will move customers to other issuers free of charge.[1] If you use certificates from this CA, you need a new issuer.

[1] theregister.com (Oct 22)

Signal: microphone stays on after hangup [1]

The flaw CVE-2026-113380 (CVSS 9.3) sits in Signal's RingRTC calling library before version 2.72.0 and can keep the mic and camera on after hangup. The fix has been available since September 2026; no exploitation is known.[1] The update via the app store is usually enough.

The rest waits until Monday.

It's Sunday, October twenty-fifth. Things have been quiet since Friday, so today is mostly a look back at a rough week. There's one new story, and it's an unpleasant one.

The bootkit BlackX gets around Secure Boot on fully patched Windows machines. It exploits a twenty twenty-two flaw called Baton Drop. The patch for it doesn't automatically block the old boot managers. According to BleepingComputer, every victim Kaspersky has seen had the patch, but not the revocation. If you manage Windows machines, you should check that step.

On PHP2Shell: the updates from October twenty-first remain the only real fix. According to Amazon, attacks began four days before the patch. So even if you updated early, take a look at your logs. heise reports millions of vulnerable PHP services in Germany. For another, smaller flaw, PHP recommends turning off session upload progress until the next regular release.

GitLab has closed a top-severity flaw. Attackers could run code on the server without logging in. Shadowserver counts more than twenty-seven hundred openly reachable instances. Node.js fixed ten flaws, including a bug in the Brotli decoder and two ways to bypass the TLS certificate check.

On Monday, two deadlines from the U.S. agency CISA run out, for Collabora Online and the Arista VeloCloud Orchestrator. For Plex, there's time until November third.

Also: according to Microsoft, Chinese spies used stolen ConnectWise credentials to target more than twenty-two hundred fifty Microsoft 365 tenants. Most attempts failed, but not all. The curl project now accepts only serious reports through HackerOne. Chrome now warns about unencrypted sites by default. And Windows Server twenty sixteen stops getting updates after January twelfth.
