Fragnesia: the kernel bug that turns PHP2Shell into root

New since yesterday On Oct 28, CISA added CVE-2026-46300 to the KEV catalog. The deadline for US federal agencies is unusually short: Oct 31, three days. According to the KEV entry, an uninitialized variable in the kernel can let data in the page cache be modified without permission. The key sentence is in the description: the bug can be chained with CVE-2026-109618 and -109619 (PHP2Shell) to drop PHP web shells and run commands as root.[1]

The bug itself is not new. Rapid7 lists an exploit module and describes it as a local privilege escalation in the IPsec path “ESP-in-TCP,” present since kernel 4.10 and public since May 14, 2026. An unprivileged attacker can use it to overwrite bytes of a read-only file.[2] The distributions have backported the fix individually; the KEV entry points to eight stable-kernel commits.[1] We did not find a CVSS score on the pages we read.

Page cache: The kernel keeps files that are read often as a copy in memory. Programs then read the copy, not the disk. Like a notice on a bulletin board: if someone secretly changes the notice, they change what everyone reads, even though the original in the binder stays untouched.
Chaining (exploit chain): One flaw gets the attacker in, the second makes them the boss. PHP2Shell gives code execution as the web server user, Fragnesia lifts that to root. Like a thief who first climbs in through an open window and then finds the master key in the hallway.
Our take This is the most important item of the day because it changes the cleanup work. Until now, PHP2Shell meant: web server user compromised, check files, patch PHP. With root in play, that is no longer enough. On a host that was exposed before the PHP patch, you have to treat the whole machine as suspect. And because Fragnesia is local, even patched PHP does not protect you from the next flaw that gets a foot in the door. Kernel update and reboot belong on the same list this week.

PHP2Shell: deadline today, and a third flaw still open

The KEV deadline for the two PHP2Shell flaws ends today, Oct 29. CISA added them on Oct 26.[1] The fixes are in 8.5.12 and 8.4.27, per php.net, released Oct 21, as well as in 8.3.36 and 8.2.35.[2] Branches from 8.1 downward get no official release; PHP only published source backports, and some distributions ship patched packages.[3]

BleepingComputer also reports a separate, still unpatched RCE: CVE-2026-115560. As a mitigation, the report names session.upload_progress.enabled=0 in php.ini.[3] We did not find a vendor fix for it. If you do not need upload progress (most people do not), turn it off.

Heads up A heise webinar with Sebastian Bergmann on Nov 6 (9:30 a.m.–noon CET) is devoted to exactly this question: how to secure legacy PHP and move it to a maintained version.[4] The topic is bigger than one patch: anyone on 8.1 or older will have this problem every week from now on.

VMware ESX: a “low” flaw in the KEV

The second KEV entry of Oct 28 is CVE-2026-41709 in Broadcom VMware ESX, deadline Nov 11. CISA describes a logging weakness: an attacker with admin rights can perform certain operations without them being logged. The entry points to Broadcom’s advisory 38017. Ransomware link: “Unknown.”[1] According to search results, Broadcom itself rates the bug as low (CVSS 2.7, advisory of Jul 29); we did not read that page directly.[2]

Our take A low score in the KEV looks paradoxical, but it is not. The flaw does not break in; it blurs tracks after someone is already admin. For attackers on hypervisors, that is exactly what is valuable. Lesson: the CVSS score says how bad a bug is on its own. The KEV entry says someone is actually using it.
[1] cisa.gov KEV (Oct 28) · [2] support.broadcom.com (Jul 29)

Tailscale: “Tailworm” in SSH and Serve

On Oct 26, Tailscale published four security bulletins, TS-2026-014 to -017. All are fixed in 1.104.4.[1] heise groups the series under the name “Tailworm” on Oct 28.[2] The details:

  • TS-2026-014: Unix socket forwarding in Tailscale SSH ran as root and checked paths only as text. Peers could reach sockets that are open to root only. Workaround: set TS_SSH_DISABLE_FORWARDING=1 and restart the service.[1]
  • TS-2026-015: A logged-in SSH session could make the memory of tailscaled grow without limit, until it crashed.[1]
  • TS-2026-016: tailscale serve with Unix backends could reach privileged sockets, including the local API of tailscaled.[1]
  • TS-2026-017: With HTTP/2 and several Serve mounts, capability values from one mount could end up on another.[1]

The good news: for the SSH flaws, an attacker must already control a device in the tailnet that the policy allows to use SSH.[2] Neither the bulletins nor heise give CVE numbers or scores.

Unix socket: A kind of phone line between programs on the same machine that looks like a file. Whoever reaches the line can talk to the service behind it. If a root service sits behind it, it is like an intercom straight into the boss’s office.
Our take For a private tailnet with a few devices this is not an emergency, but it is a clear reason to update. If you allow Tailscale SSH with forwarding, check the ACLs: does every node really need forwarding? Usually not.

eMudhra: the Mac browser is clean, the command line is not

After the leak of the eMudhra intermediate certificates, Safari, Chrome and Firefox have cleaned their trust lists. On macOS, however, this does not apply to /etc/ssl/cert.pem. The Xcode Command Line Tools, curl, git, python3, ruby, perl and openssl use this file. Apple plans to adjust the file “with a later software update”; macOS 27.2 shipped without this fix.[1]

Apple has published instructions in English: check whether cert.pem still contains “emSign ECC Root CA - G3” or “AAA Certificate Services,” back up the file, remove the entries, check again. Developer Dennis Jackson warns that macOS updates can reset manual changes to cert.pem.[1] Tools with their own certificate store, such as Python from Homebrew, need their own update. For the same case, Tailscale already shipped version 1.104.2 on Oct 21; according to Tailscale, WireGuard traffic between nodes was not affected.[2]

Intermediate certificate: A body that a root CA allows to issue IDs for websites in its name. If its private key is stolen, the thief can print valid-looking IDs for any domain. Like a stolen stamp from the town hall.

Brotli: exploited, and the fix list keeps growing

CVE-2026-111497 (“Broccoli2Shell”) has been in the KEV since Oct 27, deadline Nov 10.[1] On Oct 28, heise writes that CISA reports attacks but gives no details on type or scale. heise cites 9.2 on CVSS 4.0. The Brotli libraries 1.0.3 to 1.2.0 are affected; fixed in 1.0.10, 1.1.1 and 1.2.1. heise advises treating affected systems as compromised.[2]

Important for polyglot stacks: according to Wiz, the bug does not affect only Node.js (fixes in 22.23.4, 24.22.1, 26.12.1). There are also fixes for the Python package Brotli (1.2.1), the Go implementation andybalholm/brotli (v1.2.7) and Bun (1.4.4).[3] Node.js 20 and older are EOL and get no fix.

Our take Brotli is a lesson in transitive dependencies. Hardly anyone installed “brotli” on purpose, but almost every HTTP stack uses it to unpack responses. An npm ls, pip show brotli and go list -m all | grep brotli show in a minute where it lives.

Veeam: backup server reachable without authentication

On Oct 28, Veeam released updates for Backup & Replication, the Linux agent and Veeam ONE. The most critical flaw, CVE-2026-108142, allows unauthenticated access to the CDP service of the backup server; attackers could use it to disrupt backup schedules. There are also two path traversal bugs (medium) and a privilege escalation in the Linux agent (high). In Veeam ONE, an admin can switch off MFA (high). Fixes: B&R 13.1.2.57 or 13.0.3.63, Linux agent 13.1.2.11, ONE 13.1.0.7940. According to the vendor, there are no attacks yet.[1]

Our take Backup servers are the favorite target of ransomware groups because they prevent recovery. This is (still) not a KEV case, but one you do not leave sitting until Patch Tuesday.
[1] heise.de (Oct 28)

Ghostty 1.4.0: faster, leaner, with an SSH wrapper

After seven months, Ghostty 1.4.0 is here. The new command ghostty +ssh copies the matching terminfo file to the target machine and falls back to xterm-256color on errors. That ends the annoyance of broken keys and colors on foreign servers. Idle scrollback is compressed, with 70 to 90% less memory for text-heavy output, according to heise. The parser handles plain ASCII at 725 instead of 128 MB/s. Add the full Kitty graphics protocol and ten fixed security flaws. A native Windows UI has been struck from the roadmap.[1]

CRA: every KEV entry is now also a reporting case

Since Sept 11, 2026, the reporting obligations of the Cyber Resilience Act apply. Manufacturers report actively exploited flaws in their products through ENISA’s Single Reporting Platform: early warning within 24 hours, notification within 72 hours, final report 14 days after the fix. The rest of the law applies from Dec 11, 2027.[1] This week shows what that means: Brotli, PHP, Magento, the Linux kernel, ESX. If you ship any of these in a product for the EU market and learn of exploitation, you have a reporting case.

Cyber Resilience Act (CRA): EU law that makes manufacturers of software and connected devices responsible for their security. Like a carmaker’s duty to report a brake recall, only for code.

What Thursday is worth

Three things for today. First: the kernel goes on the list next to PHP, even on hosts without PHP, because Fragnesia only needs some local foot in the door. Second: raise Tailscale to 1.104.4 and check the SSH forwarding rules. Third, on the Mac: check cert.pem against Apple’s instructions, and again after every macOS update. The rest of this week is routine, and that is a good thing.

It’s Thursday, October twenty-ninth. This is still a patch week, but today brings a new twist: the PHP flaws known as PHP2Shell now lead all the way to root.

The federal agency CISA yesterday added a Linux kernel bug nicknamed Fragnesia to its catalog of exploited vulnerabilities. According to CISA, attackers chain it with PHP2Shell to plant web shells and run commands as root. The bug has been in the code since kernel four point ten and has been public since May. So if you’ve already patched PHP, you should update the kernel and reboot, too.

For PHP2Shell itself, the deadline for US federal agencies runs out today. The fixes are in PHP eight point five point twelve and eight point four point twenty-seven, as well as in the older maintained branches. BleepingComputer also reports a third flaw with no patch. The report’s suggested workaround is to turn off upload progress in the PHP configuration.

The second new catalog entry is for VMware ESX. It’s a logging weakness: an admin can do things without them showing up in the logs. The severity is low, but for attackers trying to cover their tracks, that’s exactly what’s useful.

Tailscale has published four security notices on Tailscale SSH and Serve, all fixed in version one point one hundred four point four. The most serious one allowed access, through socket forwarding, to services open only to root. An attacker would need an authorized device on the tailnet first, though.

On the Mac, the eMudhra certificate problem is only half solved. The browsers are clean, but the file used by curl, git and python three still contains the affected entries. Apple has published instructions for removing them. According to heise, macOS updates can undo that change.

On Brotli, CISA now reports attacks. There are fixes not just for Node.js but, according to Wiz, for the Python package, the Go library and Bun as well. On Magento, Sansec describes a group that has taken over at least nine hundred fifty-three shops since July of twenty twenty-five. And Veeam has closed a critical hole in its backup server, with no known attacks so far.

Two friendlier items: the Ghostty terminal has reached version one point four, with an SSH wrapper and a much faster parser. And according to GitHub’s Octoverse report, TypeScript and Python are neck and neck at about thirteen million contributors a month. Germany ranks eighth.

Tomorrow we’ll see whether the distributions add more kernel guidance on Fragnesia, and whether the third PHP flaw gets an official patch.
