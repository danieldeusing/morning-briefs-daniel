GitLab: A regex in the CI file is enough for code execution

New since yesterday On Oct 29, CISA added CVE-2026-97229 to the KEV catalog, deadline Nov 1. According to the KEV entry, an integer overflow lets an unauthenticated attacker execute code, using a crafted regular expression in the CI/CD configuration. CISA says the root cause lies in Onigmo, Ruby's regex engine. Other products using the same engine may therefore be affected as well. The entry names GitLab 19.4.2 as the fix.[1]

BleepingComputer reported on the flaw as early as Oct 12: CVSS 10.0, affecting 19.2 before 19.2.8, 19.3 before 19.3.5 and 19.4 before 19.4.2. GitLab.com is patched, and GitLab Dedicated customers need to do nothing. The researcher joaxcar reported the bug through HackerOne. At the time of the report there was no public exploit.[2] These details come from a search summary of the article; we have not read GitLab's own advisory. The only new fact now is that CISA reports exploitation. Warning: a second Onigmo flaw, CVE-2026-110264 (CVSS 10.0), followed on Oct 21. According to secondary sources, 19.4.2, 19.3.5 and 19.2.8 are also vulnerable to it; the targets are 19.5.1, 19.4.3, 19.3.6 or 19.2.9. We have not read GitLab's own advisory.

Integer overflow: A number grows larger than the space reserved for it and then wraps around to a small or negative value. Like an odometer that goes back to 0 after 999,999. If the code then calculates with the wrong value, it writes to places in memory it must not touch.
Regex engine: The part of a programming language that turns search patterns such as ^v[0-9]+$ into a small program and runs it. Whoever may write the pattern therefore controls a piece of code inside the server.
Our take For anyone who runs GitLab themselves, this is the most important report of the day. "Unauthenticated" plus "CI configuration" means in practice: every instance where outsiders can create a project or open a merge request with their own .gitlab-ci.yml is exposed. The second thought concerns the sentence about Onigmo. Any Ruby application that compiles user-supplied regexes should ask about a Ruby update. According to secondary sources, GitLab patches Onigmo in its bundled Ruby; other Ruby applications should watch for regex updates for Ruby 3.3, 3.4 and 4.0.
[1] cisa.gov KEV, version 2026.10.29 · [2] bleepingcomputer.com (Oct 12, search summary)

Cisco ASA/FTD: Firewall reboot on demand

New since yesterday The second KEV entry from Oct 29 is CVE-2026-76418 in Cisco's Secure Firewall ASA and Secure FTD, deadline also Nov 1. An unauthenticated attacker can force the device to reboot remotely. That is a denial of service, not a break-in. Ransomware link according to CISA: "Unknown".[1]

Cisco published the advisory on Oct 28: CVSS 8.6, the cause is a NULL pointer dereference. Cisco's PSIRT knows of attacks in October 2026. A device is vulnerable only if two things coincide: the login for the SSL remote access VPN is reachable, and secondary authentication is configured in the tunnel group. FMC, cdFMC and Secure Access are not affected. According to Cisco there are no workarounds; the only mitigation is to turn off secondary authentication.[2]

The fixes: ASA 9.16.4.104, 9.18.4.96, 9.20.4.50, 9.22.3.200, 9.23.1.48, 9.24.1.27; FTD 7.0.11, 7.2.13, 7.4.9, 7.6.7, 7.7.14, 10.0.3, 10.1.1.[2] We found no independent second source for this CVE number; the KEV entry and the vendor advisory do agree, though.

Our take A DoS sounds harmless, but on a VPN firewall it is not: if it goes down, remote access goes down for everyone. Attackers also use such reboots to interrupt logs or to force a failover to a weaker device. The mitigation costs convenience, not protection against intrusion. If you cannot patch right away, turn off secondary authentication temporarily.
[1] cisa.gov KEV (Oct 29) · [2] cisco.com advisory (Oct 28)

PHP2Shell plus Fragnesia: 25 servers rooted

Yesterday was about the theory of chaining the flaws; today there are numbers. BleepingComputer quotes Dream Security: using PHP2Shell (CVE-2026-109618 / -109619) and Fragnesia (CVE-2026-46300), the attackers rooted 25 servers in the US, Japan, Taiwan and South Korea. Three servers in an environment linked to the US government were also targeted. A honeypot run by Adel Karimi showed attacks on Apache with mod_php and PHP 8.4.26.[1]

According to the same report, Fragnesia affects major Linux distributions with kernels released before May 13, 2026; a public exploit exists.[1] The KEV deadline for the kernel flaw ends tomorrow, Oct 31.[2] The PHP fixes are in 8.5.12 and 8.4.27.[3] The victim count comes from a single source.

Heads up A patched PHP on an old kernel is only half the job. A host that was exposed before the PHP update counts as suspect until someone has checked it. Root access means: logs and binaries on the machine itself are no longer a reliable witness.

"testmetest": the npm worm that takes revenge with a wiper

heise describes a campaign uncovered by JFrog. Attackers hijacked 42 GitHub repositories belonging to 11 legitimate owners. The payload sits in .github/init.js and is 12.9 to 13.7 MB in size, so large that GitHub code search does not display it. It is launched through the workspace configuration of Claude Code, Gemini, Cursor and VS Code: anyone who opens the repo in one of these tools runs the code. In addition there are 15 npm packages, such as @testsecuiitytestme/cache-helper, and 17 attacker repos under the name "CementBeetleSteeple".[1]

Two details make the case nasty. First, according to SafeDep, --ignore-scripts no longer protects you. Second, the worm installs a wiper that deletes the home directory as soon as the stolen GitHub token is revoked. In addition, "Shellpanel" workflows target the cPanel flaw CVE-2026-41940. How many victims there are and what was exfiltrated is unknown.[1] All details come from the heise article, which cites JFrog and SafeDep.

Workspace configuration: Files in the repo (for example under .vscode/) that tell an editor what to do on opening: start tasks, run hooks, load extensions. Handy for teams, dangerous with foreign code. Like a parcel that unpacks itself when you open the front door.
Wiper: Malicious code that steals nothing but destroys data. Here it is built as a dead man's switch: it waits for the victim to react, and then deletes.
Our take This is exactly the kind of AI story that belongs in the software brief: the model is not the topic, the tooling layer as a launchpad is. The practical lesson concerns the order of steps when you suspect an infection. The reflex "revoke the token immediately" is wrong here. First disconnect the machine from the network and back up the data, then revoke. And open foreign repos in the editor's restricted mode (VS Code: "Restricted Mode") until you know what is inside.
[1] heise.de (Oct 29, single source)

GitHub issues as a supply-chain attack

The Register reports on an analysis by Radware. As of Oct 13, the researchers had found at least 83 malicious issues and PR comments in 61 public repos, spread across 74 accounts. 77 of them were created on Sep 1 within 43 minutes. The commands hide in HTML comments that are invisible in the rendered issue. They run when a workflow inserts the issue text into a shell command. Among the targets: aquasecurity/trivy, podman, cilium, mlflow, discord.js, Homebrew/homebrew-cask and dotnet/maui.[1]

The good news: researchers Nakibly and Babo could not confirm that the attackers gained write access or changed any code. Their recommendation: minimal permissions for workflows, and strictly separate workflows for external events from privileged jobs.[1] The numbers come from one source.

Script injection in GitHub Actions: If a workflow contains run: echo "${{ github.event.issue.title }}", GitHub inserts the title literally into the script before running it. Whoever writes the title therefore co-writes the script. Like a form where you can write "and transfer 100 euros" into the "Name" field.
Our take The most instructive report of the day, because it affects everyone who uses GitHub Actions. Five minutes is enough: search all workflows for github.event.issue, github.event.comment and github.event.pull_request.title inside run: blocks. Pass any hits as a variable via env: instead of inserting them directly, and set permissions: to the bare minimum.
[1] theregister.com (Oct 29, single source)

Hugging Face: Models that hijack GPUs for crypto mining

According to BleepingComputer, Pluto Security found 31 malicious repos across seven Hugging Face accounts, with more than 32,000 downloads in total. Downloads are not infections. The route is trust_remote_code: anyone who loads a model with this option runs the Python code that ships with it. The targets are GPU hosts running Xinference or GPUStack. The showcase repo "qwen2-tiny" rose from 7,354 to 28,412 downloads by Oct 28.[1] For us this is a supply-chain case like npm; the ai-dev brief covers the model side.

WatchGuard Fireware: 18 flaws, CERT-Bund warns with a 10.0

WatchGuard fixed 18 vulnerabilities: 17 in Fireware OS, one in the Windows VPN client. According to heise, seven of them have CVSS scores of 9.1 to 9.5; the CERT-Bund warning from the BSI rates the package at 10.0. They include remote code flaws such as CVE-2026-93857 and CVE-2026-103593 (code as root) and CVE-2026-115495 in the VPN client. Fixes: Fireware 2026.4 or 12.12.4, T15/T35 12.5.22, VPN client 2026.4. WatchGuard knows of no attacks so far.[1]

Our take Firewalls land on the KEV list every week, but this one has not yet. That is exactly the window for patching: before someone has analyzed the patch diff.

Oracle E-Business Suite: CVSS 9.8, and someone is already knocking

CVE-2026-101767 in the Application Object Library of Oracle E-Business Suite (12.2.3 to 12.2.15) has CVSS 9.8, according to heise. Horizon3.ai describes an unauthenticated SQL injection in a servlet of the thin-client framework. DefusedCyber's honeypots are already registering probing attempts; there are no confirmed compromises so far. The fix came with Oracle's October CPU a good week ago.[1]

SQL injection: An input is built unchecked into a database query, so the attacker rewrites the query. Like an order slip on which someone adds "and give me the whole cash register", and the kitchen carries out everything.

Cisco SD-WAN: "KeyDrift" malware reads IPsec keys

CVE-2026-20127 is a maximum-severity authentication bypass in Catalyst SD-WAN Controller and Manager; Cisco patched it in February 2026. According to BleepingComputer, the group UAT-8616 used it as a zero-day "since at least 2023". Now a new cluster has appeared, UAT-11473, with malware called KeyDrift. It consists of PolyFlame and LittleFilch; the latter hooks into SSL_read and siphons off IPsec keys. Targets are space and satellites, defense and aviation, and policy research.[1] The article gives no CVSS score.

Our take The lesson is old but good: a patch closes the door, but it does not throw out anyone who is already inside. If you had SD-WAN exposed before February, look for traces and rotate the keys.
[1] bleepingcomputer.com (Oct 29, single source)

systemd lets Rust in, cautiously

Rust has moved into the development branch of systemd 263; 262 came out about a month ago. The rules are tight: Rust only for new peripheral components, built with Meson instead of Cargo and without the standard library. The minimum versions: Rust 1.85, bindgen 0.71.1, Meson 1.4.0.[1]

Our take This is the right path for a project of this size: no rewrite, but new parts in a memory-safe language. For distributions it mainly means that a Rust compiler becomes a build dependency of the init system.

What Friday is worth

Three things before the weekend. First: if you run GitLab yourself, move to a patched version (19.5.1, 19.4.3, 19.3.6 or 19.2.9) today, because the KEV deadline falls on Sunday. Second: five minutes for your own GitHub workflows, searching for issue and comment text in run: blocks. Third: Fragnesia is due tomorrow, and the kernel reboot belongs on every PHP host. And if a machine acts strange after opening a foreign repo: disconnect first, then revoke the token.

It's Friday, October thirtieth. The federal cybersecurity agency CISA added two new entries yesterday to its catalog of actively exploited vulnerabilities, both with a deadline of this Sunday.

The bigger one involves GitLab. A specially crafted regular expression in the CI configuration lets an attacker run code without logging in. The root cause is in Onigmo, the regex engine used by Ruby, and CISA says other products may be affected too. GitLab closed the hole back in mid-October, in versions nineteen point two point eight, nineteen point three point five, and nineteen point four point two. If you run GitLab yourself, check that now.

The second entry involves Cisco's ASA and FTD firewalls. An attacker can force the device to reboot remotely. Only devices with a VPN login and secondary authentication are affected. There are no workarounds, but turning off secondary authentication helps.

On PHP2Shell, we now have numbers. According to Dream Security, attackers used the PHP flaws together with the Linux kernel bug Fragnesia to take over twenty-five servers. The deadline for the kernel bug runs out tomorrow.

There's a lot going on in the supply chain. An npm worm called testmetest has hijacked forty-two GitHub repositories, according to JFrog. It launches through the project configuration of editors and coding agents. SafeDep says it wipes your home directory the moment you revoke the stolen token. So if you suspect an infection, unplug the machine first, then revoke.

A second campaign hides commands in GitHub issues. Radware says it hit sixty-one public repositories, including trivy and Homebrew. The commands only run if a workflow drops the issue text straight into a shell. It's worth a quick look at your own workflows.

Also in the news: WatchGuard is patching eighteen flaws in its firewalls, and Germany's CERT-Bund is warning with the top severity rating. A critical flaw in Oracle's E-Business Suite is already being probed. And a new piece of malware called KeyDrift abuses an old Cisco SD-WAN flaw to steal IPsec keys.

Two quieter items to close. systemd is allowing Rust for the first time, for now only in new peripheral components. And Spring Boot is out in versions four point zero point nine and four point one point two, plus a first release candidate for four point two.
