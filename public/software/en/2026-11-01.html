Linux kernel: use-after-free in the IPv4 TCP code

New since yesterday CVE-2026-98432 is a use-after-free in the kernel's IPv4 TCP code and, according to BleepingComputer, is present in all kernels since 4.4.[1] According to heise, it is fixed in 6.12.113, 6.18.56, 7.2.10 and 7.3-rc7; IPv6 is not affected.[2] Debian has packages for Debian 12 (6.1.190-1) and Debian 13 (6.12.113-1). For Ubuntu and RHEL, no fixes were available yet at publication.[1]

The kernel rating is CVSS 9.8 according to BleepingComputer; Red Hat still listed 5.9 there on Oct 30, because exploitation was said to be complicated.[1] Red Hat itself now lists CVSS 9.8 (preliminary) and rates the flaw "Critical" for RHEL, with bulletin RHSB-2026-016.[3] The bug was found by Anthropic's Claude, and Anthropic built an exploit via MPTCP that, according to the report, gets root on the server in "about 53 minutes" and bypasses KASLR. The exploit is not public, and no attacks in the wild are known. According to BleepingComputer, disabling MPTCP alone is not enough.[1] We did not check against NVD.

Use-after-free: A program frees memory and then keeps using it anyway. Anyone who places their own data in that spot in the meantime can steer the program. Like a hotel room whose old key card still works after a new guest has already moved in.
MPTCP: Multipath TCP spreads one connection across several paths, for example Wi-Fi and cellular at the same time. It is part of the kernel, but on most servers it is not an everyday topic.
Our View Since Red Hat raised its rating to 9.8, there is no more dispute about severity. "Since 4.4" means: practically every Linux machine you own. A public exploit and attacks are not known so far, but this is a kernel update with a reboot, and you should install it as soon as your distribution ships it. If you run Ubuntu or RHEL, watch the advisories, because the fix was still missing there at publication.

GitLab: the problem sits in Ruby

Correction to yesterday Yesterday this said that only new GitLab versions matter. That is not correct. According to heise, four critical GitLab flaws trace back to bugs in Onigmo, Ruby's regex engine: a double free, an integer overflow and a counter overflow. heise cites CVSS 9.9 for CVE-2026-89078 and CVE-2026-93577 and CVSS 10.0 for CVE-2026-97229 and CVE-2026-110264. GitLab closed them between Sep 23 and Oct 21. Anyone who self-hosts GitLab needs Ruby 3.3.13, 3.4.12 or 4.0.9, according to heise.[1]

The Alpine Linux case shows why this matters. The project's GitLab instance had accidentally been running 19.3.4 since Oct 13 and was attacked on Oct 20 and 21. The upgrade to 19.3.6 on Oct 22 did not close the hole, because the Ruby underneath stayed old. Only the image from Oct 27 contains Ruby 3.3.13.[2]

On CVE-2026-97229 itself: a crafted regular expression in the CI/CD configuration leads to code execution without authentication. heise lists 19.2.8, 19.3.5 and 19.4.2 as fixed versions.[2] BleepingComputer reports active attacks; according to press reports, the flaw entered the KEV catalog on Oct 29, and the deadline ends today.[3] We could not retrieve the KEV entry itself today. The sources contradict each other on which versions are affected; we leave that detail out.

Regex engine: The part of a programming language that evaluates search patterns such as ^v[0-9]+. GitLab lets users write such patterns into the CI configuration. If the engine is faulty, a search pattern becomes a weapon.
Heads up The GitLab version number alone proves nothing. Also check the Ruby version GitLab actually runs with, especially for installations from distribution packages or from source. That is our reading of the Alpine case; we did not check the official Omnibus packages.

Cisco ASA/FTD: fixed versions on today's deadline

CVE-2026-76418 lets attackers force the firewall to reboot remotely, with CVSS 8.6 according to heise. It affects SSL VPN with secondary authentication in the tunnel group. There is no official workaround. According to heise, the bug is fixed in ASA 9.16.4.104, 9.18.4.96, 9.20.4.50, 9.22.3.200, 9.23.1.48, 9.24.1.27 and 9.24.10.1 as well as in FTD 7.0.11, 7.2.13, 7.4.9, 7.6.7, 7.7.14, 10.0.3 and 10.1.1. KEV listing on Oct 29 according to heise, deadline today.[1]

Supply chain: the developer workstation as an entry point

Four incidents in one week, one pattern: attackers no longer target production, but the tools of the people who build it.

Tampered editor extension in the Cursor marketplace

According to BleepingComputer, a tampered version 2.1.313 of the Claude Code extension sat in the marketplace of the Cursor editor for about 11 hours on Oct 29 (2:27 a.m. to 1:35 p.m. PT). Up to 5,000 developers may have installed it. It plants an SSH backdoor; the telltale sign is an SSH key named svc-telemetry.[1] An update alone does not remove the backdoor.[2] According to The Register, Anthropic employee Felix Rieseberg says on X that its own systems were not affected: "A malicious actor used access to Cursor's marketplace to publish a tampered copy …"[2] How the package got into the marketplace is still open. The AI tool itself is covered in the ai-dev brief.

Heads up If you use Cursor: search ~/.ssh/authorized_keys for svc-telemetry. It takes a minute, even if you did not knowingly install the extension.

GitHub issues as a command slingshot

According to The Register, Radware found 83 GitHub issues, pull requests and comments with malicious code in 61 public repositories, created by 74 accounts. On Sep 1, 77 of them arrived within 43 minutes. The targets are workflows that take text from issues into commands unchecked. In two cases there is evidence that the command ran. Among the targets: Trivy, Podman, Brave and MLflow.[3]

Workflow injection: A GitHub Actions workflow, for example, inserts an issue's title directly into a shell command. If an attacker writes commands into the title, the CI runs them. Like a form where you can type "and transfer me 100 euros" into the "Name" field, and the accounting department does it.

Northflank: treat all environment variables as stolen

According to BleepingComputer, the PaaS provider Northflank reported a breach on Oct 30. The instruction to customers is clear: "Assume all environment variables have been decrypted. Disable/rotate all keys." According to Wiz, there were at least 9 incidents at AI development platforms in October, including Railway, OpenCode, Warp and Lightning AI. In two cases, stolen keys were used to run about 2.5 million Bedrock calls worth roughly USD 100,000.[4]

Binance: DevOps laptop as the starting point

On Oct 29 from 20:05 UTC, about USD 6.36 billion flowed out of Binance according to TRM, 6.4 billion according to Chainalysis. About 2.7 billion is frozen. According to BleepingComputer, Binance describes the path like this: compromised DevOps laptop, then a service container, then withdrawals. TRM and Chainalysis attribute the attack to the TraderTraitor group.[5] A caution on the numbers: the totals in the article do not add up, leaving a gap of about USD 1.2 billion.

Our View This is the story of the week, not the kernel. Editor plugins, CI workflows, PaaS secrets and the laptop with production access are the softest spot today. Three cheap countermeasures: search CI workflows for ${{ github.event.issue.title }} and similar expressions in run: lines, keep secrets short-lived and separated per environment, and treat editor extensions like dependencies, meaning few, well-known and pinned.

Web CMS: WordPress and Drupal Commerce

WordPress 7.1.4

The update closes a code injection in the core's update process, exploitable without authentication, with CVSS 8.1 according to heise. The flaw only takes effect during a full core upgrade. Backports exist for all branches from 4.7.39 to 7.0.8. A CVE number is still missing. According to heise, Wordfence counted more than 18,500 scan requests in 21 hours.[1]

Drupal Commerce Core

Drupal warns of a "highly critical" flaw in Commerce Core that, according to BleepingComputer, is being actively exploited: "This vulnerability is being actively exploited in the wild." Fixed in 3.3.13 and 8.x-2.41; more than 42,000 sites use the module. We did not check the CVE number against NVD.[2]

Our View With WordPress, the automatic update is the best protection, and that is exactly where the flaw sits. Paradoxical, but no reason to turn off auto-updates. With Drupal Commerce, on the other hand, attacks are under way; if you run a shop on it, patch that before anything else on this list.

systemd 263 adopts Rust [1]

systemd has added Rust support for version 263; the current release is 262. The scope is narrow: only peripheral components, without Rust's standard library, built with Meson. "No cargo. Everything is built with meson." The minimum version is Rust 1.85.[1]

Our View A cautious start, just like with the kernel. For operators, nothing changes. For distributions, it means a Rust compiler becomes a build dependency for the init system. That will fuel the discussion around small architectures and minimal distributions.
[1] theregister.com (Oct 29)

PDFsharp switches from MIT to AGPL [1]

According to heise, the .NET library PDFsharp switches from the MIT license to AGPL plus a commercial option with the jump from 6.2.4 to 6.5.0.[1]

AGPL: A copyleft license. Anyone who uses the library in software that others use over the network must disclose their own source code, or buy a commercial license.
Our View The familiar pattern: first adoption with MIT, then monetization with AGPL. If you use PDFsharp in client projects, pin to 6.2.x now and check whether Dependabot or Renovate automatically propose the major update. An unnoticed license upgrade costs more than any CVE.

What Sunday is worth

Three things, none of them urgent. First: if you self-host GitLab, check the Ruby version today, not just the GitLab version. Second: if you use Cursor, search authorized_keys for svc-telemetry, and if you maintain GitHub Actions, search for issue titles in run: lines. Third: plan a reboot window this week for the kernel fix, and put PostgreSQL 14 instances on the list before Nov 12.

It's Sunday, November first. The week has piled on once more, with an old flaw in the Linux kernel and several attacks on developers' tools.

The Linux kernel's TCP code has had a use-after-free since version four point four. The kernel rating is nine point eight out of ten, and Red Hat has since raised its own rating to nine point eight as well, meaning critical. An exploit exists but isn't public, and no attacks are known. Debian has fixes, while Ubuntu and Red Hat hadn't caught up yet at publication. Our view: install the kernel update, with a reboot, as soon as your distribution ships it.

At GitLab, the real problem sits in Ruby's regex engine. According to heise, four critical flaws trace back to it, and GitLab needs a current Ruby. The Alpine Linux project found this out the hard way: the GitLab update alone didn't help because the old Ruby stayed in place. For the most widely cited flaw, the deadline from the US agency CISA ends today. The deadline for Cisco's firewall flaw also ends today.

The big theme is the supply chain. According to BleepingComputer, a tampered extension sat in the Cursor editor's marketplace for eleven hours, planting an SSH backdoor. Up to five thousand developers may be affected. Radware found malicious code in GitHub issues across sixty-one projects, aimed at poorly built workflows. The provider Northflank is telling all customers to rotate their keys. And at Binance, about six point four billion dollars disappeared, which Binance says came through a hacked DevOps laptop.

WordPress closes a flaw in its update process with version seven point one point four, and people are already scanning for it. At Drupal Commerce, attacks are under way; if you run a shop on it, patch there first. There are also updates for TeamViewer and a crash-inducing text message for older Android phones.

From the open-source world: systemd is adopting Rust, cautiously and only at the edges. The dotnet library PDFsharp is switching from the MIT license to the AGPL, so if you use it, pin your version. Spring Boot has shipped new versions, and PostgreSQL fourteen gets no more fixes after November twelfth.

Tomorrow the deadline for Ivanti's VPN gateway runs out, and we'll check whether Ubuntu and Red Hat have delivered the kernel fix.
