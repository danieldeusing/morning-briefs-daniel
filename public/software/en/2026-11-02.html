After the deadline weekend

KEV catalog: The list from the US cyber agency CISA of vulnerabilities that are demonstrably being attacked. Each entry has a deadline by which US federal agencies must patch. Like a notice on the bulletin board: "This lock has already been broken into." For everyone else, it is a good priority filter.

Ivanti Connect Secure: deadline today

CISA lists three flaws in Ivanti's VPN appliance as actively exploited. CVE-2026-111357 (privilege escalation to root) and CVE-2026-118527 (predictable file names) entered the catalog on Oct. 30; the deadlines are today and Nov. 13.[1] According to secondary sources, they belong to a chain with the authentication bypass CVE-2026-104935; affected are 25.1.1.2 and older as well as 22.8R2.5 and older, and patches have been available since Oct. 29.[2] Conflicting CVSS scores are circulating for CVE-2026-111357 (8.8 and 7.0), so we cite none.

Our take For the second time in three weeks, Ivanti Connect Secure is in the catalog with a chain. If you run one of these devices, patch today and plan its replacement in parallel. That is not panic, it is maintenance math.

GitLab: deadline expired, don't forget Ruby

CVE-2026-97229 has been in the KEV since Oct. 29, and the deadline ended on Sunday.[1] BleepingComputer names the fixed versions as 19.4.2, 19.3.5 and 19.2.8.[3] SecurityWeek rates the flaw CVSS 10.0; the bug sits in Ruby's regex library Onigmo, so Ruby must also be updated to 3.3.13, 3.4.12 or 4.0.9.[4] After an attempted RCE attack, Alpine Linux rebuilt its GitLab server and reset all passwords.[5] A caution when reading up: according to BleepingComputer, CVE-2026-110264 is a separate GitLab flaw, not a second ID for 97229. The GitLab versions above fix only CVE-2026-97229; check CVE-2026-110264 separately in the GitLab advisory.

Cisco ASA/FTD: crash via SSL VPN

CVE-2026-76418 is an exploited zero-day in the SSL VPN of ASA and FTD that crashes devices (denial of service). KEV entry on Oct. 29, deadline Sunday.[1] Patches are available. Secondary sources cite CVSS 8.6 and advise checking all tunnel groups, including the DefaultWEBVPNGroup; we did not retrieve Cisco's own advisory.[6]

Linux kernel: Ubuntu still has no finished fix

As of Monday CVE-2026-98432 is a use-after-free with a race condition in the IPv4 TCP code, present since kernel 4.4, rated CVSS 9.8.[1] It is fixed in 5.10.272, 5.15.223, 6.1.190, 6.6.159, 6.12.113, 6.18.56, 7.2.10 and 7.3-rc7. Debian, Oracle, SUSE and Amazon are shipping packages.[1]

Ubuntu is the straggler. The CVE page (last updated Oct. 30) shows "Fix in progress" for 22.04, 24.04, 26.04 and 26.10, for 24.04 for example with package 6.8.0-149.149. For 20.04, 18.04 and 16.04 it says "Vulnerable" with no fix version.[2] For RHEL, CSO reported on Oct. 30 that there was likewise no fix yet; we did not check today's status. Red Hat's own rating changed several times in reports, so we cite only the kernel score here.

That the attack leads to root via MPTCP listeners appears only in Anthropic's own report; the CVE entry does not mention MPTCP. How an AI model found the flaw is covered in the ai-dev brief. Don't confuse it: the kernel entry in the KEV from Oct. 28 is a different flaw, CVE-2026-46300.[3]

Our take Monday is the right day to book the reboot window. For Ubuntu servers that means: watch the advisory, apply the package as soon as it arrives, then reboot. That 20.04 and older do not even have a fix version is the strongest argument of the week for retiring old LTS machines.

Binance: FBI confirms North Korea

New since yesterday According to BleepingComputer on Nov. 1, the FBI has confirmed that the North Korean group TraderTraitor is behind the theft of $6.3 billion from Binance.[1] Previously, the attribution came from blockchain analysts such as Chainalysis and TRM Labs; the FBI had only reported its involvement in the investigation.[2] The figure varies by source between $6.3 and $6.4 billion. Binance traces the breach to the compromised laptop of a DevOps engineer.[1]

Our take The lesson is not specific to crypto. The laptop with deploy rights is the most valuable device in the company. Hardware keys, separate signing environments and short-lived credentials cost little by comparison.

Supply chain: attacks on the tooling

Tampered editor extension

The "Claude Code" extension in version 2.1.313 was in circulation with malicious code for about eleven hours on Oct. 29 (roughly 2:27 a.m. to 1:35 p.m. PT); up to 5,000 developers may have installed it.[1] It plants an SSH backdoor that survives uninstallation. The clean version 2.1.314 arrived on Oct. 30. Where exactly it was distributed is disputed: reports name the Cursor marketplace, others Open VSX; according to The Register, Anthropic says it was not hosted on its side.[2] On the tool itself, see the ai-dev brief.

If you had that version: check ~/.ssh/authorized_keys for foreign keys and rotate your keys. Uninstalling alone is not enough.

GitHub issues as a command channel

According to The Register, attackers needed less than an hour to run a campaign against 61 public repositories via GitHub issues.[2] The typical pattern: an Actions workflow that inserts an issue title or body unchecked into a shell command.

LiteLLM: the exposed master key

According to The Register, the supply chain attack on LiteLLM began with an exposed master key.[2] The lesson for every proxy that bundles third-party API keys: a single master key is a single point of failure.

Heads up Three incidents, one pattern: the attacks do not target your code but your editor, CI and key management. That is usually where you have the fewest controls.

Brotli and PHP2Shell: web runtimes in the KEV

Brotli: A compression format from Google that lets servers send web pages in smaller form. The decoder unpacks the data again on the receiving end. Like a vacuum bag for clothes: if the valve is broken, the suitcase bursts when you open it.

CVE-2026-111497 in the Brotli decoder was disclosed by Node.js on Oct. 21; it has been in the KEV since Oct. 27, deadline Nov. 10.[1] Fixes are available in Node 26.12.1, 24.22.1 and 22.23.4 as well as in Brotli 1.2.1, 1.1.1 and 1.0.10. Proofs of concept are public, and ELLIO sees attack traffic. Node 20, 23 and 25 are EOL and get no fix.[1] According to reports, this also affects .NET, Bun, Envoy, Istio and Python clients. Scores vary (9.2 under CVSS 4.0, 8.1 under 3.1 at Microsoft); Help Net Security cites none.

With PHP, the flaws are CVE-2026-109618 and -109619, each CVSS 9.2, unauthenticated code execution ("PHP2Shell"). The fixes in PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35 arrived on Oct. 21, the KEV entry on Oct. 26.[2] TU Delft counted more than 50,000 attack requests from over 600 IPs in 70 countries; honeypots recorded 35 successful shell executions, documented only for -109618.[2]

Our take Brotli is the underrated case. The library sits inside many runtimes, so the Node update is not enough. If you still run Node 20, your only mitigation is the upgrade.

Releases and end-of-support dates

LTS and EOL: LTS (Long Term Support) means a version gets security updates for years. EOL (End of Life) means it gets none at all. Like a car: with LTS there are spare parts, after EOL only the scrapyard.

Node.js shipped 26.13.0 and 24.22.2 (both LTS) on Oct. 28, and the first alpha of Node 27 (27.0.0-alpha.0) on Oct. 29.[1]

Python released 3.15.2 and 3.14.10 as bugfix releases on Oct. 25, as well as 3.13.18, 3.12.16 and 3.11.18 as security releases. Python 3.10 has reached its end with 3.10.22 from Oct. 1.[2]

PostgreSQL 14 gets its last release on Nov. 12, according to the versioning page.[3] The project has not yet confirmed the exact date of the next minor releases for the other branches.

Our take Python 3.10 and PostgreSQL 14 end in the same fall. If you run a FastAPI service on exactly that combination, you have a reason for an upgrade ticket this month. For PostgreSQL this is a major upgrade, so do a test run with pg_upgrade first.

Open source and infrastructure

Torvalds: end of the stabilization phase

Linus Torvalds says the kernel is out of the "stabilization phase" and describes a "much healthier model" for AI contributions: machine-generated patches would "often get rewritten."[1] For kernel users, this mainly means the normal development rhythm is back.

Tesco replaces VMware with Proxmox

Proxmox VE: An open-source platform for running many virtual servers on one piece of hardware, similar to VMware vSphere. Like an apartment building: one structure, many separate units.

According to The Register, the British retail chain is looking for someone to lead a "cost-effective alternative virtualisation platform," and is betting on Proxmox in its stores and at the edge.[2] One more big name on the list of those leaving VMware since the Broadcom acquisition.

GitHub: four million more cores

GitHub is rebuilding its platform and, according to The Register, is switching on four million additional cores to keep the service stable under load.[3] For Actions users, that is good news if it reduces outages.

In brief from the OSS camp

  • Emacs turns 50, by coincidence exactly like Vi, per The Register.[5]
  • OTTL 1.0: OpenTelemetry's transformation language, used to rewrite telemetry data in the Collector, is stable (iX, Oct. 30).[6]
  • Ubuntu Core Desktop returns, based on Core 26 (iX, Oct. 29).[6]

EU and Germany

Cyber Resilience Act: reporting obligation in force

Since Sept. 11, 2026, Article 14 of the CRA applies: manufacturers report actively exploited vulnerabilities and severe incidents. The deadlines: early warning within 24 hours, notification within 72 hours, final report after 14 days (vulnerability) or one month (incident). The rest of the CRA applies from Dec. 11, 2027.[1] We could not confirm whether ENISA's central reporting platform is fully running. For flaws like Brotli or PHP2Shell in your own products, the clock would already be ticking.

BSI warns about Apple spyware notifications

heise reported on Nov. 1 at 10:38 p.m. that Apple has sent out spyware warnings and that the BSI is therefore warning about the phones of German politicians; the digital minister reportedly confirmed receiving such a notice.[2] So far this is a single source; we did not find a second one.

What Monday is worth

Three things for the week. First: patch Ivanti today, if you have it. Second: book a reboot window for the kernel fix, and check the Ubuntu advisory daily. Third: put Node 20 services and PostgreSQL 14 instances on a list, because one gets no more fixes and the other soon will not either.

It's Monday, November second. The deadline weekend is over, and the week starts with an open problem in the Linux kernel.

For GitLab and for Cisco's firewalls, the deadline set by the US agency CISA ran out on Sunday. With GitLab, one thing still applies: along with the GitLab update, you also need a current Ruby, because the bug sits in Ruby's regex library. For Ivanti Connect Secure, the deadline ends today, and a second one follows on November thirteenth. If you run one of these devices, patch today.

The kernel flaw, rated nine point eight, has been sitting in the TCP code since version four point four. Debian, SUSE and Amazon have fixes. Ubuntu reports a finished fix for no version at all, and for twenty oh four and older releases, there isn't even a planned version. Our take: book the reboot window now and keep an eye on the advisory.

New since yesterday: according to BleepingComputer, the FBI has confirmed that the North Korean group TraderTraitor is behind the theft of roughly six point three billion dollars from Binance. According to Binance, the starting point was a DevOps engineer's laptop. The laptop with deploy rights is the most valuable device in the company.

The supply chain remains the second big story. A tampered editor extension planted an SSH backdoor, attackers used GitHub issues against sixty-one projects, and at LiteLLM it all began with an exposed master key. On top of that, the Brotli decoder and PHP2Shell are in the catalog of exploited vulnerabilities. If you're still running Node twenty, there's no Brotli fix coming for you.

On the release front, Node twenty-six point thirteen is out as an LTS, along with Python three point fifteen point two. Python three point ten has reached its end, and PostgreSQL fourteen follows on November twelfth. Linus Torvalds declares the kernel's stabilization phase over, Tesco is switching from VMware to Proxmox, and Emacs turns fifty.
