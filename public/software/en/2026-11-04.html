WordPress Core in the KEV: Three Days to Patch an Upgrade RCE

KEV catalog: The US agency CISA's list of flaws proven to be used in real attacks. Like a wanted poster at the police station: it doesn't just say "dangerous," it says "already out there."

The newest KEV entry is CVE-2026-119977 in WordPress Core, added on Nov. 3, with a deadline for US federal agencies of Nov. 6.[1] According to NVD (published Oct. 31, updated Nov. 4), the flaw allows code execution without authentication: during an upgrade with the full core package, files sit briefly in predictable, web-accessible staging paths. An attacker exploits this time window (CWE-367, a TOCTOU race condition). Like a parcel left unguarded at the door for a moment. Versions 4.7 through 7.1.3 are affected. Wordfence rates the flaw CVSS 3.1 8.1 (high).[3]

The fix is the security release WordPress 7.1.4 of Oct. 28. According to WordPress, it fixes twelve flaws, including "A weakness in the WordPress upgrade process which can lead to remote code execution" and several stored XSS bugs. [2] For CVE-2026-119977, NVD references this release post and the changed files class-wp-upgrader.php and update-core.php in 7.1.4.[3] According to WordPress, the fixes were "backported to all branches eligible to receive security fixes (currently through 4.7)". According to the 7.1.4 post, backports are still in progress and ship as they become ready.[2] If you are on an older branch, check whether your backport is out yet; otherwise move to 7.1.4. So the action is: update to 7.1.4 or the matching backport for your branch.

Our take If you run WordPress, check two things today: is 7.1.4 (or the matching backport) running, and do the automatic background updates really work? According to WordPress, the update starts on its own there. According to the KEV, sites on 7.1.3 or older are already targets of real attacks.

cPGuard: The Update Channel as an Entry Point

Compromised update channel: Software fetches its updates from a vendor's server. If an attacker takes over that server, they deliver their own goods. Like a delivery driver in a real uniform bringing fake packages: nobody opens the door suspiciously.

cPGuard from OpsShield is a security suite for Linux web servers that runs alongside panels such as cPanel, DirectAdmin and Plesk. According to BleepingComputer, an unknown attacker gained access to the update CDN with stolen credentials. From Nov. 2, 02:06 UTC, the attacker distributed versions 5.88.12 through 5.88.19 with a backdoor and a script.[1] The script collected password hashes, the root configuration of MariaDB/MySQL, root's shell history and the SSH files authorized_keys and known_hosts. The attacker pulled 32 files per customer.

OpsShield says it stopped the distribution within twelve hours. A spokesperson: "We detected 2946 servers were affected."[1] Remedy: update to 5.88.25 or newer, which removes the backdoor. Then change passwords, database credentials, cloud secrets and SSH keys.

Heads up The update alone is not enough. The data is already gone. Anyone who had cPGuard in the update window must rotate their credentials, or they lock the door and leave the thief the key.
Our take Of all things, a security product with root privileges. That is the bitter punchline: the more privileges an agent has on the server, the more valuable its update channel. Signed updates with a key that does not sit on the CDN would have been the defense here. Whether cPGuard signs this way, the report does not say.
[1] bleepingcomputer.com (Nov. 3)

Binance: The Coding Assignment Was the Malware

According to BleepingComputer, Binance reports a loss of "about $6.34 billion in digital assets" on Oct. 29.[1] The way in was a software engineer. On a job platform, a supposed project director of a made-up company got in touch. After two conversations, one of them by video, the developer was asked to download a coding assignment from an online repository. The code installed malware that no antivirus detected and replaced the pyenv file in the Homebrew directory on macOS.[1]

The FBI attributes the scheme to the North Korean group TraderTraitor, also known as Lazarus. Binance itself has not yet tied the incident to a campaign; according to the article, though, the approach matches known North Korean operations exactly. The first access began as early as September.[1]

Our take This is the story of the day for every developer. You run foreign code from a hiring process only in a throwaway VM or a container with no access to keys or the company network. And: a tool like pyenv in Homebrew is not a harmless place. Whoever can write there runs along with every Python call.

Ivanti Connect Secure: The CVSS Scores

Update since yesterday heise now gives CVSS scores for the chain that Volexity attributes to the group UTA0576[2]: CVE-2026-104935 (authentication bypass) CVSS 8.6, CVE-2026-111357 CVSS 8.8 and CVE-2026-118527 CVSS 4.3.[1] NVD confirms two of the three scores (8.6 and 4.3). For CVE-2026-111357: heise: 8.8; NVD entry (MITRE): 7.0, local attack vector.[4] The low score of the third flaw is deceptive: the file upload is one link of a chain that, according to Volexity, gives unauthenticated code execution as root overall. NVD ties the step to root to CVE-2026-111357.[4] According to BleepingComputer, attacks began on Oct. 1; Volexity sees the chain on fully patched devices since at least Oct. 3.[2] The KEV deadline for CVE-2026-111357 expired on Nov. 2; the one for CVE-2026-118527 ends on Nov. 13.[3]

Android: Patch Day and a Factory-Installed Botnet

November patch day: critical, but still quiet

Patch level: A date in the Android settings showing up to which monthly bulletin the device is repaired. Like the inspection sticker on a car: it doesn't say everything is fine, only until when it was checked.

According to heise, Google closes several critical flaws that allow code execution "without user interaction": CVE-2026-58868 in the framework as well as CVE-2026-58876 and CVE-2026-58936 in the system component. Android 14 through 17 are affected. The fixes arrive with the patch levels 2026-11-01 and 2026-11-05.[1] "So far there are no indications of attacks." The official bulletin of Nov. 2 confirms the three critical RCE flaws and both patch levels; it notes no active exploitation.[3]

XCPE: The malware came with the device

Google's Threat Intelligence Group (GTIG) has disrupted the XCPE botnet. According to heise, it comprised "over 1.3 million Android devices," mainly set-top boxes.[2] The accusation is harsh: the devices were infected from the factory, and Google blames the manufacturer Videostrong. Japanese police were a partner in the operation. Yesterday we wrote "around one million"; the number is now higher.

Our take A cheap TV box without Play Protect certification is not a device but a stranger's computer on your own Wi-Fi. At home, something like that belongs on the guest or IoT network, separate from the NAS and your work computer.

Barracuda: Two Flaws, Chained to Root

According to BleepingComputer, Barracuda warns of CVE-2026-116606 (critical, in the Email Security Gateway) and CVE-2026-111560 (several products). Together they yield command execution as root.[1] The caveat: "Successful exploitation requires an attacker to have access to the administrative interface". According to NVD, however, CVE-2026-116606 is an authentication bypass: anyone who reaches the interface needs no account (CVSS 4.0: 9.3).[2] No attacks are known. Our take: the admin interface doesn't belong on the open internet anyway.

Certificates: emSign Gets Thrown Out

Root CA: An authority whose signature your system believes without further checks. This is where the padlock in the browser comes from. Like a notary: if their license is revoked, their stamps no longer count.

python.org carries a conspicuous notice: "Security notice: the emSign root CA has been removed from certifi. Upgrade certifi, pip, uv and sigstore now."[1] WordPress pulls on the same thread: according to the release post, version 7.1.4 includes an update of the bundled root certificates "due to the eMudhra revocation".[2] eMudhra operates the emSign CA. We did not find the reason for the withdrawal in a primary source.

For Python projects this means: update certifi in every lockfile and every Docker image. The notice names pip, uv and sigstore explicitly, so updating certifi alone apparently isn't enough.

Our take This is a job for the next dependency round, not a night shift. But it shows why a frozen base image goes stale even without a CVE: the trust list inside it ages.

C++26: Waiting for Búzios

Quick update There has been no new primary source since yesterday. Status unchanged: the DIS ballot ended after twelve weeks with "Disapproved," announced on Oct. 23. Two-thirds approval and at most one-quarter no votes would have been needed.[1] To his knowledge it is the first no on a C++ DIS ever, says Andreas Fertig. What Wednesday Is Worth

Three things. First: get WordPress sites onto 7.1.4 or the matching backport today, because the KEV flaw is an unauthenticated upgrade RCE. Second: if you use cPGuard, rotate the credentials, not just the package. Third: never run coding assignments from job applications on your work computer. And while you're at it, update certifi.

It's Wednesday, November fourth. Today's theme is trust in updates and in code from strangers: a WordPress flaw on the list of actively exploited vulnerabilities, a hijacked update channel, and a coding assignment that cost billions.

First, WordPress. On November third, the US agency CISA added a flaw in WordPress Core to its catalog and gave federal agencies just three days, until November sixth. According to the US database NVD, attackers without a login can run their own code on the server during a core upgrade. Versions four point seven through seven point one point three are affected. The fix is version seven point one point four from October twenty-eighth, or the matching backport for older branches.

Then cPGuard, a security suite for Linux web servers. According to BleepingComputer, an attacker took over the vendor's update network and pushed a backdoor for twelve hours. Nearly three thousand servers were affected, and the script stole password hashes, database credentials and SSH files. The key point: updating to five point eighty-eight point twenty-five removes the backdoor, but the credentials still have to be changed.

The story every developer should know comes from Binance. According to BleepingComputer, the exchange lost about six point three four billion dollars. The way in was an engineer who downloaded a coding assignment during a fake job interview. The code installed undetected malware. The FBI ties the scheme to North Korea. Our take: you run a stranger's hiring code only in a throwaway environment.

On Android, Google has patched several critical flaws that can be exploited without any action from the user. According to heise, no attacks are known yet. Google also disrupted a botnet of more than one point three million set-top boxes that were apparently infected right from the factory.

Two smaller infrastructure items: Python reports that the emSign root certificate authority has been removed from the certifi package, and WordPress has adjusted its bundled certificates as well. And Python three point ten no longer gets security updates.

From Germany, notebooksbilliger and Pÿur report data leaks after attacks. There are also the first German cases of attacks on refrigeration systems in supermarkets, in Bavaria and North Rhine-Westphalia. At Barracuda, two flaws together give root access, but they require access to the admin interface. No login is needed.

In the coming days, what matters most is the WordPress deadline on Friday, then Patch Tuesday on November tenth. And from November sixteenth, the C plus plus committee meets in Búzios to decide how to proceed with C plus plus twenty-six.
