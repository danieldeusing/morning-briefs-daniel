Linux Kernel: A 9.8 for the IPv4 TCP Stack

Use-after-free: A program hands back a piece of memory but then uses it once more. In the meantime something else may be sitting there, in the worst case an attacker's data. Like a hotel guest who, after checking out, can still get into the room with the old key card, where someone else is now staying.

Update from recent days Akamai has published the technical analysis of CVE-2026-98432. The flaw is a use-after-free in the kernel's TCP stack, with a CVSS 3.1 score of 9.8 (critical).[1] heise independently confirms the score and writes that the flaw "betrifft demnach alle IPv4-Implementierungen seit Version 4.4 des Linux-Kerns" (affects all IPv4 implementations since version 4.4 of the Linux kernel). IPv6 is not affected.[2] The CVE has been public since Oct. 15, and the fix has been in the kernel since Oct. 5.[1]

The fix versions according to Akamai: 7.3 plus the stable releases 5.10.272, 5.15.223, 6.1.190, 6.6.159, 6.12.113, 6.18.56 and 7.2.10.[1] For the new branch, heise still lists 7.3-rc7.[2] Akamai knows of no public working exploit. As of the Oct. 30 distro status, Debian, SUSE, Oracle and Amazon Linux 2023 had fixes in part, while Ubuntu and RHEL had no finished kernel yet.[1]

The switches net.mptcp.enabled=0 and net.ipv4.tcp_migrate_req=0 only lower the likelihood, according to Akamai. Verbatim: "Disabling MPTCP alone does not prevent exploitation."[1] The remedy is a kernel update. We could not check the kernel.org entry.

Our take An unauthenticated network bug that has been in since kernel 4.4 affects practically every server, every container host and many routers. The sysctl switches are a band-aid, not a fix. So: compare uname -r against the list, and for Ubuntu/RHEL watch the distro's security tracker instead of building your own kernel.

WordPress: Actively Exploited, but How Severe?

Update from yesterday BleepingComputer writes on Nov. 4 that CISA has flagged a "recently patched high-severity WordPress vulnerability" as actively exploited, CVE-2026-119977. According to the report, US federal agencies must patch by Friday, Nov. 6.[1] Important: we could not check the KEV catalog ourselves today, the CISA site was unreachable, and one search source did not list the entry. We therefore present the rating as a BleepingComputer report, not as a confirmed KEV status.

The severity is also disputed. Wordfence rates the race condition in the core update process (CWE-367) at CVSS 8.1, while WordPress's own advisory is said to list "Low" according to search results. The affected version range is also unclear: 7.1.0 through 7.1.3 or 4.7 through 7.1.3. The fix is undisputed: WordPress 7.1.4 from Oct. 28 with fixes for 22 flaws, backported to older branches.[2]

Our take The dispute over the number does not change the task: 7.1.4 or the backport for your own branch. The only interesting question is why an advisory says "Low" and attackers use it anyway. A race condition is hard to exploit, but not impossible, and mass scanners have time.

Zyxel GS1900: Nearly 1,000 Switches Taken Over

According to GreyNoise, attackers have taken over 996 switches of the Zyxel GS1900 series in 48 countries, starting around Aug. 17.[1] BleepingComputer names the flaw CVE-2026-107441; we could not independently confirm this ID, and other sources name only the older CVE-2026-7273. Zyxel shipped the repaired firmware on Oct. 22 and published the advisory on Nov. 3. The report gives no CVSS score. According to the report, a group called "Kapibala," presumably Chinese-speaking, is behind the campaign.[1]

The older flaw CVE-2026-7273 (pre-authentication buffer overflow, CVSS 8.8) was already patched by Zyxel on June 16; according to Help Net Security it entered the KEV on Sept. 21.[2] The lesson: a switch with a web interface on the internet is a server, even if it looks like hardware.

Our take GS1900s are small office switches that you set up once and forget. That is exactly what makes them attractive. Update the firmware and make management reachable only from an internal network.
[1] bleepingcomputer.com (Nov. 4) · [2] helpnetsecurity.com (Sept. 22)

NIKKE: The Launcher Delivered the Trojan

RAT (Remote Access Trojan): A program that gives an attacker remote control of the computer. Like a spare key someone secretly copies: the door looks locked, but it is not.

Starting Sept. 27, the PC launcher of the game NIKKE downloaded tampered JavaScript files from the vendor's CDN. The publisher writes that the scripts "may have been tampered with by a third party." According to BleepingComputer, they installed the remote-access trojan K2F.[1] The launcher has over 45 million downloads since 2022. The analyzed sample contains code for crypto wallets such as MetaMask, Phantom and Coinbase; whether it was actually used is unknown. The client correction came on Nov. 4, 2:30 a.m. (UTC+9).[1]

Heads up Anyone who used the launcher during that period should treat the computer as compromised: run a malware scan, change passwords from a clean device, check wallets.
Our take This is the same pattern as cPGuard yesterday: the code comes from a trusted source and is not verified. A launcher that loads scripts from the CDN at runtime needs an integrity check with a hash or signature. Otherwise the CDN is the real publisher.
[1] bleepingcomputer.com (Nov. 4)

Apple: Public iCloud Links Will Be Scanned

Starting with iOS, iPadOS, macOS and visionOS 27.3, Apple checks content shared via "Anyone with the Link." According to The Register: "Items shared using Anyone with the Link will be checked by Apple for harmful content." These items thereby lose end-to-end encryption, even with Advanced Data Protection enabled.[1] The beta arrived on Nov. 3; the final version is expected in December.

Second Apple report: heise reports that the security firm Calif.io has bypassed Lockdown Mode in iOS 27 and that the attack survives an update.[2] The report does not yet give details on flaws and patches.

Our take Technically this is consistent: what anyone with the link can open was never truly private. But anyone who shares files with clients via link should know that from 27.3 Apple reads along. For confidential material, use sharing with named people.

Vercel: Sessions Bound to the Device

DBSC (Device Bound Session Credentials): A browser standard that binds a login cookie to a key in the device. If someone steals the cookie, it is useless to them on another computer. Like a ticket that is only valid together with your own ID.

Vercel is rolling out Device Bound Session Credentials on its platform as protection against stolen session cookies.[1] This is the answer to the infostealer wave: malware like the K2F trojan above does not steal the password but the cookie after login, and thereby also bypasses two-factor authentication.

Our take Good that a major host does this for its own dashboard. Anyone running their own web apps with long sessions should put DBSC on the list. The effort is small, the benefit against cookie theft large.
[1] bleepingcomputer.com (Nov. 4)

What Thursday Is Worth

Three things for your own systems: compare the kernel version against the CVE-2026-98432 fix list. Check WordPress for 7.1.4 or the backport. Retire PostgreSQL 14 by Nov. 12 or consciously accept the risk. The thread of the week remains the delivery path: cPGuard yesterday, NIKKE today. Code that is loaded at runtime needs a signature that does not sit on the same server.

It's Thursday, November fifth. Today is about the Linux network stack, hijacked switches, and a game launcher that served up malicious code for five weeks.

First, the kernel. Akamai has published its analysis of the flaw CVE-2026-98432. It's a use-after-free in the TCP stack with a score of nine point eight, and it affects every IPv4 implementation since kernel four point four. Fixes are in kernel seven point three and in the stable branches, for example six point twelve point one hundred thirteen. No public exploit is known. Ubuntu and Red Hat still had no finished kernel at the end of October, and the sysctl switches only lower the odds. The real fix is a kernel update.

Next, WordPress. According to BleepingComputer, the US agency CISA rates the flaw CVE-2026-119977 as actively exploited, with a deadline of Friday. We couldn't check the catalog itself today, and the severity is disputed too: Wordfence says eight point one, WordPress itself says low. Either way, the fix is version seven point one point four.

At Zyxel, attackers have taken over nearly a thousand GS1900 switches in forty-eight countries since mid-August. The repaired firmware has been available since October twenty-second. Management for devices like these doesn't belong on the open internet.

With the game NIKKE, the PC launcher began downloading tampered scripts from the vendor's server on September twenty-seventh and installed a remote-access trojan. The launcher has more than forty-five million downloads. Anyone who used it should treat the computer as compromised and change passwords from a clean device.

Starting with version twenty-seven point three, Apple checks content shared through public iCloud links. Those files lose end-to-end encryption as a result. Also, heise reports that the firm Calif.io has bypassed Lockdown Mode in iOS.

There's good news, too. Fedora forty-five is done, with kernel seven point two point fifteen, which already includes the TCP fix. And Vercel is binding login sessions to the device, so stolen cookies become worthless.

Finally, a look ahead: Tuesday is Microsoft Patch Tuesday, and on November twelfth support ends for PostgreSQL fourteen. If you're still running it, plan your move now.
