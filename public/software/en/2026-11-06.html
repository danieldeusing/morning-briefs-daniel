OpenSSH: Locked Accounts on Alpine Were Open

musl and PAM: musl is a lean C standard library that Alpine Linux uses instead of the usual glibc. PAM is the module system Linux uses to check logins. Picture a house with a bouncer: PAM is the bouncer. Without it, the lock alone does the checking, and here the lock had a flaw.

Portable OpenSSH 10.6p2 arrived on Nov 5. The release notes speak of a "critical security workaround that affects Linux systems that use the musl libc and PAM disabled". It is a password-login bypass via sshd. According to OpenSSH, the root cause lies outside sshd but can be caught there.[1] Neither the release notes nor BleepingComputer give a CVE number or a CVSS score.

According to BleepingComputer, affected systems use musl, have no PAM (the Alpine default), allow password login, and have an account whose password field is merely locked (*). Alpine, OpenWrt, Buildroot and Yocto are named. The bug has been in the code since 2016. Systems with glibc or PAM are not affected. The source reports no attacks in the wild.[2]

The remedy is apk upgrade openssh or, if that is not possible right away, PasswordAuthentication no. According to the report, the Alpine images for AWS and Azure have a default account "alpine" with passwordless doas, which makes the situation more serious there.[2] Maintainer Damien Miller writes, per LWN: "stop reading and set PasswordAuthentication=no or disable SSH for these systems IMMEDIATELY."[3]

Our take A bug that slept for ten years because the combination "musl without PAM with password login" is rarely tested. Containers mostly run no sshd at all, which defuses a lot. But routers running OpenWrt and small Alpine VMs in the cloud are exactly the boxes you set up and forget. Our rule stands: SSH with keys only, and ideally reachable only over a private network like Tailscale.

WordPress: KEV Confirmed, Deadline Today

Update since yesterday Yesterday we could not check the catalog ourselves; today we could. CISA has listed CVE-2026-119977 (WordPress Core) as actively exploited since Nov 3, and the deadline for US federal agencies is today, Nov 6.[1]

The contradiction on severity remains. In the CVE record, Wordfence as CNA rates the race condition in the update process at CVSS 3.1 8.1 (High, vector AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H).[2] The WordPress advisory GHSA-4w3m-c66w-69mg of Oct 29 rates it "Low". The fix is 7.1.4 from Oct 28, with backports down to 4.7.39; there is none for 4.6 and older.[3]

Our take When attackers are using a hole, the debate over "Low" or "High" is academic. Anyone still running a WordPress install below 4.7 is no longer running a website but a liability.

DigiCert: ID Copies Caught in the Archive

Certificate authority (CA): A company that confirms that a website or business really is who it claims to be. Like a notary who checks an ID and then gives a stamp. For some certificates, it checks real ID documents to do so.

According to BleepingComputer (Nov 5), DigiCert is sending notifications about a breach. During a server migration in February 2025, an internal system became reachable. According to the report, attackers had access from Jun 27 to Jul 2, 2026, and DigiCert confirmed this on Oct 19. Affected is "a small portion of its archived customer data", including identity documents. DigiCert does not say how many customers are hit. According to the report, CertCentral and DigiCert ONE were not compromised, and the access was read-only.[1]

Our take The report contains no sign of compromised certificates or keys, so as things stand the chain of trust is not the issue. The issue is retention: why do ID copies from validations sit in an archive that stays open during a migration? A good question for any GDPR officer with their own KYC archive.
[1] bleepingcomputer.com (Nov 5)

CWPdoor: The Panel's Own Web Server Was the Backdoor

Attackers replace the file cwpsrv, the web server of Control Web Panel, with a tampered version on Linux servers. According to BleepingComputer, this affects versions 1.15.10 and 1.24.0. According to XLab, "more than 340,000 CWP instances" were visible on the public internet last month. There is no CVE, because it is not a programming error but an implant.[1]

Our take A backdoor in the admin panel is the most convenient persistence imaginable, since the panel runs with extensive privileges anyway. If you run CWP: check the binary against the vendor version and do not expose the panel openly to the internet. How the file got onto the servers is not described by our source.
[1] bleepingcomputer.com (Nov 5)

PHP2Shell: Where Things Stand

A reminder, because PHP sits underneath so much: CVE-2026-109618 and -109619 allow unauthenticated code execution in the PHP core. The patches came on Oct 21, and according to Amazon Threat Intelligence, attacks were already running four days earlier.[1] According to php.net, the fix versions are PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35.[2] For the separate hole CVE-2026-115560, php.net has had an informational advisory since Oct 23. It recommends session.upload_progress.enabled=0; a patch comes only with the next regular bugfix release (as of Nov 6).[2]

What Friday Is Worth

Three things for your own systems: on Alpine and OpenWrt hosts, install OpenSSH 10.6p2 or turn off password login. Bring WordPress to 7.1.4 or the backport. Replace PostgreSQL 14 by Thursday or knowingly carry the risk. The common thread of the week: attackers go after whatever you set up once and then forget. Switches, admin panels, archives, default accounts.

It's Friday, November sixth. Today: a small OpenSSH patch with a big impact, a data breach at the certificate authority DigiCert, and a web server that turned out to be the backdoor itself.

First, OpenSSH. Version ten point six p two, released November fifth, closes a hole on Linux systems that use the musl library and have PAM turned off. That's the default on Alpine. On those systems, someone could log in to accounts that are supposed to be locked. There's no CVE number so far, and no known attacks. The fix: update the package, or turn off password login. Systems running glibc or PAM aren't affected.

On WordPress, we were able to check the catalog of the U.S. agency CISA ourselves today. The flaw, CVE-2026-119977, has been listed there since November third, and the deadline for federal agencies is today. The fix is version seven point one point four.

DigiCert reports a breach of an internal system. A small portion of archived customer data is affected, including ID documents. The company doesn't say how many customers are hit. There's no mention of compromised certificates.

With Control Web Panel, attackers swap the built-in web server for a tampered version. According to researchers at XLab, more than three hundred forty thousand of these panels were visible online last month. If you run one, check the file and take the interface off the open internet.

On releases: Spring Cloud is out in its second release candidate, Tor Browser sixteen arrives on Firefox ESR, and FreeRDP brings remote desktops into the browser via WebAssembly.

Finally, a look ahead: Tuesday is Microsoft Patch Tuesday, and on Thursday, November twelfth, support for PostgreSQL fourteen ends. If you're still running it, start planning your move now. In the next issue, we'll see whether the OpenSSH flaw has been assigned a CVE number.
