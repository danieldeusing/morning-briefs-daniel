Due Monday: Check Point and UnrealIRCd

On Nov 13, CISA added two flaws to the KEV catalog, both with a deadline of Monday, Nov 16: Check Point "Multiple Products" CVE-2026-123039 and UnrealIRCd CVE-2026-114713.[1] We covered the Check Point case, with PHP2Shell, root access and the ESXi wiper, in detail yesterday. What is new today are the UnrealIRCd details.

According to the security advisory on oss-security, the flaw "allows normal users to execute commands with server/IRCOp authority". So an ordinary chat user gets the rights of a server operator.[2] The fix: "upgrade to 6.2.7.1", released on Nov 7. There is a hot patch for versions 6.0.0 through 6.2.7, and UnrealIRCd 5 is affected too.[2] CISA lists the flaw as "Improper Neutralization of Delimiters".[1]

Delimiter flaw: A protocol separates commands from data with certain characters, for example a line break. If the server does not filter these characters out of user input, the user smuggles in a command of their own. Like a letter in which someone writes, mid-text, "End of letter. New order from the boss:".
Our view IRC sounds like 1999, but it still runs in many OSS communities and in internal chat bridges. If you run your own IRC server, install 6.2.7.1 or the hot patch today.

Danfoss: the update is not the fix

The Danfoss AK-SM 800A refrigeration controller sits in many supermarkets and has been considered vulnerable since August. According to heise, the Dutch firm Midnight Blue found further flaws in firmware 5.3.2, which is the update itself: "Among them were six previously unknown vulnerabilities alone". All of them allow code execution from the network without logging in.[1] According to the report, the devices lack stack canaries, PIE and secure boot. Attackers could therefore load their own firmware, and the BSI warns that devices can become unusable afterward.[1]

For firmware 5.4.0 from Nov 12, the BSI could not yet rule out on Nov 13 that it is also vulnerable. The Belgian CCB issued an urgent warning on Nov 12. The article gives no CVE numbers or CVSS scores.[1]

Stack canaries, PIE, secure boot: Three standard layers of protection. A canary is a check value in memory that raises the alarm if an overflow overwrites it. PIE loads the program at random addresses so an attacker does not know where to jump. Secure boot starts only signed firmware. With all three missing, it is like a house with no smoke detector, no changing house number and no door lock.
Heads up Midnight Blue recommends "disconnecting the devices from the internet completely". The BSI allows remote access at most from trusted networks or via VPN, and says plainly that patches are no guarantee against further flaws.[1]
Our view This is the lesson for anyone building embedded or IoT software: patching individual flaws helps little when basic hardening is missing. According to heise, the researchers found the problems in about one hour of code review. That says more about the build process than about individual bugs.
[1] heise.de (Nov 13)

Through Tuesday, Nov 24: Outlook, Chrome and two more

Four KEV entries from Nov 10 have a deadline of Nov 24: Microsoft Office CVE-2026-124194 (the Outlook flaw), Chromium CVE-2026-125350, Cisco BroadWorks CVE-2026-20320 and Openwave Webtop Media Transcoder CVE-2026-111793.[1] The catalog now has 1,781 entries.[1]

Chrome: Google writes "an exploit for CVE-2026-125350 exists in the wild". The flaw is a use-after-free in the XML component. It is fixed in Chrome 157.0.8103.50 or .51, depending on platform. According to BleepingComputer it is the "eighth such flaw since the start of the year".[2]

Patch Tuesday: according to Qualys, Microsoft closed "only one vulnerability that has been exploited in the wild", the Outlook flaw. Qualys counts 63 critical fixes.[3] On the total, we stick with "over 1,000". Qualys gives 1,235 in its text, its own table adds up to 1,094, and other sources write 1,093.[3] We have CVSS scores for Outlook and Chrome only from search hits, so we do not cite them.

Use-after-free: A program frees memory but then uses it again. If an attacker has meanwhile filled that spot with their own data, the program runs that data. Like a hotel room already given to the next guest, but the previous guest still has a key.
Our view Chrome usually updates itself but needs a restart. If you have had the browser open for days, check under "About Google Chrome".

Barracuda ESG: deadline passed, patch numbers clear

The KEV deadline for CVE-2026-116606 (login bypass, ESG only) and CVE-2026-111560 (command injection, multiple products) expired on Nov 13.[1] Barracuda says: "We have identified exploitation activity affecting a small number of organizations."[2]

The patches for ESG: "BNSF-40425 for 9.4.017 and later; BNSF-40430 for versions before 9.4.017". The other products have their own numbers, for example BNADC-16586 for ADC/WAF.[2] CVSS scores and a "fixed version" circulate only on aggregators and do not match these patch numbers. So we do not cite them.

Our view With Barracuda you check the installed patch number, not the version number. If you do not manage the ESG yourself, ask your service provider for exactly that number.

PostgreSQL: Sunday work before Thursday

On Nov 12, 18.7, 17.12, 16.16, 15.20 and 14.25 arrived with over 140 bug fixes. "This is the final release of PostgreSQL 14." And: "PostgreSQL 19 should be made generally available on November 19, 2026."[1]

The announcement lists follow-up tasks that tend to get forgotten:[1]

  • Several fixes for corrupted GIN indexes: rebuild affected indexes.
  • "If you use pg_trgm, you should reindex any GiST indexes that use the gist_trgm_ops operator class."
  • Also rebuild B-tree indexes on bpchar columns.
  • If you use incremental backups, take a new full backup afterward.
REINDEX: An index is a table's keyword directory. If the old version had a bug when creating it, the directory is wrong, even after the update. REINDEX rebuilds it. Like a book where the publisher fixed the typo in the index, but the index in your own copy is still the old one.
Our view If you are still on 14, do not jump to 19 on day one; jump to 18. 19 earns our trust only with its first minor release. And REINDEX ... CONCURRENTLY spares you the lock on large tables.
[1] postgresql.org release announcement (Nov 12)

EU: Danfoss and the CRA

Since Sep 11, 2026, the Cyber Resilience Act's reporting obligations for exploited vulnerabilities have applied, with most other obligations from Dec 11, 2027. The EU Commission published non-binding guidance on this in July.[1]

Our view Danfoss shows why, from 2027, the CRA demands basic hardening and not just reporting. A device without secure boot sold in the EU then becomes a compliance problem and not just a security problem.

What Sunday Is Worth

Three short tasks: if you run an IRC server, install the UnrealIRCd hot patch. If you have PostgreSQL with pg_trgm or GIN indexes, plan the REINDEX. And if you have had Chrome open for days, restart it.

It's Sunday, November fifteenth. Almost nothing new has happened in our sources since Friday afternoon. So this brief sorts the week by what's still open.

On Monday, two deadlines from the U.S. agency CISA run out. One covers the Check Point flaw we reported on in detail yesterday. The other covers the chat server UnrealIRCd, where an ordinary user can gain the rights of a server operator. The fix is version six point two point seven point one, and there's a hot patch for older versions.

The only fresh story comes from heise. Danfoss refrigeration controllers, which sit in many supermarkets, still have critical flaws even after the update. Researchers at Midnight Blue found six new vulnerabilities. The BSI, Germany's cybersecurity agency, can't rule out that even the latest firmware is vulnerable, and advises against leaving the devices openly connected to the internet.

Four more deadlines run through November twenty-fourth, including the Outlook flaw from Patch Tuesday and a Chrome zero-day. According to BleepingComputer, it's the eighth exploited Chrome zero-day this year. If you haven't restarted your browser in a while, do it now.

For Barracuda, the deadline has already passed. What matters there is the installed patch number, not the version number.

PostgreSQL 19 is due on Thursday. Before then, take a look at the November twelfth update: several index types need to be rebuilt, and PostgreSQL fourteen has reached its end of life.
