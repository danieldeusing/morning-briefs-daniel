Optimizely: Malicious Code in the A/B-Test Script

Attackers exploited a flaw in the login flow of Optimizely Experimentation to write malicious JavaScript into customer projects. Because the Optimizely scripts run directly on customer sites, the malicious code ran there too. Security researcher Scott Helme checked 1,611 scripts and found "188 infected Optimizely JavaScript files belonging to 178 organizations".[1] According to BleepingComputer, those affected included Zoom, CNN, Fox News, BBC, Salesforce and GitLab, among others. The first observed injection came in the early morning of Nov 16.[1]

The track.js that was loaded in swapped crypto wallet addresses, read card numbers along with their security codes, collected cookies and screenshots, and delivered iOS exploit kits. The attacker's wallets received roughly 7,000 US dollars by Nov 16; how much of that was really stolen remains unclear.[1] Optimizely blocked the path, removed the code, revoked tokens and ended sessions. At 21:52 UTC on Nov 16, only one of the 188 files still contained malicious code. Salesforce switched off Optimizely scripts as a precaution.[1]

Third-party script: A <script src=…> from a foreign domain is like a subtenant with their own key. They have the same rights in the house as you do: they see every form, every cookie, every click. If the subtenant is hijacked, the whole house is open.
Our View For scripts that change on every page load, Subresource Integrity does not help, because the hash would have to be new all the time. What does help: a strict Content Security Policy with a connect-src list, no test scripts on checkout and login pages, and a list of which third-party scripts run where. If you cannot answer that in five minutes, you have just found today's most important task.
[1] bleepingcomputer.com (Nov 16)

NoisyTCP: Crashing Linux Servers from the Network

Hyunwoo Kim has published an eleven-year-old flaw in the TCP code of the Linux kernel, CVE-2026-99288. According to BleepingComputer it is a "pre-authenticated remote corruption flaw", and nearly all distributions are affected.[1] The result is a kernel panic, so denial of service, not code execution. Conditions: the host receives TCP packets directly, runs for example Nginx, Apache or SSH, and spreads packets across several CPUs (multiple RX queues or RPS). The timing window is narrow; on a quiet bare-metal server, triggering it can take a long time.[1]

  • Fix: "a fix was already merged into the mainline Linux kernel two weeks ago". The report names no specific versions, so wait for your distribution's kernel updates and apply them.[1]
  • Workaround: turn off SYN cookies (weakens protection against SYN floods) and move to a single RX queue.[1]
  • Status: no exploitation in the wild reported, no CVSS score in the report.
Our View The workaround is worse than the disease. If you sit behind Cloudflare or a load balancer, you do not receive the packets directly and can calmly wait for the regular kernel update. Debian, Oracle and SUSE shipped kernel updates on Monday; we did not check whether NoisyTCP is in them.[2] By the way: Linux 7.4-rc3 arrived on Sunday, "fairly normal" according to Torvalds.[2]
[1] bleepingcomputer.com (Nov 16) · [2] lwn.net (Nov 16)

Project Zero Cuts the Deadline to 30 Days

Google's Project Zero will give vendors less time from now on. Until now the policy was "90+30", that is 90 days plus a 30-day extension. The extension was dropped on Nov 13. From 2027-02-02 a fixed 60 days applies, from 2028-01-03 only 30 days.[1] "Once the deadline expires, Project Zero will publish vulnerability details even if a fix is not available." Google cites AI as the reason: flaws and patches can be analyzed faster and turned into exploits.[1]

Disclosure deadline: The finder tells the vendor: "You have X days, then I tell everyone." Shorter deadlines put the vendor under pressure. But they also hit small OSS projects with a maintainer working in their spare time.
Our View Right direction, difficult effect. A large company patches in 30 days; a volunteer with a library in millions of builds often cannot. For us that means being able to update dependencies faster, that is, tests and CI that can wave an update through in an afternoon. The AI side (Google's warning about automated attacks, ARTEX) is in the ai-dev brief.
[1] bleepingcomputer.com (Nov 16)

BundID: Login Wave Knocks Out Accounts

Many BundID users received emails saying their account was locked after too many failed attempts. The BSI confirms an attack: "Automated, mass login attempts took place against BundID accounts" (translated from German).[1] According to the BSI, there are no indications of taken-over accounts. Login with username and password is switched off; eID still works. Locked accounts can only be unlocked by resetting the password.[1]

Our View A hard lockout after X failed attempts turns credential stuffing into a denial of service against real users. For your own logins, better: rate limits per IP and device, increasing wait times, passkeys. That the state offers eID in parallel is what saves BundID here.
[1] heise.de (Nov 16)

Microsoft: Outage with Consequences, a Patch for the Patch

Phantasialand: Alert email never arrived

The Microsoft cloud outage from Thursday to at least Friday noon had real consequences. At Phantasialand's Hotel Ling Bao, a safety system reported a fault, but the alert email did not arrive. A defective dosing unit kept feeding chlorine into the pool. "At first 13 guests complained of respiratory problems, then the number rose to 15." Four guests went to the hospital.[1]

Windows: Licensing bug fixed

An out-of-band update from Nov 16 fixes activation errors after Patch Tuesday; certain slmgr commands failed with 0x80041008. Mainly affected were company machines with KMS activation. The updates are named KB5136489 (Server 2025) and KB5136483 (Windows 11 23H2), for example, and contain the November security fixes.[2] The number of Patch Tuesday fixes remains disputed between sources; we stay with "over 1,000"; only the Outlook flaw CVE-2026-124194 was exploited.[3]

Heads up An alarm that only goes out by email through a single cloud provider is not an alarm. For anything that endangers people, you need a second path: SMS, siren, a watchdog that reports when messages stop arriving.

Rust 1.100: Ten Years of Waiting for !

Rust 1.100.0 came out on Nov 12, and heise picked it up on Nov 16. The announcement says it itself: "the never type is finally stable". The type ! can now be written anywhere, for example Result<T, !>; Infallible is now just an alias.[1] The Allocator trait is also stable, so libraries can offer their own allocators for Vec and Box.[1]

  • Cargo reports unused dependencies, but only if all targets are built. dev-dependencies are never reported.[1]
  • Cooldown: global-min-publish-age = "3 days" in .cargo/config.toml makes Cargo skip versions that are too new. Opt-in; cargo install ignores it.[1]
  • Heads up for old code: in editions before 2024, the never-type fallback changes from () to !. Rarely visible, but it can hit code with ignored generic return values.[1]
Never type: The type for "nothing ever comes back from here", such as with panic!() or an endless loop. The compiler then knows: this branch never ends, so I do not need to check it. Result<T, !> means: errors are impossible.
Our View The cooldown is the more important feature. Poisoned packages are usually spotted in the first days after upload and removed. If you wait three days, you let others find the mine. Good that Cargo now has it built in; npm and pip should follow.
[1] blog.rust-lang.org (Nov 12) · heise.de (Nov 16)

C++26 Hangs on Contracts — Decision in Brazil

The Draft International Standard for C++26 failed the ISO ballot in October. "The ballot saw 13 votes cast in favor, 9 against, and 12 abstentions"; ISO allows at most 25% votes against.[1] The point of dispute is contracts, that is, preconditions and postconditions in code. Bjarne Stroustrup and colleagues call the P2900 version "an existential threat to C++".[1]

WG21 meets from Nov 16 to 21 in Búzios near Rio de Janeiro.[2] The options according to The Register: drop contracts, move them into their own Technical Specification, or change them slightly and vote again. The standard could then officially be called ISO/IEC 14882:2027.[1]

Our View Moving contracts out is the pragmatic path. Only, library hardening already depends on contracts and would have to go back with them. For teams that means: do not write C++26 features into your coding standard before 2027.

EU: The CRA and the Partner Key

Since 2026-09-11, the reporting obligations of the Cyber Resilience Act apply: exploited flaws go to ENISA or the national CSIRTs within 24 hours, through the Single Reporting Platform. Fines of up to €15 million or 2.5% of turnover; the product obligations follow from 2027-12-11.[1]

Our View Cases like Optimizely show the open question: who reports when the code is compromised at the supplier and runs on the customer's product? Manufacturers should write that into their contracts before ENISA asks.

What Tuesday Is Worth

Three tasks: count third-party scripts on login and checkout pages and remove them where possible. Check on-prem ScreenConnect for RMM+ extensions. And set global-min-publish-age in Rust projects; it costs one line.

It's Tuesday, November seventeenth. The supply-chain week rolls on, and the biggest case this time comes from a tool for A-B testing.

At Optimizely, attackers exploited a flaw in the login flow and wrote malicious code into the scripts of one hundred seventy-eight organizations, including CNN, BBC and GitLab. The code read card data, swapped crypto addresses and delivered attacks on iPhones. Optimizely removed the code almost everywhere by Monday evening.

Uber reports nearly one hundred fifty thousand affected drivers. The way in was a vendor, according to TechCrunch Fireworks, the same provider as in yesterday's Cursor case. At ConnectWise ScreenConnect, there's still no update for the abused extension, and admins running their own installation have to switch it off themselves.

There's a new flaw for Linux servers called NoisyTCP. An attacker can crash a server without logging in if it receives packets directly. The fix is in the kernel, and distributions are rolling it out. No exploitation is known so far.

In Germany, mass login attempts have locked many BundID accounts. The BSI sees no taken-over accounts, but password login is switched off for now. And last week's Microsoft outage had a sad consequence: at Phantasialand an alert email never arrived, and fifteen guests were hurt by chlorine.

Google's Project Zero is shortening its deadline for vendors step by step, down to thirty days starting in January twenty twenty-eight. The reason: AI makes attackers faster.

Good news for developers: Rust one point one hundred makes the never type stable after ten years and gets a cooldown that lets Cargo leave brand-new package versions alone for a while. C plus plus twenty-six, on the other hand, failed the ISO ballot. This week the committee is working on a solution in Búzios, Brazil.

PostgreSQL nineteen is due on Thursday. Tomorrow we'll see what comes out of Búzios and whether Optimizely explains the attack path in more detail.
