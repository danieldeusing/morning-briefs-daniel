Microsoft's PyPI Account Distributes Malware

Versions 1.26.1 and 1.26.2 of the Agent Framework, a library for building AI agents, came through the official Microsoft account on PyPI. According to heise, "the malware is in versions 1.26.1 and 1.26.2".[1] Microsoft rolled 1.26.1 back to the clean 1.26.0, after which the attackers uploaded 1.26.2.[1] According to Wiz, 1.26.1 went live on Tuesday, Nov. 17, at 20:35 UTC and 1.26.2 around 21:08 UTC; by about 21:30 UTC PyPI had removed both.[3] The package gets "on average about 200,000" downloads a month.[1] OX Security and OpenSourceMalware discovered it.[2]

The trick: version 1.26.1 drops the files agent_framework_meta.pth and agent_framework_meta/_telemetry.py, 1.26.2 drops af_runtime_diag.pth plus af_runtime_diag.py. The .pth file runs every time Python starts, even without import.[1][3] To check, search your site-packages folder for both variants. The malware then looks for credentials for Azure, Git, Docker and Hugging Face, according to Baguete requests new identity tokens in GitHub Actions, Azure DevOps and Azure, and sends everything out encrypted.[2] Wiz attributes the theft of GitHub Actions OIDC tokens to 1.26.2 only.[3] How the attackers got into the account is not confirmed; OX Security suspects stolen Microsoft logins.[1] Microsoft is investigating and has set some GitHub repos to private.[1]

.pth file: A small text file in the site-packages folder. Python reads it on every start to set search paths. If a line in it begins with import, Python runs it. It is like a note on the fridge that every roommate automatically follows in the morning, even if they never meant to go into the kitchen.
Our take This is the most important point of the day, even for people without an AI project. A package with Microsoft as the sender is exactly what nobody checks. The damage happens in CI: that is where the tokens this thing looks for are stored. Anyone using Python lockfiles with hashes (pip install --require-hashes or uv lock) was protected. If you build with >= and no lock, search your builds, lockfiles and caches from Tuesday, Nov. 17, onward for these two versions and then rotate all secrets the runner could see. The AI side of the framework belongs in the ai-dev brief.

PostgreSQL 19 Is Released

Update since Thu Yesterday this said "due today". Now it is here: the PostgreSQL Global Development Group announced the release of PostgreSQL 19 on Nov. 19.[1] The highlights according to the announcement:

  • Faster foreign-key checks: in testing, bulk inserts were "nearly 2x faster".[1]
  • REPACK (CONCURRENTLY): reorganize tables without disturbing live operation.[1]
  • INSERT ... ON CONFLICT DO SELECT: RETURNING also returns the row that already exists, so "get or create" in one statement.[1]
  • WAIT FOR LSN: "read-your-writes" on standbys; plus the extension pg_stash_advice, which stores plan hints per query.[1]
  • Replication and TLS: the first logical slot raises the WAL level automatically; the server can present its own certificate per hostname via SNI.[1]

Heads up on the changes: RADIUS authentication is removed, JIT is now off by default, and after a successful md5 login a warning appears because md5 will disappear in a later version.[1]

REPACK: Over time a table collects gaps from deleted rows, like a bookshelf with empty spots. VACUUM FULL tidies up but locks the whole shelf. REPACK (CONCURRENTLY) rearranges while others keep taking books out.
Our take ON CONFLICT DO SELECT is the feature backend people have waited years for; the usual detour with a CTE and a second SELECT goes away. Still: do not put 19.0 into production on day one. First check pg_hba.conf for md5 and RADIUS, and test queries that benefited from JIT. The Nov. 12 minor update with 52 CVEs comes first.

PHP 8.6.0 and a Heavy Security Day

On Nov. 19 five PHP releases arrived at once: the new major 8.6.0 and the security updates 8.5.13, 8.4.28, 8.3.37 and 8.2.36.[1] The day before, php.net had announced an "Upcoming Critical PHP Security Release".[1] According to heise the updates close 17 flaws, seven of them with CVSS 9.2; the critical ones need special configurations, though.[2] The count is not consistent: the php.net changelog lists 18 CVE IDs, heise's headline speaks of five flaws with code execution, its URL of four.[2][3]

PHP 8.6 itself brings partial function application with ? placeholders, a class \Time\Duration, the Io\Poll API as a base for event loops like ReactPHP and AMPHP, a function clamp(), an enum SortDirection and default values for readonly properties.[4]

Our take The security update is mandatory, 8.6 is optional. heise writes: "Admins should bring their PHP installations up to date quickly."[2] If you are on 8.2, you still get the patches. Io\Poll is the most interesting piece because it replaces stream_select() and its limits.

ruby2ßhell: 21 ß and One Encoding

Ruby released versions 4.0.10, 3.4.13 and 3.3.14 on Nov. 18. According to ruby-lang.org there are "seven vulnerabilities" in the regex engine and in string case handling; the recommendation is "We strongly recommend upgrading."[1] Veria Labs gave one of them the name "ruby2ßhell". According to heise, affected are apps that process strings in ISO-8859 or Windows-125x encoding with upcase, swapcase, downcase(:fold) or casecmp?; Rails and Sinatra in the classic default are said to be affected.[2]

"A CVE number has not been assigned yet"; there is only the GitHub advisory GHSA-34m4-m9fh-gqp5.[2] No attacks are known, and heise quotes: "This is not a finished attack". Veria Labs plans to show a PoC in about a week.[2] According to the Ruby advisory, the maintainers are aware of PoCs that prove remote code execution for some of the flaws.[3] We read the technical details on ruby2ßhell only at heise, not in the advisory itself.

Why ß of all things? In capitals, "ß" becomes "SS", so one character turns into two. A string gets longer during the conversion than it was before. Our guess (not from the source): jumps in length like this are the classic place where code writes past the end of a buffer. The 21 ß come from the title of the find.

nginx: Ten CVEs in One Release

nginx.org reports versions 1.30.7 (stable) and 1.31.9 (mainline) for Nov. 18 with fixes for ten flaws, including use-after-free in the resolver, in HTTP/2, HTTP/3 and in the mail proxy, a memory corruption in HTTP/2 flow control and a buffer overflow with alias and try_files.[1] According to heise "five of them at once" have CVSS 4.0 with 9.2, and two bugs have been in the code since 2007.[2] The CVSS values come only from heise; nginx.org gives no scores. There is no report of attacks.

Our take This is the second big nginx security release in five weeks: on Oct. 14 five fixes already arrived.[1] If you use nginx from your distribution, wait for the backport; if you use the upstream repo, update as usual. For Caddy users: 2.11.9 from Nov. 5 is current, with security fixes "mostly in FastCGI".[3]

BSI: "Tense to Critical" [1]

The BSI raised its situation assessment to "tense to critical" on Nov. 19, according to heise for the first time since 2023. heise cites about 160 new vulnerabilities per day (plus 35 percent). The time from the publication of a flaw to the first exploit is about 25 days on average, and about eight days in the second quarter of 2026; a year earlier it was around 53. 88 percent of infected devices are said to be Android devices; BadBox is said to count about 30,000 in Germany, Vo1d more than 10,000 devices. We did not load the original BSI announcement.

Our take Eight days to exploit, that is the number that counts. A monthly patch cycle is therefore too slow for anything with internet access. No reason to panic, but a good argument for automatic minor updates and Renovate or Dependabot with auto-merge for patches.
[1] heise.de (Nov. 19, 12:41)

Windows: PowerShell 5.1 Is Deprecated [1]

Microsoft wants to build PowerShell 7 firmly into future Windows versions. "Windows Server 2025 and Windows 11 26H2 are to be the last versions in which PowerShell 5.1 is built in." After that, 5.1 will be available as a Feature on Demand. Microsoft names no end date, and security updates continue. From PowerShell 7.7 on there is no MSI package anymore.

Our take This mainly hits old build and deploy scripts that quietly call powershell.exe instead of pwsh, and modules that only run under 5.1. A search for powershell.exe in pipelines and GitHub Actions workflows costs nothing. The end of MSI hits everyone who distributes PowerShell via Intune or GPO.

EU Commission: Attack With a Pentest Tool? [1]

The EU Commission discovered the attack on Oct. 22 and confirmed it on Oct. 26. The HR systems Sysper and MyPMO were taken offline as a precaution and have been back since early this week; according to heise, citing Politico, Sysper briefly crashed again on Wednesday. The Commission speaks of an "AI-generated cyber campaign". Suspicion falls on Artex, an open-source pentest platform in Go that is driven by a language model; this is not confirmed. According to the FBI, Artex has been abused since at least August, and in early November over 1,600 instances were reachable. According to a spokesperson, no personal data has leaked so far.

Our take For us the operational aspect counts: an open attack tool, freely on the net, with over 1,600 reachable instances. The AI side (how much the model does itself) belongs in the ai-usecases brief.

What Friday Is Worth

Three tasks before the weekend: search CI logs for agent-framework 1.26.1 or 1.26.2 and rotate secrets if you get a hit. Fold the PHP, Ruby and nginx updates into the normal cycle. And plan a test run for PostgreSQL 19, not the production move.

It's Friday, November twentieth. Yesterday brought two big releases, and a serious supply-chain incident came to light.

First, the incident. Through Microsoft's official account on PyPI, two poisoned versions of the Agent Framework went out on Tuesday evening, one point twenty-six point one and one point twenty-six point two. According to heise, the package is downloaded about two hundred thousand times a month. The malware kicks in with every Python process and hunts for credentials for Azure, Git, Docker and Hugging Face, plus tokens from GitHub Actions. Our take: if you've built without a lockfile since Tuesday, check your build logs and rotate your secrets.

Now the good news: PostgreSQL nineteen is out. Foreign-key checks are faster, and in testing, bulk inserts ran almost twice as fast. New are online REPACK and ON CONFLICT DO SELECT for the classic get-or-create pattern. JIT is now off by default, and RADIUS has been removed. Our advice: test first, and don't put it into production on day one.

PHP eight point six is here too, along with security updates for versions eight point two through eight point five. According to heise, they close seventeen flaws, seven of them rated nine point two out of ten, though only in special configurations.

Ruby closed seven vulnerabilities. One of them is called ruby2ßhell, because when you capitalize a German sharp S, it turns into two characters. Apps using older encodings like ISO-8859 are affected. A proof of concept is expected in about a week. Also in the mix: nginx with ten flaws and WordPress with twenty.

Germany's BSI has raised its threat level to tense to critical, for the first time since twenty twenty-three. According to heise, it now takes only about eight days on average for a new flaw to be exploited. And the blog software Apache Roller is already under active attack, according to its developers.

For the Windows crowd: PowerShell five point one is deprecated. Windows eleven twenty-six H two and Server twenty twenty-five are the last versions to ship with five point one. At the European Commission, the fallout from a cyberattack continues, with suspicion falling on a freely available AI pentest tool.

Next week we'll see whether Spring Boot four point two finally ships, and whether the announced proof of concept for Ruby arrives. On Saturday, the deadlines for Apache Axis, REDCap and Synology on the known-exploited-vulnerabilities list run out.
