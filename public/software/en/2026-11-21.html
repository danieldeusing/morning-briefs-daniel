vCenter: flaw exploited since September

Broadcom published advisory VMSA-2026-0009 on Nov 19 and updated it on Nov 20.[1] At its core is CVE-2026-123890, an "authentication bypass vulnerability in the VMware Directory Service" with CVSS 9.8.[1] According to CISA, anyone with network access to the vCenter gets in without logging in.[3] According to heise, vCenter, Cloud Foundation, vSphere Foundation, Telco Cloud Platform and Telco Cloud Infrastructure are affected.[2] The fixes: vCenter 9.1.1.0200, 9.0.2.0200 and 8.0 U3m. There is no workaround.[1]

On the attack: according to heise, Mandiant reports that a group called "Armory Castle" exploited the flaw as early as September with the toolkit "Bonesaw".[2] The attackers reportedly copied the LMDB database, took over the SAML Security Token Service and created an SSO admin account. They gained initial access through a zero-day flaw in BeyondTrust Remote Support, CVE-2026-102764. Mandiant attributes the group to China.[2] Google Threat Intelligence (GTIG/Mandiant) confirms this in its own report of Nov 19: exploitation since early September, a copied LMDB database, a taken-over STS and a new SSO admin account, with entry through the BeyondTrust flaw CVE-2026-102764. GTIG calls the group "PRC-nexus".[5] According to heise, the same advisory contains four more flaws, including an SQL injection in SDDC Manager (CVE-2026-123891, CVSS 8.1).[2]

Security Token Service (STS): The service in vCenter that issues the digital badges (SAML tokens) after login. Every other component trusts these badges. Whoever takes over the STS holds the printing press for company ID badges: no need to crack a password, they simply print themselves an admin badge.
Our view This is the story of the day. A vCenter is the key ring for all the VMs beneath it, and the attackers were apparently inside two and a half months before the patch. Patching alone is therefore not enough: anyone who might be affected should also check the SSO accounts for unknown admins. Notably, VMSA-2026-0006 in July already closed an authentication bypass in the same Directory Service (CVE-2026-59309, CVSS 9.8).[4] According to GTIG, the BONESAW attack ran against a vCenter that already had the patch for CVE-2026-59309. CVE-2026-123890 is therefore a separate flaw that the July fix does not close.[5]

KEV list: four new entries, deadline Monday

CISA updated the catalog on Nov 20 at 17:48 UTC (version 2026.11.20).[1] All four new entries have the deadline Nov 23. The section above describes the vCenter entry.

Cisco Expressway

CVE-2026-76466 allows, according to CISA, executing commands as root on a clustered device through the database service, due to hard-coded credentials.[1] Cisco gives it CVSS 9.8. Expressway-C and -E in a cluster are affected; the fix is X15.5.20, and for X14 and older the guidance is "Migrate to a fixed release".[2] The contradiction: Cisco's advisory has been unchanged at version 1.0 since Oct 21, and there PSIRT is "not aware of any public announcements or malicious use".[2] CISA only adds flaws to the catalog when there is evidence of exploitation. We cannot settle who is right; we go with the KEV entry.

SAP NetWeaver

CVE-2025-42884: an unauthenticated attacker can read or modify server information in the Enterprise Portal by injecting JNDI environment variables.[1] According to NVD, it has CVSS 3.1 6.5 (Medium); EP-BASIS and EP-RUNTIME 7.50 are affected, and the fix is in SAP Note 3660969. We know these details only from secondary snippets of the NVD entry.[4] The ID dates from 2025, so the flaw is not new.

JNDI: Java's phone book. An app asks "Where is the database?", and JNDI looks up the address. If an attacker can write the entries in the phone book themselves, the app ends up calling their number. That is exactly how Log4Shell worked in 2021, too.

Apache Roller

Update since Fri Yesterday we wrote here: Roller is still missing from the catalog. Now CVE-2026-129448 is listed. CISA writes that code can be executed through the XML-RPC endpoint without authentication, and that the entry duplicates CVE-2026-82384 but "covers a wider range of versions".[1] The target version stays 6.1.7, because 6.1.6 leaves a second XML-RPC flaw open (see Friday's brief).

GitLab 19.6: the bundled NGINX is old [1]

GitLab 19.6 came out on Nov 19, patch 19.6.1 on Nov 20. Both ship NGINX 1.31.7. That means the fixes for the five "nginx2root" flaws from Nov 18, which are only in NGINX 1.30.7 and 1.31.9, are missing. "The patches change nothing about the bundled NGINX." The most dangerous one, CVE-2026-123007, sits in the HTTP/2 code and can be exploited without authentication. Because the NGINX lives under /opt/gitlab/embedded, a distribution update does not help either. Until GitLab catches up, heise recommends nginx['http2_enabled'] = false in gitlab.rb followed by gitlab-ctl reconfigure. That mitigates two of the five flaws.

Otherwise new in 19.6: Rapid Diffs is the only diff view, and self-managed admins can no longer switch back. Git access with CI/CD job tokens now counts against the rate limit of the user who starts the job. Ultimate gets a malware rule for approval policies and, in beta, "Rotate and fix" for leaked personal access tokens. The new audit log for AI agents belongs in the ai-dev brief.

Our view This is the classic problem of Omnibus packages: you cannot see the built-in dependencies, and apt upgrade feels safe. The rate-limit change is the quiet breaker: pipelines that clone many repos can suddenly get 429 errors from 19.6 on.

Ruby flaws also hit Rails [1]

Update since Fri heise has analyzed the Nov 18 advisories. Six of the seven flaws can allow code execution in the Ruby process; according to heise, proof-of-concept exploits already exist for five. Whether these are public is not clear from the article. So far only the ß flaw has a CVE ID: CVE-2026-132825, CVSS 7.4 with a local attack vector. The GitHub advisory rates the same flaw as critical. The others run only under GHSA IDs.

What is new is the link to frameworks: according to Veria Labs, Rails and classic Sinatra are attackable without authentication in the default configuration, plain Rack is not. The analysis names GitLab 19.6.0, GitHub Enterprise Server 3.22.5 and Chatwoot 4.20.0 as affected. Affected are Ruby 4.0.0 to 4.0.9, 3.4.0 to 3.4.12 and 3.3 to 3.3.13; the fixes are 4.0.10, 3.4.13 and 3.3.14. Ruby 3.2 and older get nothing anymore. A gem update does not help. Official Docker images for the patched versions are available. So far nobody reports attacks.

Our view The CVSS score of 7.4 with "local" is misleading if Rails is attackable without login. We consider the GitHub rating the more realistic one. In practice that means: raise the base image to ruby:3.4.13 or ruby:4.0.10 and rebuild. That is the whole effort, so better this week than after the announced PoC.

PHP 8.6 hardens the session defaults [1]

We reported on the Nov 19 security releases on Friday. heise has now looked at 8.6 itself. Three session defaults change: session.use_strict_mode is on, session.cookie_httponly is on, and session.cookie_samesite is set to Lax. The catch: "These default values only apply if neither the application nor the framework or php.ini set other values." Anyone who carries over their old php.ini keeps the old behavior. The new builtin_default_value field in ini_get_all() shows the built-in value.

Otherwise: partial function application (str_replace(' ', '-', ?) returns a closure), Time\Duration, Io\Poll, clamp() and defaults for readonly properties. Sodium gets ML-KEM-768 and X-Wing. fclose(), file_put_contents() and copy() now return false when writing fails. 31 things are deprecated, including the mb_ereg family and return in finally.

SameSite=Lax: A rule for cookies. The browser does not send the session cookie along with a POST from a foreign site. It is like a house pass that only works if you come through your own front door, not through the neighbor's door.
Our view Good defaults, but with a trap: according to heise, Lax can break cross-site POSTs, such as SAML SSO callbacks and redirects back from payment providers, especially in Safari and Firefox. Anyone with SSO or a payment provider should test exactly that flow before the upgrade. For PHP 8.2, security updates end on Dec 31.[2]

Windows hotpatches knock out apps [1]

On Windows 11 24H2 and later, which receives the November updates as a hotpatch via Windows Autopatch, some apps no longer start. Mainly affected are programs that load the 32-bit msi.dll; the error reads ERROR_ALLOTTED_SPACE_EXCEEDED (0xC0000099). "On systems with the standard updates, these errors reportedly do not occur." Microsoft tracks the problem as WI1559710. The workaround: in the registry path …\Session Manager\Memory Management, set the DWORD HotPatchTableSize to 2000 (hex) and restart. On the heise test devices the value was already set that way, so it does not help everywhere. Nobody advises uninstalling the patch, because it closes flaws that are already being exploited.

SonicWall: Gen6 belongs in the scrap heap [1]

The Gen6 and Gen6.5 firewalls (TZ, NSA, NSa, SOHO, NSv, SuperMassive) have been out of support since Oct 1 at the latest. "Therefore SonicWall will no longer release any further firmware updates or security patches for Gen6 devices." Support cannot be extended. In early November SonicWall reported several SonicOS flaws, one of them already exploited; updates came only for Gen7 and Gen8. The way forward is Gen8 with SonicOS 8.

Our view A firewall without patches is an open window with a warning sign. Anyone who still has an old-series TZ at customers' sites or in their own office should plan the swap now, not after the next exploit.

MongoDB buys Firebolt [1]

MongoDB announced the acquisition of the analytics database Firebolt on Nov 17. Firebolt was founded in Israel in 2019; the engine was developed by a team in Munich under Benjamin Wagner. MongoDB does not state a price. In 2022 Firebolt was valued at $1.4 billion; Calcalist estimates the purchase price as considerably lower. The engine is to run alongside MongoDB and keep both automatically in sync, "in the coming months". "Existing Firebolt customers keep product, support and service."

Our view This is MongoDB's answer to the question "And where do I run my analytics?", which so far led to PostgreSQL or a data warehouse. What remains open is whether in the end there will again be two copies of the data. Nice for the Munich database scene, which once more ends up in a big US product.

FFmpeg 9.1 "Gauss" [1]

The new FFmpeg brings a Vulkan encoder for APV, xHE-AAC via libfdk-xhe-aac, ASTC support and a reworked AAC encoder. The fruc_vulkan filter computes intermediate frames for a higher frame rate, but needs Nvidia's VK_NV_optical_flow for that. NVDEC can hand CUDA arrays to NVENC without an intermediate copy (from Video Codec SDK 13.1). Optionally there is an HTTP client based on libcurl with HTTP/2, HTTP/3 and SOCKS5. The asf_o demuxer is removed. heise gives no date for the release.

What Saturday is worth

One task is urgent: get vCenter to 9.1.1.0200, 9.0.2.0200 or 8.0 U3m and check the SSO accounts for foreign admins. For GitLab self-managed: turn off HTTP/2 in the bundled NGINX until a fix arrives. Rebuilding Ruby images and testing the SSO login before the PHP 8.6 upgrade can wait until Monday.

It's Saturday, November twenty-first. It's a quiet day, but one item from Friday matters: a critical flaw in VMware vCenter is already being attacked.

Broadcom closed the flaw on Thursday. It lets attackers bypass the vCenter login and scores nine point eight out of ten. According to heise, Mandiant reports that a group has been exploiting the flaw since early September. The attackers took over the service that issues login tokens and set up an admin account of their own. There is no workaround. Our advice: update vCenter, then check the SSO accounts for unknown admins.

The U.S. agency CISA added the vCenter flaw to its catalog of exploited vulnerabilities on Friday evening, along with Cisco Expressway, SAP NetWeaver and the blogging software Apache Roller. The deadline for federal agencies ends Monday. There's a contradiction on Cisco: Cisco itself says it knows of no exploitation, while CISA sees it differently.

There are new details on the Ruby flaws. According to heise, Rails and Sinatra can be attacked without a login in the default configuration. Proof-of-concept code already exists for five of the seven flaws. The fix is a new Ruby, not a gem update, and the Docker images are ready.

GitLab nineteen point six ships an old NGINX in which this week's flaws are still open. Until GitLab catches up, it helps to turn off HTTP two in the bundled NGINX. Also, Git access from CI jobs now counts against the rate limit.

PHP eight point six makes session cookies safer by default. But that only applies if your old php.ini doesn't say otherwise. And the new SameSite rule can break SSO logins and redirects back from payment providers, so test before you upgrade.

Briefly: Microsoft's November hotpatches keep some apps from starting on Windows eleven, SonicWall advises retiring old Gen6 firewalls, and MongoDB is buying the analytics database Firebolt, whose engine was built in Munich.

Next week we'll watch whether GitLab ships a new NGINX and whether the announced Ruby exploit appears. On Monday, the KEV deadlines for vCenter and the others run out.
