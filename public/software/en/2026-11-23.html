vCenter: deadline today, and Google adds more

Update since Sun The KEV catalog lists a deadline of Nov 23, today, for CVE-2026-123890 (VMware vCenter, "Authentication Bypass Using an Alternate Path or Channel").[1] New is a report from The Register dated Nov 23. According to The Register, the China-linked group ARMORY CASTLE knew about the flaw as early as July and exploited it from September.[2] Google Threat Intelligence names July only as a build timestamp; according to Google, exploitation began in early September. The attackers first got into the network through BeyondTrust remote-support appliances. They then moved on to other Linux appliances and deeper into the victims' networks.

Google names five tools used by the group: two webshells (SLIMSAVAGE, CAGEMATCH), an exploit tool written in Go (BONESAW), a backdoor (BEARBONES) and a SAML tool (SAWSNAKE). According to Google, the BONESAW exploit tool can "forge authentication tokens, bypass MFA, and impersonate any user".[2] In early September it also ran on a server that had been patched against the older vCenter flaw CVE-2026-59309. In total, the operation used two zero-days, according to Google. Google does not say how many victims there are. VMware did not answer the question of whether it knew about the September attacks.[2]

Heads up According to The Register, Broadcom says its free zero-day patch policy still applies, but "This policy covers vSphere 8 patches only".[2] So anyone on vCenter 7.0 without Extended Support gets no fix (see Sunday's brief). A patch alone is not enough either: if you were exposed since September, check SSO accounts and SAML configuration for foreign entries.
Our take The report changes the question. It is no longer "patch by today" but "what has happened since July?". The webshells survive a patch. If you have vCenter on the network, look at the logs from July onward, not from the advisory.

KEV: no new entry since Friday

The newest entry in the KEV catalog is still from Nov 20.[1] Four deadlines expire today: vCenter, Cisco Expressway (CVE-2026-76466, hard-coded credentials), SAP NetWeaver (CVE-2025-42884) and Apache Roller (CVE-2026-129448, deserialization).[1] Chromium, Microsoft Outlook (CVE-2026-124194), Cisco BroadWorks (CVE-2026-20320, XXE) and Openwave Webtop Media Transcoder (CVE-2026-111793) follow tomorrow.[1] Apache Axis, REDCap and Synology DSM were added to the catalog on Nov 18; their deadline was Saturday, Nov 21. The CVSS scores of 9.8 for these three come from The Hacker News, not from CISA.[2]

After that come Puppet Enterprise (CVE-2026-115731, deadline Dec 1) and LiteLLM (CVE-2026-40217, deadline Dec 2).[1] LiteLLM is a proxy in front of AI APIs. Details are in the ai-dev brief.

XXE: An XML document may point to external files. If the parser resolves that unchecked, it reads files from the server on the attacker's command. Like a letter saying: "Please enclose the contents of your safe."

Chrome: the zero-day has its deadline tomorrow

On Nov 9, Google closed the flaw CVE-2026-125350, a use-after-free in XML processing. According to Google, an exploit exists "in the wild".[1] The fix is in 157.0.8103.50/.51 for Windows and macOS and in 157.0.8103.50 for Linux. According to BleepingComputer, it is the eighth exploited Chrome zero-day of 2026. CISA added the flaw on Nov 10, and the deadline is Nov 24.[2]

Our take For desktops this is long done, because Chrome updates itself. But the flaw is in Chromium, and Chromium sits inside Electron apps, headless browsers in CI and kiosk images. Nothing updates itself there. That is the real check point.

GL.iNet: breach through its own cloud

According to heise from Nov 22, GL.iNet's cloud remote management had a vulnerability. "However, an unauthorized third party had already exploited this vulnerability beforehand", in order to access some routers and KVM devices and install malware.[1] GL.iNet fixed the flaw in the cloud and blocked access. New infections by this route are therefore no longer possible. But: "However, these measures do not remove malware from devices that were already infected."[1]

Firmware patches are due from Sunday, Nov 22. heise names no CVE or version numbers. Anyone with an infected device needs the new firmware or a factory reset and must set everything up again afterwards.[1]

Our take This is the unpleasant side of "convenient remote access". The flaw was not in the device but at the vendor, and the customer could do nothing about it. If you have GL.iNet KVMs in a homelab, you usually don't need the cloud management. Remote access through your own VPN such as Tailscale or WireGuard is the more robust route.
[1] heise.de (Nov 22)

Windows hotpatch: apps won't start

According to heise, the security updates from the November Patch Tuesday cause problems when they arrive as a hotpatch via Windows Autopatch. Systems with Windows 11 24H2 and newer are affected. Some apps cannot be installed, started or run.[1] It mainly hits 32-bit apps that load msi.dll. The error message reads "ERROR_ALLOTTED_SPACE_EXCEEDED (0xC0000099)". According to heise, systems with standard updates are not affected.[1]

Microsoft tracks the problem as WI1559710. The workaround: in the registry under …\Session Manager\Memory Management, set the DWORD HotPatchTableSize to 2000 (hex) and restart. Uninstalling the patches is not a good idea, because they close exploited flaws.[1]

Hotpatch: An update that swaps code in running memory without a restart. Like changing a tire while driving: handy, as long as everything fits.
[1] heise.de (Nov 20)

PostgreSQL 14 is at its end

On Nov 12, PostgreSQL 18.7, 17.12, 16.16, 15.20 and 14.25 arrived. According to the announcement, the round fixes "over 140 bugs".[1] For one version it is the last: "This is the final release of PostgreSQL 14. PostgreSQL 14 is now end-of-life."[1] From now on there are no security fixes for 14.

The fixes themselves are no routine update. The announcement lists several GIN bugs that could lead to index corruption. For pg_trgm GiST indexes it says plainly: "You need to reindex after updating".[1] There are also fixes for incremental backups that "could produce corrupt backups".[1]

GIN and GiST index: Special indexes for full-text search, JSONB or similarity search (pg_trgm, for example for LIKE '%foo%'). If the index is broken, the query does not find rows that are there. There is no error message, just wrong results. Like an index in a book that points to the wrong page.
Heads up The package update alone does not repair an already damaged index. After updating to the new minor version, rebuild the pg_trgm GiST indexes, ideally with REINDEX INDEX CONCURRENTLY. If you use incremental backups, take a new full backup afterwards and test the restore.
Our take This is the work of the week, not PostgreSQL 19. Many Docker setups still run postgres:14 because "it works". Now is the moment to plan the migration to 17 or 18. If you wait until 19.1, you will otherwise jump over five versions.
[1] postgresql.org update announcement (Nov 12)

PostgreSQL 19: two upgrade traps

Update since Sun PostgreSQL 19 has been GA since Nov 19, with REPACK … CONCURRENTLY, pg_plan_advice, WAIT FOR LSN and JIT off by default (details in Sunday's brief).[1] heise adds a hard trap: "The server no longer starts if the configuration still contains io_workers".[2] Like every major release, 19 needs a major-upgrade strategy, meaning pg_upgrade or pg_dump/pg_restore.[3]

Our take Before the test upgrade, search postgresql.conf for io_workers. A server that won't start is a laugh in staging and a long evening in production.

SonicWall: Gen6 no longer belongs on the network

Update since Sat In a support notice, SonicWall advises replacing Gen6 and Gen6.5 firewalls and no longer running them at the internet edge.[1] According to heise, support ended on Oct 1. There is no more firmware and no more patches, not even for critical flaws. Affected are, among others, TZ300 through TZ600, NSA 2600 through 6600 and the NSa x650 series.[1] SonicWall cites the Verizon DBIR 2025: in 22% of breaches via an exploited vulnerability, edge devices and VPNs were the target, up from 3% the year before.[1]

Until replacement, SonicWall recommends: turn off WAN management via HTTPS, SSH and SNMP, restrict SSL-VPN, MFA for admin and remote accounts.[1]

[1] heise.de (Nov 20)

CI/CD: "A green build" is no proof

In the iX interview from Nov 20, Fabian Deitelhoff says pipeline security must cover the whole path from source code to release: "A green build alone does not provide sufficient proof of that."[1] He cites the attacks on GitHub Actions, including the breach of tj-actions/changed-files in 2025. His recommendations: set token permissions narrowly, pin actions to full commit SHAs, separate build and publish jobs, and review changes to workflows.[1] He sees Trusted Publishing as a real gain, because long-lived tokens go away.

Our take None of this is new, but SHA pinning is missing in a surprising number of repos. An owner can move a tag like @v4 at any time. A commit SHA, no. A Dependabot setup keeps pinned SHAs current, so the effort is small.
[1] heise.de / iX (Nov 20)

TeleTrusT: crypto-agility before post-quantum

The German IT security association TeleTrusT has published a 30-page guide on crypto-agility (heise, Nov 19).[1] The core idea: do not tie standards and systems to one specific method, because post-quantum methods are replacing RSA and Diffie-Hellman. The first step is a crypto inventory, for example a Cryptography Bill of Materials (CBOM). Migration by risk follows.[1] According to heise, the guide names no concrete dates, only legal frameworks such as the IT-SiG and the EU Cybersecurity Act.

Crypto-agility: Build software so you can swap the encryption method like a light bulb. Without rebuilding the lamp.
[1] heise.de (Nov 19)

AWS: the outage nobody noticed

In The Register, Corey Quinn describes an outage in us-east-1 on Nov 15. From about 3:05 a.m. PST there were errors with sign-in and connections. It hit IAM Identity Center hardest, which engineers use to sign in to AWS.[1] According to Quinn, the status page only reported 93 minutes later, and the all-clear came at 6:53 a.m. His thesis: whether anyone notices an outage "depends upon what layer broke, and when". Early Sunday morning, a service only for engineers, no spike on Downdetector.[1]

Our take For operators this is the more important lesson than from any big outage. If IAM Identity Center is gone, in an emergency you can't get into your own console. A break-glass access outside SSO belongs in every AWS account.
[1] theregister.com (Nov 21)

GTA VI: how GeoDNS saved the network

Rockstar distributed the downloads for GTA VI from Nov 10, and play started on Nov 19. Researchers at RIPE NCC measured it with RIPE Atlas.[1] The tool was GeoDNS: a domain returns different IP addresses depending on location. According to the measurement, Fastly carried more than half of the Xbox traffic. Emile Aben sums it up: "DNS helps steer each player towards a download server, while multiple CDNs share the work".[1]

GeoDNS: The internet's phone book gives out a different number depending on the caller. Whoever asks in São Paulo gets the server in São Paulo.
[1] theregister.com (Nov 19)

UK: court confirms Apple order

According to The Register, the Investigatory Powers Tribunal has ruled: the British government must admit that it sent Apple a secret Technical Capability Notice. The court rejected the Home Office's argument that even the admission harms national security.[1] The exact content is not known: "there has been no publication of its precise content". Apple switched off Advanced Data Protection for UK users in February 2025.[1]

Our take For developers this is a lesson. A backdoor for one state is a backdoor for everyone. End-to-end encryption is only as strong as the rule that protects it.

Python 3.15: status after one month

Python 3.15.0 has been final since Oct 9. Since then 3.15.1 (Oct 21) and 3.15.2 (Oct 25) have come, plus 3.14.10.[1] According to python.org, 3.15.2 was "an expedited security release to address the compromised eMudhra intermediate CA keys". It's Monday, November twenty-third. Today the weekend's list comes due, and a database version goes into retirement.

At the top is VMware vCenter again. Today the deadline from the U.S. agency CISA ends. New is a report from The Register: it says a Chinese group knew about the flaw as early as July. Google itself names July only as a build timestamp and sees attacks from early September. Their tools can forge login tokens and get around multifactor authentication. So a patch alone isn't enough. If you were exposed, look at the logs from July on.

Tomorrow the deadline ends for the Chrome flaw that is already being exploited, for the Outlook flaw from Patch Tuesday, and for Cisco BroadWorks. On the desktop, Chrome has long been up to date. But Chromium is also inside Electron apps and test pipelines, and nothing updates itself there.

The most important database news is not PostgreSQL nineteen, it's the end of PostgreSQL fourteen. The last update, from November twelfth, fixes more than one hundred forty bugs. Some of them could damage indexes. For certain search indexes, you have to reindex after the update. If you're still on version fourteen, now is the time to plan the migration.

For PostgreSQL nineteen, heise points out a trap: the server won't start if the configuration still contains the io workers setting. It's better to check that before the test upgrade.

Over the weekend, GL.iNet reported a breach through its own cloud management. Attackers installed malware on some routers and KVM devices. The hole is closed, but infected devices need new firmware or a factory reset. Also, Microsoft's November hotpatches are breaking some apps on Windows eleven. Microsoft offers a workaround in the registry.

SonicWall advises replacing old sixth-generation firewalls, because there are no more patches. In Germany, the TeleTrusT association recommends building software so that encryption methods can be swapped. That is preparation for the post-quantum era.

Finally, two stories about the network. At AWS, sign-in in the us-east-1 region failed on November fifteenth, and hardly anyone noticed. And GTA six didn't overload the internet, because GeoDNS sent players to nearby servers.

Tomorrow we'll see whether CISA adds new flaws to the catalog, whether GL.iNet names firmware versions, and whether GitLab ships a new NGINX.
