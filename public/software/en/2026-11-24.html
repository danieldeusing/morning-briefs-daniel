Cisco Expressway: Attacks After the PoC

Update since Mon The flaw CVE-2026-76466 sits in the cluster function of Cisco Expressway, according to Action1.[4] Unauthenticated attackers on the network can use it to run system commands as root. Cisco cites CVSS 9.8, heise calls it "critical."[1][5] CISA has listed the flaw in the KEV catalog since Nov 20 as "Use of Hard-coded Credentials"; the deadline was yesterday.[2] What's new is confirmation of attacks: according to heise, the security firm F6 confirmed them, and The Register writes that the attacks began after a PoC went public.[1][3]

According to Cisco, version X15.5.20 closes the hole. Anyone running X14 or older should migrate to a fixed release; there are no workarounds.[5] On Nov 23 Cisco updated its advisory (version 1.1) to note the KEV listing. Cisco says it has no direct evidence of active exploitation.[5]

Hard-coded credentials: Login details the vendor built right into the software. Nobody can change them. Like a master key that fits every lock in a product line: once someone knows it, they can get in anywhere.
Our take Expressway is the gateway that lets video and voice connections through the firewall. By definition, it sits at the edge of the network. A fixed key plus a public PoC means mass scanning is only a matter of days. Anyone still running X14 doesn't have a patch problem, but a replacement problem.

KEV: Two New Entries, Three Days to Remediate [1]

Update since Mon Yesterday we reported "no new entry since Friday." Monday evening (catalog version 2026.11.23) brought two. CVE-2026-134624 affects N-able MailAssure (formerly SpamExperts), a mail-filtering service. It is a server-side request forgery. CVE-2026-133968 is a path traversal in MONAI Label, an open-source tool for annotating medical images. Both are due Thu Nov 26.

SSRF: The attacker gets a server to fetch an address on their behalf that can't be reached from outside. Like a stranger calling the front desk and saying: "Please bring me the file from the boss's office." The front desk is allowed in; the stranger isn't.
Our take The deadlines stand out. The four entries from Nov 10 that fall due today got two weeks, while all entries from Nov 20 and Nov 23 get only three days. For teams that plan around KEV, that means the catalog has to be read daily, not weekly.
[1] CISA KEV feed (version 2026.11.23, retrieved Nov 24)

SAP NetWeaver: Medium Score, Real Attacks

CVE-2025-42884 is a JNDI injection in the SAP NetWeaver Enterprise Portal. heise cites CVSS 6.5, "medium."[1] Even so, it has been in the KEV catalog since Nov 20, which means documented attacks.[2] SAP released the patch back at the November 2025 patch day.[1]

JNDI injection: JNDI is the Java service an application uses to look up resources by name. If an attacker can control that name, they send the application to their own server. That was the mechanism behind Log4Shell. Like a delivery note where the customer writes in the warehouse address themselves.
Our take This is the lesson of the day. A year-old patch, a medium score, and still under attack. CVSS tells you how bad a flaw can be. KEV tells you that someone is using it right now. For prioritizing work, the second one counts.
[1] heise.de (Nov 23) · [2] CISA KEV (retrieved Nov 24)

Spring: One Big Patch Round

spring.io lists 25 advisories on the first page, all from Nov 19; more sit behind "Load more."[1] Affected are Spring Security, Spring Web Services, Spring Integration, Spring Data MongoDB, Spring Vault, Spring for GraphQL and Spring AI, among others. heise summarized the round on Nov 23 and calls some of the flaws "critical."[2] Three points stand out:

  • Spring Security CVE-2026-59273: Code execution, but only with a specific configuration, according to heise. spring.io rates it MEDIUM. Fixes: 5.7.27, 5.8.29, 6.4.20, 6.5.13, 7.0.8.1, 7.0.9, 7.1.2.1 and 7.1.3. According to heise, only 7.0.9 and 7.1.3 are freely available.[1][2] Three more Spring Security advisories (59330, 59331, 59333) are HIGH.[1]
  • Spring LDAP CVE-2026-59367: The embedded LDAP server for tests has fixed admin credentials and listens on all network interfaces. Anyone on the same network takes it over. spring.io rates it CRITICAL. Free (OSS) fixes: 4.1.3 and 4.0.7.[2][3]
  • Spring Boot CVE-2026-59411: Servlet apps with Actuator on Cloud Foundry and no security configuration of their own lose default protection. Reactive apps are not affected. spring.io rates it CRITICAL. Free (OSS) fixes: 4.1.3 and 4.0.10.[2][4]

Spring AI has nine of the 25 advisories, five of them HIGH.[1] The AI side belongs in the ai-dev brief; what counts here is that Spring AI is a normal Maven artifact and belongs in the dependency scan.

Heads up The test LDAP server is the hidden winner. It is meant for tests, but tests also run on CI runners and dev machines on the office Wi-Fi. If you use spring-ldap-test, check whether the server is reachable from outside localhost.
Our take The real news is the version list. Eight fix versions, two of them free. Anyone on Spring Security 5.x or 6.x either pays for enterprise support or migrates. It's the same math as vCenter 7.0, only quieter. That turns the move to Spring Boot 4 / Security 7 from a wish into a must.

Azure API Management: Secrets Stolen in Norway

Attackers combed instances of Azure API Management (APIM) for secrets and carried out admin actions. According to The Register, only Classic tiers are affected, not APIM v2. The Norwegian security authority NSM names two energy companies as victims: Equinor and Skagerak Energi.[1] Microsoft says it detected the problem on Nov 18 and rolled out a mitigation automatically the next day. No CVE or CVSS value has been made public.

The NSM advises assuming that secrets and named values are exposed. So: rotate all tokens, check what each instance can reach, and look for traces from before Nov 19.[1]

Our take The setups hit hardest were mainly those that stored secrets directly in APIM instead of pointing to Key Vault. It's the old pattern: secrets belong in a vault, not in the gateway's configuration. The Register points to forgotten dev and test instances. They often hold real keys.
[1] theregister.com (Nov 23)

Cleverbridge: Card Data Including CVV Stolen

Cleverbridge is a software-shop service provider based in Germany. Many vendors sell licenses and subscriptions through it. The company noticed unauthorized access on Nov 4 and notified those affected starting Nov 20. What was stolen: card numbers, expiry dates and CVV/CVC codes, plus email address, billing address and phone number. Passwords are not affected, according to Cleverbridge. The company gives no figures.[1]

The Register counts Red Hat, SUSE, Tenable, Veeam, Jamf, Parallels and Plesk among the customers. That does not mean their buyers are affected.[1]

Our take The sentence about the CVV is the scandal. PCI DSS forbids storing the security code after authorization, even encrypted. Either it was lying around somewhere after all, or the attackers sat live in the payment form. Both are bad. Anyone who bought a license through a Cleverbridge checkout this year should check their credit card statement.
[1] theregister.com (Nov 23)

PostgreSQL: Who Is Really at the End

The official versions table is unambiguous: PostgreSQL 14 got its last release, 14.25, on Nov 12, 2026 and is no longer supported. PostgreSQL 15 (currently 15.20) runs until Nov 11, 2027.[1]

PostgreSQL 19 has been out since Nov 19.[2] For upgrades, keep in mind: JIT is now off by default, RADIUS login is removed, and old pg_dump dumps with standard_conforming_strings=off load "not properly" in 19, according to the release notes.[2]

Android: Developer Requirement Goes Global

Google is gradually extending Android developer verification to the whole world starting in January 2027. It applies to all installation sources on certified devices. Brazil, Indonesia, Singapore and Thailand have been part of it since Sep 30, 2026.[1] Registering apps takes under ten minutes, according to Google. Open-source repositories can register for developers via the Android Developer Console API.

Exceptions: installation via ADB from a PC is not affected. Anyone who wants to install unverified apps without ADB uses the "Advanced Flow" with a one-time 24-hour wait. Hobby and student accounts can now unlock 50 devices instead of 20.[1]

Our take In Brazil this is already everyday life, and the world didn't end. The ADB route stays open, so it mostly hits users, not developers. If you distribute internal Android apps as APKs, plan the registration now and not in January.
[1] heise.de (Nov 23)

Microsoft: Three Months Undetected

Microsoft has published the final report on the outage from Nov 12 to 14. Exchange Online went down, and other Microsoft 365 services were disrupted. At the worst moment, more than 80% of North American gateway servers did not respond.[1] The cause: a code change from July, combined with a failover and reduced capacity. The bug ran worldwide for more than three months before it struck.

The core of the report: the load tests ran on older hardware with fewer cores. The bug only got bad on newer machines. Microsoft promises load tests on new hardware, more spare capacity and broader failover tests. Business email was not lost, according to Microsoft.[1]

Our take This is the most instructive report of the week because it is so ordinary. Almost every team tests load on an environment that is smaller or older than production. If you run staging on cheaper hardware, you should know which class of bug you're blind to.
[1] theregister.com (Nov 23)

USA: More Outages From Rushed Patches

US government officials are preparing the public for more IT outages, according to heise. Director of National Intelligence Jay Clayton spoke of "bumps in the road" on CNN. Treasury Secretary Scott Bessent compared patches to a vaccination.[1] The background, according to heise, is a wave of rapid patches because AI is finding many flaws. In some cases, rushed patches are said to have caused the outages. heise stresses: there is no evidence of a link between the incidents.[1]

The Register takes a more sober view: not a conspiracy, but technical debt defined the week.[2] A heise commentary adds: two providers are not a contingency plan if they share the same dependencies.[3]

Shirudo: Shield Instead of Instant Patch

Cisco and OpenAI are introducing Shirudo, an open-source tool for "compensating controls" on Linux. It builds on Tetragon, a project from Isovalent, which Cisco owns. The idea: for a flaw you can't patch right away, you write a small eBPF program, a "shield," that blocks the attack path. A human reviews every shield before production.[1] The code is on GitHub.

eBPF: Small programs that run inside the Linux kernel, but only within a checked, narrow frame. Like a bouncer you station at one particular door: he may turn people away there, but he may not rebuild the house.
Our take This fits the outage debate exactly. A shield is smaller than a patch and can be withdrawn. But it is still a change in the kernel, and the plan is for an AI (Codex) to write the shields. The agent side belongs in the ai-dev brief. For operators, the rule is: a shield doesn't replace the patch, it buys time.
[1] theregister.com (Nov 24)

CRA: The Dates From the Source

The EU Commission's fact page (as of Jul 27, 2026) gives the dates for the Cyber Resilience Act: reporting duties apply since Sep 11, 2026, the rules for conformity assessment bodies since Jun 11, 2026, and full application comes on Dec 11, 2027.[1]

Our take We stick with the Commission. So anyone selling software with digital elements in the EU already has a reporting duty when a flaw in their own product is exploited. December 2027 is the deadline for everything else, not for reporting.

Cisco Expressway and SAP don't affect most individual developers. Spring does.

It's Tuesday, November twenty-fourth. The catalog of exploited vulnerabilities is moving again, and Java developers have a big patch round to deal with.

At the top is Cisco Expressway. That's the gateway that lets video and voice connections through the firewall. According to heise, attackers can run commands as root without logging in, with a severity score of nine point eight. Since a sample exploit went public, the flaw has been under attack. Version X fifteen point five point twenty closes it. Anyone on an older version must migrate, according to Cisco. Cisco itself says it has no direct evidence of attacks.

Monday evening, the US agency CISA added two new flaws to its catalog: one in the mail filter N-able MailAssure and one in MONAI Label, a tool for medical imaging. The deadline is already Thursday. Notably, several entries from November twentieth and twenty-third got only three days.

SAP NetWeaver offers a lesson. The flaw has only a medium score of six point five, and the patch is a year old. It's under attack anyway. The score says how bad a flaw can be. The catalog says someone is using it right now.

For Java developers, Spring is the most important story. On November nineteenth, Spring published at least twenty-five advisories. For Spring Security, only two of eight fix versions are freely available, according to heise. And the embedded LDAP server for tests has fixed admin credentials and listens across the whole network. If you use it, check that today.

In Norway, according to The Register, attackers stole secrets from Azure API Management at two energy companies. The Classic instances are affected. The Norwegian authority advises swapping out all keys. And at the German software shop Cleverbridge, card data was stolen, security codes included. If you bought a license there, check your statement.

Microsoft has published its report on the big Exchange outage. A bug from July ran unnoticed for three months because the load tests ran on older hardware. In the US, the government is warning of more outages from rushed patches, according to heise. And with Shirudo, Cisco and OpenAI are proposing small protective programs in the Linux kernel that buy time until the patch.

Two clarifications. PostgreSQL fourteen is at its end of life, and version fifteen runs until November twenty twenty-seven, according to the official table. And under the European Cyber Resilience Act, the EU Commission says the reporting duty has applied since September of this year.

Tomorrow we'll see whether CISA adds more entries and which Spring versions the community actually gets.
