Drupal Core: the installer as a back door

The Drupal security team published SA-CORE-2026-017 (CVE-2026-132165) on Nov. 18, rated "Highly critical," now 20 of 25 points after the attack reports (18/25 at launch).[1] Drupal ships a file install.php. Under certain conditions, an attacker can use it to try to reinstall Drupal. According to the advisory, the result is a site takeover or code execution on the server.[1]

Affected: everything below 10.6.22, 11.0 up to below 11.3.22, and 11.4 up to below 11.4.13. The fixes are 11.4.13, 11.3.22 and 10.6.22. The 11.2.x and 10.5.x lines and older are end of life and get no fix.[1] The team has a report of attacks on real sites "as early as 2026-11-19 19:00 UTC," which is 4:00 p.m. Brasília time.[1] CISA added the flaw to the KEV catalog on Nov. 24. The deadline for US federal agencies is Friday, Nov. 27.[2]

KEV catalog: The list from the US agency CISA of flaws that are proven to be under attack. The deadline applies only to US federal agencies, but it is a good signal for everyone. Like a notice in the stairwell saying "There has been a break-in here": it does not say how bad the lock is, only that someone is picking it right now.

What helps without an immediate update: the advisory points to the guide for hardening the installer. Some, but not all, attack paths are blocked if the web server can neither write settings.php nor change its permissions.[1] The same day brought SA-CORE-2026-018 ("Moderately critical," 14/25): a gadget chain that is only usable together with a second deserialization flaw.[3]

Our take An installer on a production site is like a workshop key hanging on the outside of the car. The update is mandatory, but the real lesson applies to every PHP, Java or Node project: setup endpoints should be locked after installation, and the configuration should belong to the deploy user, not the web server. Anyone running 10.5 or 11.2 has had no patch problem since Nov. 18, but an upgrade problem.

Zstandard 1.6.0: buffer leftovers in the output

The Zstd team moved up version 1.6.0 to close a security hole.[2] The flaw is CVE-2026-124851.[1] According to heise, streaming decompression can let the contents of an internal buffer leak into the output. The buffer is 64 KiB in the default configuration. Versions 1.5.1 through 1.5.7 are affected. An attacker has to supply compressed data themselves and be able to see the output.[2] Neither source gives a CVSS score. The project writes: "updating to v1.6.0 is highly recommended."[1]

Streaming decompression with a memory leak: The program unpacks data piece by piece into an intermediate buffer. With broken input, it sometimes writes leftovers from that buffer into the output. Like a copier that prints a remnant of the previous job next to your page.

Two other changes affect operations. A default build no longer reads files compressed with Zstd before 0.8.0; ZSTD_LEGACY_SUPPORT turns that back on at compile time.[1][2] The CLI gets --patch-apply, and benchmark mode uses one thread by default.[1] On AArch64, 1.6.0 decompresses faster according to heise, and on RISC-V it uses the vector extension RVV. heise gives no figures.[2]

Our take The risky case is a service that accepts foreign compressed data and returns the result, such as an upload or proxy endpoint. There, a leftover from the memory of the previous request can end up with the attacker. The distribution package is the easy part. Harder are statically linked or bundled copies in images and language bindings. Only an SBOM scan finds those, not apt list.

vCenter: a two-and-a-half-month head start for the attackers

Update since Tue Yesterday this spot carried the expired KEV deadline. Google's report of 19 Nov gives the details first-hand: Google Threat Intelligence describes how the group ARMORY CASTLE exploited the flaw CVE-2026-123890 in early September 2026 with the tool BONESAW.[1] VMware only disclosed the flaw on Nov. 19. That is roughly two and a half months in which nobody could patch.

According to Google, the flaw is an "unauthenticated Secure Remote Password (SRP-6a) session key disclosure" over DCE/RPC. BONESAW uses it to fully take over vCenter appliances of versions 7.x and 8.x.[1] The bitter part: the attack also worked against a vCenter that was already patched against CVE-2026-59309 from July.[1] In this context Google also names a BeyondTrust zero-day, CVE-2026-102764, patched with BT26-05.[1] Google gives no CVSS score; the fix builds are in the Broadcom notice, which we did not read.

SRP-6a and DCE/RPC: SRP is a method by which client and server agree via a password without sending the password itself. At the end there is a shared session key. DCE/RPC is an old protocol for function calls over the network. The flaw reveals this key without a login, like a hotel that copies a guest's room key for anyone at the front desk.
Our take "Patched" is not an end state with vCenter. Anyone who has had a reachable vCenter since September should search the logs from September, not from Nov. 19. And vCenter belongs in a management network that is not reachable from the office network.
[1] cloud.google.com Threat Intelligence (retrieved Nov. 25)

Entra Connect Health: admin addresses leaked

Microsoft reports unauthorized access through a flaw in the Entra Connect Health API. According to heise, attackers read the email addresses of technical contacts and admin accounts of a tenant, plus configuration metadata.[1] Passwords, password hashes, tokens and Azure subscription data were not affected, per heise. The flaw had been in the code since July 23, 2026, per heise, and Microsoft found it on Nov. 9.[1]

Microsoft fixed the flaw on the server side. "IT administrators do not need to install a software update."[1] heise gives no CVE number.

Heads up A list of admin addresses is a phishing starter kit. Expect targeted emails "from Microsoft" to exactly these addresses. Microsoft recommends, per heise, checking the stored technical contacts and notification recipients.[1]
[1] heise.de (Nov. 24)

PostgreSQL: the REINDEX list from Nov. 12

The November update (18.7, 17.12, 16.16, 15.20, 14.25) fixes over 140 bugs. 14.25 is the last release for PostgreSQL 14.[1] The version number alone is not enough this time. Some fixes only prevent new damage; old damage you have to repair yourself. The release note lists these steps after the update:[1]

  • GIN indexes: rebuild if an index might be affected. The bugs can make rows disappear or foreign rows appear.
  • pg_trgm: rebuild all GiST indexes with gist_trgm_ops. This is mandatory, not optional.
  • bpchar without length: rebuild B-tree indexes. char(n) is not affected.
  • "missing chunk number": anyone who sees the error rebuilds the table with REINDEX TABLE.
  • Incremental backups: take a new full backup as the base after the update.
REINDEX: An index is a table's keyword register. If the register is wrong, the database does not find rows or finds the wrong ones. REINDEX throws the register away and rewrites it from the data. Like a book whose page numbers in the index have slipped: the text is right, only the lookup is not.

Anyone moving to PostgreSQL 19 (generally available since 19 Nov): with pg_upgrade, indexes for full-text search, pg_trgm and fuzzystrmatch may also need a REINDEX afterward.[1]

Our take pg_trgm sits in almost every "search with typos" feature. Anyone who updated by Docker tag has a new binary but old indexes. Nobody sees that until a customer asks why the search does not find them.
[1] postgresql.org release note (Nov. 12, retrieved Nov. 25)

CrowdStrike wants to buy Zscaler

CrowdStrike announced on Nov. 23 that it will acquire Zscaler, all-stock. Zscaler shareholders get 1.135 CrowdStrike shares per share. The enterprise value is "approximately $43.9 billion," a premium of about 34% over the Nov. 20 closing price.[1] After closing, existing CrowdStrike shareholders hold about 84.1%. Zscaler shareholders and regulators must approve. Closing is planned for the second half of CrowdStrike's fiscal 2028.[1]

Enterprise value: The price for the whole company, including debt and minus cash. Like buying a house: the price counts plus the mortgage you take on, minus the money still in the safe.
Our take CrowdStrike sits on the endpoint, Zscaler in the network path between user and internet. Together that is one vendor for both. For customers that means fewer agents on the laptop, but also more dependence on one vendor. That is a concentration risk that buyers will examine closely. Until closing, nothing changes for developers.
[1] sec.gov 8-K, press release (Nov. 23)

It's Wednesday, November twenty-fifth. The top story comes from the PHP world: a flaw in the Drupal installer is under attack, and the US agency CISA is giving just three days to fix it.

Drupal ships a file that starts a fresh installation. Under certain conditions, an attacker can use it to reinstall a running site and take it over. The Drupal team rates it highly critical, twenty out of twenty-five points. Real attacks have been going on since November nineteenth. The fixed versions are eleven point four point thirteen, eleven point three point twenty-two, and ten point six point twenty-two. Older lines get no fix.

Two more entries joined Drupal in the catalog: Optimizely Web Experimentation and the AntiCsrf library. The deadline for all three is Friday. Tomorrow, the deadlines for N-able MailAssure and MONAI Label run out.

The compression tool Zstandard has moved up version one point six. When data is decompressed in chunks, leftovers from an internal buffer can end up in the output. Versions one point five point one through one point five point seven are affected. It's most dangerous for services that accept compressed data from outsiders and return the result.

Google has published details on the vCenter campaign. The group ARMORY CASTLE used the flaw as early as September, two and a half months before the patch. The attack even hit servers that had the July patch. If you had a reachable vCenter, search your logs starting in September.

At Microsoft Entra Connect Health, according to heise, the email addresses of admins and technical contacts leaked. No update is needed; Microsoft fixed it on the server. But that list is a gift to phishers.

PostgreSQL users should look back at the November update. If you use the pg_trgm extension for typo-tolerant search, you need to rebuild the matching indexes. The same goes for indexes on bpchar columns without a length. And if you run incremental backups, take a new full backup.

In business news: CrowdStrike wants to buy Zscaler, all-stock, at an enterprise value of about forty-three point nine billion dollars. The deal still needs approvals and is planned for CrowdStrike's fiscal year twenty twenty-eight.
