DIGIT: One Flaw, Ten Countries

According to The Register, DIGIT is "a modular suite that offers common services", such as sign-in and payment collection for government agencies.[1] The platform is maintained by eGov India. Nine countries use parts of it; with India that makes ten, where more than 20,000 local governments use it.[1] The Register's line on this: "DIGIT is therefore used by governments that serve over two billion people."[1]

The flaw is CVE-2026-136706, a "9.3-rated SQL injection flaw" in the "User and Access Control Service" components.[1] India's CERT-In warns in CIVN-2026-0570: "An unauthenticated remote attacker could exploit this vulnerability by sending specially crafted input through the affected API endpoint."[1] eGov India published the fix as source code, in release v2.9.3.[1][2] CERT-In rates the flaw "HIGH" on Nov 25; according to the advisory, "DIGIT Core - version v2.9" is affected, and the solution is an upgrade to v2.9.3.[3] Neither the report nor CERT-In says whether anyone is attacking yet.[1][3]

SQL injection: The program builds a database query from text a user sends. If the attacker sends a piece of SQL instead of a name, the database runs it. Like an order slip where someone writes at the bottom "and give me the cash register key", and the waiter simply reads everything out loud.
Our take Two things are embarrassing here. First: SQL injection has been solved for two decades with parameterized queries; that it sits in the sign-in service in 2026 is a review failure. Second: a shared platform for many states saves money, but every flaw hits all of them at once. Whoever runs DIGIT needs v2.9.3. Whoever builds a toolkit for many customers should check the auth path first.

Drupal: The Deadline Is Today

Update since Thu The CISA deadline for CVE-2026-132165 in Drupal Core ends today, Nov 27.[1] Drupal advisory SA-CORE-2026-017 from Nov 18 rates the flaw "Highly critical", risk score 20 out of 25.[2] According to the security team it was "exploited on live sites as early as 2026-11-19 19:00 UTC", that is 4:00 PM Brasília.[2] The fixes:

  • Drupal 11.4.x: update to 11.4.13
  • Drupal 11.3.x: update to 11.3.22
  • Drupal 10.6.x: update to 10.6.22

On the same day the deadline ends for two more KEV entries from Nov 24: Optimizely Web Experimentation (CVE-2026-132224) and Idunno AntiCsrf (CVE-2026-131914).[1]

Our take A week of active attacks on a Highly critical advisory: whoever has not updated yet should not only patch, but also check the logs from Nov 19 onward for unknown admin accounts and new PHP files.

PAN-OS: The Kernel Fixes Are Here

Update since Thu On Nov 26, heise describes the chain we explained yesterday: "Currently, attackers are combining two security flaws to attack Palo Alto firewalls."[1] First PHP2Shell (CVE-2026-109618, "critical") through a management interface reachable from the internet. Then Fragnesia (CVE-2026-46300, "high").[1] Palo Alto itself rates CVE-2026-109618 at CVSS 4.0 9.2 (critical); the vendor lists Fragnesia in bulletin PAN-SA-2026-0015 as "Informational", with no CVSS score.[2][3] Important context: Fragnesia is not a PAN-OS flaw of its own, but a bug in the Linux kernel that PAN-OS runs on. On its own it cannot be exploited remotely; it only raises the privileges of an attacker who is already inside.[1]

According to heise, researchers at Dream reported 25 compromised firewalls in October, presumably by Chinese attackers. CISA added CVE-2026-46300 to the KEV catalog on Oct 28.[1] New is the list of builds with the kernel fix: heise names 20 releases across all lines, from 10.2.7-h41 to 12.2.4-h3.[1] Whoever already has the PHP2Shell patch is protected against this attack path. heise still recommends the kernel fix.[1]

Heads up Dataplane interfaces with a management profile also count as open management. heise advises: turn off public access; if there is no other way, allow only HTTPS and SSH, and only from trusted internal IPs.[1]

Rackspace Spot: The Way In Was the Monitoring

Update since Thu The Register reports new details on the breach at Rackspace's Kubernetes service Spot. On Nov 17 the attacker had access for almost 22 hours, using stolen credentials.[1] He "could have read any Secret in an affected user's clusters, and any Spot API token or refresh token that user held".[1] The cause according to a Platform9 co-founder: "An observability system was breached using a compromised credential."[1] Rackspace does not say how many customers are affected. Spot ends on Dec 8 at 5:00 PM Central Time, that is 8:00 PM Brasília.[1]

Observability system: The software that collects logs, metrics and traces from all clusters so the operations team can see what is running. To see everything, it gets broad read permissions. Like the janitor with the master key: he has to get in everywhere, and so does anyone who steals his key.
Our take The second case in two days, after 1Password, where the entry point was not the product but the tooling around it. Monitoring agents need metrics, not secrets. Whoever has Prometheus, Grafana Agent or Datadog in the cluster: check whether their ServiceAccount may read secrets. For metrics it rarely needs that.

Windows Server 2025: A Hotpatch for the Hotpatch

On Nov 25 Microsoft released KB5138318 out of band.[1] It fixes a bug from the November hotpatch KB5131077 (OS Build 26100.33730) of Nov 10.[1][2] Servers with Router Advertisements enabled that receive time-limited IPv6 routes crash when a route's timer expires. The stop code: "0x139 (KERNEL_SECURITY_CHECK_FAILURE)".[1] The fix "takes effect without requiring a restart".[1] Microsoft does not explain the actual programming error.[1]

Hotpatch: An update that swaps the running code in memory without a restart. Like changing a tire while driving: handy, as long as the new tire fits. Here it did not, and the server stopped as soon as an IPv6 route expired.
Our take Hotpatching saves maintenance windows, but not testing. A bug that only appears when a route timer expires does not show up in a smoke test right after the update. For IPv6 networks with RA that means: run a canary server for a day first.

Zstandard 1.6.0: Memory Leftovers in the Output

The Zstandard team moved up version 1.6.0 to close CVE-2026-124851.[1] Versions 1.5.1 to 1.5.7 are affected: "When decompressing manipulated data, affected versions can expose memory contents."[1] With streaming decompression, the content of an internal buffer (64 KiB by default) can end up in the output, including leftovers from an earlier decompression in the same context. The attacker must supply compressed data and be able to see the output.[1] heise gives no CVSS score.[1]

In addition, 1.6.0 brings faster decompression on AArch64 and RVV support on RISC-V. Careful when upgrading: a default build no longer reads files compressed with Zstd before 0.8.0; ZSTD_LEGACY_SUPPORT brings that back.[1]

Our take This matters for services that decompress third-party compressed data and return the result, such as upload previews or proxies. Zstd usually sits as a system library or in language bindings; the fix therefore arrives through the distribution, not through your package.json.
[1] heise.de (Nov 24, 10:09 AM)

Data Leaks: Deichmann and FIFA

Deichmann

The shoe retailer reports access to "selected customer data on purchases in our online shop".[1] Affected are name, billing and delivery address, invoices, email, phone and the chosen payment method. Passwords, login data and payment data such as credit card numbers are not affected, according to Deichmann.[1] The company does not say which flaw was exploited, only that it is closed. It gives no number of people affected.[1]

Heads up Real order data makes fraud emails believable. Deichmann says its own bank details have not changed and that it never asks for passwords.[1]

FIFA

An attack led to "unauthorized access to a limited amount of personal and business data" at FIFA.[2] According to heise, Reuters speaks of "less than 0.1 percent of total data holdings". A group called Handsome Boy Hacking Club has claimed responsibility, according to The Record; this is not independently confirmed.[2] Which systems are affected is open.

Stack Check: PostgreSQL 14 Has Reached the End

PostgreSQL 19 has been generally available since Nov 19.[2] For your own stack, though, this counts: with the Nov 12 update (18.7, 17.12, 16.16, 15.20, 14.25 and 19 RC2), 14.25 was the last release for PostgreSQL 14.[1] The next scheduled minor release comes on Feb 11, 2027.[2] Whoever still runs 14 gets no more fixes then. The November round fixed 52 security vulnerabilities, including CVE-2026-6460, a type confusion after ALTER ... SET DATA TYPE with CVSS 8.8.[1]

For Caddy users: current is 2.11.9 from Nov 5, according to the release notes "a quick follow-up on top of 2.11.8, to fix a regression it introduced and a few more security issues".[3]

Our take The upgrade from 14 to 18 or 19 with pg_upgrade is usually one evening of work. February is a good deadline for it, before the first unpatched flaw arrives.

It's Friday, November twenty-seventh, the day after Thanksgiving. The news is quiet, but one story stands out. It comes from India.

DIGIT is a toolkit for digital government, with services like sign-in and payments. According to The Register, ten countries use it, and their governments serve more than two billion people combined. The user and access control services contain a SQL injection rated nine point three out of ten. An attacker doesn't need to log in, just send a crafted request to the API. The fix is in version two point nine point three. Whether anyone is attacking yet is not known.

Today is the deadline set by the U.S. agency CISA for the Drupal flaw. The fixes are Drupal eleven point four point thirteen, eleven point three point twenty-two and ten point six point twenty-two. Attacks have been running since November nineteenth. More deadlines end tomorrow, including Mitel MiCollab, Danfoss, Xen Orchestra and Juniper. There have been no new entries since Wednesday.

On the Palo Alto firewalls, heise now lists the versions with the kernel fix against Fragnesia. Fragnesia is a flaw in the Linux kernel that PAN-OS runs on. Combined with PHP2Shell, it gives attackers full control, but only if the management interface is reachable from the internet.

Rackspace has named the cause of the Spot breach. The attacker got in through a monitoring system with a stolen credential and was inside for almost twenty-two hours. He could read every secret in the affected clusters. Spot shuts down on December eighth.

Microsoft is fixing a hotpatch with a hotpatch. The November patch for Windows Server twenty twenty-five crashed servers as soon as a time-limited IPv6 route expired. The fix needs no restart. Also, Zstandard version one point six closes a flaw that let leftover memory leak into the output when decompressing.

In Germany, Deichmann reports access to customer data from its online shop, including names, addresses and invoices, but no passwords or card data. FIFA also confirms an attack. And the Ladybird browser now runs on Rust, but explicitly offers no security guarantee.

One last reminder: PostgreSQL fourteen no longer gets updates. The next security update in February will come without that version. Tomorrow we'll see whether DIGIT sees its first attacks and whether CISA adds new entries after the holiday.
