La cuenta de Microsoft en PyPI distribuye malware

Por la cuenta oficial de Microsoft en PyPI salieron las versiones 1.26.1 y 1.26.2 del Agent Framework, una biblioteca para construir agentes de IA. Según heise, "el malware está en las versiones 1.26.1 y 1.26.2".[1] Microsoft revirtió la 1.26.1 a la 1.26.0 limpia, tras lo cual los atacantes subieron la 1.26.2.[1] Según Wiz, la 1.26.1 se publicó el martes 17/11 a las 20:35 UTC y la 1.26.2 hacia las 21:08 UTC; para alrededor de las 21:30 UTC PyPI había retirado ambas.[3] El paquete tiene "en promedio unas 200.000" descargas al mes.[1] Lo descubrieron OX Security y OpenSourceMalware.[2]

El truco: la versión 1.26.1 deja los archivos agent_framework_meta.pth y agent_framework_meta/_telemetry.py, la 1.26.2 deja af_runtime_diag.pth y af_runtime_diag.py. El archivo .pth se ejecuta cada vez que arranca Python, incluso sin import.[1][3] Para revisar, busca ambas variantes en la carpeta site-packages. Luego el malware busca credenciales de Azure, Git, Docker y Hugging Face, según Baguete solicita nuevos tokens de identidad en GitHub Actions, Azure DevOps y Azure, y envía todo cifrado hacia afuera.[2] Wiz atribuye el robo de tokens OIDC de GitHub Actions solo a la 1.26.2.[3] Cómo llegaron los atacantes a la cuenta no está confirmado; OX Security sospecha de inicios de sesión robados de Microsoft.[1] Microsoft investiga el caso y puso en privado algunos repositorios de GitHub.[1]

Archivo .pth: Un pequeño archivo de texto en la carpeta site-packages. Python lo lee en cada arranque para definir rutas de búsqueda. Si hay en él una línea que empieza con import, Python la ejecuta. Es como una nota en el refrigerador que todo compañero de casa cumple automáticamente por la mañana, aunque nunca haya querido entrar a la cocina.
Nuestra opinión Este es el punto más importante del día, también para quien no tiene proyecto de IA. Un paquete con Microsoft como remitente es justo lo que nadie revisa. El daño ocurre en CI: ahí están los tokens que busca esa cosa. Quien usa lockfiles de Python con hashes (pip install --require-hashes o uv lock) estaba protegido. Quien construye con >= sin lock debería buscar estas dos versiones en builds, lockfiles y cachés desde el martes 17/11 y luego rotar todos los secretos que el runner pudo ver. El lado de IA del framework corresponde al brief ai-dev.

Se publicó PostgreSQL 19

Actualización desde el jueves Ayer aquí decía "debe salir hoy". Ahora ya está: el PostgreSQL Global Development Group anunció el 19/11 el lanzamiento de PostgreSQL 19.[1] Los puntos destacados según el anuncio:

  • Verificaciones de llave foránea más rápidas: en la prueba, los inserts masivos quedaron "nearly 2x faster".[1]
  • REPACK (CONCURRENTLY): reorganizar tablas sin molestar la operación en curso.[1]
  • INSERT ... ON CONFLICT DO SELECT: RETURNING devuelve también la fila ya existente, es decir, "get or create" en una sola instrucción.[1]
  • WAIT FOR LSN: "read-your-writes" en standbys; además la extensión pg_stash_advice, que guarda sugerencias de plan por query.[1]
  • Replicación y TLS: el primer slot lógico sube el nivel del WAL automáticamente; el servidor puede mostrar un certificado propio por hostname mediante SNI.[1]

Atención a los cambios: la autenticación RADIUS se eliminó, el JIT ahora viene apagado por defecto y, tras un inicio de sesión md5 exitoso, aparece una advertencia porque md5 desaparecerá en una versión posterior.[1]

REPACK: Con el tiempo, una tabla junta huecos de filas borradas, como un librero con espacios vacíos. VACUUM FULL ordena, pero bloquea todo el librero. REPACK (CONCURRENTLY) reacomoda mientras los demás siguen sacando libros.
Nuestra opinión ON CONFLICT DO SELECT es la función que la gente de backend espera desde hace años; el rodeo habitual con CTE y un segundo SELECT desaparece. Aun así: no pongan la 19.0 en producción el primer día. Antes revisen el pg_hba.conf por md5 y RADIUS, y prueben las consultas que se beneficiaban del JIT. La actualización minor del 12/11 con 52 CVE va primero.

PHP 8.6.0 y un día pesado de seguridad

El 19/11 salieron cinco releases de PHP a la vez: el nuevo major 8.6.0 y las actualizaciones de seguridad 8.5.13, 8.4.28, 8.3.37 y 8.2.36.[1] El día anterior, php.net había anunciado un "Upcoming Critical PHP Security Release".[1] Según heise, las actualizaciones cierran 17 fallas, siete de ellas con CVSS 9,2; las críticas, sin embargo, requieren configuraciones especiales.[2] El conteo no es uniforme: el changelog de php.net lista 18 ID de CVE, el titular de heise habla de cinco fallas con ejecución de código, la URL de cuatro.[2][3]

El propio PHP 8.6 trae aplicación parcial de funciones con marcadores ?, una clase \Time\Duration, la API Io\Poll como base para event loops como ReactPHP y AMPHP, una función clamp(), un enum SortDirection y valores por defecto para propiedades readonly.[4]

Nuestra opinión La actualización de seguridad es obligatoria, la 8.6 es opcional. heise escribe: "Los administradores deberían actualizar pronto sus instalaciones de PHP."[2] Quien está en la 8.2 todavía recibe los parches. Io\Poll es la pieza más interesante, porque sustituye a stream_select() con sus límites.

ruby2ßhell: 21 ß y una codificación

Ruby publicó el 18/11 las versiones 4.0.10, 3.4.13 y 3.3.14. Según ruby-lang.org hay "seven vulnerabilities" en el motor de regex y en el manejo de mayúsculas y minúsculas de strings; la recomendación es "We strongly recommend upgrading."[1] El nombre "ruby2ßhell" se lo puso Veria Labs a una de ellas. Según heise, resultan afectadas las apps que procesan strings en codificación ISO-8859 o Windows-125x con upcase, swapcase, downcase(:fold) o casecmp?; Rails y Sinatra en su configuración clásica estarían afectados.[2]

"Todavía no se asignó un número CVE", solo existe el advisory de GitHub GHSA-34m4-m9fh-gqp5.[2] No se conocen ataques, y heise cita: "Esto no es un ataque terminado". Veria Labs quiere mostrar una PoC en cerca de una semana.[2] Según el advisory de Ruby, los mantenedores conocen PoCs que demuestran ejecución remota de código para algunas de las fallas.[3] Los detalles técnicos de ruby2ßhell solo los leímos en heise, no en el advisory mismo.

¿Por qué justo la ß? En mayúsculas, "ß" se convierte en "SS", o sea, de un carácter salen dos. Un string queda más largo tras la conversión de lo que era antes. Nuestra suposición (no de la fuente): saltos de longitud como estos son el lugar clásico en que el código escribe más allá del final de un búfer. Las 21 ß vienen del título del hallazgo.

nginx: diez CVE en un release

nginx.org informa para el 18/11 las versiones 1.30.7 (stable) y 1.31.9 (mainline) con correcciones para diez fallas, entre ellas use-after-free en el resolver, en HTTP/2, HTTP/3 y en el proxy de correo, una corrupción de memoria en el control de flujo de HTTP/2 y un desbordamiento de búfer con alias y try_files.[1] Según heise, "cinco de ellas a la vez" tienen CVSS 4.0 con 9,2, y dos errores están en el código desde 2007.[2] Los valores CVSS vienen solo de heise; nginx.org no da puntuaciones. No hay reporte de ataques.

Nuestra opinión Es el segundo gran release de seguridad de nginx en cinco semanas: el 14/10 ya habían salido cinco correcciones.[1] Quien usa nginx de la distribución espera el backport; quien usa el repo upstream actualiza como de costumbre. Para usuarios de Caddy: ahí la 2.11.9 del 05/11 es la vigente, con correcciones de seguridad "mostly in FastCGI".[3]

BSI: "tensa a crítica" [1]

El BSI elevó el 19/11 su evaluación de la situación a "tensa a crítica", según heise por primera vez desde 2023. heise menciona unas 160 vulnerabilidades nuevas al día (35 por ciento más). El tiempo entre la publicación de una falla y el primer exploit sería en promedio de unos 25 días, en el segundo trimestre de 2026 de unos ocho días; un año antes eran cerca de 53. El 88 por ciento de los dispositivos infectados serían Android; BadBox contaría unos 30.000 dispositivos en Alemania, Vo1d más de 10.000. No cargamos el comunicado original del BSI.

Nuestra opinión Ocho días hasta el exploit, ese es el número que cuenta. Un ciclo mensual de parches es, por tanto, demasiado lento para cualquier cosa con acceso a internet. No es motivo de pánico, pero sí un buen argumento a favor de actualizaciones minor automáticas y de Renovate o Dependabot con auto-merge para parches.

Comisión Europea: ¿ataque con herramienta de pentest? [1]

La Comisión Europea descubrió el ataque el 22/10 y lo confirmó el 26/10. Lo que vale el viernes

Tres tareas antes del fin de semana: buscar en los logs de CI agent-framework 1.26.1 o 1.26.2 y, si hay coincidencia, rotar los secretos. Meter las actualizaciones de PHP, Ruby y nginx en el ciclo normal. Y planear una prueba para PostgreSQL 19, no la migración a producción.

Hoy es viernes veinte de noviembre. Ayer hubo dos grandes lanzamientos, y salió a la luz un incidente serio en la cadena de suministro.

Primero el incidente. Por la cuenta oficial de Microsoft en PyPI salieron, ya el martes por la noche, dos versiones infectadas del Agent Framework, la uno punto veintiséis punto uno y la uno punto veintiséis punto dos. Según heise, el paquete se descarga unas doscientas mil veces al mes. El malware arranca con cada proceso de Python y busca credenciales de Azure, Git, Docker y Hugging Face, además de tokens de GitHub Actions. Nuestra opinión: si desde el martes construyeron sin lockfile, revisen los logs de build y roten los secretos.

La buena noticia: ya salió PostgreSQL diecinueve. Las verificaciones de llave foránea son más rápidas, y en la prueba los inserts masivos casi duplicaron su velocidad. Llegan REPACK con la base en operación y ON CONFLICT DO SELECT para el clásico buscar o crear. El JIT ahora viene apagado por defecto, y RADIUS se eliminó. Nuestro consejo: probar primero, no llevarlo a producción el primer día.

También llegó PHP ocho punto seis, junto con actualizaciones de seguridad para las versiones ocho punto dos a ocho punto cinco. Según heise, cierran diecisiete fallas, siete de ellas con nueve coma dos de diez puntos, aunque solo en configuraciones especiales.

Ruby cerró siete fallas. Una se llama ruby2ßhell, porque al poner en mayúscula la ese alemana salen dos caracteres. Resultan afectadas las apps con codificaciones antiguas como ISO-8859. Se espera una prueba de concepto en cerca de una semana. A eso se suman nginx con diez fallas y WordPress con veinte.

El BSI elevó su evaluación a tensa a crítica, por primera vez desde dos mil veintitrés. Según heise, ahora pasan en promedio solo unos ocho días hasta que se explota una falla nueva. Y el software de blogs Apache Roller ya está bajo ataque activo, según sus desarrolladores.

Para quienes usan Windows: PowerShell cinco punto uno está en desuso. Windows once veintiséis H dos y Server dos mil veinticinco son las últimas versiones con el cinco punto uno integrado. En la Comisión Europea continúa la investigación de un ciberataque en el que la sospecha recae sobre una herramienta de pentest con IA de acceso libre.

La próxima semana veremos si por fin sale Spring Boot cuatro punto dos, y si llega la prueba de concepto anunciada para Ruby. El sábado vencen los plazos de Apache Axis, REDCap y Synology en el catálogo de fallas explotadas activamente.
