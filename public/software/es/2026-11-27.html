DIGIT: una vulnerabilidad, diez países

Según The Register, DIGIT es "a modular suite that offers common services", por ejemplo inicio de sesión y cobro de pagos para dependencias de gobierno.[1] La plataforma la mantiene eGov India. Nueve países la usan en parte; con India son diez, y allí la utilizan más de 20.000 administraciones locales.[1] La frase de The Register al respecto: "DIGIT is therefore used by governments that serve over two billion people."[1]

La vulnerabilidad se llama CVE-2026-136706, una "9.3-rated SQL injection flaw" en los componentes "User and Access Control Service".[1] El CERT-In de India advierte en CIVN-2026-0570: "An unauthenticated remote attacker could exploit this vulnerability by sending specially crafted input through the affected API endpoint."[1] eGov India publicó la corrección como código fuente, en el release v2.9.3.[1][2] El CERT-In clasifica la vulnerabilidad como "HIGH" el 25/11; según el aviso, la versión afectada es "DIGIT Core - version v2.9", y la solución es actualizar a v2.9.3.[3] Si alguien ya está atacando, ni el reporte ni el CERT-In lo dicen.[1][3]

Inyección SQL: El programa arma una consulta a la base de datos con texto que envía un usuario. Si el atacante, en lugar de un nombre, manda un pedazo de SQL, la base de datos lo ejecuta. Como una comanda a la que alguien le escribe abajo "y dame la llave de la caja", y el mesero lee todo en voz alta.
Nuestra opinión Aquí hay dos cosas vergonzosas. Primera: la inyección SQL está resuelta desde hace dos décadas con consultas parametrizadas; que en 2026 siga en el servicio de inicio de sesión es un fallo de revisión. Segunda: una plataforma común para muchos estados ahorra dinero, pero cada error los golpea a todos al mismo tiempo. Quien opere DIGIT necesita la v2.9.3. Quien construya un kit para muchos clientes debería revisar primero la ruta de autenticación.

Drupal: el plazo es hoy

Actualización desde el jue El plazo de CISA para CVE-2026-132165 en Drupal Core vence hoy, 27/11.[1] El aviso de Drupal SA-CORE-2026-017 del 18/11 clasifica la vulnerabilidad como "Highly critical", con un valor de riesgo de 20 de 25.[2] Según el equipo de seguridad, fue "exploited on live sites as early as 2026-11-19 19:00 UTC", es decir, las 16:00 hora de Brasilia.[2] Las correcciones:

  • Drupal 11.4.x: actualizar a 11.4.13
  • Drupal 11.3.x: actualizar a 11.3.22
  • Drupal 10.6.x: actualizar a 10.6.22

El mismo día vence el plazo de otras dos entradas del KEV del 24/11: Optimizely Web Experimentation (CVE-2026-132224) e Idunno AntiCsrf (CVE-2026-131914).[1]

Nuestra opinión Una semana de ataques activos con un aviso Highly critical: quien hoy aún no haya actualizado no solo debería parchar, sino también revisar los registros desde el 19/11 en busca de cuentas de administrador ajenas y archivos PHP nuevos.

PAN-OS: ya están las correcciones del kernel

Actualización desde el jue heise describe el 26/11 la cadena que explicamos ayer: "Actualmente los atacantes combinan dos vulnerabilidades para atacar firewalls de Palo Alto."[1] Primero PHP2Shell (CVE-2026-109618, "crítica") a través de una interfaz de administración accesible desde internet. Después Fragnesia (CVE-2026-46300, "alta").[1] La propia Palo Alto califica CVE-2026-109618 con CVSS 4.0 de 9,2 (crítica); el fabricante clasifica Fragnesia en el boletín PAN-SA-2026-0015 como "Informational", sin valor CVSS.[2][3] Importante para ubicarla: Fragnesia no es una vulnerabilidad propia de PAN-OS, sino un error del kernel de Linux sobre el que corre PAN-OS. Por sí sola no se puede explotar de forma remota; solo eleva los privilegios de un atacante que ya está dentro.[1]

Según heise, investigadores de Dream reportaron en octubre 25 firewalls comprometidos, presuntamente por atacantes chinos. CISA agregó CVE-2026-46300 al catálogo KEV el 28/10.[1] Lo nuevo es la lista de builds con la corrección del kernel: heise menciona 20 versiones en todas las líneas, desde 10.2.7-h41 hasta 12.2.4-h3.[1] Quien ya tenga el parche de PHP2Shell está protegido contra esa vía de ataque. Aun así, heise recomienda la corrección del kernel.[1]

Atención También las interfaces de plano de datos con perfil de administración cuentan como administración expuesta. heise aconseja: desactivar el acceso público; si no hay otra opción, solo HTTPS y SSH y solo desde IP internas de confianza.[1]

Rackspace Spot: la puerta de entrada fue el monitoreo

Actualización desde el jue The Register da nuevos detalles sobre la intrusión en Spot, el servicio de Kubernetes de Rackspace. El atacante tuvo acceso el 17/11 durante casi 22 horas, con credenciales robadas.[1] Él "could have read any Secret in an affected user's clusters, and any Spot API token or refresh token that user held".[1] La causa, según un cofundador de Platform9: "An observability system was breached using a compromised credential."[1] Cuántos clientes están afectados, Rackspace no lo dice. Spot termina el 08/12 a las 17:00 hora del centro (CT), es decir, las 20:00 hora de Brasilia.[1]

Sistema de observabilidad: El software que recopila logs, métricas y trazas de todos los clústeres para que el equipo de operaciones vea qué está corriendo. Para poder verlo todo, recibe amplios permisos de lectura. Como el conserje con la llave maestra: tiene que entrar a todos lados, y quien le robe la llave también.
Nuestra opinión Segundo caso en dos días, después de 1Password, en el que la puerta de entrada no fue el producto sino la herramienta que lo rodea. Los agentes de monitoreo necesitan métricas, no secretos. Si tienen Prometheus, Grafana Agent o Datadog en el clúster: revisa si tu ServiceAccount puede leer secrets. Para métricas casi nunca lo necesita.

Windows Server 2025: un hotpatch para el hotpatch

Microsoft publicó el 25/11, fuera de ciclo, KB5138318.[1] Repara un error del hotpatch de noviembre KB5131077 (OS Build 26100.33730) del 10/11.[1][2] Los servidores con Router Advertisements activados que reciben rutas IPv6 de duración limitada se caen en cuanto vence el temporizador de una ruta. El código de detención: "0x139 (KERNEL_SECURITY_CHECK_FAILURE)".[1] La corrección "takes effect without requiring a restart".[1] Microsoft no explica el error de programación en sí.[1]

Hotpatch: Una actualización que reemplaza el código en ejecución en la memoria, sin reiniciar. Como cambiar una llanta con el carro en marcha: práctico, mientras la llanta nueva sea la correcta. Aquí no lo fue, y el servidor se detuvo en cuanto expiró una ruta IPv6.
Nuestra opinión El hotpatching ahorra ventanas de mantenimiento, pero no las pruebas. Un error que solo aparece cuando vence el temporizador de una ruta no se ve en la prueba de humo justo después de la actualización. Para redes IPv6 con RA, esto significa: primero dejar un servidor canario corriendo un día.

Zstandard 1.6.0: restos de memoria en la salida

El equipo de Zstandard adelantó la versión 1.6.0 para cerrar CVE-2026-124851.[1] Están afectadas las versiones 1.5.1 a 1.5.7: "Al descomprimir datos manipulados, las versiones afectadas pueden revelar contenido de la memoria."[1] En la descompresión en streaming, el contenido de un búfer interno (por defecto 64 KiB) puede llegar a la salida, incluso restos de una descompresión anterior en el mismo contexto. El atacante debe proporcionar datos comprimidos y poder ver la salida.[1] heise no menciona ningún valor CVSS.[1]

Además, la 1.6.0 trae una descompresión más rápida en AArch64 y soporte de RVV en RISC-V. Ojo al actualizar: un build estándar ya no lee archivos comprimidos con Zstd anterior a 0.8.0; ZSTD_LEGACY_SUPPORT lo recupera.[1]

Nuestra opinión Es relevante para servicios que descomprimen datos comprimidos ajenos y devuelven el resultado, por ejemplo vista previa de cargas o proxies. Zstd suele venir como biblioteca del sistema o en bindings de lenguajes; la corrección llega por la distribución, no por tu package.json.

Filtraciones de datos: Deichmann y FIFA

Deichmann

La zapatería reporta un acceso a "datos seleccionados de clientes sobre compras en nuestra tienda en línea".[1] Están afectados nombre, dirección de facturación y de envío, facturas, correo electrónico, teléfono y la forma de pago elegida. Contraseñas, datos de acceso y datos de pago como números de tarjeta de crédito no están afectados, según Deichmann.[1] Qué vulnerabilidad se explotó, la empresa no lo dice, solo que ya está cerrada. Tampoco menciona cuántas personas están afectadas.[1]

Atención Los datos reales de pedidos hacen creíbles los correos de fraude. Deichmann dice que su propia cuenta bancaria no cambió y que nunca piden contraseñas.[1]

FIFA

Un ataque provocó en la FIFA un "acceso no autorizado a una cantidad limitada de datos personales y comerciales".[2] Según heise, Reuters habla de "menos del 0,1 por ciento del total de los datos". Un grupo llamado Handsome Boy Hacking Club se atribuyó el ataque, según The Record; no está confirmado de forma independiente.[2] Qué sistemas están afectados sigue sin saberse.

Navegadores: Ladybird en Rust, actualizaciones de Chrome

Ladybird

Actualización desde el jue The Register complementa la nota de ayer sobre la alfa. El líder del proyecto, Andreas Kling, migró el motor en 2026 de Swift a Rust.[1] Los paquetes: macOS para Apple Silicon con 68,4 MB, Linux x86-64 como Flatpak con unos 111 MB, además de paquetes para Ubuntu y Fedora.[1] El proyecto dice abiertamente que "make[s] no security guarantees at this stage". Desde junio ya no acepta contribuciones públicas de código.[1]

Nuestra opinión Para pruebas de frontend, Ladybird ya es una herramienta real. Para navegar con el login del banco, expresamente no lo es. El freno a las contribuciones externas no cuadra con la imagen de código abierto; conviene seguirlo de cerca.

Revisión del stack: PostgreSQL 14 llegó a su fin

PostgreSQL 19 tiene disponibilidad general desde el 19/11.[2] Pero para tu propio stack cuenta esto: con la actualización del 12/11 (18.7, 17.12, 16.16, 15.20, 14.25 y 19 RC2), 14.25 fue el último release de PostgreSQL 14.[1] La siguiente versión menor programada llega el 11/02/2027.[2] Quien siga en la 14 ya no recibirá correcciones. La ronda de noviembre corrigió 52 vulnerabilidades de seguridad, entre ellas CVE-2026-6460, una confusión de tipos tras ALTER ... SET DATA TYPE con CVSS 8,8.[1]

Para usuarios de Caddy: la versión actual es la 2.11.9 del 05/11, según las notas del release "a quick follow-up on top of 2.11.8, to fix a regression it introduced and a few more security issues".[3]

Nuestra opinión La actualización de 14 a 18 o 19 con pg_upgrade suele ser el trabajo de una tarde. Febrero es un buen plazo para hacerlo, antes de que aparezca la primera vulnerabilidad sin parchar.

Hoy es viernes veintisiete de noviembre, el día después de Thanksgiving. El panorama noticioso es tranquilo, pero una historia destaca. Viene de India.

DIGIT es un kit para la administración digital, con servicios como inicio de sesión y pagos. Según The Register, lo usan diez países, cuyos gobiernos atienden en conjunto a más de dos mil millones de personas. En los servicios de usuarios y control de acceso hay una inyección SQL con nueve punto tres de diez puntos. Un atacante no necesita iniciar sesión, solo una solicitud manipulada a la interfaz. La corrección está en la versión dos punto nueve punto tres. Se desconoce si alguien ya está atacando.

Hoy vence el plazo de la agencia estadounidense CISA para la vulnerabilidad de Drupal. Las correcciones son Drupal once punto cuatro punto trece, once punto tres punto veintidós y diez punto seis punto veintidós. Los ataques corren desde el diecinueve de noviembre. Mañana vencen otros plazos, entre otros para Mitel MiCollab, Danfoss, Xen Orchestra y Juniper. Desde el miércoles no hubo entradas nuevas.

Sobre los firewalls de Palo Alto, heise menciona ahora las versiones con la corrección del kernel contra Fragnesia. Fragnesia es una vulnerabilidad del kernel de Linux sobre el que corre PAN-OS. Junto con PHP2Shell da a los atacantes el control total, pero solo si la administración es accesible desde internet.

Rackspace revela la causa de la intrusión en Spot. El atacante entró por un sistema de monitoreo con un acceso robado y estuvo dentro casi veintidós horas. Pudo leer todos los Secrets de los clústeres afectados. Spot se apaga el ocho de diciembre.

Microsoft repara un hotpatch con otro hotpatch. El parche de noviembre para Windows Server dos mil veinticinco hacía que los servidores se cayeran en cuanto vencía una ruta IPv6 de duración limitada. La corrección no requiere reinicio. Además, Zstandard cierra en su versión uno punto seis una vulnerabilidad por la que, al descomprimir, restos de memoria llegaban a la salida.

En Alemania, Deichmann reporta un acceso a datos de clientes de la tienda en línea, con nombres, direcciones y facturas, pero sin contraseñas ni datos de tarjetas. También la FIFA confirma un ataque. Y el navegador Ladybird ahora corre sobre Rust, pero expresamente no da ninguna garantía de seguridad.

Para terminar, un recordatorio: PostgreSQL catorce ya no recibe actualizaciones. La próxima actualización de seguridad, en febrero, llega sin esa versión. Mañana veremos si hay primeros ataques a DIGIT y si CISA agrega entradas nuevas después del feriado.
