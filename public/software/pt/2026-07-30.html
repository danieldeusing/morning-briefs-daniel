Node.js: os releases chegaram — dois dias depois e com onze números

Atualização desde seg O anúncio era para segunda-feira, 27/07, "ou logo depois". Saíram na quarta-feira, 29/07: v22.23.2, v24.18.1 e v26.5.1, juntos onze CVEs.[1] Três são HIGH, e as três ficam exatamente onde uma aplicação Node fica exposta ao mundo externo: CVE-2026-56846 contorna a opção HTTP/2 maxSessionMemory, CVE-2026-56848 é um use-after-free na mesma pilha, e CVE-2026-58043 concede mais permissões do que as solicitadas no Permission Model — justo no mecanismo usado para restringir o Node de propósito.

maxSessionMemory: O HTTP/2 mantém várias requisições paralelas numa única conexão. Para que o outro lado não sobrecarregue o servidor com cabeçalhos, dá para definir um orçamento de memória por conexão — como um hidrômetro na entrada de uma casa: passa mais do que o combinado, e corta. O bug é que o medidor não conta uma parte do fluxo.

Mais relevante no dia a dia, na minha opinião, é a falha de severidade média: CVE-2026-58040 faz o agente HTTPS pular a verificação do hostname — o certificado é válido, só que para outra pessoa, e é exatamente essa checagem que separa TLS de teatro. Some a isso CVE-2026-58041 (reuso de iterador no node:sqlite), CVE-2026-58042 (interrupção de dns.resolveAny() como DoS) e CVE-2026-58044 (request smuggling via cabeçalhos truncados, LOW).[1]

A parte prática não está no advisory: na maioria das instalações, o Node não chega via apt, mas como imagem base de container. Quem só atualiza o runtime no laptop não tocou no registry — o node:22 da semana passada continua em cada imagem derivada dali. Para toolchains de Angular e TypeScript, isso significa reconstruir, não só atualizar.

233 ferramentas, sem login — e acesso a shell era uma delas

CVE-2026-59726, batizada de RufRoot, é uma execução de código sem qualquer autenticação na MCP Bridge do Ruflo, uma camada open source para orquestrar agentes. CVSS 10,0, afetando todas as versões abaixo da 3.16.3. O núcleo do problema, nas palavras da própria análise: a bridge "exposed 233 tools, including shell command execution, database operations, agent management, and memory storage, through an unauthenticated Model Context Protocol (MCP) bridge that's open to the network by default".[2] Reportada em 30/06, corrigida em 24 horas.

MCP Bridge: Um serviço de rede que oferece uma lista de funções acionáveis — "leia este arquivo", "consulte o banco de dados", "execute este comando" — para que outro programa possa usá-las. Como um interfone com um botão para cada porta da casa. O problema não é o interfone, é ele estar pendurado na rua, sem perguntar o nome de ninguém.

Minha leitura: essa não é uma história sobre agentes, é a história de infraestrutura mais antiga que existe. Um serviço administrativo escuta em 0.0.0.0, a autenticação é opcional e, por isso, está desligada — conhecido de instâncias Redis abertas, do Elasticsearch sem senha, do socket do Docker exposto via TCP. O que muda é só a conveniência do payload: não precisa de cadeia de exploração quando a lista de ferramentas já diz "executar comando shell".

Na prática: rode ss -tlnp uma vez e veja o que está escutando num endereço externo em vez de 127.0.0.1. Que a correção tenha saído em um dia é o elogio; que a configuração padrão a tenha tornado necessária é a crítica.

Faltou um noindex, e os chats compartilhados apareceram na busca

No fim de semana de 25 e 26/07, usuários do Reddit notaram que era possível encontrar conversas alheias via site:claude.ai/share: páginas do recurso "Compartilhar por link", às quais faltava a instrução para manter os buscadores afastados. O que a heise encontrou nos resultados é do tipo desconfortável — "crypto keys for wallets were found there, or a lawyer's request as to whether he should report himself for misconduct". O Google removeu os resultados; Bing e Brave demoraram mais.[3]

Comprovado e contestado Está comprovado que resultados eram encontráveis via site:claude.ai/share e que a heise viu conteúdo desse tipo neles. Contestada é a causa: a Anthropic rebate, afirmando que links de compartilhamento só "são detectáveis se os próprios usuários os tornarem públicos". A heise escreve: "It is currently unclear to what extent private chats became public as a result."[3] Por isso tratamos a extensão do problema como em aberto — o mecanismo, não.

O ponto vale independentemente de quem esteja certo, porque aparece em qualquer produto com "compartilhar por link". Um link assim não é privado, é não listado — secreto só enquanto ninguém o deixa em algum lugar. Mas URLs vazam: cabeçalhos de referência, o chat em que você o repassa, extensões com acesso de leitura. Se um crawler já o viu, não dá mais para apagar o conteúdo, só pedir a desindexação.

Por isso as três linhas que deveriam vir de fábrica em um recurso assim, e não custam nada: X-Robots-Tag: noindex no lado do servidor, e não só como meta tag (numa página renderizada via JS, o crawler nunca vê a tag de outra forma), uma entrada no robots.txt, e uma data de expiração no token. O terceiro é o mais importante: um link de compartilhamento sem expiração é uma publicação com atraso embutido.

Dois prazos regulatórios: um vence hoje, o próximo na terça-feira

Atualização desde qua O primeiro é o CVE-2026-16812 no Arista VeloCloud Orchestrator, uma injeção de comando com CVSS 10,0, ativamente explorada. Para órgãos federais dos EUA, o prazo termina hoje. Afetadas: VCO 5.2.x anteriores à 5.2.3.14, 6.1.x anteriores à 6.1.3.4, 6.4.x anteriores à 6.4.2.4 e 7.0.x anteriores à 7.0.0.1.[4]

O segundo é a cadeia wp2shell do WordPress — CVE-2026-60137 (injeção SQL) encadeada com CVE-2026-63030 (confusão de rotas no endpoint REST batch), juntas resultando em execução de código antes de qualquer login. O prazo federal é divulgado como 04/08 — as fontes, porém, se contradizem: uma indica uma data mais cedo, 24/07, para a CVE-2026-63030, capaz de RCE, separada do 04/08 para a CVE-2026-60137; outra indica uma data anterior a 24/07 para ambos os CVEs. O próprio cisa.gov estava inacessível para esclarecer isso. A exploração ativa é dada como confirmada desde a divulgação em 17/07.[5] Segundo a VulnCheck, as versões afetadas são 6.8.0–6.8.5, 6.9.0–6.9.4 e 7.0.0–7.0.1; os branches corrigidos ficam, em cada caso, uma versão pontual acima.[6]

A verdadeira notícia está no ritmo: a exploração começou "just hours after fixes came out", e o The Register considera bem possível que "the attackers had an AI assist".[7] É suposição, não constatação — mas a direção está certa mesmo assim. Quem consegue reconstruir a rota de ataque a partir de um patch trabalha mais rápido do que antes, e isso encurta a janela em que "corrigimos na janela de manutenção" costumava funcionar. No WordPress, por isso, atualizações automáticas do core deixaram de ser conveniência e passaram a ser a única defesa realista.

JDK 28: Valhalla chega como preview — 197.000 linhas para uma palavra-chave

JEP 401, as value classes do Project Valhalla, estão previstas para o JDK 28 como preview — cerca de 197.000 linhas de código em 1.816 arquivos, a maior mudança na linguagem em uma década. O próprio Brian Goetz, da Oracle, modera as expectativas: é "just the first part of Valhalla", e ele chama de "optimistic" a esperança de o recurso sair do status de preview já no Java 29.[8] O JDK 28 é esperado para março de 2027.

Value classes: Um objeto Java normal tem identidade — a JVM o armazena na memória e aponta para ele de qualquer lugar. Uma value class abre mão disso: dois pontos com as mesmas coordenadas são o mesmo ponto, então a JVM pode colocar o conteúdo direto em vez de uma referência. A diferença entre "aqui está o número da prateleira" e "aqui está o conteúdo" — menos memória, sem perseguir ponteiros, um array de pontos fica contíguo no cache.

Mais duas JEPs estão propostas para o JDK 28: a JEP 540, uma Simple JSON API no incubator, e a JEP 541, que depreca a porta macOS/x64 visando remoção futura.[9] A API JSON é a nota de rodapé do caso Fastjson de ontem: não substitui o Jackson, mas se o próprio JDK trouxer um parser mínimo, o argumento "carregamos uma biblioteca de desserialização só para ler três campos" fica mais fraco.

Praticamente relevante hoje não é nenhuma das grandes notícias, e sim a JEP 541: quem ainda desenvolve Java num Mac Intel, ou tem macOS x64 na matriz de CI, vê um relógio começar a correr. Valhalla continua sendo a promessa de que tipos de valor pequenos e imutáveis, um dia, não custarão nada em tempo de execução — "um dia" realisticamente quer dizer depois de 2027.

Parecer do Bundestag: "open source first" é permitido pela lei de licitações

Desde meados de julho, está público um parecer do Serviço Científico do Bundestag alemão (referência WD 7 – 3000 – 010/26) sobre a pergunta que deixa órgãos de compras públicas alemães cautelosos há anos: uma licitação pode exigir software de código aberto? O resultado: "Em suma, uma restrição a software de código aberto é juridicamente admissível em matéria de licitações, desde que seja objetivamente justificada, proporcional e fundamentada de forma transparente."[10]

Igualmente clara é a outra face: "Já é inadmissível uma definição puramente genérica ou politicamente motivada, sem relação concreta com o objeto do contrato."[10] Como motivos objetivos válidos, valem os óbvios: segurança da informação, interoperabilidade com o parque já existente, e a capacidade de futuramente continuar desenvolvendo e mantendo o software por conta própria.[11]

Isso não é uma nova situação jurídica, e sim uma que finalmente foi dita em voz alta — e esse era justamente o gargalo: quem dentro de um órgão público queria uma exigência de OSS carregava sozinho o risco da licitação, sem ninguém para respaldar a decisão. Para fornecedores pequenos diante dos pacotes de licença de sempre, isso desloca o ônus da prova do se para o como. O contraponto está na própria citação: o que conta é a justificativa documentada em cada caso — trabalho minucioso, não um passe livre.

Banco do Brasil constrói 43.000 caixas eletrônicos como uma distribuição Linux

O Banco do Brasil migrou seu parque de caixas eletrônicos — segundo a própria instituição, mais de 43.000 equipamentos — para o SUSE Linux Enterprise e trouxe o Open Build Service como camada de build e entrega. O gerente de TI responsável, Berthonio de Medeiros Lucena, descreve o ganho assim: "With the SUSE solutions, we managed to create an automated deployment pipeline. BB developers no longer face what is known as 'dependency hell.'"[12]

O interessante não é o sistema operacional, é a ferramenta. O Open Build Service é a maquinaria com a qual o openSUSE constrói sua própria distribuição: pacotes contra ambientes-alvo definidos, de forma reproduzível, com dependências resolvidas. Abastecer uma frota de caixas eletrônicos com isso significa não empurrar a aplicação como um blob para o dispositivo, mas construí-la como pacote de distribuição — a mesma ideia que popularizou os containers, só que sem containers.

Números do fabricante As cifras de "até 5× mais rapidez na entrega de aplicações" e "74% menos tempo de desenvolvimento" vêm da comunicação do estudo de caso sobre o projeto, não de uma medição independente.[12] O que se sustenta é a afirmação arquitetural, não o fator.

Como sinal da tecnologia brasileira, isso diz mais do que qualquer keynote: um dos maiores bancos da América Latina faz do código aberto a base operacional bem onde menos se experimenta.

75 milhões de registros por 500 dólares — e como verificar isso

Em 29/07, foram oferecidos supostamente 75 milhões de registros da neobank Revolut num fórum clandestino, ao preço de US$ 500. A Revolut nega qualquer invasão, e a negativa vem com um argumento verificável: ao comparar os identificadores de usuário e cartão da amostra com os próprios sistemas, "none of them […] to valid or real Revolut identifiers" — nenhum correspondia. A suspeita dos pesquisadores envolvidos: um conjunto de dados remontado a partir de material antigo, não um vazamento recente.[15]

O preço é o segundo sinal de alerta: um lote recente de 75 milhões de clientes fintech custaria um múltiplo disso nos mesmos fóruns. Tratamos isso como não confirmado — e levamos o método, porque funciona para qualquer produto próprio: a verificação mais rápida e confiável não é "os dados são reais?", e sim comparar o formato do identificador com o próprio espaço de chaves. Se nenhum ID cabe no intervalo de valores que a aplicação já emitiu, a alegação está encerrada sem precisar de perícia.

Três configurações padrão, um padrão

Nenhuma das três histórias de segurança de hoje é do tipo que se encontra com fuzzing. No Ruflo, a autenticação está desligada porque vem desligada por padrão. Nos links de compartilhamento, a página é indexável porque páginas na web são indexáveis por padrão. E no Node, um limite não conta tudo o que deveria limitar. Três vezes, o erro é uma decisão que outra pessoa tomou há muito tempo.

Padrão aberto→ ninguém muda→ a rede encontra

O desconfortável é que nossas ferramentas não enxergam essa classe de erro: um scanner compara versões, e a versão aqui está em ordem. Não existe bot que abra um pull request dizendo "esse serviço escuta em todas as interfaces". Por isso, o exercício chato continua sendo a meia hora mais produtiva da semana: olhar de fora e não perguntar "está tudo atualizado?", e sim "o que responde aqui, e quem tem permissão para isso?". Ontem foram 24.650 módulos de gerenciamento remoto de servidores entregando hash de senha; hoje, 233 ferramentas com acesso a shell.

O que não conseguimos comprovar hoje O cisa.gov continua respondendo com 403 — os dois prazos regulatórios acima vêm de matérias especializadas que reproduzem a entrada da KEV da CISA com sua data, não da própria página do órgão. Para os dois CVEs do wp2shell, a análise disponível não traz número de CVSS, só rótulos de severidade; os valores contraditórios de 27/07 seguem sem esclarecimento e não são repetidos aqui. E, para o RufRoot, não foi possível abrir o advisory do fabricante — a pontuação e as versões são consistentes em duas fontes secundárias, mas não foram lidas na fonte primária.

Hoje é quinta-feira, dia trinta de julho. O dia tem um fio condutor só, e ele é incômodo: a maior parte das histórias de segurança de hoje não é erro de programação, é configuração padrão. Alguma coisa fica aberta porque vem aberta de fábrica, e ninguém fechou.

Primeiro, o lançamento que esperávamos desde segunda-feira. O projeto Node ponto J-S tinha anunciado releases de segurança para o dia vinte e sete de julho. Eles saíram na quarta-feira, dia vinte e nove: as versões vinte e dois vinte e três dois, vinte e quatro dezoito um e vinte e seis cinco um. Juntas, elas fecham onze vulnerabilidades, três delas de severidade alta. Duas envolvem HTTP dois, e uma delas contorna um limite de memória que se define justamente para o outro lado não sobrecarregar o servidor com cabeçalhos. O limite está lá no código, só que não funciona.

A terceira falha de severidade alta fica num lugar particularmente irônico: o próprio modelo de permissões do Node, o mecanismo usado justamente para restringir o runtime de propósito. Ele concede mais acesso do que o pedido. Some a isso uma falha de severidade média em que o cliente HTTPS pula a verificação do hostname — o certificado é válido, só que para outra pessoa. A parte prática não está no aviso oficial: na maioria das instalações, o Node não chega via gerenciador de pacotes, chega como imagem base de container. Quem só atualizou o runtime no notebook hoje não tocou no registry.

A segunda história é a mais marcante. Uma camada open source para orquestrar agentes de IA, a MCP Bridge do Ruflo, tinha uma falha de execução de código sem qualquer autenticação, com a maior severidade possível, dez de dez. O serviço expunha duzentas e trinta e três ferramentas acionáveis — incluindo execução de comandos shell, operações de banco de dados e acesso à memória — e, por padrão, escutava em todas as interfaces de rede, sem exigir login. Foi reportada no fim de junho e corrigida em vinte e quatro horas, na versão três dezesseis três. Eu não leio isso como uma história sobre inteligência artificial, e sim como a história de infraestrutura mais antiga que existe, a mesma que já vimos com instâncias Redis abertas, Elasticsearch sem senha, sockets do Docker expostos na rede. O que muda é só a conveniência do payload: não precisa de cadeia de exploração quando a lista de ferramentas já diz "executar comando shell".

A terceira configuração padrão é uma meta tag que faltou. No fim de semana de vinte e cinco e vinte e seis de julho, percebeu-se que conversas compartilhadas do Claude apareciam no Google, no Bing e no Brave, porque faltava nas páginas a instrução que mantém os buscadores afastados. Entre os resultados havia coisas como chaves de carteiras de criptomoeda. O Google removeu os resultados; Bing e Brave demoraram mais. A Anthropic contesta essa leitura e diz que links assim só ficam visíveis se os próprios usuários os tornarem públicos. Quantos chats privados foram realmente afetados continua em aberto.

O ponto vale independentemente de quem está certo, porque se aplica a qualquer produto com função de compartilhar por link. Um link desses não é privado, é só não listado — e apenas enquanto ninguém o deixa em algum lugar. Assim que um crawler o vê, não dá mais para apagar o conteúdo, só pedir a desindexação. Três linhas evitariam tudo isso e não custam nada: um cabeçalho noindex do lado do servidor em vez de só uma tag no HTML, uma entrada no robots ponto t-x-t, e uma data de expiração no link. O terceiro ponto é o mais importante.

Depois, dois prazos regulatórios. Hoje vence o prazo para uma falha de injeção de comando no Arista VeloCloud Orchestrator, severidade dez de dez, ativamente explorada. Na terça-feira que vem, dia quatro de agosto, vence — segundo uma fonte — o prazo para a cadeia do WordPress chamada wp2shell; outras fontes já apontam essa data para vinte e quatro de julho. De todo modo, são duas falhas encadeadas que permitem executar código antes mesmo do login. O que chama atenção é a velocidade: segundo o The Register, a exploração começou poucas horas depois dos lançamentos das correções, e o veículo considera plausível que os atacantes tenham tido ajuda de IA. Isso é especulação, não constatação — mas a tendência é real. Para o WordPress, atualizações automáticas do núcleo deixaram de ser conveniência, viraram a única defesa realista.

Do mundo Java vem a maior mudança de linguagem em uma década. As value classes do Project Valhalla devem chegar no JDK vinte e oito como preview — cento e noventa e sete mil linhas de código em mil oitocentos e dezesseis arquivos. O próprio Brian Goetz, da Oracle, modera as expectativas e chama isso de só a primeira parte do Valhalla. O JDK vinte e oito é esperado para março de dois mil e vinte e sete. Duas outras propostas se destacam: uma API JSON simples no incubator, e a descontinuação da porta macOS para Intel. Quem ainda desenvolve Java num Mac Intel viu um relógio começar a correr.

Uma boa notícia de cada lado, Alemanha e Brasil. Um parecer do serviço de pesquisa do Bundestag alemão resolveu uma dúvida antiga: restringir uma licitação pública a software de código aberto é legal, desde que a justificativa seja objetiva, proporcional e documentada — uma restrição genérica ou politicamente motivada, não. E o Banco do Brasil migrou mais de quarenta e três mil caixas eletrônicos para o SUSE Linux, construindo o software para eles com a mesma ferramenta que o openSUSE usa para construir sua própria distribuição. Eu levaria os percentuais do fornecedor com uma pitada de sal; a decisão arquitetural em si me parece acertada.

O que fica: nossas ferramentas não enxergam essa classe de erro. Um scanner verifica número de versão, e a versão está em ordem quando o problema é uma configuração padrão ruim. Não existe bot que abra um pull request dizendo "esse serviço escuta em todas as interfaces". Ontem foram vinte e quatro mil seiscentos e cinquenta módulos de gerenciamento remoto de servidores entregando seus hashes de senha. Hoje são duzentas e trinta e três ferramentas com acesso a shell. Amanhã veremos se o prazo de terça-feira do WordPress realmente muda alguma coisa na prática, e se a Anthropic apresenta uma explicação técnica mais completa sobre como esses links acabaram indexados.
