Conta da Microsoft no PyPI distribui malware

Pela conta oficial da Microsoft no PyPI saíram as versões 1.26.1 e 1.26.2 do Agent Framework, uma biblioteca para construir agentes de IA. Segundo o heise, "o malware está nas versões 1.26.1 e 1.26.2".[1] A Microsoft reverteu a 1.26.1 para a 1.26.0 limpa, e então os atacantes subiram a 1.26.2.[1] Segundo a Wiz, a 1.26.1 entrou no ar na terça-feira, 17/11, às 20h35 UTC, e a 1.26.2 por volta das 21h08 UTC; até cerca de 21h30 UTC o PyPI havia removido ambas.[3] O pacote tem "em média cerca de 200.000" downloads por mês.[1] Quem o descobriu foram OX Security e OpenSourceMalware.[2]

O truque: a versão 1.26.1 deposita os arquivos agent_framework_meta.pth e agent_framework_meta/_telemetry.py, a 1.26.2 deposita af_runtime_diag.pth e af_runtime_diag.py. O arquivo .pth roda a cada início do Python, mesmo sem import.[1][3] Para conferir, procure as duas variantes na pasta site-packages. Depois o malware procura credenciais do Azure, Git, Docker e Hugging Face, segundo o Baguete solicita novos tokens de identidade no GitHub Actions, Azure DevOps e Azure, e envia tudo criptografado para fora.[2] O roubo de tokens OIDC do GitHub Actions a Wiz atribui só à 1.26.2.[3] Como os atacantes chegaram à conta não está confirmado; a OX Security suspeita de logins roubados da Microsoft.[1] A Microsoft investiga o caso e tornou privados alguns repositórios do GitHub.[1]

Arquivo .pth: Um pequeno arquivo de texto na pasta site-packages. O Python o lê a cada início para definir caminhos de busca. Se houver nele uma linha começando com import, o Python a executa. É como um bilhete na geladeira que todo colega de casa cumpre automaticamente de manhã, mesmo que nunca tenha pretendido entrar na cozinha.
Nossa visão Este é o ponto mais importante do dia, mesmo para quem não tem projeto de IA. Um pacote com a Microsoft como remetente é exatamente o que ninguém verifica. O dano acontece no CI: é lá que ficam os tokens que a coisa procura. Quem usa lockfiles Python com hashes (pip install --require-hashes ou uv lock) estava protegido. Quem monta builds com >= sem lock deve vasculhar builds, lockfiles e caches a partir de terça, 17/11, atrás dessas duas versões e depois rotacionar todos os segredos que o runner podia ver. O lado de IA do framework pertence ao brief ai-dev.

PostgreSQL 19 foi lançado

Atualização desde quinta Ontem, aqui estava "deve sair hoje". Agora saiu: o PostgreSQL Global Development Group anunciou em 19/11 o lançamento do PostgreSQL 19.[1] Os destaques segundo o anúncio:

  • Verificações de chave estrangeira mais rápidas: no teste, inserts em massa ficaram "nearly 2x faster".[1]
  • REPACK (CONCURRENTLY): reorganizar tabelas sem atrapalhar a operação em andamento.[1]
  • INSERT ... ON CONFLICT DO SELECT: RETURNING devolve também a linha que já existe, ou seja, "get or create" em um único comando.[1]
  • WAIT FOR LSN: "read-your-writes" em standbys; além disso a extensão pg_stash_advice, que guarda dicas de plano por query.[1]
  • Replicação e TLS: o primeiro slot lógico eleva o nível do WAL automaticamente; o servidor pode apresentar um certificado próprio por hostname via SNI.[1]

Atenção às mudanças: a autenticação RADIUS foi removida, o JIT agora vem desligado por padrão e, após um login md5 bem-sucedido, aparece um aviso porque o md5 vai sumir em uma versão futura.[1]

REPACK: Com o tempo, uma tabela acumula buracos de linhas apagadas, como uma estante com espaços vazios. O VACUUM FULL arruma, mas trava a estante inteira. O REPACK (CONCURRENTLY) reorganiza enquanto os outros continuam tirando livros.
Nossa visão ON CONFLICT DO SELECT é o recurso que o pessoal de backend espera há anos; o desvio habitual com CTE e um segundo SELECT deixa de ser necessário. Mesmo assim: não coloque a 19.0 em produção no primeiro dia. Antes, verifique o pg_hba.conf por md5 e RADIUS e teste as consultas que se beneficiavam do JIT. A atualização minor de 12/11 com 52 CVEs vem primeiro.

PHP 8.6.0 e um dia pesado de segurança

Em 19/11 saíram cinco releases do PHP de uma vez: o novo major 8.6.0 e as atualizações de segurança 8.5.13, 8.4.28, 8.3.37 e 8.2.36.[1] Na véspera, o php.net havia anunciado um "Upcoming Critical PHP Security Release".[1] Segundo o heise, as atualizações fecham 17 falhas, sete delas com CVSS 9,2; as críticas, porém, exigem configurações especiais.[2] A contagem não é uniforme: o changelog do php.net lista 18 IDs de CVE, a manchete do heise fala em cinco falhas com execução de código, a URL em quatro.[2][3]

O próprio PHP 8.6 traz aplicação parcial de funções com marcadores ?, uma classe \Time\Duration, a API Io\Poll como base para event loops como ReactPHP e AMPHP, uma função clamp(), um enum SortDirection e valores padrão para propriedades readonly.[4]

Nossa visão A atualização de segurança é obrigatória, a 8.6 é opcional. O heise escreve: "Admins devem atualizar rapidamente suas instalações PHP."[2] Quem está na 8.2 ainda recebe os patches. Io\Poll é a peça mais interessante, porque substitui o stream_select() com seus limites.

ruby2ßhell: 21 ß e uma codificação

O Ruby lançou em 18/11 as versões 4.0.10, 3.4.13 e 3.3.14. Segundo o ruby-lang.org há "seven vulnerabilities" no motor de regex e na capitalização de strings; a recomendação é "We strongly recommend upgrading."[1] O nome "ruby2ßhell" foi dado a uma delas pela Veria Labs. Segundo o heise, são afetados apps que processam strings em codificação ISO-8859 ou Windows-125x com upcase, swapcase, downcase(:fold) ou casecmp?; Rails e Sinatra no padrão clássico seriam afetados.[2]

"Ainda não foi atribuído um número CVE", há apenas o advisory do GitHub GHSA-34m4-m9fh-gqp5.[2] Não há ataques conhecidos, e o heise cita: "Isto não é um ataque pronto". A Veria Labs pretende mostrar uma PoC em cerca de uma semana.[2] Segundo o advisory do Ruby, os mantenedores conhecem PoCs que comprovam execução remota de código para algumas das falhas.[3] Os detalhes técnicos do ruby2ßhell só lemos no heise, não no próprio advisory.

Por que justo o ß? Em maiúsculas, "ß" vira "SS", ou seja, de um caractere saem dois. Uma string fica mais longa na conversão do que era antes. Nossa suposição (não da fonte): saltos de tamanho assim são o lugar clássico em que o código escreve além do fim de um buffer. Os 21 ß vêm do título da descoberta.

nginx: dez CVEs em um release

O nginx.org informa para 18/11 as versões 1.30.7 (stable) e 1.31.9 (mainline) com correções para dez falhas, entre elas use-after-free no resolver, em HTTP/2, HTTP/3 e no proxy de e-mail, uma corrupção de memória no controle de fluxo do HTTP/2 e um estouro de buffer com alias e try_files.[1] Segundo o heise, "cinco delas de uma vez" têm CVSS 4.0 com 9,2, e dois erros estão no código desde 2007.[2] Os valores CVSS vêm só do heise; o nginx.org não informa notas. Não há relato de ataques.

Nossa visão É o segundo grande release de segurança do nginx em cinco semanas: em 14/10 já tinham saído cinco correções.[1] Quem usa o nginx da distribuição espera o backport; quem usa o repositório upstream atualiza normalmente. Para usuários do Caddy: lá a 2.11.9 de 05/11 é a atual, com correções de segurança "mostly in FastCGI".[3]

BSI: "tensa a crítica" [1]

O BSI elevou em 19/11 sua avaliação da situação para "tensa a crítica", segundo o heise pela primeira vez desde 2023. O heise cita cerca de 160 novas vulnerabilidades por dia (mais 35%). O tempo entre a publicação de uma falha e o primeiro exploit seria em média de cerca de 25 dias, no segundo trimestre de 2026 de cerca de oito dias; um ano antes eram uns 53. 88% dos dispositivos infectados seriam Android; o BadBox contaria cerca de 30.000 dispositivos na Alemanha, o Vo1d mais de 10.000. Não carregamos o comunicado original do BSI.

Nossa visão Oito dias até o exploit, esse é o número que conta. Um ciclo mensal de patches é, portanto, lento demais para qualquer coisa com acesso à internet. Não é motivo de pânico, mas é um bom argumento para atualizações minor automáticas e Renovate ou Dependabot com auto-merge para patches.

Apache Roller

Para o software de blog Apache Roller há dois registros de CVE para o mesmo erro: CVE-2026-129448 (versões 4.0.0 a 6.1.4) e CVE-2026-82384 (6.1.5), ambos CVSS 9,8.[1] Segundo a descrição dos desenvolvedores, a falha "já está sendo ativamente atacada". A 6.1.6 corrige a falha ativamente atacada; a atualização descarta requisições XML-RPC quando o XML-RPC está desligado.[1] Segundo o Apache Security, porém, há ainda o CVE-2026-123374, uma desserialização XML-RPC da 4.0 até a 6.1.6, que só a 6.1.7 corrige. A versão-alvo é, portanto, a 6.1.7.[3] Até ontem, o Roller não constava do catálogo KEV.[2]

Comissão Europeia: ataque com ferramenta de pentest? [1]

A Comissão Europeia descobriu o ataque em 22/10 e o confirmou em 26/10. Os sistemas de pessoal Sysper e MyPMO foram tirados do ar por precaução e voltaram no início desta semana; segundo o heise, citando o Politico, o Sysper caiu de novo por pouco tempo na quarta-feira. A Comissão fala em "campanha cibernética gerada por IA". A suspeita recai sobre o Artex, uma plataforma open source de pentest em Go controlada por um modelo de linguagem; isso não está confirmado. Segundo o FBI, o Artex é usado de forma abusiva desde pelo menos agosto, e no início de novembro mais de 1.600 instâncias estavam acessíveis. Segundo um porta-voz, até agora não houve vazamento de dados pessoais.

Nossa visão Para nós conta o aspecto operacional: uma ferramenta de ataque aberta, solta na rede, com mais de 1.600 instâncias acessíveis. O lado de IA (quanto o modelo faz por conta própria) pertence ao brief ai-usecases.

O que vale a sexta-feira

Três tarefas antes do fim de semana: procurar nos logs de CI por agent-framework 1.26.1 ou 1.26.2 e, em caso de achado, rotacionar os segredos. Colocar as atualizações de PHP, Ruby e nginx no ciclo normal. E planejar um teste para o PostgreSQL 19, não a migração para produção.

Hoje é sexta-feira, vinte de novembro. Ontem tivemos dois grandes lançamentos, e veio à tona um incidente sério na cadeia de suprimentos.

Primeiro o incidente. Pela conta oficial da Microsoft no PyPI saíram, já na noite de terça-feira, duas versões contaminadas do Agent Framework, a um ponto vinte e seis ponto um e a um ponto vinte e seis ponto dois. Segundo o heise, o pacote é baixado cerca de duzentas mil vezes por mês. O malware dispara a cada processo Python e procura credenciais do Azure, Git, Docker e Hugging Face, além de tokens do GitHub Actions. Nossa visão: quem fez build desde terça sem lockfile deve conferir os logs de build e rotacionar os segredos.

A boa notícia: o PostgreSQL dezenove foi lançado. As verificações de chave estrangeira ficaram mais rápidas, e no teste os inserts em massa quase dobraram de velocidade. Entram o REPACK com o banco em operação e o ON CONFLICT DO SELECT para o clássico buscar-ou-criar. O JIT agora vem desligado por padrão, e o RADIUS foi removido. Nosso conselho: testar primeiro, não colocar em produção no primeiro dia.

O PHP oito ponto seis também chegou, junto com atualizações de segurança para as versões oito ponto dois a oito ponto cinco. Segundo o heise, elas fecham dezessete falhas, sete delas com nota nove vírgula dois em dez, mas apenas em configurações especiais.

O Ruby fechou sete falhas. Uma delas se chama ruby2ßhell, porque, ao pôr em maiúscula o eszett alemão (ß), saem dois caracteres. São afetados apps com codificações antigas, como ISO-8859. Uma prova de conceito deve sair em cerca de uma semana. Somam-se o nginx com dez falhas e o WordPress com vinte.

O BSI elevou sua avaliação para tensa a crítica, pela primeira vez desde dois mil e vinte e três. Segundo o heise, em média só passam cerca de oito dias até uma nova falha ser explorada. E o software de blog Apache Roller já está sob ataque ativo, segundo seus desenvolvedores.

Para o pessoal do Windows: o PowerShell cinco ponto um foi descontinuado. Windows onze vinte e seis H dois e Server dois mil e vinte e cinco são as últimas versões com o cinco ponto um embutido. Na Comissão Europeia continua a apuração de um ciberataque em que a suspeita recai sobre uma ferramenta de pentest com IA de livre acesso.

Na próxima semana vamos ver se o Spring Boot quatro ponto dois finalmente sai, e se a prova de conceito anunciada para o Ruby aparece. No sábado vencem os prazos de Apache Axis, REDCap e Synology no catálogo de falhas ativamente exploradas.
