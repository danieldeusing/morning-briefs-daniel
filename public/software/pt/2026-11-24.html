Cisco Expressway: ataques após a PoC

Atualização desde seg A falha CVE-2026-76466 está, segundo a Action1, na função de cluster do Cisco Expressway.[4] Invasores não autenticados na rede podem usá-la para executar comandos de sistema como root. A Cisco cita CVSS 9,8; o heise fala em "crítico".[1][5] A CISA lista a falha no catálogo KEV desde 20/11 como "Use of Hard-coded Credentials"; o prazo terminou ontem.[2] A novidade é a confirmação de ataques: segundo o heise, a empresa de segurança F6 os confirmou, e o The Register escreve que os ataques começaram depois que uma PoC se tornou pública.[1][3]

Segundo a Cisco, a versão X15.5.20 fecha a falha. Quem usa X14 ou anterior deve migrar para uma versão corrigida; não há soluções alternativas.[5] Em 23/11 a Cisco atualizou o aviso (versão 1.1) para registrar a inclusão no KEV. Segundo a própria Cisco, não há evidência direta de exploração ativa.[5]

Credenciais fixas no código: dados de acesso que o fabricante embutiu no software. Ninguém consegue alterá-los. Como uma chave-mestra que serve em todas as fechaduras de uma linha de produção: quem a conhece uma vez entra em qualquer lugar.
Nossa visão O Expressway é a porta que deixa conexões de vídeo e voz atravessarem o firewall. Por definição, fica na borda da rede. Uma chave fixa mais uma PoC pública significa: varreduras em massa são questão de dias. Quem ainda roda X14 não tem um problema de patch, mas de substituição.

KEV: duas novas entradas, três dias de prazo [1]

Atualização desde seg Ontem relatamos "nenhuma entrada nova desde sexta". Na noite de segunda (versão do catálogo 2026.11.23) entraram duas. CVE-2026-134624 afeta o N-able MailAssure (antes SpamExperts), um serviço de filtro de e-mail. É uma Server-Side Request Forgery. CVE-2026-133968 é um path traversal no MONAI Label, uma ferramenta de código aberto para anotar imagens médicas. Para ambas vale o prazo de qui 26/11.

SSRF: o invasor faz um servidor buscar para ele um endereço que não é acessível de fora. Como se um estranho ligasse para a recepção e dissesse: "Pegue para mim a pasta da sala do chefe." A recepção pode entrar; o estranho não.
Nossa visão Os prazos chamam a atenção. As quatro entradas de 10/11 que vencem hoje tiveram duas semanas de prazo; todas as entradas de 20/11 e 23/11, apenas três dias. Para equipes que planejam pelo KEV, isso significa: o catálogo precisa ser lido todo dia, não toda semana.

SAP NetWeaver: pontuação média, ataques reais

CVE-2025-42884 é uma injeção JNDI no SAP NetWeaver Enterprise Portal. O heise cita CVSS 6,5, "médio".[1] Mesmo assim, ela consta no catálogo KEV desde 20/11, ou seja, com ataques comprovados.[2] A SAP já publicou o patch no dia de patches de novembro de 2025.[1]

Injeção JNDI: JNDI é o serviço Java com o qual uma aplicação procura recursos por um nome. Se um invasor consegue definir esse nome, ele manda a aplicação para o próprio servidor dele. Esse foi o mecanismo por trás do Log4Shell. Como uma nota de entrega em que o próprio cliente escreve o endereço do depósito.
Nossa visão Esta é a lição do dia. Um patch de um ano atrás, pontuação média e, mesmo assim, atacada. O CVSS diz o quão grave uma falha pode ser. O KEV diz que alguém a está usando agora. Para a ordem do trabalho, o segundo conta.

Spring: uma grande rodada de patches

O spring.io lista na primeira página 25 avisos, todos de 19/11; outros ficam atrás de "Load more".[1] Entre os afetados estão Spring Security, Spring Web Services, Spring Integration, Spring Data MongoDB, Spring Vault, Spring for GraphQL e Spring AI. O heise resumiu a rodada em 23/11 e chama algumas falhas de "críticas".[2] Três pontos se destacam:

  • Spring Security CVE-2026-59273: execução de código, mas, segundo o heise, só com uma configuração específica. O spring.io a classifica como MEDIUM. Correções: 5.7.27, 5.8.29, 6.4.20, 6.5.13, 7.0.8.1, 7.0.9, 7.1.2.1 e 7.1.3. Segundo o heise, só 7.0.9 e 7.1.3 estão disponíveis gratuitamente.[1][2] Outros três avisos do Spring Security (59330, 59331, 59333) são HIGH.[1]
  • Spring LDAP CVE-2026-59367: o servidor LDAP embutido para testes tem credenciais de administrador fixas e escuta em todas as interfaces de rede. Quem estiver na mesma rede assume o controle. O spring.io a classifica como CRITICAL. Correções gratuitas (OSS): 4.1.3 e 4.0.7.[2][3]
  • Spring Boot CVE-2026-59411: apps servlet com Actuator no Cloud Foundry, sem configuração de segurança própria, perdem a proteção padrão. Apps reativos não são afetados. O spring.io a classifica como CRITICAL. Correções gratuitas (OSS): 4.1.3 e 4.0.10.[2][4]

O Spring AI tem nove dos 25 avisos, cinco deles HIGH.[1] O lado de IA pertence ao brief ai-dev; aqui importa que o Spring AI é um artefato Maven comum e deve entrar na varredura de dependências.

Atenção O servidor LDAP de teste é o vencedor secreto. Ele é feito para testes, mas testes também rodam em runners de CI e em máquinas de desenvolvimento no Wi-Fi da empresa. Quem usa spring-ldap-test deve verificar se o servidor é acessível também fora de localhost.
Nossa visão A verdadeira notícia é a lista de versões. Oito versões de correção, duas delas gratuitas. Quem está no Spring Security 5.x ou 6.x paga suporte enterprise ou migra. É a mesma conta do vCenter 7.0, só que mais discreta. A migração para o Spring Boot 4 / Security 7 deixa de ser desejo e vira obrigação.

Azure API Management: segredos roubados na Noruega

Invasores vasculharam instâncias do Azure API Management (APIM) em busca de segredos e executaram ações de administrador. Segundo o The Register, só os tiers Classic são afetados, não o APIM v2. A agência norueguesa de segurança NSM cita duas empresas de energia como vítimas: Equinor e Skagerak Energi.[1] A Microsoft diz que identificou o problema em 18/11 e aplicou uma mitigação automaticamente no dia seguinte. Não há CVE nem valor CVSS públicos.

A NSM recomenda presumir que segredos e Named Values estão expostos. Ou seja: rotacionar todos os tokens, verificar o que cada instância alcança e procurar vestígios anteriores a 19/11.[1]

Nossa visão Foram afetados sobretudo ambientes que guardavam segredos direto no APIM em vez de apontar para o Key Vault. É o velho padrão: segredos pertencem a um cofre, não à configuração do gateway. O The Register lembra de instâncias esquecidas de dev e teste. Ali muitas vezes ficam chaves reais.

Cleverbridge: dados de cartão com CVV roubados

A Cleverbridge é uma prestadora de serviços de loja de software com sede na Alemanha. Muitos fabricantes vendem licenças e assinaturas por ela. A empresa percebeu acessos não autorizados em 04/11 e informou os afetados a partir de 20/11. Foram roubados números de cartão, datas de validade e códigos CVV/CVC, além de e-mail, endereço de cobrança e telefone. Senhas não foram afetadas, segundo a Cleverbridge. A empresa não informa números.[1]

O The Register inclui Red Hat, SUSE, Tenable, Veeam, Jamf, Parallels e Plesk entre os clientes. Isso não significa que os compradores deles foram afetados.[1]

Nossa visão A frase sobre o CVV é o escândalo. O PCI DSS proíbe armazenar o código de verificação após a autorização, mesmo criptografado. Ou ele estava guardado em algum lugar, ou os invasores estavam ao vivo no formulário de pagamento. As duas hipóteses são ruins. Quem comprou uma licença este ano por um checkout da Cleverbridge deve olhar a fatura do cartão de crédito.

PostgreSQL: quem realmente chegou ao fim

A tabela oficial de versões é inequívoca: o PostgreSQL 14 recebeu em 12/11/2026, com a 14.25, seu último release e não é mais suportado. O PostgreSQL 15 (atualmente 15.20) vai até 11/11/2027.[1]

O PostgreSQL 19 saiu em 19/11.[2] Para upgrades, vale lembrar: o JIT agora vem desligado por padrão, o login RADIUS foi removido, e dumps antigos do pg_dump com standard_conforming_strings=off carregam "not properly" na 19, segundo as notas de versão.[2]

Android: exigência para desenvolvedores se torna global

O Google estende gradualmente a verificação de desenvolvedores Android ao mundo todo a partir de janeiro de 2027. Ela vale para todas as fontes de instalação em dispositivos certificados. Brasil, Indonésia, Singapura e Tailândia participam desde 30/09/2026.[1] Registrar apps leva menos de dez minutos, segundo o Google. Repositórios de código aberto podem registrar desenvolvedores pela API do Android Developer Console.

Exceções: a instalação via ADB a partir do PC não é afetada. Quem quiser instalar apps não verificados sem ADB usa o "Advanced Flow", com uma espera única de 24 horas. Contas de hobby e estudo agora podem liberar 50 em vez de 20 dispositivos.[1]

Nossa visão No Brasil isso já é rotina, e o mundo não acabou. O caminho via ADB continua aberto, então atinge principalmente usuários, não desenvolvedores. Quem distribui apps Android internos por APK deve planejar o registro agora, e não em janeiro.

Microsoft: três meses sem ser detectado

A Microsoft publicou o relatório final sobre a queda de 12 a 14/11. O Exchange Online saiu do ar, e outros serviços do Microsoft 365 ficaram instáveis. No pior momento, mais de 80% dos servidores de gateway norte-americanos não respondiam.[1] A causa: uma mudança de código de julho, combinada com um failover e capacidade reduzida. O erro ficou ativo no mundo todo por mais de três meses antes de se manifestar.

O cerne do relatório: os testes de carga rodaram em hardware mais antigo, com menos núcleos. Mas o erro só ficou grave em máquinas mais novas. A Microsoft promete testes de carga em hardware novo, mais capacidade de reserva e testes de failover mais amplos. E-mails corporativos não se perderam, segundo a Microsoft.[1]

Nossa visão Este é o relatório mais instrutivo da semana justamente por ser tão comum. Quase toda equipe testa carga em um ambiente menor ou mais antigo que o de produção. Quem roda o staging em hardware mais barato deveria saber que classe de erro deixa de enxergar.

Shirudo: escudo em vez de patch imediato

Cisco e OpenAI apresentam o Shirudo, uma ferramenta de código aberto para "compensating controls" no Linux. Ele se baseia no Tetragon, um projeto da Isovalent, que pertence à Cisco. A ideia: para uma falha que não dá para corrigir já, escreve-se um pequeno programa eBPF, um "shield", que bloqueia o caminho do ataque. Uma pessoa revisa cada shield antes da produção.[1] O código está no GitHub.

eBPF: pequenos programas que rodam dentro do kernel do Linux, mas só em um espaço verificado e estreito. Como um segurança posto em uma porta específica: ali ele pode barrar pessoas, mas não pode reformar a casa.
Nossa visão Isso combina exatamente com o debate sobre as quedas. Um shield é menor que um patch e pode ser retirado. Mas continua sendo uma mudança no kernel, e, pelo plano, os shields serão escritos por uma IA (Codex). O lado dos agentes pertence ao brief ai-dev. Para quem opera vale: um shield não substitui o patch, ele ganha tempo.

Cisco Expressway e SAP não afetam a maioria dos desenvolvedores individuais. O Spring, sim.

Hoje é terça-feira, vinte e quatro de novembro. O catálogo de falhas exploradas voltou a se mexer, e para os desenvolvedores Java há uma grande rodada de patches.

No topo está o Cisco Expressway. Ele é a porta que deixa conexões de vídeo e voz passarem pelo firewall. Segundo o heise, invasores conseguem executar comandos como root sem fazer login, com nota nove vírgula oito. Desde que um exploit de exemplo se tornou público, a falha é atacada. A versão X quinze ponto cinco ponto vinte fecha a brecha. Quem usa uma versão mais antiga precisa migrar, segundo a Cisco. A própria Cisco diz não ter evidência direta de ataques.

Na noite de segunda, a agência americana CISA incluiu duas novas falhas em seu catálogo: uma no filtro de e-mail N-able MailAssure e outra no MONAI Label, uma ferramenta para imagens médicas. O prazo já é na quinta-feira. Chama a atenção que várias entradas de vinte e de vinte e três de novembro receberam só três dias de prazo.

O SAP NetWeaver traz uma lição. A falha tem só uma nota média, seis vírgula cinco, e o patch tem um ano. Mesmo assim, é atacada. A nota diz o quão grave uma falha pode ser. O catálogo diz que alguém a está usando agora.

Para desenvolvedores Java, o Spring é a notícia mais importante. Em dezenove de novembro, o Spring publicou pelo menos vinte e cinco avisos. No Spring Security, das oito versões de correção, segundo o heise, só duas estão disponíveis gratuitamente. E o servidor LDAP embutido para testes tem credenciais de administrador fixas e escuta na rede inteira. Quem o usa deveria verificar isso hoje.

Na Noruega, segundo o The Register, invasores roubaram segredos do Azure API Management em duas empresas de energia. As instâncias Classic são as afetadas. A agência norueguesa recomenda trocar todas as chaves. E na loja de software alemã Cleverbridge foram roubados dados de cartão, inclusive o código de segurança. Quem comprou uma licença lá deve olhar a fatura.

A Microsoft publicou o relatório sobre a grande queda do Exchange. Um erro de julho ficou três meses sem ser notado, porque os testes de carga rodaram em hardware mais antigo. Nos Estados Unidos, o governo alerta, segundo o heise, para novas quedas causadas por patches apressados. E com o Shirudo, Cisco e OpenAI propõem pequenos programas de proteção no kernel do Linux que ganham tempo até o patch.

Dois esclarecimentos. O PostgreSQL catorze chegou ao fim, e a versão quinze vai até novembro de dois mil e vinte e sete, segundo a tabela oficial. E, pelo Cyber Resilience Act europeu, a Comissão Europeia diz que a obrigação de notificar vale desde setembro deste ano.

Amanhã veremos se a CISA acrescenta mais entradas e quais versões do Spring a comunidade realmente recebe.
