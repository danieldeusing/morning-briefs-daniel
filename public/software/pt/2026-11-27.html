DIGIT: uma falha, dez países

Segundo o The Register, o DIGIT é “a modular suite that offers common services”, como login e recebimento de pagamentos para órgãos públicos.[1] A plataforma é mantida pela eGov India. Nove países a usam em parte; com a Índia são dez, e lá mais de 20.000 administrações locais a utilizam.[1] A frase do Register: “DIGIT is therefore used by governments that serve over two billion people.”[1]

A falha se chama CVE-2026-136706, uma “9.3-rated SQL injection flaw” nos componentes “User and Access Control Service”.[1] O CERT-In indiano avisa no CIVN-2026-0570: “An unauthenticated remote attacker could exploit this vulnerability by sending specially crafted input through the affected API endpoint.”[1] A eGov India publicou a correção como código-fonte, na release v2.9.3.[1][2] O CERT-In classifica a falha como “HIGH” em 25/11; segundo o aviso, a versão afetada é “DIGIT Core - version v2.9”, e a solução é atualizar para a v2.9.3.[3] Se alguém já está atacando, nem o relatório nem o CERT-In dizem.[1][3]

Injeção de SQL: O programa monta uma consulta ao banco de dados com o texto que um usuário envia. Se o atacante envia, em vez de um nome, um pedaço de SQL, o banco o executa. É como uma comanda em que alguém escreve embaixo “e me dê a chave do caixa”, e o garçom lê tudo em voz alta.
Nossa visão Duas coisas são constrangedoras aqui. Primeiro: a injeção de SQL está resolvida há duas décadas, com consultas parametrizadas; ela estar no serviço de login em 2026 é uma falha de revisão. Segundo: uma plataforma comum para vários Estados economiza dinheiro, mas cada erro atinge todos ao mesmo tempo. Quem opera o DIGIT precisa da v2.9.3. Quem constrói um kit para muitos clientes deveria revisar primeiro o caminho de autenticação.

Drupal: o prazo é hoje

Atualização desde quinta O prazo da CISA para a CVE-2026-132165 no Drupal Core termina hoje, 27/11.[1] O aviso do Drupal SA-CORE-2026-017, de 18/11, classifica a falha como “Highly critical”, com valor de risco 20 de 25.[2] Segundo a equipe de segurança, ela foi “exploited on live sites as early as 2026-11-19 19:00 UTC”, ou seja, 16h em Brasília.[2] As correções:

  • Drupal 11.4.x: atualizar para 11.4.13
  • Drupal 11.3.x: atualizar para 11.3.22
  • Drupal 10.6.x: atualizar para 10.6.22

No mesmo dia termina o prazo de duas outras entradas do KEV de 24/11: Optimizely Web Experimentation (CVE-2026-132224) e Idunno AntiCsrf (CVE-2026-131914).[1]

Nossa visão Uma semana de ataques ativos com um aviso Highly critical: quem ainda não atualizou hoje deveria não só aplicar o patch, mas também verificar nos logs, a partir de 19/11, contas de administrador estranhas e novos arquivos PHP.

PAN-OS: as correções de kernel chegaram

Atualização desde quinta O heise descreve em 26/11 a cadeia que explicamos ontem: “Atualmente, atacantes combinam duas falhas de segurança para atacar firewalls da Palo Alto.”[1] Primeiro o PHP2Shell (CVE-2026-109618, “crítico”) por uma interface de gerenciamento acessível pela internet. Depois o Fragnesia (CVE-2026-46300, “alto”).[1] A própria Palo Alto avalia a CVE-2026-109618 com CVSS 4.0 de 9,2 (crítica); o fabricante lista o Fragnesia no boletim PAN-SA-2026-0015 como “Informational”, sem valor CVSS.[2][3] Importante para o contexto: o Fragnesia não é uma falha própria do PAN-OS, mas um erro no kernel Linux sobre o qual o PAN-OS roda. Sozinho, ele não pode ser explorado remotamente; apenas eleva os privilégios de um atacante que já está dentro.[1]

Segundo o heise, pesquisadores da Dream relataram em outubro 25 firewalls comprometidos, supostamente por atacantes chineses. A CISA incluiu a CVE-2026-46300 no catálogo KEV em 28/10.[1] A novidade é a lista de builds com correção de kernel: o heise cita 20 versões em todas as linhas, de 10.2.7-h41 a 12.2.4-h3.[1] Quem já tem o patch do PHP2Shell está protegido contra esse caminho de ataque. O heise recomenda a correção de kernel mesmo assim.[1]

Atenção Interfaces de dataplane com perfil de gerenciamento também contam como gerenciamento aberto. O heise aconselha: desativar o acesso público; se não houver alternativa, apenas HTTPS e SSH e só a partir de IPs internos confiáveis.[1]

Rackspace Spot: o caminho de entrada foi o monitoramento

Atualização desde quinta O The Register traz novos detalhes sobre a invasão do serviço de Kubernetes Spot, da Rackspace. O atacante teve acesso por quase 22 horas em 17/11, com credenciais roubadas.[1] Ele “could have read any Secret in an affected user's clusters, and any Spot API token or refresh token that user held”.[1] A causa, segundo um cofundador da Platform9: “An observability system was breached using a compromised credential.”[1] A Rackspace não diz quantos clientes foram afetados. O Spot termina em 08/12 às 17h Central Time, ou seja, 20h em Brasília.[1]

Sistema de observabilidade: O software que coleta logs, métricas e traces de todos os clusters para que a equipe de operação veja o que está rodando. Para enxergar tudo, ele recebe amplos direitos de leitura. É como o zelador com a chave-mestra: ele precisa entrar em todo lugar, e quem roubar a chave dele também.
Nossa visão Segundo caso em dois dias, depois da 1Password, em que a porta de entrada não foi o produto, mas a ferramenta ao redor. Agentes de monitoramento precisam de métricas, não de secrets. Quem tem Prometheus, Grafana Agent ou Datadog no cluster: verifiquem se o ServiceAccount deles pode ler secrets. Para métricas, raramente é necessário.

Windows Server 2025: hotpatch para o hotpatch

A Microsoft publicou em 25/11, fora do ciclo, o KB5138318.[1] Ele corrige um erro do hotpatch de novembro KB5131077 (OS Build 26100.33730), de 10/11.[1][2] Servidores com Router Advertisements ativados que recebem rotas IPv6 de duração limitada travam assim que o timer de uma rota expira. O stop code: “0x139 (KERNEL_SECURITY_CHECK_FAILURE)”.[1] A correção “takes effect without requiring a restart”.[1] A Microsoft não explica o erro de programação em si.[1]

Hotpatch: Uma atualização que troca o código em execução na memória, sem reiniciar. É como trocar o pneu com o carro andando: prático, desde que o pneu novo sirva. Aqui ele não serviu, e o servidor parou assim que uma rota IPv6 expirou.
Nossa visão O hotpatching economiza janelas de manutenção, mas não economiza testes. Um erro que só aparece quando o timer de uma rota expira não aparece no smoke test logo após a atualização. Para redes IPv6 com RA, isso significa: deixe primeiro um servidor canário rodando por um dia.

Zstandard 1.6.0: restos de memória na saída

A equipe do Zstandard antecipou a versão 1.6.0 para fechar a CVE-2026-124851.[1] As versões 1.5.1 a 1.5.7 são afetadas: “Ao descompactar dados manipulados, as versões afetadas podem expor conteúdo da memória.”[1] Na descompressão em streaming, o conteúdo de um buffer interno (por padrão 64 KiB) pode chegar à saída, inclusive restos de uma descompressão anterior no mesmo contexto. O atacante precisa fornecer dados comprimidos e conseguir ver a saída.[1] O heise não informa um valor CVSS.[1]

Além disso, a 1.6.0 traz descompressão mais rápida em AArch64 e suporte a RVV no RISC-V. Atenção ao atualizar: um build padrão não lê mais arquivos comprimidos com Zstd anterior à 0.8.0; ZSTD_LEGACY_SUPPORT traz isso de volta.[1]

Nossa visão Isso é relevante para serviços que descompactam dados comprimidos de terceiros e devolvem o resultado, como pré-visualização de uploads ou proxies. O Zstd costuma vir como biblioteca do sistema ou em bindings de linguagem; a correção chega, portanto, pela distribuição, não pelo seu package.json.

Vazamentos de dados: Deichmann e FIFA

Deichmann

A varejista de calçados relata um acesso a “dados selecionados de clientes sobre compras em nossa loja online”.[1] Foram afetados nome, endereço de cobrança e de entrega, notas fiscais, e-mail, telefone e a forma de pagamento escolhida. Senhas, dados de login e dados de pagamento, como números de cartão de crédito, não foram afetados, segundo a Deichmann.[1] Qual falha foi explorada, a empresa não diz, apenas que ela foi fechada. Ela não informa o número de afetados.[1]

Atenção Dados reais de pedidos tornam e-mails de golpe críveis. A Deichmann diz que seus dados bancários não mudaram e que nunca pede senhas.[1]

FIFA

Um ataque levou, na FIFA, a um “acesso não autorizado a um número limitado de dados pessoais e comerciais”.[2] A Reuters fala, segundo o heise, em “menos de 0,1 por cento do total dos dados”. Um grupo chamado Handsome Boy Hacking Club assumiu a autoria, segundo o The Record; isso não foi confirmado de forma independente.[2] Quais sistemas foram afetados está em aberto.

Checagem de stack: o PostgreSQL 14 chegou ao fim

O PostgreSQL 19 está em disponibilidade geral desde 19/11.[2] Para a sua própria stack, porém, o que conta é isto: com a atualização de 12/11 (18.7, 17.12, 16.16, 15.20, 14.25 e 19 RC2), a 14.25 foi o último release do PostgreSQL 14.[1] A próxima versão menor planejada sai em 11/02/2027.[2] Quem ainda roda a 14 não receberá mais correções a partir daí. A rodada de novembro corrigiu 52 vulnerabilidades de segurança, entre elas a CVE-2026-6460, uma type confusion após ALTER ... SET DATA TYPE com CVSS 8,8.[1]

Para usuários do Caddy: a versão atual é a 2.11.9, de 05/11, que segundo as release notes é “a quick follow-up on top of 2.11.8, to fix a regression it introduced and a few more security issues”.[3]

Nossa visão A migração da 14 para a 18 ou 19 com pg_upgrade costuma ser trabalho de uma noite. Fevereiro é um bom prazo para isso, antes que apareça a primeira falha sem patch.

Hoje é sexta-feira, 27 de novembro, o dia seguinte ao Thanksgiving. O noticiário está calmo, mas uma história se destaca. Ela vem da Índia.

O DIGIT é um kit de ferramentas para a administração digital, com serviços como login e pagamentos. Segundo o The Register, dez países o usam, e os governos deles atendem juntos mais de dois bilhões de pessoas. Nos serviços de usuários e controle de acesso há uma injeção de SQL com nota nove vírgula três em dez. O atacante não precisa de login, só de uma requisição manipulada para a interface. A correção está na versão dois ponto nove ponto três. Se alguém já está atacando, não se sabe.

Hoje termina o prazo da agência americana CISA para a falha do Drupal. As correções são Drupal onze ponto quatro ponto treze, onze ponto três ponto vinte e dois e dez ponto seis ponto vinte e dois. Os ataques acontecem desde 19 de novembro. Amanhã terminam outros prazos, entre eles os de Mitel MiCollab, Danfoss, Xen Orchestra e Juniper. Não houve entradas novas desde quarta-feira.

Sobre os firewalls da Palo Alto, o heise agora cita as versões com a correção de kernel contra o Fragnesia. O Fragnesia é uma falha no kernel Linux, sobre o qual o PAN-OS roda. Junto com o PHP2Shell, ela dá aos atacantes controle total, mas só se o gerenciamento estiver acessível pela internet.

A Rackspace revela a causa da invasão do Spot. O atacante entrou por um sistema de monitoramento com um acesso roubado e ficou dentro por quase vinte e duas horas. Ele podia ler todos os Secrets dos clusters afetados. O Spot será desligado em 8 de dezembro.

A Microsoft corrige um hotpatch com outro hotpatch. O patch de novembro para o Windows Server dois mil e vinte e cinco derrubava servidores assim que uma rota IPv6 de duração limitada expirava. A correção não exige reinicialização. Além disso, o Zstandard, na versão um ponto seis, fecha uma falha em que restos de memória iam parar na saída durante a descompressão.

Na Alemanha, a Deichmann relata um acesso a dados de clientes da loja online, com nomes, endereços e notas fiscais, mas sem senhas nem dados de cartão. A FIFA também confirma um ataque. E o navegador Ladybird agora roda em Rust, mas diz expressamente que não dá garantia de segurança.

Para terminar, um lembrete: o PostgreSQL catorze não recebe mais atualizações. A próxima atualização de segurança, em fevereiro, sai sem essa versão. Amanhã vamos ver se surgem os primeiros ataques ao DIGIT e se a CISA publica novas entradas depois do feriado.
